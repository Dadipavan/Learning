7.7 The Bridge to Deep Learning for Tables

Everything in this chapter ends in a plain question: should you put a neural network on a spreadsheet? Published comparisons keep finding that tuned gradient boosting is as good or better than neural networks on most medium-size tabular data, and much cheaper to train. Networks win with huge data, text or image columns mixed in, multi-task output, or when you need embeddings shared with other models. This section shows why trees have the edge with a small experiment you can reproduce (scikit-learn only; PyTorch and the specialised tabular networks TabNet, FT-Transformer and TabPFN are not installed here, so they are not run here).

Problem 7.7.1 The data has 3 heavy-tailed features, 3 normal features, and 14 pure-noise columns; the label depends on a threshold in a skewed feature, a sine and a thresholded interaction. Explain the ranking of the four models.

Step 1HistGradientBoosting: 0.884. Trees ask "is x > 1.5?", which is invariant to monotone rescaling, so heavy tails do not matter and it finds the thresholds directly. Noise columns are simply never chosen.
Step 2MLP on raw features: 0.695. The log-normal columns have occasional values near 30, which dominate the first-layer sums and make training unstable.
Step 3Standardising did not help (0.648): a skewed variable stays skewed after centring, and the sharp threshold at 1.5 still sits in the compressed part of the scale.
Step 4A QuantileTransformer (map every column to a normal shape by rank) restored it to 0.693, the same as raw, so preprocessing was not the whole story: the network must also approximate step functions with smooth units and ignore 14 distracting inputs, which takes more data and tuning.
AnswerOn this kind of data trees win by about 19 points of accuracy without any tuning. The result is a property of the data (thresholds, noise columns, skew), not a law: with more rows or smoother targets the gap closes.
Why it mattersStart with boosting. Try a network when you have a reason: unstructured columns, huge data, or a need for shared embeddings.

What a tabular network adds to a plain MLP

  • Embeddings for categories: each category value gets a learned vector (typically 4 to 50 numbers) instead of a one-hot. Similar categories end up close together, and the vectors can be reused in other models.
  • Numeric treatment: quantile or piecewise-linear encodings of each number, so that the network can respond sharply at thresholds as trees do.
  • Architectures: TabNet (learned feature masks), FT-Transformer (each feature a token, then self-attention), and TabPFN (a transformer pretrained on millions of synthetic tables that predicts in one forward pass for small data). All are not run here.
  • Training recipe: AdamW, early stopping on a validation set, dropout and weight decay, and several seeds, since the run-to-run noise is large.
COMMON MISTAKE
Comparing a tuned network with a default boosting model (or the other way around). Give each the same tuning budget, the same split, and report the mean and spread over several seeds.
COMMON MISTAKE
Skipping preprocessing for the network. Skewed or exploding scales, missing values and unencoded categories are the usual reasons it loses by a large margin.

Check yourself

  1. Why are trees unaffected by log-transforming a feature? Answer: a monotone transform does not change the order of values, so the best threshold selects the same rows.
  2. Name two situations favouring a network. Answer: image or text columns in the same row, and data with millions of rows or a need for shared embeddings.
