8.7 Seeing Your Splits: Draw the Folds Before You Trust Them

Every leak in 8.5 has the same fingerprint: a row in the training set that is "too close" to a row in the test set (same person, same week, same copy). The cheapest defence is to draw the split on a toy table of twelve rows before running it on the real one. Rows are in time order; rows 0 to 2 belong to patient 0, 3 to 5 to patient 1, and so on.

How to read it: in plain KFold (left) the test block of fold 1 (rows 4 to 7) straddles patients 1 and 2, whose other rows (3, 8) sit in the training set, so the same person is on both sides. In GroupKFold (middle) the dotted lines mark patient boundaries and no patient is split: fold 0 tests patients 0 and 3 together, which is fine. In TimeSeriesSplit (right) the training block always ends before the test block begins and grows with each fold, so you only ever predict the future from the past; note that fold 0 trains on just 3 rows, so early folds are noisy.

Problem 8.7.1 Using the printed folds, count how many test rows share a patient with some training row under KFold, versus GroupKFold.

Step 1KFold fold 0: test [0, 1, 2, 3]. Patient 0 owns 0 to 2 (all in test, no overlap), but row 3 belongs to patient 1 whose rows 4, 5 are in training: 1 contaminated test row.
Step 2Fold 1: test [4, 5, 6, 7]. Rows 4, 5 (patient 1) have row 3 in training; rows 6, 7 (patient 2) have row 8 in training. 4 contaminated rows.
Step 3Fold 2: test [8, 9, 10, 11]. Row 8 (patient 2) has 6, 7 in training; rows 9 to 11 are all patient 3, clean. 1 contaminated row. Total 6 of 12.
AnswerKFold: 6 of 12 test rows are contaminated. GroupKFold: 0, because every test patient is entirely absent from training.
Why it mattersHalf the evaluation is a lookup of a patient the model has already seen, which inflates the score; with real data the effect is often several points of AUC.
COMMON MISTAKE
Shuffling before TimeSeriesSplit, or passing a shuffled frame. The splitter assumes the rows are already in time order and uses position, so shuffled data silently turns it into a random split.
COMMON MISTAKE
Forgetting groups=. GroupKFold(3).split(X, y) without groups raises an error, but cross_val_score(model, X, y, cv=GroupKFold(3)) without groups= is easy to write when you pass a splitter object by habit: always pass groups.

Check yourself

  1. What would you check on a split of customer transactions? Answer: that no customer id appears in both train and test, and, if predicting the future, that all test dates are later than all train dates.
  2. Why can the first TimeSeriesSplit fold be unreliable? Answer: it trains on very few rows; use a minimum train size and read the later folds more.
