7.6 More Worked Boosting Examples: Log Loss, Gain Arithmetic, Early Stopping, Custom Loss

Example A: two rounds of log-loss boosting with Newton leaves

Same six rows as Problem 7.2.2 (x = 1..6, y = 0, 0, 1, 0, 1, 1), but now with the XGBoost-style leaf w = −G/(H+λ), λ = 1 and η = 0.5.

Problem 7.6.1 Do round 1 by hand and read round 2 from the code. What happens to the log loss?

SetupF₀ = 0, so p = 0.5. g = p − y = (0.5, 0.5, −0.5, 0.5, −0.5, −0.5), h = 0.25 for every row. Initial log loss is ln 2 = 0.6931.
Split after row 2G_L = 1.0, H_L = 0.5; G_R = −1.0, H_R = 1.0. Gain = ½ · [1/(0.5+1) + 1/(1+1) − 0/(1.5+1)] = ½ · (0.6667 + 0.5) = 0.5833.
Leaf valuesw_L = −1.0/1.5 = −0.6667, w_R = +1.0/2 = 0.5.
UpdateF = 0.5 × w: −0.3333 for rows 1 and 2, +0.25 for rows 3 to 6. Probabilities become σ(−0.3333) = 0.417 and σ(0.25) = 0.562.
Round 2Now the rows are no longer equal: g and h are recomputed from the new p. The code picks the split after row 4 (a different split from round 1), because rows 1 to 4 still contain mostly zeros and rows 5, 6 are both ones.
@@CODE c07_logloss_hand.py@@

Read the output: the log loss falls from 0.6931 to 0.6057 to 0.5324, and every round re-derives g and h from the current probabilities. The round 2 leaf values (−0.4848 and +0.5868) are computed exactly like round 1's.

COMMON MISTAKE
Reusing round 1's g and h in round 2. They depend on the current predictions. If you do not recompute them, every tree is the same tree.

Example B: split gain, λ and γ on eight rows

Problem 7.6.2 Eight rows x = 1..8, y = 2, 3, 3, 2, 8, 9, 7, 9, squared error. Find the best first split, the leaf values for several λ, and see which deeper splits γ removes.

SetupF₀ = mean(y) = 43/8 = 5.375. For squared error ½(y−F)²: g = F − y, h = 1. So g = (3.375, 2.375, 2.375, 3.375, −2.625, −3.625, −1.625, −3.625).
Split after row 4 by handG_L = 3.375 + 2.375 + 2.375 + 3.375 = 11.5, H_L = 4; G_R = −11.5, H_R = 4. With λ = 1: gain = ½ · [11.5²/5 + 11.5²/5 − 0²/9] = ½ · (26.45 + 26.45) = 26.45.
Leaf valuew_L = −11.5/(4+1) = −2.3 and w_R = +2.3. With λ = 0 it would be ±2.875, the plain mean residual.
@@CODE c07_xgb_gain.py@@
Read the gain rowGain peaks at the split after row 4 for every λ, which is where y jumps from 2 to 8. Larger λ shrinks all the gains (33.06, 26.45, 9.45) without moving the best split here.
Read the leaf valuesThe leaf shrinks by the factor H/(H+λ) for squared error: 4/(4+1) = 0.8 gives 2.3, and 4/14 = 0.2857 gives 0.8214 for λ = 10. A leaf with few rows shrinks more than a leaf with many.
Read the child splitsWith λ = 0 and γ = 0, splitting inside the children still has positive gain (0.167 and 0.375) even though those children are just noise around 2.5 and 8.25. γ = 1 turns both negative, so the tree stops at depth 1. With λ = 1 they are negative even at γ = 0.
KEY IDEA
Think of λ as a tax on the size of leaf values and γ as a fixed fee for every new leaf. A split must earn more than the fee. Both are ways of saying "do not fit noise".

Example C: early stopping in practice

Early stopping chooses the number of trees from the validation curve instead of guessing. We use scikit-learn's make_friedman1 (a standard synthetic regression benchmark with noise), a 50 percent train, 25 percent validation, 25 percent test split, learning rate 0.1, depth 3 and up to 600 trees. staged_predict gives the predictions after each tree, so one fit gives the whole curve.

@@CODE c07_early_stop.py@@

How to read it (left): training error keeps falling toward zero (2.710 at 67 trees, 0.213 at 600) while validation error reaches its floor of 5.091 at 67 trees and then creeps back up to 5.675. The test error follows (5.580 at the best round, 5.743 at 600). The gap between train and validation widens every round past the minimum: that gap is overfitting made visible. The difference between stopping and not stopping is small here (0.16 test MSE), because shallow trees with a small learning rate overfit slowly; with deeper trees or a larger rate the penalty is bigger. A patience rule of 20 rounds stopped at round 87 and kept round 67, so patience costs 20 extra trees of training time but no accuracy.

COMMON MISTAKE
Early stopping on the same set you then report as the test score. The validation set picked the round, so its score is optimistic. Here validation said 5.091 and an untouched test set said 5.580. Keep a third set, or use nested cross-validation.

Example D: a custom asymmetric loss and a monotonic constraint, run

Section 7.5 gave the formulas for the asymmetric squared loss. Here is the full Newton boosting loop that uses them, written from scratch with scikit-learn trees. The trick to get XGBoost's leaf −G/H from an ordinary regression tree: fit the tree to the target −g/h with sample_weight = h, because a weighted mean of −g/h with weights h equals −Σg / Σh. Under-predicting (when y > F) costs 3 times as much as over-predicting.

@@CODE c07_asym.py@@

The asymmetric model under-predicts 39.7 percent of test rows instead of 50.4 percent, because it deliberately leans high. It pays for that in plain average error (2.01 versus 1.87) but wins on the cost it was trained for (10.29 versus 11.26, about 9 percent lower). Choosing the loss is a business decision: the "best" model depends on which mistake costs more.

Going deeper: why the leaf formula is a Newton step

For one leaf with total slope G and curvature H, the loss as a function of the leaf value w is approximated by G·w + ½(H+λ)w². Setting the derivative to zero gives w = −G/(H+λ). For squared error the loss is exactly quadratic, so one Newton step lands on the minimum: with λ = 0 the leaf is the mean residual. For log loss it is only approximately quadratic, which is why the leaf values are an approximation and why the learning rate η still helps. In Example D, for a single row with y = 10, F = 7, w = 3: g = −2 × 3 × 3 = −18, h = 6, leaf = 18/6 = 3, moving F exactly to 10 before the learning rate.

Check yourself

  1. Why does the best split in Example B not move when λ grows? Answer: λ shrinks every gain by a similar factor here, and the jump from 2 to 8 dominates.
  2. Why recompute g and h every round? Answer: they depend on the current predictions.
  3. What does early stopping protect against, and what does it not protect against? Answer: it protects against too many trees; it does not make the validation score an honest final estimate.
