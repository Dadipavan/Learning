
@@H2 8.7 matplotlib in Depth: the Figure, the Axes and Everything You Can Control
@@CALL blue|INTUITION|matplotlib is a drawing program driven by code. Its secret is that everything on a chart is an object you can hold in your hand: the canvas (Figure), each plot area (Axes), each number line (Axis), each line and bar and word. Beginners call functions that act on "whatever chart is current". Professionals hold the objects and say exactly which one to change. The second way is a little longer to type and never surprises you.
<h3>The object model: Figure, Axes, Axis, Artist</h3>
@@PY mplmodel
#H
from matplotlib.patches import FancyBboxPatch
fig = plt.figure(figsize=(8, 4.4))
bg = fig.add_axes([0, 0, 1, 1]); bg.set(xlim=(0, 100), ylim=(-4, 55)); bg.axis("off")
def box(x, y, w, h, fc, ec, label, size=12, weight="bold", tc="#222"):
    bg.add_patch(FancyBboxPatch((x, y), w, h, boxstyle="round,pad=0.4,rounding_size=1.2", fc=fc, ec=ec, lw=2))
    bg.text(x + 1.2, y + h - 2.4, label, fontsize=size, fontweight=weight, color=tc, va="center")
box(2, 2, 96, 50, "#f4f6fb", BLUE, "Figure   (the canvas: size, dpi, saving)    fig = plt.figure() or plt.subplots()")
box(6, 6, 58, 38, "white", TEAL, "Axes   (one plot)    ax = fig.add_subplot()")
box(10, 10, 24, 12, "#eef6f4", TEAL, "xaxis   (ticks)", 10)
box(38, 10, 24, 12, "#eef6f4", TEAL, "yaxis   (ticks)", 10)
box(10, 26, 24, 11, "#fbf1ec", ORANGE, "Line2D   ax.plot()", 10)
box(37, 26, 23, 11, "#fbf1ec", ORANGE, "Bars   ax.bar()", 10)
box(68, 24, 28, 12, "#f4f0fb", PURPLE, "Legend / Text / Annotation", 10)
box(68, 8, 28, 12, "#f4f0fb", PURPLE, "Second Axes   (subplots)", 10)
bg.text(50, -2, "Every box is an object. Methods on ax change one plot; methods on fig change the whole canvas.",
        ha="center", fontsize=10.5, color="#444")
fig.savefig("ch08v_mplmodel.png", dpi=110)
print("saved")
@@END
@@FIG mplmodel|Nested boxes showing a Figure containing Axes, which contain axis objects, lines, bars, a legend and a second Axes|The matplotlib object model: a Figure holds Axes; an Axes holds Axis objects and artists such as lines and bars.
@@TABLE
Object | What it is | Typical calls
Figure | The whole canvas: size, resolution, overall title, saving | <code>fig.savefig</code>, <code>fig.suptitle</code>, <code>fig.tight_layout</code>
Axes | One plot with its own coordinates, data, title and labels | <code>ax.plot</code>, <code>ax.set_title</code>, <code>ax.set_xlim</code>
Axis | The x or y number line of an Axes (with ticks, tick labels, scale) | <code>ax.xaxis.set_major_locator</code>, <code>ax.set_yscale</code>
Artist | Anything drawn: a line, bar, text, legend, patch | the return values of <code>ax.plot</code>, <code>ax.bar</code>, <code>ax.text</code>
@@END
<p>Method names follow a pattern: <code>set_</code> methods change a property (<code>ax.set_title</code>, <code>ax.set_xlim</code>), <code>get_</code> methods read it, <code>add_</code> methods put new objects in. The shortcut <code>ax.set(title=..., xlabel=..., ylim=...)</code> sets many properties in one call.</p>
<h3>pyplot versus object-oriented: same chart, two styles</h3>
@@PY oo_vs_pyplot
import numpy as np
import matplotlib.pyplot as plt

x = np.arange(1, 7)
y = np.array([350, 330, 375, 405, 430, 455])

# Style 1: the pyplot "state machine" (acts on the current figure and axes)
plt.figure(figsize=(6, 3))
plt.plot(x, y, color="#2b4fd6")
plt.title("Sales")
plt.xlabel("Month")
line_a = plt.gca().lines[0].get_ydata()      # gca() = "get current axes"
plt.close()

# Style 2: object-oriented (you hold fig and ax and call methods on them)
fig, ax = plt.subplots(figsize=(6, 3))
ax.plot(x, y, color="#2b4fd6")
ax.set_title("Sales")
ax.set_xlabel("Month")
line_b = ax.lines[0].get_ydata()
plt.close(fig)

print("same data drawn:", bool((line_a == line_b).all()))
print("figures still open after closing both:", len(plt.get_fignums()))
@@END
<p>Both draw the same chart. The difference is control. With pyplot, <code>plt.title</code> goes to "the current axes", and as soon as you have two subplots you must remember which one is current. With the object-oriented style, <code>ax1.set_title</code> and <code>ax2.set_title</code> cannot be confused. Rule for this chapter, and for any code you share: <strong>use <code>fig, ax = plt.subplots()</code> and call methods on <code>ax</code>.</strong> Use <code>plt</code> only for <code>plt.subplots</code>, <code>plt.rcParams</code>, <code>plt.show()</code> and <code>plt.close()</code>. The last printed line shows the tidy habit: close each figure when you are done, so none are left open.</p>
@@CALL red|COMMON MISTAKE|Mixing the two styles and drawing on the wrong plot. Wrong: <code>fig, (ax1, ax2) = plt.subplots(1, 2)</code> then <code>plt.title("A")</code> (it lands on the last axes you touched). Right: <code>ax1.set_title("A")</code>. Another classic: forgetting that in a loop each <code>plt.figure()</code> stays open and uses memory. Close with <code>plt.close(fig)</code> after saving.
<h3>The house-style header, line by line</h3>
<p>Almost every block in this chapter starts with the same four lines. Here is what each does and how to see the effect.</p>
@@PY rcparams
import matplotlib.pyplot as plt
from matplotlib import rc_context
from matplotlib.colors import to_hex

print("default figure size:", plt.rcParams["figure.figsize"], "| dpi:", plt.rcParams["figure.dpi"],
      "| font size:", plt.rcParams["font.size"])
print("default top spine visible:", plt.rcParams["axes.spines.top"])
print("first 3 colours of the default cycle:", [to_hex(d["color"]) for d in plt.rcParams["axes.prop_cycle"]][:3])

house = {"figure.figsize": (8, 4.2), "figure.dpi": 110, "font.size": 12, "axes.titlesize": 14,
         "axes.titleweight": "bold", "axes.titlelocation": "left",
         "axes.spines.top": False, "axes.spines.right": False}
with rc_context(house):                      # temporary: restored when the block ends
    print("inside context  :", plt.rcParams["figure.figsize"], plt.rcParams["axes.titlelocation"])
print("after context   :", plt.rcParams["figure.figsize"], plt.rcParams["axes.titlelocation"])
@@END
<ol><li><code>plt.rcParams</code> is a dictionary of ~300 default settings (the "run commands" parameters). <code>plt.rcParams.update({...})</code> changes several at once for the rest of the program.</li><li><code>"figure.figsize": (8, 4.2)</code> is the canvas in inches (width, height). With <code>"figure.dpi": 110</code> the PNG is 8 x 110 = 880 pixels wide and 462 tall.</li><li><code>"font.size": 12</code> is the base size in points (1/72 inch). Tick labels and legends use it; <code>axes.titlesize</code> and <code>axes.labelsize</code> can differ. Aim for 11 to 14 pt on the final size.</li><li><code>"axes.titlelocation": "left"</code> with <code>"axes.titleweight": "bold"</code> gives left-aligned bold headline titles, which is where eyes start.</li><li><code>"axes.spines.top": False</code> and right remove the box frame. A <em>spine</em> is one of the four lines around the plotting area.</li><li><code>BLUE, ORANGE, ... = "#2b4fd6", ...</code> are plain strings holding hex colours (#RRGGBB: red, green, blue amounts from 00 to ff). Naming them once keeps colours consistent.</li><li><code>rc_context</code> applies settings temporarily, perfect for one special chart inside a long script.</li></ol>
<h3>Layouts: subplots, mosaic and GridSpec</h3>
<p>A grid of equal panels is <code>plt.subplots(nrows, ncols)</code>, which returns an array of axes (one axes if 1 by 1, a 1D array if one row or column, a 2D array otherwise). When panels differ in size, use a <em>mosaic</em>: draw the layout as text, one letter per panel, repeated letters merge cells.</p>
@@PY mosaic
#H
#MONTHLY
#ORD
import matplotlib.dates as mdates
fig, axd = plt.subplot_mosaic("AAB;AAC;DDD", figsize=(8, 5.2), layout="constrained")
axd["A"].plot(monthly.index, monthly.values, color=BLUE, lw=2.5)
axd["A"].set_title("A: wide panel"); axd["A"].set_ylim(0, 700)
axd["A"].xaxis.set_major_locator(mdates.MonthLocator(bymonth=[1, 4, 7, 10]))
axd["A"].xaxis.set_major_formatter(mdates.DateFormatter("%b %y"))
city = orders.groupby("city")["amount"].sum().sort_values()
axd["B"].barh(city.index, city.values / 1000, color=GREY); axd["B"].set_title("B")
axd["C"].hist(orders["amount"], bins=15, color=TEAL); axd["C"].set_title("C")
yoy = (monthly.pct_change(12) * 100).dropna()
axd["D"].bar(yoy.index.strftime("%b"), yoy.values, color=ORANGE); axd["D"].set_title("D: full-width strip: YoY growth, %")
for ax in axd.values(): ax.tick_params(labelsize=9)
print("panels:", list(axd), "| A size (inches):", np.round(axd["A"].get_figure().get_size_inches(), 1))
fig.savefig("ch08v_mosaic.png", dpi=110)
print("saved")
@@END
@@FIG mosaic|Four panels of different sizes: a large line chart, a small bar chart, a small histogram and a wide strip of bars|subplot_mosaic("AAB;AAC;DDD"): A spans two rows and two columns, B and C stack at the right, D spans the bottom.
<ol><li>The string <code>"AAB;AAC;DDD"</code> is a 3-row, 3-column drawing: rows are separated by <code>;</code>, and a letter repeated across cells merges them into one panel. A is 2 by 2 cells, B and C are single cells, D spans the bottom row.</li><li><code>layout="constrained"</code> lets matplotlib solve the spacing between panels and their labels. It replaces most manual <code>tight_layout</code> and <code>subplots_adjust</code> calls and handles colour bars better.</li><li><code>axd</code> is a dictionary: <code>axd["A"]</code> is the Axes named A. Naming panels beats counting indexes.</li><li><code>monthly.pct_change(12) * 100</code> is year-on-year growth (this month versus 12 rows earlier); <code>.dropna()</code> keeps the six months that have a partner.</li></ol>
<p>The older, more manual tool is <code>GridSpec</code>: <code>gs = fig.add_gridspec(2, 3, width_ratios=[2, 1, 1], height_ratios=[3, 1])</code> and <code>ax = fig.add_subplot(gs[0, :2])</code> (row 0, columns 0 and 1). The dual-axis figure in 8.4 used it. Use GridSpec when you need exact ratios or spacing (<code>wspace</code>, <code>hspace</code>); use mosaic when a text picture of the layout is clearer.</p>
<h3>Styles, fonts and colormaps</h3>
<p>A <strong>style</strong> is a bundle of rcParams. You can switch the whole look with one line.</p>

@@FIG styles|Four small line charts of the same data drawn in the default, ggplot, seaborn whitegrid and bmh styles|The same two lines in four built-in styles. A style changes fonts, grid, colours and background in one line.
<p>Styles are a good starting point, but for work you share, set your own house style once (as in the header) so every chart in a report looks like the same author drew it. Create a style file <code>house.mplstyle</code> with lines like <code>axes.spines.top: False</code> and load it with <code>plt.style.use("house.mplstyle")</code>.</p>

<p><strong>Colormaps</strong> (the <code>cmap=</code> argument) turn numbers into colours: sequential (<code>"Blues"</code>, <code>"viridis"</code>), diverging (<code>"RdBu_r"</code>, <code>"coolwarm"</code>) and qualitative (<code>"tab10"</code>). Add <code>_r</code> to reverse any of them. Choosing among them is a design question and is covered in 8.10.</p>
<h3>Saving at the right size and format</h3>
@@PY savefig
import numpy as np
import matplotlib.pyplot as plt
import tempfile, os

fig, ax = plt.subplots(figsize=(8, 4.2))
ax.plot([1, 2, 3], [3, 1, 2])
tmp = tempfile.mkdtemp()
for dpi in (72, 110, 300):
    path = os.path.join(tmp, f"chart_{dpi}.png")
    fig.savefig(path, dpi=dpi)
    h, w = plt.imread(path).shape[:2]
    print(f"dpi {dpi:>3}: {w} x {h} pixels  (= 8 x {dpi}, 4.2 x {dpi})")
fig.savefig(os.path.join(tmp, "chart.svg"))
fig.savefig(os.path.join(tmp, "chart.pdf"))
print("formats written:", sorted(f.split(".")[-1] for f in os.listdir(tmp) if not f.startswith("chart_")))
@@END
<ul><li><strong>Pixels = inches x dpi.</strong> A chart for a web page needs about 800 to 1,200 pixels wide: 8 inches at 110 to 150 dpi. A slide at 1920 pixels wide: 10 inches at 192 dpi. A printed A4 page column of 6 inches at 300 dpi needs 1,800 pixels.</li><li><strong>Raster (PNG) versus vector (SVG, PDF):</strong> PNG is fine for web, e-mail and Office. For print and journals use PDF or SVG: they stay sharp at any size and text stays selectable. Convert at the end, do not draw twice.</li><li><code>bbox_inches="tight"</code> trims blank margins but can change the final pixel size, so do not combine it with exact size requirements. <code>transparent=True</code> removes the white background for dark slides.</li><li>Fonts in PDF: set <code>pdf.fonttype: 42</code> in rcParams to embed editable TrueType fonts.</li></ul>

@@FIG annotate|Monthly sales line with a dashed target line at 450, shaded teal areas where sales are above target and a boxed arrow label on the December peak|Annotation toolbox: reference line, filled region, boxed text with a curved arrow.
<ol><li><code>ax.axhline(y, ls="--")</code> draws a horizontal reference line across the axes (<code>axvline</code> for vertical). Use it for targets, averages and zero.</li><li><code>fill_between(x, y1, y2, where=condition, interpolate=True)</code> shades between two curves only where the condition holds; <code>interpolate=True</code> makes the edges meet exactly at the crossings.</li><li><code>ax.annotate(text, xy=, xytext=, bbox=, arrowprops=)</code>: <code>bbox</code> boxes the text; <code>arrowprops</code> controls the arrow (<code>arrowstyle="-|&gt;"</code> is a filled head, <code>connectionstyle="arc3,rad=-0.25"</code> bends it).</li><li>The printed list proves the title: only Oct 2024 (470), Nov 2024 (560), Dec 2024 (620) and Jun 2025 (455) are at or above 450. The teal area covers the festive run; June 2025 is a single point, so it has no visible area yet.</li></ol>
<p>Coordinates: by default <code>xy</code> and <code>xytext</code> are in data units (the axis values). Use <code>xycoords="axes fraction"</code> (0 to 1 across the plot), <code>"figure fraction"</code> or <code>textcoords="offset points"</code> when you want a position that survives changes of the data range, as we did with the bubble labels.</p>
<h3>Scales: log, symlog and a second axis in other units</h3>
@@PY scales
#H
months = np.arange(0, 11)
signups = 100 * 2 ** months                       # doubles every month
print("signups:", signups.tolist())
fig, (ax1, ax2, ax3) = plt.subplots(1, 3, figsize=(11, 3.8), layout="constrained")
ax1.plot(months, signups, color=BLUE, lw=2.5, marker="o"); ax1.set_title("Linear axis")
ax1.yaxis.set_major_formatter("{x:,.0f}")
ax2.plot(months, signups, color=BLUE, lw=2.5, marker="o"); ax2.set_yscale("log"); ax2.set_title("Log axis: a straight line")
ax2.set_yticks([100, 1000, 10000, 100000], ["100", "1,000", "10,000", "100,000"]); ax2.minorticks_off()
rs = np.array([350, 330, 375, 405, 430, 455])
ax3.plot(["Jan", "Feb", "Mar", "Apr", "May", "Jun"], rs, color=ORANGE, lw=2.5, marker="o")
ax3.set_title("Second axis, other unit"); ax3.set_ylabel("Rs thousand"); ax3.set_ylim(300, 500)
sec = ax3.secondary_yaxis("right", functions=(lambda r: r / 84, lambda d: d * 84))      # illustrative rate: Rs 84 per US dollar
sec.set_ylabel("US dollars thousand (at Rs 84)"); sec.spines["right"].set_visible(True)
for ax in (ax1, ax2):
    ax.set_xlabel("Months since launch"); ax.set_ylabel("Signups"); ax.set_xticks(range(0, 11, 2))
fig.savefig("ch08v_scales.png", dpi=110)
print("log10 of the values:", np.round(np.log10(signups[[0, 5, 10]]), 2).tolist())
print("saved")
@@END
@@FIG scales|Three panels: exponential growth on a linear axis curving up sharply, the same growth on a log axis as a straight line, and a sales line with a second right axis in US dollars|Left: doubling looks like an explosion on a linear axis. Middle: on a log axis equal ratios are equal distances, so doubling is a straight line. Right: a second axis that is the first re-expressed in other units.
<p><strong>When to use a log axis.</strong> When values span orders of magnitude (money per customer, web traffic, populations) or when you care about <em>percent</em> change: on a log axis the same distance always means the same ratio. Doubling from 100 to 200 and from 25,600 to 51,200 is the same step. The cost: readers need to know the axis is logarithmic, so label it ("log scale"). It cannot show zero or negative values; for data with both signs use <code>ax.set_yscale("symlog")</code>, which is linear near zero and logarithmic far from it.</p>
<p><strong>Second axis done right.</strong> <code>ax.secondary_yaxis("right", functions=(forward, inverse))</code> adds an axis that is a pure re-expression of the first, in other units (Celsius and Fahrenheit, Rs and dollars). It cannot mislead, because it has no data of its own, unlike a <code>twinx</code> axis. Compare the last block of 8.4.</p>

<h3>Common errors, with the real messages and fixes</h3>
@@PY errors
import numpy as np
import pandas as pd
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

def attempt(label, fn):
    try:
        fn()
    except Exception as e:
        print(f"{label}\n   {type(e).__name__}: {str(e)[:110]}")

fig, ax = plt.subplots()
attempt("1 title on the Figure", lambda: fig.set_title("x"))
attempt("2 x and y lengths differ", lambda: ax.plot([1, 2, 3], [1, 2, 3, 4]))
axs = plt.subplots(2, 2)[1]
attempt("3 indexing a 2D array of axes as one", lambda: axs.plot([1, 2]))
df = pd.DataFrame({"amount": [1, 2]})
attempt("4 column name typo", lambda: ax.hist(df["Amount"]))
attempt("5 style name typo", lambda: plt.style.use("ggplotx"))
attempt("6 bar with text heights", lambda: ax.bar(["a", "b"], [1, "two"]))
@@END
@@TABLE
Symptom | Cause | Fix
<code>AttributeError: 'Figure' object has no attribute 'set_title'</code> | Called an Axes method on the Figure | <code>ax.set_title</code> or <code>fig.suptitle</code>
<code>ValueError: x and y must have same first dimension</code> | Different lengths after a filter or merge | Print <code>len(x), len(y)</code>; align with the same index
<code>AttributeError: 'numpy.ndarray' object has no attribute 'plot'</code> | <code>plt.subplots(2, 2)</code> returns an array of axes | <code>axs[0, 1].plot</code> or <code>axs.ravel()</code>
<code>KeyError: 'Amount'</code> | Column name case or spelling | <code>print(df.columns.tolist())</code>
Blank or half-empty PNG | <code>savefig</code> called after <code>plt.show()</code> closed the figure | Save first, then show (or use <code>fig.savefig</code> on the object)
Overlapping labels and titles | Default margins | <code>layout="constrained"</code> or <code>fig.tight_layout()</code>
Chart shows in notebook but file is empty or cut | Labels outside canvas | <code>bbox_inches="tight"</code>, then re-check pixel size
Dates look like 19000 | Strings or integers instead of datetimes | <code>pd.to_datetime</code>
Legend says "_child0" or is empty | No <code>label=</code> on the artists | Add <code>label=</code> to each plot call, then <code>ax.legend()</code>
Script hangs on a server | An interactive backend is trying to open a window | <code>matplotlib.use("Agg")</code> before importing pyplot
@@END
@@CALL red|COMMON MISTAKE|Calling <code>plt.show()</code> and then <code>plt.savefig()</code>. In a normal script, <code>show()</code> blocks until you close the window, and the figure is empty afterwards, so the saved file is a blank white image. Wrong: <code>plt.show(); plt.savefig("a.png")</code>. Right: <code>fig.savefig("a.png"); plt.show()</code>.
<h3>Going deeper: backends, artists and performance</h3>
<p>A <em>backend</em> turns the figure into pixels or a file: <code>Agg</code> writes PNG without a screen (use this on servers, in scheduled jobs and in this chapter), <code>macosx</code> and <code>QtAgg</code> open windows, <code>pdf</code> and <code>svg</code> write vector files. Under the hood everything is an <em>Artist</em>; the Figure draws its Axes, which draw their lines, patches and text, in order of <code>zorder</code>. For hundreds of thousands of points, <code>ax.plot</code> with markers gets slow; use <code>rasterized=True</code> on the heavy artist so a vector PDF stays small, or reduce the data first (see 8.13).</p>
