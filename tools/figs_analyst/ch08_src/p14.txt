
@@H2 8.14 Debugging Charts and a Pre-Flight Checklist
@@CALL blue|INTUITION|The scariest chart bug is the one that raises no error. A loud failure (a traceback) is easy; a quiet one (labels paired with the wrong bars, months in alphabetical order, a filter that dropped half the rows) gives a polished chart that is simply false. So the debugging habit is: before you trust a picture, print the table behind it and check one number by hand.
<h3>A five-step method</h3>
<ol><li><strong>Print the table that feeds the chart</strong> (<code>print(df.head())</code>, <code>df.shape</code>, <code>df.dtypes</code>). Most bugs are visible here.</li><li><strong>Check one number by hand</strong> against the source: a total, a single bar, the first and last point.</li><li><strong>Reduce.</strong> Draw only one series or one panel with a three-row table. If that works, add back pieces until it breaks.</li><li><strong>Read the traceback bottom-up.</strong> The last line says what; the line above says where in your code.</li><li><strong>Look at the picture as a stranger.</strong> Squint test, greyscale test, ten-second test: what do you read first? Is it what you intended?</li></ol>
<h3>Quiet bug 1: labels paired with the wrong values</h3>
@@PY bug_labels
import pandas as pd

by_city = pd.Series({"Delhi": 3298, "Mumbai": 3047, "Pune": 2995})
labels = sorted(by_city.index)                       # alphabetical: Delhi, Mumbai, Pune
values = by_city.sort_values().values.tolist()       # ascending by value: 2995, 3047, 3298
print("BUG : ", list(zip(labels, values)))
fixed = by_city.sort_values()                        # sort once, keep labels and values together
print("FIX : ", list(zip(fixed.index, fixed.values.tolist())))
@@END
<p>The buggy version would draw without a single warning, with Delhi labelled as 2,995 and Pune as 3,298: the ranking is reversed. Two sorted lists are independent, so sorting one and not the other (or sorting them differently) breaks the pairing. <strong>Never split a Series into two lists before sorting; sort the Series, then read <code>.index</code> and <code>.values</code> from the same object.</strong></p>
<h3>Quiet bug 2: months in the wrong order</h3>
@@PY bug_dates
import pandas as pd

sales = pd.Series([350, 330, 375, 405], index=["Jan", "Feb", "Mar", "Apr"])
print("BUG  (sort_index on text)  :", sales.sort_index().index.tolist())
order = pd.CategoricalIndex(sales.index, categories=["Jan", "Feb", "Mar", "Apr"], ordered=True)
print("FIX  (ordered categories)  :", pd.Series(sales.values, index=order).sort_index().index.tolist())
dates = pd.to_datetime(["2025-01-01", "2025-02-01", "2025-03-01", "2025-04-01"])
print("BEST (real dates)          :", pd.Series(sales.values, index=dates).sort_index().index.strftime("%b").tolist())
@@END
<p>Text sorts alphabetically (Apr, Feb, Jan, Mar). Fix by using real dates (best: they also give correct spacing on the axis), or an ordered categorical when the labels are not dates (age bands, "Low/Medium/High"). Seaborn and matplotlib plot categories in the order they appear, so sort before you plot.</p>
<h3>Symptom table for charts that run but look wrong</h3>
@@TABLE
Symptom | Likely cause | What to check | Fix
All bars the same colour (or all grey) | Colour list shorter than expected, or one colour passed | <code>len(colors) == len(bars)</code> | Build the colour list from the same index as the data
Legend missing or "Axes" labels | <code>label=</code> not set, or legend called before plotting | Does each <code>ax.plot</code> have <code>label=</code>? | Add labels; call <code>ax.legend()</code> after
Overlapping x labels | Too many categories or long text | Count of labels | Horizontal bars; rotate by 30 degrees with <code>ha="right"</code>; thin the ticks
Line chart is a zigzag | Data not sorted by x | <code>df["x"].is_monotonic_increasing</code> | <code>sort_values("x")</code> first
A straight line joins distant points | Missing months were dropped | Count rows against the expected calendar | <code>reindex</code> to the full date range, leave NaN (a gap)
Numbers too large (1e6) on the axis | Default scientific notation | Axis offset text at the top | <code>ax.yaxis.set_major_formatter("{x:,.0f}")</code> or divide and say "millions"
Bar heights look identical | Wrong y-limits, or all values near each other | <code>ax.get_ylim()</code> | Start at 0; consider whether the data really is nearly equal
Wrong totals | Duplicate rows after a join, or a filter dropped rows | <code>df.duplicated().sum()</code>, row count before/after | Fix the join keys (Chapter 5); print the count at each step
Title shows an old number | Number typed by hand | Search the title for digits | f-string from data
Colours differ between panels or slides | Each chart assigns its own colours | Is the colour mapping a dict? | One dict {category: colour} reused everywhere
Blurry image in PowerPoint | Low dpi PNG enlarged | Pixel size of the file | Save at 150 to 300 dpi, or use SVG/EMF for vector
@@END
@@CALL red|COMMON MISTAKE|Fixing a chart by guesswork: changing the code until it looks right without knowing why. Wrong: adding <code>plt.xticks(rotation=90)</code> to cure overlapping labels when the real problem is that the data has 200 categories. Right: ask what the reader needs and change the chart type or reduce the categories first.
<h3>The pre-flight checklist (print this)</h3>
@@TABLE
Area | Question to answer before sending
Question | Can I state the one question this chart answers, in a sentence? Is the title that answer?
Data | Is the source named? Do totals match the source (checked one by hand)? Are dates real dates? Any missing, duplicated or filtered rows?
Chart type | Does the type match the question (8.1 table)? Is it the simplest chart that works?
Axes | Bars from zero? Units in the label? Sensible number format? Time window justified? Axes shared across panels?
Marks and colour | One accent? Max 5 colours? Colour-blind and greyscale safe, or redundant coding? Contrast 4.5:1 for text?
Text | Title states the finding; fonts at least 11 pt at final size; labels horizontal; direct labels instead of a legend where possible; no overlaps?
Honesty | Rates not counts where groups differ; n shown; no 3D; no dual axis; no cherry-picked window; claim no stronger than the evidence?
Story | Does the chart have an annotation for the point? Is the next step stated?
Output | Right size and dpi for the destination (screen 110 to 150, print 300 or vector)? File named and dated? Code saved with seed?
Accessibility | Alt text or a sentence in the body that gives the finding? Data table available?
@@END
<h3>Going deeper: testing visualization code</h3>
<p>Treat chart code like any code. Keep the aggregation in a function that returns a DataFrame and write a small test for it (a known mini table in, a known total out). Keep the drawing function free of calculation: it takes tables and writes pixels. Use <code>matplotlib.testing</code> or the <code>pytest-mpl</code> plugin to compare a new image to a saved baseline in a scheduled pipeline, and fail the job if a number in a title differs from the data. A dashboard is software; it deserves a review.</p>
