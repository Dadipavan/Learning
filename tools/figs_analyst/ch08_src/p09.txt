<h3>What a plotly figure really is</h3>
<p>The following block needs no plotly. It writes by hand the recipe that plotly builds for a bar chart, and prints it. Reading it once removes the mystery from <code>fig.update_layout</code>.</p>
@@PY plotly_json
import json

figure = {
    "data": [{"type": "bar", "x": ["Delhi", "Mumbai", "Pune"], "y": [3298, 3047, 2995],
              "marker": {"color": ["#2b4fd6", "#9a9a9a", "#9a9a9a"]},
              "hovertemplate": "%{x}: Rs %{y:,.0f}<extra></extra>"}],
    "layout": {"title": {"text": "Delhi sold the most: Rs 3,298 of Rs 9,340"},
               "yaxis": {"title": {"text": "Sales (Rs)"}, "range": [0, 3800]},
               "template": "plotly_white"},
}
print(json.dumps(figure["data"][0]))
print(json.dumps(figure["layout"]))
print("traces:", len(figure["data"]), "| trace type:", figure["data"][0]["type"],
      "| layout keys:", sorted(figure["layout"]))
@@END
<p>Two top-level parts: <code>data</code> is a list of <strong>traces</strong> (one bar series, one line, one scatter cloud: each with a <code>type</code> and its values), and <code>layout</code> controls everything around them (titles, axes, legend, size, template). Every plotly function, express or not, ends up building this dictionary. <code>fig.update_traces(...)</code> edits the traces; <code>fig.update_layout(...)</code> edits the layout; <code>fig.update_xaxes(...)</code> and <code>fig.update_yaxes(...)</code> are shortcuts for the axis parts of the layout.</p>
<h3>plotly express versus graph_objects</h3>
@@TABLE
 | plotly express (<code>px</code>) | graph_objects (<code>go</code>)
Style | One function call per chart, from a tidy DataFrame | Build a <code>Figure</code> and add traces one by one
Typical call | <code>px.bar(df, x="city", y="amount", color="city")</code> | <code>go.Figure(go.Bar(x=..., y=...))</code>
Colour, facets, trendlines | Built in (<code>color=</code>, <code>facet_col=</code>, <code>trendline=</code>) | You do it yourself
Control | High-level, fast, 90% of needs | Full: custom traces, waterfall, funnel area, subplots with mixed types, secondary axes
Returns | A <code>go.Figure</code> you can still modify | A <code>go.Figure</code>
Use when | Exploring, standard charts | Fine-tuning, combining chart types, unusual traces
@@END
<p>They are not rivals: start with express, then refine with <code>fig.update_*</code> or add a trace with <code>fig.add_trace(go.Scatter(...))</code>. The same chart in both styles:</p>
@@NORUN
import pandas as pd
import plotly.express as px
import plotly.graph_objects as go

df = pd.DataFrame({"city": ["Delhi", "Mumbai", "Pune"], "amount": [3298, 3047, 2995]})

# 1. express: one line, columns by name
fig1 = px.bar(df, x="city", y="amount", text_auto=",.0f")

# 2. graph_objects: the same, building the trace yourself
fig2 = go.Figure(go.Bar(x=df["city"], y=df["amount"], text=df["amount"], texttemplate="%{text:,.0f}"))

for fig in (fig1, fig2):
    fig.update_layout(template="plotly_white", title="Sales by city (Rs)", yaxis_range=[0, 3800])
print(fig1.data[0].type, fig2.data[0].type)       # both print: bar
@@END
<p><em>Not run here.</em> Both figures contain one bar trace and draw the same three bars; the last line would print <code>bar bar</code>. <code>text_auto</code> (express) and <code>texttemplate</code> (graph_objects) both put the value on the bar.</p>

<h3>Hover: the feature that justifies plotly</h3>
<p>Hover turns the chart into a lookup tool and lets you keep the chart clean while the detail is one mouse move away. Three levels of control:</p>
<ul><li><code>hover_name="product"</code> puts a bold title in the tooltip; <code>hover_data=["price", "units"]</code> adds columns (or <code>hover_data={"units": ":,.0f", "price": False}</code> to format or hide).</li><li><code>fig.update_traces(hovertemplate=...)</code> gives full control with a template in which <code>%{x}</code>, <code>%{y}</code>, <code>%{customdata[0]}</code> insert values and <code>&lt;br&gt;</code> breaks lines; end with <code>&lt;extra&gt;&lt;/extra&gt;</code> to remove the grey secondary box.</li><li><code>fig.update_layout(hovermode="x unified")</code> shows one tooltip for all lines at the x under the cursor (best for time series); <code>"closest"</code> is the default for scatter.</li></ul>
@@NORUN
import plotly.express as px

fig = px.line(city_m, x="month", y="sales_k", color="city", markers=True)     # city_m: month, city, sales_k
fig.update_traces(hovertemplate="%{x|%b %Y}<br>Rs %{y:,.1f}k<extra>%{fullData.name}</extra>")
fig.update_layout(hovermode="x unified", template="plotly_white")
@@END
<p><em>Not run here.</em> Hovering over March shows "Mar 2025", then a line per city such as "Delhi: Rs 21.7k". <code>%{x|%b %Y}</code> formats a date with the same codes as matplotlib; <code>%{y:,.1f}</code> is a d3 number format (comma, one decimal). <code>%{fullData.name}</code> in <code>&lt;extra&gt;</code> prints the series name.</p>
<h3>Facets and animation</h3>
<p><strong>Facets</strong> are small multiples: add <code>facet_col="category"</code> (and <code>facet_row=</code>, <code>facet_col_wrap=3</code>). Axes are shared so panels compare fairly; to give each panel its own y-range, call <code>fig.update_yaxes(matches=None)</code>. Clean up the panel titles with <code>fig.for_each_annotation(lambda a: a.update(text=a.text.split("=")[-1]))</code>, because express writes "category=Home" by default.</p>
<p><strong>Animation</strong> adds a play button and slider: <code>animation_frame="year"</code> picks the column that defines frames, <code>animation_group="country"</code> says which rows are the same object from frame to frame so the bubble moves instead of jumping. Set the axis ranges yourself (<code>range_x</code>, <code>range_y</code>) or the axes will rescale every frame and the picture will jitter.</p>
@@NORUN
import plotly.express as px

gap = px.data.gapminder()                  # built-in data: country, year, lifeExp, pop, gdpPercap, continent
fig = px.scatter(gap, x="gdpPercap", y="lifeExp", size="pop", color="continent", hover_name="country",
                 log_x=True, size_max=55, range_x=[200, 100000], range_y=[25, 90],
                 animation_frame="year", animation_group="country",
                 labels={"gdpPercap": "GDP per person (US$, log)", "lifeExp": "Life expectancy (years)"})
fig.update_layout(template="plotly_white")
fig.write_html("gapminder.html", include_plotlyjs="cdn")
@@END
<p><em>Not run here.</em> A bubble chart with a Play button and a year slider. Bubbles slide from 1952 to 2007 because <code>animation_group</code> matches each country across frames. Animations are powerful in a live talk and weak on paper: a static small-multiples view of two or three years is almost always clearer to read (Chapter 14 on storytelling).</p>
<h3>Saving and sharing</h3>
@@TABLE
Goal | Code | Notes
Standalone interactive file | <code>fig.write_html("chart.html")</code> | Bundles plotly.js (several megabytes); opens in any browser, works offline
Small HTML that needs internet | <code>fig.write_html("chart.html", include_plotlyjs="cdn")</code> | A few kilobytes of data plus a link to the library
HTML snippet for a web page | <code>fig.to_html(full_html=False, include_plotlyjs="cdn")</code> | Paste the returned string into your page or template
Static image (PNG, SVG, PDF) | <code>fig.write_image("chart.png", scale=2)</code> | Requires <code>pip install kaleido</code>; <code>scale=2</code> doubles the resolution
Save the recipe | <code>fig.write_json("chart.json")</code> then <code>plotly.io.read_json</code> | Good for version control and for regenerating later
In Jupyter | <code>fig.show()</code> | Renderer chosen automatically; <code>pio.renderers.default = "browser"</code> for scripts
@@END
@@CALL red|COMMON MISTAKE|Sending a colleague a notebook screenshot of a plotly chart, which throws away the interactivity, or e-mailing a 4 MB HTML file for a five-bar chart. Wrong: <code>fig.write_html("c.html")</code> as the default for everything. Right: a static PNG (<code>write_image</code>) for slides and e-mail; an HTML file with <code>include_plotlyjs="cdn"</code> or a hosted dashboard for people who need to explore.
<h3>From a chart to an app: Streamlit and Dash</h3>
<p>When one chart is not enough you need <em>controls</em> (a dropdown for city, a date range) that redraw the charts. Two Python frameworks do that without writing JavaScript.</p>
@@TABLE
 | Streamlit | Dash
Idea | The script re-runs top to bottom when a widget changes | You declare a layout and write callbacks: function(Input) returns Output
Learning curve | Very gentle: 15 lines make an app | Steeper: layout and callbacks, closer to a web framework
Charts | <code>st.plotly_chart(fig)</code>, <code>st.pyplot(fig)</code>, <code>st.dataframe</code> | <code>dcc.Graph(figure=fig)</code>
Best for | Analyst prototypes, internal tools | Larger, production-style dashboards, fine control of layout and state
Run | <code>streamlit run app.py</code> | <code>python app.py</code> (local server)
Compared with Power BI | More flexible, needs Python hosting; no built-in security model | Same; Power BI gives governance and sharing out of the box (Chapter 11)
@@END
@@NORUN
# app.py : run with  streamlit run app.py   (not run here)
import pandas as pd
import plotly.express as px
import streamlit as st

st.set_page_config(page_title="Sales", layout="wide")
orders = pd.read_csv("orders.csv", parse_dates=["date"])           # your data file
cities = st.sidebar.multiselect("City", sorted(orders["city"].unique()), default=["Delhi", "Mumbai", "Pune"])
view = orders[orders["city"].isin(cities)]                         # the widget filters the DataFrame

c1, c2, c3 = st.columns(3)
c1.metric("Sales (Rs)", f"{view['amount'].sum():,}")
c2.metric("Orders", f"{len(view):,}")
c3.metric("Average order (Rs)", f"{view['amount'].mean():,.0f}")

monthly = view.groupby(view["date"].dt.to_period("M").dt.to_timestamp())["amount"].sum().reset_index()
st.plotly_chart(px.line(monthly, x="date", y="amount", markers=True, title="Monthly sales"), use_container_width=True)
@@END
<p><em>Not run here.</em> Each time the user changes the City selector, Streamlit re-runs the script, filters <code>orders</code>, recomputes the three numbers and redraws the chart. The pattern to remember is always the same: <strong>widget value, filtered DataFrame, aggregation, figure</strong>. The same aggregation code you use for a static chart is what feeds the interactive one.</p>
@@NORUN
# dash_app.py : run with  python dash_app.py   (not run here)
from dash import Dash, dcc, html, Input, Output
import plotly.express as px

app = Dash(__name__)
app.layout = html.Div([
    dcc.Dropdown(["Delhi", "Mumbai", "Pune"], "Delhi", id="city"),
    dcc.Graph(id="chart"),
])

@app.callback(Output("chart", "figure"), Input("city", "value"))
def update(city):
    view = orders[orders["city"] == city]
    return px.histogram(view, x="amount", nbins=25, title=f"Order sizes in {city}")

if __name__ == "__main__":
    app.run(debug=True)
@@END
<p><em>Not run here.</em> The decorator <code>@app.callback</code> wires the dropdown (Input) to the chart (Output); Dash calls <code>update</code> whenever the dropdown changes and replaces the figure with what the function returns.</p>
<h3>Going deeper: size, speed and security</h3>
<ul><li><strong>Performance:</strong> plotly draws with SVG by default, which gets sluggish above roughly ten thousand points. Use <code>render_mode="webgl"</code> in <code>px.scatter</code> (or <code>go.Scattergl</code>) for up to a few hundred thousand, and aggregate or bin (<code>px.density_heatmap</code>, datashader in 8.13) beyond that. A browser cannot usefully show a million points anyway; a screen has about two million pixels.</li><li><strong>File size:</strong> every point in the chart is inside the HTML. A 100,000-row scatter is a large file and also shares those 100,000 rows with anyone who opens it. Aggregate first when the audience should not see row-level data.</li><li><strong>Templates:</strong> <code>template="plotly_white"</code> is the cleanest default; set once with <code>import plotly.io as pio; pio.templates.default = "plotly_white"</code>. The default plotly colour sequence is not colour-blind-tuned: override with <code>color_discrete_sequence</code> (use the house palette of this chapter).</li><li><strong>Accessibility:</strong> interactive charts are harder for screen readers. Put the headline finding in the page text and give a data table link.</li></ul>
