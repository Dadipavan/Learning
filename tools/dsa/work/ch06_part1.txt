<p>You open a folder on your laptop. Inside are three files and two more folders. Each of those folders has files and folders of its own. You want the total size of everything. You do not know how deep the folders go. Still, the rule is tiny: <em>the size of a folder is the size of its files plus the size of each folder inside it.</em> That one sentence, which uses the word "folder" to explain "folder", is recursion.</p>
<p>Now a second scene. A delivery app has five coupons and you may use any group of them. How many groups are there? Which groups add up to exactly 10 dollars of discount? A chess puzzle asks you to place 8 queens so none attack each other. Sudoku, route planning, password guessing, scheduling: all of them are "try a choice, go deeper, and if it fails, undo the choice and try the next one". That is backtracking, and it is recursion with an undo button.</p>
<p>Recursion is the skill that unlocks trees (Chapter 7), graphs (Chapter 8) and dynamic programming (Chapter 9). Many beginners find it spooky because they try to hold the whole chain of calls in their head. In this chapter you will stop doing that. You will learn to <strong>draw the recursion tree</strong> and trust one small rule. After the chapter you can: write any recursive function from three questions, count its work from the tree, write one backtracking template and bend it to subsets, permutations, combinations, strings, grids and boards, prune and de-duplicate, and turn recursion into a loop with your own stack.</p>
<p>For another take on the same ideas in a lighter style, see also the Computer Science document, Chapter 11. All code here was run in Python 3.14 and the printed outputs are real.</p>

<h2 id="s6-1">6.1 Recursion from Zero: Base Case, Recursive Case and the Call Stack</h2>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt"><strong>Idea in one sentence:</strong> solve a big problem by solving a slightly smaller copy of it, and stop at a case so small that the answer is obvious.<br><strong>Real life:</strong> you stand in a queue and want to know your position. You tap the person in front and ask "what is your position?" They ask the person in front of them, and so on. The first person says "1". Each person then adds 1 on the way back and tells the person behind. Nobody needed the whole picture.</div></div>
<p><strong>Words you need first</strong></p>
<div class="tablewrap"><table class="data"><thead><tr><th>Word</th><th>Plain meaning</th></tr></thead><tbody><tr><td>Recursion</td><td>A function that calls itself on a smaller input</td></tr><tr><td>Base case</td><td>The input so small that the function answers directly, with no further call</td></tr><tr><td>Recursive case</td><td>The part that calls the function again on a smaller input and uses the result</td></tr><tr><td>Call stack</td><td>The pile of unfinished function calls Python keeps in memory. The newest call is on top</td></tr><tr><td>Frame</td><td>One entry in the call stack: the variables of one call, plus where to continue when it finishes</td></tr><tr><td>Depth</td><td>How many calls are stacked up at the same time</td></tr></tbody></table></div>
<h3>How to recognise it</h3>
<ul><li>The data is nested or repeats itself: folders in folders, a tree, a list that is "one item plus a shorter list".</li><li>You can say the answer for size <code>n</code> in terms of the answer for size <code>n - 1</code> (or <code>n / 2</code>).</li><li>You need to try several options and go deeper on each (backtracking).</li><li>The problem says "all possible", "every way", "generate all", "list all".</li></ul>
<h3>The three questions</h3>
<p>Before you write any recursive function, answer these three questions in order. This is the only template you need for plain recursion.</p>
<ol><li><strong>Base case:</strong> for which smallest input do I know the answer without thinking?</li><li><strong>Smaller problem:</strong> what is the same question on a smaller input?</li><li><strong>Combine:</strong> how do I turn the smaller answer into the answer for the big input?</li></ol>
<p>The call stack for <code>fact(4)</code> (factorial: 4 × 3 × 2 × 1) looks like this. Each call waits for the call above it. When <code>fact(1)</code> returns, the waiting calls finish one by one, from the top down.</p>
<figure><img src="images/dsa6_callstack.png" alt="Stack of four boxes for fact(4) to fact(1), arrow up for calls, list of return values 1, 2, 6, 24" loading="lazy"/><figcaption>Figure 6.1: the call stack of fact(4). Calls pile up until the base case, then answers flow back.</figcaption></figure>
<p>How to read it: the teal box is the base case and the only box that answers by itself. Every blue box is "waiting for the box above". The red list on the right is the order in which the boxes finish.</p>
<p>Here is the code, with a print on the way down and on the way back so you can see the stack live. Indentation shows the depth.</p>
@@PY
def fact(n, depth=0):
    pad = "  " * depth
    print(pad + "call fact(" + str(n) + ")")
    if n == 1:                      # base case
        print(pad + "base case, return 1")
        return 1
    smaller = fact(n - 1, depth + 1)   # same question, smaller input
    result = n * smaller               # combine
    print(pad + "fact(" + str(n) + ") = " + str(n) + " * " + str(smaller) + " = " + str(result))
    return result

assert fact(4) == 24
@@END
<p><strong>Trace table</strong> for <code>fact(4)</code>. Read it top to bottom.</p>
<div class="tablewrap"><table class="data"><thead><tr><th>Step</th><th>Event</th><th>Stack after the event (top on the right)</th></tr></thead><tbody><tr><td>1</td><td>call fact(4)</td><td>fact(4)</td></tr><tr><td>2</td><td>call fact(3)</td><td>fact(4), fact(3)</td></tr><tr><td>3</td><td>call fact(2)</td><td>fact(4), fact(3), fact(2)</td></tr><tr><td>4</td><td>call fact(1), base case</td><td>fact(4), fact(3), fact(2), fact(1)</td></tr><tr><td>5</td><td>fact(1) returns 1</td><td>fact(4), fact(3), fact(2)</td></tr><tr><td>6</td><td>fact(2) = 2 * 1 = 2 returns</td><td>fact(4), fact(3)</td></tr><tr><td>7</td><td>fact(3) = 3 * 2 = 6 returns</td><td>fact(4)</td></tr><tr><td>8</td><td>fact(4) = 4 * 6 = 24 returns</td><td>empty</td></tr></tbody></table></div>
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>No base case, or a base case that is never reached.</strong> Wrong: <code>def f(n): return n * f(n - 1)</code>. It never stops, so Python raises <code>RecursionError</code> after about 1000 stacked calls (the default limit). Right: add <code>if n &lt;= 1: return 1</code>. Also check that every recursive call moves <em>toward</em> the base case: <code>f(n + 1)</code> with base case <code>n == 0</code> goes the wrong way.</div></div>
<p>Let us see that error on purpose, safely. We catch it and print only its name.</p>
@@PY
import sys

def broken(n):
    return n * broken(n - 1)      # no base case

try:
    broken(5)
except RecursionError as e:
    print("caught:", type(e).__name__)
print("default limit:", sys.getrecursionlimit())
@@END
<p>The next three problems climb from easy to medium. Each one uses the same three questions.</p>
<p class="problem"><span class="pl">Problem 6.1.1</span> (easy) Return the sum of a list of numbers using recursion, without a loop and without <code>sum()</code>.</p>
<table class="steps"><tr><th>Idea</th><td>The sum of a list is its first item plus the sum of the rest. The sum of an empty list is 0.</td></tr><tr><th>Brute force</th><td>A loop adding one by one: <code>O(n)</code> time, <code>O(1)</code> space. It is already optimal; recursion here is practice only.</td></tr><tr><th>Better approach</th><td>Recursion with an index <code>i</code> instead of slicing. Slicing <code>nums[1:]</code> copies the list each time and makes the whole thing <code>O(n²)</code>.</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>[3, 5, 2]: f(0) = 3 + f(1); f(1) = 5 + f(2); f(2) = 2 + f(3); f(3) = 0 (base). Back: 2, then 7, then 10.</td></tr><tr><th>Complexity</th><td>Time <code>O(n)</code>, space <code>O(n)</code> because n frames are on the stack.</td></tr><tr><th>Edge cases</th><td>Empty list gives 0. One item gives that item. Negative numbers work the same.</td></tr></table>
@@PY
def total(nums, i=0):
    if i == len(nums):           # base case: nothing left
        return 0
    return nums[i] + total(nums, i + 1)

assert total([]) == 0
assert total([7]) == 7
assert total([3, 5, 2]) == 10
assert total([-4, 4, 1]) == 1
print(total([3, 5, 2]))
@@END
<p class="problem"><span class="pl">Problem 6.1.2</span> (medium) Compute x to the power n (n is a whole number, n &gt;= 0) with far fewer multiplications than n.</p>
<table class="steps"><tr><th>Idea</th><td>x<sup>n</sup> = (x<sup>n/2</sup>)<sup>2</sup> when n is even, and x times that when n is odd. The problem halves each time.</td></tr><tr><th>Brute force</th><td>Multiply x by itself n times: <code>O(n)</code> multiplications.</td></tr><tr><th>Better approach</th><td>Halving: about log<sub>2</sub> n levels. Compute the half power <em>once</em> and store it. Calling it twice would bring back <code>O(n)</code> work.</td></tr><tr><th>Code</th><td>Below, with a counter of multiplications.</td></tr><tr><th>Dry run</th><td>power(2, 10) needs power(2, 5), then power(2, 2), then power(2, 1), then power(2, 0) = 1. Back: 2, 4, then 4*4*2 = 32, then 32*32 = 1024.</td></tr><tr><th>Complexity</th><td>Time <code>O(log n)</code>, space <code>O(log n)</code>.</td></tr><tr><th>Edge cases</th><td>n = 0 gives 1 (even 0 to the power 0 is 1 in Python). x = 0 or 1 work. Negative n needs 1 / result.</td></tr></table>
@@PY
calls = 0

def power(x, n):
    global calls
    calls += 1
    if n == 0:
        return 1
    half = power(x, n // 2)      # compute once, reuse
    if n % 2 == 0:
        return half * half
    return half * half * x

assert power(2, 10) == 1024
assert power(3, 0) == 1
assert power(5, 1) == 5
assert power(7, 13) == 7 ** 13
calls = 0
print(power(2, 1000) == 2 ** 1000, "calls:", calls)
@@END
<p class="problem"><span class="pl">Problem 6.1.3</span> (medium) A list may contain numbers and other lists, to any depth. Return one flat list of all the numbers in their original order.</p>
<table class="steps"><tr><th>Idea</th><td>Go through the items. If an item is a number, keep it. If an item is a list, flatten it (same question, smaller input) and keep its result.</td></tr><tr><th>Brute force</th><td>For a known depth of 2 or 3 you could write nested loops, but the depth is unknown, so loops cannot do it directly.</td></tr><tr><th>Better approach</th><td>Recursion matches the shape of the data. One call per list and one step per item.</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>[1, [2, [3]], 4]: keep 1; recurse on [2, [3]]: keep 2, recurse on [3]: keep 3; back, keep 4. Result [1, 2, 3, 4].</td></tr><tr><th>Complexity</th><td>Time <code>O(n)</code> for n numbers plus lists, space <code>O(d)</code> for depth d (plus the output).</td></tr><tr><th>Edge cases</th><td>Empty lists inside ([] gives nothing). A list nested 2000 levels deep would hit the recursion limit.</td></tr></table>
@@PY
def flatten(items):
    out = []
    for x in items:
        if isinstance(x, list):
            out.extend(flatten(x))   # smaller problem
        else:
            out.append(x)            # base: a plain number
    return out

assert flatten([]) == []
assert flatten([1, [2, [3]], 4]) == [1, 2, 3, 4]
assert flatten([[], [[]], 5]) == [5]
print(flatten([1, [2, [3, [4]]], [], 5]))
@@END
<h3>Going deeper</h3>
<ul><li><strong>Each frame costs memory.</strong> A Python frame holds the local variables and the place to resume. That is why depth matters: recursion has <code>O(depth)</code> space even when it looks like it uses no list.</li><li><strong>Python does not remove tail calls.</strong> Some languages turn a call in the last position (a "tail call") into a loop. Python does not, so a tail-recursive function still uses one frame per call. See 6.9 for the loop version.</li><li><strong>Raising the limit</strong> with <code>sys.setrecursionlimit</code> only moves the line. For depths in the tens of thousands, prefer an explicit stack (6.9).</li></ul>
