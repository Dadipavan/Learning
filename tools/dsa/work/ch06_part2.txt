
<h2 id="s6-2">6.2 Recursion Trees, Complexity and a Memo Preview</h2>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt"><strong>Idea in one sentence:</strong> draw every call as a box, and draw an arrow from a call to each call it makes; the total work is the number of boxes times the work inside one box.<br><strong>Real life:</strong> a company email chain. The boss asks two managers, each asks two team leads, and so on. To know how many people were bothered, you count the people in the family tree, not the length of one chain.</div></div>
<h3>How to recognise the shape</h3>
<ul><li><strong>One call inside the function</strong> (like <code>fact</code>): the tree is a single chain. Work is about the depth.</li><li><strong>One call on half the input:</strong> a chain of about log<sub>2</sub> n boxes.</li><li><strong>Two calls on <code>n - 1</code> and <code>n - 2</code>:</strong> a bushy tree that doubles roughly at each level. Exponential.</li><li><strong>A loop that calls the function inside it:</strong> the number of children is the loop size. Think "branching factor".</li></ul>
<p>The famous example is Fibonacci. Each number is the sum of the two before it: fib(0) = 0, fib(1) = 1, fib(n) = fib(n-1) + fib(n-2). The tree for <code>fib(5)</code>:</p>
<figure><img src="images/dsa6_fibtree.png" alt="Recursion tree of fib(5) with 15 nodes; repeated subtrees colored" loading="lazy"/><figcaption>Figure 6.2: the recursion tree of fib(5). Colours mark repeated work.</figcaption></figure>
<p>How to read it: each circle is one call, labelled with its input. Teal circles are base cases. The orange <code>3</code> appears twice and each copy builds its own subtree. The red <code>2</code> appears three times. The program does the same work again and again. Count the circles: 15 calls to get one small number.</p>
<p><strong>Trace table</strong> for the calls of <code>fib(4)</code> in the order Python makes them (depth-first, left child first).</p>
<div class="tablewrap"><table class="data"><thead><tr><th>Call number</th><th>Call</th><th>Depth</th><th>What happens</th></tr></thead><tbody><tr><td>1</td><td>fib(4)</td><td>0</td><td>calls fib(3) first</td></tr><tr><td>2</td><td>fib(3)</td><td>1</td><td>calls fib(2) first</td></tr><tr><td>3</td><td>fib(2)</td><td>2</td><td>calls fib(1) first</td></tr><tr><td>4</td><td>fib(1)</td><td>3</td><td>base case, returns 1</td></tr><tr><td>5</td><td>fib(0)</td><td>3</td><td>base case, returns 0; fib(2) = 1 + 0 = 1</td></tr><tr><td>6</td><td>fib(1)</td><td>2</td><td>base case, returns 1; fib(3) = 1 + 1 = 2</td></tr><tr><td>7</td><td>fib(2)</td><td>1</td><td>calls fib(1)</td></tr><tr><td>8</td><td>fib(1)</td><td>2</td><td>base case, returns 1</td></tr><tr><td>9</td><td>fib(0)</td><td>2</td><td>returns 0; fib(2) = 1; fib(4) = 2 + 1 = 3</td></tr></tbody></table></div>
<p>Nine calls for fib(4), 15 for fib(5). Let us measure how fast the number of calls grows.</p>
@@PY
count = 0

def fib(n):
    global count
    count += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

for n in [4, 5, 10, 20, 25]:
    count = 0
    value = fib(n)
    print("n =", n, " fib =", value, " calls =", count)
@@END
<p>Going from 20 to 25 multiplied the calls by about 11. Each step of +1 in <code>n</code> multiplies the calls by roughly 1.6. That is exponential growth.</p>
<h3>Reading complexity from the tree</h3>
<p>A <strong>recurrence</strong> is a formula for the cost of a call in terms of cheaper calls. Write <code>T(n)</code> for "the work for input size n". Then read the tree.</p>
<div class="tablewrap"><table class="data"><thead><tr><th>Recurrence</th><th>Tree shape</th><th>Time</th><th>Example</th></tr></thead><tbody><tr><td>T(n) = T(n-1) + 1</td><td>chain of n boxes</td><td>O(n)</td><td>fact, total</td></tr><tr><td>T(n) = T(n/2) + 1</td><td>chain of log n boxes</td><td>O(log n)</td><td>power, binary search</td></tr><tr><td>T(n) = 2 T(n/2) + n</td><td>log n levels, each costing n in total</td><td>O(n log n)</td><td>merge sort</td></tr><tr><td>T(n) = T(n-1) + T(n-2) + 1</td><td>bushy, depth n</td><td>O(2<sup>n</sup>) (really about 1.6<sup>n</sup>)</td><td>naive fib</td></tr><tr><td>T(n) = 2 T(n-1) + 1</td><td>binary, depth n</td><td>O(2<sup>n</sup>)</td><td>subsets (6.3)</td></tr><tr><td>T(n) = n T(n-1)</td><td>n children, then n-1, ...</td><td>O(n!)</td><td>permutations (6.4)</td></tr></tbody></table></div>
<div class="callout green"><div class="lab">KEY IDEA</div><div class="txt"><strong>Time = nodes in the tree × work per node. Space = the depth (the longest chain), not the node count.</strong> The stack only holds the calls on the current path from the top to where you are now. Siblings that have finished are gone.</div></div>
<h3>Memo preview: remember answers you already computed</h3>
<p><strong>Memoization</strong> means saving the result of a call in a dictionary so that a repeat call returns instantly. In Python the decorator <code>functools.cache</code> does it for you. This is only a preview; Chapter 9 turns it into a full method.</p>
@@PY
from functools import cache

body_runs = 0

@cache
def fib(n):
    global body_runs
    body_runs += 1               # counts real work, not cache hits
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(25), "body runs:", body_runs)
print(fib(90), "body runs:", body_runs)
@@END
<p>Naive <code>fib(25)</code> made 242,785 calls. With the cache the body ran only 26 times, once per value from 0 to 25. The tree collapsed from bushy to a single chain.</p>
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Using a cache on a function whose answer depends on something else.</strong> Wrong: caching <code>def f(i)</code> when the result also depends on a global list that changes. The cache returns stale answers. Right: cache only <em>pure</em> functions (same inputs always give the same output). Also, a cache needs hashable arguments, so pass a tuple or a number, never a list.</div></div>
<p class="problem"><span class="pl">Problem 6.2.1</span> (medium) You climb a staircase of n steps. Each move is 1 or 2 steps. In how many different orders of moves can you reach the top?</p>
<table class="steps"><tr><th>Idea</th><td>The last move was either 1 step (from step n-1) or 2 steps (from step n-2). So ways(n) = ways(n-1) + ways(n-2). Base: ways(0) = 1 (do nothing), ways(1) = 1.</td></tr><tr><th>Brute force</th><td>The plain recursion above. The tree is the same as the Fibonacci tree: <code>O(2<sup>n</sup>)</code> time.</td></tr><tr><th>Better approach</th><td>Cache each <code>ways(k)</code>: only n + 1 distinct inputs, so <code>O(n)</code> time and <code>O(n)</code> space.</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>ways(4) = ways(3) + ways(2) = 3 + 2 = 5: 1111, 112, 121, 211, 22.</td></tr><tr><th>Complexity</th><td>Time <code>O(n)</code>, space <code>O(n)</code>.</td></tr><tr><th>Edge cases</th><td>n = 0 gives 1; n = 1 gives 1; very large n needs an iterative loop (stack depth).</td></tr></table>
@@PY
from functools import cache

@cache
def ways(n):
    if n <= 1:
        return 1
    return ways(n - 1) + ways(n - 2)

assert ways(0) == 1 and ways(1) == 1 and ways(2) == 2
assert ways(4) == 5
assert ways(10) == 89
print([ways(n) for n in range(1, 11)])
@@END
<p class="problem"><span class="pl">Problem 6.2.2</span> (hard) What is the time complexity of this function? <code>def g(n): if n &lt;= 1: return 1; return g(n // 2) + g(n // 2) + n</code>. Show the tree level by level, then check it by counting the calls.</p>
<table class="steps"><tr><th>Idea</th><td>Two children, each with half the input. Level k has 2<sup>k</sup> nodes of size n / 2<sup>k</sup>. The depth is about log<sub>2</sub> n.</td></tr><tr><th>Brute force</th><td>Guess "two calls means exponential". That is wrong here, because the input halves rather than shrinking by 1.</td></tr><tr><th>Better approach</th><td>Count the nodes: 1 + 2 + 4 + ... + 2<sup>log n</sup> is about 2n. Work per node is constant (one addition). So the total is <code>O(n)</code>. (If each node did <code>n</code> work, as merge sort does, the sum per level would be n and the total n log n.)</td></tr><tr><th>Code</th><td>Below.</td></tr><tr><th>Dry run</th><td>n = 8: 8 -> 4,4 -> 2,2,2,2 -> eight 1s. Nodes: 1 + 2 + 4 + 8 = 15 = 2 * 8 - 1.</td></tr><tr><th>Complexity</th><td>Time <code>O(n)</code>, space <code>O(log n)</code> (depth).</td></tr><tr><th>Edge cases</th><td>When n is not a power of 2, the integer division makes some branches shorter, but the bound stays <code>O(n)</code>.</td></tr></table>
@@PY
count = 0

def g(n):
    global count
    count += 1
    if n <= 1:
        return 1
    return g(n // 2) + g(n // 2) + n

for n in [1, 2, 8, 64, 1024]:
    count = 0
    g(n)
    print("n =", n, " calls =", count)
@@END
<h3>Going deeper</h3>
<ul><li><strong>The master theorem</strong> is a shortcut for recurrences of the form T(n) = a T(n/b) + f(n). The recursion tree method above gives the same answers and is easier to remember: compare the work at the top level, the work per level, and the work at the leaves; whichever dominates wins.</li><li><strong>Why fib is "about 1.6<sup>n</sup>" and not "2<sup>n</sup>".</strong> The tree is lopsided: the right child is always smaller than the left. The growth rate is the golden ratio, roughly 1.618. Interviewers accept <code>O(2<sup>n</sup>)</code> as an upper bound.</li></ul>
