
<h2 id="s6-5">6.5 Combinations, Combination Sum and Pruning</h2>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt"><strong>Idea in one sentence:</strong> choose k items where the order does not matter, by only ever looking forward in the list so that the same group is never built twice.<br><strong>Real life:</strong> picking a 2-person team from 4 colleagues. "Asha and Ben" is the same team as "Ben and Asha". If you always list people in the order they stand in the office, you write each team exactly once.</div></div>
<h3>How to recognise it</h3>
<ul><li>"Choose k from n", "all groups of size k", "combinations".</li><li>"Find all groups that add up to a target". Often the number of items in the group is not fixed.</li><li>Order does not matter: [2, 3] and [3, 2] are the same answer.</li><li>Each candidate may be used once, or many times (read the statement for this).</li></ul>
<h3>The only change from subsets</h3>
<p>Combinations are subsets with a rule for when the path counts as an answer (length equals k, or the sum equals the target). The loop still starts at <code>start</code>, which is what prevents [2, 1] after [1, 2]. If the same item may be reused, recurse with <code>i</code>; if each item may be used once, recurse with <code>i + 1</code>.</p>
@@PY
def combine(n, k):
    result, path = [], []
    def bt(start):
        if len(path) == k:                    # complete answer
            result.append(path[:])
            return
        # Prune: we still need (k - len(path)) items, so the last useful
        # start is n - (k - len(path)) + 1. Beyond that there are too few left.
        for i in range(start, n - (k - len(path)) + 2):
            path.append(i)
            bt(i + 1)
            path.pop()
    bt(1)
    return result

print(combine(4, 2))
@@END

<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Looping from 0 (or 1) every time instead of from <code>start</code>.</strong> Wrong: <code>for i in range(1, n + 1)</code> inside the recursion. You build [1, 2] and also [2, 1]: that is permutations, not combinations, and the answer count is wrong (12 instead of 6 for n = 4, k = 2). Right: <code>for i in range(start, ...)</code> and recurse with <code>i + 1</code>.</div></div>
<h3>Combination sum, drawn</h3>
<p>Now the classic: given distinct positive numbers, list every group that adds up to a target, where a number may be reused. Here is the tree for candidates 2, 3, 5 and target 5. Each edge adds a number. The label in each box is the sum still needed.</p>
<figure><img src="images/dsa6_combosum.png" alt="Search tree for candidates 2,3,5 and target 5, green answers [2,3] and [5], red overshoot nodes" loading="lazy"/><figcaption>Figure 6.5: the combination sum tree (partly drawn). Green boxes are answers, red boxes overshoot.</figcaption></figure>
<p>How to read it: from <code>[]</code> with 5 left, adding 2 leaves 3 left. From <code>[2]</code> we may add 2 again (reuse) or 3. <code>[2, 3]</code> reaches 0 left, so it is an answer. <code>[2, 2, 2]</code> has -1 left: too much, so we stop. Because the candidates are sorted, once one candidate overshoots, all the larger ones overshoot too, so we can stop the whole loop. That is <strong>pruning</strong>.</p>
<div class="callout green"><div class="lab">KEY IDEA</div><div class="txt"><strong>Pruning cuts a whole branch with one test.</strong> If the remaining sum is already negative, no deeper step can fix it (all numbers are positive), so the entire subtree under that node is skipped. The saved work is the size of that subtree, which can be most of the tree. Always ask: "what condition tells me this path is hopeless?"</div></div>
<p class="problem"><span class="pl">Problem 6.5.1</span> (easy) List all combinations of k numbers chosen from 1 to n. Show how much work the pruning bound saves for n = 10, k = 8.</p>
<table class="steps"><tr><th>Idea</th><td>The template above. Count recursive calls with and without the upper bound.</td></tr><tr><th>Brute force</th><td>Generate all subsets of 1..n and keep those of size k: 2<sup>n</sup> subsets.</td></tr><tr><th>Better approach</th><td>Stop each path at length k, and stop looping when too few numbers remain for the rest of the path.</td></tr><tr><th>Code</th><td>Below: two versions that count calls.</td></tr><tr><th>Dry run</th><td>See the trace table for n = 4, k = 2: 6 answers.</td></tr><tr><th>Complexity</th><td>Answers: n choose k. Time <code>O(k × C(n, k))</code>, space <code>O(k)</code>.</td></tr><tr><th>Edge cases</th><td>k = 0 gives [[]]. k = n gives one answer. k &gt; n gives none.</td></tr></table>
@@PY
from math import comb

def count_calls(n, k, prune):
    calls = 0
    found = 0
    path = []
    def bt(start):
        nonlocal calls, found
        calls += 1
        if len(path) == k:
            found += 1
            return
        stop = n - (k - len(path)) + 2 if prune else n + 1
        for i in range(start, stop):
            path.append(i)
            bt(i + 1)
            path.pop()
    bt(1)
    return found, calls

assert count_calls(4, 2, True)[0] == comb(4, 2) == 6
print("no prune:", count_calls(10, 8, False))
print("pruned:  ", count_calls(10, 8, True))
@@END
<p>Both versions find the same 45 answers. The plain one makes 1013 calls and the pruned one only 165, because it never starts a path that cannot reach length 8.</p>
<p class="problem"><span class="pl">Problem 6.5.2</span> (medium) Given distinct positive integers and a target, return all combinations that sum to the target. A number can be used any number of times.</p>
<table class="steps"><tr><th>Idea</th><td>Loop over candidates from <code>start</code>. Choose one, subtract it from the remaining target, and recurse with the <em>same</em> index (reuse allowed). Record when the remaining target is 0.</td></tr><tr><th>Brute force</th><td>Try every multiset of numbers up to length target / smallest and test sums. Huge.</td></tr><tr><th>Better approach</th><td>Sort the candidates. When a candidate is larger than the remaining target, <code>break</code>, since all later ones are larger too. The recursion depth is at most target / smallest.</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>[2, 3, 5], target 5. Choose 2 (3 left), 2 again (1 left): 2 is too big, break. Back, choose 3 from [2] at index 1: 0 left, record [2, 3]. Back to top, choose 3 (2 left): 3 too big, break; choose 5 (0 left), record [5]. Result [[2, 3], [5]].</td></tr><tr><th>Complexity</th><td>Time roughly <code>O(N<sup>T/M</sup>)</code> for N candidates, target T, smallest M; space <code>O(T/M)</code> depth.</td></tr><tr><th>Edge cases</th><td>Target smaller than all candidates gives []. A candidate equal to the target is its own answer.</td></tr></table>
@@PY
def combination_sum(candidates, target):
    candidates = sorted(candidates)
    result, path = [], []
    def bt(start, left):
        if left == 0:
            result.append(path[:])
            return
        for i in range(start, len(candidates)):
            c = candidates[i]
            if c > left:               # prune: this and all later are too big
                break
            path.append(c)
            bt(i, left - c)            # i, not i + 1: reuse allowed
            path.pop()
    bt(0, target)
    return result

assert combination_sum([2, 3, 5], 5) == [[2, 3], [5]]
assert combination_sum([2], 1) == []
assert combination_sum([7], 7) == [[7]]
assert combination_sum([2, 3, 6, 7], 7) == [[2, 2, 3], [7]]
print(combination_sum([2, 3, 5], 8))
@@END
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Mixing up "reuse" and "use once".</strong> Wrong: recursing with <code>i + 1</code> when numbers may repeat (you miss [2, 2, 3]), or recursing with <code>i</code> when each number may be used once (you reuse). Right: read the statement and write the choice in the call: <code>bt(i, ...)</code> for reuse, <code>bt(i + 1, ...)</code> for once.</div></div>
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Using <code>break</code> on an unsorted list.</strong> Wrong: <code>if c &gt; left: break</code> with candidates [5, 2, 3]. The 5 stops the loop and 2 and 3 are never tried. Right: sort first, or use <code>continue</code> (correct but slower).</div></div>
<h3>Going deeper</h3>
<ul><li><strong>Where pruning comes from.</strong> There are three habits: a <em>bound</em> (sum or length too large), a <em>feasibility</em> check (too few items left), and a <em>validity</em> check (the new choice breaks a rule, as in N-Queens in 6.8). Name which one you use when you explain your solution.</li><li><strong>Stronger pruning with bounds.</strong> Optimisation versions ("find the best group") use branch and bound: prune when even the best possible completion cannot beat the best answer found so far.</li></ul>

<h2 id="s6-6">6.6 Handling Duplicates in the Input</h2>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt"><strong>Idea in one sentence:</strong> sort the input, and at each step never start a new branch with a value you already started a branch with at that same step.<br><strong>Real life:</strong> a lunch menu has two identical burgers. Choosing "burger A then salad" or "burger B then salad" gives the same meal. A waiter who treats the two burgers as one item prints each meal once.</div></div>
<h3>How to recognise it</h3>
<ul><li>The statement says the input "may contain duplicates" and the answer must be "unique" or "without duplicate groups".</li><li>You get repeated answers like [1, 2] twice when you run the basic template.</li></ul>
<figure><img src="images/dsa6_dups.png" alt="Subset tree for 1,2,2 with the second 2 at the same level crossed out in red" loading="lazy"/><figcaption>Figure 6.6: subsets of the sorted list [1, 2, 2]. Red dashed branches would only repeat answers.</figcaption></figure>
<p>How to read it: the green solid edges are explored. At the root, there are two 2s in the list. The first 2 is allowed to start a branch. The second 2 would start a branch giving exactly the same subsets, so it is skipped (red dashed). Inside <code>[1]</code> the same thing happens. Notice that <code>[2, 2]</code> is still found: the second 2 is allowed <em>deeper</em>, where it is the first choice of its own level.</p>
<h3>The rule, in one line</h3>
<p>After sorting, inside the loop add: <code>if i &gt; start and nums[i] == nums[i - 1]: continue</code>. Read it as: "this value is the same as the one I just tried at this level, and it is not the first item of this level".</p>
@@PY
def subsets_unique(nums):
    nums = sorted(nums)                      # equal values become neighbours
    result, path = [], []
    def bt(start):
        result.append(path[:])
        for i in range(start, len(nums)):
            if i > start and nums[i] == nums[i - 1]:
                continue                     # same value already tried at this level
            path.append(nums[i])
            bt(i + 1)
            path.pop()
    bt(0)
    return result

assert subsets_unique([]) == [[]]
assert subsets_unique([3, 3, 3]) == [[], [3], [3, 3], [3, 3, 3]]
assert len(subsets_unique([4, 4, 1, 4])) == 8
print(subsets_unique([2, 1, 2]))
@@END

<p class="problem"><span class="pl">Problem 6.6.1</span> (medium) Return all distinct orderings of a list that may contain repeated numbers, for example [1, 1, 2] has only 3 distinct orderings.</p>
<table class="steps"><tr><th>Idea</th><td>Sort. Use the <code>used</code> array from 6.4. Skip a value if it equals the previous value and that previous copy is not currently in the path. This forces equal copies to be placed left to right, in order.</td></tr><tr><th>Brute force</th><td>Generate all n! permutations, put them in a set. For [1, 1, 2, 2, 3, 3] that is 720 generated and 90 kept.</td></tr><tr><th>Better approach</th><td>The rule prevents the duplicates from ever being built.</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>[1, 1, 2]: at seat 1, index 0 (value 1) is chosen. Index 1 (value 1) has an equal previous item that is unused, so it is skipped at this seat. Index 2 is chosen. So seat 1 is 1 or 2 only, not 1 twice.</td></tr><tr><th>Complexity</th><td>Time <code>O(n × n!)</code> worst case, space <code>O(n)</code>.</td></tr><tr><th>Edge cases</th><td>All equal values give one answer. A single item gives one answer.</td></tr></table>
@@PY
def permutations_unique(nums):
    nums = sorted(nums)
    result, path = [], []
    used = [False] * len(nums)
    def bt():
        if len(path) == len(nums):
            result.append(path[:])
            return
        for i in range(len(nums)):
            if used[i]:
                continue
            # equal twin to the left is still unused: placing this one would repeat an answer
            if i > 0 and nums[i] == nums[i - 1] and not used[i - 1]:
                continue
            used[i] = True
            path.append(nums[i])
            bt()
            path.pop()
            used[i] = False
    bt()
    return result

assert permutations_unique([1, 1, 2]) == [[1, 1, 2], [1, 2, 1], [2, 1, 1]]
assert permutations_unique([5, 5]) == [[5, 5]]
assert len(permutations_unique([1, 1, 2, 2, 3, 3])) == 90
print(permutations_unique([2, 1, 1]))
@@END
<p class="problem"><span class="pl">Problem 6.6.2</span> (hard) Candidates may repeat, and each candidate (each position in the list) may be used at most once. Return all distinct groups that sum to a target.</p>
<table class="steps"><tr><th>Idea</th><td>Combination sum (6.5) with <code>i + 1</code> for single use, plus the duplicate skip rule from this section, plus the sorted <code>break</code> prune.</td></tr><tr><th>Brute force</th><td>Generate all subsets, keep the ones that sum correctly, remove repeats with a set: <code>O(n 2<sup>n</sup>)</code>.</td></tr><tr><th>Better approach</th><td>Three cuts together: overshoot (<code>break</code>), duplicates (<code>continue</code>), single use (<code>i + 1</code>).</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>[1, 1, 2, 5], target 4. Choose 1 (3 left). Choose the second 1, which is allowed because it is the first choice at its own level (2 left). Choose 2 (0 left): record [1, 1, 2]. Back one level, choose 2 instead of the second 1: [1, 2] has 1 left, and 5 breaks. At the top level the second 1 repeats the first 1, so it is skipped. Starting with 2 leaves 2, and 5 breaks. Result [[1, 1, 2]].</td></tr><tr><th>Complexity</th><td>Time <code>O(2<sup>n</sup>)</code> worst case, space <code>O(n)</code>.</td></tr><tr><th>Edge cases</th><td>Target unreachable gives []. All items equal to the target give a single answer [[t]].</td></tr></table>
@@PY
def combination_sum2(nums, target):
    nums = sorted(nums)
    result, path = [], []
    def bt(start, left):
        if left == 0:
            result.append(path[:])
            return
        for i in range(start, len(nums)):
            if nums[i] > left:                          # too big: stop the loop
                break
            if i > start and nums[i] == nums[i - 1]:    # repeat at this level
                continue
            path.append(nums[i])
            bt(i + 1, left - nums[i])                   # once only
            path.pop()
    bt(0, target)
    return result

assert combination_sum2([1, 1, 2, 5], 4) == [[1, 1, 2]]
assert combination_sum2([2, 5, 2, 1, 2], 5) == [[1, 2, 2], [5]]
assert combination_sum2([3, 3, 3], 3) == [[3]]
assert combination_sum2([4], 3) == []
print(combination_sum2([10, 1, 2, 7, 6, 1, 5], 8))
@@END
<h3>Going deeper</h3>
<ul><li><strong>Why the used-flag rule works for permutations.</strong> Among equal values we force a fixed order: the second copy can only be placed once the first copy is already in the path. Each distinct ordering then arises exactly once.</li><li><strong>Counting without generating.</strong> The number of distinct orderings of a multiset is n! divided by the factorial of each repeat count. For [1, 1, 2, 2, 3, 3] that is 720 / (2 × 2 × 2) = 90, matching the assert above.</li><li><strong>Set of tuples as a fallback.</strong> In an interview, if you cannot remember the rule, say "I can dedupe with a set of tuples, then I will show the sorted skip rule". That is a clean path from brute force to the better method.</li></ul>
