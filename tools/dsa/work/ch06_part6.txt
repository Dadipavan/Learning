
<h2>Chapter recap</h2>
<ul>
<li>Recursion needs three answers: the <strong>base case</strong>, the <strong>smaller problem</strong>, and how to <strong>combine</strong>. Check that every call moves toward the base case.</li>
<li>The <strong>call stack</strong> holds one frame per unfinished call. Space used by recursion is the depth of the tree, not the number of nodes. Python's default limit is about 1000 frames.</li>
<li>Draw the <strong>recursion tree</strong>: time is nodes times work per node. Two calls on <code>n - 1</code> and <code>n - 2</code> give an exponential tree; halving gives a chain of <code>log n</code>.</li>
<li>If the same input appears in many nodes, <strong>cache</strong> the result (memoization). That is the bridge to Chapter 9.</li>
<li>Backtracking template: record or stop, loop over choices, skip invalid ones, <strong>choose, explore, unchoose</strong>. Always record a <strong>copy</strong> of the path.</li>
<li>Subsets use a <code>start</code> index. Permutations use a <code>used</code> array. Combinations use <code>start</code> plus a size or sum goal.</li>
<li><strong>Reuse</strong> means recurse with <code>i</code>; <strong>use once</strong> means recurse with <code>i + 1</code>.</li>
<li><strong>Prune</strong> with a bound (sum too big), feasibility (too few items left) or validity (rule broken). Sorted candidates allow a cheap <code>break</code>.</li>
<li><strong>Duplicates:</strong> sort, then skip <code>nums[i]</code> if <code>i &gt; start</code> and it equals <code>nums[i - 1]</code>. For permutations, also use the used-flag rule.</li>
<li>Grids need bounds checks first and a mark that is undone. Boards (N-Queens, sudoku) need an <code>O(1)</code> safety test.</li>
<li>Deep recursion becomes a loop with your own stack, or a bitmask for subsets.</li>
</ul>

<p class="problem"><span class="pl">Problem 6.10.9</span> (medium) State the time and space of generating all permutations of n distinct items. Why is the stack space <code>O(n)</code> even though there are n! answers?</p>
<p><strong>Answer:</strong> time <code>O(n × n!)</code>: n! leaves, and each answer costs up to n to copy. Stack space is the depth of the tree, which is n, plus the <code>path</code> and <code>used</code> lists of size n. The n! answers live in the result list, which is output, not working space. Say "auxiliary space <code>O(n)</code>, output <code>O(n × n!)</code>" to be exact.</p>

<p class="problem"><span class="pl">Problem 6.10.10</span> (medium) Generate all binary strings of length n that have no two neighbouring 1s. For n = 3 there should be five.</p>
<p><strong>Answer:</strong> at each position the choices are 0 (always allowed) and 1 (only if the previous character is not 1). That check is the prune.</p>
@@PY
def no_adjacent_ones(n):
    result, path = [], []
    def bt():
        if len(path) == n:
            result.append("".join(path))
            return
        path.append("0")
        bt()
        path.pop()
        if not path or path[-1] != "1":          # prune
            path.append("1")
            bt()
            path.pop()
    bt()
    return result

assert no_adjacent_ones(3) == ["000", "001", "010", "100", "101"]
assert [len(no_adjacent_ones(k)) for k in range(1, 8)] == [2, 3, 5, 8, 13, 21, 34]
print(no_adjacent_ones(3))
@@END
<p>The counts 2, 3, 5, 8, 13 are Fibonacci numbers: a string either ends in 0 (any valid string of length n-1 before it) or ends in 01 (any valid string of length n-2 before that).</p>

<p class="problem"><span class="pl">Problem 6.10.11</span> (medium) Count the routes from the top-left to the bottom-right corner of a grid with r rows and c columns, moving only right or down. First write the plain recursion, then add a cache.</p>
<p><strong>Answer:</strong> the last move into the corner came from above or from the left, so routes(r, c) = routes(r-1, c) + routes(r, c-1), with routes = 1 when r = 1 or c = 1 (a single line). Plain recursion has a Fibonacci-like tree (exponential); the cache makes it <code>O(r × c)</code>. The closed form is C(r + c - 2, r - 1).</p>
@@PY
from functools import cache
from math import comb

@cache
def routes(r, c):
    if r == 1 or c == 1:
        return 1
    return routes(r - 1, c) + routes(r, c - 1)

assert routes(3, 3) == 6 == comb(4, 2)
assert routes(3, 7) == 28 == comb(8, 2)
assert routes(18, 18) == comb(34, 17)
print(routes(3, 3), routes(3, 7), routes(18, 18))
@@END

<p class="problem"><span class="pl">Problem 6.10.12</span> (medium) Given a string such as "a1b", return every string you get by changing the case of each letter independently (digits stay). For "a1b" the answer has 4 strings.</p>
<p><strong>Answer:</strong> walk along the string. A digit has one option; a letter has two (lower, upper). The count is 2 to the number of letters.</p>
@@PY
def case_variants(s):
    result, path = [], []
    def bt(i):
        if i == len(s):
            result.append("".join(path))
            return
        options = {s[i].lower(), s[i].upper()}       # one option for a digit
        for ch in sorted(options, reverse=True):     # lowercase first
            path.append(ch)
            bt(i + 1)
            path.pop()
    bt(0)
    return result

assert case_variants("a1b") == ["a1b", "a1B", "A1b", "A1B"]
assert case_variants("12") == ["12"]
assert len(case_variants("abcd")) == 16
print(case_variants("a1b"))
@@END

<p class="problem"><span class="pl">Problem 6.10.13</span> (medium, interview) Why does the subsets code use a <code>start</code> index while the permutations code uses a <code>used</code> array?</p>
<p><strong>Answer:</strong> in subsets, order does not matter, so {1, 3} must be built once, as 1 then 3, never as 3 then 1. A start index that only moves forward guarantees that. In permutations, order matters and every item must appear exactly once, but in any order, so each seat may take any item that is not yet placed. The <code>used</code> array records "already placed" without limiting the order. Combinations share the <code>start</code> idea with subsets; arrangements share the <code>used</code> idea with permutations.</p>

<p class="problem"><span class="pl">Problem 6.10.14</span> (hard) Give every number a plus or a minus sign. Count the sign choices that make the total equal a target. For [1, 1, 1, 1, 1] and target 3, how many? Use a cache.</p>
<p><strong>Answer:</strong> each number has two choices, so 2<sup>n</sup> leaves without a cache. The state is (index, running total); equal states give equal futures, so cache on that pair. For five ones and target 3, you need four +1 and one -1: 5 positions for the minus sign, so 5 ways.</p>
@@PY
from functools import cache

def target_sum_ways(nums, target):
    nums = tuple(nums)
    @cache
    def go(i, total):
        if i == len(nums):
            return 1 if total == target else 0
        return go(i + 1, total + nums[i]) + go(i + 1, total - nums[i])
    return go(0, 0)

assert target_sum_ways([1, 1, 1, 1, 1], 3) == 5
assert target_sum_ways([1], 1) == 1
assert target_sum_ways([1], 2) == 0
assert target_sum_ways([], 0) == 1
print(target_sum_ways([1, 1, 1, 1, 1], 3))
@@END

<p class="problem"><span class="pl">Problem 6.10.15</span> (hard) Can a list of positive whole numbers be split into two groups with equal sums? Examples: [1, 5, 11, 5] yes (11 and 1 + 5 + 5); [1, 2, 3, 5] no.</p>
<p><strong>Answer:</strong> if the total is odd, the answer is no at once (prune). Otherwise ask whether some subset sums to total / 2. Take or skip each number with the remaining target, and cache on (index, left).</p>
@@PY
from functools import cache

def can_split(nums):
    total = sum(nums)
    if total % 2:
        return False
    nums = tuple(sorted(nums, reverse=True))     # big numbers first prune sooner
    @cache
    def go(i, left):
        if left == 0:
            return True
        if i == len(nums) or left < 0:
            return False
        return go(i + 1, left - nums[i]) or go(i + 1, left)
    return go(0, total // 2)

assert can_split([1, 5, 11, 5]) is True
assert can_split([1, 2, 3, 5]) is False
assert can_split([]) is True
assert can_split([3]) is False
print(can_split([1, 5, 11, 5]), can_split([1, 2, 3, 5]))
@@END

<p class="problem"><span class="pl">Problem 6.10.16</span> (hard) Write <code>next_permutation(nums)</code> that rearranges the list into the next larger ordering in dictionary order (and into the smallest ordering if it is already the largest), in place, in <code>O(n)</code>. Examples: [1, 2, 3] becomes [1, 3, 2]; [3, 2, 1] becomes [1, 2, 3]; [1, 1, 5] becomes [1, 5, 1].</p>
<p><strong>Answer:</strong> (1) from the right, find the first position <code>i</code> where <code>nums[i] &lt; nums[i + 1]</code>. The suffix after it is in decreasing order, the largest it can be. (2) If none exists, reverse everything. (3) Otherwise, from the right find the first value larger than <code>nums[i]</code>, swap the two, then reverse the suffix after <code>i</code> so it becomes the smallest possible.</p>
@@PY
def next_permutation(nums):
    i = len(nums) - 2
    while i >= 0 and nums[i] >= nums[i + 1]:     # find the pivot
        i -= 1
    if i >= 0:
        j = len(nums) - 1
        while nums[j] <= nums[i]:                # first larger value from the right
            j -= 1
        nums[i], nums[j] = nums[j], nums[i]
    nums[i + 1:] = reversed(nums[i + 1:])        # smallest suffix
    return nums

assert next_permutation([1, 2, 3]) == [1, 3, 2]
assert next_permutation([3, 2, 1]) == [1, 2, 3]
assert next_permutation([1, 1, 5]) == [1, 5, 1]
assert next_permutation([1, 3, 2]) == [2, 1, 3]
assert next_permutation([7]) == [7]
print(next_permutation([1, 3, 2]), next_permutation([1, 1, 5]))
@@END

<p class="problem"><span class="pl">Problem 6.10.18</span> (hard) Count N-Queens solutions faster by using three integers as bitmasks instead of three sets. Verify n = 8 gives 92 and print the counts for n = 1 to 9.</p>
<p><strong>Answer:</strong> in <code>cols</code>, bit <code>c</code> is 1 if column <code>c</code> is taken. For the two diagonals, shift the mask by one bit per row so that it always lines up with the current row. <code>free = full &amp; ~(cols | d1 | d2)</code> holds all safe squares; <code>free &amp; -free</code> extracts the lowest set bit.</p>
@@PY
def count_queens(n):
    full = (1 << n) - 1
    def bt(cols, d1, d2):
        if cols == full:
            return 1
        total = 0
        free = full & ~(cols | d1 | d2)          # bits of safe columns
        while free:
            bit = free & -free                   # lowest safe column
            free -= bit
            total += bt(cols | bit, ((d1 | bit) << 1) & full, (d2 | bit) >> 1)
        return total
    return bt(0, 0, 0)

assert count_queens(8) == 92
print([count_queens(n) for n in range(1, 10)])
@@END

<p class="problem"><span class="pl">Problem 6.10.19</span> (hard) Given a string of digits and a target, put "+", "-" or nothing between the digits so that the expression equals the target. Numbers may not have leading zeros (the single digit "0" is allowed). Return all expressions. Example: "105" and target 5 gives ["10-5"].</p>
<p><strong>Answer:</strong> cut-style recursion. Choose the next number as <code>s[start:end]</code> (skip pieces with a leading zero), then choose "+" or "-" before the next one. The first number has no sign. Keep the running total.</p>
@@PY
def add_signs(s, target):
    result = []
    def bt(start, total, expr):
        if start == len(s):
            if total == target:
                result.append(expr)
            return
        for end in range(start + 1, len(s) + 1):
            piece = s[start:end]
            if len(piece) > 1 and piece[0] == "0":      # leading zero: stop growing
                break
            v = int(piece)
            if start == 0:
                bt(end, v, piece)
            else:
                bt(end, total + v, expr + "+" + piece)
                bt(end, total - v, expr + "-" + piece)
    bt(0, 0, "")
    return result

assert add_signs("105", 5) == ["10-5"]
assert add_signs("123", 6) == ["1+2+3"]
assert add_signs("00", 0) == ["0+0", "0-0"]
assert add_signs("9", 8) == []
print(add_signs("105", 5), add_signs("00", 0))
@@END

<p class="problem"><span class="pl">Problem 6.10.20</span> (hard, interview) You have 40 coupons with different values. The interviewer asks: "can some of them add up to exactly 1000?" Backtracking over subsets would do about 2<sup>40</sup> steps. What do you say?</p>
<p><strong>Answer:</strong> 2<sup>40</sup> is about 1.1 × 10<sup>12</sup>, far too slow. I say: first, clarify whether the values are whole numbers and how large they are. If the target is small (1000), use dynamic programming over (index, reachable sum): 40 × 1001 states, as in Problem 6.10.15 and Chapter 9. If the values are huge, use meet in the middle: split the coupons into two halves of 20, list all 2<sup>20</sup> (about a million) subset sums of each half, sort one list, and look up the complement of every sum of the other half. That is about 2<sup>20</sup> × 20 steps. The point is to recognise when "all subsets" is the wrong plan, and to name the fix.</p>
