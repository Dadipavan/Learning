
<h2 id="s6-7">6.7 Backtracking on Strings: Letter Combinations, Palindrome Partitions and IP Addresses</h2>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt"><strong>Idea in one sentence:</strong> walk along the string; at each position either pick one letter from a small set (letter combinations) or choose where to cut (partitions).<br><strong>Real life:</strong> an old phone keypad. Typing 2 then 3 could mean "ad", "ae", "af", "bd" and so on, because key 2 stands for a, b or c and key 3 for d, e or f. A spell checker tries all nine and keeps real words.</div></div>
<h3>How to recognise it</h3>
<ul><li><strong>Letter-style:</strong> every position has its own small list of options, and the answers are all the strings made by choosing one option per position. The answer count is the product of the option counts.</li><li><strong>Cut-style:</strong> "split the string into pieces such that every piece satisfies a rule" (palindromes, valid numbers, dictionary words). The choice is the length of the next piece.</li><li>The input length is small (about 15 to 20 characters at most for cut-style problems).</li></ul>
<figure><img src="images/dsa6_letters.png" alt="Tree for digits 2 and 3: root, three letters a b c, then nine leaves" loading="lazy"/><figcaption>Figure 6.7: letter combinations for the digits "23". Level 1 picks a letter for 2, level 2 picks one for 3.</figcaption></figure>
<p>How to read it: the tree is as deep as the number of digits. The first level has three children (a, b, c), and each of those has three children (d, e, f). Nine leaves means 3 × 3 combinations. The tree is wide but shallow.</p>
<p class="problem"><span class="pl">Problem 6.7.1</span> (easy) Given a string of digits 2 to 9, return all letter strings it could spell on a phone keypad (2 = abc, 3 = def, 4 = ghi, 5 = jkl, 6 = mno, 7 = pqrs, 8 = tuv, 9 = wxyz). An empty input gives an empty list.</p>
<table class="steps"><tr><th>Idea</th><td>Position <code>i</code> is the digit being decoded. The choices are the letters of that digit. When the path is as long as the input, record it.</td></tr><tr><th>Brute force</th><td>Nested loops, one per digit. That only works if you know the number of digits in advance.</td></tr><tr><th>Better approach</th><td>Recursion supplies "one loop per digit" for any length.</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>"23": path [] at i = 0; choose a; at i = 1 choose d, record "ad"; unchoose d, choose e, record "ae"; f gives "af". Back, unchoose a, choose b, and so on. Total 9.</td></tr><tr><th>Complexity</th><td>Time <code>O(4<sup>n</sup> × n)</code> worst case (digits 7 and 9 have 4 letters), space <code>O(n)</code> plus output.</td></tr><tr><th>Edge cases</th><td>Empty string returns [] (not [""]). One digit returns its letters.</td></tr></table>
@@PY
KEYS = {"2": "abc", "3": "def", "4": "ghi", "5": "jkl",
        "6": "mno", "7": "pqrs", "8": "tuv", "9": "wxyz"}

def letter_combinations(digits):
    if not digits:
        return []
    result, path = [], []
    def bt(i):
        if i == len(digits):
            result.append("".join(path))
            return
        for ch in KEYS[digits[i]]:
            path.append(ch)          # choose
            bt(i + 1)                # explore
            path.pop()               # unchoose
    bt(0)
    return result

assert letter_combinations("") == []
assert letter_combinations("2") == ["a", "b", "c"]
assert len(letter_combinations("79")) == 16
assert letter_combinations("23") == ["ad", "ae", "af", "bd", "be", "bf", "cd", "ce", "cf"]
print(letter_combinations("23"))
@@END
<p class="problem"><span class="pl">Problem 6.7.2</span> (medium) Split a string into pieces so that every piece is a palindrome. Return all ways.</p>
<table class="steps"><tr><th>Idea</th><td>At position <code>start</code>, try every end position <code>end</code>. If <code>s[start:end]</code> is a palindrome, choose it as a piece and continue from <code>end</code>. When <code>start</code> reaches the end of the string, record the pieces.</td></tr><tr><th>Brute force</th><td>Try every set of cut positions (2<sup>n-1</sup> ways) and test each piece.</td></tr><tr><th>Better approach</th><td>Test the piece as soon as it is cut. A non-palindrome piece prunes everything after it. (A table of palindrome flags, Chapter 9, makes the test <code>O(1)</code>.)</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>"aab": cut "a" (palindrome), then "a", then "b", start reaches 3: record [a, a, b]. Back: from start 1, "ab" is not a palindrome. Back to start 0: cut "aa", then "b": record [aa, b]. Cut "aab": not a palindrome. Result [[a, a, b], [aa, b]].</td></tr><tr><th>Complexity</th><td>Time <code>O(n 2<sup>n</sup>)</code> worst case (a string of one repeated letter), space <code>O(n)</code>.</td></tr><tr><th>Edge cases</th><td>One letter gives [[letter]]. A string of all the same letter gives 2<sup>n-1</sup> answers.</td></tr></table>
<p><strong>Trace table</strong> for "aab".</p>

@@PY
def palindrome_partitions(s):
    result, path = [], []
    def bt(start):
        if start == len(s):                       # all characters used
            result.append(path[:])
            return
        for end in range(start + 1, len(s) + 1):
            piece = s[start:end]
            if piece != piece[::-1]:              # prune: not a palindrome
                continue
            path.append(piece)
            bt(end)
            path.pop()
    bt(0)
    return result

assert palindrome_partitions("a") == [["a"]]
assert palindrome_partitions("aab") == [["a", "a", "b"], ["aa", "b"]]
assert len(palindrome_partitions("aaaa")) == 8
print(palindrome_partitions("aab"))
print(palindrome_partitions("abba"))
@@END
<p class="problem"><span class="pl">Problem 6.7.3</span> (hard) A string of digits is given. Insert three dots to make a valid IPv4 address (four parts, each between 0 and 255, no leading zeros except the single digit "0"). Return all valid addresses.</p>
<table class="steps"><tr><th>Idea</th><td>Cut-style: choose the length (1, 2 or 3) of the next part. Four parts must use all the characters.</td></tr><tr><th>Brute force</th><td>Try every triple of dot positions: C(n - 1, 3) ways, then validate each.</td></tr><tr><th>Better approach</th><td>Validate each part when cutting it. Prune if the remaining characters cannot fill the remaining parts: the rest must be between 1 and 3 characters per missing part.</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>"25525511135": parts 255, 255, 11, 135 uses all 11 characters: valid. Parts 255, 255, 111, 35 also valid. A part "025" is rejected for its leading zero.</td></tr><tr><th>Complexity</th><td>At most 3<sup>4</sup> = 81 paths, so <code>O(1)</code> for a fixed 4 parts.</td></tr><tr><th>Edge cases</th><td>Fewer than 4 or more than 12 digits give []. "0000" gives only 0.0.0.0.</td></tr></table>
@@PY
def restore_ips(s):
    result, parts = [], []
    def valid(p):
        if len(p) > 1 and p[0] == "0":     # no leading zero
            return False
        return int(p) <= 255
    def bt(start):
        left_parts = 4 - len(parts)
        left_chars = len(s) - start
        if left_chars < left_parts or left_chars > 3 * left_parts:
            return                          # prune: impossible to finish
        if left_parts == 0:
            result.append(".".join(parts))
            return
        for size in (1, 2, 3):
            p = s[start:start + size]
            if len(p) < size or not valid(p):
                continue
            parts.append(p)
            bt(start + size)
            parts.pop()
    bt(0)
    return result

assert restore_ips("25525511135") == ["255.255.11.135", "255.255.111.35"]
assert restore_ips("0000") == ["0.0.0.0"]
assert restore_ips("111") == []
assert restore_ips("1111111111111") == []
print(restore_ips("101023"))
@@END
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Returning <code>[""]</code> for empty digits, or forgetting the empty case.</strong> With the "record when the path is full" rule, empty input records one empty string. Many problems define the answer as an empty list. Read the statement and add <code>if not digits: return []</code> as the first line.</div></div>
<h3>Going deeper</h3>
<ul><li><strong>Cut-style generalises to word break.</strong> "Split the string into dictionary words" is the same code with <code>piece in words</code> as the test. Listing all splits is backtracking, only counting or testing is dynamic programming (Chapter 9).</li><li><strong>Generators.</strong> If the caller needs only the first answer, write the backtracking as a generator with <code>yield</code> and stop early; this avoids building the whole list.</li></ul>

<h2 id="s6-8">6.8 Grids and Boards: Word Search, N-Queens and Sudoku Awareness</h2>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt"><strong>Idea in one sentence:</strong> the "choices" are moves on a grid or squares on a board; the "undo" is un-marking a cell or removing a piece.<br><strong>Real life:</strong> finding a word in a letter puzzle with your finger: you slide to a neighbour, and if the path fails, you slide back. You are not allowed to reuse a cell in the same word, so you need a mark that means "my finger is here already".</div></div>
<h3>How to recognise it</h3>
<ul><li>A 2D grid and a path or placement: "does the word exist in the grid", "count the ways to place pieces", "fill the board".</li><li>A cell may not be reused in one path (needs a visited mark that is undone on the way back).</li><li>The constraint is local and can be checked at once (same row, column, diagonal, box).</li></ul>
<h3>Word search</h3>
<figure><img src="images/dsa6_wordsearch.png" alt="3 by 3 grid CAR ATE DOG with arrows tracing the word CATE from C down to A, right to T, right to E" loading="lazy"/><figcaption>Figure 6.8: finding CATE in the grid. The path uses each cell once.</figcaption></figure>
<p>How to read it: the green cells are the path, the orange arrows the moves. The algorithm tries the four neighbours in a fixed order (down, right, up, left). It meets D (below A) and O (below T), which do not match, and backs away from each before it goes right.</p>

<p class="problem"><span class="pl">Problem 6.8.1</span> (medium) Given a grid of letters and a word, say whether the word can be traced through neighbouring cells (up, down, left, right), using each cell at most once.</p>
<table class="steps"><tr><th>Idea</th><td>Try every cell as a start. From a cell that matches the current letter, mark it, try the four neighbours for the next letter, then unmark it (backtrack).</td></tr><tr><th>Brute force</th><td>Generate all paths of length len(word) from every cell: about 4 × 3<sup>L-1</sup> paths each, then compare letters at the end.</td></tr><tr><th>Better approach</th><td>Stop the moment a letter does not match. Wrong branches die after one step. Marking by temporarily changing the cell to <code>"#"</code> saves a separate visited array.</td></tr><tr><th>Code</th><td>Below, tested with asserts.</td></tr><tr><th>Dry run</th><td>See the trace table for CATE. The word "CAB" fails: C, A, then no B in the neighbours, then every other start fails too.</td></tr><tr><th>Complexity</th><td>Time <code>O(R × C × 3<sup>L</sup>)</code> for R rows, C columns, word length L; space <code>O(L)</code> depth.</td></tr><tr><th>Edge cases</th><td>One-letter word. Word longer than the number of cells. A word that would reuse a cell, such as "ABA" in a single row "AB".</td></tr></table>
@@PY
def exists(grid, word):
    rows, cols = len(grid), len(grid[0])
    moves = [(1, 0), (0, 1), (-1, 0), (0, -1)]       # down, right, up, left

    def dfs(r, c, k):
        # check bounds FIRST: a negative index would wrap around in Python
        if r < 0 or r >= rows or c < 0 or c >= cols:
            return False
        if grid[r][c] != word[k]:
            return False
        if k == len(word) - 1:
            return True
        saved = grid[r][c]
        grid[r][c] = "#"                              # choose: mark visited
        for dr, dc in moves:
            if dfs(r + dr, c + dc, k + 1):
                grid[r][c] = saved                    # leave the grid unchanged
                return True
        grid[r][c] = saved                            # unchoose
        return False

    return any(dfs(r, c, 0) for r in range(rows) for c in range(cols))

g = [list("CAR"), list("ATE"), list("DOG")]
assert exists(g, "CATE") and exists(g, "CAR") and exists(g, "DOG")
assert not exists(g, "CAB")
assert not exists([list("AB")], "ABA")
assert g == [list("CAR"), list("ATE"), list("DOG")]
print(exists(g, "CATE"), exists(g, "CAB"), exists([list("AB")], "ABA"))
@@END

<h3>N-Queens</h3>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt"><strong>Idea in one sentence:</strong> place queens one row at a time; a queen is safe if no earlier queen shares its column or either diagonal.<br><strong>Real life:</strong> seating guests at a round of tables where some pairs must not see each other. You seat one guest per table and as soon as someone is in view of a rival, you re-seat the last person.</div></div>
<p>A queen attacks along its row, column and both diagonals. Place exactly one queen in each row, so rows never clash. We only need to remember three things: which <strong>columns</strong> are used, which <strong>down-right diagonals</strong> (cells with the same <code>row - col</code>), and which <strong>down-left diagonals</strong> (same <code>row + col</code>). Three sets give an <code>O(1)</code> safety test.</p>
<figure><img src="images/dsa6_nqueens.png" alt="Left: 4 by 4 board with queens in columns 1,3,0,2. Right: dead end board where the third row is fully attacked" loading="lazy"/><figcaption>Figure 6.9: left, the solution with columns 1, 3, 0, 2. Right, a dead end that forces a backtrack.</figcaption></figure>
<p>How to read it: on the right, queens at row 0 column 0 and row 1 column 2 attack every square of row 2 (pink). The search cannot continue, so it removes the queen of row 1 and tries its next column. This is why backtracking beats trying all boards: dead ends are found after two queens, not eight.</p>
<p><strong>Trace table</strong> for n = 4. A cell written (r, c) is row r, column c, counting from 0.</p>

<p class="problem"><span class="pl">Problem 6.8.2</span> (hard) Count the ways to place n queens on an n by n board so no two attack each other, and print one board for n = 4.</p>
<table class="steps"><tr><th>Idea</th><td>One queen per row. At row <code>r</code>, try each column <code>c</code>; it is safe if <code>c</code>, <code>r - c</code> and <code>r + c</code> are not already in the three sets.</td></tr><tr><th>Brute force</th><td>Choose any n of the n² squares: C(64, 8) = 4,426,165,368 boards for n = 8. Test each.</td></tr><tr><th>Better approach</th><td>One queen per row cuts it to n<sup>n</sup> placements (16,777,216 for n = 8). The safety check cuts it to a small fraction: the code below reports how many nodes the whole search tree has for n = 8.</td></tr><tr><th>Code</th><td>Below, tested with asserts against the known counts for n = 1 to 8.</td></tr><tr><th>Dry run</th><td>See the 12-step trace for n = 4: 2 solutions in total.</td></tr><tr><th>Complexity</th><td>Time is below <code>O(n!)</code> and exact bound is hard; space <code>O(n)</code>.</td></tr><tr><th>Edge cases</th><td>n = 1 gives 1. n = 2 and n = 3 give 0. Board output must be built from the saved columns.</td></tr></table>
@@PY
def solve_n_queens(n):
    solutions = []
    cols, diag1, diag2 = set(), set(), set()
    placed = []                                   # placed[r] = column of the queen in row r
    nodes = 0

    def bt(r):
        nonlocal nodes
        nodes += 1
        if r == n:
            solutions.append(placed[:])
            return
        for c in range(n):
            if c in cols or (r - c) in diag1 or (r + c) in diag2:
                continue                          # prune: attacked square
            cols.add(c); diag1.add(r - c); diag2.add(r + c)      # choose
            placed.append(c)
            bt(r + 1)                                             # explore
            placed.pop()
            cols.remove(c); diag1.remove(r - c); diag2.remove(r + c)   # unchoose

    bt(0)
    return solutions, nodes

def draw(cols_of_queens):
    n = len(cols_of_queens)
    return ["".join("Q" if c == q else "." for c in range(n)) for q in cols_of_queens]

counts = [len(solve_n_queens(n)[0]) for n in range(1, 9)]
assert counts == [1, 0, 0, 2, 10, 4, 40, 92]
sols, nodes = solve_n_queens(4)
assert sols == [[1, 3, 0, 2], [2, 0, 3, 1]]
print("counts n=1..8:", counts)
print("nodes visited for n=8:", solve_n_queens(8)[1])
for row in draw(sols[0]):
    print(row)

<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Wrong diagonal keys.</strong> Wrong: using <code>r + c</code> for both diagonals, or storing only one diagonal set. Two squares share a down-right diagonal when <code>r - c</code> is equal, and a down-left diagonal when <code>r + c</code> is equal. Right: keep two separate sets. With a single set you reject safe squares or accept attacked ones, and the count for n = 4 is not 2.</div></div>
<h3>Sudoku awareness</h3>
<p>Sudoku is the same idea on a 9 by 9 board. The board is a grid of 81 cells, some filled. Each row, column and 3 by 3 box must hold the digits 1 to 9 once. The backtracking: find the next empty cell, try the digits 1 to 9, skip any digit already in that cell's row, column or box (pruning), place it, recurse, and clear the cell if the recursion fails. You are not expected to memorise a solver for most interviews, but you must be able to describe it in two sentences and recognise it as "N-Queens with a different safety test". A compact version follows. A row of the puzzle is written as a string with dots for empty cells.</p>
@@PY
puzzle = ["53..7....", "6..195...", ".98....6.", "8...6...3", "4..8.3..1",
          "7...2...6", ".6....28.", "...419..5", "....8..79"]
board = [[0 if ch == "." else int(ch) for ch in row] for row in puzzle]

def ok(r, c, d):
    if any(board[r][j] == d for j in range(9)):            # row
        return False
    if any(board[i][c] == d for i in range(9)):            # column
        return False
    br, bc = 3 * (r // 3), 3 * (c // 3)                    # top-left of the 3x3 box
    return all(board[br + i][bc + j] != d for i in range(3) for j in range(3))

def solve():
    for r in range(9):
        for c in range(9):
            if board[r][c] == 0:                           # next empty cell
                for d in range(1, 10):
                    if ok(r, c, d):
                        board[r][c] = d                    # choose
                        if solve():                        # explore
                            return True
                        board[r][c] = 0                    # unchoose
                return False                               # no digit fits: backtrack
    return True                                            # no empty cell: solved

assert solve()
assert all(sorted(row) == list(range(1, 10)) for row in board)

<ul><li><strong>Bitmasks make the safety test faster.</strong> Replace the three sets by three integers and test with <code>&amp;</code>. This is a common speed-up for N-Queens counting; Chapter 10 covers bit tricks.</li><li><strong>Choosing the most constrained cell first.</strong> Strong sudoku solvers pick the empty cell with the fewest legal digits instead of the next one. This often cuts the search by orders of magnitude. <h2 id="s6-9">6.9 Converting Recursion to Iteration</h2>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt"><strong>Idea in one sentence:</strong> recursion is a stack that Python manages for you; to avoid deep recursion, manage the stack yourself with a list.<br><strong>Real life:</strong> reading a book where footnotes lead to other books. Instead of keeping everything in your head, you keep a pile of bookmarks on the desk. Take the top bookmark, read, and add new bookmarks to the pile.</div></div>
<h3>How to recognise the need</h3>
<ul><li>The recursion depth could exceed about 1000 (a chain of 100,000 nodes, a long linked list, a large grid flood fill).</li><li>You hit <code>RecursionError</code> on valid input.</li><li>The interviewer asks "can you do it without recursion?"</li></ul>
<h3>Three conversions, easiest first</h3>
<ol><li><strong>The last-line call becomes a loop</strong> (tail calls, like factorial with an accumulator).</li><li><strong>Branching recursion becomes a loop with a stack</strong> of "work still to do".</li><li><strong>Subset-style recursion becomes a bitmask or a doubling loop.</strong></li></ol>
<p><strong>Template for the explicit stack.</strong> Put the starting state on the stack. While the stack is not empty: pop a state, handle it, push the states that the recursive calls would have started. Each state must carry everything a frame would hold (the arguments).</p>
<p><strong>Trace table</strong> of flattening <code>[1, [2, [3]], 4]</code> with a stack. We push items in reverse so the first item is popped first.</p>
<div class="tablewrap"><table class="data"><thead><tr><th>Step</th><th>Stack before (top on the right)</th><th>Popped</th><th>Action</th><th>Output so far</th></tr></thead><tbody><tr><td>1</td><td>[4, [2, [3]], 1]</td><td>1</td><td>a number: output it</td><td>[1]</td></tr><tr><td>2</td><td>[4, [2, [3]]]</td><td>[2, [3]]</td><td>a list: push its items reversed</td><td>[1]</td></tr><tr><td>3</td><td>[4, [3], 2]</td><td>2</td><td>output</td><td>[1, 2]</td></tr><tr><td>4</td><td>[4, [3]]</td><td>[3]</td><td>push its items</td><td>[1, 2]</td></tr><tr><td>5</td><td>[4, 3]</td><td>3</td><td>output</td><td>[1, 2, 3]</td></tr><tr><td>6</td><td>[4]</td><td>4</td><td>output</td><td>[1, 2, 3, 4]</td></tr></tbody></table></div>
<p class="problem"><span class="pl">Problem 6.9.1</span> (easy) Rewrite the recursive <code>flatten</code> from 6.1 so it cannot run out of stack, however deeply the lists are nested.</p>
<table class="steps"><tr><th>Idea</th><td>Replace the call stack by a list used as a stack, as in the trace table.</td></tr><tr><th>Brute force</th><td>Raise the recursion limit. It delays the crash but does not remove it.</td></tr><tr><th>Better approach</th><td>The explicit stack lives on the heap (ordinary memory) and can grow to millions of items.</td></tr><tr><th>Code</th><td>Below, tested, including a nesting of 5000 levels that would break the recursive version.</td></tr><tr><th>Dry run</th><td>See the trace table.</td></tr><tr><th>Complexity</th><td>Time <code>O(n)</code>, space <code>O(n)</code> for the stack.</td></tr><tr><th>Edge cases</th><td>Empty list gives []. Remember to push in reverse so the order is preserved.</td></tr></table>
@@PY
def flatten_iter(items):
    out = []
    stack = list(reversed(items))
    while stack:
        x = stack.pop()
        if isinstance(x, list):
            stack.extend(reversed(x))     # reversed, so the first item pops first
        else:
            out.append(x)
    return out

assert flatten_iter([]) == []
assert flatten_iter([1, [2, [3]], 4]) == [1, 2, 3, 4]
deep = [7]
for _ in range(5000):
    deep = [deep]
assert flatten_iter(deep) == [7]
print(flatten_iter([1, [2, [3]], 4]), "deep ok")
@@END
<p class="problem"><span class="pl">Problem 6.9.2</span> (medium) Produce all subsets of a list without recursion, in two ways: a bitmask and a doubling loop.</p>
<table class="steps"><tr><th>Idea</th><td>A bitmask is a number whose binary digits say take or skip for each item. The numbers 0 to 2<sup>n</sup> - 1 cover every pattern once. The doubling loop starts with [[]] and, for each item, adds a copy of every existing subset with the item appended.</td></tr><tr><th>Brute force</th><td>Recursion (6.3).</td></tr><tr><th>Better approach</th><td>No stack at all, so no depth limit.</td></tr><tr><th>Code</th><td>Below, tested.</td></tr><tr><th>Dry run</th><td>[a, b]: start [[]]. Item a: [[], [a]]. Item b: [[], [a], [b], [a, b]]. Mask view: 00 = {}, 01 = {a}, 10 = {b}, 11 = {a, b}.</td></tr><tr><th>Complexity</th><td>Time <code>O(n 2<sup>n</sup>)</code>, space is the output.</td></tr><tr><th>Edge cases</th><td>Empty input gives [[]] in both.</td></tr></table>
@@PY
def subsets_mask(nums):
    n = len(nums)
    result = []
    for mask in range(1 << n):                      # 0 .. 2^n - 1
        result.append([nums[i] for i in range(n) if mask >> i & 1])
    return result

def subsets_double(nums):
    result = [[]]
    for x in nums:
        result += [s + [x] for s in result]         # copy every subset, add x
    return result

assert subsets_mask([]) == [[]] == subsets_double([])
a, b = subsets_mask([1, 2, 3]), subsets_double([1, 2, 3])
assert sorted(a) == sorted(b) and len(a) == 8
print(a)
print(b)
@@END
<p class="problem"><span class="pl">Problem 6.9.3</span> (hard) Solve combination sum (6.5) with an explicit stack instead of recursion.</p>
<table class="steps"><tr><th>Idea</th><td>A frame had three variables: <code>start</code>, <code>left</code> and <code>path</code>. Put each frame on the stack as a tuple. There is no "unchoose": each state carries its own copy of the path, so nothing needs undoing.</td></tr><tr><th>Brute force</th><td>The recursive version.</td></tr><tr><th>Better approach</th><td>Same pruning, no depth limit. The price: copying the path into each new state, which costs <code>O(path length)</code> per step.</td></tr><tr><th>Code</th><td>Below, checked against the answers from 6.5.</td></tr><tr><th>Dry run</th><td>Stack [(0, 5, ())]. Pop it: push (0, 3, (2,)), (1, 2, (3,)), (2, 0, (5,)). Pop (2, 0, (5,)): left is 0, record [5]. And so on.</td></tr><tr><th>Complexity</th><td>Same time as recursion times the path copy; space <code>O(depth × path)</code> for pending states.</td></tr><tr><th>Edge cases</th><td>Push order decides output order, so compare sorted results.</td></tr></table>
@@PY
def combination_sum_iter(candidates, target):
    candidates = sorted(candidates)
    result = []
    stack = [(0, target, ())]                       # (start, left, path)
    while stack:
        start, left, path = stack.pop()
        if left == 0:
            result.append(list(path))
            continue
        for i in range(start, len(candidates)):
            c = candidates[i]
            if c > left:                            # same prune as before
                break
            stack.append((i, left - c, path + (c,)))
    return result

assert sorted(combination_sum_iter([2, 3, 5], 8)) == [[2, 2, 2, 2], [2, 3, 3], [3, 5]]
assert combination_sum_iter([2, 3, 6, 7], 7) == [[7], [2, 2, 3]] or sorted(combination_sum_iter([2, 3, 6, 7], 7)) == [[2, 2, 3], [7]]
assert combination_sum_iter([4], 3) == []
assert len(combination_sum_iter([1], 30)) == 1
print(sorted(combination_sum_iter([2, 3, 5], 8)))
@@END
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Sharing one mutable path between stack states.</strong> Wrong: pushing <code>(i, left - c, path)</code> after <code>path.append(c)</code> on a shared list. All pending states then see the same changing list. Right: give each state its own value, as here with the tuple <code>path + (c,)</code>, or copy the list.</div></div>
<h3>Going deeper</h3>
<ul><li><strong>Why not always iterate?</strong> The recursive version is shorter and has an automatic undo (the end of the function). Explicit stacks cost clarity. Use them when depth is a real risk.</li><li><strong>Memoised recursion has the same depth issue.</strong> A cached function over n = 100,000 hits the recursion limit; this is one reason Chapter 9 also teaches the bottom-up table that fills in a loop.</li></ul>
