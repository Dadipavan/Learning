Maya solved 200 random practice problems in two months. In her first interview she froze on a question she had "seen". She could not remember how she solved it, and she had never learned to tell which kind of problem it was. Her problem was not effort. It was method.

This chapter gives you the method and the tools every later chapter uses: a 12-week plan built on patterns (reusable ideas) instead of single problems; Big-O, a simple way to say how fast a solution is; and your Python toolkit of built-in structures. After it you can estimate the speed of any code, choose between a list, set, dict, deque and heap on purpose, and test your own solutions. Code was run with Python 3.14 and every output is real. For a gentler first look, see also the Linux, Git, Algorithms and CS Foundations document, Chapters 7 to 9. Later chapters are pointed to as "Chapter N".

1.1 The 12-Week Method: Patterns, Not Problems

BASIC EXPLANATION
A pattern is a reusable way of solving a group of similar problems. The 12-week method means learning the main patterns in a fixed order and practising each one, instead of solving random problems.
INTUITION
A cook who knows ten techniques (fry, boil, roast, reduce...) can make thousands of dishes. A cook who memorised 2,000 recipes is lost when one ingredient is missing. Learn about 12 techniques, and thousands of problems become variations.

The idea. Almost every interview problem uses one of a few patterns: hashing, two pointers, sliding window, binary search, stack, recursion, tree, graph, dynamic programming, greedy, heap, design. See each pattern clearly once, drawn and traced, then use it on a ladder from easy to hard.

HabitSlow wayFast way
What you studyRandom problemsOne pattern per week, in order
When stuckRead the solution at onceTime-box 25 minutes, read only a hint, retry, then read
After solvingMove onWrite the pattern name and the signal that revealed it
ReviewRe-read old codeRe-solve from a blank page on days 1, 3, 7, 14, 30

A suggested week (60 to 90 minutes a day): days 1 to 2 read the chapter and re-draw every figure; days 3 to 4 type the templates from memory and solve the easy and medium problems; day 5 try the hard ones; day 6 re-solve three old problems blind; day 7 rest or do the practice set.

How to read it: each box is one week and one chapter. The dots show growing gaps between reviews. Each effortful recall makes the memory last longer, so close the book before you re-solve.

KEY IDEA
Deliberate practice means working just beyond what you can do, with feedback. Pick a problem you cannot solve in 5 minutes but can in 45, attempt it honestly, check a solution, then redo it without help. Ten problems done this way teach more than fifty read passively.

The 4-step solve routine

  1. Understand. Restate the problem. Inputs, sizes, output? Empty input? Duplicates? Negatives?
  2. Examples. Write two small ones and an edge case. Solve them by hand and notice what you did; that is the algorithm.
  3. Brute force. Say the slowest correct solution and its Big-O. It is your safety net and test oracle (Section 1.8).
  4. Optimise. Ask what work is repeated and which pattern removes it. Code, trace, test.

Problem 1.1.1 (Easy) Given a list of integers, return True if any value appears at least twice.

IdeaWalk the list and remember the values seen. If the current value is already remembered, it is a repeat.
Brute forceCompare every pair (i, j), i < j: n(n-1)/2 comparisons, O(n²) time, O(1) space.
Better approachA set answers x in seen in O(1) on average: one pass, O(n) time, O(n) space. Memory is traded for speed.
CodeBelow, with asserts checking that both versions agree.
Dry runTrace table after the code.
ComplexityBrute O(n²) / O(1). Set O(n) / O(n).
Edge casesEmpty list (False), one item (False), all equal (True), repeat at the very end (True).
def has_dup_brute(nums):
    for i in range(len(nums)):            # every pair (i, j) with i < j
        for j in range(i + 1, len(nums)):
            if nums[i] == nums[j]:
                return True
    return False

def has_dup_fast(nums):
    seen = set()                          # values met so far
    for x in nums:
        if x in seen:                     # O(1) average lookup
            return True
        seen.add(x)
    return False

tests = [([], False), ([7], False), ([3, 1, 4, 1], True), ([4, 5, 6], False), ([2, 2, 2], True)]
for nums, expected in tests:
    assert has_dup_brute(nums) == expected
    assert has_dup_fast(nums) == expected

1.2 Big-O From Zero

BASIC EXPLANATION
Big-O notation describes how the running time (or memory) of an algorithm grows as the input size n grows. It ignores constants and small terms, so it is used to compare algorithms.
INTUITION
Finding a name in a phone book. Reading every page is slow: double the book, double the work. Opening the middle and halving is fast: double the book, one extra step. Big-O names that difference: how does the work grow when the input grows?
DEFINITION
Big-O describes how the number of steps grows with the input size n, keeping only the fastest-growing part and ignoring constants. 3n + 10 steps is O(n). n² + 5n steps is O(n²).

Step 1: count the steps

def one_loop(n):
    c = 0
    for _ in range(n):
        c += 1
    return c

def two_loops(n):
    c = 0
    for _ in range(n):
        for _ in range(n):
            c += 1
    return c

def halving(n):
    c = 0
    while n > 1:
        n //= 2
        c += 1
    return c

print("n      constant  halving  one_loop  two_loops")
for n in (10, 100, 1000):
    print(f"{n:<6} {1:<9} {halving(n):<8} {one_loop(n):<9} {two_loops(n)}")
n      constant  halving  one_loop  two_loops
10     1         3        10        100
100    1         6        100       10000
1000   1         9        1000      1000000

When n grows 10 times: the constant column stays 1, halving gains about 3 steps, one loop grows 10 times, two loops grow 100 times. Those are O(1), O(log n), O(n) and O(n²).

Step 2: the seven classes

NameBig-OEveryday pictureTypical code

How to read it: the higher a curve at the right edge, the worse it scales. By n = 10 the factorial curve is off the chart (10! = 3,628,800). The three at the bottom (constant, log, linear) are the ones you want.

Step 3: three simplification rules

  1. Drop constants. 5n is O(n).
  2. Keep the biggest term. n² + n + 1 is O(n²).
  3. Add for steps in sequence, multiply for steps inside steps. Two loops one after another: O(n). A loop whose body costs O(n): O(n²).

Problem 1.2.1 (Easy) Give the time complexity: (a) two separate loops over n items; (b) a loop over n items that tests x in some_list (n items) inside; (c) i = 1; while i < n: i *= 2.

IdeaCount loops, then ask what each line inside really costs.
(a)n + n = 2n: O(n).

(c)i takes 1, 2, 4, 8... until n: about log₂ n steps, O(log n).
COMMON MISTAKE
Counting only visible loops. Wrong: "one loop, so O(n)". But x in list, list.pop(0), list.insert(0, x), s += "a", slicing a[1:] and list.index(x) each hide an O(n) loop. Right: price every line inside the loop.

Space complexity

Space complexity is the extra memory needed as n grows, not counting the input. A running total is O(1). A set of seen values is O(n). Recursion counts too: each active call sits on the call stack, so a recursion n levels deep uses O(n) space.

Example: summing a list of 100 numbers with a plain loop needs O(1) extra space. Summing it recursively (a[0] + sum_of_rest) keeps 101 calls on the stack at once: O(n) space for the same answer.

1.3 Cases, Amortised Cost and Constraints

Best, average and worst case

Searching a list: if the value is first you stop at once (best case, 1 comparison); if it is last or missing you scan everything (worst case, n). Interviews usually mean the worst case.

def linear_search(a, target):
    comparisons = 0
    for i, x in enumerate(a):
        comparisons += 1
        if x == target:
            return i, comparisons
    return -1, comparisons

a = [10, 20, 30, 40, 50, 60, 70, 80, 90]
counts = [linear_search(a, v)[1] for v in a]
print("best:", min(counts), "worst:", max(counts), "average:", sum(counts) / len(counts))
print("missing value costs:", linear_search(a, 99)[1])
best: 1 worst: 9 average: 5.0
missing value costs: 9

The average is (1 + 2 + ... + 9) / 9 = 5.0 = (n + 1) / 2: still O(n). Case matters elsewhere too: Python's sorted is O(n log n) in the worst case, while a naive quicksort that always picks the first item as pivot degrades to O(n²) on sorted input.

Amortised cost

BASIC EXPLANATION
Amortised cost is the average cost per operation over a long sequence of operations. It is used to describe structures where an occasional operation is expensive but most are cheap.
INTUITION
A small coffee bill each day plus a large subscription once a year. One day can be expensive, but the average per day is small. Amortised O(1): any single operation may be costly, but over a long sequence the average is O(1).

A Python list keeps spare room. append is usually one write. When the room runs out, Python allocates a bigger block and copies every item once. Growing by a fraction of the current size keeps the copies rare enough that the average stays constant.

How to read it: on the left, most appends cost 1; the red ones (appends 2, 3, 5, 9, 17) copy the list. On the right, the running average never passes 3. Reason: copies total 1 + 2 + 4 + ... + n/2 < n, so n appends cost less than n writes + n copies = 2n, below 3n in all. Real Python grows more gently than doubling, with the same argument. dict and set inserts are also amortised O(1): now and then the table is rebuilt at O(n).

COMMON MISTAKE
Confusing amortised with average. Amortised O(1) is a guarantee over any sequence of operations, with no assumption about the data. Average-case (like a hash lookup) assumes friendly inputs. And list.insert(0, x) and list.pop(0) are not O(1) at all: they shift every item.

Reading constraints

Limits such as "1 ≤ n ≤ 105" hint at the intended complexity. A working budget in Python is about 107 simple operations per second (a rule of thumb, not a guarantee). Work backwards from n.

Going deeper

  • Formal meaning. f(n) is O(g(n)) if some constants c and n₀ give f(n) ≤ c · g(n) for all n ≥ n₀. It is an upper bound; Ω is a lower bound; Θ is both. Log base does not matter (a constant factor).
  • Two inputs. A list of n items and a string of m characters: say O(n · m), never O(n²). Hash lookups are O(1) expected, not guaranteed.

Slicing copies

a[i:j] builds a new list, costing O(j - i), not O(1). Slicing inside a loop or recursion is a favourite hidden O(n).

Slicing a list of n items inside a recursion that recurses n times copies about n(n-1)/2 items in total (for n = 200, 19,900 items). Passing an index instead copies nothing. a[::-1], a[:k] and a[-k:] are copies too.

sorted, sort and key

sorted(x) returns a new list; x.sort() sorts in place. Both are O(n log n) and stable: equal items keep their input order. key is a function giving the value to sort by; a tuple key breaks ties with later parts.

words = ["pear", "fig", "apple", "kiwi", "date", "plum"]
print(sorted(words))
print(sorted(words, key=len))                     # ties keep input order (stable)
print(sorted(words, key=lambda w: (-len(w), w)))  # longest first, then alphabetical
print(max(words, key=len), min(words, key=lambda w: w[-1]))

1.5 Hashing Toolkit: dict, set, Counter and defaultdict

BASIC EXPLANATION
A dict stores key-value pairs and a set stores unique items, both using hashing for fast lookup. Counter counts items and defaultdict creates a default value for missing keys.
INTUITION
A coat check. You hand over a coat, get a numbered ticket, and the attendant goes straight to the right hook. A dict does this: the key is the ticket, the hash says which slot to open, and nothing is searched.

The idea. Replace a slow search (O(n)) by a direct lookup (O(1) average). How to recognise it:

  • You keep asking "have I seen X?" inside a loop.
  • You need counts, frequencies, or "the first / only one that...".
  • You must group items by a property (anagrams, same remainder).
  • A pair must add to a target, so one partner can be looked up.
  • The brute force compares every pair and one side could be looked up instead.

How to read it: each arrow is hash(key) % 8 choosing a slot. 'bob' and 'dee' land on slot 2, a collision, drawn as a short chain (real Python resolves collisions differently, with the same effect). A lookup jumps to one slot and checks a few entries: O(1) on average, however many items exist.

Three reusable templates

from collections import Counter, defaultdict

# Template 1: "seen" set. Have I met this value before?
def first_repeat(nums):
    seen = set()
    for x in nums:
        if x in seen:
            return x
        seen.add(x)
    return None

# Template 2: frequency map. How many of each?
def frequencies(items):
    freq = {}
    for x in items:
        freq[x] = freq.get(x, 0) + 1     # same as Counter(items)
    return freq

# Template 3: group by a key. Which items share a property?
def group_by_length(words):
    groups = defaultdict(list)           # a missing key starts as []
    for w in words:
        groups[len(w)].append(w)
    return dict(groups)

print(first_repeat([4, 2, 9, 2, 4]))
print(frequencies("banana"), Counter("banana"))
print(group_by_length(["to", "be", "or", "not", "too"]))
print(Counter("abracadabra").most_common(2))
2
{'b': 1, 'a': 3, 'n': 2} Counter({'a': 3, 'n': 2, 'b': 1})
{2: ['to', 'be', 'or'], 3: ['not', 'too']}
[('a', 5), ('b', 2)]

Counter is a dict for counts: missing keys count as 0 and most_common(k) returns the k biggest. defaultdict(factory) creates a missing entry by calling factory() (list, int, set).

COMMON MISTAKE
A list as a key, or trusting set order. Wrong: groups[sorted(w)] raises TypeError: unhashable type: 'list'. Right: groups["".join(sorted(w))]. Never rely on the printed order of a set of strings; it can change between runs. Sort it if you need an order.

def group_anagrams(words):
    groups = defaultdict(list)
    for w in words:
        groups["".join(sorted(w))].append(w)
    return list(groups.values())

result = group_anagrams(["eat", "tea", "tan", "ate", "nat", "bat"])

Problem 1.5.2 (Hard) Given an unsorted list of integers, find the length of the longest run of consecutive values (like 4, 5, 6, 7) in O(n). The values need not be adjacent in the list.

IdeaPut all numbers in a set. Start counting only at a number that begins a run: x - 1 is not in the set. Then walk up while x + 1 exists.
Brute forceFor each number, count upward using in list checks: at least O(n²). Sorting first gives O(n log n), but O(n) is asked.
Better approachEach number is a start at most once and is walked over only inside the run beginning below it, so total work is O(n).
CodeBelow.
Dry runTrace table after the code.
ComplexityTime O(n) average; space O(n).
Edge casesEmpty list: 0. Duplicates vanish in the set. Negatives work the same.
def longest_run(nums):
    values = set(nums)               # O(n); also removes duplicates
    best = 0
    for x in values:
        if x - 1 not in values:      # x starts a run
            length = 1
            while x + length in values:
                length += 1
            best = max(best, length)
    return best

assert longest_run([]) == 0
assert longest_run([5]) == 1
assert longest_run([100, 4, 200, 1, 3, 2]) == 4
assert longest_run([0, 3, 7, 2, 5, 8, 4, 6, 0, 1]) == 9
print(longest_run([100, 4, 200, 1, 3, 2]))
4

1.6 Toolkit II: deque, heapq and bisect

deque: a queue that is fast at both ends

BASIC EXPLANATION
A deque (double-ended queue) is a Python container that adds and removes items at both ends in O(1) time. It is used for queues and breadth-first search.
INTUITION
A line at a ticket counter: people join at the back and leave from the front, and nobody shuffles. A Python list is a row of seats: removing the first person makes everyone slide one seat. collections.deque is the real queue.

The idea. A deque gives O(1) append, appendleft, pop and popleft. It is slow at indexing the middle. (A list used as a queue with pop(0) shifts every item: 100,000 items cost about 5 billion moves.) How to recognise it: "first in, first out", "process in arrival order", "the last k items", "rotate", "level by level" (breadth-first search, Chapter 8).

from collections import deque

# Template: queue of work, process from the front.
q = deque([1, 2, 3])
q.append(4)               # join at the back, O(1)
front = q.popleft()       # leave from the front, O(1)  (list.pop(0) is O(n))
q.appendleft(0)
print(front, list(q))

# Keep only the last 3 items automatically.
last3, trace = deque(maxlen=3), []
for x in [10, 20, 30, 40, 50]:
    last3.append(x)
    trace.append(list(last3))
print(trace)
1 [0, 2, 3, 4]
[[10], [10, 20], [10, 20, 30], [20, 30, 40], [30, 40, 50]]

The maxlen trace is a fixed-size window: when the deque is full, the oldest item falls off the other end. q.rotate(-m) moves m items from the front to the back, which simulates circles and rotations.

heapq: always know the smallest, cheaply

BASIC EXPLANATION
heapq is a Python module that keeps a list arranged as a binary min-heap, so the smallest item is always first. It is used for priority queues and top-k problems.
INTUITION
An emergency room. Patients arrive in any order, but the nurse always takes the most urgent next. She does not keep a perfectly sorted list; she only guarantees the most urgent is at the front. A heap is that cheap partial order.

The idea. A min-heap keeps the smallest item at index 0. heappush and heappop cost O(log n); peeking h[0] is O(1). How to recognise it: "k largest / smallest", "next best item as things change", "merge sorted streams", "process the cheapest first" (also Dijkstra, Chapter 8; full treatment in Chapter 7).

How to read it: each parent is smaller than its children. The list stores the tree row by row; the node at index i has children at 2i+1 and 2i+2 and a parent at (i-1)//2. A new item is added at the end and "bubbles up" past larger parents, at most the tree height, about log₂ n steps.

import heapq

h = []
for x in [5, 1, 9, 3, 7]:
    heapq.heappush(h, x)          # O(log n) each
print("heap list :", h)           # a valid heap, NOT sorted
print("smallest  :", h[0])        # peek, O(1)
print("pop order :", [heapq.heappop(h) for _ in range(len(h))])

nums = [8, 2, 6, 4]

Template: top-k with a heap of size k. Keep a min-heap of the k largest items so far. Its smallest member is the weakest of the current top k; a new item either beats it or not.

import heapq

def k_largest(nums, k):
    heap = []                              # min-heap holding the k largest so far
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:                  # beats the weakest member
            heapq.heapreplace(heap, x)     # pop smallest and push x in one step
    return sorted(heap, reverse=True)

Problem 1.6.1 (Hard) Merge k sorted lists into one sorted list in O(N log k), where N is the total number of items.

IdeaThe next output item is the smallest among the current front items of the k lists. Keep those fronts in a min-heap.
Brute forceConcatenate and sort: O(N log N). Correct, but ignores that the lists are already sorted.
Better approachHeap of (value, list_index, position). Pop the smallest, output it, push the next item of the same list. The heap never exceeds k items, so each of N steps is O(log k).
CodeBelow.
Dry runLists [1,4], [2,3], [0,9]. Heap {(1,0,0), (2,1,0), (0,2,0)}. Pop 0, push 9. Pop 1, push 4. Pop 2, push 3. Pop 3. Pop 4. Pop 9. Output 0,1,2,3,4,9.
ComplexityO(N log k) time, O(k) extra space.
Edge casesEmpty lists (skip when seeding), k = 1, all empty, equal values across lists (the list index in the tuple keeps comparisons valid).
import heapq

def merge_sorted(lists):
    heap = []
    for li, lst in enumerate(lists):
        if lst:                                   # skip empty lists
            heapq.heappush(heap, (lst[0], li, 0))
    out = []
    while heap:
        value, li, pos = heapq.heappop(heap)      # smallest current front
        out.append(value)
        if pos + 1 < len(lists[li]):              # push that list's next item
            heapq.heappush(heap, (lists[li][pos + 1], li, pos + 1))
    return out

assert merge_sorted([]) == []
assert merge_sorted([[], []]) == []
assert merge_sorted([[1, 4], [2, 3], [0, 9]]) == [0, 1, 2, 3, 4, 9]
assert merge_sorted([[5], [5], [5]]) == [5, 5, 5]
print(merge_sorted([[1, 4], [2, 3], [0, 9]]))
[0, 1, 2, 3, 4, 9]

Going deeper

Going deeper: heapify is O(n), not O(n log n), because most nodes sit near the bottom and move only a step or two. heapq has no decrease-key; use lazy deletion (push the new version, skip stale entries), Chapter 8. Tuples compare field by field, so put a unique index before any object that cannot be ordered.

bisect: binary search for free

BASIC EXPLANATION
bisect is a Python module that does binary search on a sorted list. It finds the position where a value belongs, or inserts it, in O(log n) time.
INTUITION
Guess a number from 1 to 100, hearing "higher" or "lower". Start at 50. Each answer throws away half the numbers, so seven guesses cover up to 128. That is binary search.

The idea. On a sorted list the middle item tells you which half holds the target. Discard the other half and repeat: O(log n); a million items need about 20 steps. How to recognise it: sorted data, or an answer in a numeric range where a yes/no test on a guess is monotone ("if t works, every bigger t works"). "Minimum possible maximum" is a strong signal. Chapter 4 covers it fully.

How to read it: blue cells are still possible, grey are ruled out. Row 1 checks 16 (too small), discarding everything up to it. Row 2 checks 56 (too big). Row 3 finds 23 at index 5.

Template: first index where a condition becomes true. Invariant: "the answer is in [lo, hi]".

def first_true(lo, hi, ok):
    # Smallest x in [lo, hi] with ok(x) True, where ok is False...False True...True.
    # Returns hi + 1 if none.
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            hi = mid - 1          # mid works; look for an earlier one
        else:
            lo = mid + 1          # mid fails; the answer is to the right
    return lo

a = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
print("index of 23:", first_true(0, len(a) - 1, lambda i: a[i] >= 23))
index of 23: 5

Python's bisect module does this for lists: bisect_left(a, x) is the first index with a[i] >= x; bisect_right(a, x) the first with a[i] > x. So in the sorted list [1, 2, 2, 2, 5] the value 2 occupies indexes 1 to 3: bisect_left gives 1, bisect_right gives 4, and the count is 4 - 1 = 3.

Problem 1.6.2 (Hard) Packages with given weights (in order) must ship within days days. Each day you load packages in order until the next one would exceed the ship's capacity. Find the smallest capacity that works.

IdeaSearch on the answer. If capacity c works, any larger one works, so answers look like False...False True...True: the first-true template applies.
Brute forceTry c = max(weights), max+1, ... up to sum(weights), simulating each: O(n · sum).
Better approachThe answer lies in [max(weights), sum(weights)]. Binary search it with an O(n) simulation: O(n log sum).
CodeBelow.
Dry runWeights 1..10, 5 days, range 10 to 55. Try 32: 2 days, works, hi = 32. Try 21: 3 days, hi = 21. Try 15: 5 days, hi = 15. Try 12: 6 days, fails, lo = 13. Try 14: 6 days, fails, lo = 15. Answer 15.
ComplexityO(n log S) time, S = sum(weights); O(1) space.
Edge casesdays = 1 gives the sum; days >= n gives the maximum; one package.
def days_needed(weights, cap):
    days, load = 1, 0
    for w in weights:
        if load + w > cap:        # this package does not fit today
            days += 1
            load = 0
        load += w
    return days

def min_capacity(weights, days):
    lo, hi = max(weights), sum(weights)
    while lo < hi:
        mid = (lo + hi) // 2
        if days_needed(weights, mid) <= days:
            hi = mid              # mid works; maybe smaller works
        else:
            lo = mid + 1
    return lo

w = list(range(1, 11))
assert min_capacity(w, 5) == 15
assert min_capacity(w, 1) == 55 and min_capacity(w, 10) == 10
assert min_capacity([7], 3) == 7
for d in range(1, 8):                       # cross-check with brute force
    brute = next(c for c in range(max(w), sum(w) + 1) if days_needed(w, c) <= d)
    assert min_capacity(w, d) == brute
print(min_capacity(w, 5), [days_needed(w, c) for c in (14, 15)])
15 [6, 5]

By hand at 15: [1..5] = 15, [6,7] = 13 (adding 8 gives 21), [8], [9], [10]: five days. At 14: [1..4] = 10 (adding 5 gives 15), [5,6], [7], [8], [9], [10]: six days, too many. So 15.

COMMON MISTAKE
Off-by-one in binary search. Wrong: mixing styles, such as while lo < hi with hi = mid - 1, or lo = mid (which never moves when lo + 1 == hi, so the loop never ends). Right: pick one pattern. A: lo <= hi, hi = mid - 1, lo = mid + 1. B: lo < hi, hi = mid, lo = mid + 1. Each step must shrink the range.

Going deeper

  • The invariant is the proof. Say it aloud: "the answer, if it exists, is always inside [lo, hi]". Each branch must keep it true and shrink the range.
  • Monotone check. Search on the answer works only if feasibility is monotone. Test two values by hand before coding.
  • Overflow exists in fixed-size-integer languages (lo + (hi - lo) // 2); Python integers never overflow.

functools.lru_cache: remember answers you already computed

BASIC EXPLANATION
functools.lru_cache is a decorator that stores the results of a function for the arguments it has already seen. It is used to avoid repeating the same computation in recursion.
INTUITION
A student writes every answer in a notebook. When the same question returns, she looks it up instead of re-deriving it. @lru_cache gives any function that notebook.

The idea. A recursive function often asks the same question many times. Store each answer the first time (memoisation) and return the stored answer afterwards. Exponential time can become polynomial. How to recognise it: a recursion tree with repeated calls; "count the ways", "minimum cost", "is it possible" over choices; recursion inputs that are small (indexes, counts), not whole lists. Chapter 9 builds a full method on this.

How to read it: the root is f(5); each node calls f(n-1) and f(n-2). The red nodes are inputs that already appeared, so their subtrees are wasted. With a cache each red node is answered at once and the tree below it disappears: 15 calls shrink to 6 real computations, one per distinct input 0 to 5.

Problem 1.7.1 (Easy). Compare the number of calls of naive and cached Fibonacci. Naive recursion makes a number of calls that itself grows like Fibonacci (about 1.6 times per step), so O(2n). With @lru_cache each of the n + 1 distinct inputs is computed once: O(n) time and space.

from functools import lru_cache

calls = 0
def fib_naive(n):
    global calls
    calls += 1
    return n if n < 2 else fib_naive(n - 1) + fib_naive(n - 2)

@lru_cache(maxsize=None)               # the template: one decorator line
def fib_cached(n):
    return n if n < 2 else fib_cached(n - 1) + fib_cached(n - 2)

assert fib_naive(20) == fib_cached(20) == 6765
print("naive calls for fib(20):", calls)
print("cache info for fib(20): ", fib_cached.cache_info())

Problem 1.7.2 (Hard) The edit distance between two words is the fewest single-letter inserts, deletes or replacements needed to turn one into the other. Compute it.

IdeaLet d(i, j) be the distance between the first i letters of A and the first j of B. If the last letters match, it is d(i-1, j-1). Otherwise 1 plus the best of delete, insert, replace.
Brute forceTry all edit sequences recursively: exponential.
Better approachOnly (len A + 1) × (len B + 1) distinct pairs exist. Cache them: O(len A × len B).
CodeBelow.
Dry run"cat" to "cut": last letters match, so d(3,3) = d(2,2). Now "a" and "u" differ: 1 + min(d(1,2), d(2,1), d(1,1)). d(1,1) compares "c" with "c": d(0,0) = 0. So the answer is 1 + 0 = 1.
ComplexityO(m · n) time and space for lengths m and n.
Edge casesOne empty word: the other's length. Equal words: 0.
from functools import lru_cache

def edit_distance(a, b):
    @lru_cache(maxsize=None)
    def d(i, j):                       # distance between a[:i] and b[:j]
        if i == 0:
            return j                   # insert j letters
        if j == 0:
            return i                   # delete i letters
        if a[i - 1] == b[j - 1]:
            return d(i - 1, j - 1)     # last letters match: free
        return 1 + min(d(i - 1, j),        # delete from a
                       d(i, j - 1),        # insert into a
                       d(i - 1, j - 1))    # replace
    return d(len(a), len(b))

assert edit_distance("cat", "cut") == 1
assert edit_distance("", "abc") == 3
assert edit_distance("same", "same") == 0
assert edit_distance("kitten", "sitting") == 3
assert edit_distance("horse", "ros") == 3
print(edit_distance("kitten", "sitting"), edit_distance("intention", "execution"))
3 5
COMMON MISTAKE
Caching unhashable arguments or impure functions. Wrong: @lru_cache on a function taking a list (TypeError: unhashable type), or whose result depends on a changing global. Right: pass indexes or tuples, keep the function pure, and call cache_clear() between independent tests.

Going deeper

  • LRU means "least recently used": with maxsize=n the entry unused longest is dropped. Use maxsize=None for dynamic programming; functools.cache (3.9+) is the same.
  • Top-down versus bottom-up. Memoised recursion is top-down; filling a table from small cases up is bottom-up. Same idea, no recursion limit. Chapter 9 teaches both. Chapter 11 builds your own LRU cache.

Recursion limit

Python stops recursion at a fixed depth to protect memory; deeper raises RecursionError. For paths of 100,000 nodes, use a loop with your own stack.

import sys

def depth(n):
    return 0 if n == 0 else 1 + depth(n - 1)

print("default limit:", sys.getrecursionlimit())
print(depth(500))
try:
    depth(100_000)
except RecursionError as e:
    print("RecursionError:", e)

def depth_loop(n):
    count = 0
    while n > 0:               # the same idea as a loop: no stack growth
        n -= 1
        count += 1
    return count

print(depth_loop(100_000))
sys.setrecursionlimit(5000)    # allowed, but use sparingly
print(depth(3000))
default limit: 1000
500
RecursionError: maximum recursion depth exceeded
100000
3000

Raising the limit patches moderate depth (a few thousand). A very high limit can crash the interpreter, so prefer a loop when depth can reach 105.

1.8 How to Test Your Solutions

A solution you have not tested is a guess, and the statement's own example is chosen to be pleasant: bugs live in all-negative lists, empty input, duplicates and boundaries. Use three layers: asserts on small cases (write them before the code, from your step 2 examples); the edge-case checklist below; and a brute-force cross-check against the slow, obviously correct version on thousands of random small inputs.

Problem 1.8.1 (Medium) A teammate wrote a fast function for "the largest sum of any non-empty run of consecutive items". Find its bug with a brute-force cross-check.

IdeaRun a trusted slow version and the fast one on many random tiny lists. The first disagreement is a small counterexample.
Brute forceSum every run a[i..j]: O(n³) as written. Fine for 5 items.
Better approachTrack the best sum ending at the current item and the best so far: O(n).
CodeBelow: buggy version, then the fix.
Dry runOn [-3] the buggy version starts best = 0, never updates, and returns 0; a non-empty run must give -3.
ComplexityTest loop: 1000 tiny cases, instant.
Edge casesAll negatives (the bug), one item, zeros.
import random

def best_brute(a):
    best = a[0]
    for i in range(len(a)):
        for j in range(i, len(a)):
            best = max(best, sum(a[i:j + 1]))
    return best

def best_buggy(a):
    best = cur = 0                       # BUG: assumes an empty run is allowed
    for x in a:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best

def best_fixed(a):
    best = cur = a[0]                    # start from the first item
    for x in a[1:]:
        cur = max(x, cur + x)
        best = max(best, cur)
    return best

random.seed(7)
tests = [[random.randint(-5, 5) for _ in range(random.randint(1, 5))] for _ in range(1000)]
fails = [a for a in tests if best_buggy(a) != best_brute(a)]
smallest = min(fails, key=len)
print("buggy version fails on", len(fails), "of 1000 tests; smallest:", smallest,
      "expected", best_brute(smallest), "got", best_buggy(smallest))
assert all(best_fixed(a) == best_brute(a) for a in tests)
print("fixed version agrees on all 1000 tests")
buggy version fails on 176 of 1000 tests; smallest: [-4] expected -4 got 0
fixed version agrees on all 1000 tests

Going deeper

  • Seed the randomness (random.seed) so failures reproduce, and print the failing input. Prefer the smallest failing input, as min(fails, key=len) did above.
  • Properties help when no brute force exists: a sort's output is ordered and has the same items; a search result, if not -1, equals the target.
  • In an interview, trace your own example through the finished code. Interviewers value that more than silent confidence. Engineers call the cross-check differential testing and use it to validate rewritten pipelines against old ones.

Practice 1.9 (Conceptual) A list doubles its capacity when full. Show that n appends do under 3n units of work in total.

Answer: Writes cost n. Copies at sizes 1, 2, 4, ... total 1 + 2 + 4 + ... + n/2 < n. So the total is below 2n, and the average per append is constant.

Practice 1.13 (Write) Return True if two different positions of an unsorted list hold values summing to a target, in O(n).

Answer: For each x the partner is target - x. Check whether it was seen earlier, then remember x.

def has_pair_sum(nums, target):
    seen = set()
    for x in nums:
        if target - x in seen:
            return True
        seen.add(x)
    return False

assert has_pair_sum([3, 8, 5], 11) and not has_pair_sum([3, 8, 5], 6)
assert has_pair_sum([3, 3], 6)          # two different positions, same value
assert not has_pair_sum([3], 6)         # one 3 must not pair with itself
print(has_pair_sum([2, 7, 11, 15], 9), has_pair_sum([], 0))

Practice 1.14 (Interview) Why is x in some_set O(1) on average but O(n) in the worst case, and why do we usually say O(1)?

Answer: The hash picks one slot and only the few entries there are compared. If many keys share a slot, a lookup compares against all of them: O(n). Python keeps tables sparse and resizes them, so long collision chains are rare for ordinary data. We quote O(1) because it is the expected cost, and mention the worst case if asked.

Practice 1.15 (Medium) Count index pairs i < j whose values differ by exactly k (k > 0), in O(n), for [1, 2, 2, 1, 3] with k = 1.

Answer: Count each value with Counter. A value v seen c[v] times pairs with every occurrence of v + k, giving c[v] × c[v + k] pairs. Here 1 (twice) with 2 (twice) gives 4, and 2 (twice) with 3 (once) gives 2. Total 6, in O(n) time. Code: sum(c[v] * c[v + k] for v in c).

Practice 1.17 (Hard) Count contiguous runs of a list whose sum equals k. Values may be negative. Aim for O(n).

Answer: A run from i to j has sum k exactly when prefix[j+1] - prefix[i] = k. Scan once, keeping a counter of earlier prefix sums, and add how many equal prefix - k. Count prefix 0 once at the start.

from collections import Counter

def count_runs_with_sum(nums, k):
    seen = Counter({0: 1})        # prefix sum 0 occurs once before we start
    prefix = total = 0
    for x in nums:
        prefix += x
        total += seen[prefix - k]
        seen[prefix] += 1
    return total

assert count_runs_with_sum([], 0) == 0
assert count_runs_with_sum([0, 0], 0) == 3     # runs [0], [0], [0, 0]
print(count_runs_with_sum([1, 2, 3, -3, 3], 3))
5

Trace on [1, 2, 3, -3, 3], k = 3: prefixes 1, 3, 6, 3, 6. At 1 look for -2: 0 matches. At 3 look for 0: 1 (the run [1,2]). At 6 look for 3: 1 (run [3]). At 3 look for 0: 1 (run [1,2,3,-3]). At 6 look for 3: seen twice, so 2 (runs [3,-3,3] and [3]). Total 0 + 1 + 1 + 1 + 2 = 5.

Practice 1.18 (Hard) Machines take 2, 3 and 5 seconds per item. Find the least time in which together they make at least 10 items.

Answer: In time t they make t//2 + t//3 + t//5 items, a total that never decreases as t grows, so binary search t with the first-true template (range 1 to 20, since the fastest machine alone needs 2 × 10). At t = 10: 5 + 3 + 2 = 10 items. At t = 9: 4 + 3 + 1 = 8. The answer is 10, found in O(m log T) for m machines and range T.

Practice 1.19 (Hard) Items arrive one at a time. After each arrival report the median of all items so far, in O(log n) per item.

Answer: Keep a max-heap low (negated values) with the smaller half and a min-heap high with the larger half, sizes equal or low one bigger. The median is the top of low, or the average of both tops.

import heapq

def running_medians(stream):
    low, high, out = [], [], []          # low holds negated values (max-heap)
    for x in stream:
        heapq.heappush(low, -x)
        heapq.heappush(high, -heapq.heappop(low))     # move the largest of low up
        if len(high) > len(low):                      # rebalance sizes
            heapq.heappush(low, -heapq.heappop(high))
        out.append(float(-low[0]) if len(low) > len(high) else (-low[0] + high[0]) / 2)
    return out

assert running_medians([5, 15, 1, 3]) == [5.0, 10.0, 5.0, 4.0]
assert running_medians([]) == []
print(running_medians([5, 15, 1, 3]))
[5.0, 10.0, 5.0, 4.0]

Trace: 5 gives low {5}: median 5. 15 goes to high: median (5 + 15) / 2 = 10. 1 enters low (low {1, 5}, high {15}): median 5. 3 pushes 5 up to high: low {1, 3}, high {5, 15}, median (3 + 5) / 2 = 4.
