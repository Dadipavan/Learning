22.8 How to choose

Start with the size of the data and the size of your machine, then ask what you already know. The flow chart below encodes the order of questions. Follow it from the top; stop at the first tool that answers yes.

How to read it: blue boxes are questions, green boxes are single-machine answers, orange boxes are multi-machine answers. Notice how many paths end on one machine: a modern laptop or a single big cloud machine with DuckDB or Polars handles data far beyond what people expect, and avoids the cost of a cluster. Go right and down only when the data truly cannot be handled by one machine, or when the platform (data lake, scheduler, security) is already built on Spark.

A quick way to know which row you are in: estimate the in-memory size from a sample before you load anything. The block builds a 200,000-row CSV, reads only the first 20,000 rows, and extrapolates.

import os, tempfile import numpy as np import pandas as pd rng = np.random.default_rng(3) n = 200_000 df = pd.DataFrame({ "order_id": np.arange(n), "region": rng.choice(["EU", "US", "APAC", "LATAM", "MEA"], n), "qty": rng.integers(1, 20, n), "price": rng.normal(50, 15, n).round(2), }) path = os.path.join(tempfile.mkdtemp(), "o.csv") df.to_csv(path, index=False) total_rows = sum(1 for _ in open(path)) - 1 sample = pd.read_csv(path, nrows=20_000) per_row = sample.memory_usage(deep=True, index=False).sum() / len(sample) estimate = per_row * total_rows actual = pd.read_csv(path).memory_usage(deep=True, index=False).sum() print("rows:", total_rows) print("estimate within 5% of actual:", abs(estimate - actual) / actual < 0.05) print("in-memory is larger than the file:", actual > os.path.getsize(path))
  1. Counting lines is a cheap streaming pass over the file (no parsing), giving the row count.
  2. Reading the first 20,000 rows and measuring memory_usage(deep=True) gives bytes per row at the dtypes pandas would choose.
  3. Multiplying by the row count estimates the full size. The estimate is good when the sample is representative: if the file is sorted so that long strings appear only at the end, the sample under-estimates.
  4. For this table the in-memory size exceeds the CSV file size, mostly because strings are bulky as Python objects. A common surprise: a 10 GB CSV can need 20 GB or more of RAM in pandas, plus working memory for every operation.
REAL JOB
In interviews and design reviews, defend the choice with numbers: data size, growth rate, how many people run the job, how often, and the cost of the platform. "We used Spark because it is big data" is a weak answer. "Our largest table is 40 GB, DuckDB on one 64 GB machine finished in 3 minutes, so we skipped the cluster" is a strong one.
