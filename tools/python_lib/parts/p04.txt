<h3>Beginner: clean messy text</h3>
@@CODE
import pandas as pd

names = pd.Series(["  Ana Silva ", "BO chen", "cy O'Neil"])
clean = names.str.strip().str.title()
print(clean.tolist())
parts = clean.str.split(" ", n=1, expand=True)
parts.columns = ["first", "last"]
print(parts)
print(clean.str.contains("an", case=False).tolist())
print(clean.str.len().tolist())
@@END
<ol>
<li><code>.str</code> is an <em>accessor</em>: it applies a text method to every element of the column. You chain methods: strip first, then title-case.</li>
<li><code>title()</code> capitalises each word; it handles these three names, but it turns "mcdonald" into "Mcdonald", so check on your real data.</li>
<li><code>split(" ", n=1, expand=True)</code> splits at the first space only and returns a DataFrame with one column per piece; we then name them.</li>
<li><code>contains("an", case=False)</code> tests for the substring ignoring case: True for "Ana Silva", False for the others.</li>
<li><code>len()</code> counts characters (after cleaning, so the spaces are gone).</li>
</ol>
<h3>Intermediate: regex extraction and dates</h3>
@@CODE
import pandas as pd

log = pd.DataFrame({
    "line": ["ERR 2025-03-07 14:05 code=502", "OK 2025-03-08 09:30 code=200", "ERR 2025-03-09 23:59 code=404"],
})
ex = log["line"].str.extract(r"^(?P<level>\w+) (?P<when>[\d-]+ [\d:]+) code=(?P<code>\d+)$")
ex["when"] = pd.to_datetime(ex["when"])
ex["code"] = ex["code"].astype(int)
print(ex)
print(ex["when"].dt.day_name().tolist())
ex["day"] = ex["when"].dt.normalize()
ex["hour"] = ex["when"].dt.hour
print(ex[["day", "hour"]])
gap = ex["when"].diff()
print(gap.dt.total_seconds().div(3600).round(1).tolist())
@@END
<ol>
<li><code>str.extract</code> takes a regular expression with <em>named groups</em> <code>(?P&lt;name&gt;...)</code> and returns one column per group. Rows that do not match become NaN.</li>
<li>Extracted pieces are text, so we convert: <code>to_datetime</code> for the timestamp and <code>astype(int)</code> for the code.</li>
<li><code>.dt</code> is the date accessor, the twin of <code>.str</code>. <code>day_name()</code> gives weekday names (7 March 2025 was a Friday).</li>
<li><code>normalize()</code> sets the time to midnight, which is the easiest way to get a "date" key for grouping; <code>hour</code> is an integer part.</li>
<li><code>diff()</code> on a datetime column gives a Timedelta between consecutive rows. <code>total_seconds()</code> converts to seconds, and dividing by 3600 gives hours. The first gap is NaN because no row precedes it.</li>
</ol>
<h3>apply vs map vs vectorised: the speed ladder</h3>
<p>The same task, "total = price times quantity", can be written four ways. They give the same answer at very different cost.</p>
@@CODE
import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
df = pd.DataFrame({"price": rng.uniform(1, 10, 5), "qty": rng.integers(1, 5, 5)})

a = df["price"] * df["qty"]
b = df.apply(lambda r: r["price"] * r["qty"], axis=1)
c = pd.Series([p * q for p, q in zip(df["price"], df["qty"])])
d = pd.Series([r.price * r.qty for r in df.itertuples()])
print(np.allclose(a, b), np.allclose(a, c), np.allclose(a, d))
print(a.round(2).tolist())

tier = pd.Series([1, 2, 3, 1, 4]).map({1: "single", 2: "pair"}).fillna("bulk")
print(tier.tolist())
@@END
<ol>
<li><code>a</code> is vectorised: one multiplication of two whole columns, executed in compiled code. This is the default choice.</li>
<li><code>b</code> uses <code>apply(axis=1)</code>, which builds a Series object for every row and calls your Python function once per row. It is the slowest and the most overused.</li>
<li><code>c</code> is a list comprehension over <code>zip</code> of two columns. It is a Python loop but avoids row objects, so it is typically much faster than <code>apply(axis=1)</code> and is a good fallback for logic that cannot be vectorised.</li>
<li><code>d</code> uses <code>itertuples()</code>, the right way to loop over rows if you must (much faster than <code>iterrows</code>).</li>
<li><code>np.allclose</code> checks that all four agree. The timings are in the figure below.</li>
<li><code>Series.map(dict)</code> is the vectorised way to recode values. Anything not in the dict becomes NaN, which we fill with "bulk".</li>
</ol>
<figure><img src="images/lib17_speed.png" alt="Log-scale bar chart of milliseconds for iterrows, apply axis 1, list comprehension and vectorised addition" loading="lazy"/><figcaption>Adding two columns of 100,000 rows. Times measured on one laptop; they vary by machine, version and data, but the ordering is stable.</figcaption></figure>
<p><strong>How to read it:</strong> the horizontal axis is logarithmic, so each gridline is ten times larger than the one before. The vectorised bar is orders of magnitude shorter than the two row-wise approaches. The gap grows with the number of rows. Reach for <code>apply(axis=1)</code> only after you have tried column arithmetic, <code>np.where</code>, <code>np.select</code>, <code>map</code> and the <code>.str</code>/<code>.dt</code> accessors.</p>

<h2 id="s17-9">17.9 groupby: agg, transform, filter and Named Aggregation</h2>
<figure><img src="images/lib17_splitapply.png" alt="Diagram: all rows are split into groups A, B and C, each is summed, and the results are combined into one row per key" loading="lazy"/><figcaption>groupby is split, apply, combine: cut the rows by key, summarise each piece, stack the summaries.</figcaption></figure>
<p><strong>How to read it:</strong> follow the arrows left to right. The blue box holds all rows. They are split by key into three boxes, a function (here <code>sum</code>) runs inside each box independently, and the three small results are combined into the final table with one row per key. <code>agg</code> shrinks each group to one row. <code>transform</code> returns one value for <em>every</em> original row. <code>filter</code> keeps or drops whole groups.</p>

<h3>Beginner: one key, one statistic</h3>
@@CODE
import pandas as pd

df = pd.DataFrame({
    "city": ["Oslo", "Rome", "Oslo", "Lima", "Rome", "Oslo"],
    "sales": [10, 7, 3, 5, 9, 12],
})
print(df.groupby("city")["sales"].sum())
print(df.groupby("city")["sales"].agg(["count", "mean", "max"]))
print(df.groupby("city", as_index=False)["sales"].sum())
@@END
<ol>
<li><code>groupby("city")</code> says "split by city". <code>["sales"]</code> selects the column to summarise and <code>.sum()</code> adds within each group. Oslo: 10+3+12 = 25. Groups are sorted by key by default.</li>
<li>Passing a list to <code>agg</code> computes several statistics at once; each becomes a column.</li>
<li><code>as_index=False</code> keeps <code>city</code> as an ordinary column instead of the index, which is easier to merge or plot afterwards.</li>
</ol>
<h3>Intermediate: named aggregation, transform and filter</h3>
@@CODE
import pandas as pd

df = pd.DataFrame({
    "city": ["Oslo", "Rome", "Oslo", "Lima", "Rome", "Oslo"],
    "channel": ["web", "web", "shop", "web", "shop", "web"],
    "sales": [10, 7, 3, 5, 9, 12],
})
summary = df.groupby("city").agg(
    orders=("sales", "size"),
    total=("sales", "sum"),
    best=("sales", "max"),
    channels=("channel", "nunique"),
)
print(summary)

df["share_of_city"] = (df["sales"] / df.groupby("city")["sales"].transform("sum")).round(2)
df["vs_city_mean"] = df["sales"] - df.groupby("city")["sales"].transform("mean")
print(df)

big = df.groupby("city").filter(lambda d: len(d) >= 2)
print(sorted(big["city"].unique()))
@@END
<ol>
<li>Named aggregation has the form <code>output_name=(column, function)</code>. It gives flat, readable column names, so prefer it over the dict-of-lists form which creates a two-level header.</li>
<li><code>size</code> counts rows, <code>nunique</code> counts distinct channels. Lima has one order and one channel.</li>
<li><code>transform("sum")</code> returns a Series aligned to the original rows: each Oslo row sees 25. Dividing gives each row's share of its city total.</li>
<li><code>sales - transform("mean")</code> centres each value on its group mean: a common feature-engineering step.</li>
<li><code>filter</code> receives each group as a small DataFrame and returns True to keep it. Lima has only one row, so it is dropped; Oslo and Rome stay.</li>
</ol>
<p class="problem"><span class="pl">Problem 17.9.1</span> For the table above, find the city whose average sale is highest, using one chain.</p>
<table class="steps"><tr><th>Idea</th><td>Group by city, take the mean of sales, then pick the label of the largest mean.</td></tr><tr><th>Code</th><td><code>df.groupby("city")["sales"].mean().idxmax()</code></td></tr><tr><th>By hand</th><td>Oslo (10+3+12)/3 = 8.33, Rome (7+9)/2 = 8.0, Lima 5/1 = 5.0.</td></tr><tr><th>Answer</th><td>Oslo. <code>idxmax()</code> returns the <em>label</em> (the city), whereas <code>max()</code> would return the number 8.33.</td></tr></table>
<h3>Expert: top-N per group, custom aggregations, and what apply costs</h3>
@@CODE
import pandas as pd

df = pd.DataFrame({
    "dept": ["a", "a", "a", "b", "b", "b"],
    "emp": ["u1", "u2", "u3", "u4", "u5", "u6"],
    "pay": [50, 80, 65, 90, 40, 70],
})
top2 = df.sort_values("pay", ascending=False).groupby("dept").head(2)
print(top2.sort_values(["dept", "pay"], ascending=[True, False]))

df["rank"] = df.groupby("dept")["pay"].rank(ascending=False, method="first").astype(int)
print(df[df["rank"] == 1][["dept", "emp"]])

spread = df.groupby("dept")["pay"].agg(lambda s: s.max() - s.min())
print(spread.to_dict())
print(df.groupby("dept")["pay"].agg(["min", "max"]).assign(spread=lambda d: d["max"] - d["min"])["spread"].to_dict())
@@END
<ol>
<li>Sorting by pay descending and then taking <code>groupby("dept").head(2)</code> is the fast idiom for top-N per group. <code>head</code> is implemented without calling Python per group.</li>
<li>The second <code>sort_values</code> is only for tidy display.</li>
<li><code>rank(ascending=False, method="first")</code> numbers pay within each department; ties get distinct ranks in order of appearance. Filtering <code>rank == 1</code> gives the top earner per department. Ranks are floats, hence <code>astype(int)</code>.</li>
<li><code>agg(lambda ...)</code> calls your Python function once per group: simple and flexible, but slower for many groups.</li>
<li>The last line computes the same spread with built-ins (<code>min</code>, <code>max</code>, then subtract). Prefer built-in aggregations whenever possible; they run in compiled code.</li>
</ol>
