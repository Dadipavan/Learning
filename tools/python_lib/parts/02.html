22.2 Before you scale: measure, shrink and chunk in pandas

The cheapest speed-up is the one that needs no new library. Most "big data" problems at the 1 to 20 GB scale are really "wasteful data" problems: columns you never use, 64-bit numbers holding values below 100, and the word "EU" stored a million times. This section gives you the measuring tools and the three fixes: read less, store smaller, read in pieces.

Beginner: how big is a column really?

An integer in pandas defaults to 64 bits, which is 8 bytes, even if the value is 7. A column of 1 million integers therefore takes 8 MB. A string column is worse: each Python string object costs dozens of bytes beyond its characters. A category column keeps each distinct value once and stores a tiny integer code per row. The next block builds a synthetic table of 1 million orders and measures every column before and after shrinking. This synthetic table is reused in the next blocks.

Problem 22.2.1 Build a 1-million-row orders table (order_id, customer_id, region, qty, price). Measure the memory of each column, then shrink it with downcasting, category and float32, and compare.

import numpy as np import pandas as pd rng = np.random.default_rng(42) n = 1_000_000 df = pd.DataFrame({ "order_id": np.arange(n), "customer_id": rng.integers(0, 50_000, n), "region": rng.choice(["EU", "US", "APAC", "LATAM", "MEA"], n), "qty": rng.integers(1, 20, n), "price": rng.normal(50, 15, n).round(2), }) mb = lambda s: round(s.memory_usage(deep=True, index=False) / 1e6, 1) print("BEFORE") for c in df: print(f" {c:12s} {str(df[c].dtype):6s} {mb(df[c]):6.1f} MB") print(" total", round(df.memory_usage(deep=True).sum() / 1e6, 1), "MB") small = df.assign( order_id=pd.to_numeric(df.order_id, downcast="unsigned"), customer_id=pd.to_numeric(df.customer_id, downcast="unsigned"), region=df.region.astype("category"), qty=pd.to_numeric(df.qty, downcast="unsigned"), price=df.price.astype("float32"), ) print("AFTER") for c in small: print(f" {c:12s} {str(small[c].dtype):8s} {mb(small[c]):5.1f} MB") print(" total", round(small.memory_usage(deep=True).sum() / 1e6, 1), "MB")
  1. Lines 4 to 12 build the table with a seeded random generator, so every run gives the same numbers.
  2. mb is a one-line helper: deep=True counts the real size of string contents, not just pointers.
  3. BEFORE: the four numeric columns cost 8 MB each (1 million values times 8 bytes). The region column (the text EU, US and so on) costs over 50 MB, more than the other four together. In pandas 3.0 text columns default to the str dtype; without PyArrow installed it is still backed by Python string objects, which is why it is large. With PyArrow installed the text is stored more compactly, but a category is smaller still for few distinct values.
  4. pd.to_numeric(..., downcast="unsigned") picks the smallest unsigned integer dtype that holds every value: 1,000,000 ids need 32 bits, customers below 50,000 need 16, quantities below 20 need 8.
  5. astype("category") stores 5 labels and one 8-bit code per row: 1 MB.
  6. float32 halves the price column. It keeps about 7 significant digits, fine for a price of 49.99 in analytics, wrong for money you must add up exactly (see pitfalls).
  7. Result: about 84 MB becomes about 12 MB, seven times smaller, with the same information. Check the range before you force a type: to_numeric(downcast=) picks a dtype from the actual min and max, but a blind astype("uint8") on a value of 300 silently wraps it to 44, and writing 300 into an existing uint8 column raises an error.

How to read it: each pair of bars is one column. The orange bar is the default dtype, the green bar the shrunk version. The tall orange bar is the text column; the other columns shrink by half or more. The lesson: look at the biggest bar first. Shrinking an already small column barely helps.

Intermediate: chunking, the way to beat the memory wall

If you cannot fit the file, do not load the file. A chunk is a block of rows. You read one chunk, reduce it to a small partial answer (a sum, a count, a filtered set of rows), throw the chunk away, and move to the next. At the end you combine the partial answers. This works for any decomposable statistic: sums, counts, min, max, and the mean (as sum divided by count). It does not work directly for the median or the exact distinct count, which need other tricks (Section 22.9).

Problem 22.2.2 Write the 1-million-row table to a CSV file. Compute the revenue (qty times price) per region two ways: reading the whole file, and in chunks of 100,000 and 10,000 rows. Compare the peak memory and check that the answers agree.

import os, tempfile, tracemalloc import numpy as np import pandas as pd rng = np.random.default_rng(42) n = 1_000_000 df = pd.DataFrame({ "order_id": np.arange(n), "customer_id": rng.integers(0, 50_000, n), "region": rng.choice(["EU", "US", "APAC", "LATAM", "MEA"], n), "qty": rng.integers(1, 20, n), "price": rng.normal(50, 15, n).round(2), }) path = os.path.join(tempfile.mkdtemp(), "orders.csv") df.to_csv(path, index=False) del df print("file size over 20 MB:", os.path.getsize(path) > 20e6) def revenue_full(): d = pd.read_csv(path) return (d.qty * d.price).groupby(d.region).sum() def revenue_chunked(size): total = None for ch in pd.read_csv(path, chunksize=size): part = (ch.qty * ch.price).groupby(ch.region).sum() total = part if total is None else total.add(part, fill_value=0) return total peaks, answers = {}, {} for label, fn in [("full", revenue_full), ("chunk 100k", lambda: revenue_chunked(100_000)), ("chunk 10k", lambda: revenue_chunked(10_000))]: tracemalloc.start() answers[label] = fn().sort_index() peaks[label] = tracemalloc.get_traced_memory()[1] tracemalloc.stop() print("full peak above 60 MB:", peaks["full"] > 60e6) print("chunk 100k peak below 30 MB:", peaks["chunk 100k"] < 30e6) print("chunk 10k peak below 10 MB:", peaks["chunk 10k"] < 10e6) print("same answer:", np.allclose(answers["full"], answers["chunk 10k"])) print(answers["chunk 10k"].round(0).astype("int64").to_string())
  1. The first half is the same data generator, written to a temporary CSV. del df frees the in-memory copy, so only the file remains, like Priya's situation.
  2. revenue_full loads everything, multiplies qty * price row by row, and groups the products by the region column.
  3. revenue_chunked asks for an iterator: read_csv(chunksize=size) yields DataFrames of at most size rows. Each one is reduced to a 5-row Series of partial sums.
  4. total.add(part, fill_value=0) adds two Series aligned on the region label. fill_value=0 treats a region missing from one chunk as zero instead of producing NaN.
  5. tracemalloc measures the peak Python-level memory while the function runs. The prints use thresholds, not exact bytes, because exact numbers differ a little between machines.
  6. The peak shrinks roughly in proportion to the chunk size, while the answer is identical (up to floating-point rounding, hence allclose). The last line prints the revenue per region as whole numbers.

How to read it: the x-axis is the number of rows per chunk (log scale), the y-axis the peak memory. The blue line climbs with chunk size and the red dashed line is the cost of loading everything. If the file were 100 times larger, the blue points would not move at all, because the chunk size sets the memory, not the file size. That is what lets a laptop process a 10 GB file.

Expert: speed numbers, honestly measured

Smaller data is also faster data, but not every trick helps every time. The next block measures reading and group-by variants on the same million rows. Timings are not pasted as checked output because they change on every run; the table after it shows what one run on one laptop gave.

import os, tempfile, time import numpy as np import pandas as pd rng = np.random.default_rng(42) n = 1_000_000 df = pd.DataFrame({ "order_id": np.arange(n), "customer_id": rng.integers(0, 50_000, n), "region": rng.choice(["EU", "US", "APAC", "LATAM", "MEA"], n), "qty": rng.integers(1, 20, n), "price": rng.normal(50, 15, n).round(2), }) path = os.path.join(tempfile.mkdtemp(), "orders.csv") df.to_csv(path, index=False) def best(fn, reps=5): times = [] for _ in range(reps): t0 = time.perf_counter(); fn(); times.append(time.perf_counter() - t0) return min(times) print("--- reading the CSV (best of 5, seconds) ---") print("read everything ", round(best(lambda: pd.read_csv(path)), 3)) print("usecols 2 of 5 ", round(best(lambda: pd.read_csv(path, usecols=["region", "price"])), 3)) print("usecols + dtype ", round(best(lambda: pd.read_csv(path, usecols=["region", "price"], dtype={"region": "category", "price": "float32"})), 3)) print("chunks of 100k, sum ", round(best(lambda: sum(c.price.sum() for c in pd.read_csv(path, chunksize=100_000))), 3)) df_cat = df.assign(region=df.region.astype("category")) codes = df_cat.region.cat.codes.to_numpy() price = df.price.to_numpy() region = df.region.tolist() def py_loop(): tot = {} for r, p in zip(region, price): tot[r] = tot.get(r, 0.0) + p return tot print("--- mean price per region (best of 5, seconds) ---") print("python dict loop ", round(best(py_loop), 3)) print("groupby str column ", round(best(lambda: df.groupby("region")["price"].mean()), 3)) print("groupby category ", round(best(lambda: df_cat.groupby("region", observed=True)["price"].mean()), 3)) print("numpy bincount codes ", round(best(lambda: np.bincount(codes, weights=price) / np.bincount(codes)), 3))

  1. The timing helper runs each variant five times and keeps the minimum, which is the least noisy estimate of the cost of the code itself.
  2. Reading fewer columns saved about a third here. On a 100-column file the saving is far larger because parsing cost is per column.
  3. Chunking is not free: the same work done in 10 pieces carries a little overhead. You chunk because you must, not to go faster.
  4. Group-by on a category is much faster than on strings because comparing small integers is cheaper than comparing text. This is the same reason databases dictionary-encode strings.
  5. Your numbers will differ, and the ordering is what you should expect to reproduce. The ratios shown are computed from this single run.
COMMON MISTAKE
Wrong: df["price"] = df["price"].astype("float32") on money columns, then summing a billion of them. Symptom: totals differ from the finance system by a few units, and differ again if you change the row order. Fix: store money as integer cents (int64, or int32 if the range allows) and divide by 100 only for display. Use float32 only for measurements where 7 digits are plenty.
