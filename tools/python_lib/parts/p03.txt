<h3>Beginner: columns, labels, positions</h3>
@@CODE
import pandas as pd

df = pd.DataFrame(
    {"city": ["Oslo", "Rome", "Lima", "Oslo"], "sales": [10, 7, 3, 12]},
    index=[10, 11, 12, 13],
)
print(df["city"].tolist())
print(df.loc[11, "sales"])
print(df.iloc[1, 1])
print(df.loc[10:12, "city"].tolist())
print(df.iloc[0:2].index.tolist())
@@END
<ol>
<li><code>df["city"]</code> returns a Series; <code>.tolist()</code> turns it into a plain list so the print is short.</li>
<li><code>df.loc[11, "sales"]</code> means "the row labelled 11, column sales", which is 7.</li>
<li><code>df.iloc[1, 1]</code> means "second row, second column" by position. It is also 7 here because label 11 sits in position 1.</li>
<li><code>loc[10:12]</code> is a <em>label</em> slice and includes the end label 12, so three rows come back.</li>
<li><code>iloc[0:2]</code> is a <em>position</em> slice and excludes the end, so two rows come back, with labels 10 and 11.</li>
</ol>
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Mixing up loc and iloc end points.</strong> <code>loc[0:2]</code> returns three rows, <code>iloc[0:2]</code> returns two. And with a non-default index, <code>s[0]</code> no longer falls back to position in pandas 3.0: it raises a <code>KeyError</code>. Say <code>loc</code> or <code>iloc</code> every time.</div></div>
<h3>Intermediate: Boolean masks and query</h3>
@@CODE
import pandas as pd

df = pd.DataFrame({
    "city": ["Oslo", "Rome", "Lima", "Oslo", "Rome"],
    "sales": [10, 7, 3, 12, 9],
    "paid": [True, False, True, True, False],
})
mask = (df["sales"] > 5) & df["paid"]
print(mask.tolist())
print(df[mask])
print(df[df["city"].isin(["Rome", "Lima"]) | (df["sales"] > 11)])
print(df[~df["paid"]]["sales"].sum())
cut = 8
print(df.query("sales > @cut and city != 'Rome'"))
@@END
<ol>
<li>Each comparison returns a Series of True/False. <code>&amp;</code> combines them element by element. Every comparison needs its own brackets because <code>&amp;</code> binds tighter than <code>&gt;</code>.</li>
<li>The column <code>paid</code> is already Boolean, so it works as a mask on its own.</li>
<li><code>df[mask]</code> keeps the rows where the mask is True and keeps their original labels (0 and 3).</li>
<li>Line 3 uses <code>|</code> (or) with <code>isin</code>: rows in Rome or Lima, or with sales above 11.</li>
<li><code>~df["paid"]</code> flips True and False, selecting the unpaid rows (sales 7 and 9, total 16).</li>
<li><code>query</code> takes the condition as a string, which reads like SQL. <code>@cut</code> pulls in the Python variable. Use <code>and</code>/<code>or</code> inside query, but <code>&amp;</code>/<code>|</code> outside it.</li>
</ol>
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Using and / or on Series.</strong> <code>df[(df.a &gt; 1) and (df.b &lt; 2)]</code> raises "The truth value of a Series is ambiguous". Python's <code>and</code> wants one True or False, but a Series holds many. Use <code>&amp;</code>, <code>|</code>, <code>~</code> with brackets.</div></div>
<h3>Expert: assigning safely with loc, where and np.where</h3>
@@CODE
import numpy as np
import pandas as pd

df = pd.DataFrame({"x": [-5, 2, -1, 8], "grp": ["a", "b", "a", "b"]})
df.loc[df["x"] < 0, "x"] = 0
print(df["x"].tolist())

df["sign"] = np.where(df["x"] > 0, "pos", "zero")
df["capped"] = df["x"].where(df["x"] < 5, 5)
df["label"] = np.select([df["x"] == 0, df["x"] < 5], ["none", "low"], default="high")
print(df)
@@END
<ol>
<li><code>df.loc[mask, "x"] = 0</code> changes only the cells where the mask is True. This one-step form is the safe way to assign into a selection.</li>
<li><code>np.where(cond, a, b)</code> builds a whole new column: "pos" where x is positive, else "zero".</li>
<li><code>Series.where(cond, other)</code> keeps values where the condition is True and replaces the rest. Here it caps x at 5.</li>
<li><code>np.select(conditions, choices, default)</code> handles more than two outcomes. The conditions are checked in order and the first True wins, so <code>x == 0</code> is tested before <code>x &lt; 5</code>.</li>
</ol>

import pandas as pd

df = pd.DataFrame({"item": ["pen", "book", "lamp"], "price": [2.0, 12.5, 30.0], "qty": [10, 2, 1]})

<h3>Intermediate: dtypes that save memory and prevent bugs</h3>
@@CODE
import pandas as pd

raw = pd.Series(["12", "7", "oops", "30", None])
nums = pd.to_numeric(raw, errors="coerce")
print(nums.tolist())

ints = nums.astype("Int64")
print(ints.tolist(), ints.dtype)

size = pd.Series(["M", "S", "L", "M", "S"])
cat = pd.Series(pd.Categorical(size, categories=["S", "M", "L"], ordered=True))
print(cat.dtype, (cat >= "M").tolist())
print(cat.sort_values().tolist(), cat.cat.codes.tolist())

dates = pd.to_datetime(pd.Series(["03/04/2025", "15/04/2025"]), format="%d/%m/%Y")
print(dates.dt.month.tolist(), dates.dtype)
@@END
<ol>
<li><code>to_numeric(..., errors="coerce")</code> turns "oops" and the missing value into NaN instead of crashing. The default <code>errors="raise"</code> is better when you want to be told about bad data.</li>
<li><code>astype("Int64")</code> (capital I) is the <em>nullable</em> integer: it keeps integers as integers and shows the gap as <code>&lt;NA&gt;</code>. The plain <code>int64</code> cannot hold a missing value.</li>
<li>An ordered <code>Categorical</code> knows S &lt; M &lt; L, so comparisons (<code>&gt;= "M"</code>) and sorting follow that order, not the alphabet (where L would come before M).</li>
<li><code>cat.cat.codes</code> are the small integers pandas actually stores: S=0, M=1, L=2. That is why categories save memory.</li>
<li>Always give <code>format=</code> to <code>to_datetime</code> for non-ISO dates. "03/04/2025" is 3 April in Europe but 4 March in the US, and guessing is how silent bugs are born.</li>
</ol>
<h3>Expert: what each dtype costs</h3>
<figure><img src="images/lib17_dtypes.png" alt="Horizontal bar chart of memory for str, category, int64, int8 and float64 columns of 200,000 rows" loading="lazy"/><figcaption>Memory for the same 200,000 values stored with different dtypes. Measured on one machine; exact bytes vary by platform and version.</figcaption></figure>
<p><strong>How to read it:</strong> each bar is one column of 200,000 values. The text column built from four repeated words is the longest bar. Converting it to <code>category</code> stores each word once plus a small integer code per row, so the bar shrinks a lot. For numbers, shrinking <code>int64</code> to <code>int8</code> divides memory by eight when values fit between -128 and 127. The lesson: low-cardinality text becomes category, and numbers get the smallest safe type.</p>
@@CODE
import numpy as np
import pandas as pd

rng = np.random.default_rng(0)
n = 200_000
city = pd.Series(rng.choice(["Oslo", "Rome", "Lima", "Kyiv"], n))
qty = pd.Series(rng.integers(0, 100, n))

print(round(city.memory_usage(deep=True) / 1e6, 2), "MB as str")
print(round(city.astype("category").memory_usage(deep=True) / 1e6, 2), "MB as category")
print(round(qty.memory_usage(deep=True) / 1e6, 2), "MB int64")
print(round(qty.astype("int8").memory_usage(deep=True) / 1e6, 2), "MB int8")
print(qty.astype("int8").max(), np.iinfo("int8").max)
@@END
<ol>
<li>200,000 values drawn from 4 words; <code>default_rng(0)</code> makes it repeatable.</li>
<li><code>memory_usage(deep=True)</code> measures real bytes including the text; without <code>deep=True</code> pandas under-counts text columns.</li>
<li>The category version stores 4 strings once plus one byte per row, which is why it is far smaller.</li>
<li>The int8 conversion is only safe because the largest value, 99, is below <code>np.iinfo("int8").max</code> (127). If a value did not fit, the conversion would silently wrap or raise; always check the range first, or use <code>pd.to_numeric(s, downcast="integer")</code> which picks a safe size for you.</li>
</ol>
<div class="callout cream"><div class="lab">REAL JOB</div><div class="txt">Rule of thumb: if a text column has fewer distinct values than about half of its rows, try <code>category</code>. It cuts memory and speeds up <code>groupby</code>. If the column is nearly all unique (ids, free text), keep it as <code>str</code>.</div></div>

<h3>Beginner: find, drop, fill</h3>
@@CODE
import numpy as np
import pandas as pd

df = pd.DataFrame({"id": [1, 2, 3, 4], "age": [25, np.nan, 40, np.nan], "city": ["Oslo", "Rome", None, "Lima"]})
print(df.isna().sum().to_dict())
print(df.dropna().shape)
print(df.dropna(subset=["city"]).shape)
filled = df.assign(age=df["age"].fillna(df["age"].median()), city=df["city"].fillna("unknown"))
print(filled)
@@END
<ol>
<li><code>isna().sum()</code> counts missing cells: 2 in age, 1 in city.</li>
<li><code>dropna()</code> with no arguments removes every row that has <em>any</em> gap. Rows 1 and 3 lack an age and row 2 lacks a city, so only row 0 survives: the shape is (1, 3).</li>
<li><code>subset=["city"]</code> only cares about city, so rows with a missing age are kept and only row 2 is dropped: (3, 3).</li>
<li>Filling age with the median (32.5, the middle of 25 and 40) is a simple, outlier-resistant choice. Filling text with the word "unknown" keeps the row and makes the gap visible.</li>
</ol>
<h3>Intermediate: group-aware fill, sentinels, forward fill</h3>
@@CODE
import numpy as np
import pandas as pd

df = pd.DataFrame({
    "dept": ["a", "a", "b", "b", "b"],
    "pay": [100.0, np.nan, 200.0, -999.0, np.nan],
})
df["pay"] = df["pay"].replace(-999, np.nan)
df["pay_filled"] = df["pay"].fillna(df.groupby("dept")["pay"].transform("median"))
print(df)

ts = pd.Series([1.0, np.nan, np.nan, 4.0, np.nan])
print(ts.ffill().tolist())
print(ts.interpolate().tolist())
@@END
<ol>
<li>Some systems store "unknown" as -999. If you average that you get nonsense, so <code>replace(-999, np.nan)</code> converts the sentinel to a real missing marker first.</li>
<li><code>groupby("dept")["pay"].transform("median")</code> returns a Series the same length as <code>df</code> in which each row holds the median of its own department (100 for a, 200 for b).</li>
<li><code>fillna(that_series)</code> fills each gap with the matching department median. This is better than one global median because departments differ.</li>
<li><code>ffill()</code> carries the last known value forward (1, 1, 1, 4, 4): right for state that persists, such as a price.</li>
<li><code>interpolate()</code> draws a straight line between known points (1, 2, 3, 4, then 4 at the end because nothing follows): right for smooth measurements such as temperature.</li>
</ol>
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Filling before you understand why it is missing.</strong> If "no discount" is stored as NaN, filling it with the mean invents a discount. Decide per column: is missing zero, unknown, or not applicable? Keep an indicator column (<code>df["age_missing"] = df["age"].isna()</code>) when missingness itself carries information.</div></div>
<h3>Duplicates: exact, by key, and keep the latest</h3>
@@CODE
import pandas as pd

df = pd.DataFrame({
    "id": [1, 1, 2, 3, 3],
    "ts": ["2025-01-01", "2025-01-05", "2025-01-02", "2025-01-03", "2025-01-03"],
    "val": [10, 12, 7, 5, 5],
})
print(df.duplicated().tolist())
print(df.duplicated("id", keep=False).tolist())
latest = df.sort_values("ts").drop_duplicates("id", keep="last")
print(latest.sort_values("id"))
print(df.drop_duplicates().shape[0])
@@END
<ol>
<li><code>duplicated()</code> with no arguments compares whole rows. Only the last row repeats an earlier one exactly, so only it is True.</li>
<li><code>duplicated("id", keep=False)</code> compares only the key and marks <em>every</em> row that shares an id (<code>keep=False</code>), which is what you want when you need to inspect all conflicting versions.</li>
<li>To keep the most recent row per id: sort by time first, then <code>drop_duplicates("id", keep="last")</code>. Order matters; without the sort, "last" means last in file order.</li>
<li>Dropping exact duplicates leaves 4 rows. Note the difference: key duplicates (id 1 appears with different values) are a <em>business</em> question, exact duplicates are usually an extraction error.</li>
</ol>
