22.3 Parquet and columnar file formats

Beginner: why CSV is the wrong format for big data

A CSV file is plain text. That is friendly (you can open it anywhere) and wasteful. The number 49.99 is stored as five characters, not one 8-byte float. Nothing says whether a column is an integer or a date, so the reader must guess. You cannot read one column without scanning every line. And a CSV cannot be split safely in the middle of a quoted multi-line field. Parquet is an open file format built for analytics. It stores data by column, with a schema (names and types), compression, and small statistics (minimum and maximum) for each block. The same data is typically many times smaller than the CSV, and a query that needs two columns reads two columns.

DEFINITION
Row group: a block of rows (for example 100,000 to 1,000,000) inside a Parquet file. Column chunk: the data of one column inside one row group. Footer: metadata at the end of the file with the schema and, for each column chunk, its location, row count and minimum/maximum. A reader jumps to the footer first, decides which chunks it needs, and reads only those. Apache Arrow is the matching in-memory columnar format that Polars, DuckDB, PyArrow, and (optionally) pandas use, so data moves between them with little copying.

How to read it: the dataset is a folder, not a file. Each level of sub-folders is named column=value. The query asks for year 2025 and region EU, so the engine lists the folders, discards every branch whose name fails the filter (grey) and opens one file (green). Nothing was read from the other three files. This is called partition pruning. Inside the one file we additionally get row-group skipping from the footer statistics.

Intermediate: see the columnar idea with tools you have

We cannot write Parquet here (no PyArrow), but we can show the principle with NumPy. Store each numeric column as its own binary .npy file (typed, no parsing, one file per column), and compare with the CSV.

Problem 22.3.1 Write the 1-million-row table as one CSV and as one binary file per column. Then compute the total of the price column from each, and report how many bytes each approach had to touch.

import os, tempfile import numpy as np import pandas as pd rng = np.random.default_rng(42) n = 1_000_000 df = pd.DataFrame({ "order_id": np.arange(n, dtype="uint32"), "customer_id": rng.integers(0, 50_000, n).astype("uint16"), "region": pd.Categorical(rng.choice(["EU", "US", "APAC", "LATAM", "MEA"], n)), "qty": rng.integers(1, 20, n).astype("uint8"), "price": rng.normal(50, 15, n).round(2), }) d = tempfile.mkdtemp() csv_path = os.path.join(d, "orders.csv") df.to_csv(csv_path, index=False) for c in ["order_id", "customer_id", "qty", "price"]: np.save(os.path.join(d, c + ".npy"), df[c].to_numpy()) np.save(os.path.join(d, "region_codes.npy"), df["region"].cat.codes.to_numpy()) size = lambda p: os.path.getsize(p) col_files = [f for f in os.listdir(d) if f.endswith(".npy")] print("csv MB :", round(size(csv_path) / 1e6, 1)) print("all columns MB :", round(sum(size(os.path.join(d, f)) for f in col_files) / 1e6, 1)) print("price.npy MB :", round(size(os.path.join(d, "price.npy")) / 1e6, 1)) total_csv = pd.read_csv(csv_path)["price"].sum() price = np.load(os.path.join(d, "price.npy"), mmap_mode="r") total_npy = float(price.sum()) print("same total :", np.isclose(total_csv, total_npy)) print("bytes touched, binary vs csv:", f"{size(os.path.join(d, 'price.npy')) / size(csv_path):.0%}")
  1. The table uses already-small dtypes, built with the knowledge from Section 22.2.
  2. The CSV is the row-oriented, text version. Each numeric column is saved by np.save into its own file; the region column is saved as 8-bit category codes.
  3. The CSV is about 25 MB. All column files together are about 16 MB, because 8-bit and 16-bit numbers need fewer bytes than their decimal text.
  4. For the total price, the CSV approach must parse the entire file. The column approach opens only price.npy.
  5. mmap_mode="r" memory-maps the file: the operating system pages bytes in on demand and the array behaves like a normal NumPy array.
  6. The last line reports that the binary price column is about a third of the size of the CSV that held all five columns. Real Parquet adds compression on top (dictionary encoding, run-length encoding, a general compressor), so it usually does better still, and it adds a schema and statistics that this toy lacks.

Now the folder idea. Here we write a small dataset in the Hive layout (as CSV files, since Parquet is unavailable), then answer a filtered query by opening only the matching folder.

Problem 22.3.2 Write 100,000 orders into year=.../region=.../part-0.csv folders. Answer "total amount for year 2025 and region EU" by reading only one file, and prove the answer equals the full scan.

import os, tempfile from pathlib import Path import numpy as np import pandas as pd rng = np.random.default_rng(5) n = 100_000 df = pd.DataFrame({ "year": rng.choice([2024, 2025], n), "region": rng.choice(["EU", "US", "APAC"], n), "amount": rng.integers(1, 500, n), }) root = Path(tempfile.mkdtemp()) / "sales" for (year, region), part in df.groupby(["year", "region"]): folder = root / f"year={year}" / f"region={region}" folder.mkdir(parents=True) part[["amount"]].to_csv(folder / "part-0.csv", index=False) for p in sorted(root.rglob("*.csv")): print(p.relative_to(root)) wanted = root / "year=2025" / "region=EU" / "part-0.csv" fast = pd.read_csv(wanted) print("rows read with pruning:", len(fast), "of", n) full = df[(df.year == 2025) & (df.region == "EU")]["amount"].sum() print("same total:", fast["amount"].sum() == full)
  1. The generator makes three columns; year and region will become folder names.
  2. groupby(["year", "region"]) yields one group per combination. For each, we build the path year=2025/region=EU and write only the amount column, because the other two are encoded in the folder names (that is how Hive layout saves space).
  3. rglob("*.csv") walks the tree; printing the relative paths shows the six files.
  4. A reader that knows the layout builds the path for the wanted year and region and opens that single file: about one sixth of the rows.
  5. The check compares with a brute-force filter over the full table. Equal totals prove that pruning changes how much you read, never the answer.

Real engines do this automatically. The same task in real libraries (not run here):

import pandas as pd import duckdb import polars as pl import pyarrow.dataset as ds # df is the 100,000-row DataFrame (year, region, amount) from the block above # 1. pandas + pyarrow: write a partitioned folder, then read with a filter df.to_parquet("sales", partition_cols=["year", "region"], index=False) eu_2025 = pd.read_parquet("sales", filters=[("year", "==", 2025), ("region", "==", "EU")]) # 2. DuckDB: the folder names become columns; the WHERE clause prunes folders total = duckdb.sql(""" SELECT SUM(amount) FROM read_parquet('sales/*/*/*.parquet', hive_partitioning = true) WHERE year = 2025 AND region = 'EU' """).fetchone()[0] # 3. Polars lazy: scan, filter, aggregate, collect total = (pl.scan_parquet("sales/**/*.parquet", hive_partitioning=True) .filter((pl.col("year") == 2025) & (pl.col("region") == "EU")) .select(pl.col("amount").sum()) .collect() .item()) # 4. pyarrow dataset dataset = ds.dataset("sales", format="parquet", partitioning="hive") table = dataset.to_table(filter=(ds.field("year") == 2025) & (ds.field("region") == "EU"), columns=["amount"])
  1. All four read only the matching folder and only the amount column. The answer is the same number as the runnable block above prints (fast["amount"].sum()).
  2. partition_cols in pandas and PARTITION_BY in DuckDB create the column=value folders for you.
  3. In DuckDB, hive_partitioning = true turns the folder names back into columns, so the WHERE can use them.
  4. Polars scan_parquet is lazy: nothing is read until collect(), and the optimizer pushes the filter and the column choice into the scan.
  5. The PyArrow dataset API is the lower-level building block that several of the others sit on.

Expert: choosing a layout

  • Partition by a column that queries filter on and that has few values (date, country, tenant). Do not partition by a high-cardinality column such as customer_id: you will create millions of tiny files, and listing them costs more than reading them.
  • Aim for files of roughly 100 MB to 1 GB in a distributed setting. Thousands of tiny files (the "small files problem") slow every engine, since each file costs an open, a footer read and a task.
  • Sort within files by the column you filter on. Row-group statistics then become tight (a small min-max range per group), so more groups can be skipped.
  • Compression: snappy is quick and moderate; zstd gives smaller files at a similar speed; gzip is small but slow. Measure on your data.
  • Schema is part of the file. Write dates as dates and money as decimals or integers, not strings. Changing a column type later means rewriting files.
KEY IDEA
Convert once, query many times. Reading a 10 GB CSV costs minutes every time you do it. Convert it to partitioned Parquet once (the recipe in Section 22.9), and every later query reads only the columns and folders it needs.
