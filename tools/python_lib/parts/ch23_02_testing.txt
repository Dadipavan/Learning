
<h2>23.2 Testing: pytest, unittest, Fixtures, Parametrize, Markers and Mocking</h2>
<p>A test is a small function that calls your code with a known input and checks the answer. When you change code next month, the tests tell you in seconds whether you broke something. <strong>pytest</strong> is the standard runner: tests are plain functions and plain <code>assert</code> statements. It is <strong>not installed</strong> on the study machine, so for every pytest example below you see the pytest version labelled <em>not run here</em>, followed by the same checks written with <strong>unittest</strong> (standard library), which really ran and printed the output shown. The ideas (arrange, act, assert) are identical.</p>
<div class="callout green"><div class="lab">KEY IDEA</div><div class="txt">Every test has three parts: <strong>arrange</strong> (build the input), <strong>act</strong> (call the code once), <strong>assert</strong> (compare with the expected answer). If a test has several acts, split it into several tests, so a failure points at exactly one behaviour.</div></div>

<h3>Example 1: the smallest test</h3>
<p>The function under test cleans a price string such as <code>"$1,299.50"</code> into a float. First pytest (not run here), then unittest (run).</p>
@@np
# test_prices.py   -- NOT RUN HERE: pytest is not installed
from prices import clean_price

def test_plain_number():
    assert clean_price("12") == 12.0

def test_dollar_and_comma():
    assert clean_price("$1,299.50") == 1299.5

def test_blank_is_none():
    assert clean_price("  ") is None
@@end
@@py
import io
import unittest

def clean_price(text):
    text = text.strip().replace("$", "").replace(",", "")
    return float(text) if text else None

class TestPrices(unittest.TestCase):
    def test_plain_number(self):
        self.assertEqual(clean_price("12"), 12.0)

    def test_dollar_and_comma(self):
        self.assertEqual(clean_price("$1,299.50"), 1299.5)

    def test_blank_is_none(self):
        self.assertIsNone(clean_price("  "))

def run(case):
    suite = unittest.defaultTestLoader.loadTestsFromTestCase(case)
    res = unittest.TextTestRunner(stream=io.StringIO(), verbosity=0).run(suite)
    print("ran", res.testsRun, "failures", len(res.failures), "errors", len(res.errors))
    return res

run(TestPrices)
@@end
<ol><li>The pytest file imports the function and defines three functions whose names start with <code>test_</code>. pytest finds them by that prefix; no class is needed.</li>
<li>In the unittest version we define <code>clean_price</code> and the tests in one file so the block is standalone. A test class must inherit from <code>unittest.TestCase</code> and its methods must start with <code>test</code>.</li>
<li><code>assertEqual(a, b)</code> is the unittest spelling of <code>assert a == b</code>; <code>assertIsNone(x)</code> is <code>assert x is None</code>.</li>
<li><code>run</code> loads all tests in the class, runs them silently into a string buffer, and prints only the counts. We keep it small because the next blocks reuse the same idea.</li>
<li>Output: 3 tests ran, 0 failures and 0 errors. A <em>failure</em> is a wrong answer (an assertion); an <em>error</em> is an unexpected exception.</li></ol>
<h3>Example 2: parametrize, many inputs one test</h3>
<p>Copy-pasting a test per input is noisy. <code>parametrize</code> turns one test into a table of cases. unittest's closest tool is <code>subTest</code>, which reports each failing row separately. We include one wrong expectation on purpose to see what a failure looks like.</p>
@@np
# NOT RUN HERE: pytest is not installed
import pytest
from prices import clean_price

@pytest.mark.parametrize(
    "text, expected",
    [
        ("12", 12.0),
        ("$1,299.50", 1299.5),
        ("  7.5 ", 7.5),
        pytest.param("$0", 1.0, id="wrong-on-purpose"),
    ],
)
def test_clean_price(text, expected):
    assert clean_price(text) == expected
@@end
@@py
import io
import unittest

def clean_price(text):
    text = text.strip().replace("$", "").replace(",", "")
    return float(text) if text else None

class TestPrices(unittest.TestCase):
    def test_table(self):
        cases = [("12", 12.0), ("$1,299.50", 1299.5), ("  7.5 ", 7.5), ("$0", 1.0)]
        for text, expected in cases:
            with self.subTest(text=text):
                self.assertEqual(clean_price(text), expected)

suite = unittest.defaultTestLoader.loadTestsFromTestCase(TestPrices)
res = unittest.TextTestRunner(stream=io.StringIO(), verbosity=0).run(suite)
print("failures:", len(res.failures))
case, message = res.failures[0]
print(str(case))
print(message.strip().splitlines()[-1])
@@end
<ol><li>The pytest version lists four rows; <code>pytest.param(..., id=...)</code> gives the last row a readable name in the report. It will fail on purpose, and pytest prints that one row only; the other three pass.</li>
<li>The unittest loop does the same: <code>with self.subTest(text=text)</code> wraps each row so a failure in one row does not stop the loop.</li>
<li>After the run, <code>res.failures</code> is a list of <code>(test, traceback_text)</code> pairs. We print the test label, which includes the failing parameter, and the last line of the traceback, which holds the comparison.</li>
<li>The output shows 1 failure. Read it as: the case with <code>text='$0'</code> returned <code>0.0</code> while the test expected <code>1.0</code>. The code is right and the test row is wrong, a reminder that tests have bugs too.</li></ol>
<h3>Example 3: fixtures and temporary folders</h3>
<p>A <strong>fixture</strong> prepares something many tests need (a DataFrame, a file, a database connection) and cleans it up afterwards. pytest injects it by argument name. <code>tmp_path</code> is a built-in fixture that gives every test its own empty folder.</p>
@@np
# NOT RUN HERE: pytest is not installed
import pandas as pd
import pytest

@pytest.fixture
def csv_file(tmp_path):
    path = tmp_path / "orders.csv"
    path.write_text("order_id,amount\n1,10.5\n2,4.5\n")
    yield path            # the test runs here
    print("teardown")     # code after yield runs afterwards

def test_total(csv_file):
    df = pd.read_csv(csv_file)
    assert df["amount"].sum() == 15.0
@@end
@@py
import io
import tempfile
import unittest
from pathlib import Path

import pandas as pd

events = []

class TestOrders(unittest.TestCase):
    def setUp(self):
        events.append("setup")
        tmp = tempfile.TemporaryDirectory()
        self.addCleanup(lambda: events.append("teardown"))
        self.addCleanup(tmp.cleanup)
        self.path = Path(tmp.name) / "orders.csv"
        self.path.write_text("order_id,amount\n1,10.5\n2,4.5\n")

    def test_total(self):
        events.append("test_total")
        df = pd.read_csv(self.path)
        self.assertEqual(df["amount"].sum(), 15.0)

    def test_rows(self):
        events.append("test_rows")
        self.assertEqual(len(pd.read_csv(self.path)), 2)

suite = unittest.defaultTestLoader.loadTestsFromTestCase(TestOrders)
res = unittest.TextTestRunner(stream=io.StringIO()).run(suite)
print(res.testsRun, "tests, ok:", res.wasSuccessful())
print(events)
@@end
<ol><li>The pytest fixture <code>csv_file</code> asks for <code>tmp_path</code>, a fixture that pytest builds for you. A fixture can depend on other fixtures in the same way a test does.</li>
<li>Everything before <code>yield</code> is setup; the yielded value is what the test receives; everything after is teardown, even when the test fails.</li>
<li>In unittest, <code>setUp</code> runs before each test method. <code>tempfile.TemporaryDirectory</code> is the standard-library counterpart of <code>tmp_path</code>.</li>
<li><code>addCleanup</code> registers a function to run after the test, in last-in first-out order. That is why the <code>tmp.cleanup</code> registered second runs before the <code>"teardown"</code> note registered first.</li>
<li>The printed event list shows the lifecycle twice: setup, test, teardown for each of the two tests. Tests run in alphabetical order (<code>test_rows</code> before <code>test_total</code>), so never depend on order.</li></ol>
<figure><img src="images/lib23_fixture_scope.png" alt="Two timelines. With function scope each of four tests has its own setup and teardown. With session scope setup runs once, then four test bodies, then one teardown" loading="lazy"/><figcaption>Fixture scope controls how many times the expensive setup is paid.</figcaption></figure>
<p><strong>How to read it:</strong> each coloured bar is a block of time. In the top row (the default <code>scope="function"</code>) the orange setup bar repeats before every test. In the bottom row (<code>scope="session"</code>) it is paid once and shared, which is what you want for loading a large model or starting a database. The price of sharing: tests can now affect each other through the shared object, so share only things tests do not modify.</p>
<h3>Example 4: monkeypatch and mocking</h3>
<p>Tests must not call the internet, read your real secrets or wait on a slow model. <code>monkeypatch</code> temporarily replaces an environment variable or attribute; a <code>Mock</code> replaces an object and records how it was called.</p>
@@np
# NOT RUN HERE: pytest is not installed
import os
from unittest.mock import Mock

def get_key():
    return os.environ["API_KEY"]

def score_all(client, ids):
    return [client.predict(i) for i in ids]

def test_get_key(monkeypatch):
    monkeypatch.setenv("API_KEY", "test-key")      # undone after the test
    assert get_key() == "test-key"

def test_missing_key(monkeypatch):
    monkeypatch.delenv("API_KEY", raising=False)
    import pytest
    with pytest.raises(KeyError):
        get_key()

def test_score_all():
    client = Mock()
    client.predict.side_effect = [0.1, 0.9]
    assert score_all(client, [7, 8]) == [0.1, 0.9]
    client.predict.assert_any_call(8)
@@end
@@py
import os
import unittest
from unittest import mock
from unittest.mock import Mock

def get_key():
    return os.environ["API_KEY"]

def score_all(client, ids):
    return [client.predict(i) for i in ids]

# 1. replace an environment variable for the length of a with-block
with mock.patch.dict(os.environ, {"API_KEY": "test-key"}):
    print(get_key())
print("API_KEY" in os.environ)

# 2. a Mock records calls and returns scripted values
client = Mock()
client.predict.side_effect = [0.1, 0.9]
print(score_all(client, [7, 8]))
print(client.predict.call_count, client.predict.call_args_list)
client.predict.assert_any_call(8)

# 3. patch an attribute of a real module
import math
with mock.patch.object(math, "sqrt", return_value=42.0):
    print(math.sqrt(4))
print(math.sqrt(4))
@@end
<ol><li><code>monkeypatch.setenv</code> sets the variable and pytest restores the old state when the test ends. <code>mock.patch.dict(os.environ, {...})</code> is the standard-library equivalent, scoped to a <code>with</code> block.</li>
<li>Inside the block <code>get_key()</code> sees <code>test-key</code>; afterwards the variable is gone (<code>False</code>).</li>
<li>A <code>Mock</code> accepts any call. <code>side_effect=[0.1, 0.9]</code> makes consecutive calls return those values in order.</li>
<li><code>call_count</code> and <code>call_args_list</code> show how the code under test used the fake. <code>assert_any_call(8)</code> raises if nobody called <code>predict(8)</code>; here it passes silently.</li>
<li><code>patch.object(math, "sqrt", return_value=42.0)</code> swaps one attribute. Inside the block <code>math.sqrt(4)</code> is 42.0; after the block it is the real 2.0. Patch the name where it is <em>looked up</em>, not where it is defined (see the pitfalls section).</li></ol>
<h3>Example 5: a realistic data test, markers and configuration</h3>
<p>Testing a pandas function: compare whole frames with <code>pandas.testing.assert_frame_equal</code>, which tells you which cell differs, and use a plain exception test for bad input.</p>
@@py
import io
import unittest

import pandas as pd
from pandas.testing import assert_frame_equal

def add_revenue(df):
    if "price" not in df.columns or "qty" not in df.columns:
        raise KeyError("need price and qty")
    out = df.copy()
    out["revenue"] = out["price"] * out["qty"]
    return out

class TestRevenue(unittest.TestCase):
    def test_values(self):
        df = pd.DataFrame({"price": [2.5, 4.0], "qty": [2, 3]})
        want = pd.DataFrame({"price": [2.5, 4.0], "qty": [2, 3], "revenue": [5.0, 12.0]})
        assert_frame_equal(add_revenue(df), want)

    def test_input_not_modified(self):
        df = pd.DataFrame({"price": [1.0], "qty": [1]})
        add_revenue(df)
        self.assertEqual(list(df.columns), ["price", "qty"])

    def test_missing_column(self):
        with self.assertRaises(KeyError):
            add_revenue(pd.DataFrame({"price": [1.0]}))

    def test_wrong_dtype_is_caught(self):
        df = pd.DataFrame({"price": [2.5], "qty": [2]})
        bad = pd.DataFrame({"price": [2.5], "qty": [2], "revenue": [5]})   # int, not float
        with self.assertRaises(AssertionError) as cm:
            assert_frame_equal(add_revenue(df), bad)
        print(str(cm.exception).splitlines()[0])

suite = unittest.defaultTestLoader.loadTestsFromTestCase(TestRevenue)
res = unittest.TextTestRunner(stream=io.StringIO()).run(suite)
print(res.testsRun, "tests, ok:", res.wasSuccessful())
@@end
<ol><li><code>add_revenue</code> checks its input, copies the frame (so the caller's data is untouched) and adds a column. Copy-on-write in pandas 3.0 would also protect the caller, but an explicit <code>copy()</code> states the intent.</li>
<li><code>assert_frame_equal</code> compares values, dtypes, index and column names. On a mismatch it raises <code>AssertionError</code> naming the difference.</li>
<li><code>test_input_not_modified</code> checks a promise ("I do not mutate your data") that is easy to break later; this is a typical regression test.</li>
<li>The last test expects the dtype check to fail because we compare a float column with an int column. The printed first line, <code>Attributes of DataFrame.iloc[:, 2] (column name="revenue") are different</code>, is what you would see in a real failure. The test run reports 4 tests, all ok.</li></ol>
<p>In pytest you would also tag slow tests and register the tag so that typos are caught. Configuration lives in <code>pyproject.toml</code> (not run here):</p>

@@end

<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt">Writing a test that mirrors the code. <code>assert add_revenue(df)["revenue"].tolist() == (df["price"] * df["qty"]).tolist()</code> repeats the implementation, so if the formula is wrong, the test is wrong in the same way. Compute the expected value by hand (2.5 * 2 = 5.0) and write the number into the test.</div></div>
<p class="problem"><span class="pl">Problem 23.2.1</span> A test passes alone but fails when the whole suite runs. List the likely causes in order of how often they happen.</p>
<table class="steps"><tr><th>Idea</th><td>Tests share state somewhere.</td></tr><tr><th>Cause 1</th><td>A module-level list, dict or DataFrame that one test mutates (fix: build it in a function-scoped fixture).</td></tr><tr><th>Cause 2</th><td>An environment variable or global set without monkeypatch (fix: use monkeypatch so it is undone).</td></tr><tr><th>Cause 3</th><td>Files written to a fixed path (fix: use tmp_path).</td></tr><tr><th>Cause 4</th><td>A session-scoped fixture that tests modify (fix: narrower scope or return a copy).</td></tr><tr><th>Check</th><td>Run <code>pytest -p no:randomly</code> or reverse the order; if the failure moves, state is shared.</td></tr></table>
