
<h2 id="s17-10">17.10 merge, join and concat, with Join Validation</h2>
<figure><img src="images/lib17_joins.png" alt="Bar chart of row counts for inner, left, right and outer joins of keys 1-4 with keys 3-7" loading="lazy"/><figcaption>The same two small tables joined four ways. Left keys are 1 to 4, right keys are 3 to 7, so only 3 and 4 match.</figcaption></figure>
<p><strong>How to read it:</strong> each bar is the number of rows after a join. <code>inner</code> keeps only matching keys (2). <code>left</code> keeps all four left keys (4). <code>right</code> keeps all five right keys (5). <code>outer</code> keeps every key from either side (7). The row count is the quickest sanity check: if your left join returns more rows than the left table had, the right table had duplicate keys.</p>

<h3>Beginner: the four join types</h3>
@@CODE
import pandas as pd

customers = pd.DataFrame({"cid": [1, 2, 3], "name": ["Ana", "Bo", "Cy"]})
orders = pd.DataFrame({"cid": [2, 3, 3, 4], "amount": [20, 30, 5, 99]})

for how in ["inner", "left", "outer"]:
    out = customers.merge(orders, on="cid", how=how)
    print(how, out.shape)
print(customers.merge(orders, on="cid", how="left"))
@@END
<ol>
<li>Customers 1 to 3 and orders from customers 2, 3, 3, 4. Customer 3 has two orders; order 4 belongs to a customer that does not exist in the table.</li>
<li><code>inner</code> gives 3 rows: customer 2 once and customer 3 twice. Customer 1 (no orders) and order 4 (no customer) vanish.</li>
<li><code>left</code> gives 4 rows: the same 3 plus customer 1 with NaN amount.</li>
<li><code>outer</code> gives 5 rows: left plus the orphan order for customer 4.</li>
<li>Notice that a one-to-many join <em>multiplies</em> rows: customer 3 appears twice. That is correct here, but it is the root of the classic "my totals doubled" bug.</li>
</ol>
<h3>Intermediate: validate, indicator, different key names</h3>
@@CODE
import pandas as pd

users = pd.DataFrame({"user_id": [1, 2, 3], "plan": ["free", "pro", "pro"]})
events = pd.DataFrame({"uid": [1, 1, 2, 9], "event": ["a", "b", "c", "d"]})

m = events.merge(users, left_on="uid", right_on="user_id", how="left", validate="m:1", indicator=True)
print(m)
print(m["_merge"].value_counts().to_dict())

dup_users = pd.concat([users, users.iloc[[0]]], ignore_index=True)
try:
    events.merge(dup_users, left_on="uid", right_on="user_id", validate="m:1")
except Exception as e:
    print(type(e).__name__, "-", str(e)[:60])
@@END
<ol>
<li><code>left_on="uid", right_on="user_id"</code> joins differently named keys. Both key columns stay in the result; drop one afterwards.</li>
<li><code>validate="m:1"</code> promises "many events, one user each". If any user id repeats in <code>users</code>, pandas raises <code>MergeError</code> instead of silently multiplying rows.</li>
<li><code>indicator=True</code> adds <code>_merge</code> with values <code>both</code>, <code>left_only</code> or <code>right_only</code>. Here event "d" has uid 9, which is not a user, so it is <code>left_only</code> with NaN plan.</li>
<li>We then add a duplicate user and merge again. The <code>validate</code> check fires, and the message tells you the right side is not unique. Catching this at the join is far cheaper than discovering inflated revenue in a report.</li>
</ol>
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>A left join that changes the row count.</strong> If the right table has duplicate keys the output has more rows than the left input. Always pass <code>validate="m:1"</code> (or "1:1") when you expect uniqueness, and assert the row count after the join.</div></div>
<h3>concat, merge_asof and anti-joins</h3>
@@CODE
import pandas as pd

jan = pd.DataFrame({"id": [1, 2], "v": [10, 20]})
feb = pd.DataFrame({"id": [2, 3], "v": [25, 30]})
stacked = pd.concat([jan, feb], keys=["jan", "feb"])
print(stacked)
print(pd.concat([jan, feb], ignore_index=True).shape)

trades = pd.DataFrame({"ts": pd.to_datetime(["2025-01-01 10:00:05", "2025-01-01 10:00:20"]), "qty": [5, 7]})
quotes = pd.DataFrame({"ts": pd.to_datetime(["2025-01-01 10:00:00", "2025-01-01 10:00:10"]), "px": [100.0, 101.5]})
print(pd.merge_asof(trades, quotes, on="ts"))

print(jan[~jan["id"].isin(feb["id"])]["id"].tolist())
@@END
<ol>
<li><code>concat</code> stacks rows. <code>keys=["jan","feb"]</code> records which piece each row came from as an extra index level, useful when you read many files and need to know the source.</li>
<li><code>ignore_index=True</code> discards the old labels and renumbers 0..n-1; the shape (4 rows, 2 columns) confirms nothing was lost.</li>
<li><code>merge_asof</code> matches each trade with the <em>latest quote at or before</em> it: the 10:00:05 trade gets the 10:00:00 price, the 10:00:20 trade gets the 10:00:10 price. Both tables must be sorted by the key.</li>
<li><code>~isin</code> is the anti-join: ids in January that are not in February (id 1).</li>
</ol>

<h2 id="s17-11">17.11 Reshaping: pivot, pivot_table, melt, stack and crosstab</h2>
<figure><img src="images/lib17_reshape.png" alt="Wide table with columns Q1 and Q2 becomes a long table with qtr and val columns via melt, and back via pivot" loading="lazy"/><figcaption>Wide and long are two shapes of the same data. melt goes wide to long; pivot goes long to wide.</figcaption></figure>
<p><strong>How to read it:</strong> the blue table keeps one row per id with a column per quarter (wide, good for people). The orange table has one row per id and quarter (long, good for groupby, plotting and databases). The top arrow is <code>melt</code>, the bottom arrow is <code>pivot</code>. If a tool complains that it needs "tidy data", it wants the long shape.</p>
<div class="tablewrap"><table class="data"><thead><tr><th>Name</th><th>Plain English</th><th>Minimal example</th></tr></thead><tbody>
<tr><td><code>df.pivot(index, columns, values)</code></td><td>Long to wide; fails on duplicate pairs</td><td><code>df.pivot(index="id", columns="q", values="v")</code></td></tr>

<h3>Beginner: melt and pivot are inverses</h3>
@@CODE
import pandas as pd

wide = pd.DataFrame({"id": ["a", "b"], "Q1": [5, 3], "Q2": [7, 4]})
long = wide.melt(id_vars="id", var_name="qtr", value_name="val")
print(long)
back = long.pivot(index="id", columns="qtr", values="val").reset_index()
back.columns.name = None
print(back)
print(back.equals(wide))
@@END
<ol>
<li><code>id_vars</code> are the columns that stay as identifiers. Every other column is "melted" into two new columns: <code>var_name</code> holds the old column name, <code>value_name</code> holds the cell value.</li>
<li>The long table has 2 ids x 2 quarters = 4 rows.</li>
<li><code>pivot</code> reverses it: the unique values of <code>qtr</code> become columns. <code>reset_index()</code> turns the id index back into a column and <code>columns.name = None</code> removes the leftover label "qtr".</li>
<li><code>equals</code> confirms we are back to the original table.</li>
</ol>
<h3>Intermediate: pivot_table, crosstab, stack and unstack</h3>
@@CODE
import pandas as pd

df = pd.DataFrame({
    "city": ["Oslo", "Oslo", "Rome", "Rome", "Oslo"],
    "year": [2024, 2025, 2024, 2025, 2025],
    "sales": [10, 12, 7, 9, 3],
    "paid": ["y", "n", "y", "y", "y"],
})
pt = df.pivot_table(index="city", columns="year", values="sales", aggfunc="sum", fill_value=0, margins=True)
print(pt)
print(pd.crosstab(df["city"], df["paid"]))
print(pd.crosstab(df["city"], df["paid"], normalize="index").round(2))
s = df.groupby(["city", "year"])["sales"].sum()
print(s.unstack())
print(s.unstack().stack().equals(s))
@@END
<ol>
<li><code>pivot_table</code> is <code>groupby</code> plus a reshape: rows by city, columns by year, cells are the sum of sales. Oslo in 2025 has two rows (12 and 3), so they are added to 15. Plain <code>pivot</code> would have raised an error here because of the duplicate pair.</li>
<li><code>margins=True</code> adds an "All" row and column of totals; <code>fill_value=0</code> replaces empty combinations.</li>
<li><code>crosstab</code> counts how many rows fall in each pair of values. <code>normalize="index"</code> divides each row by its total, giving row percentages (Oslo: 2 of 3 paid).</li>
<li>A groupby on two keys returns a Series with a two-level index. <code>unstack()</code> moves the inner level (year) into columns; <code>stack()</code> moves it back. The final <code>equals</code> shows they round-trip.</li>
</ol>
<h3>Realistic: explode tags and one-hot encode</h3>
@@CODE
import pandas as pd

posts = pd.DataFrame({"id": [1, 2, 3], "tags": ["py|sql", "py", "sql|dbt|py"]})
posts["tag"] = posts["tags"].str.split("|")
exploded = posts.explode("tag")[["id", "tag"]]
print(exploded.groupby("tag").size().sort_values(ascending=False).to_dict())
onehot = posts["tags"].str.get_dummies("|")
print(onehot)
print(pd.get_dummies(pd.Series(["Oslo", "Rome", "Oslo"]), dtype=int))
@@END
<ol>
<li><code>str.split("|")</code> turns each cell into a Python list.</li>
<li><code>explode</code> repeats the row once per list element, so post 3 becomes three rows. Counting rows per tag then answers "how popular is each tag" (py: 3, sql: 2, dbt: 1).</li>
<li><code>str.get_dummies("|")</code> does split plus one-hot in one call: a 0/1 column per tag, ready for a model.</li>
<li><code>pd.get_dummies</code> one-hot encodes an ordinary categorical column. Use <code>dtype=int</code> to get 0/1 instead of True/False.</li>
</ol>
