
<h2 id="s17-12">17.12 Window Functions: rolling, expanding and resample</h2>
<figure><img src="images/lib17_rolling.png" alt="Line chart of a noisy daily series with a 7-day rolling mean, an expanding mean and weekly resample means" loading="lazy"/><figcaption>One noisy daily series, smoothed three ways. Synthetic data with a fixed seed.</figcaption></figure>
<p><strong>How to read it:</strong> the grey line is the raw daily value. The blue <code>rolling(7).mean()</code> follows it closely but irons out day-to-day noise, because each point is the mean of the last seven days. The orange <code>expanding().mean()</code> averages <em>everything so far</em>, so it reacts slowly as history piles up. The teal steps are <code>resample("W").mean()</code>: one value per week, so the series has fewer points. Rolling keeps the original length; resample changes it.</p>

<h3>Beginner and intermediate: rolling, expanding and shift</h3>
@@CODE
import pandas as pd

s = pd.Series([10, 12, 9, 15, 20, 18],
              index=pd.date_range("2025-03-01", periods=6, freq="D"), name="visits")
print(s.rolling(3).mean().round(2).tolist())
print(s.rolling(3, min_periods=1).mean().round(2).tolist())
print(s.expanding().max().tolist())
print(s.shift(1).tolist())
print(s.pct_change().round(3).tolist())
print((s - s.shift(7)).isna().all())
@@END
<ol>
<li><code>rolling(3).mean()</code> averages each day with the two before it. The first two values are NaN because a full window of three does not exist yet. Fourth value: (12+9+15)/3 = 12.</li>
<li><code>min_periods=1</code> accepts shorter windows at the start, so there are no NaN, but the first values are averages of fewer points, so treat them with care.</li>
<li><code>expanding().max()</code> is the running maximum: 10, 12, 12, 15, 20, 20.</li>
<li><code>shift(1)</code> moves values down one row, giving "yesterday's visits" next to today's. This is how you build lag features.</li>
<li><code>pct_change()</code> is (today - yesterday) / yesterday: the second value is 12/10 - 1 = 0.2.</li>
<li>The last line shows that comparing with 7 days ago gives only NaN in a 6-row series: there is no history that far back.</li>
</ol>
<h3>Realistic: resample irregular events into daily and monthly totals</h3>
@@CODE
import numpy as np
import pandas as pd

rng = np.random.default_rng(3)
ts = pd.to_datetime("2025-01-01") + pd.to_timedelta(rng.integers(0, 90 * 24 * 60, 400), unit="min")
ev = pd.DataFrame({"ts": ts, "amount": rng.integers(5, 100, 400)}).sort_values("ts").set_index("ts")

daily = ev["amount"].resample("D").sum()
print(len(daily), daily.index.min().date(), daily.index.max().date())
monthly = ev["amount"].resample("ME").agg(["count", "sum"])
print(monthly)
print(ev.loc["2025-02-10":"2025-02-11", "amount"].sum())
roll = daily.rolling("7D").sum()
print(roll.iloc[[0, 6, 30]].tolist())
print(ev.groupby(ev.index.dayofweek)["amount"].sum().idxmax())
@@END
<ol>
<li>400 random timestamps over 90 days become the index. A <code>DatetimeIndex</code> unlocks time-aware slicing and resampling.</li>
<li><code>resample("D").sum()</code> puts every event into its calendar day and adds the amounts. Days with no events get 0 (for sum), so the result has no gaps.</li>
<li><code>resample("ME")</code> buckets by month end; <code>agg(["count", "sum"])</code> gives the number of events and the total per month. The 90 days run from 1 January to 31 March, so there are exactly three monthly rows and the counts add up to 400.</li>
<li>Partial string slicing <code>loc["2025-02-10":"2025-02-11"]</code> selects whole days; both ends are included.</li>
<li><code>rolling("7D")</code> is a time-based window: the sum of the last seven calendar days, correct even when rows are unevenly spaced.</li>
<li><code>dayofweek</code> gives 0 for Monday to 6 for Sunday; grouping on it finds the weekday with the largest total (2 means Wednesday here).</li>
</ol>

<h3>MultiIndex: when a table has two row keys</h3>
@@CODE
import pandas as pd

df = pd.DataFrame({
    "city": ["Oslo", "Oslo", "Rome", "Rome"],
    "year": [2024, 2025, 2024, 2025],
    "sales": [10, 15, 7, 9],
}).set_index(["city", "year"]).sort_index()
print(df)
print(df.loc[("Rome", 2025), "sales"])
print(df.xs(2025, level="year"))
print(df.groupby(level="city")["sales"].sum().to_dict())
print(df.reset_index(level="year").columns.tolist())
@@END
<ol>
<li><code>set_index(["city","year"])</code> makes a two-level row index; <code>sort_index()</code> sorts it, which pandas needs for correct and fast slicing.</li>
<li>A tuple selects a single combination: Rome in 2025 has sales 9.</li>
<li><code>xs(2025, level="year")</code> takes all rows with year 2025 and drops that level, leaving a city-indexed table.</li>
<li><code>groupby(level="city")</code> aggregates by one index level without resetting the index.</li>
<li>If a MultiIndex gets in your way, <code>reset_index()</code> flattens it back to columns. A good rule: use MultiIndex for the output of reshaping, but keep your working data flat.</li>
</ol>
<h3>Binning with cut and qcut</h3>
@@CODE
import pandas as pd

age = pd.Series([4, 17, 18, 35, 64, 65, 90])
groups = pd.cut(age, bins=[0, 17, 64, 120], labels=["child", "adult", "senior"])
print(groups.tolist())
print(pd.cut(age, bins=[0, 18, 65, 120], right=False).astype(str).tolist()[:3])

spend = pd.Series([5, 8, 12, 20, 33, 50, 80, 400])
q = pd.qcut(spend, 4, labels=["Q1", "Q2", "Q3", "Q4"])
print(q.tolist())
print(q.value_counts().sort_index().to_dict())
print(pd.qcut(spend, 4).cat.categories[0])
@@END
<ol>
<li><code>cut</code> with explicit <code>bins</code> uses your edges. By default intervals are closed on the <em>right</em>: (0, 17] contains 17 but not 0 and not 18. So 17 is a "child" and 18 is an "adult".</li>
<li><code>right=False</code> flips this to [0, 18), so 18 starts a new bin. The printed interval strings show which convention is in force. Always check a boundary value.</li>
<li><code>qcut</code> chooses edges so that each bin holds about the same number of rows (quartiles). With 8 values, each quartile gets 2: the large value 400 does not distort the bins the way equal-width bins would.</li>
<li>Counting per label confirms 2 values per quartile. The last line shows the first computed interval, whose lower edge is slightly below the minimum so the minimum is included.</li>
</ol>
<h3>Method chaining and pipe</h3>
<p>A chain reads like a recipe: each line is one step and the whole expression returns the finished table. There are no half-finished variables to confuse you later.</p>
@@CODE
import pandas as pd

raw = pd.DataFrame({
    "Order ID": [1, 2, 3, 4, 5],
    "Customer": [" ana", "BO ", "ana", "Cy", None],
    "Amount": ["10.5", "7", "oops", "30", "12"],
    "Date": ["2025-03-01", "2025-03-02", "2025-03-02", "2025-03-05", "2025-03-06"],
})

def drop_small(d, min_amount):
    return d[d["amount"] >= min_amount]

clean = (
    raw
    .rename(columns=lambda c: c.strip().lower().replace(" ", "_"))
    .assign(
        customer=lambda d: d["customer"].str.strip().str.lower(),
        amount=lambda d: pd.to_numeric(d["amount"], errors="coerce"),
        date=lambda d: pd.to_datetime(d["date"]),
    )
    .dropna(subset=["customer", "amount"])
    .pipe(drop_small, min_amount=8)
    .sort_values("date")
    .reset_index(drop=True)
)
print(clean)
print(clean.dtypes.astype(str).to_dict())
@@END
<ol>
<li>The whole pipeline is one parenthesised expression, so each line can start with a dot. Parentheses let Python continue the expression over lines without backslashes.</li>
<li><code>rename(columns=lambda c: ...)</code> normalises every header: strip spaces, lowercase, spaces to underscores. Consistent snake_case names save endless quoting later.</li>
<li><code>assign</code> creates three cleaned columns. Each lambda receives the current frame, so <code>d["customer"]</code> sees the renamed column.</li>
<li><code>dropna(subset=...)</code> removes the row with no customer and the row whose amount failed to parse ("oops").</li>
<li><code>pipe(drop_small, min_amount=8)</code> inserts your own function into the chain; the frame is passed as the first argument. This is how you keep chains readable while reusing logic.</li>
<li>Finally sort and renumber. Order 3 ("oops") and order 5 (no customer) were dropped by <code>dropna</code>, and order 2 (amount 7) by the size filter, so orders 1 and 4 remain. Printing dtypes proves the types are what you intended.</li>
</ol>

<h3>Shrink a table: a worked memory diet</h3>
@@CODE
import numpy as np
import pandas as pd

rng = np.random.default_rng(7)
n = 100_000
df = pd.DataFrame({
    "user_id": rng.integers(0, 5000, n),
    "country": rng.choice(["NO", "IT", "PE", "UA", "US"], n),
    "qty": rng.integers(1, 20, n),
    "price": rng.uniform(1, 100, n).round(2),
})
before = df.memory_usage(deep=True).sum()
slim = df.assign(
    user_id=pd.to_numeric(df["user_id"], downcast="unsigned"),
    country=df["country"].astype("category"),
    qty=pd.to_numeric(df["qty"], downcast="unsigned"),
    price=df["price"].astype("float32"),
)
after = slim.memory_usage(deep=True).sum()
print(slim.dtypes.astype(str).to_dict())
print(f"{before/1e6:.1f} MB -> {after/1e6:.1f} MB")
print(round(after / before, 2))
@@END
<ol>
<li>A 100,000-row table with an id, a country, a small integer and a price.</li>
<li><code>memory_usage(deep=True).sum()</code> is the total in bytes; we remember it as the "before" size.</li>
<li><code>downcast="unsigned"</code> asks pandas for the smallest unsigned integer that fits: user ids below 5000 need 16 bits, quantities below 20 need 8.</li>
<li>Country has five values, so <code>category</code> stores them once and uses one byte per row.</li>
<li><code>float32</code> halves the price column. It carries about 7 significant digits, which is fine for prices rounded to cents in this range but <em>not</em> for money you must add up exactly (use integer cents or <code>Decimal</code> for that).</li>
<li>The ratio shows the new table is a fraction of the old one. Always compare results before and after to make sure the diet did not change any answer.</li>
</ol>
<h3>pandas 3.0 in practice: copy-on-write and the string dtype</h3>
<div class="callout green"><div class="lab">KEY IDEA</div><div class="txt"><strong>Copy-on-write (CoW)</strong> is now the only behaviour. Every DataFrame or Series derived from another one behaves as an independent copy: changing the child never changes the parent, and vice versa. pandas achieves this lazily (it copies only when you write), so it is cheap. The consequence: <em>chained assignment</em> such as <code>df["a"][mask] = 0</code> or <code>df[mask]["a"] = 0</code> no longer modifies <code>df</code>. Use <code>df.loc[mask, "a"] = 0</code>.</div></div>
@@CODE
import pandas as pd

df = pd.DataFrame({"a": [1, 2, 3], "b": ["x", "y", "z"]})
view = df["a"]
view.iloc[0] = 100
print(df["a"].tolist(), view.tolist())

sub = df[df["a"] > 1]
sub.loc[sub.index[0], "a"] = -1
print(df["a"].tolist())

df.loc[df["a"] > 2, "a"] = 0
print(df["a"].tolist())

s = df["b"]
print(s.dtype, s.str.upper().dtype)
print(pd.Series(["a", None]).isna().tolist(), pd.Series(["a", None]).dtype)
print(pd.Series(["a", 1]).dtype)
@@END
<ol>
<li><code>view = df["a"]</code> looks like a window onto the column, but under copy-on-write it is a lazy copy. Writing to <code>view</code> triggers the real copy, so <code>df</code> is unchanged: the first list still starts with 1.</li>
<li>The same holds for a filtered frame <code>sub</code>. Editing it does not touch <code>df</code>. This removes the old <code>SettingWithCopyWarning</code> confusion: in 3.0 there is no ambiguity and no warning.</li>
<li><code>df.loc[mask, "a"] = 0</code> is a single operation on <code>df</code> itself, so it works. It changes 3 to 0.</li>
<li>Text columns now have dtype <code>str</code> by default (before 3.0 they were <code>object</code>). It stores strings only, supports missing values as NaN, and is faster and smaller, especially when <code>pyarrow</code> is installed.</li>
<li><code>Series(["a", None])</code> is still <code>str</code> and the missing value is detected by <code>isna()</code>.</li>
<li>A mixed list such as <code>["a", 1]</code> cannot be <code>str</code>, so it falls back to <code>object</code>. If you see <code>object</code> columns in 3.0, you have mixed types, which is worth investigating.</li>
</ol>
<div class="callout cream"><div class="lab">REAL JOB</div><div class="txt">Migration checklist from pandas 2.x: (1) replace chained assignment with <code>.loc</code>; (2) do not rely on <code>dtype == object</code> to find text columns, use <code>pd.api.types.is_string_dtype</code> or <code>select_dtypes(include="str")</code>; (3) replace <code>applymap</code> by <code>DataFrame.map</code>; (4) use <code>"ME"</code>, <code>"h"</code>, <code>"QE"</code> frequency aliases; (5) do not assume datetimes are nanoseconds: the unit (<code>ns</code>, <code>us</code>, <code>ms</code>, <code>s</code>) is inferred, so avoid <code>.astype("int64")</code> on a datetime and expecting nanoseconds; (6) grouping by a categorical now defaults to <code>observed=True</code> (unused categories are not shown); pass <code>observed=False</code> if you want them.</div></div>
