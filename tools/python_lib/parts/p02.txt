<h3>Beginner: read a CSV and look at what pandas guessed</h3>
@@CODE
import io
import pandas as pd

text = """order_id,customer,amount,placed
1001,ana,25.5,2025-03-01
1002,bo,,2025-03-02
1003,ana,12.0,2025-03-04
"""
df = pd.read_csv(io.StringIO(text))
print(df)
print(df.dtypes)
@@END
<ol>
<li><code>io.StringIO(text)</code> makes the string behave like an open file, so the example needs no file on disk. With a real file you would write <code>pd.read_csv("orders.csv")</code>.</li>
<li>The first line becomes the column names. Each later line becomes a row.</li>
<li>The empty amount for order 1002 becomes <code>NaN</code>, and because NaN is a float, the whole <code>amount</code> column is <code>float64</code>.</li>
<li>The <code>placed</code> column stays text (<code>str</code>), because we did not ask for dates. That is the most common surprise: pandas does not parse dates unless told.</li>
</ol>
<h3>Intermediate: control types, dates and missing markers on the way in</h3>
@@CODE
import io
import pandas as pd

text = """zip;customer;amount;placed
01234;ana;1,5;2025-03-01
02345;bo;n/a;2025-03-02
"""
df = pd.read_csv(
    io.StringIO(text),
    sep=";",
    dtype={"zip": "str"},
    decimal=",",
    na_values=["n/a"],
    parse_dates=["placed"],
)
print(df)
print(df.dtypes)
@@END
<ol>
<li><code>sep=";"</code>: European exports often use semicolons because commas are decimal marks.</li>
<li><code>dtype={"zip": "str"}</code> keeps the leading zero. Without it, <code>01234</code> becomes the integer 1234 and the zero is lost for ever.</li>
<li><code>decimal=","</code> reads <code>1,5</code> as the number 1.5.</li>
<li><code>na_values=["n/a"]</code> adds a custom missing marker. pandas already treats empty cells, <code>NA</code>, <code>NaN</code> and <code>null</code> as missing.</li>
<li><code>parse_dates=["placed"]</code> converts the column to datetimes. In pandas 3.0 the unit is chosen automatically (here microseconds, shown as <code>datetime64[us]</code>).</li>
</ol>
<h3>Realistic: write and read back, Excel, and nested JSON</h3>
@@CODE
import json
import tempfile
from pathlib import Path
import pandas as pd

df = pd.DataFrame({"id": [1, 2], "region": ["north", "south"], "sales": [10.5, 20.0]})
folder = Path(tempfile.mkdtemp())

df.to_csv(folder / "a.csv", index=False)
print((folder / "a.csv").read_text())

df.to_excel(folder / "a.xlsx", sheet_name="Q1", index=False)
print(pd.read_excel(folder / "a.xlsx", sheet_name="Q1"))

payload = [
    {"id": 1, "user": {"name": "Ana", "city": "Oslo"}, "items": [{"sku": "A", "qty": 2}, {"sku": "B", "qty": 1}]},
    {"id": 2, "user": {"name": "Bo", "city": "Rome"}, "items": [{"sku": "A", "qty": 5}]},
]
print(pd.json_normalize(payload, sep="_").drop(columns="items"))
flat = pd.json_normalize(payload, record_path="items", meta=["id", ["user", "name"]])
print(flat)
print(df.to_json(orient="records"))
@@END
<ol>
<li><code>tempfile.mkdtemp()</code> gives a throwaway folder so the example leaves nothing behind.</li>
<li><code>to_csv(..., index=False)</code> writes only your columns. Forgetting <code>index=False</code> adds an unnamed first column, which then comes back as <code>Unnamed: 0</code> when you reload.</li>
<li><code>to_excel</code> and <code>read_excel</code> use the installed <code>openpyxl</code> engine. The sheet name is how you pick one sheet out of many.</li>
<li><code>json_normalize(payload, sep="_")</code> flattens nested dicts: <code>user</code> becomes <code>user_name</code> and <code>user_city</code>. The list column <code>items</code> stays as a list, so we drop it for display.</li>
<li><code>record_path="items"</code> explodes the nested list into one row per item, and <code>meta=[...]</code> copies parent fields onto each row. This is the standard way to turn "orders with line items" JSON into a flat table.</li>
<li><code>to_json(orient="records")</code> writes a list of row dicts, the shape most APIs expect.</li>
</ol>
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Reading codes as numbers.</strong> Zip codes, phone numbers and product ids with leading zeros must be read with <code>dtype=str</code>. Fix it at read time; repairing later with <code>zfill</code> only works if you know the original width.</div></div>

<h3>The 60-second health check</h3>
<p>Whenever a new table arrives, run the same checks in the same order: size, types, missing, duplicates, ranges, categories. It catches 90 percent of data problems before they become wrong answers.</p>
@@CODE
import numpy as np
import pandas as pd

rng = np.random.default_rng(42)
n = 12
df = pd.DataFrame({
    "order_id": np.arange(1, n + 1),
    "city": rng.choice(["Oslo", "Rome", "Lima"], n),
    "amount": rng.normal(50, 20, n).round(2),
})
df.loc[3, "amount"] = np.nan
df = pd.concat([df, df.iloc[[0]]], ignore_index=True)

print(df.shape)
df.info()
print(df.describe().round(2))
print(df["city"].value_counts())
print(df.isna().sum().to_dict(), df.duplicated().sum())
@@END
<ol>
<li>The seeded generator <code>default_rng(42)</code> makes the "random" data identical every run.</li>
<li><code>df.loc[3, "amount"] = np.nan</code> plants one missing value, and <code>concat</code> with <code>df.iloc[[0]]</code> appends a copy of the first row, so we have a duplicate to find.</li>
<li><code>df.shape</code> is a tuple: 13 rows, 3 columns.</li>
<li><code>df.info()</code> prints directly (it returns <code>None</code>, so do not wrap it in <code>print</code>). Read the "Non-Null Count" column: 12 of 13 for <code>amount</code> reveals the missing cell.</li>
<li><code>describe()</code> gives count, mean, std, min, quartiles and max. Check that min and max are plausible: negative amounts or a max of 10 million are red flags.</li>
<li><code>value_counts()</code> shows how many rows per city; a misspelling like "oslo" would appear as its own row here.</li>
<li><code>isna().sum()</code> counts missing cells per column, and <code>duplicated().sum()</code> counts rows that repeat an earlier row exactly.</li>
</ol>
<div class="callout green"><div class="lab">KEY IDEA</div><div class="txt">Count before you clean. Write down how many rows you have at the start, after each filter, and at the end. A pipeline that silently drops 30 percent of rows is the most common expensive pandas bug.</div></div>
