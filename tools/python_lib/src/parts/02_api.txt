
<h2>19.2 The Estimator API, Datasets and Splitting Data</h2>
<p>This section is the foundation. Every later section is a variation of the same four verbs: <code>fit</code>, <code>predict</code>, <code>transform</code>, <code>score</code>.</p>
<h3>Reference: the 20 most important names</h3>

<h3>Example 1: the smallest possible model</h3>
<p>Four houses: size in hundreds of square metres and price in thousands. We fit a straight line and use it.</p>
@@PY
import numpy as np
from sklearn.linear_model import LinearRegression

X = np.array([[1.0], [2.0], [3.0], [4.0]])   # shape (4, 1): 4 rows, 1 feature
y = np.array([110, 190, 310, 390])

model = LinearRegression()
model.fit(X, y)
print("slope:", model.coef_, "intercept:", round(model.intercept_, 1))
print("predict size 5:", model.predict([[5.0]]))
print("R squared:", round(model.score(X, y), 4))
@@END
<ol>
<li><code>X</code> must be two-dimensional: rows by features. A single feature is a column, hence the double brackets.</li>
<li><code>y</code> is one-dimensional: one target per row.</li>
<li>The constructor <code>LinearRegression()</code> stores settings only; nothing is learned yet.</li>
<li><code>fit</code> finds the slope and intercept by least squares and stores them in <code>coef_</code> and <code>intercept_</code>.</li>
<li><code>predict</code> takes a 2-D array again (one new row with one feature) and returns an array with one number.</li>
<li><code>score</code> for a regressor returns R squared, the share of variance explained (1.0 is perfect). Here it is measured on the training data, so it is optimistic.</li>
</ol>
<p><strong>Reading the output:</strong> the fitted line is price = 10 + 96 × size, so size 5 predicts 490. R squared is 0.9931, which is high because four points almost lie on a line, and it is measured on the same four points the line was fitted to.</p>
<div class="callout red"><div class="lab">COMMON MISTAKE</div><div class="txt"><strong>Wrong:</strong> <code>model.fit([1, 2, 3, 4], y)</code> or <code>model.predict([5])</code>. <strong>Symptom:</strong> <code>ValueError: Expected 2D array, got 1D array instead</code>. <strong>Fix:</strong> reshape with <code>X.reshape(-1, 1)</code>, or select a column as <code>df[["size"]]</code> (double brackets keep it a DataFrame) rather than <code>df["size"]</code>.</div></div>
<h3>Example 2: a real classifier, an honest test</h3>
<p>The iris dataset has 150 flowers, 4 measurements each, 3 species. We hold out a test set, fit on the rest, and score on the held-out part.</p>
@@PY
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression

data = load_iris(as_frame=True)
X, y = data.data, data.target
print(X.shape, list(X.columns))

X_tr, X_te, y_tr, y_te = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=0)
print(X_tr.shape, X_te.shape, y_te.value_counts().to_dict())

clf = LogisticRegression(max_iter=200)
clf.fit(X_tr, y_tr)
print("train acc:", round(clf.score(X_tr, y_tr), 3))
print("test acc :", round(clf.score(X_te, y_te), 3))
print("classes_:", clf.classes_, " coef_ shape:", clf.coef_.shape)
print(clf.predict_proba(X_te.iloc[:2]).round(3))
@@END
<ol>
<li><code>load_iris(as_frame=True)</code> returns a bundle whose <code>.data</code> is a DataFrame and <code>.target</code> a Series.</li>
<li>We print the shape and column names to know what we have before modelling.</li>
<li><code>train_test_split</code> returns four pieces in a fixed order: X train, X test, y train, y test. <code>test_size=0.25</code> keeps a quarter for testing. <code>stratify=y</code> keeps the three species in equal proportion in both parts. <code>random_state=0</code> makes the shuffle repeatable.</li>
<li><code>max_iter=200</code> gives the optimiser enough steps to converge (the default is 100).</li>
<li><code>fit</code> sees only the training rows. The test rows are untouched.</li>
<li>Comparing train and test accuracy shows whether the model memorised. A small gap is healthy.</li>
<li><code>classes_</code> lists the labels in the column order of <code>predict_proba</code>; <code>coef_</code> has one row of weights per class.</li>
<li><code>predict_proba</code> gives one probability per class for each row; each row sums to 1.</li>
</ol>
<p><strong>Reading the output:</strong> the model has 112 training rows and 38 test rows, and the test set holds 13, 13 and 12 flowers of the three species. Train accuracy is 0.955 and test accuracy is 1.0. Test beating train is luck of a small test set (38 rows, so one error moves accuracy by 0.026); do not read it as "the model is perfect". The first two test flowers get about 0.97 for class 0, which is confident and correct.</p>
<p class="problem"><span class="pl">Problem 19.2.1</span> A dataset has 1,000 rows, 5% of them positive. You call <code>train_test_split(X, y, test_size=0.2, random_state=0)</code> without <code>stratify</code>. Is it guaranteed that the test set holds exactly 10 positives?</p>
<table class="steps"><tr><th>Expected</th><td>20% of 1,000 is 200 test rows; 5% of 200 is 10 positives on average.</td></tr><tr><th>Without stratify</th><td>The split is a random shuffle, so the count of positives in the test set is random (typically close to 10, but 6 or 14 is entirely possible).</td></tr><tr><th>With stratify=y</th><td>The split preserves the class ratio as closely as integers allow, giving 10 (or within one).</td></tr><tr><th>Answer</th><td>No. Use <code>stratify=y</code> whenever classes are imbalanced, so your test metric is not distorted by an unlucky split.</td></tr></table>
<h3>Example 3: inspecting and copying estimators</h3>
<p>Settings are visible and changeable, and <code>clone</code> gives a fresh, unfitted copy. This is how cross-validation and grid search work internally.</p>
@@PY
from sklearn.base import clone
from sklearn.exceptions import NotFittedError
from sklearn.tree import DecisionTreeClassifier
from sklearn.utils.validation import check_is_fitted

tree = DecisionTreeClassifier(max_depth=3, random_state=0)
print(tree.get_params()["max_depth"])

try:
    check_is_fitted(tree)
except NotFittedError:
    print("not fitted yet")

tree.set_params(max_depth=5)
copy = clone(tree)
print(copy.max_depth, copy is tree)
print(tree)
@@END
<ol>
<li><code>get_params()</code> returns every constructor setting as a dictionary; we read one key.</li>
<li><code>check_is_fitted</code> inspects the object for attributes ending in an underscore. None exist, so it raises <code>NotFittedError</code>, which we catch and report.</li>
<li><code>set_params</code> edits a setting in place. Searches use this to try many values.</li>
<li><code>clone</code> builds a new object from the current settings only. The fitted state, if there were any, is not copied. It is a different object (<code>copy is tree</code> is <code>False</code>).</li>
<li>Printing the estimator shows its constructor call, listing only the settings you changed from the defaults.</li>
</ol>
<h3>Example 4: realistic splitting, three parts</h3>
<p>Real projects need <em>three</em> parts. Train to fit, validation to choose settings, and a test set you open once at the very end. Splitting twice does it.</p>
@@PY
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split

X, y = make_classification(n_samples=2000, n_features=12, n_informative=5,
                           weights=[0.9, 0.1], random_state=42)
X_tmp, X_test, y_tmp, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42)
X_train, X_val, y_train, y_val = train_test_split(
    X_tmp, y_tmp, test_size=0.25, stratify=y_tmp, random_state=42)

for name, part in [("train", y_train), ("val", y_val), ("test", y_test)]:
    print(f"{name:5s} rows={len(part):4d} positive rate={part.mean():.3f}")
@@END
<ol>
<li><code>make_classification</code> builds 2,000 rows and 12 columns, 5 of them informative. <code>weights=[0.9, 0.1]</code> makes about 10% positives.</li>
<li>The first split sets aside 20% (400 rows) as the final test set. Nothing is allowed to look at it until the end.</li>
<li>The second split cuts the remaining 1,600 rows into 1,200 train and 400 validation (25% of 1,600 is 400).</li>
<li>Both splits use <code>stratify</code> so each part keeps about the same positive rate.</li>
<li>The loop prints the size and the positive rate of each part. The three rates agree closely, which is the point.</li>
</ol>
<div class="callout green"><div class="lab">KEY IDEA</div><div class="txt">Cross-validation (section 19.5) replaces the train/validation split with many rotated splits, which is more reliable on small data. The test set stays separate either way.</div></div>
