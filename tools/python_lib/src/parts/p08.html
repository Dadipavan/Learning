16.16 Cross-Library Integration

NumPy is the common language of the scientific Python world. Knowing where memory is shared and where it is copied lets you pass data between libraries without surprises. This section was run with pandas 3.0.6, SciPy 1.18.1, scikit-learn 1.9.1 and matplotlib 3.11.2.

pandas

A pandas DataFrame is a labelled table whose columns are NumPy-based arrays (strings use pandas' own string dtype, which is not a NumPy dtype). Use .to_numpy() to leave pandas, and NumPy functions work directly on Series. Since pandas 3.0, copy-on-write is always on: changing a derived object never changes the parent, and arrays handed out as views are marked read-only so you cannot corrupt the table by accident.

Problem 16.16.1 Move data between pandas and NumPy and observe dtypes and write protection.

Ideato_numpy() on mixed columns picks a common dtype; a single numeric column comes back as a read-only view. Make a .copy() if you need to write.
import numpy as np import pandas as pd df = pd.DataFrame({"price": [10.0, 12.5, 9.0], "qty": [3, 1, 4], "name": ["a", "b", "c"]}) print({k: str(v) for k, v in df.dtypes.items()}) nums = df[["price", "qty"]].to_numpy() print(nums.dtype, nums.shape) col = df["price"].to_numpy() print(col.flags.writeable) try: col[0] = 99.0 except ValueError as e: print("ValueError:", e) safe = df["price"].to_numpy().copy() safe[0] = 99.0 print(df["price"].iloc[0], safe[0]) print(np.log(df["price"]).round(3).tolist()) df["total"] = df["price"] * df["qty"] print(df["total"].to_numpy(), np.sum(df["total"])) back = pd.DataFrame(np.arange(6).reshape(3, 2), columns=["x", "y"]) print(back.dtypes.to_dict())

Line by line.

  1. Taking two numeric columns and calling to_numpy() upcasts the integers to a shared float64, giving a (3, 2) array.
  2. A single numeric column is exposed without a copy, so pandas marks it read-only (writeable is False).
  3. Copy first, then edit: the DataFrame still holds 10.0 while the copy holds 99.0.
  4. NumPy ufuncs accept Series and return Series, keeping the index. Arithmetic between columns is vectorised, exactly like arrays.

scikit-learn

scikit-learn takes NumPy arrays (or DataFrames) of shape (n_samples, n_features) and returns arrays. Remember: X must be 2D, y 1D.

import numpy as np from sklearn.linear_model import LinearRegression from sklearn.preprocessing import StandardScaler rng = np.random.default_rng(3) X = rng.normal(10, 2, size=(100, 3)) y = X @ np.array([1.0, -2.0, 0.5]) + 4.0 + rng.normal(0, 0.1, 100) sc = StandardScaler().fit(X) print(np.allclose(sc.transform(X), (X - X.mean(axis=0)) / X.std(axis=0))) model = LinearRegression().fit(X, y) print(model.coef_.round(2), round(float(model.intercept_), 2)) A = np.column_stack([X, np.ones(len(X))]) coef = np.linalg.lstsq(A, y, rcond=None)[0] print(coef.round(2)) try: LinearRegression().fit(np.arange(5.0), np.arange(5.0)) except ValueError: print("ValueError: X must be 2D") print(LinearRegression().fit(np.arange(5.0).reshape(-1, 1), np.arange(5.0) * 2).coef_)

Line by line.

  1. The data follow y = X . [1, -2, 0.5] + 4 plus small noise, so the fitted coefficients recover roughly 1, -2, 0.5 and an intercept near 4 (3.85 here, because noise and the small sample move it a little).
  2. The same least-squares fit with np.linalg.lstsq and a column of ones gives the same four numbers; scikit-learn is wrapping this kind of linear algebra with a friendly interface.
  3. Passing a 1D array as X raises a ValueError asking for a 2D array. The fix is reshape(-1, 1) (one feature, many samples), as the last line shows with the slope 2.

16.17 How to Solve Any NumPy Problem: a Playbook

The decision flow

  1. Write down the shapes of the input and the output you want. Most NumPy problems are shape problems.
  2. Ask: is it element-by-element? Use ufuncs, where, select, clip.
  3. Does it summarise along a direction? Use a reduction and decide the axis: the axis that should disappear.
  4. Does every item need to meet every other item? Add axes with None and broadcast, or use a matrix product.
  5. Does it select or rearrange? Boolean mask (by value), fancy index (by position), argsort (by rank).
  6. Does each step depend on earlier steps? Look for cumsum, accumulate, convolve, sliding_window_view; if none fits, write a loop, and consider Numba.
  7. Check it on a tiny case by hand and against a slow reference.

Eight recurring problem patterns

PatternSignal in the problemTool
1. Conditional rule per element"if ... then ... else" on each valuenp.where, np.select
2. Summary per row or column"per customer", "for each column"reduction with axis, keepdims
3. All pairs"distance between every two", "table of products"a[:, None] op b[None, :]
4. Count or group by key"how many of each", "total per store id"unique, bincount, add.at
5. Running or windowed"cumulative", "last 7 days"cumsum, sliding_window_view
6. Filter"only rows where", "remove missing"boolean mask, isnan
7. Rank or top"best 5", "order by"argsort, argpartition
8. Solve or fit"find the weights", "solve for x"solve, lstsq, @

Problem 16.17.1 One solved example for each of the eight patterns, on a small order table. Orders have a customer id (0 to 2), a price, a quantity and a rating (NaN if missing).

Data8 orders: customer ids, prices, quantities and ratings, with two missing ratings.
import numpy as np cust = np.array([0, 1, 0, 2, 1, 0, 2, 1]) price = np.array([20.0, 35.0, 15.0, 50.0, 10.0, 25.0, 40.0, 30.0]) qty = np.array([1, 2, 3, 1, 5, 2, 1, 1]) rating = np.array([4.0, np.nan, 5.0, 3.0, 4.0, np.nan, 2.0, 5.0]) revenue = price * qty size = np.where(revenue >= 60, "large", "small") print("1", size) table = np.zeros((3, 2)) for c in range(3): table[c] = [revenue[cust == c].sum(), qty[cust == c].sum()] by_cust = np.bincount(cust, weights=revenue) print("2", by_cust, table[:, 0]) P = np.column_stack([price, qty]).astype(float) D = np.abs(P[:, None, 0] - P[None, :, 0]) print("3", D.shape, D[0, :3]) print("4", np.bincount(cust), np.unique(cust, return_counts=True)[1]) running = np.cumsum(revenue) print("5", running, np.cumsum(revenue)[-1] == revenue.sum()) ok = ~np.isnan(rating) print("6", rating[ok], round(float(rating[ok].mean()), 2), round(float(np.nanmean(rating)), 2)) top2 = np.argsort(-revenue, kind="stable")[:2] print("7", top2, revenue[top2]) A = np.column_stack([price, np.ones(len(price))]) coef = np.linalg.lstsq(A, qty, rcond=None)[0] print("8", coef.round(3))

Line by line.

  1. Pattern 1. Revenue is price times quantity for every order at once. where labels orders of 60 or more as large: only order 1, with revenue 70, qualifies.
  2. Pattern 2. A loop over three customers builds the by-customer table; bincount with weights gives the same revenue per customer in one call, and the second print shows that they agree.
  3. Pattern 3. price[:, None] against price[None, :] forms the 8 by 8 table of absolute price gaps; the first row, restricted to three entries, starts with 0 (an order versus itself).
  4. Pattern 4. Counts of orders per customer, computed two ways, agree: customer 0 has 3, customer 1 has 3, customer 2 has 2.
  5. Pattern 5. A running revenue total; its last element must equal the plain sum, a cheap built-in check.
  6. Pattern 6. The mask ~isnan keeps the six known ratings; their mean is 3.83 and equals nanmean.
  7. Pattern 7. The two biggest orders by revenue: order 1 (70) and then order 3 (50). Orders 3, 4 and 5 all earn 50, and the stable sort keeps the earliest of the tie.
  8. Pattern 8. A least-squares line of quantity against price: a slope of about -0.076 units per currency unit and an intercept of about 4.14, so pricier orders tend to have smaller quantities in this tiny table.

How to verify

  • Tiny case by hand: shrink the input to 3 or 4 items you can calculate on paper.
  • Slow reference: write the obvious loop, compare with np.testing.assert_allclose on random inputs.
  • Invariants: probabilities sum to 1, a distance matrix is symmetric with a zero diagonal, a split covers every row exactly once, a sorted array has non-negative np.diff.
  • Shapes: assert expected shapes at function boundaries.
import numpy as np rng = np.random.default_rng(11) P = rng.random((40, 3)) D = np.sqrt(((P[:, None] - P[None]) ** 2).sum(-1)) ref = np.zeros((40, 40)) for i in range(40): for j in range(40): ref[i, j] = np.sqrt(sum((P[i, k] - P[j, k]) ** 2 for k in range(3))) np.testing.assert_allclose(D, ref, rtol=1e-12) print("matches loop:", True) print("symmetric:", np.allclose(D, D.T), "zero diagonal:", np.allclose(np.diag(D), 0)) print("triangle inequality holds:", bool((D[0, 1] + D[1, 2] >= D[0, 2] - 1e-12)))

Line by line.

  1. The slow reference uses three nested loops. If the arrays disagree, assert_allclose raises with a readable report of the worst mismatch.
  2. Then property checks that must hold for any distance matrix: symmetric, zero diagonal, and the triangle inequality on one triple.

How to debug

  • Print shape, dtype and a few values after every step. Most bugs show up as an unexpected shape.
  • Reproduce on a tiny seeded input, so that you can read the whole array.
  • Turn silent float warnings into errors with np.errstate(all="raise"), so that a divide by zero stops the program at the exact line.
  • Check x.base and np.shares_memory when data changes unexpectedly.
  • Split a long chain into named intermediate variables and inspect each one.

16.18 Going Deeper: Internals, Memory, Speed and Interview Questions

How a ufunc works

A ufunc such as np.add is an object with several compiled inner loops, one per dtype combination. When you call it, NumPy (1) works out the result dtype from the inputs, (2) works out the broadcast shape, (3) allocates the output and (4) calls the matching loop over the buffers, with the strides handling the broadcast. Modern CPUs also use SIMD instructions in many of these loops. The ufunc object also carries methods that generalise it.

import numpy as np print(np.add.reduce([1, 2, 3]), np.add.accumulate([1, 2, 3])) print(np.multiply.outer([1, 2], [3, 4])) print(np.maximum.accumulate([1, 3, 2, 5, 4])) a = np.zeros(3) np.add.at(a, [0, 0, 2], 1.0) print(a) print(np.add.types[:4])

Line by line.

  1. reduce folds an array with the operation: add.reduce is the sum, 6. accumulate keeps the running result: [1 3 6], which is cumsum.
  2. maximum.accumulate gives a running maximum, a pattern with no dedicated function name: [1 3 3 5 5].
  3. np.add.at adds with repeated indexes counted properly: index 0 appears twice, so a[0] is 2.

Type promotion in NumPy 2

NumPy 2 changed how Python numbers mix with arrays (NEP 50). A plain Python int or float is "weak": it takes the dtype of the array. So uint8_array + 100 stays uint8 (and wraps around), and a Python integer that does not fit raises an error rather than silently changing the result type. Two arrays of different dtypes still promote to a common type, which can be surprising: unsigned 64-bit with signed 64-bit goes to float64.

import numpy as np a = np.array([200], dtype=np.uint8) print((a + 100), (a + 100).dtype) print((np.array([1.0], dtype=np.float32) + 3.0).dtype) try: np.array([1], dtype=np.uint8) + 300 except OverflowError as e: print("OverflowError:", e) print(np.result_type(np.uint64, np.int64), np.result_type(np.int32, np.float32))

Line by line.

  1. 200 + 100 does not fit in uint8, so the answer wraps to 44, and the dtype remains uint8.
  2. Adding the integer 300 to a uint8 array raises OverflowError, because 300 cannot be represented in uint8 at all.
  3. Mixing unsigned 64-bit and signed 64-bit integers has no integer type that holds both, so the result is float64. int32 with float32 also goes to float64, to avoid losing integer digits.

Speed: what actually matters

  • Contiguity and bandwidth. Contiguous data is friendlier to the CPU cache; for big arrays memory traffic dominates, so fewer passes and smaller dtypes help more than clever arithmetic.
  • BLAS threads. Matrix products use multi-threaded libraries, usually controlled by environment variables such as OMP_NUM_THREADS. Check your build with np.show_config().
  • Sorting. The default quicksort is not stable; kind="stable" selects a stable method.
  • When NumPy is not enough: Numba or Cython for loops that cannot be vectorised (not run here); memmap, Dask or a database for data larger than memory; CuPy or PyTorch for the GPU.

What interviewers probe

INTERVIEW
  • "Why is NumPy faster than lists?" Same-type values in one contiguous buffer, compiled loops, no per-element Python object, SIMD and cache-friendly access.
  • "View or copy?" Basic slicing, reshape and transpose are views; boolean and fancy indexing copy.
  • "Explain broadcasting." Right-aligned shapes; each axis must match or be 1; size-1 axes are stretched with stride 0.
  • "Subtract row means from a matrix." X - X.mean(axis=1, keepdims=True).
  • "Why not inv to solve a system?" solve is faster and more accurate.
  • "Reproducible randomness in parallel code?" One default_rng(seed), then spawn.
