<p>Priya works at a mid-sized telecom. On Monday her manager forwards a spreadsheet of 20,000 customers with a column called <code>churned</code> and says: "Tell me who is about to leave, and tell me how sure you are." Priya knows pandas. She can filter, group and plot. But nothing in pandas will <em>learn</em> a rule from the data. She needs a tool that takes a table of examples and returns a function that makes predictions, and she needs to know whether that function will still work next month on customers it has never seen.</p>
<p>That tool is <strong>scikit-learn</strong>. It is the standard Python library for classical machine learning on tables: predicting a label (classification), predicting a number (regression), grouping similar rows (clustering), compressing columns (dimensionality reduction) and finding odd rows (anomaly detection). It is also the library where beginners most often fool themselves, because it is very easy to get a score that looks wonderful and means nothing. This chapter teaches both halves: how to use every important part of the library, and how to use it <em>honestly</em>.</p>
<p>By the end you will be able to build a complete, leak-free model pipeline, tune and evaluate it with cross-validation, pick metrics that match the business question, calibrate probabilities, handle imbalanced classes, explain a model, save it, and write your own transformer. You will also have a playbook for the recurring problems you will meet at work and 22 practice problems with full answers.</p>
<p><em>Words you need.</em> A <strong>feature</strong> is one input column. <strong>X</strong> is the table of features (rows are samples). <strong>y</strong> is the target you want to predict. <strong>Training</strong> (or fitting) means letting the algorithm learn from X and y. A <strong>hyper-parameter</strong> is a setting you choose before training (such as the depth of a tree). A <strong>leak</strong> is information from the test data that sneaks into training, which makes scores look better than reality.</p>

<h2>19.1 What scikit-learn Is, When to Use It, and the Mental Model</h2>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt">Scikit-learn is a toolbox where every tool has the same handle. Whether you use a linear model, a forest or a scaler, you build the object, call <code>fit</code> to learn from data, and then call <code>predict</code> or <code>transform</code> to use what it learned. Learn the handle once and you can pick up any tool in the box.</div></div>
<h3>What it is</h3>
<p>Scikit-learn (import name <code>sklearn</code>) is a library of machine-learning algorithms plus the machinery around them: splitting data, preprocessing, chaining steps, searching for settings, measuring quality, and inspecting results. It is built on NumPy and SciPy. Its design goal is a <strong>consistent interface</strong>: all algorithms are <em>estimators</em> that follow the same few method names.</p>
<h3>When to use it</h3>
<ul>
<li>Your data is a table (rows and columns) of up to a few million rows that fits in memory.</li>
<li>You want a strong baseline fast: logistic regression, random forest, gradient boosting.</li>
<li>You need preprocessing, validation and tuning that are correct by construction (pipelines, cross-validation).</li>
<li>You need classical unsupervised tools: k-means, PCA, DBSCAN, isolation forest.</li>
</ul>
<h3>When NOT to use it</h3>
<ul>
<li><strong>Deep learning</strong> on images, audio or long text: use PyTorch or TensorFlow (see the Deep Learning document).</li>
<li><strong>Data far larger than memory</strong>, or distributed training: use Spark ML, Dask, or the out-of-core <code>partial_fit</code> estimators for simple models only.</li>
<li><strong>Statistical inference</strong> (p-values, confidence intervals on coefficients): use <code>statsmodels</code>. Scikit-learn optimises prediction and does not report standard errors.</li>
<li><strong>Time-ordered forecasting with seasonality</strong>: scikit-learn can do the regression part, but dedicated time-series tools handle the structure better (see the Statistics document).</li>
<li><strong>Online or GPU training at scale</strong>: not its job.</li>
</ul>

<h3>The mental model</h3>
<p>Three ideas explain almost everything. First, an <strong>estimator</strong> is an object holding settings (hyper-parameters, set in the constructor). Second, calling <code>fit(X, y)</code> makes the object <em>learn</em> and store the results in attributes whose names end in an underscore, such as <code>coef_</code>. Third, a fitted object can then <code>predict</code> (models) or <code>transform</code> (preprocessors) new data using only what it stored.</p>
<figure><img src="images/lib19_api.png" alt="Diagram: training data goes into an estimator through fit, producing fitted attributes; new X goes through predict or transform using the learned state to produce output" loading="lazy"/><figcaption>The estimator life cycle: settings in, fit learns state, predict or transform applies that state to new data.</figcaption></figure>
<p><strong>How to read it:</strong> follow the top row left to right: data and an unfitted estimator meet in <code>fit</code>, and the learned numbers land in the fitted attributes. The diagonal arrow is the key: the bottom box uses only that stored state, never the training data again. Everything about leakage in this chapter is a violation of this picture, where information flows into the learned state from rows that should have been kept out.</p>
<div class="callout green"><div class="lab">KEY IDEA</div><div class="txt">Constructor = choose settings. <code>fit</code> = learn from <em>training data only</em>. <code>predict</code> / <code>transform</code> = apply what was learned. A trailing underscore (<code>coef_</code>, <code>classes_</code>, <code>mean_</code>) means "this exists only after fit".</div></div>
