
<h2>19.4 Model Families: Linear, Trees, Forests, Boosting, SVM, kNN, Naive Bayes, Clustering, PCA</h2>
<p>You do not need to know all the algorithms deeply to use them well. You need to know what each assumes, what it is fast or slow at, and which settings matter. All of them share the interface from 19.2, so swapping one for another is a one-line change.</p>

<h3>Example 1: one loop, many models</h3>
<p>Because the interface is uniform, comparing families is a short loop. Scale-sensitive models (SVM, kNN, logistic) get a <code>StandardScaler</code> in a pipeline.</p>
@@PY
from sklearn.datasets import load_breast_cancer
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import HistGradientBoostingClassifier, RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.naive_bayes import GaussianNB
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True)
cv = StratifiedKFold(5, shuffle=True, random_state=0)
models = {
    "dummy": DummyClassifier(strategy="prior"),
    "logistic": make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
    "tree": DecisionTreeClassifier(max_depth=4, random_state=0),
    "forest": RandomForestClassifier(200, random_state=0),
    "hist boosting": HistGradientBoostingClassifier(random_state=0),
    "svm": make_pipeline(StandardScaler(), SVC()),
    "knn": make_pipeline(StandardScaler(), KNeighborsClassifier(15)),
    "naive bayes": GaussianNB(),
}
for name, m in models.items():
    s = cross_val_score(m, X, y, cv=cv)
    print(f"{name:14s} {s.mean():.3f} +/- {s.std():.3f}")
@@END
<ol>
<li>The breast-cancer dataset has 569 rows, 30 numeric features and a binary target. <code>return_X_y=True</code> returns just the arrays.</li>
<li><code>StratifiedKFold(5, shuffle=True, random_state=0)</code> defines the same five folds for every model, so the comparison is fair.</li>
<li>The dictionary maps a name to an unfitted model. The dummy model always predicts the most common class and sets the floor any real model must beat.</li>
<li>Scale-sensitive models are wrapped with <code>make_pipeline(StandardScaler(), ...)</code>. Trees, forests, boosting and Naive Bayes do not need scaling.</li>
<li><code>cross_val_score</code> fits and scores each model on the five folds and returns five numbers; we print the mean and the spread.</li>
</ol>
<p><strong>Reading the output:</strong> the dummy sits at about 0.627 (the share of the common class). Every real model beats it clearly, and the scaled linear and kernel models are at the top. The differences between the best few are within about one standard deviation of each other, so on 569 rows you cannot declare a winner from this table. Report the spread, not just the mean.</p>
<h3>Example 2: linear models, penalties and coefficients</h3>
<p>Ridge and Lasso add a penalty to the fit. The strength is <code>alpha</code>. A bigger alpha means smaller weights. Lasso can set weights to exactly zero.</p>
@@PY
import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.linear_model import Lasso, LinearRegression, Ridge
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

X, y = load_diabetes(return_X_y=True)
names = load_diabetes().feature_names
X_tr, X_te, y_tr, y_te = train_test_split(X, y, random_state=0)

for label, est in [("ols", LinearRegression()), ("ridge a=10", Ridge(alpha=10)),
                   ("lasso a=2", Lasso(alpha=2.0))]:
    m = make_pipeline(StandardScaler(), est).fit(X_tr, y_tr)
    coef = m[-1].coef_
    print(f"{label:11s} R2={m.score(X_te, y_te):.3f} zeros={int((coef == 0).sum())}",
          np.round(coef[:4], 1))
print(names[:4])
@@END
<ol>
<li>The diabetes dataset has 442 patients, 10 numeric features, and a disease-progress score as the target.</li>
<li>We split once and loop over three linear models: plain least squares, Ridge with alpha 10, and Lasso with alpha 2.</li>
<li>Each model gets a scaler first. Penalised models are <strong>scale-dependent</strong>, because a penalty on weights treats a column in grams differently from the same column in kilograms.</li>
<li><code>m[-1]</code> is the last pipeline step (the linear model); <code>coef_</code> holds its weights.</li>
<li>We print the test R squared, how many weights are exactly zero, and the first four weights.</li>
</ol>
<p><strong>Reading the output:</strong> Ridge shrinks the weights toward zero but keeps all ten. Lasso at alpha 2 sets three of the ten weights to exactly zero (the first one, <code>age</code>, prints as -0.0), which is built-in feature selection. The test R squared values are almost identical, 0.359, 0.358 and 0.355: on this noisy target, shrinking does not add accuracy, but Lasso gives a smaller model with the same score, and Ridge gives more stable weights when columns are correlated.</p>
<h3>Example 3: a tree you can read, and how depth causes overfitting</h3>
@@PY
from sklearn.datasets import load_iris, make_moons
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier, export_text

iris = load_iris()
small = DecisionTreeClassifier(max_depth=2, random_state=0).fit(iris.data, iris.target)
print(export_text(small, feature_names=list(iris.feature_names)))

X, y = make_moons(600, noise=0.35, random_state=1)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.3, random_state=1)
for d in (1, 3, 6, None):
    t = DecisionTreeClassifier(max_depth=d, random_state=0).fit(X_tr, y_tr)
    print(f"depth={d!s:4s} leaves={t.get_n_leaves():3d} "
          f"train={t.score(X_tr, y_tr):.3f} test={t.score(X_te, y_te):.3f}")
@@END
<ol>
<li><code>export_text</code> prints the learned flowchart as indented rules, so a non-technical colleague can read it. We fit it on the iris flowers.</li>
<li>A depth-2 tree asks at most two questions per flower. Each line shows a question, and each <code>class:</code> line is a leaf with its prediction.</li>
<li>For the depth experiment we switch to the noisy two-moons data, where overfitting is easy to see. We hold out 30% for testing.</li>
<li>The loop trains trees of increasing depth. <code>None</code> means grow until every leaf is pure.</li>
<li><code>get_n_leaves()</code> counts the final boxes. More leaves means a more flexible model.</li>
<li>We print train and test accuracy for each depth.</li>
</ol>
<p><strong>Reading the output:</strong> the iris tree needs only the petal width, two cuts at 0.80 and 1.75. On the moons, train accuracy climbs from 0.783 to 1.000 as the tree grows to 68 leaves, while test accuracy peaks at 0.850 for depth 3 and falls to 0.822 with no limit. A perfect training score from an unlimited tree only says it memorised the rows. This train-versus-test gap is the signature of overfitting, and the fix is to limit depth or <code>min_samples_leaf</code>, or to average many trees (a forest).</p>
<h3>Example 4: forests and boosting, including missing values</h3>
<p>A random forest averages many deep, de-correlated trees. Gradient boosting builds shallow trees one after another, each fixing the errors of the last. <code>HistGradientBoosting*</code> bins numbers into 255 buckets, which makes it fast, and it accepts <code>NaN</code> directly.</p>
@@PY
import numpy as np
from sklearn.datasets import make_classification
from sklearn.ensemble import HistGradientBoostingClassifier, RandomForestClassifier
from sklearn.model_selection import train_test_split

X, y = make_classification(4000, 20, n_informative=6, random_state=0)
rng = np.random.default_rng(0)
X[rng.random(X.shape) < 0.1] = np.nan           # blank out 10% of cells
X_tr, X_te, y_tr, y_te = train_test_split(X, y, random_state=0)

hgb = HistGradientBoostingClassifier(max_iter=200, learning_rate=0.1,
                                     early_stopping=True, random_state=0)
hgb.fit(X_tr, y_tr)
print("hist boosting test acc:", round(hgb.score(X_te, y_te), 3),
      "iterations used:", hgb.n_iter_)

rf = RandomForestClassifier(200, oob_score=True, random_state=0)
rf.fit(X_tr, y_tr)
print("forest test acc:", round(rf.score(X_te, y_te), 3))
print("forest OOB score:", round(rf.oob_score_, 3))
@@END
<ol>
<li>We make 4,000 rows and then blank out 10% of all cells at random to simulate a gappy table.</li>
<li>The histogram booster is fitted directly on data containing <code>NaN</code>. It learns, at each split, which side the missing rows should go to.</li>
<li><code>early_stopping=True</code> holds out 10% of training rows internally and stops adding trees when the score stops improving, so <code>n_iter_</code> can be below <code>max_iter</code>.</li>
<li>Recent scikit-learn versions let <code>RandomForestClassifier</code> (and decision trees) take <code>NaN</code> too, so the forest is fitted on the same gappy matrix. Not every estimator does: logistic regression, SVM and kNN still raise an error, so check the docs or impute in a pipeline.</li>
<li><code>oob_score=True</code> asks the forest to evaluate each row using only the trees whose bootstrap sample did not include it. This gives a free validation estimate without a separate split.</li>
</ol>
<p><strong>Reading the output:</strong> boosting reaches 0.889 test accuracy and stopped after 75 trees because early stopping saw no further gain. The forest's test accuracy is 0.876 and its out-of-bag score is 0.876, the same to three decimals here (they will not always agree this closely), which is why OOB is a useful quick check.</p>
<div class="callout blue"><div class="lab">INTUITION</div><div class="txt"><strong>Forest versus boosting.</strong> A forest is a committee of independent experts who each saw a different random slice of the data; averaging cancels their individual quirks (it lowers variance). Boosting is an apprentice chain: each new small tree is trained on what the previous ones still get wrong (it lowers bias). Boosting usually wins on tables when tuned, and a forest is harder to break when you do not tune.</div></div>
<h3>Example 5: why scaling matters for kNN and SVM</h3>
@@PY
import numpy as np
from sklearn.model_selection import cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
n = 600
signal = rng.normal(size=n)                       # small-scale informative column
y = (signal + rng.normal(scale=0.5, size=n) > 0).astype(int)
big_noise = rng.normal(scale=1000, size=n)         # huge-scale useless column
X = np.c_[signal, big_noise]

raw = KNeighborsClassifier(15)
scaled = make_pipeline(StandardScaler(), KNeighborsClassifier(15))
print("raw   :", cross_val_score(raw, X, y, cv=5).mean().round(3))
print("scaled:", cross_val_score(scaled, X, y, cv=5).mean().round(3))
@@END
<ol>
<li>One informative column with unit scale, and one useless column with a standard deviation of 1,000.</li>
<li>kNN measures distances between rows. Without scaling, the distance is dominated almost entirely by the big useless column.</li>
<li>The scaled version puts both columns on equal footing, so the informative one can do its work.</li>
<li>The raw model scores near coin-flip, and the scaled model scores far better.</li>
</ol>
<h3>Example 6: unsupervised families, clustering and PCA</h3>
@@PY
import numpy as np
from sklearn.cluster import DBSCAN, KMeans
from sklearn.datasets import load_wine, make_moons
from sklearn.decomposition import PCA
from sklearn.metrics import adjusted_rand_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

X, y = load_wine(return_X_y=True)
Xs = StandardScaler().fit_transform(X)
pca = PCA().fit(Xs)
print("explained variance ratio:", pca.explained_variance_ratio_[:4].round(3))
print("components for 90%:", int(np.searchsorted(np.cumsum(pca.explained_variance_ratio_), 0.90) + 1))

Z = PCA(n_components=2).fit_transform(Xs)
km = KMeans(3, n_init=10, random_state=0).fit(Z)
print("kmeans vs true wine class, ARI:", round(adjusted_rand_score(y, km.labels_), 3))

M, truth = make_moons(400, noise=0.07, random_state=0)
km2 = KMeans(2, n_init=10, random_state=0).fit(M)
db = DBSCAN(eps=0.2, min_samples=5).fit(M)
print("moons ARI, kmeans:", round(adjusted_rand_score(truth, km2.labels_), 3))
print("moons ARI, dbscan:", round(adjusted_rand_score(truth, db.labels_), 3),
      "clusters:", len(set(db.labels_) - {-1}), "noise:", int((db.labels_ == -1).sum()))
@@END
<ol>
<li>The wine data has 178 rows and 13 chemical measurements. PCA is scale-sensitive, so we standardise first.</li>
<li><code>explained_variance_ratio_</code> says what fraction of the total variation each new axis carries, in decreasing order. The cumulative sum tells us how many axes keep 90%.</li>
<li>We keep two components, cluster the 2-D points with k-means (k=3), and compare to the true wine classes with the adjusted Rand index (1.0 is a perfect match, around 0 is random).</li>
<li>On the two-moons data we know the true grouping. k-means is asked for two clusters; it cuts the plane with a straight divide, which does not follow the moons.</li>
<li><code>DBSCAN</code> grows clusters from dense neighbourhoods and can follow curved shapes. Label -1 means noise. We count the clusters found and the noise points, and score both against the truth with the adjusted Rand index.</li>
</ol>
<p><strong>Reading the output:</strong> the first PCA axis carries 36.2% of the variance and the second 19.2%, so two axes keep about 55% and 8 axes are needed for 90%. Even so, k-means on just two axes recovers the true wine classes well (ARI 0.895). On the moons, k-means scores an ARI of only 0.269 because round clusters are the wrong assumption, while DBSCAN scores 1.0, finding the two moons exactly with no noise points. The lesson: pick the clustering method to match the shape you expect.</p>
