16.12 Vectorisation vs Loops, with Timings

Vectorising means replacing a Python for loop with array operations. The loop is slow not because Python is careless but because for each element it must look up types, create a Python float object and call the interpreter. A NumPy operation does that bookkeeping once, then runs a tight compiled loop over raw numbers.

How to read it: each dot is one measurement. The horizontal axis is how many numbers; the vertical axis is seconds, and each gridline is ten times bigger than the last. The loop line climbs steadily because its work is proportional to n. The NumPy line starts flat, because for small arrays the fixed cost of one call dominates, and then rises. The gap is the constant factor you buy by vectorising: for a million numbers it was more than a hundredfold in these measurements.

Problem 16.12.1 Time a loop against a vectorised version of the same job, on three tasks, and confirm the answers match. The code prints only facts that do not change between runs; the measured numbers are given in the text below.

SetupOne million random floats. Tasks: scale-and-shift every value, sum of squares, and growing an array one item at a time.
MethodUse time.perf_counter and keep the best of several repeats to reduce noise.
import time import numpy as np def best(f, repeats=3): t = float("inf") for _ in range(repeats): start = time.perf_counter() f() t = min(t, time.perf_counter() - start) return t rng = np.random.default_rng(0) x = rng.random(1_000_000) xl = x.tolist() def loop_scale(): out = [] for v in xl: out.append(v * 2 + 1) return out t_loop = best(loop_scale) t_vec = best(lambda: x * 2 + 1) print("same result:", np.allclose(loop_scale(), x * 2 + 1)) print("vectorised at least 10x faster:", t_loop / t_vec > 10) t_sum_loop = best(lambda: sum(v * v for v in xl)) t_sum_vec = best(lambda: x @ x) print("sum of squares equal:", np.isclose(sum(v * v for v in xl), x @ x)) print("at least 10x faster:", t_sum_loop / t_sum_vec > 10) def grow(): a = np.array([]) for i in range(10000): a = np.append(a, i) return a def preallocate(): a = np.empty(10000) for i in range(10000): a[i] = i return a print("growing is slower than preallocating:", best(grow) > best(preallocate))

Line by line.

  1. best runs a function a few times and keeps the fastest run. The minimum is the best estimate of the cost, because noise from other programs only ever slows a run down.
  2. The scaling task: a loop with append against x * 2 + 1. The results agree, and the vector form is more than ten times faster.
  3. Growing an array with np.append copies the whole array every time, so 10,000 appends do about 50 million copies of items.

Measured on the laptop used for this chapter (they vary): scale-and-shift 46 ms in the loop against 0.7 ms vectorised; sum of squares 20 ms against 0.1 ms; 10,000 appends 19 ms against 0.35 ms preallocated; a 300-point pairwise distance table 92 ms with nested loops against 1.1 ms vectorised.

COMMON MISTAKE
Wrong: np.sum(my_list) or np.array(my_list).sum() for a one-off sum of a small Python list. Symptom: slower than the built-in sum, because NumPy first converts the whole list to an array (measured here: about 17 ms against 2.7 ms for a million floats). Fix: convert once and keep the data as an array, or use sum for a single pass over a list.

Because arrays share buffers, the question "does this change my original?" matters. The answer follows a simple rule.

How to read it: on the left the arrows mean the red array points into the blue one: no new numbers exist, so writing through the red array edits the blue one. On the right there are no arrows: the teal array owns separate memory and edits stay private.

Problem 16.13.1 A function normalises an array and unexpectedly alters the caller's data. Find out why and fix it.

CausePassing an array to a function passes a reference to the same buffer. In-place operators such as -= and /= then change the caller's array.
FixDo not use in-place operators on arguments, or take a copy first.
import numpy as np def centre_bad(x): x -= x.mean() return x def centre_good(x): return x - x.mean() data = np.array([2.0, 4.0, 6.0]) out = centre_bad(data) print(data, out, out is data) data = np.array([2.0, 4.0, 6.0]) out = centre_good(data) print(data, out) ints = np.array([1, 2, 3]) try: ints /= 2 except Exception as e: print(type(e).__name__) ints = ints / 2 print(ints, ints.dtype) a = np.arange(6) row = a[:3] row *= 10 print(a) print(np.shares_memory(a, a[:3]), np.shares_memory(a, a[[0, 1, 2]]))

Line by line.

  1. centre_bad uses -=, which writes into the buffer it was given. After the call, data itself holds [-2. 0. 2.], and out is data is True: the "result" is the same object.
  2. ints /= 2 on an integer array tries to store floats back into integer memory and NumPy refuses, raising UFuncTypeError.
  3. Multiplying the slice row in place changes a as well: [0 10 20 3 4 5].
  4. shares_memory is True for the slice and False for the fancy selection of the same three cells.

Views also save memory: a slice of a 1 GB array costs almost nothing. The flip side is that a small view keeps the whole big buffer alive. If you keep only a tiny slice of a huge array for a long time, .copy() it so the big buffer can be freed.
