There are four ways arrays are born: from existing Python data, from a pattern (zeros, ranges), from random numbers (16.10), and from files. Pick the constructor that says what you mean.

Problem 16.3.1 Build the common starting arrays and look at them.

IdeaUse arange, linspace, full, eye and zeros_like, and watch dtypes.
import numpy as np print(np.arange(0, 10, 3)) print(np.arange(0, 1, 0.25)) print(np.linspace(0, 1, 5)) print(np.full((2, 3), 7)) print(np.eye(3, dtype=int)) x = np.array([1.5, 2.5]) print(np.zeros_like(x), np.zeros_like(x).dtype) print(np.logspace(0, 3, 4))

Line by line.

  1. arange(0, 10, 3) starts at 0, steps by 3 and stops before 10: 0 3 6 9.
  2. With a float step, arange works but can be off by one element because of rounding. Here 0.25 is exact in binary, so it is safe: four values.
  3. linspace(0, 1, 5) includes both ends and chooses the step for you (0.25). Prefer it when you know how many points you want.
  4. logspace(0, 3, 4) gives 100 to 103: 1 10 100 1000, written as floats.
COMMON MISTAKE
Wrong: np.arange(0, 1, 0.1) when you need exactly 11 points, or np.zeros(3, 4). Symptom: the first gives 10 values and never reaches 1; the second raises a TypeError because the second argument is the dtype. Fix: np.linspace(0, 1, 11) and np.zeros((3, 4)), with the shape as one tuple.

16.4 Indexing: Slicing, Boolean Masks and Fancy Indexing

Indexing is how you say "give me these elements". NumPy has three families and they behave differently in one crucial way: slices are views (no copy), while boolean and fancy indexing return copies.

Problem 16.4.1 Use boolean masks to filter and to assign. A store has daily sales and wants to cap outliers and count good days.

Step 1A comparison produces a boolean array of the same shape.
Step 2Combine conditions with & (and), | (or), ~ (not), each condition in brackets.
Step 3Summing booleans counts the Trues; averaging them gives a proportion.
import numpy as np sales = np.array([120, 340, 95, 410, 80, 275, 1500, 310]) mask = sales > 300 print(mask) print(sales[mask]) print(sales[(sales > 100) & (sales < 400)]) print(sales[~mask]) print(mask.sum(), mask.mean()) capped = sales.copy() capped[capped > 500] = 500 print(capped) print(sales[sales > 300].mean())

Line by line.

  1. For "between", write both comparisons in brackets and join with &. Writing 100 < sales < 400 raises an error, because Python tries to turn an array into a single True or False.
  2. mask.sum() is 4 (True counts as 1), and mask.mean() is 0.5, the share of days above 300.
  3. We copy before assigning so the original stays intact, then replace everything above 500 by 500; the 1500 becomes 500.

Problem 16.4.2 Fancy indexing: pick rows by position, pick individual cells, take a sub-grid, and see that it is a copy.

IdeaA list of integers selects those positions in that order. Two lists select pairs. np.ix_ turns two lists into a rectangle.
import numpy as np m = np.arange(20).reshape(4, 5) print(m[[3, 0]]) print(m[[0, 2], [1, 4]]) print(m[np.ix_([0, 2], [1, 4])]) sub = m[[0, 1]] sub[0, 0] = 999 print(m[0, 0], sub.base is None) view = m[:2] view[0, 0] = 999 print(m[0, 0])

Line by line.

  1. m[[0, 2], [1, 4]] pairs the lists: cell (0,1) and cell (2,4), giving 1 and 14. The result is 1D, not a rectangle.
  2. To get the rectangle of rows 0, 2 and columns 1, 4, use np.ix_: the result is a 2 by 2 array [[1 4] [11 14]].
  3. sub = m[[0, 1]] is fancy indexing, so it is a copy. Writing 999 into sub leaves m[0, 0] at 0, and sub.base is None shows it owns its memory.
  4. view = m[:2] is a slice, so it is a view. Writing 999 through it changes m[0, 0] to 999.
COMMON MISTAKE
Wrong: m[m[:, 0] > 5][:, 1] = 0 (chained indexing). Symptom: nothing changes in m, with no error, because m[mask] is a copy and you assigned into the copy. Fix: do the whole selection in one assignment: m[m[:, 0] > 5, 1] = 0.
REAL JOB
A common pipeline step is "set every negative sensor reading to NaN, then drop incomplete rows". In NumPy it is two lines: x[x < 0] = np.nan then x = x[~np.isnan(x).any(axis=1)]. You will see this pattern again in 16.8.
