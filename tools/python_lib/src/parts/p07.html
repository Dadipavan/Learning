16.15 Performance and Pitfalls

Speed rules that hold up

  • Move loops into NumPy (16.12), preallocate instead of growing, and collect pieces in a list before one np.concatenate.
  • Avoid needless copies. Slices and reshapes are free; fancy indexing, astype and temporaries are not. Use out= or in-place operators when you own the array.
  • Pick the smallest sufficient dtype (float32, int32) and check precision. Prefer @ to element loops, since it calls optimised BLAS code.
  • Measure, do not guess. Use time.perf_counter or timeit, repeat, keep the best.

Problem 16.15.1 Run five classic traps in one script so you can see the symptoms with your own eyes.

IdeaEach line below reproduces one pitfall. The explanation after the output names the fix.
import numpy as np a = np.array([1, 2, 3]) a[0] = 2.9 print(a) f = np.float32(16777216) print(f + np.float32(1) == f) y = np.array([1.0, 2.0, 3.0]) pred = np.array([[1.0], [2.0], [3.0]]) print((y - pred).shape, ((y - pred) ** 2).mean()) print(((y - pred.ravel()) ** 2).mean()) b = a b[1] = 99 print(a) data = np.array([3, 1, 2]) result = data.sort() print(result, data) v = np.array([1.0, np.nan, 3.0]) print(v.argmax(), np.nanargmax(v)) M = np.arange(6).reshape(2, 3) print(sum(M), M.sum())

Line by line.

  1. Assigning 2.9 into an integer array silently truncates it to 2. The array keeps its dtype and does not upgrade.
  2. float32 has only 24 bits of precision: 16,777,216 + 1 equals 16,777,216, so the addition is lost. Fix: accumulate in float64 (dtype=np.float64) when summing many values.
  3. The shapes (3,) and (3, 1) broadcast to (3, 3). The "mean squared error" is computed over nine pairs, not three, and comes out as 1.333 instead of 0.
  4. b = a copies nothing; it adds a second name for the same array. Changing b[1] changes a. Fix: b = a.copy().
  5. data.sort() sorts in place and returns None. Writing result = data.sort() leaves you with None. Fix: np.sort(data) for a new array.
  6. The built-in sum(M) adds the rows as Python objects and returns an array [3 5 7]; M.sum() returns the grand total 15.

Ten common mistakes, each with symptom and fix

COMMON MISTAKE 1: truth value of an array
Wrong: if a == b: or if x > 0: where x is an array. Symptom: ValueError: The truth value of an array with more than one element is ambiguous. Fix: say what you mean: (x > 0).all(), (x > 0).any(), np.array_equal(a, b) or np.allclose(a, b).
COMMON MISTAKE 2: and / or and operator precedence
Wrong: x[(x > 1) and (x < 5)] or x[x > 1 & x < 5]. Symptom: the same ambiguous-truth error (Python's and wants one boolean), or for the second form a confusing error because & binds tighter than >. Fix: x[(x > 1) & (x < 5)], with brackets around every comparison.
COMMON MISTAKE 3: integer wrap-around and truncation
Wrong: np.uint8 or int32 arithmetic that exceeds the range; int_array / 2 assigned back with [:] =. Symptom: negative sales totals, 255 + 1 = 0, silent truncation. Fix: convert up first (astype(np.int64) or float64), and check ranges with np.iinfo.
COMMON MISTAKE 4: accidental (n, n) broadcasting
Wrong: np.mean((y - pred) ** 2) with y of shape (n,) and pred of shape (n, 1). Symptom: a wrong number and a sudden memory spike on large n (an n by n matrix), but no error. Fix: assert shapes (assert y.shape == pred.shape) at function boundaries.
COMMON MISTAKE 5: aliasing instead of copying
Wrong: backup = arr, best = weights inside a training loop. Symptom: your "backup" changes along with the original; your "best weights" always equal the latest weights. Fix: backup = arr.copy().
COMMON MISTAKE 6: growing arrays in a loop
Wrong: for r in rows: arr = np.append(arr, r) or np.vstack([arr, r]) inside a loop. Symptom: time grows with the square of the data; a job that takes seconds for 10,000 rows takes hours for 10 million. Fix: collect results in a Python list and call np.array(results) once, or preallocate with np.empty and fill by index.
COMMON MISTAKE 7: shuffling or sorting that returns None
Wrong: x = rng.shuffle(x) or x = x.sort(). Symptom: x becomes None and the next line fails with TypeError: 'NoneType' object is not subscriptable. Fix: in-place methods return nothing; call them as statements, or use rng.permutation(x) and np.sort(x) to get a new array.
COMMON MISTAKE 8: same seed everywhere, or no seed
Wrong: calling np.random.default_rng() with no seed in a reported experiment, or reusing seed 0 for every parallel worker. Symptom: results nobody can reproduce, or workers producing identical "random" numbers. Fix: one seeded generator per run, and rng.spawn(n) to hand independent children to workers.
COMMON MISTAKE 9: float equality and accumulated error
Wrong: if total == 0.3: after adding 0.1 three times; summing a million float32 values in a plain loop. Symptom: False where you expect True; sums that are slightly off. Fix: np.isclose with a stated tolerance; use float64 for accumulation. NumPy's sum adds in pairs, which is more accurate than a naive left-to-right loop.
COMMON MISTAKE 10: object arrays from ragged data
Wrong: np.array([[1, 2], [3]]). Symptom: a ValueError about an inhomogeneous shape in NumPy 1.24 and later (older versions silently built a slow object array). Fix: pad to a common length (np.pad or NaN), or keep a list of arrays when lengths really differ.
