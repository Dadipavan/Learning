Problem 16.8.1 Sort, rank, and find the three best students without sorting everything.

Ideaargsort returns positions, which you then use to reorder other arrays that must stay aligned with the scores. argpartition finds the top k in linear time when you do not need a full sort.
import numpy as np names = np.array(["Asha", "Ben", "Chen", "Dana", "Eli"]) score = np.array([72, 95, 88, 95, 60]) order = np.argsort(score) print(order, names[order]) desc = np.argsort(-score, kind="stable") print(names[desc]) top3 = np.argpartition(-score, 3)[:3] print(sorted(top3.tolist()), names[top3[np.argsort(-score[top3])]]) ranks = np.empty_like(order) ranks[order] = np.arange(len(score)) print(ranks) sorted_scores = np.sort(score) print(np.searchsorted(sorted_scores, [60, 90, 100]))

Line by line.

  1. argsort returns [4 0 2 1 3]: position 4 (score 60) is smallest. Indexing the names with it sorts them in the same order, keeping names and scores aligned.
  2. Negating the scores sorts high to low. kind="stable" keeps tied items (Ben and Dana, both 95) in their original order, so Ben comes before Dana.
  3. Ranks: assigning ranks[order] = 0..n-1 inverts the permutation. Asha (72) is the second lowest, rank 1.
  4. searchsorted says where each value would be inserted into the sorted array: 60 at 0, 90 at 3, 100 at 5.

Problem 16.8.2 Count, group and bin with unique, bincount, digitize and where.

Ideareturn_counts gives a frequency table; return_inverse gives integer codes; digitize turns numbers into bin numbers; np.select labels them.
import numpy as np city = np.array(["Pune", "Oslo", "Pune", "Lima", "Oslo", "Pune"]) vals, counts = np.unique(city, return_counts=True) print(vals, counts) vals, codes = np.unique(city, return_inverse=True) print(codes) print(np.bincount(codes)) spend = np.array([0.0, 4.5, 12.0, 25.0, 99.0, 7.0]) bins = np.array([5, 20]) idx = np.digitize(spend, bins) print(idx) label = np.select([spend < 5, spend < 20], ["low", "mid"], default="high") print(label) print(np.where(spend > 10, "big", "small")) print(np.isin(city, ["Lima", "Oslo"]))

Line by line.

  1. With return_inverse each original city becomes its index in the distinct list (Lima 0, Oslo 1, Pune 2), so city becomes [2 1 2 0 1 2].
  2. digitize(spend, [5, 20]) returns 0 for values below 5, 1 for 5 up to (not including) 20, and 2 for 20 or more.
  3. np.select tests the conditions in order, and the first True wins; anything else gets the default high. Note that 4.5 is low, 7.0 is mid.
  4. Three-argument where is a vectorised if/else and works on strings too. isin gives a mask for membership.

NaN handling

NaN (Not a Number) is how a float array stores a missing or undefined value. Its two key properties surprise people: NaN is not equal to anything, even itself, and any arithmetic with NaN gives NaN. Integer arrays cannot hold NaN; a column with gaps must be float.

Problem 16.8.3 Compute honest statistics on a series with gaps, and fill the gaps three ways.

IdeaPlain mean poisons the answer; nanmean skips NaN. To fill, build a mask first, then choose a fill rule.
import numpy as np x = np.array([4.0, np.nan, 6.0, 10.0, np.nan]) print(np.nan == np.nan, np.isnan(x)) print(x.mean(), np.nanmean(x), np.nanstd(x)) print(np.nanmax(x), np.nanargmax(x)) mask = np.isnan(x) filled_mean = np.where(mask, np.nanmean(x), x) print(filled_mean) print(np.nan_to_num(x, nan=-1.0)) idx = np.arange(len(x)) interp = x.copy() interp[mask] = np.interp(idx[mask], idx[~mask], x[~mask]) print(interp) print(np.count_nonzero(mask), mask.mean())

Line by line.

  1. np.nan == np.nan is False. Use np.isnan to detect missing values; x == np.nan never finds anything.
  2. x.mean() is nan because one missing value poisons the sum. nanmean averages the three present values: (4+6+10)/3 = 6.667. nanstd likewise ignores the gaps.
  3. Linear interpolation: np.interp(positions_to_fill, known_positions, known_values). The gap at index 1 lands between 4 and 6, so 5. The gap at index 4 is beyond the last known point, so interp holds the last value, 10.
  4. Finally, we count the missing: two of five, a proportion of 0.4.
COMMON MISTAKE
Wrong: x[x == np.nan] = 0. Symptom: nothing is replaced, no error. Fix: x[np.isnan(x)] = 0. A related trap: np.sort puts NaN at the end, and np.max returns NaN if any value is NaN, so use nanmax when you want to ignore gaps.

Problem 16.9.1 Multiply matrices, solve a small system, and compare solve with the inverse. Two shops sell coffee and tea: 2 coffees plus 1 tea cost 7, and 1 coffee plus 3 teas cost 11. Find the prices.

SetupA = [[2, 1], [1, 3]], b = [7, 11], unknown x = [coffee, tea].
By handFrom the first equation tea = 7 - 2 coffee. Then coffee + 3(7 - 2 coffee) = 11, so 21 - 5 coffee = 11, coffee = 2, tea = 3.
import numpy as np A = np.array([[2.0, 1.0], [1.0, 3.0]]) b = np.array([7.0, 11.0]) x = np.linalg.solve(A, b) print(x) print(np.allclose(A @ x, b)) print(np.linalg.det(A), np.linalg.matrix_rank(A)) Ainv = np.linalg.inv(A) print(np.round(A @ Ainv, 10)) B = np.array([[0.0, 1.0], [1.0, 0.0]]) print(A @ B) print(A * B) print(np.linalg.norm([3, 4]), np.trace(A))

Line by line.

  1. solve(A, b) returns [2. 3.], matching the hand calculation: coffee 2, tea 3.
  2. Always verify by multiplying back: A @ x equals b up to float tolerance, so allclose is True.
  3. A @ B is the matrix product (here B swaps the columns of A). A * B is the element-wise product, a different thing.
  4. norm([3, 4]) is the length of the vector, 5. The trace is 2 + 3 = 5.
COMMON MISTAKE
Wrong: x = np.linalg.inv(A) @ b to solve a system, or np.linalg.inv on a nearly singular matrix. Symptom: slower, less accurate answers, or huge garbage numbers without an error. Fix: np.linalg.solve(A, b), and check np.linalg.cond(A): very large values (around 1e10 and above) mean results are unreliable. If the matrix is exactly singular, inv raises LinAlgError.

16.10 Random Numbers: Generator and Seeds

Modern NumPy uses a Generator: an object that produces random numbers from a seeded stream. Create it once with rng = np.random.default_rng(seed) and call methods on it. The old global functions (np.random.seed, np.random.rand) still work but are legacy; the Generator is the recommended API because it is faster, has better statistical quality, and avoids hidden global state.

Problem 16.10.1 Show that the same seed repeats, different seeds differ, and the main draws work. Simulate 10 dice rolls and a weighted choice.

IdeaA generator remembers its position in the stream. A new generator with the same seed starts again from the beginning.
import numpy as np r1 = np.random.default_rng(42) r2 = np.random.default_rng(42) print(r1.random(3), r2.random(3)) print(np.array_equal(np.random.default_rng(1).random(5), np.random.default_rng(2).random(5))) rng = np.random.default_rng(0) rolls = rng.integers(1, 7, size=10) print(rolls, rolls.min() >= 1, rolls.max() <= 6) print(rng.choice(["red", "green", "blue"], size=8, p=[0.6, 0.3, 0.1])) print(rng.choice(10, size=4, replace=False)) z = rng.normal(100, 15, size=100000) print(round(float(z.mean()), 1), round(float(z.std()), 1))

Line by line.

  1. Two generators made from seed 42 give identical numbers, so r1.random(3) and r2.random(3) print the same three values. This is what makes experiments reproducible.
  2. integers(1, 7, size=10) gives dice rolls: the upper limit 7 is excluded. The two checks confirm the range.
  3. choice with p draws with weights: mostly red. Probabilities must sum to 1.
  4. One hundred thousand draws from a normal with mean 100 and standard deviation 15 land very close to those values (100.0 and 15.0 after rounding).
COMMON MISTAKE
Wrong: creating a new generator inside a function that you call in a loop, such as np.random.default_rng(0).normal() on each iteration. Symptom: every call returns exactly the same number, so your "simulation" has no randomness. Fix: create rng once, outside the loop, and pass it into your functions as an argument. For parallel workers, give each its own child from rng.spawn(n), never the same seed.

16.11 einsum: Index Notation for Array Algebra

np.einsum writes a calculation as a recipe of axis letters. Letters that appear in the inputs but not after the arrow -> are summed over; letters that appear after the arrow stay. Once you can read it, many tangled reshape, transpose and sum chains become one line.

RecipeMeaningSame as
"i,i->"Multiply matching items and add: dot productnp.dot(u, v)
"i,j->ij"Every pair product: outer productnp.outer(u, v)
"ij->ji"Swap axes: transposeA.T
"ij->"Add everythingA.sum()
"ij->i"Sum over j: row sumsA.sum(axis=1)
"ii->"Diagonal summed: tracenp.trace(A)
"ij,jk->ik"Matrix productA @ B
"bij,bjk->bik"A batch of matrix productsnp.matmul
"ij,ij->i"Row-by-row dot products(A * B).sum(axis=1)

Problem 16.11.1 Check each recipe against the plain NumPy equivalent, then do a batch of matrix products and a row-wise dot product.

RuleSame letter on two inputs means those axes are matched. Missing from the output means summed.
import numpy as np rng = np.random.default_rng(0) A = rng.integers(0, 5, (3, 4)) B = rng.integers(0, 5, (4, 2)) u = np.array([1, 2, 3]) v = np.array([4, 5, 6]) print(np.einsum("i,i->", u, v), u @ v) print(np.array_equal(np.einsum("ij,jk->ik", A, B), A @ B)) print(np.array_equal(np.einsum("ij->i", A), A.sum(axis=1))) print(np.einsum("i,j->ij", u, v)) batch = rng.integers(0, 3, (5, 2, 3)) other = rng.integers(0, 3, (5, 3, 4)) print(np.einsum("bij,bjk->bik", batch, other).shape) P = rng.random((4, 3)) Q = rng.random((4, 3)) print(np.allclose(np.einsum("ij,ij->i", P, Q), (P * Q).sum(axis=1)))

Line by line.

  1. "i,i->" matches the two vectors item by item and sums: 4 + 10 + 18 = 32. The empty output means a single number.
  2. "ij,jk->ik": the shared letter j is summed, which is exactly the matrix product. The check prints True.
  3. "i,j->ij" has no shared letter, so nothing is summed and every pair multiplies: the 3 by 3 outer product.
  4. With a leading batch letter b kept in the output, five independent (2, 3) by (3, 4) products give shape (5, 2, 4).
INTUITION
Read einsum as "for every combination of the letters on the right-hand side, add up the product of the inputs over the remaining letters". For attention scores in a transformer, "bhqd,bhkd->bhqk" is just that: for each batch and head, dot every query with every key.
