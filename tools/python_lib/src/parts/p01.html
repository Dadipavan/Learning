It is Monday morning and a retail team hands you a file: three million sales lines, each with a price, a quantity and a store number. They want every price turned into a z-score within its store, the ten biggest baskets flagged, and the distance between every pair of stores computed from their coordinates. You write a for loop, press run, and go to make tea. The tea is cold before the loop finishes. A colleague rewrites the same logic in six lines of NumPy and it finishes while the kettle is still boiling.

That gap is not magic. It is the difference between asking Python to do one tiny thing three million times and asking compiled code to do one big thing once. NumPy makes the second way possible, and pandas, SciPy, scikit-learn, PyTorch and matplotlib are all built on its array.

By the end of this chapter you will create arrays of any shape, select exactly the elements you want, broadcast, summarise along any axis, do linear algebra, use reproducible random numbers, avoid view and copy traps, and solve everyday tasks without loops. Everything printed here ran on Python 3.14 and NumPy 2.5.3. Timings were measured on one laptop and will differ on yours.

16.1 What NumPy Is, When to Use It, and the Mental Model

INTUITION
A Python list is a shopping bag of separate boxes: each item is its own object with its own label. A NumPy array is an egg carton: every slot has the same size and type, they sit side by side in one block, and so the library can scan the whole carton in a single sweep. Same-type, side-by-side, one block: that is the whole secret of its speed.

What it is

NumPy (Numerical Python) gives you one main object, the ndarray (n-dimensional array): a grid of numbers that all share one dtype (data type), stored in one flat block of memory. Around that object it provides thousands of fast functions that work on whole arrays at once. Working on a whole array at once, with no Python loop, is called vectorisation.

When to use it, and when not to

Use NumPy whenThink twice when
You have numbers (or booleans) in bulk and want maths on all of themYour data is mixed text, dates and numbers in named columns: use pandas (the next chapter of this Handbook), which sits on top of NumPy
You need matrices, linear algebra, random numbers, image pixelsYou have a handful of values: a plain list is fine and simpler
You want to replace a loop over rows with one expressionEach step depends on the previous one (a recursion): a loop, or a tool such as Numba, may be the right answer
You feed numbers to scikit-learn, SciPy, PyTorchData is bigger than memory: use chunking, Dask, or a database (see the Data Engineering document)
You need a fixed-size table of one typeYou need to append one item at a time millions of times: collect in a list, convert once

Install, version check and import convention

Install with pip install numpy (inside a virtual environment, see Chapter 9). The universal import is import numpy as np. Never use from numpy import *: it overwrites Python names such as sum, min, max and abs with different functions and causes bugs that are very hard to see.

Problem 16.1.1 Check which NumPy you have, and see the speed difference between a list and an array on a tiny sum of squares.

IdeaPrint np.__version__. Then compute the same sum of squares with a list comprehension and with one array expression, and confirm they agree.
import numpy as np print("major version:", np.__version__.split(".")[0]) values = [1.5, 2.0, 3.5, 4.0] as_list = sum(v * v for v in values) arr = np.array(values) as_array = (arr * arr).sum() print(as_list, as_array, as_list == as_array) print(type(arr), arr.dtype, arr.shape)

Line by line.

  1. The version string looks like 2.5.3. Splitting on dots and taking the first part tells you the major version, which is 2 here.
  2. arr * arr multiplies all four pairs in one step; .sum() adds them. Both ways give 34.5.
  3. The last line shows the three facts every array carries: its type (numpy.ndarray), its dtype (float64) and its shape ((4,), a one-dimensional array of four items).

The mental model

How to read it: the six boxes are the real data, side by side in memory, four bytes each (int32). The header holds instructions: shape says "show this as 2 rows and 3 columns"; strides say how many bytes to jump to the next row (12) or column (4). Because the header is separate from the data, NumPy can show the same bytes in another shape, order or slice without copying.

KEY IDEA
An array = one buffer of same-type numbers + a header (dtype, shape, strides). Reshaping, transposing and slicing usually change only the header. Arithmetic, sorting and fancy indexing create new buffers.

Problem 16.2.1 Inspect an array, change its dtype, and see how much memory it uses.

IdeaCreate a 1000 by 1000 float64 array, read its attributes, then convert to float32 and uint8 and compare nbytes.
import numpy as np a = np.zeros((1000, 1000)) print(a.shape, a.ndim, a.size, a.dtype) print(a.itemsize, a.nbytes, a.strides) b = a.astype(np.float32) c = a.astype(np.uint8) print(a.nbytes, b.nbytes, c.nbytes) print(np.array([1, 2, 3]).dtype, np.array([1, 2.5]).dtype, np.array([1, "a"]).dtype)

Line by line.

  1. Each float64 takes 8 bytes, so the buffer is 8,000,000 bytes (8 MB). Strides (8000, 8): to go down one row, jump 1000 items of 8 bytes; to go right, jump 8.
  2. astype returns new arrays. float32 halves memory to 4 MB, uint8 cuts it to 1 MB.
  3. The last line shows type promotion on creation: all ints give int64; a mix of int and float becomes float64; a mix with text becomes a string dtype (<U21), which is rarely what you want.
COMMON MISTAKE
Wrong: np.array([200, 100], dtype=np.uint8) + np.array([100, 100], dtype=np.uint8) and trusting the answer. Symptom: you get [44 200], because 300 does not fit in 0..255 and silently wraps around. Fix: convert before arithmetic: a.astype(np.int32) + b. Integer overflow in NumPy arrays gives no warning.

Memory layout: C order and F order

A 2D array must be flattened into one line of memory. C order (row-major, the default) stores row 0 first, then row 1. Fortran order (column-major) stores column 0 first. It matters because walking along memory is fast and jumping around is slow, and because some libraries expect one order.

How to read it: the left grid counts 0,1,2 along the first row and then 3,4,5 along the second, so moving right is a step of one slot (4 bytes) and moving down jumps three slots (12 bytes). The right grid counts down each column first, so the two step sizes swap. Same table of values, two different physical orders.

Problem 16.2.2 Show that a transpose copies nothing, only swaps the strides, and that a non-contiguous array can be made contiguous.

IdeaMake a 2 by 3 int32 array, transpose it, compare strides and flags, then call np.ascontiguousarray.
import numpy as np a = np.arange(6, dtype=np.int32).reshape(2, 3) t = a.T print(a.strides, t.strides) print(a.flags["C_CONTIGUOUS"], t.flags["C_CONTIGUOUS"], t.flags["F_CONTIGUOUS"]) print(t.base is a, np.shares_memory(a, t)) c = np.ascontiguousarray(t) print(c.strides, np.shares_memory(a, c)) print(t.ravel(), t.ravel(order="K"))

Line by line.

  1. Original strides are (12, 4) as in the figure. The transpose has (4, 12): the same bytes, read with the step sizes swapped.
  2. The transpose is no longer C-contiguous but is F-contiguous, because reading it column by column walks memory in order.
  3. ascontiguousarray really copies, giving strides (8, 4) for the new 3 by 2 shape, and it no longer shares memory.
  4. ravel() flattens in logical (row-by-row) order, so the transposed array gives [0 3 1 4 2 5]. order="K" means "whatever order is in memory", giving [0 1 2 3 4 5].
WHY IT MATTERS
Walking memory in order is friendly to the CPU cache, so a reduction along a strided axis can be slower (it depends on shape and machine). When a function is slow on a transposed or sliced array, check flags and consider np.ascontiguousarray.
