20.8 HTML parsing with BeautifulSoup, and scraping ethics

When a page has no API, its facts are inside HTML tags. BeautifulSoup (package beautifulsoup4) turns HTML text into a tree you can search. It does not download pages (that is requests) and it does not run JavaScript. Always give it the "html.parser" argument (built into Python); lxml and html5lib are optional faster or more forgiving parsers, and neither was installed on the study machine.

Example 1: find things

from bs4 import BeautifulSoup
from urllib.parse import urljoin

page = """
Price list

Widgets


Updated today. Prices in USD.

About Partner no link

"""
soup = BeautifulSoup(page, "html.parser")
print(soup.title.string, "|", soup.find("h1").get_text(strip=True), soup.find("h1")["id"])
print(soup.select_one("p.intro").get_text(" ", strip=True))
for a in soup.find_all("a"):
    print(a.get("href"), "->", urljoin("https://shop.example/list/", a.get("href") or ""))
print(soup.find("table"), soup.find_all("table"))
@@
  1. The inline string is the whole "web page". soup.title.string reads the title; find("h1")["id"] reads an attribute; select_one("p.intro") uses a CSS selector, and get_text(" ", strip=True) joins the text pieces Updated, today and . Prices in USD. with spaces.
  2. The third anchor has no href: .get returns None (["href"] would raise KeyError). urljoin resolves /about against the page address and leaves a full URL unchanged.
  3. There is no table: find returns None and find_all returns []. A method call on that None is the classic scraping crash.

Example 2: robots.txt and defensive extraction

from urllib.robotparser import RobotFileParser
from bs4 import BeautifulSoup

robots = """
User-agent: *
Disallow: /private/
Crawl-delay: 5

User-agent: BadBot
Disallow: /
"""
rp = RobotFileParser()
rp.parse(robots.splitlines())
for agent, url in [("my-study-bot", "https://shop.example/list"),
                   ("my-study-bot", "https://shop.example/private/data"),
                   ("BadBot", "https://shop.example/list")]:
    print(agent, url.split(".example")[1], rp.can_fetch(agent, url))
print("crawl delay:", rp.crawl_delay("my-study-bot"))

def text_or_none(soup, css):
    tag = soup.select_one(css)
    return tag.get_text(strip=True) if tag else None

soup = BeautifulSoup("
9.99
", "html.parser")
print(text_or_none(soup, "span.price"), text_or_none(soup, "span.discount"))
@@
  1. robots.txt is a public file where a site owner says which paths automated clients may visit. Here every agent is kept out of /private/ and asked to wait 5 seconds, and BadBot is shut out completely. In real use call rp.set_url(...) and rp.read().
  2. can_fetch(agent, url) answers per user-agent; crawl_delay returns 5, which your loop should honour with time.sleep.
  3. text_or_none turns a missing element into None instead of a crash. Real pages change; this helper prevents most overnight failures.
REAL JOB
Scraping ethics and law, in practice. (1) Look for an API, a data download or a licence first. (2) Read robots.txt and the site's terms of use; robots.txt is a convention, not a security lock, but ignoring it is poor practice and can be a terms breach. (3) Identify yourself with an honest User-Agent that includes contact details. (4) Slow down: one request per few seconds, honour Crawl-delay and 429, cache pages you already have. (5) Do not collect personal data without a lawful reason, and do not republish copyrighted content. (6) Do not bypass logins, paywalls or captchas. This is general guidance, not legal advice; ask your legal team for commercial projects.

20.9 Validating data: dataclasses and pydantic

Data from outside is guilty until proven innocent. An API can send "total": "N/A", a CSV can have a negative age, a scraped price can be empty. Validation means checking each record against a schema (names, types, ranges, allowed values) at the door, so errors are caught with a clear message instead of ten steps later as a mysterious NaN. pydantic is the standard library for this. It was not installed here, so its code is labelled "not run" and each concept is paired with a runnable dataclass or plain-Python version.

pydantic in practice (not run here)

# NOT RUN HERE: pydantic is not installed on the study machine (pip install pydantic)
from datetime import date
from typing import Literal
from pydantic import BaseModel, ConfigDict, Field, TypeAdapter, ValidationError, field_validator

class Order(BaseModel):
    model_config = ConfigDict(extra="forbid")
    id: int
    customer: str = Field(min_length=1)
    total: float = Field(ge=0)
    status: Literal["new", "paid", "shipped"] = "new"
    placed: date

    @field_validator("customer")
    @classmethod
    def clean_name(cls, v: str) -> str:
        return v.strip()

good = Order.model_validate({"id": "7", "customer": " Ana ", "total": "12.5", "placed": "2025-03-01"})
print(good.model_dump())      # id is the int 7, customer "Ana", placed a date object

try:
    Order.model_validate({"id": "x", "customer": "", "total": -1, "placed": "tomorrow"})
except ValidationError as e:
    for err in e.errors():     # one entry per bad field: err["loc"], err["msg"]
        print(err["loc"], err["msg"])

orders = TypeAdapter(list[Order]).validate_python(list_of_dicts)
  1. The class body lists typed fields. pydantic converts compatible input ("7" to 7, "2025-03-01" to a date) and rejects the rest; strict=True disables conversion.
  2. Field(min_length=1) and Field(ge=0) add limits, Literal restricts status, and a default makes it optional. extra="forbid" turns an unexpected key into an error.
  3. The second record has four bad fields, and pydantic reports all four in one ValidationError. TypeAdapter validates a whole page of API results in one call.

Example 1: a runnable dataclass validator

from dataclasses import dataclass, field, asdict
from datetime import date

@dataclass
class Order:
    id: int
    customer: str
    total: float
    placed: date
    status: str = "new"
    tags: list = field(default_factory=list)

    def __post_init__(self):
        self.id = int(self.id)
        self.total = float(self.total)
        self.customer = self.customer.strip()
        if isinstance(self.placed, str):
            self.placed = date.fromisoformat(self.placed)
        if not self.customer:
            raise ValueError("customer must not be empty")
        if self.total < 0:
            raise ValueError(f"total must be >= 0, got {self.total}")
        if self.status not in {"new", "paid", "shipped"}:
            raise ValueError(f"bad status {self.status!r}")

ok = Order("7", " Ana ", "12.5", "2025-03-01")
print(ok)
print(asdict(ok)["total"], type(ok.id).__name__)
for bad in [dict(id=1, customer="Bo", total=-5, placed="2025-03-02"),
            dict(id="x", customer="Cy", total=1, placed="2025-03-02"),
            dict(id=2, customer="Di", total=3, placed="tomorrow")]:
    try:
        Order(**bad)
    except ValueError as e:
        print("rejected:", e)
@@
  1. A dataclass writes __init__ and __repr__. field(default_factory=list) gives each object its own list. __post_init__ runs after __init__: we convert types first, then check rules.
  2. The first record is accepted, with converted values. The three bad ones fail for three reasons (negative total, an id that is not an integer, a date that is not ISO format). All are ValueError, so one except catches them.
  3. Compared with pydantic you write the conversions yourself and stop at the first error. Recipe 3 (20.12) collects every error and sets rejects aside.

Example 2: validate a whole DataFrame

import numpy as np
import pandas as pd

def check_frame(df):
    problems = []
    required = {"id": "int", "total": "float", "region": "str"}
    for col, kind in required.items():
        if col not in df.columns:
            problems.append(f"missing column {col}")
        elif kind == "int" and not pd.api.types.is_integer_dtype(df[col]):
            problems.append(f"{col} should be integer, is {df[col].dtype}")
        elif kind == "float" and not pd.api.types.is_float_dtype(df[col]):
            problems.append(f"{col} should be float, is {df[col].dtype}")
    if "id" in df and df["id"].duplicated().any():
        problems.append(f"duplicate ids: {df.loc[df['id'].duplicated(), 'id'].tolist()}")
    if "total" in df:
        if df["total"].isna().any():
            problems.append(f"{int(df['total'].isna().sum())} missing totals")
        if (df["total"] < 0).any():
            problems.append("negative totals")
    return problems

good = pd.DataFrame({"id": [1, 2], "total": [5.0, 6.5], "region": ["n", "s"]})
bad = pd.DataFrame({"id": [1, 1, 3], "total": [5.0, np.nan, -2.0], "region": ["n", "s", "e"]})
print(check_frame(good))
print(check_frame(bad))
print(check_frame(bad.drop(columns="region").astype({"id": "float64"})))
@@
  1. The function returns a list of problems instead of raising, so a pipeline can warn, drop rows or stop.
  2. Column existence and dtype use pandas.api.types, which also recognises pandas 3 nullable and string types. duplicated() flags repeated ids; NaN < 0 is false, so missing values need their own check.
  3. The good frame gives []; the second gives three problems; the third (region dropped, id as float) adds the dtype and missing-column messages, and its duplicate id shows as 1.0.
KEY IDEA
Validate at the boundary, once. Convert text to real types, check ranges and keys, and send rejects to a dead-letter file with the reason. Everything downstream may then assume clean data. Libraries such as pydantic (records) and pandera or Great Expectations (tables) do the same job with more features.
