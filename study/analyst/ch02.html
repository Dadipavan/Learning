Most business data still lives in Excel files, and most analyst interviews start with an Excel test. The test is rarely hard. It checks whether you can find a value in another table, count rows that meet two conditions, clean a messy text column, and build a monthly summary without copying and pasting. In this chapter you learn the formulas that do those jobs, and you learn them with a small sales table whose answers we check by hand (and by pandas) so you can trust every result. By the end you will write formulas confidently, read other people's formulas, and know which modern function replaces which old one.

PROFESSOR'S NOTE
Excel cannot run inside this book's environment. Every formula below uses standard syntax, and every result was verified by hand or with pandas on the same small table. Function names and availability change by version: XLOOKUP, FILTER, LET and friends need Microsoft 365 or Excel 2021 or later. TEXTSPLIT, TAKE, DROP, VSTACK and HSTACK need a newer 365 build. Google Sheets has similar but not identical functions. If a formula shows #NAME?, your version lacks it.

2.1 Tables, References and Shortcuts

INTUITION
A plain range of cells is like loose papers on a desk. An Excel Table (Ctrl+T) is a labelled folder: it knows its own column names, grows when you add a row, and carries formulas down automatically. Loose papers break the moment you add one more.

Formal definitions

TermMeaningExample
Cell referenceAddress of a cellF2
Relative referenceShifts when copied=E2*F2 copied down becomes =E3*F3
Absolute referenceFixed with $, does not shift=$J$1*H2 always points to J1
Mixed referenceOne part fixed=$A2 or =B$1
Named rangeA nickname for a rangeTaxRate for $J$1
TableRange with a name and column namesSales
Structured referenceColumn name inside a TableSales[Qty], [@Qty] (this row)

How to build the table. Click any cell in the data, press Ctrl+T, tick "My table has headers". In Table Design set the name to Sales. In H2 type =[@Qty]*[@Price]. Excel fills the whole column.

Worked example 2.1.1 Add a tax column using an absolute reference. Put the tax rate 18% in J1 and name it TaxRate.

  • Formula Tax = Amount × TaxRate
  • Plug in In I2 type =H2*$J$1 (or =H2*TaxRate), then fill down.
  • Compute Row 2: 998 × 0.18 = 179.64. Row 3: 1299 × 0.18 = 233.82.
  • Answer I2 shows 179.64 and I3 shows 233.82.
  • Check Without $, filling down makes I3 become =H3*J2, which points at an empty cell and returns 0. That tells you the $ is needed.
  • Why it matters Changing J1 once updates every row. That is how models stay flexible.

Worked example 2.1.2 The same formula with a Table and structured references.

  • Step 1 Make Sales a Table.
  • Step 2 In a new column named Tax type =[@Amount]*TaxRate.
  • Step 3 Add a new row at the bottom of the Table.
  • Answer The formula fills itself for the new row. A total anywhere can be =SUM(Sales[Amount]), and it always covers every row, including future ones. For our data it returns 9,340 (998 + 1299 + 597 + 799 + 450 + 1298 + 2499 + 1400).
  • Check Add by hand in steps: 998 + 1299 = 2297; + 597 = 2894; + 799 = 3693; + 450 = 4143; + 1298 = 5441; + 2499 = 7940; + 1400 = 9340. It matches the formula. (Section 2.3 uses the Delivered-only total, 8,293.)
  • Why it matters Always do the sanity add. Trusting a number you never checked is how reports go wrong.

The picture

 Range:  =SUM(H2:H9)         <- break if you add row 10
 Table:  =SUM(Sales[Amount]) <- grows with the data

Connection to the real job. Tables are the foundation for PivotTables and Power Query (Chapter 3), and structured references read like English in code review.

Applications

  • Analytics: monthly reports that gain rows every month.
  • Finance: models with one input cell (named range) that drives hundreds of formulas.
  • Operations: trackers where rows are added daily.
COMMON MISTAKE
Forgetting $ when a formula points at a constant (tax rate, exchange rate). Fill down and the reference drifts. Press F4 while the cursor is in the reference.

Check yourself

  1. What does $J$1 mean? Answer: Column J and row 1 are both fixed, so copying does not move the reference.
  2. What is [@Qty]? Answer: The Qty value in the current row of the Table.
  3. Why prefer SUM(Sales[Amount]) over SUM(H2:H9)? Answer: It grows automatically when rows are added.

2.2 Logical and Lookup Functions

INTUITION
Logic functions are the "if this then that" of a spreadsheet. Lookup functions are the phone book: give a name, get a number. Together they let one table borrow facts from another, so you never retype data.

Logical functions

FunctionSyntaxMeaning
IF=IF(test, if_true, if_false)One decision
IFS=IFS(test1, v1, test2, v2, ..., TRUE, default)Several decisions in order
AND, OR, NOT=AND(a, b)Combine tests
IFERROR=IFERROR(value, if_error)Replace an error
SWITCH=SWITCH(expr, v1, r1, v2, r2, default)Match one value to many results

Worked example 2.2.1 Label each order: Big if Amount is above 1000, Medium if 500 to 1000, else Small.

  • Formula =IFS(H2>1000,"Big", H2>=500,"Medium", TRUE,"Small")
  • Plug in Row 2: H2 = 998. First test 998 > 1000 is FALSE. Second test 998 >= 500 is TRUE.
  • Compute Row 2 gives Medium. Row 3 (1299) gives Big. Row 5 (450) falls through to TRUE and gives Small.
  • Answer The labels for rows 2 to 9 are Medium, Big, Medium, Medium, Small, Big, Big, Big.
  • Check Amounts 998, 1299, 597, 799, 450, 1298, 2499, 1400. Above 1000: 1299, 1298, 2499, 1400 (four Big). 450 is below 500 (one Small). The other three are Medium. Matches.
  • Why it matters IFS tests in order, so order the conditions from most to least strict. The final TRUE is the catch-all. Without it, rows with no match give #N/A.

Worked example 2.2.2 Flag orders that need attention: Status is Returned OR Amount above 2000.

  • Formula =IF(OR(G2="Returned", H2>2000), "Review", "OK")
  • Compute Row 4 (1003) is Returned: Review. Row 8 (1007) has Amount 2499: Review. All others: OK.
  • Answer Two orders, 1003 and 1007, are flagged.
  • Check Scan the Status column: only one Returned. Scan Amount: only 2499 exceeds 2000.

Add a small table Tax in L1:M4:

L CategoryM Rate

Worked example 2.2.3 Look up the tax rate of each order's category.

  • Formula =XLOOKUP(D2, $L$2:$L$4, $M$2:$M$4, "Not found")
  • Plug in Row 2: D2 is Fashion. Find Fashion in L2:L4. It is in position 1.
  • Compute Return the 1st value of M2:M4, which is 12%.
  • Answer Row 2 gets 12%. Row 3 (Electronics) gets 18%. Row 4 (Grocery) gets 5%.
  • Check Same with the old way: =VLOOKUP(D2,$L$2:$M$4,2,FALSE) returns 12%. And =INDEX($M$2:$M$4,MATCH(D2,$L$2:$L$4,0)) also returns 12%. All three agree.
  • Why it matters The FALSE (exact match) in VLOOKUP is vital. Leave it out and Excel does an approximate match that silently returns wrong values on unsorted data.

Approximate match (bands). Sometimes you want "which band does this value fall into?". Put the band starts in sorted order: P2:P4 = 0, 500, 1000 and labels Q2:Q4 = Small, Medium, Big.

Worked example 2.2.4 Find the band for an amount of 998.

  • Formula =XLOOKUP(998, P2:P4, Q2:Q4, , -1) (match mode -1 means "exact or next smaller")
  • Plug in 998 is not in the list. The next smaller value is 500.
  • Compute 500 is in position 2, so return Medium.
  • Answer Medium.
  • Check =VLOOKUP(998,P2:Q4,2,TRUE) also gives Medium. For 1299 both give Big (next smaller is 1000).
  • Why it matters Bands are used for age groups, tax slabs and discount tiers.

Protect against missing keys. =IFERROR(XLOOKUP(...), 0) hides every error, including real bugs. Prefer the built-in fourth argument of XLOOKUP ("Not found"), which only covers a missing key.

The picture

 Orders (D)         Tax (L:M)

                   Grocery       5%

Connection to the real job. In SQL this is a JOIN. In pandas it is merge (Chapter 5). In Power BI it is a relationship (Chapter 9). Excel lookup is where most analysts first meet the idea of joining tables.

Applications

  • Finance: map account codes to account names.
  • HR: map employee ID to department.
  • Retail: map product ID to price or category.
  • Operations: map SKU to supplier.
COMMON MISTAKE
Duplicate keys in the lookup table. Lookup returns the first match and ignores the rest, so a duplicate Fashion row with a different rate gives a silent wrong answer. Check uniqueness with =COUNTIF(L:L, L2) or =UNIQUE.

Check yourself

  1. Which has a final catch-all in IFS? Answer: A test of TRUE.
  2. What is the problem with VLOOKUP without the fourth argument? Answer: It defaults to approximate match and may return wrong values.
  3. What does match mode -1 do in XLOOKUP? Answer: Exact match, else the next smaller item.

2.3 Math and Statistical Functions

INTUITION
A PivotTable (Chapter 3) answers many questions at once. These functions answer exactly one question, in one cell, and you control where it appears. Use them inside reports with a fixed layout.

Core functions

FunctionSyntaxPlain meaning

COUNTIFS=COUNTIFS(range1, crit1, range2, crit2)Count rows meeting all conditions
AVERAGEIFS=AVERAGEIFS(avg_range, crit_range1, crit1, ...)Average with conditions
LARGE, SMALL=LARGE(range, k)k-th biggest or smallest
RANK.EQ=RANK.EQ(value, range, [0 desc])Position in a sort
SUMPRODUCT=SUMPRODUCT(array1, array2, ...)Multiply row by row, then add
MEDIAN, STDEV.S=MEDIAN(range)Middle value; sample standard deviation
PERCENTILE.INC=PERCENTILE.INC(range, k)k between 0 and 1
CORREL=CORREL(x, y)Correlation, from −1 to 1
FORECAST.LINEAR=FORECAST.LINEAR(x, known_y, known_x)Straight-line prediction
ROUND=ROUND(number, digits)Round half away from zero

In SUMIFS, the sum range comes first. In the older SUMIF it comes last. This difference trips many people.

Worked example 2.3.1 Total Delivered revenue.

  • Formula =SUMIFS(H2:H9, G2:G9, "Delivered")
  • Plug in Delivered rows: 998, 1299, 799, 1298, 2499, 1400.
  • Compute 998 + 1299 = 2297; + 799 = 3096; + 1298 = 4394; + 2499 = 6893; + 1400 = 8293.
  • Answer 8,293 rupees.
  • Check Total of all rows is 9,340. Remove Returned 597 and Cancelled 450: 9,340 − 1,047 = 8,293. Matches.

Worked example 2.3.2 Delivered revenue in Mumbai, and number of Delivered Mumbai orders.

  • Formula =SUMIFS(H2:H9, C2:C9, "Mumbai", G2:G9, "Delivered") and =COUNTIFS(C2:C9, "Mumbai", G2:G9, "Delivered")
  • Plug in Mumbai rows: 1002 (Delivered, 1299), 1005 (Cancelled, 450), 1006 (Delivered, 1298).
  • Compute Delivered only: 1299 + 1298 = 2597, and count = 2.
  • Answer Rs 2,597 from 2 orders.
  • Check Average order value = 2597 / 2 = 1298.5. The formula =AVERAGEIFS(H2:H9, C2:C9, "Mumbai", G2:G9, "Delivered") returns 1298.5.

Worked example 2.3.3 Weighted average price per unit with SUMPRODUCT.

  • Formula =SUMPRODUCT(E2:E9, F2:F9) / SUM(E2:E9)
  • Plug in Numerator = 998 + 1299 + 597 + 799 + 450 + 1298 + 2499 + 1400 = 9340. Quantities: 2 + 1 + 3 + 1 + 5 + 2 + 1 + 4 = 19.
  • Compute 9340 / 19 = 491.58 (rounded to 2 decimals).
  • Answer The average price per unit sold is Rs 491.58.
  • Check A plain AVERAGE(F2:F9) gives 798, which ignores how many units sold at each price and so is the wrong tool here.
  • Why it matters Whenever rows have different weights (quantity, users, hours), a simple average lies.

SUMPRODUCT also counts with conditions: =SUMPRODUCT((C2:C9="Pune")*(E2:E9)*(F2:F9)) equals Pune revenue 998 + 597 + 1400 = 2,995.

Worked example 2.3.4 Forecast the next day with FORECAST.LINEAR. Known days 1 to 5 had orders 10, 12, 15, 19, 21. Predict day 6.

  • Formula Fit y = a + b × x. b = Σ(x − x̄)(y − ȳ) / Σ(x − x̄)².
  • Plug in x̄ = 3, ȳ = 15.4. Σ(x − x̄)(y − ȳ) = (−2)(−5.4) + (−1)(−3.4) + 0 + (1)(3.6) + (2)(5.6) = 10.8 + 3.4 + 0 + 3.6 + 11.2 = 29. Σ(x − x̄)² = 4 + 1 + 0 + 1 + 4 = 10.
  • Compute b = 29 / 10 = 2.9. a = 15.4 − 2.9 × 3 = 6.7. Day 6: 6.7 + 2.9 × 6 = 24.1.
  • Answer =FORECAST.LINEAR(6, B2:B6, A2:A6) returns 24.1 orders.
  • Check numpy polyfit gives slope 2.9 and intercept 6.7.
  • Interpretation Orders grew about 2.9 per day. A straight line over five points is a rough guess; do not forecast months ahead from five points.

The picture

 SUMIFS( what to add , where to look , what to match )
            H2:H9       G2:G9        "Delivered"

Connection to the real job. These are the building blocks of KPI tables in finance and sales reports. In SQL, SUMIFS is SUM(...) WHERE ... GROUP BY. In pandas it is df.loc[mask].groupby(...).

Applications

  • Sales: revenue by region and month in a fixed report grid.
  • Finance: budget vs actual with SUMIFS by cost centre.
  • Operations: count of tickets meeting an SLA.
  • HR: average salary by grade.
COMMON MISTAKE
Criteria written as text with operators. For "greater than 1000" write ">1000" in quotes, and to reference a cell write ">"&K1. Forgetting the quotes or the & gives zero or errors.

Check yourself

  1. Which comes first in SUMIFS, the sum range or the criteria? Answer: The sum range.
  2. When is SUMPRODUCT better than AVERAGE? Answer: When rows have different weights.
  3. What does CORREL near −1 mean? Answer: When one rises, the other falls, almost in a straight line.

2.4 Text and Date Functions

INTUITION
Real data is messy: " pune", "PUNE", "Pune " are three different values to a computer. Text functions tidy them. Date functions turn "when" into numbers you can count, which is how you build months, deadlines and ages.

Worked example 2.4.1 Clean a city column that holds " pune", "MUMBAI " and "Delhi".

  • Formula =PROPER(TRIM(A2))
  • Plug in For " pune", TRIM removes the leading space giving "pune".
  • Compute PROPER("pune") gives Pune. For "MUMBAI ": TRIM gives "MUMBAI", PROPER gives Mumbai.
  • Answer All three become Pune, Mumbai, Delhi.
  • Check =LEN(A2) before is 5 for " pune" (5 characters including the space) and =LEN(PROPER(TRIM(A2))) after is 4.
  • Why it matters Without this, a lookup of "Pune" fails on "Pune ", and a PivotTable shows two rows for the same city.

Worked example 2.4.2 Extract the year and the serial number from the ID PUN-2025-0042, as a number.

  • Formula Year: =VALUE(MID(A2, FIND("-", A2)+1, 4)). Serial: =VALUE(RIGHT(A2, 4)).
  • Plug in FIND("-", A2) is 4, so MID(A2, 5, 4) is 2025.
  • Compute VALUE("2025") = 2025. RIGHT(A2, 4) = 0042, and VALUE("0042") = 42.
  • Answer Year 2025, serial 42.
  • Check Count positions: P(1) U(2) N(3) -(4) 2(5) 0(6) 2(7) 5(8). Characters 5 to 8 are 2025.

Date functions. Excel stores a date as a number: the count of days since 1 January 1900 (with a quirk for 1900 that you can ignore). So date + 7 is a week later. Format the cell as Date to see it.

Worked example 2.4.3 How many days and complete months between 15 January 2025 and 10 March 2025?

  • Compute (days) January 15 to January 31 is 16 days, February has 28 days (2025 is not a leap year), then 10 days into March: 16 + 28 + 10 = 54.
  • Compute (months) 15 Jan to 15 Mar would be 2 full months, but we stop on 10 March, five days short, so 1 complete month.
  • Answer =DATEDIF(DATE(2025,1,15),DATE(2025,3,10),"d") is 54 and with "m" it is 1. Also =DATE(2025,3,10)-DATE(2025,1,15) is 54.
  • Check Count: Jan 15 + 54 days: Jan 15 + 16 = Jan 31, + 28 = Feb 28, + 10 = Mar 10. Matches.

Worked example 2.4.4 Make a month key and weekday label for each order.

  • Formula Month key: =TEXT(B2, "yyyy-mm"). Weekday: =TEXT(B2, "ddd").
  • Compute Row 2: B2 is 3 Jan 2025. Month key 2025-01. Weekday Fri.
  • Answer All eight orders have month key 2025-01. Weekdays for rows 2 to 9: Fri, Fri, Sat, Sun, Mon, Tue, Thu, Fri.
  • Check 1 Jan 2025 was a Wednesday, so 3 Jan is Friday, 4 Sat, 5 Sun, 6 Mon, 7 Tue, 9 Thu, 10 Fri. Matches.
  • Why it matters Month keys let you group by month in a PivotTable or SUMIFS.

Connection to the real job. Cleaning text and dates is the first half of every analysis. The same steps in pandas are .str.strip().str.title() and pd.to_datetime (Chapter 5).

Applications

  • Customer data: standardise names, cities, emails.
  • Finance: month-end dates, due dates, ageing buckets.
  • HR: tenure in years and months.
  • Logistics: working days to deliver.
COMMON MISTAKE
Dates stored as text (left-aligned, from a CSV). =B2+1 fails or gives #VALUE!. Convert with =DATEVALUE(B2) or use Data > Text to Columns, or better, import with Power Query (Chapter 3).

Check yourself

  1. What does EOMONTH(DATE(2025,2,10), 0) return? Answer: 28 Feb 2025.
  2. Why does TRIM matter before a lookup? Answer: Extra spaces make two equal-looking values different.
  3. What is the number behind a date? Answer: The count of days since the start date (1 Jan 1900).

2.5 Dynamic Array Functions

INTUITION
The old way: one formula, one cell. To list the unique cities you needed a helper column and copying. The new way: one formula "spills" its answer into as many cells as needed. Change the data, and the spilled list resizes itself, like water filling a container.

How it works. A formula that returns many values writes them into neighbouring cells. The first cell holds the formula. The blue border shows the spill range. Refer to the whole spill with #, as in E2#. If a cell in the way is not empty, you get #SPILL!.

The functions

FunctionSyntaxDoes
FILTER=FILTER(array, include, [if_empty])Keep rows that meet a test
SORT=SORT(array, [sort_index], [order], [by_col])Sort (1 ascending, −1 descending)
SORTBY=SORTBY(array, by_array1, order1, ...)Sort by another column
UNIQUE=UNIQUE(array, [by_col], [exactly_once])Distinct values
SEQUENCE=SEQUENCE(rows, [cols], [start], [step])Number grid
LET=LET(name1, value1, ..., calculation)Name an intermediate result

Worked example 2.5.1 List the distinct categories and total Delivered revenue for each, without a PivotTable.

  • Formula In K2: =UNIQUE(D2:D9). In L2: =SUMIFS(H2:H9, D2:D9, K2#, G2:G9, "Delivered").
  • Plug in UNIQUE lists values in order of first appearance: Fashion, Electronics, Grocery. K2# is that whole list.
  • Compute Fashion Delivered: 998 + 799 + 1298 + 1400 = 4495. Electronics Delivered: 1299 + 2499 = 3798. Grocery Delivered: none (1003 Returned, 1005 Cancelled), so 0.
  • Answer The two spilled columns read Fashion 4495, Electronics 3798, Grocery 0.
  • Check 4495 + 3798 + 0 = 8293, equal to the Delivered total from Example 2.3.1.

Worked example 2.5.2 Show only Mumbai Delivered orders, sorted by Amount, highest first, top 1.

  • Formula =TAKE(SORTBY(FILTER(A2:H9, (C2:C9="Mumbai")*(G2:G9="Delivered")), FILTER(H2:H9, (C2:C9="Mumbai")*(G2:G9="Delivered")), -1), 1)
  • Plug in The test multiplies two TRUE/FALSE columns. TRUE × TRUE = 1 keeps a row. Matching rows: 1002 (1299) and 1006 (1298).
  • Compute Sorted high to low: 1002 first (1299), then 1006 (1298). TAKE(...,1) keeps the first.
  • Answer One row: 1002, 2025-01-03, Mumbai, Electronics, 1, 1299, Delivered, 1299.
  • Check * means AND and + means OR inside these tests. Row 1005 is Mumbai but Cancelled, so 0 × 1 = 0 and it is dropped.

Long formulas like this repeat the same FILTER. LET fixes that.

Worked example 2.5.3 The same logic with LET, to compute the average Delivered amount.

  • Formula =LET(d, FILTER(H2:H9, G2:G9="Delivered"), SUM(d)/COUNT(d))
  • Plug in d becomes the Delivered amounts: 998, 1299, 799, 1298, 2499, 1400 (six values).
  • Compute 8293 / 6 = 1382.17 (rounded).
  • Answer The average Delivered order is Rs 1,382.17.
  • Check =AVERAGEIFS(H2:H9, G2:G9, "Delivered") returns the same.

LAMBDA. Create a reusable function. In Formulas > Name Manager, add a name AfterTax with the definition =LAMBDA(x, r, x*(1+r)). Then =AfterTax(1000, 0.18) returns 1180 (1000 × 1.18). Use LAMBDA for logic you repeat across workbooks.

Connection to the real job. Dynamic arrays replace most helper columns and many PivotTables for small reports. They behave like SQL SELECT DISTINCT, WHERE, ORDER BY and LIMIT. If you know SQL (see the separate SQL document), you already know their logic.

Applications

  • Reporting: dropdown lists that update when new categories appear.
  • Dashboards: top-5 tables that refresh with data.
  • Finance: lists of overdue invoices using FILTER.
  • Data prep: VSTACK to append monthly sheets before analysis.
COMMON MISTAKE
Using AND(...) inside FILTER. AND returns a single TRUE or FALSE for the whole range. Use multiplication (a)*(b) for AND and addition (a)+(b) for OR to keep one answer per row.

Check yourself

  1. What does K2# mean? Answer: The full spill range that starts at K2.
  2. How do you write "City is Pune OR Delhi" inside FILTER? Answer: (C2:C9="Pune")+(C2:C9="Delhi").
  3. What causes #SPILL!? Answer: Something non-empty blocks the cells where the result wants to go.

2.6 Error Handling and Auditing

INTUITION
A broken formula that shows an error is a friendly alarm. A wrong formula that shows a believable number is the real danger. Auditing means looking inside to make sure the number is right for the right reason.

Common errors

ErrorMeaningTypical cause
#N/ANot availableLookup did not find the key
#VALUE!Wrong typeText where a number is needed
#REF!Bad referenceDeleted a row or column used by a formula
#DIV/0!Divide by zeroEmpty denominator
#NAME?Unknown nameTypo, or function not in your version
#SPILL!Spill blockedCells in the way
#NUM!Invalid numberImpossible maths, e.g. root of a negative

Information functions. =ISBLANK(A2) is TRUE for an empty cell. =ISERROR(A2) is TRUE for any error. =ISNUMBER(A2) checks that a value is a true number. =IFERROR(a, b) returns b when a is an error.

Auditing tools (Formulas tab)

  • Trace Precedents: arrows to the cells a formula uses.
  • Trace Dependents: arrows to the cells that use this cell.
  • Evaluate Formula: step through a formula part by part.
  • Show Formulas (Ctrl+`) and Error Checking.
  • Watch Window: keep an eye on key cells while editing elsewhere.

Worked example 2.6.1 Avoid #DIV/0! in a return-rate formula.

  • Formula =IF(COUNTIFS(C2:C9, K2) = 0, "", COUNTIFS(C2:C9, K2, G2:G9, "Returned") / COUNTIFS(C2:C9, K2))
  • Plug in For city Pune (K2): orders = 3 (rows 1001, 1003, 1008), returned = 1 (row 1003).
  • Compute 1 / 3 = 0.3333.
  • Answer Pune return rate is 33.3%. For a city with no orders, say Chennai, the formula returns an empty text instead of an error.
  • Check Mumbai: orders 3, returned 0, rate 0%. Delhi: 2 orders, 0 returned, 0%.
  • Interpretation The 33% is based on only 3 orders, so it is very noisy. Always show the count next to a rate.

Worked example 2.6.2 Find why a total looks wrong.

  • Step 1 Suppose =SUM(H2:H9) returns 8,743 but you expect 9,340. The gap is 597, which is exactly the amount in row 4 (order 1003).
  • Step 2 Use Trace Precedents and look at H4. It is left-aligned: the number was stored as text "597", and SUM silently skips text.
  • Step 3 Confirm with =COUNT(H2:H9). It returns 7 instead of 8, because COUNT also skips text. =ISNUMBER(H4) returns FALSE. Fix it with =VALUE(H4) or re-import the data with correct types.
  • Answer The method: compare COUNT with the expected row count to detect text numbers, then repair at the source.
  • Check After repair COUNT equals the row count and the total equals your hand sum.

Connection to the real job. In pandas the equivalent checks are df.dtypes, df.isna().sum() and assert statements. A reviewer who sees you add an error check for blanks trusts your work more.

Applications

  • Finance: month-end reconciliation, where a 600 rupee gap must be explained.
  • Operations: dashboards that must not show #N/A to executives.
  • Audit and compliance: every formula must be traceable.
COMMON MISTAKE
Wrapping everything in IFERROR(..., 0). It turns real problems (a missing lookup key) into silent zeros that feed totals. Use it only where an empty result is truly fine, and test for the specific case if you can.

Check yourself

  1. What does #REF! mean? Answer: A reference points to a deleted cell, row or column.
  2. How can COUNT expose numbers stored as text? Answer: COUNT skips text, so it returns less than the number of rows.
  3. Name two audit tools. Answer: Trace Precedents and Evaluate Formula.

Chapter recap

  • Use a Table (Ctrl+T) and structured references so formulas grow with your data.
  • Use $ when a formula points to a fixed cell, and F4 to add it.
  • XLOOKUP replaces VLOOKUP/HLOOKUP; always use exact match unless you want bands.
  • SUMIFS, COUNTIFS, AVERAGEIFS take the value range first, then criteria pairs.
  • SUMPRODUCT gives weighted sums and conditional counts without helper columns.
  • Clean text with TRIM, PROPER, SUBSTITUTE; split with LEFT, MID, RIGHT, TEXTSPLIT.
  • Dates are numbers; use EDATE, EOMONTH, DATEDIF, NETWORKDAYS, TEXT.
  • Dynamic arrays (FILTER, UNIQUE, SORTBY, LET, LAMBDA) replace helper columns; use * for AND, + for OR.
  • Check totals by hand. Use COUNT to detect text numbers.

Practice set

All questions use the Sales table from the start of this chapter.

Problem 1 What does =COUNTIFS(G2:G9, "Delivered") return?

Answer: 6 (rows 1001, 1002, 1004, 1006, 1007, 1008).

Problem 2 What does =SUMIFS(H2:H9, D2:D9, "Grocery") return?

Answer: 597 + 450 = 1,047.

Problem 3 Write a formula for the average Fashion Delivered amount and give its value.

Answer: =AVERAGEIFS(H2:H9, D2:D9, "Fashion", G2:G9, "Delivered"). Values 998, 799, 1298, 1400 sum to 4495. 4495 / 4 = 1123.75.

Problem 4 What is the output of =XLOOKUP(1004, A2:A9, C2:C9)?

Answer: Delhi. Order 1004 is in the 4th row of the data, and its city is Delhi.

Problem 5 Find the bug: =VLOOKUP(D2, L2:M4, 2) returns 18% for a Fashion order.

Answer: The fourth argument is missing, so Excel uses approximate match on an unsorted list and returns a wrong row. Use =VLOOKUP(D2, L2:M4, 2, FALSE) to get 12%.

Problem 6 What does =SUMPRODUCT((C2:C9="Delhi")*H2:H9) return?

Answer: Delhi rows: 799 and 2499. 799 + 2499 = 3,298.

Problem 7 What does =EDATE(DATE(2025,1,31), 1) return, and why not 31 February?

Answer: 28 February 2025. EDATE moves by months and caps at the last valid day of the target month.

Problem 8 Write one formula that returns the number of distinct cities.

Answer: =COUNTA(UNIQUE(C2:C9)). The distinct cities are Pune, Mumbai, Delhi, so the result is 3.

Problem 9 =NETWORKDAYS(DATE(2025,1,3), DATE(2025,1,10)) equals what?

Answer: 3 Jan (Fri), 6 to 10 Jan (Mon to Fri). That is 1 + 5 = 6 working days, both ends included.

Problem 10 (interview) A report has the same customer twice, as "Asha Rao" and "asha rao ". How do you merge them and keep the original data safe?

Answer: Add a helper column =PROPER(TRIM(A2)) (or in Power Query use Trim and Capitalize Each Word), then use that column for lookups and pivots. Never overwrite the raw column.

Problem 11 (interview) You must replace a sheet where each of 30,000 rows has VLOOKUP to a 5,000 row table and Excel is slow. What do you do?

Answer: Convert the ranges to Tables, use XLOOKUP with exact match on a unique key, avoid whole-column references, or move the join into Power Query (Chapter 3), where the merge happens once at refresh time, not on every recalculation.
