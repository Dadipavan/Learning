If Excel is a calculator with a grid, pandas is the same grid controlled by code: you write the steps once, and you can run them on 100 rows or 10 million rows, tomorrow or next year. 4.1 Series: One Labelled Column

BASIC EXPLANATION
A pandas Series is a one-dimensional labelled array of values with an index. It is the basic building block of a DataFrame.
INTUITION
A Series is a list where every item has a name tag. A plain Python list says "the third number is 310". A Series says "Leh is 310". You look things up by name, not by counting positions.

Formal definition. A Series is a one-dimensional array with an index (the labels) and a dtype (the type of all values). It also has an optional name.

Worked example 4.1.1 Store the average parcel delivery time (hours) for four cities.

s = pd.Series([120, 95, 310, 88],
              index=["delhi", "pune", "leh", "goa"],
              name="hours")
print(s)
print(s["leh"], s.iloc[0], s.mean())
print(s[s > 100])

Predict: what does s[s > 100] keep?

delhi    120
pune      95
leh      310
goa       88
Name: hours, dtype: int64
310 120 153.25
delhi    120
leh      310
Name: hours, dtype: int64
  • Print 1 Labels on the left, values on the right, the name and dtype below.
  • Print 2 s["leh"] looks up by label: 310. s.iloc[0] looks up by position: 120 (the first item). s.mean() = (120 + 95 + 310 + 88) / 4 = 613 / 4 = 153.25.
  • Print 3 s > 100 makes a Series of True/False (a boolean mask). Using it inside [] keeps only the True rows: delhi (120) and leh (310).
  • Check 120 + 95 = 215, + 310 = 525, + 88 = 613. 613 / 4 = 153.25. Correct.

Aligned arithmetic. Operations match labels, not positions:

print(s + pd.Series({"delhi": 1, "pune": 2}))
delhi    121.0
goa        NaN
leh        NaN
pune      97.0
dtype: float64

Labels that exist in only one Series give NaN (Not a Number, pandas' missing value). The dtype changed to float because NaN is a float. This alignment is powerful and surprising. A KeyError appears when you ask for a missing label: s["pay"] raises KeyError: 'pay'.

The picture

 index      values
 delhi       120
 pune         95   <- s["pune"] = 95    (label)
 leh         310   <- s.iloc[2] = 310   (position)
 goa          88

Connection to the real job. Every column of a DataFrame is a Series. When you write df["price"].mean() you use a Series method.

Applications

  • Analytics: one metric per day as a time-indexed Series.
  • Data Science: a target column y is a Series.
  • Data Engineering: lookup dictionaries as Series (map).
COMMON MISTAKE
Confusing label and position. After sorting, s.iloc[0] and s.loc["delhi"] can be different items. Use .loc for labels and .iloc for positions on purpose.

Check yourself

  1. What does s.iloc[2] return in the example? Answer: 310 (the third item).
  2. What is a boolean mask? Answer: A Series of True/False used to select rows.
  3. Why did the sum above give NaN for leh? Answer: That label had no partner in the other Series.

4.2 DataFrame: A Table of Series

BASIC EXPLANATION
A pandas DataFrame is a two-dimensional table of rows and labelled columns, where each column is a Series. It is the main structure for data analysis in pandas.
INTUITION
A DataFrame is an Excel sheet inside Python: columns have names, rows have labels, every column has its own type. Think of it as many Series that share one index.

Formal definition. A DataFrame is a two-dimensional table: an index (row labels), columns (column labels) and one dtype per column.

Our running dataset. Six orders. We read it from text so the example is complete.

import io
csv = """order_id,order_date,customer_id,city,qty,price,status
1001,2025-01-03,C01,Pune,2,499.0,delivered
1002,2025-01-03,C02,Mumbai,1,1299.5,delivered
1003,2025-01-04,C01,Pune,3,199.0,returned
1004,2025-01-05,C03,Delhi,1,,delivered
1005,2025-01-06,C04,Mumbai,5,89.9,cancelled
1006,2025-01-07,C02,Mumbai,2,649.0,delivered
"""
df = pd.read_csv(io.StringIO(csv), parse_dates=["order_date"],
                 dtype={"customer_id": "string"})
print(df)
print(df.dtypes)
print(df.shape)
df.info()

4.3 Reading and Writing Files

BASIC EXPLANATION
Reading and writing files means loading data into pandas from formats such as CSV, Excel and Parquet and saving results back, for example with read_csv and to_csv.
INTUITION
Data lives in files, databases and web services. read_* functions bring them into a DataFrame, and to_* functions put results back. Choose the format to match the job: CSV for sharing, Parquet for speed and size, Excel for business users, SQL for databases, JSON for web data.

Worked example 4.3.2 Read a file in chunks. The file has 6 orders and the chunk size is 4 rows.

for chunk in pd.read_csv("orders_small.csv", chunksize=4):
    print(len(chunk), chunk.qty.sum())

Predict: how many chunks print?

2 7

Reading from SQL. We used Python's built-in sqlite3 with an in-memory database.

import sqlite3

df.drop(columns=["status"]).assign(order_date=df.order_date.astype(str)).to_sql("orders", con, index=False)

  • Check The Mumbai and Pune sums add up by hand. This is the same SQL you learn in the separate SQL document, now running from Python.

JSON. df.to_json("orders.json", orient="records", date_format="iso") writes a list of objects. pd.read_json reads it back. We checked: the date came back as text (str), not datetime, because JSON has no date type. Convert again with pd.to_datetime.

Excel. pd.read_excel("file.xlsx", sheet_name="Data") needs openpyxl. See Chapter 3 for a real run and a formula caveat.

4.4 Selecting Rows and Columns

BASIC EXPLANATION
Selecting means choosing rows and columns from a DataFrame by label with loc, by position with iloc, or by condition with boolean masks.
INTUITION
You rarely need the whole table. Selecting is like asking a librarian: "give me the rows where the city is Mumbai, and only the columns order number and price". There are three ways to say it: by label (loc), by position (iloc), and by condition (a boolean mask).

The tools

GoalCodeNotes
One columndf["city"]A Series
Several columnsdf[["order_id", "price"]]Double brackets, returns a DataFrame
Rows and columns by labeldf.loc[rows, cols]End of slice is included
Rows and columns by positiondf.iloc[rows, cols]End of slice is excluded
Conditiondf[df["qty"] > 1]Boolean mask
Several conditionsdf[(a) & (b)], `\ for OR, ~` for NOT
Membershipdf["city"].isin(["Pune", "Delhi"])Like SQL IN
Rangedf["price"].between(200, 700)Inclusive both ends
Readable conditiondf.query("qty >= 2 and status != 'cancelled'")Text expression
Name patterndf.filter(like="_id")Selects columns by name

Worked example 4.4.1 Select Mumbai orders and two columns, then a slice by position.

print(df.loc[df.city == "Mumbai", ["order_id", "price"]])
print(df.iloc[1:4, 0:3])
   order_id   price
1      1002  1299.5
4      1005    89.9
5      1006   649.0
   order_id order_date customer_id
1      1002 2025-01-03         C02
2      1003 2025-01-04         C01
3      1004 2025-01-05         C03
  • Compute df.city == "Mumbai" is True for rows 1, 4, 5. iloc[1:4, 0:3] means rows at positions 1, 2, 3 (4 is excluded) and the first three columns (positions 0, 1, 2).
  • Answer Three Mumbai rows with two columns, and a 3 by 3 block.
  • Check The row labels on the left (1, 4, 5) are the original index values, preserved after filtering.
  • Why it matters loc slices include the end label while iloc slices exclude it. That rule causes most off-by-one bugs.

Worked example 4.4.2 Combine conditions: orders with qty at least 2 that were not cancelled.

print(df.query("qty >= 2 and status != 'cancelled'"))
   order_id order_date customer_id    city  qty  price     status
0      1001 2025-01-03         C01    Pune    2  499.0  delivered
2      1003 2025-01-04         C01    Pune    3  199.0   returned
5      1006 2025-01-07         C02  Mumbai    2  649.0  delivered
  • Compute qty >= 2 holds for rows 0 (2), 2 (3), 4 (5), 5 (2). Row 4 is cancelled, so it drops out.
  • Answer Rows 0, 2 and 5.
  • Check The same filter with masks, df[(df.qty >= 2) & (df.status != "cancelled")], returns the same three rows.

More examples we ran: df[df.city.isin(["Pune", "Delhi"])] returns rows 0, 2, 3; df[df.price.between(200, 700)] returns rows 0 (499.0) and 5 (649.0), because 199.0 is below 200 and the NaN price never matches.

MultiIndex. An index with more than one level, for example mi = df.set_index(["city", "order_id"]).sort_index(). Then mi.loc["Mumbai"] returns all Mumbai rows, and mi.loc[("Mumbai", 1002)] returns one row. Grouped results often come back with a MultiIndex (Chapter 5), and reset_index() turns the levels back into normal columns.

Wrong version and its error. df["order_id", "price"] fails: pandas treats the tuple as one column name and raises a KeyError. Use df[["order_id", "price"]]. And df[df.qty > 1 & df.price > 100] fails because & binds tighter than >: write df[(df.qty > 1) & (df.price > 100)].

Connection to the real job. Selecting is the WHERE and SELECT of SQL. In interviews you will be asked to filter with two or three conditions on a screen share. Practise until the brackets feel natural.

Applications

  • Analytics: orders of one region; customers who bought twice.
  • Data Science: split a dataset by condition for train/test.
  • Data Engineering: filter bad records before loading.
COMMON MISTAKE
Using and / or instead of & / | with Series. Python's and cannot handle a whole column and raises "The truth value of a Series is ambiguous". Use &, | with parentheses.

Check yourself

  1. Which slice includes its end: loc or iloc? Answer: loc includes the end label.
  2. How do you write "city is Pune or Delhi"? Answer: df["city"].isin(["Pune", "Delhi"]).
  3. Why parentheses in (a) & (b)? Answer: & binds tighter than comparison operators.

4.5 Data Types and Common Pitfalls

BASIC EXPLANATION
A data type defines what kind of values a column holds, such as integers, floats, text or dates. Wrong types cause errors and wrong results, so they should be checked and converted.
INTUITION
A type tells pandas how to treat a column. "10" + "10" as text gives "1010", as numbers gives 20. Types affect memory, speed, and correctness. A wrong type is the most common silent bug in analytics.

The dtypes to know

dtypeHoldsMissing valueNote
int64Whole numbersNot allowedOne NaN turns it into float
float64DecimalsNaN
Int64, Float64 (capital)Nullable numbers<NA>Keeps integers when values are missing
boolTrue/False
str (pandas 3) / object (older)TextNaN
stringExplicit text type<NA>Can use string[pyarrow]
categoryFew repeated valuesNaNSaves memory, allows order
datetime64[us]Date and timeNaT[us] means microsecond resolution (older versions: [ns])
timedelta64DurationNaTDifference of two dates

Worked example 4.5.1 Nullable integers.

print(pd.Series([1, 2, None]).dtype)
print(pd.Series([1, 2, None], dtype="Int64").tolist(), pd.Series([1, 2, None], dtype="Int64").dtype)
float64
[1, 2, <NA>] Int64
  • Compute A normal Series with a missing value must use float, so 1 and 2 are stored as 1.0 and 2.0. The capital Int64 keeps true integers and shows <NA>.
  • Answer float64 versus Int64.
  • Why it matters Counts and IDs should not become 1.0, 2.0. Use nullable types when integers can be missing.

Converting types (we ran each; the comment shows the real result)

pd.to_numeric(pd.Series(["10", "20", "x"]), errors="coerce").tolist()   # [10.0, 20.0, nan]
pd.Series(["10", "20", "x"]).astype(int)    # ValueError: invalid literal for int() with base 10: 'x'
pd.to_datetime("03/04/2025")                # 2025-03-04 (month first)
pd.to_datetime("03/04/2025", dayfirst=True) # 2025-04-03 (day first)

astype(int) fails on the bad text "x", while to_numeric(..., errors="coerce") turns it into NaN so you can find and handle bad values. Notice that 03/04/2025 means 4 March or 3 April depending on dayfirst. With Indian data (day first) always set dayfirst=True or give an explicit format="%d/%m/%Y". A wrong guess here shifts a month of sales into another month, silently.

Category dtype and memory. Text repeated many times costs memory. On a 300,000-row column with 4 city names, memory was 16,349,930 bytes as text and 300,350 bytes as category, 54 times smaller (Chapter 6 shows the full run).

Copy-on-Write and SettingWithCopyWarning. In older pandas, assigning into a filtered slice sometimes changed the original table and sometimes did not, and pandas printed SettingWithCopyWarning. In pandas 3 Copy-on-Write is always on: every derived object behaves as its own copy. We ran this (with df freshly read from the CSV):

view = df[df.city == "Pune"]
view["qty"] = 0
print(df.qty.tolist())            # [2, 1, 3, 1, 5, 2]  (original unchanged)

df2 = df.copy()
df2[df2.city == "Pune"]["qty"] = 99      # chained assignment
print(df2.qty.tolist())           # [2, 1, 3, 1, 5, 2]  (nothing happened!)
df2.loc[df2.city == "Pune", "qty"] = 99  # correct: one step
print(df2.qty.tolist())           # [99, 1, 99, 1, 5, 2]

pandas 3 printed a ChainedAssignmentError warning for the chained line and left the data unchanged. The rule is simple: update with one .loc[rows, column] = value call, never df[mask]["col"] = value. In older pandas the chained version sometimes worked and sometimes did not, which is why it was dangerous.

Implicit casting pitfalls. Mixed types in one column become text. Integers with missing values become float. Adding a number to a text column fails. Comparing text numbers ("10" < "9" is True as text) gives wrong sorts. Always convert first.

Memory. df.memory_usage(deep=True) shows bytes per column; deep=True counts the text. Use usecols, category, smaller ints (int16) and chunksize to control it.

The picture

 "1,150"  --(replace ',' then to_numeric)--> 1150.0 float64
 "10"     --astype(int)--> 10      "x" --astype(int)--> ValueError
 "x"      --to_numeric(errors="coerce")--> NaN   (you can then find it)

Connection to the real job. Bad dtypes cause bad joins (IDs "007" vs 7), bad sorts, and bad charts. In code review, the question "what are the dtypes?" is routine.

Applications

  • Analytics: IDs as text, money as float, dates as datetime.
  • Data Science: ordered category types for features.
  • Data Engineering: schema enforcement (Parquet keeps types).
COMMON MISTAKE
Reading IDs as numbers. C001 is fine, but 00123 becomes 123 and loses its zeros, and then it will not match the key in another table. Use dtype={"id": "string"} at read time.

Check yourself

  1. What does errors="coerce" do in to_numeric? Answer: Bad values become NaN instead of raising an error.
  2. Which is the right way to set values on a filter? Answer: df.loc[mask, "col"] = value.
  3. What does dayfirst=True do? Answer: It reads 03/04/2025 as 3 April.

4.6 MultiIndex Deep Dive: Rows and Columns with Several Levels

BASIC EXPLANATION
A MultiIndex is an index with several levels, so rows or columns are labelled by more than one key. It is used for grouped and hierarchical data.
INTUITION
A normal index is a street address with only a house number. A MultiIndex is a full address: city, then month, then product. The table is still flat underneath, but pandas now knows the levels, so you can ask for "everything in Pune", "Pune in February" or "tea in every city" with one short expression. You will meet MultiIndex whether you want it or not, because groupby with two keys, pivot_table and unstack all produce one.
PROFESSOR'S NOTE
Every block below ran with pandas 3.0.6. This is the expert layer of the short MultiIndex note in Section 4.4: read that first if the word is new.

Building and selecting

import pandas as pd
sales = pd.DataFrame({
    "city": ["Pune", "Pune", "Pune", "Pune", "Delhi", "Delhi", "Delhi", "Delhi"],

COMMON MISTAKE
Slicing an unsorted MultiIndex. Without sort_index(), range slices fail with UnsortedIndexError (we triggered it: "Key length (2) was greater than MultiIndex lexsort depth (0)"). Sort once right after set_index. Also note that sort_index sorts text alphabetically, so months appear as feb before jan. Store months as numbers (1, 2, 3) or as an ordered categorical when order matters.

Aggregating and reshaping with levels

groupby(level=...) aggregates by one or several index levels without resetting the index. unstack(level) moves a level into columns, which is the pandas version of a PivotTable, and stack does the reverse. swaplevel reorders levels and reset_index flattens everything back to ordinary columns.

import pandas as pd
sales = pd.DataFrame({
    "city": ["Pune", "Pune", "Pune", "Pune", "Delhi", "Delhi", "Delhi", "Delhi"],
    "month": ["jan", "jan", "feb", "feb", "jan", "jan", "feb", "feb"],
    "product": ["tea", "coffee"] * 4,
    "revenue": [200, 150, 260, 120, 300, 90, 280, 110]})
mi = sales.set_index(["city", "month", "product"]).sort_index()
print(mi.groupby(level=["city", "month"]).sum())          # drop the product level
print(mi["revenue"].unstack("month"))                     # months become columns
print(mi["revenue"].unstack("product").sum(axis=1))       # total per city and month
print(mi.reset_index().head(2))                           # back to a flat table

MultiIndex columns: wide reports with two header rows

Excel reports often have two header rows ("Jan" over "Revenue, Quantity"). pandas represents this as MultiIndex columns. Select a top-level group with df["jan"] and a single column with a tuple.

import pandas as pd
cols = pd.MultiIndex.from_product([["jan", "feb"], ["rev", "qty"]])
w = pd.DataFrame([[200, 10, 260, 12], [300, 14, 280, 13]], index=["Pune", "Delhi"], columns=cols)
print(w)
print(w["jan"])                      # all columns under jan
print(w[("feb", "rev")])             # one column
w.columns = ["_".join(c) for c in w.columns]    # flatten the two header rows into one

Before saving to CSV, a database or Power BI, flatten the headers (as in the last lines). Most tools expect one header row, and the names jan_rev, jan_qty are clearer than a hidden second level.

KEY IDEA
Use a MultiIndex as a working structure for slicing, unstack and group totals, and flatten it with reset_index() before you merge, plot or export. Many experts avoid MultiIndex rows in stored tables altogether and keep a flat table with ordinary columns, because merges, SQL and BI tools all prefer that.

Going deeper

  • Unique or not. A MultiIndex does not have to be unique. mi.index.is_unique tells you. A non-unique index makes .loc return several rows where you expected one, and assignment through it is ambiguous. Check it right after set_index (verify_integrity=True raises at once).
  • Speed. Lookups on a sorted MultiIndex use binary search and are fast. On an unsorted one, pandas must scan, and some operations fail outright.
  • Where it comes from in practice. df.groupby(["city", "product"]).agg(["sum", "mean"]) gives MultiIndex columns, one pair per statistic. Named aggregation (.agg(total=("revenue", "sum")), Section 5.3) avoids it entirely.
  • Compare. The same "tea in every city" question in SQL is WHERE product = 'tea' and in Excel is a PivotTable filter. A MultiIndex is just the pandas way to keep that filter cheap.

Chapter recap

  • A Series is a labelled column; a DataFrame is a table of Series sharing an index.
  • Always start with head(), info(), describe(), isna().sum(), dtypes.
  • read_csv has arguments that save you later (dtype, parse_dates, usecols, chunksize).
  • Parquet is fast and typed but needs pyarrow; JSON loses dates; Excel needs openpyxl.
  • loc selects by label (end included); iloc by position (end excluded); masks and query filter rows.
  • Combine conditions with &, |, ~ and parentheses.
  • One missing value turns integers into floats; use nullable Int64 when needed.
  • Convert with to_numeric(errors="coerce") and to_datetime(dayfirst=True).
  • Set values with one .loc call; chained assignment never works in pandas 3.

Problem 11 (interview) "What is the difference between loc and iloc, and when does it matter?"

Answer: loc uses labels and includes the end of a slice; iloc uses positions and excludes the end. It matters after sorting or filtering, because the labels no longer equal the positions.
