Your music app has a "next" button, a "previous" button and a "play next" queue. Behind them sit three small ideas: a chain of items where each item knows what comes after it (the linked list), a pile where the last thing in is the first out (the stack), and a line where the first in is the first out (the queue). They look humble, yet they hide some of the most reused tricks in interviews.

In this chapter you build all three, then learn two powerful tricks on top of them: the monotonic stack and the monotonic deque. "Monotonic" means the items inside are always in one order (always increasing or always decreasing). That single rule turns many slow nested loops into one pass. You will meet these again in Chapters 7, 8 and 11. For a shorter first look, see also the CS document, Chapter 9.

5.1 Linked Lists From Scratch

IDEA
A linked list is a chain of nodes. Each node holds a value and a pointer to the next node. You cannot jump to the 5th node; you must walk from the first.

Real-life picture. A treasure hunt: each clue tells you where the next clue is hidden. Lose one clue and everything after it is lost.

WordPlain meaning
NodeOne box: a value plus a link to the next box
PointerA variable that says which node to look at (in Python, a variable holding a node or None)
Head / tailThe first / last node. The tail's next is None
Singly / doubly linkedNodes know only the next node / both the previous and the next

How to recognise it: the input is a head node, not a Python list; the statement says "in place" or "O(1) extra space"; words like cycle, middle, n-th from the end, reverse, merge.

How to read it: start at head, follow the arrows, stop at None.

Compared with a Python list: reading item i costs O(n) (walk) instead of O(1); inserting or deleting next to a node you already hold costs O(1) instead of O(n) (no shifting); searching costs O(n) for both.

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val      # data stored in this box
        self.next = next    # next box, or None at the end

def build(values):
    head = None
    for v in reversed(values):      # build from the back: no tail variable needed
        head = ListNode(v, head)
    return head

def to_list(head):
    out, cur = [], head
    while cur:                      # the walk loop: stop when cur is None
        out.append(cur.val)
        cur = cur.next
    return out

head = build([3, 7, 9])
node = head.next                    # the 7-box
new = ListNode(8)
new.next = node.next                # 1. point the new node at the rest
node.next = new                     # 2. then connect the front
print(to_list(head))
[3, 7, 8, 9]
COMMON MISTAKE
Cutting the chain before saving the rest. Wrong: node.next = new first. The old rest is now unreachable. Right: new.next = node.next first, then node.next = new.
Step0: 3 → 7 → 9.   1: create a lone box 8.   2: new.next = node.next gives 8 → 9.   3: node.next = new gives 3 → 7 → 8 → 9.

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

class LinkedList:
    def __init__(self):
        self.head = None

    def push_front(self, v):
        self.head = ListNode(v, self.head)

    def append(self, v):
        if self.head is None:
            self.head = ListNode(v)
            return
        cur = self.head
        while cur.next:                # walk to the last node
            cur = cur.next
        cur.next = ListNode(v)

    def find(self, v):
        cur = self.head
        while cur and cur.val != v:
            cur = cur.next
        return cur is not None

    def delete(self, v):
        if self.head and self.head.val == v:   # the head has no node before it
            self.head = self.head.next
            return
        cur = self.head
        while cur and cur.next and cur.next.val != v:
            cur = cur.next                     # stop one node BEFORE the target
        if cur and cur.next:
            cur.next = cur.next.next

    def to_list(self):
        out, cur = [], self.head
        while cur:
            out.append(cur.val)
            cur = cur.next
        return out

Problem 5.1.2 (medium) Build a doubly linked list where remove(node) deletes a node you already hold in O(1).

IdeaThe node knows both neighbours, so join them to each other. Handle head and tail changes.
Brute forceWalk from the head to find the predecessor: O(n).
BetterUse node.prev: O(1).
CodeBelow.
Dry run1 ⇄ 2 ⇄ 3, remove 2: 1.next = 3 and 3.prev = 1.
ComplexityO(1) per operation.
Edge casesRemoving the head, the tail, the only node.
class DNode:
    def __init__(self, val):
        self.val, self.prev, self.next = val, None, None

class DList:
    def __init__(self):
        self.head = self.tail = None

    def append(self, v):
        node = DNode(v)
        if self.tail is None:
            self.head = self.tail = node
        else:
            node.prev, self.tail.next = self.tail, node
            self.tail = node
        return node

    def remove(self, node):
        if node.prev: node.prev.next = node.next
        else: self.head = node.next            # node was the head
        if node.next: node.next.prev = node.prev
        else: self.tail = node.prev            # node was the tail

    def forward(self):
        out, cur = [], self.head
        while cur:
            out.append(cur.val); cur = cur.next
        return out

d = DList()
a, b, c = d.append(1), d.append(2), d.append(3)
d.remove(b); assert d.forward() == [1, 3]
d.remove(a); assert d.head is c and d.tail is c
d.remove(c); assert d.head is None and d.tail is None

5.2 Reversing a Linked List

IDEA
Walk down the list once and turn every arrow around. Use prev (the reversed part), cur (the node being fixed) and a saved copy of cur.next so you never lose the rest.

Real-life picture. Train coaches: uncouple the first coach, couple it to the front of a new train, then do the next coach. The new train is the old one backwards.

How to recognise it: "reverse (part of) the list", "palindrome list", "reorder list", "add two numbers stored as lists".

How to read it: go row by row. prev heads the reversed part, curr is the next node to fix. At the end prev is the new head.

BetterReverse in place: O(n) time, O(1) space.

    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def to_list(h):
    out = []
    while h:
        out.append(h.val)
        h = h.next
    return out

def reverse(head):
    prev, cur = None, head      # the reversed part starts empty
    while cur:
        nxt = cur.next          # 1. save the rest of the list
        cur.next = prev         # 2. turn the arrow around
        prev = cur              # 3. grow the reversed part
        cur = nxt               # 4. move on to the saved rest
    return prev                 # prev is the new head

Problem 5.2.2 (hard) Reverse the list in groups of k; leave a final group shorter than k untouched. Example: 1..5 with k = 2 gives 2,1,4,3,5.

IdeaFor each group: first check that k nodes exist. If yes, reverse exactly those and reconnect to the group before and the rest after.
Brute forceCopy to a list, reverse each full chunk, rebuild: O(n) space.
BetterKeep group_prev, the node before each group: O(n) time, O(1) space.

def reverse_k_group(head, k):
    dummy = ListNode(0, head)
    group_prev = dummy
    while True:
        kth = group_prev
        for _ in range(k):             # count first: do k nodes exist?
            kth = kth.next
            if kth is None:
                return dummy.next
        prev, cur = kth.next, group_prev.next   # first node will point past the group
        for _ in range(k):
            nxt = cur.next
            cur.next = prev
            prev, cur = cur, nxt
        old_first = group_prev.next    # now the group's last node
        group_prev.next = prev         # prev is the group's new first node
        group_prev = old_first

assert to_list(reverse_k_group(build([1, 2, 3]), 1)) == [1, 2, 3]
assert to_list(reverse_k_group(build([1, 2]), 5)) == [1, 2]
print(to_list(reverse_k_group(build([1, 2, 3, 4, 5]), 2)))

COMMON MISTAKE
Reversing a short last group. With 1..5 and k = 3 you must get 3,2,1,4,5. Reversing the leftover gives 3,2,1,5,4. Count k nodes first, reverse second.

Going deeper

  • State the loop invariant: "prev heads a correctly reversed list of everything before cur; cur heads the untouched rest."
  • A recursive reverse is shorter but uses O(n) stack frames. Python's default limit is about 1000, so a 5000-node list raises RecursionError. Prefer the loop.
  • Doubly linked lists reverse by swapping each node's prev and next.

5.3 Fast and Slow Pointers: Middle and Cycle

IDEA
Send two runners down the list: slow moves 1 node per step, fast moves 2. When fast reaches the end, slow is at the middle. If the list loops, fast laps slow and they meet.

Real-life picture. Two joggers on a track. On a straight road the fast one finishes first and the slow one is halfway. On a circular track the fast one catches the slow one from behind.

How to recognise it: "find the middle", "has a cycle", "where does the cycle start", "palindrome list", or a sequence made by repeating a function that might loop.

How to read it: once both runners are inside the cycle, fast gains exactly one node on slow per step, so the gap shrinks to zero.

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:        # fast needs two nodes ahead of it
        slow = slow.next             # 1 step
        fast = fast.next.next        # 2 steps
        if slow is fast:             # same object, not same value
            return True
    return False

def middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow                      # for even length: the second middle

def make(n):                         # chain of n nodes holding 1..n
    nodes = [ListNode(i + 1) for i in range(n)]
    for a, b in zip(nodes, nodes[1:]):
        a.next = b
    return nodes

for n in (1, 2, 5, 6):
    print(n, "nodes: middle is", middle(make(n)[0]).val)
chain = make(8)

chain[7].next = chain[2]             # last node points back to node 3

Problem 5.3.2 (medium) Return the node where a cycle begins, or None.

IdeaPhase 1: run until slow meets fast. Phase 2: restart one pointer at the head; move both one step at a time. They meet at the cycle entry.
Brute forceA set of visited nodes; the first repeat is the entry: O(n) space.
BetterFloyd's two phases. Proof: let a = tail length, b = distance from the entry to the meeting point, c = cycle length. Slow walked a + b; fast walked 2(a + b), which is slow's distance plus m whole laps: a + b = m·c. So a = m·c - b: walking a steps from the meeting point lands on the entry, and so does walking a steps from the head.
CodeBelow.
Dry runMeet at 5. Pairs (0,5), (1,6), (2,7), (3,3): the entry is 3.
ComplexityO(n) time, O(1) space.
Edge casesNo cycle; the whole list is the cycle; a node pointing to itself.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def cycle_entry(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:                 # phase 1: met inside the cycle
            finder = head
            while finder is not slow:    # phase 2: one step each
                finder = finder.next
                slow = slow.next
            return finder
    return None

def link(n, back_to):                    # nodes 0..n-1; last points to back_to (or None)
    nodes = [ListNode(i) for i in range(n)]
    for a, b in zip(nodes, nodes[1:]):
        a.next = b
    if back_to is not None:
        nodes[-1].next = nodes[back_to]
    return nodes

Problem 5.3.3 (hard) Is a linked list a palindrome? Use O(1) extra space.

IdeaFind the middle, reverse the second half, compare the halves.
Brute forceCopy values to a list and compare with its reverse: O(n) space.
BetterCombine two earlier patterns: middle (5.3) and reverse (5.2).
CodeBelow.
Dry run1,2,2,1: slow stops at the second 2; reversed half is 1 → 2; compare 1=1, 2=2: True. 1,2,3: reversed half 3 → 2; 1 vs 3 differ: False.
ComplexityO(n) time, O(1) space.
Edge casesEmpty or one node: True. Odd length: the middle node sits in the reversed half and is compared with itself, which is harmless.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def build(a):
    head = None
    for v in reversed(a):
        head = ListNode(v, head)
    return head

def is_palindrome(head):
    slow = fast = head
    while fast and fast.next:          # 1. find the middle
        slow, fast = slow.next, fast.next.next
    prev, cur = None, slow             # 2. reverse the second half
    while cur:
        cur.next, prev, cur = prev, cur, cur.next
    left, right = head, prev           # 3. compare the halves
    while right:
        if left.val != right.val:
            return False
        left, right = left.next, right.next
    return True

assert is_palindrome(build([1, 2, 3, 2, 1])) and is_palindrome(build([1])) and is_palindrome(None)
assert not is_palindrome(build([1, 2, 3]))
print(is_palindrome(build([1, 2, 2, 1])), is_palindrome(build([1, 2, 3])))

INTERVIEW
When asked for O(1) space, state the brute force first (copy to a list), then say which two known pieces you will reuse. Clear decomposition scores higher than a silent leap.

Going deeper

  • Speeds 1 and 2 are special: the gap shrinks by exactly one per step, so it cannot jump over zero. With other speeds the pointers can circle without ever landing together.
  • The same idea works on any sequence x, f(x), f(f(x)), ...: the "happy number" puzzle, finding the repeated number in an array of values 1 to n, and Pollard's rho factoring.

5.4 The Dummy-Node Trick: Merge and Remove

IDEA
Put a fake node (the dummy) in front of the real head. Now every real node, even the first, has a node before it, so "is this the head?" special cases vanish. Return dummy.next at the end.

Real-life picture. A rope barrier at the front of a queue. It is not a customer, but everyone, even the first customer, stands behind something.

How to recognise it: you build a new list node by node (merge, filter, partition), or you may delete the head, or you catch yourself writing if head is None special cases.

How to read it: compare the two fronts, hook the smaller after tail, move tail onto it, advance the list it came from.

Problem 5.4.1 (easy) Merge two sorted linked lists into one sorted list by reusing the nodes. The code is also the dummy-node template.

IdeaDummy plus tail. Attach the smaller front each time. When one list runs out, attach the other whole.
Brute forcePut all values in a Python list, sort, rebuild: O((n + m) log(n + m)) time and extra space. It ignores that the inputs are already sorted.
BetterTwo-pointer merge: O(n + m) time, O(1) space.

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def build(a):
    head = None
    for v in reversed(a):
        head = ListNode(v, head)
    return head

def to_list(h):
    out = []
    while h:
        out.append(h.val)
        h = h.next
    return out

def merge(a, b):
    dummy = ListNode()              # fake first node
    tail = dummy                    # last node of the output so far
    while a and b:
        if a.val <= b.val:
            tail.next, a = a, a.next
        else:
            tail.next, b = b, b.next
        tail = tail.next
    tail.next = a if a else b       # attach the leftover list in one move
    return dummy.next               # skip the dummy

Problem 5.4.2 (medium) Remove the n-th node from the end (n = 1 is the last node) in one pass. Example: 1..5 with n = 2 gives 1 → 2 → 3 → 5.

How to read it: fast started n nodes ahead of slow and the gap never changes, so the end of the list tells you where the n-th from the end is.

IdeaStart both pointers on the dummy. Move fast n steps. Then move both until fast.next is None. Delete slow.next.
Brute forceCount the length L, then walk L - n steps from the dummy: two passes, O(1) space.
BetterThe gap trick: one pass. The dummy makes "remove the head" (n = L) work.
CodeBelow.
Dry run1..5, n = 2: fast moves dummy → 1 → 2. Then (slow, fast) = (1,3), (2,4), (3,5). Stop. Delete 4: 3.next = 5.

Edge casesn = L (remove the head); one-node list; n = 1.
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def build(a):
    head = None
    for v in reversed(a):
        head = ListNode(v, head)
    return head

def to_list(h):
    out = []
    while h:
        out.append(h.val)
        h = h.next
    return out

def remove_nth_from_end(head, n):
    dummy = ListNode(0, head)
    slow = fast = dummy
    for _ in range(n):               # open a gap of n nodes
        fast = fast.next
    while fast.next:                 # run until fast is on the last node
        slow, fast = slow.next, fast.next
    slow.next = slow.next.next       # slow is just before the target
    return dummy.next

Off-by-one gap. If both pointers start on the real head and you stop when fast is None, slow lands on the target, and a singly linked list cannot delete the node you stand on. Start on the dummy and stop at fast.next is None.

    return out

def merge(a, b):
    dummy = tail = ListNode()
    while a and b:
        if a.val <= b.val:
            tail.next, a = a, a.next
        else:
            tail.next, b = b, b.next
        tail = tail.next
    tail.next = a if a else b
    return dummy.next

def sort_list(head):
    if head is None or head.next is None:      # 0 or 1 node: sorted
        return head
    slow, fast = head, head.next               # fast one ahead: slow ends on the LEFT middle
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
    second, slow.next = slow.next, None        # cut the list in two
    return merge(sort_list(head), sort_list(second))

print(to_list(sort_list(build([4, 2, 1, 3]))))

COMMON MISTAKE
Forgetting to cut the list (slow.next = None). The first half still links to the second, each recursive call sees the whole list again, and you get RecursionError. Starting fast at head on a two-node list has the same effect.

  • Merging k sorted lists: merge them in pairs (O(N log k) for N nodes) or use a min-heap (Chapter 7).
  • Merging with <= makes merge sort stable, which is why it is the usual choice for sorting records.

5.5 Stacks: Last In, First Out

IDEA
A stack is a pile where you touch only the top. Push adds on top, pop removes the top, peek reads the top. Last in, first out (LIFO). A Python list is a stack: append, pop(), stack[-1], all O(1).

Real-life picture. A pile of plates, the Back button of a browser, the Undo button of an editor: the most recent thing is the first to go.

How to recognise it: matching pairs (brackets, tags); "the most recent unmatched item decides"; undo or backtracking; evaluating expressions; replacing recursion with a loop; "nearest bigger item" (Section 5.7).

How to read it: picture 1 has pushed three openers; each later picture pops one because the next character closes it.

class MinStack:
    def __init__(self):
        self.items = []            # pairs (value, minimum so far)

    def push(self, x):
        low = min(x, self.items[-1][1]) if self.items else x
        self.items.append((x, low))

    def pop(self):
        return self.items.pop()[0]

    def top(self):
        return self.items[-1][0]

    def get_min(self):
        return self.items[-1][1]

Problem 5.5.3 (hard) Evaluate a string like "14-3*2+8/4" with non-negative integers and + - * / (no brackets, spaces allowed). Multiplication and division bind tighter. Division truncates toward zero.

def calculate(s):
    stack, num, op = [], 0, "+"     # op = operator that came BEFORE num
    for ch in s + "+":              # the extra "+" flushes the last number
        if ch.isdigit():
            num = num * 10 + int(ch)
        elif ch != " ":
            if op == "+": stack.append(num)
            elif op == "-": stack.append(-num)
            elif op == "*": stack.append(stack.pop() * num)
            else: stack.append(int(stack.pop() / num))
            op, num = ch, 0
    return sum(stack)

5.6 Queues and Deques: First In, First Out

IDEA
A queue is a line: items join at the back and leave from the front (FIFO). A deque (say "deck", double-ended queue) allows adds and removes at both ends in O(1).

Real-life picture. A ticket counter: first to arrive, first served. In a deque, VIPs may also join at the front and the last person may leave from the back.

How to recognise it: things processed in arrival order; "level by level" or "fewest steps" (breadth-first search, Chapter 8); a moving window over a stream where items expire from one end.

How to read it: in the top queue A arrived first, so A leaves first. In the bottom deque the orange double arrows show that both ends accept both operations.

5.7 The Monotonic Stack

IDEA
A monotonic stack is a stack that keeps its items in one order (for example always decreasing from bottom to top). Before pushing a new item, pop every item that would break the order. Each popped item has just found its answer: the new item.

Real-life picture. People in a waiting room, all facing right, each wanting to know who is the first taller person to their right. Those still waiting sit on the stack. A newcomer enters: every waiting person shorter than the newcomer gets their answer and leaves. Taller people keep waiting. So the waiting room is always in decreasing height.

How to recognise it: next or previous greater/smaller element; "days until a warmer day"; stock span; largest rectangle in a histogram; "remove digits to make the smallest number"; a nested loop whose inner loop searches for "the first bigger item to the right".

How to read it: 71 and 69 both point to 72, and 75 jumps over everything up to 76. The stack finds all arrows in one left-to-right pass.

def next_greater_indexes(nums):
    answer = [-1] * len(nums)          # -1 means "no greater element to the right"
    stack = []                         # indexes still waiting; their values decrease
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:   # x beats the waiting item
            answer[stack.pop()] = i            # the popped item found its answer
        stack.append(i)                        # i now waits for its own answer
    return answer

In words: for each new item, pop everything it beats and record the answer for them, then push yourself. For "next smaller" flip the comparison. For "previous greater" read the stack top before pushing.

import random

def largest_rectangle(heights):
    stack = []                                 # indexes, heights increasing
    best = 0
    for i, h in enumerate(heights + [0]):      # the 0 sentinel flushes the stack
        while stack and heights[stack[-1]] >= h:
            height = heights[stack.pop()]
            left = stack[-1] if stack else -1  # previous smaller bar, or the left wall
            best = max(best, height * (i - left - 1))
        stack.append(i)
    return best

def brute(heights):
    best = 0
    for left in range(len(heights)):
        lowest = heights[left]
        for right in range(left, len(heights)):
            lowest = min(lowest, heights[right])
            best = max(best, lowest * (right - left + 1))
    return best

5.8 The Monotonic Deque: Sliding Window Maximum

IDEA
A window slides along an array and you need its maximum at every position. Keep a deque of indexes whose values decrease from front to back. The front is the window maximum. Pop weaker items from the back when a new item arrives; pop from the front when the front index leaves the window.

Real-life picture. A talent show where each performer is remembered for k rounds. A stronger performer arrives: every weaker performer already in line will never be the best again (the newcomer is stronger and stays longer), so they are removed. The front of the line is the current best.

How to recognise it: "maximum or minimum of every window of size k"; "longest subarray where max minus min is at most a limit"; a sliding window where you need the window max or min fast; a DP recurrence that takes the best of the last k states.

How to read it: window 1 covers indexes 0 to 2 (max 3). Window 5 covers indexes 4 to 6 (values 5, 3, 6, max 6). There are n - k + 1 = 6 windows.

Problem 5.8.1 (medium) Sliding window maximum. Return the maximum of every window of size k. Example: [1, 3, -1, -3, 5, 3, 6, 7], k = 3 gives [3, 3, 5, 5, 6, 7]. The code is also the template.

IdeaFour steps per item: pop weaker from the back, push the index, expire the front, record the front once the window is full.
Brute forcemax of every slice: O(n·k). For n = 105 and k = 5·104 that is billions of steps.
BetterA heap with lazy deletion is O(n log n). The deque is O(n): every index enters and leaves once.
CodeBelow, checked against the brute force.
Dry runThe trace table below.
ComplexityO(n) time, O(k) space (the deque holds at most k indexes).
Edge casesk = 1 (output equals input); k = n (one output); duplicates (pop on <=, keeping the newest, which stays longest); decreasing input (only expiry shrinks the deque).
from collections import deque
import random

def window_max(nums, k):
    dq = deque()                           # indexes; values decrease front to back
    out = []
    for i, x in enumerate(nums):
        while dq and nums[dq[-1]] <= x:    # 1. drop weaker items from the back
            dq.pop()
        dq.append(i)                       # 2. add the new index
        if dq[0] <= i - k:                 # 3. drop the front if it left the window
            dq.popleft()
        if i >= k - 1:                     # 4. window is full: the front is the maximum
            out.append(nums[dq[0]])
    return out

def brute(nums, k):
    return [max(nums[i:i + k]) for i in range(len(nums) - k + 1)]

Problem 5.8.2 (hard) Return the length of the longest contiguous subarray in which the largest minus the smallest value is at most limit. Example: [10, 1, 2, 4, 7, 2] with limit 5 gives 4 (the subarray [2, 4, 7, 2]).

IdeaA variable-size sliding window (Chapter 3) with two monotonic deques: decreasing for the window max, increasing for the window min. Add the right end to both. While max - min > limit, advance left and pop deque fronts that fell out.
Brute forceCheck every subarray with max and min: O(n³), or O(n²) with running values.
BetterTwo deques: each index enters and leaves each deque once, and left only moves forward: O(n).
CodeBelow.
Dry runLimit 5. Window {10, 1}: 9 > 5, so left moves past 10. Grow to {1, 2, 4, 7}: 6 > 5, so left moves past 1. Window {2, 4, 7} has difference 5. Add 2: {2, 4, 7, 2}, length 4.
ComplexityO(n) time, O(n) space.

from collections import deque

def longest_subarray(nums, limit):
    big, small = deque(), deque()    # indexes: values decreasing / increasing
    left = best = 0
    for right, x in enumerate(nums):
        while big and nums[big[-1]] <= x:
            big.pop()
        big.append(right)
        while small and nums[small[-1]] >= x:
            small.pop()
        small.append(right)
        while nums[big[0]] - nums[small[0]] > limit:   # too uneven: shrink from the left
            left += 1
            if big[0] < left:
                big.popleft()
            if small[0] < left:
                small.popleft()
        best = max(best, right - left + 1)
    return best

COMMON MISTAKE
Shrinking the window but not the deques. After left += 1, the index that left may still be at the front of a deque, so max - min keeps using a value from outside the window. After every move of left, pop each deque front whose index is below left.

Going deeper

  • A stack only pops from the back, so it answers "everything to the left or right". A deque also pops from the front, so it answers "the last k items".
  • DP speed-up: a recurrence like dp[i] = nums[i] + max(dp[i-k..i-1]) (jump at most k steps) needs a window maximum of earlier results; the deque brings it from O(n·k) to O(n).
  • Alternatives for a window maximum: a heap with lazy deletion (O(n log n), simpler), a segment tree (more power than needed), or splitting into blocks of size k with prefix and suffix maxima (O(n), no deque).

Chapter recap

  • A linked list is nodes joined by next pointers. Reading is O(n); inserting or deleting beside a node you hold is O(1). Save the rest of the chain before you change a pointer.
  • Reverse: save next, point back, move prev, move cur. The answer is prev.
  • Fast and slow pointers find the middle (fast ends the list, slow is halfway) and a cycle (fast laps slow). Floyd's second phase finds the cycle entry.
  • A dummy node removes head special cases. Build with tail; return dummy.next. A gap of n between two pointers finds the n-th node from the end.
  • A stack is last in, first out: matching pairs, expressions and undo. A min stack stores the running minimum next to each value.
  • A queue is first in, first out. Use collections.deque with popleft, never list.pop(0).
  • A monotonic stack keeps indexes in sorted order; each pop is an answer. Next greater, daily temperatures and the histogram are the same loop. It is O(n) because each index is pushed once and popped at most once.
  • A monotonic deque of indexes gives the window maximum: pop weaker items from the back, expire the front, read the front.
  • Always store indexes in monotonic structures, decide strict or non-strict comparison on purpose, and test empty, single-node and all-equal inputs.

Problem 5.P.6 (easy) A string holds only ( and ). Return the minimum number of parentheses to insert to make it valid. Example: "()))((" needs 4.

Answer: only one kind of bracket, so a counter replaces the stack. Count unmatched openers (bal) and closers that arrived with nothing to match (need). The answer is their sum.

def min_add(s):
    need = bal = 0
    for ch in s:
        if ch == "(":
            bal += 1
        elif bal:
            bal -= 1            # this closer matches an earlier opener
        else:
            need += 1           # a closer with nothing to match: one "(" must be added
    return need + bal           # plus one ")" for each unmatched opener

Problem 5.P.7 (medium) Evaluate a Reverse Polish Notation list such as ["4","13","5","/","+"], which means 4 + 13 / 5. Division truncates toward zero.

Answer: push numbers; for an operator pop b (right operand) first, then a, and push a op b. Popping in the wrong order turns 5 - 2 into 2 - 5. Use int(a / b), because // floors toward minus infinity.

def eval_rpn(tokens):
    stack = []
    for t in tokens:
        if t in ("+", "-", "*", "/"):
            b = stack.pop()
            a = stack.pop()
            stack.append({"+": a + b, "-": a - b, "*": a * b,
                          "/": int(a / b) if t == "/" else 0}[t])
        else:
            stack.append(int(t))
    return stack[0]

assert eval_rpn(["5", "2", "-"]) == 3 and eval_rpn(["7", "-2", "/"]) == -3

Problem 5.P.8 (medium) Build a queue from two stacks, with amortised O(1) operations.

Answer: an inbox stack takes pushes. An outbox stack serves pops. Pour the inbox into the outbox only when the outbox is empty: pouring reverses the order, so the oldest item ends on top. Each item moves at most once, hence amortised O(1).

class QueueFromStacks:
    def __init__(self):
        self.inbox, self.outbox = [], []

    def push(self, x):
        self.inbox.append(x)

    def pop(self):
        if not self.outbox:
            while self.inbox:
                self.outbox.append(self.inbox.pop())
        return self.outbox.pop()

q = QueueFromStacks()
for x in (1, 2, 3):
    q.push(x)
first = q.pop()
q.push(4)
print(first, q.pop(), q.pop(), q.pop())
1 2 3 4

Problem 5.P.9 (medium) Reverse the nodes from position left to right (1-indexed) of a linked list.

Answer: use a dummy head, walk to the node before the segment, then right - left times move the node after the segment's first node to the front of the segment. For 1..5 with (2, 4) the list goes 1,3,2,4,5 then 1,4,3,2,5.

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def build(a):
    head = None
    for v in reversed(a):
        head = ListNode(v, head)
    return head

def to_list(h):
    out = []
    while h:
        out.append(h.val)
        h = h.next
    return out

def reverse_between(head, left, right):
    dummy = ListNode(0, head)
    before = dummy
    for _ in range(left - 1):
        before = before.next
    first = before.next
    for _ in range(right - left):
        moving = first.next
        first.next = moving.next
        moving.next = before.next
        before.next = moving
    return dummy.next

Problem 5.P.12 (medium) Stock span. For each day, count the consecutive days ending today (including today) whose price is at most today's price. For [100, 80, 60, 70, 60, 75, 85] the spans are [1, 1, 1, 2, 1, 4, 6].

Answer: this is "previous strictly greater". Keep a stack of indexes with decreasing prices. Pop prices at most today's. What remains on top is the previous greater day, so the span is i - top (or i + 1 if the stack is empty).

def stock_span(prices):
    spans, stack = [], []
    for i, p in enumerate(prices):
        while stack and prices[stack[-1]] <= p:
            stack.pop()
        spans.append(i - stack[-1] if stack else i + 1)
        stack.append(i)
    return spans

Problem 5.P.13 (medium) In a circular array, return the next strictly greater value for each item, or -1. For [1, 2, 1] the answer is [2, -1, 2].

Answer: loop over 2n positions using i % n and push indexes only during the first lap. The second lap lets items near the end see the start.

def next_greater_circular(nums):
    n = len(nums)
    answer, stack = [-1] * n, []
    for i in range(2 * n):
        x = nums[i % n]
        while stack and nums[stack[-1]] < x:
            answer[stack.pop()] = x
        if i < n:
            stack.append(i)
    return answer

Problem 5.P.14 (medium) Remove exactly k digits from a number string so the result is as small as possible, without leading zeros ("0" if empty). Example: "1432219", k = 3 gives "1219".

def remove_k_digits(num, k):
    stack = []
    for d in num:
        while k and stack and stack[-1] > d:
            stack.pop()
            k -= 1
        stack.append(d)
    if k:
        stack = stack[:-k]
    return "".join(stack).lstrip("0") or "0"

Problem 5.P.15 (medium) Decode strings of the form k[text], which repeat text k times, possibly nested. "3[a2[c]]" becomes "accaccacc".

Answer: when you see [, push the text built so far and the repeat count, then start fresh. When you see ], pop them and set cur = previous + cur * count.

def decode(s):
    stack, cur, num = [], "", 0
    for ch in s:
        if ch.isdigit():
            num = num * 10 + int(ch)
        elif ch == "[":
            stack.append((cur, num))
            cur, num = "", 0
        elif ch == "]":
            prev, k = stack.pop()
            cur = prev + cur * k
        else:
            cur += ch
    return cur

Problem 5.P.16 (medium to hard) Asteroids move along a line. The sign is the direction (positive right, negative left) and the size is the absolute value. All move at the same speed. When two meet, the smaller explodes; equal sizes both explode. Return what survives. [10, 2, -5] gives [10].

Answer: a stack of survivors. A collision can only happen when the top moves right and the new asteroid moves left. Keep resolving while that is true.

def asteroid_collision(asteroids):
    stack = []
    for a in asteroids:
        alive = True
        while alive and a < 0 and stack and stack[-1] > 0:
            if stack[-1] < -a:
                stack.pop()              # the right-mover is smaller: it explodes
            else:
                if stack[-1] == -a:
                    stack.pop()          # both explode
                alive = False
        if alive:
            stack.append(a)
    return stack

Problem 5.P.17 (hard) Reorder a list L0 → L1 → ... → Ln-1 into L0 → Ln-1 → L1 → Ln-2 → ... in place. 1..5 becomes 1,5,2,4,3.

Answer: three known pieces. Find the middle with fast and slow (ending on the left middle). Cut the list and reverse the second half. Interleave the two halves.

class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def build(a):
    head = None
    for v in reversed(a):
        head = ListNode(v, head)
    return head

def to_list(h):
    out = []
    while h:
        out.append(h.val)
        h = h.next
    return out

def reorder(head):
    if not head or not head.next:
        return head
    slow, fast = head, head.next
    while fast and fast.next:                  # slow ends on the left middle
        slow, fast = slow.next, fast.next.next
    second, slow.next = slow.next, None        # cut
    prev = None
    while second:                              # reverse the second half
        second.next, prev, second = prev, second, second.next
    first, second = head, prev
    while second:                              # interleave
        a, b = first.next, second.next
        first.next, second.next = second, a
        first, second = a, b
    return head

assert to_list(reorder(build([1, 2, 3, 4]))) == [1, 4, 2, 3]
print(to_list(reorder(build([1, 2, 3, 4, 5]))))
[1, 5, 2, 4, 3]

Problem 5.P.18 (hard) A grid of "0" and "1" characters: find the area of the largest rectangle containing only 1s. For ["10100","10111","11111","10010"] the answer is 6.

Answer: treat each row as the floor of a histogram: the height of a column is the number of consecutive 1s ending at that row. Run the histogram solution (Problem 5.7.3) per row: O(rows × cols).

def largest_rectangle(heights):
    stack, best = [], 0
    for i, h in enumerate(heights + [0]):
        while stack and heights[stack[-1]] >= h:
            height = heights[stack.pop()]
            left = stack[-1] if stack else -1
            best = max(best, height * (i - left - 1))
        stack.append(i)
    return best

def maximal_rectangle(grid):
    heights = [0] * len(grid[0])
    best = 0
    for row in grid:
        heights = [h + 1 if c == "1" else 0 for h, c in zip(heights, row)]
        best = max(best, largest_rectangle(heights))
    return best

Problem 5.P.19 (hard) Given integers (possibly negative) and a target k, return the length of the shortest non-empty subarray with sum at least k, or -1. For [2, -1, 2] and k = 3 the answer is 3.

Answer: a sliding window with two pointers fails because negatives break monotonicity. Use prefix sums P (Chapter 3) and a deque of indexes with increasing P. For each i, pop from the front while P[i] - P[front] >= k (a candidate; the front can never help a later index, because later indexes are further away). Pop from the back while P[back] >= P[i] (the newer, smaller prefix is better for every future subarray). Checked against brute force.

from collections import deque
import random

def shortest_subarray(nums, k):
    prefix = [0]
    for x in nums:
        prefix.append(prefix[-1] + x)
    dq, best = deque(), len(nums) + 1
    for i, p in enumerate(prefix):
        while dq and p - prefix[dq[0]] >= k:
            best = min(best, i - dq.popleft())
        while dq and prefix[dq[-1]] >= p:
            dq.pop()
        dq.append(i)
    return best if best <= len(nums) else -1

def brute(nums, k):
    best = len(nums) + 1
    for i in range(len(nums)):
        total = 0
        for j in range(i, len(nums)):
            total += nums[j]
            if total >= k:
                best = min(best, j - i + 1)
    return best if best <= len(nums) else -1

random.seed(4)
for _ in range(300):
    data = [random.randint(-3, 5) for _ in range(random.randint(1, 10))]
    kk = random.randint(1, 8)
    assert shortest_subarray(data, kk) == brute(data, kk)
print(shortest_subarray([2, -1, 2], 3), shortest_subarray([1, 2], 4))

Problem 5.P.20 (hard, interview) An interviewer says: "Your monotonic stack has a while loop inside a for loop. Isn't that O(n²)? And when would you use a heap instead of a deque for window maximum?"

Answer: it is O(n). Each index is pushed exactly once and popped at most once, so the total number of pops over the whole run is at most n, and the total work is at most about 2n steps even though one iteration may pop many items. For window maximum, the deque is O(n) time and O(k) space but needs a fixed window that moves forward. A heap with lazy deletion costs O(n log n), but it also works when removals are arbitrary, not only from the left end, and when you need the top few values, not just the maximum.
