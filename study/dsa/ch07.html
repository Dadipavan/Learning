7.1 Binary Tree Anatomy

IDEA IN ONE SENTENCE
A binary tree is a set of boxes (nodes) where every box points to at most two boxes below it, called its left child and right child. Analogy: an org chart in which every manager has at most two direct reports.

How to recognise it

  • The input is a root node with .left and .right, not a list.
  • The words "subtree", "ancestor", "descendant", "leaf", "path from root" appear.
  • The structure is hierarchical: a node has exactly one parent (except the top one).
  • A question says "for every node" or "at each level".

The words you need

How to read it: start at the blue root and walk down. Each step down is one edge, so depth goes up by one. A node with no lines going further down (green) is a leaf. The height of the whole tree is the number of edges on the longest downward walk, here 8 to 3 to 6 to 4, which is 3 edges.

The template: a node class and a quick builder

Interview platforms give you a TreeNode class. We call ours Node. The function tree() is a tiny helper for this book that builds a tree from nested tuples, so every example is short. In an interview you write the class only; they build the tree for you.

class Node:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def tree(t):
    # Build a tree from nested tuples: int = leaf, (val, left, right), None = empty
    if t is None:
        return None
    if isinstance(t, int):
        return Node(t)
    return Node(t[0], tree(t[1]), tree(t[2]))

def count(n):
    # How many nodes? Empty tree has 0; otherwise 1 + both sides.
    return 0 if n is None else 1 + count(n.left) + count(n.right)

def height(n):
    # Height in EDGES. An empty tree gets -1 so a single node gets 0.
    if n is None:
        return -1
    return 1 + max(height(n.left), height(n.right))

root = tree((8, (3, 1, (6, 4, 7)), (10, None, (14, 13, None))))
print("root value:", root.val)
print("left child of root:", root.left.val)
print("right child of root:", root.right.val)
print("left child of 10:", root.right.left)
print("nodes:", count(root), "height:", height(root))
assert count(root) == 9 and height(root) == 3

Notice the pattern in count and height. Both start with "if the node is None, return a fixed answer", then call themselves on the left and right child, then combine. That three-part shape is the heart of this whole chapter.

COMMON MISTAKE
Mixing up height counted in edges and in nodes. Wrong: returning 0 for an empty tree and then saying a single node has height 0 (the two rules clash: a lone node would come out as 1). Right: pick one rule and keep it. Edges: empty = -1, single node = 0. Nodes: empty = 0, single node = 1. Many interview problems (such as "maximum depth") count nodes. Read the statement, then choose your base case to match.

Shapes you will hear about

Why does balance matter? A tree with n nodes has height at least about log2(n) and at most n - 1. The code below prints both extremes so you can see how big the gap is.

Going deeper

  • Recursion depth. Python allows about 1,000 nested calls by default. A skewed tree with 5,000 nodes breaks a recursive height, as shown below. Interviewers usually give you trees that fit, but when they ask "what if the tree is a million nodes in a line?", the answer is: switch to an iterative version with an explicit stack (next section).
  • Real trees. File systems, the HTML DOM, JSON documents, decision trees in machine learning, and database indexes (B-trees, which are wide balanced trees with many children per node) are all trees. Knowing the binary case makes all of them readable.

7.2 Depth-First Search: Preorder, Inorder, Postorder

IDEA IN ONE SENTENCE
Depth-first search (DFS) goes as deep as it can down one branch, then backs up and tries the next. Analogy: exploring a cave system: take the left tunnel until it dead-ends, walk back to the last fork, take the other tunnel.

How to recognise it

  • You must look at every node and the answer depends on a path or a subtree.
  • The answer for a node can be built from the answers for its two children.
  • Words: "path", "root-to-leaf", "subtree", "ancestor", "depth", "height", "same tree", "mirror".
  • Order matters: "process parents before children" (preorder), "sorted order of a BST" (inorder), "children before parent" (postorder).

One walk, three moments to act

Every DFS visits each node exactly once but passes through it three times: when it arrives, after returning from the left child, and after returning from the right child. The three classic traversals are named after the moment you "visit" (record) the node.

NameOrderMnemonicTypical use
Preordernode, left, right"Pre" = node before childrenCopy a tree, serialize it, print a directory listing
Inorderleft, node, right"In" = node in the middleRead a BST in sorted order
Postorderleft, right, node"Post" = node after childrenDelete a tree, compute heights and sizes (need the children's answers first)

How to read it: in each panel, follow the numbers 1, 2, 3 and so on. Preorder records 8 first because the root comes before its children. Inorder records 1 first because it walks as far left as possible before recording anything. Postorder records the root 8 last. Notice that inorder gives 1 3 4 6 7 8 10 13 14, which is sorted. That is not an accident, and we use it in 7.5.

Template: recursive

The three versions differ by one line: where the out.append sits.

class Node:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def tree(t):
    # Build a tree from nested tuples: int = leaf, (val, left, right), None = empty
    if t is None:
        return None
    if isinstance(t, int):
        return Node(t)
    return Node(t[0], tree(t[1]), tree(t[2]))

def preorder(n, out):
    if n is None:            # base case: nothing to visit
        return
    out.append(n.val)        # VISIT first
    preorder(n.left, out)
    preorder(n.right, out)

def inorder(n, out):
    if n is None:
        return
    inorder(n.left, out)
    out.append(n.val)        # VISIT in the middle
    inorder(n.right, out)

def postorder(n, out):
    if n is None:
        return
    postorder(n.left, out)
    postorder(n.right, out)
    out.append(n.val)        # VISIT last

root = tree((8, (3, 1, (6, 4, 7)), (10, None, (14, 13, None))))
for f in (preorder, inorder, postorder):
    out = []
    f(root, out)
    print(f.__name__.ljust(10), out)
assert inorder.__name__ == "inorder"

Template: iterative with a stack

Recursion uses the computer's hidden call stack. An iterative version uses a stack you create yourself, which avoids the recursion limit. Preorder is the simplest: push the right child first so the left child comes out first.

class Node:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def tree(t):
    # Build a tree from nested tuples: int = leaf, (val, left, right), None = empty
    if t is None:
        return None
    if isinstance(t, int):
        return Node(t)
    return Node(t[0], tree(t[1]), tree(t[2]))

def preorder_iter(root):
    out, stack = [], [root] if root else []
    while stack:
        n = stack.pop()
        out.append(n.val)                 # visit when popped
        if n.right: stack.append(n.right) # right goes in first...
        if n.left:  stack.append(n.left)  # ...so left comes out first
    return out

def inorder_iter(root):
    out, stack, cur = [], [], root
    while cur or stack:
        while cur:                        # slide down the left edge
            stack.append(cur)
            cur = cur.left
        cur = stack.pop()                 # leftmost unvisited node
        out.append(cur.val)               # visit it
        cur = cur.right                   # then deal with its right side
    return out

def postorder_iter(root):
    # Trick: "node, right, left" reversed is "left, right, node".
    out, stack = [], [root] if root else []
    while stack:
        n = stack.pop()
        out.append(n.val)
        if n.left:  stack.append(n.left)
        if n.right: stack.append(n.right)
    return out[::-1]

root = tree((8, (3, 1, (6, 4, 7)), (10, None, (14, 13, None))))
print(preorder_iter(root))
print(inorder_iter(root))
print(postorder_iter(root))
assert preorder_iter(root) == [8, 3, 1, 6, 4, 7, 10, 14, 13]

Why does this work? The stack always holds the nodes whose left side we are still exploring. The top of the stack is the next node in sorted order. Popping it is "return from the left subtree"; moving to the right child is "now do the right subtree".

COMMON MISTAKE
Forgetting the base case, or checking the child instead of the node. Wrong: def depth(n): return 1 + max(depth(n.left), depth(n.right)). It crashes with AttributeError: 'NoneType' object has no attribute 'left' at the first leaf. Right: start with if n is None: return 0. Put the check for None on the node you were handed, once, at the top. Then the code below never needs if n.left guards.

The universal DFS return-value template

Almost every tree problem fits this skeleton. Learn it once and you can write 80 percent of tree solutions in under two minutes.

def solve(node):
    if node is None:
        return BASE_VALUE               # answer for an empty tree
    left = solve(node.left)             # trust recursion: answer for left subtree
    right = solve(node.right)           # answer for right subtree
    return COMBINE(node.val, left, right)

"Trust recursion" means: do not try to picture all the levels at once. Assume the call on each child already gives the right answer for that child's subtree, then ask only "how do I combine two such answers with this node?"

Problem 7.2.1 (easy) The maximum depth of a binary tree is the number of nodes on the longest path from the root down to a leaf. Return it. An empty tree has depth 0.

IdeaThe depth of a tree is 1 (for the root) plus the deeper of its two subtrees.
Brute forceList every root-to-leaf path and take the longest. There are up to n/2 leaves and each path is up to n long, so a naive version can cost O(n2) time and space on some shapes.
Better approachReturn-value DFS. Base case 0, combine with 1 + max(left, right). Each node is touched once.
CodeBelow.
Dry runLeaf 4: 1 + max(0, 0) = 1. Node 6: 1 + max(1, 1) = 2. Node 3: 1 + max(depth(1) = 1, depth(6) = 2) = 3. Node 14: 1 + max(depth(13) = 1, 0) = 2. Node 10: 1 + max(0, 2) = 3. Root 8: 1 + max(3, 3) = 4.

Going deeper

  • Recursion versus an explicit stack. They are the same walk. Recursion hides the stack; iterative code shows it. Interviewers like it when you can do both: write recursive first, then say "if depth is a concern I would convert to an explicit stack".
  • Parameters going down versus values coming up. In 7.2.1 information flows up (the depth). In path-sum problems (7.4 and the practice set) it flows down (the remaining sum). Many hard problems use both.

7.3 Breadth-First Search: Level Order

IDEA IN ONE SENTENCE
Breadth-first search (BFS) visits the tree one whole level at a time, using a queue (first in, first out). Analogy: a ripple in a pond: it reaches everything at distance 1, then everything at distance 2, and so on.

How to recognise it

  • The question says "level by level", "each row", "right side view", "zigzag", "width of the tree".
  • You need the closest something: minimum depth, nearest leaf, fewest steps.
  • The answer is a list of lists, one inner list per level.

How to read it: each colour is one level. BFS finishes the blue level before the orange level, and so on. Compare with DFS, which dives down the left side first.

Template

The trick that makes "one list per level" easy: at the start of each round, len(queue) is exactly the number of nodes on the current level. Process that many nodes, and anything you add during the round belongs to the next level.

class Node:
    def __init__(self, val, left=None, right=None):
        self.val, self.left, self.right = val, left, right

def tree(t):
    # Build a tree from nested tuples: int = leaf, (val, left, right), None = empty
    if t is None:
        return None
    if isinstance(t, int):
        return Node(t)
    return Node(t[0], tree(t[1]), tree(t[2]))
from collections import deque

def level_order(root):
    if root is None:
        return []
    result, queue = [], deque([root])
    while queue:
        size = len(queue)              # nodes on THIS level, frozen now
        level = []
        for _ in range(size):
            node = queue.popleft()     # O(1), unlike list.pop(0)
            level.append(node.val)
            if node.left:
                queue.append(node.left)    # next level
            if node.right:
                queue.append(node.right)
        result.append(level)
    return result

root = tree((8, (3, 1, (6, 4, 7)), (10, None, (14, 13, None))))
print(level_order(root))
assert level_order(root) == [[8], [3, 10], [1, 6, 14], [4, 7, 13]]
assert level_order(None) == []

COMMON MISTAKE
Using a list as a queue, or reading len(queue) inside the loop. Wrong: queue.pop(0) shifts every remaining item, so each pop costs O(n) and the whole BFS can become O(n2). Right: collections.deque and popleft(), O(1) each. Also wrong: for _ in range(len(queue)) is fine (the range is computed once), but while len(queue) > 0 used as the level loop mixes levels together because children are added while you loop. Freeze size first.

Problem 7.3.1 (medium) Return the values of the nodes you would see if you stood on the right side of the tree and looked across: for each level, the last node from the left.

IdeaRun level order. For each level, keep only the last value. The right-side view is "the last node of every level".
Brute forceBuild the full list of lists, then take level[-1] from each. Correct, but stores every value: O(n) extra space.
Better approachSame BFS, but record only the node when i == size - 1. Space is the widest level, not the whole tree. (A DFS that visits right first and records the first node seen at each new depth gives the same answer.)

def right_side_view(root):

        return []
    view, queue = [], deque([root])

Going deeper

  • Memory shape. DFS needs space proportional to the height; BFS needs space proportional to the widest level. A very wide shallow tree favours DFS; a very deep thin tree favours BFS.
  • Shortest path. BFS finds the fewest-edges path in any graph where every edge costs the same. Trees are graphs, and Chapter 8 uses the exact same loop on grids and networks.

7.4 Return-Value Recursion: Balanced, Diameter, Path Sum, LCA, Serialize

IDEA IN ONE SENTENCE
Ask each subtree one small question, get back one small answer, and combine the two answers at the parent. Analogy: a manager asks each team lead "how many people are in your team?" and adds the two replies plus themselves.

How to recognise it

  • The answer is a single number or yes/no about the whole tree, but it depends on facts about subtrees.
  • The word "any path" or "every node" appears (balanced? diameter? best path?).
  • You catch yourself computing the height inside a loop over nodes. That is a sign to compute it once, bottom-up.

Template: return one thing, record another

def solve(root):
    best = 0                            # side answer, updated as we go
    def dfs(node):
        nonlocal best
        if node is None:
            return BASE
        l, r = dfs(node.left), dfs(node.right)
        best = max(best, CANDIDATE(l, r))   # best answer that turns at this node
        return EXTENDABLE(l, r)             # what the parent is allowed to extend
    dfs(root)
    return best

The key insight: the value a node returns upward and the best answer that passes through the node are two different things. A path that bends at a node cannot be extended further up by the parent, so the parent only gets the one-sided version.

COMMON MISTAKE
Returning the candidate answer instead of the extendable one. Wrong (diameter): return left + right + 2 from the helper. The parent then adds the bent path to its own other side, which is not a real path. Right: update best with left + right + 2 but return 1 + max(left, right). The same bug appears in "maximum path sum".

    return height(root) != FAIL

Problem 7.4.4 (hard) Serialize a binary tree into a string, and deserialize the string back into an identical tree.

IdeaWrite the tree in preorder and put a marker # for every empty child. The markers make the shape unambiguous. To rebuild, read the tokens in the same order: take a token, if it is # return None, else make a node and let the next tokens build its left and then its right subtree.
Brute forceStore only the values (say, inorder). Different shapes share the same inorder list, so the tree cannot be rebuilt. You would need two traversals (preorder plus inorder) and unique values: more work and fragile.
Better approachPreorder with null markers: one pass each way, O(n) time. An iterator over the tokens is the cleanest way to keep the "next token" position shared across recursive calls.

        node = Node(int(tok))
        node.left = build()              # left subtree uses the next tokens
        node.right = build()
        return node
    return build()

Going deeper

  • Bottom-up beats top-down. Whenever you see O(n2) from "compute height at every node", the fix is to return height from the recursion. This is also the shape behind maximum path sum, which the practice set asks you to solve.
  • Two jobs per node. Diameter, balanced and max path sum all return one value up and track another on the side. Naming those two things before coding prevents most bugs.

7.5 Binary Search Trees

IDEA IN ONE SENTENCE
A binary search tree (BST) is a binary tree where, for every node, everything in its left subtree is smaller and everything in its right subtree is larger. Analogy: the "higher or lower?" guessing game: each answer throws away half of the remaining possibilities.

How to recognise it

  • The statement says "binary search tree" or "BST". Then use the ordering; ignoring it is the number-one wasted opportunity.
  • Words: "sorted", "kth smallest", "successor", "range", "validate", "closest value".
  • You need search, insert and delete in about log n steps when the tree is balanced.

How to read it: on the left, searching for 7 starts at the root. 7 is smaller than 8, so everything on the right of 8 is ruled out. At 3, 7 is bigger, so the whole left of 3 is ruled out. Four nodes visited out of nine. On the right, node 4 is the left child of 8, and 4 is less than 8, so that single parent-child check passes. But 4 lives on the right side of the root 5, so it must be greater than 5. It is not, so the tree is not a BST.

The rules, stated precisely

  • For each node with value v: every value in its left subtree is < v and every value in its right subtree is > v (we assume no duplicates; if duplicates are allowed, the problem states which side they go to).
  • Consequence 1: an inorder traversal visits the values in increasing order.
  • Consequence 2: the minimum is the leftmost node, the maximum is the rightmost node.
  • Cost: search, insert and delete take O(h) time. The height h is about log n if the tree is balanced and up to n if it is a chain.

def search(root, key):
    cur = root
    while cur:
        if key == cur.val:
            return cur
        cur = cur.left if key < cur.val else cur.right   # ordering throws half away
    return None

def insert(root, key):
    # Returns the (possibly new) root of this subtree. USE the return value.
    if root is None:
        return Node(key)
    if key < root.val:
        root.left = insert(root.left, key)
    elif key > root.val:
        root.right = insert(root.right, key)
    return root                                          # equal keys: ignore

def inorder(n):
    return [] if n is None else inorder(n.left) + [n.val] + inorder(n.right)

Problem 7.5.1 (medium) Decide whether a binary tree is a valid BST.

IdeaEach node has an allowed open interval (low, high). The root may be anything. Going left, the node's value becomes the new upper bound. Going right, it becomes the new lower bound.
Brute forceAt each node scan its whole left subtree for a value that is too big, and its right subtree for one that is too small. That is O(n) per node, O(n2) in the worst case.

Problem 7.5.2 (medium) Delete a key from a BST so that the result is still a BST. Return the new root.

def delete(node, key):
    if node is None:
        return None                            # key not found
    if key < node.val:
        node.left = delete(node.left, key)     # reconnect with the returned subtree
    elif key > node.val:
        node.right = delete(node.right, key)
    else:

        if node.right is None:

        succ = node.right                      # 2 children: smallest in right subtree

            succ = succ.left
        node.val = succ.val
        node.right = delete(node.right, succ.val)
    return node

def kth_smallest(root, k):
    stack, cur = [], root
    while cur or stack:
        while cur:
            stack.append(cur)
            cur = cur.left
        cur = stack.pop()
        k -= 1
        if k == 0:                  # this is the k-th node in sorted order
            return cur.val
        cur = cur.right
    return None                     # k was larger than the number of nodes

Going deeper

  • Balance. Plain BSTs degrade to chains on sorted input. Self-balancing trees (AVL, red-black) fix the height with rotations. You almost never code them in interviews; know the name and the promise: O(log n) guaranteed.
  • Python has no built-in BST. For "sorted collection with fast insert" people use a sorted list with bisect (insert is O(n) because of shifting, but it is fast in practice) or the third-party sortedcontainers package.
  • Order statistics. If you must answer many "k-th smallest" queries on a changing tree, store the size of each subtree in every node. Then you can pick left, node or right in O(h) without walking all k nodes.

7.6 Heaps and Priority Queues

IDEA IN ONE SENTENCE
A heap keeps the smallest item (or the largest) always at the top, so you can see it in O(1) and remove it in O(log n). Analogy: the triage desk in a hospital: whoever arrives, the most urgent patient is always called next, and nobody sorts the whole waiting room.

A priority queue is the idea: "give me the item with the best priority". A heap is the standard way to build one. A min-heap keeps the smallest at the top. A max-heap keeps the largest on top. In a min-heap every parent is less than or equal to its children. Nothing is promised between siblings or cousins, so a heap is not sorted.

How to recognise it

  • "The K largest / K smallest / K most frequent / K closest".
  • "Repeatedly take the smallest (or best) and then add more items".
  • "Merge K sorted things".
  • "Median of a stream" or "k-th largest in a stream" (data keeps arriving).
  • "Schedule by priority or deadline", "always process the cheapest next" (Dijkstra, Chapter 8).

How to read it: the root 2 is the smallest value. Every parent is smaller than its two children (5 has 9 and 6; 3 has 8 and 4). The tree is complete: every level is full except possibly the last, which fills from the left. That shape is the reason an array works. The node at index i has its children at 2i+1 and 2i+2, and its parent at (i-1)//2. Check with 3 at index 2: children at indices 5 and 6, values 8 and 4. Correct.

The two moves: sift up and sift down

  • Push: put the new value at the end (the next free slot keeps the shape complete), then swap it with its parent while it is smaller. This is sift up. At most one swap per level: O(log n).
  • Pop: take the root as the answer. Move the last item into the root hole, then swap it with its smaller child while it is bigger than that child. This is sift down. O(log n).

How to read it: panel 1 puts the red 1 at the first free slot, below 9. Since 1 < 9, swap (panel 2). Now it sits below 5, and 1 < 5, swap (panel 3). Below 2, swap again (panel 4). It reached the root, so it stops. The array shown under each panel changes only by those swaps.

class MinHeap:
    def __init__(self, items=None):
        self.a = list(items or [])      # assume items already form a valid heap
        self.log = []

    def push(self, x):
        a = self.a
        a.append(x)                      # 1. put at the end
        i = len(a) - 1
        while i > 0:
            p = (i - 1) // 2             # parent index
            if a[p] <= a[i]:
                break
            self.log.append(f"swap index {i} (value {a[i]}) with parent index {p} (value {a[p]})")
            a[i], a[p] = a[p], a[i]      # 2. sift up
            i = p

    def pop(self):
        a = self.a
        top = a[0]
        last = a.pop()                   # remove the last item...
        if a:
            a[0] = last                  # ...and drop it in the root hole
            i, n = 0, len(a)
            while True:                  # sift down
                l, r, m = 2 * i + 1, 2 * i + 2, i
                if l < n and a[l] < a[m]: m = l
                if r < n and a[r] < a[m]: m = r
                if m == i:
                    break
                self.log.append(f"swap index {i} (value {a[i]}) with child index {m} (value {a[m]})")
                a[i], a[m] = a[m], a[i]
                i = m
        return top

Problem 7.6.1 (easy) Return the k-th largest value in a list of numbers (counting duplicates, so the 2nd largest of [5, 5, 3] is 5).

IdeaKeep a min-heap holding the k largest values seen so far. Its top is the k-th largest. When a new value is bigger than the top, it deserves a place: swap it in.
Brute forceSort in descending order and take index k - 1: O(n log n) time, and it needs all data in memory.
Better approachA heap of size k: O(n log k) time and O(k) space. It also works on a stream where you cannot sort.

import heapq

def kth_largest(nums, k):
    heap = []                                   # min-heap of the k largest so far
    for x in nums:
        if len(heap) < k:
            heapq.heappush(heap, x)
        elif x > heap[0]:
            heapq.heapreplace(heap, x)          # pop the smallest, push x
    return heap[0]

Problem 7.6.3 (medium) You are given k sorted linked lists. Merge them into one sorted linked list. For display, return the values as a Python list.

IdeaAt any moment the next output value is the smallest among the current heads of the k lists. Keep those k heads in a min-heap. Pop the smallest, attach it to the output, push that list's next node.
Brute forceDump all N values into one Python list and sort: O(N log N). It ignores that each list is already sorted. Merging lists one after another costs O(N k) in the worst case.
Better approachHeap of at most k nodes: each of the N nodes is pushed once and popped once, each in O(log k). Total O(N log k).
CodeBelow. The middle number in each tuple is the tie-breaker that stops Python comparing two nodes.
Dry runLists [1, 4, 5], [1, 3, 4], [2, 6]. Heap holds heads (1, list 0), (1, list 1), (2, list 2). Pop (1, list 0), output 1, push its next 4. Pop (1, list 1), output 1, push 3. Pop 2, push 6. Pop 3, push 4... and so on until the heap is empty. Output: 1 1 2 3 4 4 5 6.
ComplexityO(N log k) time, O(k) extra space (the nodes are relinked, not copied).
Edge casesEmpty input list; some lists empty (skip them when seeding the heap); k = 1.
import heapq

class ListNode:
    def __init__(self, val=0, next=None):
        self.val, self.next = val, next

def make(values):
    head = None
    for v in reversed(values):
        head = ListNode(v, head)
    return head

def to_list(head):
    out = []
    while head:
        out.append(head.val)
        head = head.next
    return out

def merge_k(lists):
    heap = []
    for i, node in enumerate(lists):
        if node:                                    # skip empty lists

        tail.next = node
        tail = node
        if node.next:
            heapq.heappush(heap, (node.next.val, i, node.next))
    return dummy.next

Problem 7.6.4 (hard) Numbers arrive one at a time. After each arrival, report the median of everything seen so far. The median is the middle value of the sorted data, or the average of the two middle values when the count is even.

IdeaSplit the sorted data into a lower half and an upper half. Keep the lower half in a max-heap (its top is the biggest of the small numbers) and the upper half in a min-heap (its top is the smallest of the big numbers). The median sits at the two tops. Keep the halves equal in size, or the lower half one bigger.
Brute forceAfter each arrival, sort everything and read the middle: O(n log n) per arrival, O(n2 log n) total. Or keep a sorted list with bisect.insort: O(n) per insert because of shifting.
Better approachTwo heaps: add in O(log n), read the median in O(1).
CodeBelow.
Dry runStream 5, 2, 8. Add 5: it passes through lower to upper and the balance step moves it back, so lower {5}, upper {}. Median 5.0. Add 2: lower becomes {5, 2}, its biggest (5) moves to upper, giving lower {2}, upper {5}. Median (2 + 5) / 2 = 3.5. Add 8: lower becomes {2, 8}, its biggest (8) moves up, so upper is {5, 8}, which is too big, so 5 moves back down: lower {2, 5}, upper {8}. Median 5.0.
Complexityadd: O(log n). median: O(1). Space O(n).
Edge casesFirst element. Equal values. Negative numbers (the max-heap stores negatives, so negate carefully). Even versus odd counts.

How to read it: the sorted data is 1, 2, 3, 5, 8, 9. The left three (blue) live in a max-heap whose top, 3, is their largest. The right three (orange) live in a min-heap whose top, 5, is their smallest. The median is halfway between the two tops: (3 + 5) / 2 = 4.0. If the counts were odd, the lower heap would hold one extra and its top alone would be the median.

import heapq

class MedianFinder:
    def __init__(self):
        self.low = []     # max-heap (store negatives): the smaller half
        self.high = []    # min-heap: the larger half

    def add(self, x):
        # 1. Always go through the lower half first...
        heapq.heappush(self.low, -x)
        # 2. ...then move its biggest to the upper half, so every low <= every high.
        heapq.heappush(self.high, -heapq.heappop(self.low))
        # 3. Keep sizes balanced: low may have one extra, never fewer.
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))

    def median(self):
        if len(self.low) > len(self.high):
            return float(-self.low[0])
        return (-self.low[0] + self.high[0]) / 2

Going deeper

  • Why heapify is O(n), not O(n log n). Half the nodes are leaves and need no work. A quarter are one level above the leaves and move at most one step, an eighth at most two steps, and so on. The total work is n/4 + 2 * n/8 + 3 * n/16 + ... which adds up to at most about n. Building by n separate pushes is the slower O(n log n).
  • No decrease-key in heapq. To change a priority, push a new entry and ignore the old one when it pops (lazy deletion). Dijkstra in Chapter 8 does this.
  • Top-K choices. Sorting is O(n log n). A size-k heap is O(n log k). Quickselect finds the k-th element in O(n) on average but changes the input and cannot handle streams. Pick by constraints: stream or tiny k means heap.
  • Heaps are not for search. Finding an arbitrary value in a heap is O(n). If you need both "min" and "find or delete arbitrary", think BST or a heap plus a hash set.

7.7 Tries: Prefix Trees and Autocomplete

IDEA IN ONE SENTENCE
A trie (say "try") stores words letter by letter in a tree, so all words that share a beginning share the same path. Analogy: the thumb index on a paper dictionary: first you go to the letter C, then to CA, then to CAR. Each step narrows the pile.

How to recognise it

  • The words "prefix", "starts with", "autocomplete", "suggest", "dictionary of words".
  • Many lookups against one fixed word list, where a hash set can answer "is this a word?" but not "does any word begin with this?".
  • Searching a grid or text for many words at once (word search II uses a trie to prune).

How to read it: start at the blue root, which stands for the empty prefix. Follow c, then a: you are now at the node for the prefix "ca". It has three children r, t, p, one for each word that continues. Note that "do" is a word and a prefix of "dog": its node is green but still has a child g. That is why every node needs an "a word ends here" flag.

Template

class TrieNode:
    def __init__(self):
        self.children = {}        # letter -> TrieNode
        self.is_end = False       # does a word finish at this node?

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:            # create the path as needed
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def _walk(self, text):
        node = self.root
        for ch in text:
            node = node.children.get(ch)
            if node is None:
                return None                        # path breaks: nothing has this prefix
        return node

    def search(self, word):                        # exact word?
        node = self._walk(word)
        return node is not None and node.is_end

    def starts_with(self, prefix):                 # any word begins with this?
        return self._walk(prefix) is not None

Problem 7.7.1 (medium) Autocomplete: given a list of words and a typed prefix, return up to 3 matching words in alphabetical order.

IdeaWalk down to the node for the prefix. Every word in that subtree starts with the prefix. Collect them with a DFS that visits children in alphabetical order, and stop when you have 3.
Brute forceScan the whole word list and test word.startswith(prefix): O(N * L) per query for N words. Fine for one query, slow for thousands of queries.
Better approachBuild the trie once. A query costs O(P) to reach the prefix node (P = prefix length) plus the work to collect 3 words. A sorted list with bisect is another good answer: O(log N) comparisons to find the first match.
CodeBelow.
Dry runWords: car, cat, cap, do, dog, carbon, cart. Prefix "ca": walk c, a. The children are p, r, t. In alphabetical order the words are cap, then car (and under r: carbon, cart), then cat. The DFS stops at 3 results: cap, car, carbon. Prefix "d": the node for d is not a word; below it, o is a word (do), then its child g gives dog. Prefix "z": the walk fails, so the answer is an empty list.
ComplexityO(P) to reach the prefix, then the DFS explores only until 3 words are found. In the worst case it walks a few long chains, bounded by 3 times the longest word length.

    def __init__(self):
        self.children = {}
        self.is_end = False

def build(words):
    root = TrieNode()
    for w in words:
        node = root
        for ch in w:
            node = node.children.setdefault(ch, TrieNode())
        node.is_end = True
    return root

def autocomplete(root, prefix, limit=3):
    node = root
    for ch in prefix:
        node = node.children.get(ch)
        if node is None:
            return []
    found = []
    def dfs(n, path):
        if len(found) == limit:
            return
        if n.is_end:
            found.append(prefix + path)          # words come out in alphabetical order
        for ch in sorted(n.children):
            dfs(n.children[ch], path + ch)
    dfs(node, "")
    return found

Going deeper

  • Memory. A dictionary per node is flexible but heavy. For lowercase letters only, a fixed list of 26 slots is faster and often smaller. A compressed trie (radix tree) merges chains of single-child nodes into one edge labelled with a string.
  • Trie versus hash set versus sorted list. A hash set answers exact membership in O(L). A trie adds prefix questions. A sorted list plus bisect also answers prefix questions and is the shortest code. In an interview, say which you chose and why.

7.8 Segment Trees and Fenwick Trees: Awareness

IDEA IN ONE SENTENCE
When an array changes and you keep asking for range totals, store partial totals in a tree so both the update and the query take O(log n). Analogy: a company reports sales by branch, then by region, then by country. To change one shop you fix a handful of reports, and to total any group of shops you add a handful of reports.

How to recognise it

  • "Many queries of the form: sum (or min, or max) of the items from index l to r".
  • "And also updates: change the value at index i" between queries.
  • If the array never changes, prefix sums (Chapter 3) are simpler: O(1) per query. A segment tree or Fenwick tree is needed only when updates are mixed in.

How to read it: the entry tree[i] covers the last i & -i cells ending at i. The expression i & -i keeps only the lowest 1 bit of i: for 6 (binary 110) it is 2, so tree[6] covers cells 5 and 6. For 4 (binary 100) it is 4, so tree[4] covers cells 1 to 4. To get the sum of the first 7 cells, add tree[7], then tree[6], then tree[4]: jump from i to i minus its lowest bit until you reach 0 (7, then 6, then 4, then 0).

Problem 7.8.1 (hard, awareness) An array of numbers receives updates ("set position i to value v") and queries ("sum of positions l to r inclusive"). Support both in O(log n) each.

IdeaFenwick: an update adds a difference to every entry that covers position i, moving i up by its lowest bit. A query adds entries while moving down. Range sum = prefix(r) - prefix(l - 1).
Brute forceSlice and sum for each query: O(n) per query, O(n * q) for q queries. Prefix sums make queries O(1) but each update rebuilds in O(n).
Better approachA Fenwick tree (O(log n) for both). A segment tree has the same cost and also handles min and max (see Going deeper).
CodeBelow, checked against the slow method.
Dry runArray [3, 1, 4, 1, 5, 9, 2, 6]. Prefix sum of the first 7: tree[7] = 2, tree[6] = 5 + 9 = 14, tree[4] = 3 + 1 + 4 + 1 = 9, total 25. Direct: 3 + 1 + 4 + 1 + 5 + 9 + 2 = 25. Setting position 3 (value 4) to 14 adds a difference of 10 to tree[3], tree[4] and tree[8], the entries that cover cell 3.
ComplexityBuild O(n log n) with this simple loop (O(n) is possible), query and update O(log n), space O(n).
Edge casesFenwick trees are 1-indexed (index 0 would loop forever). l equal to 1. Updates that set the same value.
import random

class Fenwick:
    def __init__(self, values):
        self.n = len(values)
        self.tree = [0] * (self.n + 1)           # 1-indexed
        self.vals = [0] * (self.n + 1)
        for i, v in enumerate(values, 1):
            self.set(i, v)

    def set(self, i, v):
        delta, self.vals[i] = v - self.vals[i], v
        while i <= self.n:
            self.tree[i] += delta
            i += i & -i                          # move up to the next covering entry

    def prefix(self, i):
        s = 0
        while i > 0:
            s += self.tree[i]
            i -= i & -i                          # drop the lowest bit
        return s

    def range_sum(self, l, r):                   # positions l..r, 1-indexed, inclusive
        return self.prefix(r) - self.prefix(l - 1)

Going deeper

  • Why log n. A number has at most about log2 n bits, and each jump in a Fenwick tree removes or adds one bit.
  • Segment tree. Store the answer for every block of a binary split of the array: a node holds the combined answer of its two children, leaves hold single items. A query touches at most two nodes per level and an update rewrites one root-to-leaf path. It can answer range minimum, range maximum or gcd by replacing + with min, max or gcd, which a Fenwick tree needs an operation that can be undone (subtraction) for its range trick: it fits sums and counts, not min or max.
  • Range updates. "Add 5 to every item from l to r" needs lazy propagation (segment tree) or a pair of Fenwick trees. It is a topic for advanced practice, rarely for a first interview.
  • Counting inversions and "how many smaller numbers appear to my right" are classic Fenwick uses: compress values to ranks, then query prefix counts as you sweep.
  • When not to bother. If the array is static, use prefix sums. If there are few queries, brute force is fine. Mention the structure by name, state its cost, and write the code only if asked.

Chapter recap

  • A binary tree node has a value, a left child and a right child. Height is the number of edges on the longest downward path; depth is the number of edges from the root. Always state whether you count edges or nodes.
  • DFS visits every node once and costs O(n) time and O(h) space. Preorder acts before the children, inorder between them, postorder after them. Inorder on a BST is sorted.
  • BFS uses a deque and freezes len(queue) at the start of each round to separate levels.
  • Most tree problems fit one template: base case for None, recurse on both children, combine. Return what the parent may extend, and record the best "bent" answer on the side (diameter, max path sum).
  • A BST obeys the rule at distance, not just at the parent. Validate with (low, high) bounds. Delete a node with two children by copying the inorder successor.
  • A heap is a complete binary tree stored in an array. Children of i are 2i+1 and 2i+2, the parent is (i-1)//2. heapq is a min-heap only: negate for a max-heap, and use a tie-breaker inside tuples.
  • Top-K: a min-heap of size k for the k largest, O(n log k). Merge K sorted lists: a heap of the k current heads. Running median: a max-heap for the lower half and a min-heap for the upper half.
  • heapify is O(n); n separate pushes are O(n log n).
  • A trie shares prefixes: insert, search and prefix queries cost O(L) for a word of length L. A word exists only if the walk ends on a node with is_end set.
  • Fenwick and segment trees answer range queries with point updates in O(log n); prefix sums are enough when nothing changes.

def max_path_sum(root):

    def gain(n):
        nonlocal best
        if n is None:
            return 0
        l = max(gain(n.left), 0)          # ignore a side that only hurts
        r = max(gain(n.right), 0)
        best = max(best, n.val + l + r)   # best path that bends at n
        return n.val + max(l, r)          # best chain the parent can extend
    gain(root)
    return best

Problem 7.P.19 (hard, interview) Integers between 0 and 100 arrive in a stream of millions. Report the median at any time. Is there something better than two heaps?

Problem 7.P.20 (hard, interview) A teammate says "heapify is O(n log n), so building a heap is no better than sorting". Respond.

Answer: Bottom-up heapify is O(n). About half of the nodes are leaves and need no work. About a quarter sit one level above and move at most one step, an eighth move at most two steps, and so on. The work is n/4 * 1 + n/8 * 2 + n/16 * 3 + ..., which sums to at most about n. Only the version that does n separate pushes is O(n log n). Sorting is always at least O(n log n) in the comparison model, so building a heap is genuinely cheaper than sorting. (The teammate is right that popping everything is O(n log n).)
