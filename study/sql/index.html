A Note From Your Professor

Dear learner, welcome. SQL is the craft of asking clear questions of data: how many orders came in, which delivery was slowest, which students passed. A database is a system with queues, caches and limits, like a busy bank or hospital, and a SQL query is a request that you can measure and tune. Everyday examples (shop orders, delivery times, exam marks, hospital appointments) will carry you through, especially in the chapters on indexes and query plans.

SQL looks easy, and the first week is easy. The difficulty hides in a few ideas: NULL, joins that repeat rows, grouping, and window functions. People who skip them write queries that run without errors and return wrong numbers. This book teaches those ideas slowly, with a small shop database that you can check by hand, and with real output from real runs.

Study about one hour a day. Type every example yourself. Before you run a query, predict the output. If your prediction is wrong, that is the best moment to learn. And remember the one rule that matters most: never move on until the current topic feels obvious. If a chapter feels foggy, repeat its practice set before you open the next chapter. SQL rewards patience, and a clear mind about the basics is worth more than a long list of tricks. I am glad you are here. Let us begin.

What Every Topic Contains

  1. Intuition: the problem the concept solves, in everyday language, often with a performance-testing analogy.
  2. Formal definition: how it works, precise but plain, with every new word explained.
  3. Worked examples: real SQL with the exact output, with Predict, Compute, Check and Meaning steps.
  4. The picture: an ASCII diagram, table or image, explained completely.
  5. Connection to the real job: where it shows up in analytics, data engineering and ML work.
  6. Applications: grouped by role, each with a concrete example.
  7. Common mistakes: what beginners get wrong and how to catch it.
  8. Check yourself: three short questions with answers.

Every chapter also ends with a recap and cheat-sheet table, a practice set (8 to 12 problems with answers) and a prompt pack of 5 prompts to paste into any AI assistant.

Contents

  1. Databases and the Relational Model: what a database is, tables, keys, and how to set up SQLite and PostgreSQL.
  2. SELECT, WHERE, ORDER BY, LIMIT, DISTINCT and NULL Logic: reading one table and the three-valued logic of NULL.
  3. Aggregation, GROUP BY, HAVING and FILTER: turning many rows into summaries.
  4. Joins: inner, left, right, full, cross, self, anti- and semi-joins, and the duplicate-row traps.
  5. Subqueries and CTEs: queries inside queries, named steps, and recursive CTEs.
  6. CASE, Strings, Dates and Times, JSON and Arrays: cleaning and reshaping values.
  7. Set Operations, Pivot and Unpivot, GROUPING SETS, ROLLUP, CUBE: stacking, comparing and subtotalling.
  8. Window Functions in Depth: ranking, LAG/LEAD, frames, top-N per group, running totals, gaps and islands.
  9. DDL, DML, Constraints, Upserts, Transactions, ACID, Isolation Levels and Locks: changing data safely.
  10. Indexes, EXPLAIN / EXPLAIN ANALYZE and Query Optimization: making queries fast, with a measure, change one thing, re-measure mindset.
  11. Schema Design: ER diagrams, normalization 1NF to BCNF, denormalization, OLTP vs OLAP, star and snowflake, slowly changing dimensions.
  12. Analytics SQL Patterns: funnels, cohort retention, RFM, MoM and YoY, sessionization, deduplication, data-quality queries.
  13. Beyond SQL: MongoDB, Redis, Cassandra and DynamoDB, time-series, graph, search engines, vector databases, CAP, and when to use which.
  14. SQL Dialect Differences and the 40-Problem Interview Bank: PostgreSQL, MySQL, SQL Server, BigQuery and Snowflake, with answers.

An appendix (99_cheatsheet.md) collects the key patterns and ends with an honest closing note.

How To Study This Document

Use this learning loop for every chapter.

  1. Build first. Create the shop database and type the first example before reading the theory. Seeing a result makes the explanation easier to hold.
  2. Ask. Write down what you do not understand. Use a prompt from the chapter's prompt pack to ask an AI assistant to explain it a second way.
  3. Just-in-time theory. Read the definitions only when you need them to explain what you saw.
  4. Rebuild. Close the book and redo the worked examples from memory on a new small table of your own (for example, your own shop orders or exam marks).
  5. Teach. Explain the idea aloud, in simple words, as if to a colleague. If you cannot, repeat step 3.

Suggested pace: one chapter per week, about one hour a day. Days 1 to 2: read and run the worked examples. Days 3 to 4: rebuild and do the practice set. Day 5: prompt pack (quiz and mock interview). Weekend: redo the problems you got wrong. Chapters 8 and 10 deserve two weeks each.

Using the prompt packs: paste one prompt into any AI assistant. Replace [PASTE HERE] with your own query or table design for the review prompts. Always try the problem yourself first, and treat the assistant as a coach, not an answer machine. Check every number it gives by running the query.

The mastery tests from your skill map are a good finish: solve 300 or more SQL problems (about 50 hard) on LeetCode, StrataScratch or DataLemur; speed up a slow query from 10 seconds to under 1 second using EXPLAIN ANALYZE; and design an e-commerce schema with all its analytics queries.

Prerequisites

  • Comfortable use of a computer and a terminal (opening a shell, running a command).
  • Basic arithmetic and percentages. No programming is required, though a little Python helps.
  • The learner's Math PDF is not needed for this book.

Tools you need

All free.

  • SQLite (command sqlite3, version 3.39 or newer; this book was run on 3.51). Included on macOS; installable on Windows and Linux.
  • PostgreSQL (any recent version) through Docker or a native install, plus psql. Examples marked "PostgreSQL syntax, not run here" were not executed in this book.
  • A SQL client such as DBeaver, pgAdmin, DB Browser for SQLite or a VS Code extension.
  • A text editor.
  • Optional for Chapter 13: Docker images for MongoDB and Redis.
