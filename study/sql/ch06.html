Real data is messy. Names have extra spaces, emails come in capital letters, dates arrive as text, and half the interesting fields hide inside a JSON blob. Before you can count or join anything, you must clean and reshape the values. This chapter gives you the four toolboxes that do it: CASE (if-then-else inside SQL), text functions, date functions, and JSON/array functions. SQLite runs most of our examples. When PostgreSQL has a better or different tool (DATE_TRUNC, SPLIT_PART, jsonb, UNNEST), we show it and label it "PostgreSQL syntax, not run here".

6.1 CASE WHEN: If-Then-Else Inside a Query

BASIC EXPLANATION
CASE WHEN is an SQL expression that returns a value depending on conditions, like if-then-else. It is used to label, group or transform values inside a query.
INTUITION
A traffic officer looks at a vehicle and decides: if it is a truck, send it left; if a bus, send it right; otherwise straight. CASE WHEN does the same for each row: it tests conditions in order and returns the value of the first one that is true.

Words you need

  • Bucketing (also binning): turning a number into a label such as small, medium, large.
  • Conditional aggregation: using CASE inside SUM or COUNT (Chapter 3).
  • Manual pivot: turning row values into columns using conditional aggregation.

Syntax

CASE WHEN condition1 THEN value1
     WHEN condition2 THEN value2
     ELSE default_value        -- if omitted, the default is NULL
END

Conditions are checked top to bottom; the first TRUE wins. All THEN values should have the same type. There is also the "simple" form CASE column WHEN 'a' THEN ..., which only tests equality.

Real-world mapping

Use of CASEExampleWhere it appears in the job
Bucketingorder size small / medium / largecustomer segments, delivery-time bands
Recodingstatus codes to labelscleaning source-system codes
Conditional sumSUM(CASE WHEN ... )funnels, KPIs by segment
Manual pivotone column per statusreport layouts

Worked examples

Problem 6.1.1 (trivial) Label each product as cheap (under 200), mid (200 to 999) or premium (1000 or more).

Step 1Write the conditions from lowest to highest.
Step 2Because the first TRUE wins, the second test can just say price < 1000.
SELECT name, price,
       CASE WHEN price < 200  THEN 'cheap'
            WHEN price < 1000 THEN 'mid'
            ELSE 'premium' END AS band
FROM products
ORDER BY price;
name       price  band   
---------  -----  -------
Notebook   80     cheap  
Pen Pack   120    cheap  
Mug        250    mid    
Mouse      600    mid    
Desk Lamp  900    mid    
Keyboard   1500   premium
  • Check 80 and 120 are below 200 (cheap). 250, 600, 900 are below 1000 (mid). 1500 is premium.
  • Answer Notebook and Pen Pack cheap; Mug, Mouse and Desk Lamp mid; Keyboard premium.
  • Meaning One column of numbers became three labels that a manager can read.

Problem 6.1.2 Bucket orders by total value: small below 500, medium 500 to 1499, large 1500 or more. How many orders and how much revenue are in each bucket?

Step 1Compute each order's total in a CTE.
Step 2Apply CASE, then GROUP BY the bucket.
WITH order_totals AS (
  SELECT order_id, SUM(qty * unit_price) AS total
  FROM order_items GROUP BY order_id
)
SELECT CASE WHEN total < 500  THEN '1 small'
            WHEN total < 1500 THEN '2 medium'
            ELSE '3 large' END AS bucket,
       COUNT(*) AS n_orders,
       SUM(total) AS revenue
FROM order_totals
GROUP BY bucket
ORDER BY bucket;
bucket    n_orders  revenue
--------  --------  -------
1 small   4         1600   
2 medium  5         4400   
3 large   5         8560
  • Compute Order totals: 101:1660, 102:600, 103:1020, 104:400, 105:1500, 106:1280, 107:360, 108:900, 109:1500, 110:440, 111:600, 112:1800, 113:400, 114:2100. Small (under 500): 104, 107, 110, 113 give 400 + 360 + 440 + 400 = 1600. Medium: 102, 103, 106, 108, 111 give 600 + 1020 + 1280 + 900 + 600 = 4400. Large: 101, 105, 109, 112, 114 give 1660 + 1500 + 1500 + 1800 + 2100 = 8560.
  • Check 4 + 5 + 5 = 14 orders and 1600 + 4400 + 8560 = 14560, the full revenue.
  • Answer Small 4 orders / 1600, medium 5 / 4400, large 5 / 8560.
  • Meaning Five large orders (36 percent of orders) bring 59 percent of revenue (8560 / 14560). The number prefix in the label (1 small) is a trick to sort buckets in the right order.

Problem 6.1.3 A manual pivot: one row per month, one column per order status.

SELECT substr(order_date,1,7) AS month,
       SUM(CASE WHEN status = 'paid'      THEN 1 ELSE 0 END) AS paid,
       SUM(CASE WHEN status = 'cancelled' THEN 1 ELSE 0 END) AS cancelled,
       SUM(CASE WHEN status = 'refunded'  THEN 1 ELSE 0 END) AS refunded
FROM orders
GROUP BY month
ORDER BY month;
month    paid  cancelled  refunded
-------  ----  ---------  --------
2024-01  2     0          0       
2024-02  2     1          0       
2024-03  4     0          1       
2024-04  4     0          0
  • Check Matches Chapter 3: Jan 2 paid; Feb 2 paid and 1 cancelled; Mar 4 paid and 1 refunded; Apr 4 paid. Column sums: 12 + 1 + 1 = 14.
  • Answer One compact table, months down, statuses across.
  • Meaning This is the portable way to pivot. Chapter 7 returns to it.

Problem 6.1.4 The wrong version: no ELSE, and overlapping conditions. What does this return for the Mouse (600)?

SELECT name, price,
       CASE WHEN price >= 100 THEN 'A'
            WHEN price >= 500 THEN 'B' END AS grade
FROM products WHERE name IN ('Mouse', 'Notebook');
name      price  grade
--------  -----  -----
Mouse     600    A    
Notebook  80     NULL
  • Answer Mouse gets A, not B: the first TRUE wins, and 600 >= 100 is true. Notebook (80) matches nothing and gets NULL because there is no ELSE.
  • Fix Order the tests from the most specific (>= 500) to the least, and add an ELSE.

The picture

  value 600 --> [price < 200?] no --> [price < 1000?] YES --> 'mid'  (stop)
  value 80  --> [price < 200?] YES --> 'cheap'                (stop)
  value 1500 -> [price < 200?] no --> [price < 1000?] no --> ELSE 'premium'

Connection to the real job

Segmentation (new / returning, small / large, fast / slow) is the first step of most analyses. A courier company buckets delivery times (under 1 day, 1 to 3 days, over 3 days) to show promise compliance, exactly the same CASE pattern.

Applications

  • Data Analytics: customer segments, revenue bands, SLA bands.
  • Data Science and ML: creating categorical features, flag columns (is_high_value).
  • Data Engineering: mapping source codes to clean values.
  • Logistics: delivery-time bands (under 1 day, 1 to 3 days, over 3 days).
COMMON MISTAKE
Wrong order of conditions, and forgetting ELSE so unmatched rows silently become NULL. Also mixing types: THEN 1 ... ELSE 'none' fails in PostgreSQL.

Check yourself

  1. What does CASE return if no condition is true and there is no ELSE?

Answer: NULL.

  1. If two conditions are both true, which one wins?

Answer: The first one, from the top.

  1. How do you count rows meeting a condition inside one aggregate?

Answer: SUM(CASE WHEN cond THEN 1 ELSE 0 END) or COUNT(*) FILTER (WHERE cond).

6.2 String Functions

BASIC EXPLANATION
String functions work on text values. Common ones are LENGTH, SUBSTR, UPPER, LOWER, TRIM, REPLACE and concatenation.
INTUITION
Text from forms, files and logs is like a hand-written note: extra spaces, wrong capitals, joined fields. String functions are scissors, glue and an eraser.

Words you need

  • String (also text): a sequence of characters. Literal: 'abc'.
  • Substring: a piece of a string. Position: where a piece starts (counting from 1 in SQL, not 0).
  • Regular expression (regex): a pattern language for text, for example [0-9]+ means "one or more digits".

Worked examples (messy contacts)

CREATE TABLE contacts (id INTEGER PRIMARY KEY, raw_name TEXT, email TEXT, phone TEXT);
INSERT INTO contacts VALUES
 (1,'  Asha  Rao ','ASHA.RAO@Example.COM','+91-98765-43210'),
 (2,'ravi kumar','ravi.k@example.com','+91-91234-56789'),
 (3,'MEENA IYER','meena@work.in','98765 00000');

Problem 6.2.1 (trivial) How long is each raw name, and how long after trimming? Predict: ' Asha Rao ' has 2 leading, 1 trailing spaces and a double space inside.

SELECT id, raw_name, LENGTH(raw_name) AS len_raw,
       TRIM(raw_name) AS trimmed, LENGTH(TRIM(raw_name)) AS len_trim
FROM contacts;
id  raw_name      len_raw  trimmed     len_trim
--  ------------  -------  ----------  --------
1     Asha  Rao   12       Asha  Rao   9       
2   ravi kumar    10       ravi kumar  10      
3   MEENA IYER    10       MEENA IYER  10
  • Compute ' Asha Rao ': 2 spaces + Asha (4) + 2 spaces + Rao (3) + 1 space = 12 characters. After TRIM (ends only): Asha Rao = 4 + 2 + 3 = 9.
  • Check The output shows 12 and 9 for row 1. ravi kumar has 10 characters, MEENA IYER has 10, and trimming changes nothing.
  • Answer TRIM removes spaces at both ends but not the double space in the middle.
  • Meaning Extra spaces make 'Asha' and 'Asha ' look equal to humans but different to = and GROUP BY, so trimming comes first in every cleaning job.

Problem 6.2.2 Clean the email domain: lowercase the email and take the part after @.

Step 1LOWER(email) for case.
Step 2INSTR(email, '@') gives the position of @.
Step 3SUBSTR(text, position + 1) returns everything after it.
SELECT id,
       LOWER(email) AS email_clean,
       SUBSTR(LOWER(email), INSTR(email, '@') + 1) AS domain
FROM contacts;
id  email_clean           domain     
--  --------------------  -----------
1   asha.rao@example.com  example.com
2   ravi.k@example.com    example.com
3   meena@work.in         work.in
  • Check ASHA.RAO@Example.COM: @ is at position 9, so the domain starts at 10: Example.COM in lowercase is example.com.
  • Answer Domains: example.com, example.com, work.in.
  • Meaning Grouping by domain tells you which companies your users come from.

Problem 6.2.3 Clean phone numbers to digits only, and pad an id to five digits with leading zeros.

SELECT id,
       REPLACE(REPLACE(REPLACE(phone, '+', ''), '-', ''), ' ', '') AS digits,
       printf('%05d', id) AS padded_id
FROM contacts;
id  digits        padded_id
--  ------------  ---------
1   919876543210  00001    
2   919123456789  00002    
3   9876500000    00003
  • Check +91-98765-43210 becomes 919876543210 (12 digits). 98765 00000 becomes 9876500000 (10 digits). The id 1 padded to 5 digits is 00001.
  • Answer Nested REPLACE calls remove each unwanted character.
  • Meaning The two phones now differ in length (12 and 10): one has the country code and one does not. A length check like LENGTH(digits) is a quick data-quality test (Chapter 12).

Problem 6.2.4 Split a value: take the middle block of +91-98765-43210. In PostgreSQL SPLIT_PART('+91-98765-43210', '-', 2) returns 98765. SQLite has no SPLIT_PART, so use INSTR and SUBSTR.

SELECT phone,
       SUBSTR(phone, INSTR(phone, '-') + 1,
              INSTR(SUBSTR(phone, INSTR(phone, '-') + 1), '-') - 1) AS middle_block
FROM contacts
WHERE phone LIKE '%-%-%';
phone            middle_block
---------------  ------------
+91-98765-43210  98765       
+91-91234-56789  91234
  • Check In +91-98765-43210, the first - is at position 4; after it the text is 98765-43210; the next - is at position 6 of that text, so the length is 5, and the result is 98765.
  • Answer 98765 and 91234.
  • Meaning This is ugly. When you can choose, use SPLIT_PART or a regex in PostgreSQL.
-- PostgreSQL syntax, not run here
SELECT SPLIT_PART(phone, '-', 2)                AS middle_block,
       REGEXP_REPLACE(phone, '[^0-9]', '', 'g') AS digits_only,
       LPAD(id::text, 5, '0')                   AS padded_id
FROM contacts
WHERE email ~* '^[a-z.]+@example\.com$';   -- ~* means regex match, case-insensitive

Problem 6.2.5 Pattern search with LIKE: contacts whose email ends with .com (any case).

SELECT id, email FROM contacts WHERE LOWER(email) LIKE '%.com';
id  email               
--  --------------------
1   ASHA.RAO@Example.COM
2   ravi.k@example.com
  • Answer Contacts 1 and 2; contact 3 ends in .in.
  • Check ASHA.RAO@Example.COM lowercased ends with .com. meena@work.in does not.

The picture

 'ASHA.RAO@Example.COM'
  1234567890123...        INSTR(...,'@') = 9
  ASHA.RAO | @ | Example.COM
  SUBSTR(s, 1, 8)  = 'ASHA.RAO'   (the part before @: length = position - 1)
  SUBSTR(s, 10)    = 'Example.COM' (the part after @)

Positions count from 1. Characters before @ are 9 - 1 = 8.

Connection to the real job

Cleaning text is half of data work: standardise names, extract domains and area codes, build keys, search logs. A web analyst often parses URLs and log lines the same way (for example, take the path before ?).

Applications

  • Data Analytics: grouping by cleaned categories; email domains.
  • Data Engineering: standardising keys before joins; parsing log fields.
  • Data Science and NLP: text pre-cleaning before features.
  • Web analytics: extracting page names from URLs.
COMMON MISTAKE
Joining on dirty text ('Pune' vs 'pune ') so rows silently fail to match. Clean with TRIM and LOWER on both sides, or better, fix the data once at load time. Also: NULL || 'x' is NULL, so use COALESCE before joining text; PostgreSQL's CONCAT ignores NULLs.

Check yourself

  1. In SQL, does the first character have position 0 or 1?

Answer: 1.

  1. What does TRIM(' a b ') return?

Answer: a b (inner space kept).

  1. What is NULL || 'x'?

Answer: NULL.

6.3 Dates and Times

BASIC EXPLANATION
Date and time functions create, compare, format and extract parts of dates and timestamps. They are used to add intervals, find differences and group data by day, month or year.
INTUITION
Dates are the hardest "simple" data type: months have different lengths, leap years exist, and a timestamp means different clock times in Mumbai and London. A good analyst always asks: "which time zone, and what is the cut-off?"

Words you need

  • Date: a calendar day. Timestamp: date plus time. timestamptz (PostgreSQL): timestamp stored in UTC and shown in your session time zone.
  • UTC: the world reference time. India Standard Time is UTC + 5:30.
  • Interval: a length of time (7 days, 1 month).
  • Truncate: cut a date down to the start of its period (month start, week start).
  • ISO format: YYYY-MM-DD, which sorts correctly as text.

SQLite has no real date type. It stores dates as text ('2024-03-05'), numbers, or Julian days, and uses functions date(), datetime(), strftime() and julianday(). PostgreSQL has true DATE, TIMESTAMP, TIMESTAMPTZ and INTERVAL.

Worked examples

Problem 6.3.1 (trivial) For each order, show its month start and the date a 30-day return window closes. Show the first 4 orders.

SELECT order_id, order_date,
       date(order_date, 'start of month') AS month_start,
       date(order_date, '+30 days')       AS return_by
FROM orders ORDER BY order_id LIMIT 4;
order_id  order_date  month_start  return_by 
--------  ----------  -----------  ----------
101       2024-01-10  2024-01-01   2024-02-09
102       2024-01-15  2024-01-01   2024-02-14
103       2024-02-03  2024-02-01   2024-03-04
104       2024-02-10  2024-02-01   2024-03-11
  • Check Order 101 is on 2024-01-10. January has 31 days, so +30 days is 2024-02-09. Order 103 on 2024-02-03 plus 30 days: February 2024 has 29 days (a leap year), so 26 days take us to 2024-02-29, and 4 more to 2024-03-04.

Problem 6.3.2 How many days passed from each customer's signup to their first order?

Step 1In a CTE find the first order date per customer.
Step 2Subtract the Julian day numbers (days since a fixed past date).
WITH first_orders AS (
  SELECT customer_id, MIN(order_date) AS first_order FROM orders GROUP BY customer_id
)
SELECT c.name, c.signup_date, f.first_order,
       CAST(julianday(f.first_order) - julianday(c.signup_date) AS INTEGER) AS days_to_first_order
FROM customers c JOIN first_orders f ON f.customer_id = c.customer_id
ORDER BY c.customer_id;
name   signup_date  first_order  days_to_first_order
-----  -----------  -----------  -------------------
Asha   2024-01-05   2024-01-10   5                  
Ravi   2024-01-12   2024-01-15   3                  
Meena  2024-01-20   2024-02-10   21                 
John   2024-02-02   2024-02-20   18                 
Priya  2024-02-14   2024-03-07   22

Problem 6.3.4 The classic trap: filtering a whole month. Show that BETWEEN '2024-03-01' AND '2024-03-31' is fine for dates but loses rows for timestamps. We simulate a timestamp column.

CREATE TABLE log (ts TEXT);
INSERT INTO log VALUES ('2024-03-31 09:15:00'), ('2024-03-31 23:59:59'), ('2024-04-01 00:00:00');

SELECT COUNT(*) AS between_version FROM log
WHERE ts BETWEEN '2024-03-01' AND '2024-03-31';

SELECT COUNT(*) AS half_open_version FROM log
WHERE ts >= '2024-03-01' AND ts < '2024-04-01';
between_version
---------------
0              
half_open_version
-----------------
2
  • Compute The text '2024-03-31 09:15:00' is greater than '2024-03-31' (longer, same start), so BETWEEN loses both March 31 rows. The half-open test keeps rows from the first moment of March up to, but not including, April 1.
  • Check The half-open version returns 2 (the two March 31 rows); BETWEEN returns 0.
  • Answer Use >= start AND < next_start.
  • Meaning Half-open ranges work for dates, timestamps and any precision.

Connection to the real job

Month-over-month growth, retention by week and "orders in the last 7 days" are all date logic. Time-zone errors are among the most common causes of dashboards that "do not match finance". Many systems (mobile apps, sensors, payment logs) store timestamps as milliseconds since 1970 (epoch time); converting them to dates is a typical first query.

Applications

  • Data Analytics: monthly and weekly trends, age of customer, SLA days.
  • Data Engineering: partitioning tables by date; incremental loads by updated_at.
  • Data Science and ML: time-based features (day of week, days since last order).
  • Healthcare: grouping hospital appointments by hour of the day.
COMMON MISTAKE
Using BETWEEN with an end date on timestamp columns (loses the last day), mixing time zones, and storing dates as text in free formats (03/04/24 is March 4 or April 3?). Use ISO YYYY-MM-DD.

6.4 JSON and Array Values

BASIC EXPLANATION
JSON and array values store structured or multiple values inside one column. SQL has functions to extract fields from JSON, expand arrays into rows and build them.
INTUITION
A relational table is a spreadsheet with fixed columns. But app events, API responses and logs arrive as JSON, a flexible text format with nested fields: {"user":"asha","device":{"os":"android"}}. You can store the whole blob in one column and still pull fields out with SQL.

Words you need

  • JSON (JavaScript Object Notation): text made of objects {"key": value}, arrays [1, 2, 3], strings, numbers, booleans and null.
  • Semi-structured data: data whose fields vary per record.
  • Path: an address inside JSON, like $.device.os ($ is the root).
  • Array column: PostgreSQL can store a list in one cell (ARRAY['a','b']).
  • Unnest / explode: turning one row with a list into many rows, one per element.

Worked examples

CREATE TABLE events (id INTEGER PRIMARY KEY, payload TEXT);
INSERT INTO events VALUES
 (1,'{"user":"asha","device":{"os":"android","ver":14},"tags":["promo","new"],"amount":250}'),
 (2,'{"user":"ravi","device":{"os":"ios","ver":17},"tags":[],"amount":600}'),
 (3,'{"user":"meena","device":{"os":"android","ver":13},"tags":["promo"]}');

Problem 6.4.1 (trivial) Pull the user, the operating system and the amount out of each event. Predict: event 3 has no amount field. What will that cell show?

SELECT id,
       payload ->> '$.user'         AS user,
       payload ->> '$.device.os'    AS os,
       payload ->> '$.amount'       AS amount
FROM events;
id  user   os       amount
--  -----  -------  ------
1   asha   android  250   
2   ravi   ios      600   
3   meena  android  NULL
  • Answer Event 3's amount is NULL (a missing key gives NULL, not an error).
  • Check Event 1: asha, android, 250; event 2: ravi, ios, 600; event 3: meena, android, NULL.
  • Meaning You can query flexible data without a fixed schema, but missing keys become NULL, so count them.

ORDER BY os;

android  2       1            250         
ios      1       1            600
  • Compute Android has events 1 and 3: amounts 250 and NULL, so COUNT(amount) = 1 and SUM = 250. iOS has event 2: 600.
  • Check 250 + 600 = 850 total across both groups.
  • Answer Android: 2 events, 1 with amount, 250. iOS: 1 event, 1 with amount, 600.
  • Meaning SUM ignores NULL. If event 3's missing amount really means zero, add COALESCE.

Problem 6.4.3 Explode the tags array: one row per (event, tag). Also count events per tag.

SELECT e.id, t.value AS tag
FROM events e, json_each(e.payload, '$.tags') AS t
ORDER BY e.id;
id  tag  
--  -----
1   promo
1   new  
3   promo
SELECT t.value AS tag, COUNT(*) AS n_events
FROM events e, json_each(e.payload, '$.tags') AS t
GROUP BY t.value ORDER BY n_events DESC;
tag    n_events
-----  --------
promo  2

  • Check Event 1 has two tags, event 2 has none (an empty array gives no rows), event 3 has one. Total 3 rows. promo appears in events 1 and 3 (2), new in event 1 (1).

Problem 6.4.4 The reverse: collapse rows into lists. For each product category, list its product names.

SELECT category, GROUP_CONCAT(name, ', ') AS products, COUNT(*) AS n
FROM (SELECT category, name FROM products ORDER BY name)
GROUP BY category
ORDER BY category;
category     products            n
-----------  ------------------  -
Electronics  Keyboard, Mouse     2
Home         Desk Lamp, Mug      2
Stationery   Notebook, Pen Pack  2
  • Check Electronics holds Keyboard and Mouse; Home holds Desk Lamp and Mug; Stationery holds Notebook and Pen Pack. Alphabetical inside each group because we sorted before grouping.
  • Answer One row per category with a comma list.
  • Meaning SQLite does not guarantee the order of GROUP_CONCAT; sorting in a subquery works in practice. In PostgreSQL write STRING_AGG(name, ', ' ORDER BY name).
-- PostgreSQL syntax, not run here
-- jsonb and arrays in PostgreSQL
SELECT payload ->> 'user'                      AS user_name,
       payload -> 'device' ->> 'os'            AS os,
       (payload ->> 'amount')::numeric         AS amount
FROM events
WHERE payload @> '{"tags": ["promo"]}';        -- contains this fragment (GIN index can help)

SELECT category, ARRAY_AGG(name ORDER BY name) AS names,
       STRING_AGG(name, ', ' ORDER BY name)    AS names_text
FROM products GROUP BY category;

SELECT e.id, tag
FROM events e, LATERAL jsonb_array_elements_text(e.payload -> 'tags') AS tag;

SELECT UNNEST(ARRAY[10, 20, 30]) AS n;         -- one row per element

                                                      (event 1, new)

Connection to the real job

Event data (clickstream, API logs, mobile telemetry) arrives as JSON. A data engineer lands the raw JSON in one column, then flattens it with these functions into proper tables (a common step in ELT). Many apps already store order details or settings as JSON; the same functions let you query them.

Applications

  • Data Analytics: product events with flexible properties.
  • Data Engineering: flattening raw JSON into columns during ELT.
  • Data Science and ML: extracting features from event payloads.
  • GenAI: storing LLM request and response metadata as JSON for analysis.
COMMON MISTAKE
Putting everything into one JSON column "for flexibility". You lose type checks, constraints and good indexing. Use JSON for truly variable fields; keep core fields as real columns. Another trap: -> returns JSON (with quotes), ->> returns plain text; comparing payload -> 'user' = 'asha' fails because the left side is "asha" with quotes.

Check yourself

  1. What does ->> return compared to ->?

Answer: ->> returns plain text; -> returns JSON.

  1. What does an empty array produce when you unnest it?

Answer: Zero rows.

  1. Which function joins rows into one comma string in PostgreSQL?

Answer: STRING_AGG.

Chapter recap

  • CASE WHEN tests conditions top to bottom and returns the first match; add ELSE.
  • CASE inside SUM or COUNT builds conditional metrics and manual pivots.
  • TRIM, LOWER, REPLACE, SUBSTR and INSTR clean text; positions start at 1.
  • NULL || text is NULL; clean text on both sides before joining.
  • Use ISO dates, half-open ranges (>= start AND < next) and never hand-count days.
  • Know your time zone; convert before truncating to a day.
  • JSON fields are read with -> (JSON) and ->> (text); missing keys give NULL.
  • Unnest arrays to rows to count or join them; aggregate rows back to lists with STRING_AGG / ARRAY_AGG.

Problem 6.P.3 (what is the output?) What does this print?

SELECT date('2024-01-31', '+1 month') AS a, date('2024-02-29', '+1 year') AS b;
a           b         
----------  ----------
2024-03-02  2025-03-01

Answer: a = 2024-03-02 in SQLite (31 January plus one month is "31 February", which rolls over to 2 March) and b = 2025-03-01 (29 February 2025 does not exist, so it rolls to 1 March). Problem 6.P.8 (scenario) A column created_at holds UTC timestamps. The business wants daily orders in India time. What do you do? Answer: Convert to Asia/Kolkata first (created_at AT TIME ZONE 'Asia/Kolkata' in PostgreSQL), then truncate to date and group. An order at 20:00 UTC on 31 March is 01:30 IST on 1 April, so it belongs to April in India.

Problem 6.P.9 (interview) What is the difference between COALESCE and CASE WHEN x IS NULL? Answer: COALESCE(a, b, c) is a short form that returns the first non-NULL argument. CASE WHEN a IS NULL THEN b ELSE a END does the same for two values but is longer, and it allows any conditions, not only NULL tests.

Problem 6.P.10 (interview) How would you find all users who have a particular tag in a JSON array column in PostgreSQL, and how would you make it fast? Answer: With jsonb: WHERE payload @> '{"tags":["promo"]}', and create a GIN index on the column: CREATE INDEX ON events USING GIN (payload). Without the index the database scans every row.
