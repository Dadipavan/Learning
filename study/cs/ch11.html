Many hard-looking problems are easy once you see the pattern. This chapter teaches four related ideas: recursion (a function calls itself), backtracking (try, undo, try again), dynamic programming or DP (recursion that remembers), and greedy (always take the best-looking choice). We finish with intervals, bit tricks and small number-theory tools. By the end you will be able to write a recursive function with confidence, list all combinations of a small set, and fill a table to solve problems like "fewest coins" or "how different are these two strings". These skills show up in coding interviews and, in real data work, in text matching, scheduling and budget allocation. The chapter has a ladder: recursion first, then backtracking (recursion with undo), then DP (recursion with memory), then greedy (no looking back). We keep one running idea: a big problem is made of smaller copies of itself. All code was run with Python 3 and the output is real.

11.1 Recursion and Memoization

INTUITION
To count the people in a queue, you ask the person in front "how many are ahead of you?", add one, and answer the person behind. Each person solves a smaller version of the same problem. The first person in line (nobody ahead) answers 0 directly: that is the base case.

How it works. A recursive function has (1) a base case that answers without calling itself, and (2) a recursive case that calls itself on a smaller input. Python keeps each call on the call stack; the default limit is about 1,000 nested calls (sys.getrecursionlimit()).

A problem: plain recursion can repeat work. Fibonacci (fib(n) = fib(n−1) + fib(n−2)) recomputes the same values again and again. Memoization stores each answer the first time, so later calls just look it up. In Python: @functools.lru_cache(None).

import functools

def fact(n): return 1 if n <= 1 else n * fact(n - 1)

calls = 0
def fibn(n):                      # plain, no memory
    global calls; calls += 1
    return n if n < 2 else fibn(n-1) + fibn(n-2)

@functools.lru_cache(None)
def fib(n): return n if n < 2 else fib(n-1) + fib(n-2)

print(fact(5))
print(fibn(20), calls)
print(fib(50), fib.cache_info().misses)

Line by line. In fact, n * fact(n - 1) waits for the smaller answer, then multiplies. In fibn, the counter calls is bumped on every call; the two recursive calls repeat work, so the count explodes to 21,891. In fib, lru_cache is a notebook: before running, it checks whether n was seen; the 51 "misses" are the 51 first-time values fib(0) to fib(50).

The typical wrong version. No base case:

def fact(n): return n * fact(n - 1)
fact(5)
RecursionError: maximum recursion depth exceeded

fact(0) calls fact(-1), then fact(-2), and never stops. Python gives up near 1,000 nested calls. The fix is the if n <= 1: return 1 part.

Problem 11.1.2 Why did fibn(20) need 21,891 calls but fib(50) only 51 real computations?

Step 1Plain recursion makes two calls per call, so work grows roughly like 1.6ⁿ (exponential). For n = 20 that is 21,891 calls.
Step 2With memoization each value fib(0)..fib(50) is computed once: 51 values, 51 misses.
AnswerMemoization turns exponential O(2ⁿ)-like time into linear O(n). Plain fib(50) would need over 40 billion calls.
Check51 misses equals the 51 values from 0 to 50. In plain recursion, the call count for n = 20 was 21,891, matching the "about 1.6ⁿ" growth (1.6²⁰ is about 12,000, the same order).
Why it mattersIn plain words: one line of caching turned "never finishes" into "instant".
KEY INSIGHT
Memoization works when the same sub-problem appears many times (overlapping sub-problems) and the answer depends only on the inputs (no hidden state).

Connection to the real job. Recursion walks JSON, folders and trees (Chapter 10). Memoization (lru_cache) is also an everyday caching trick: cache a slow function that is called repeatedly with the same arguments. Applications: parsers, file walkers, caching expensive lookups, divide and conquer (merge sort).

COMMON MISTAKE
No base case, or a base case that is never reached. You get RecursionError: maximum recursion depth exceeded. Check that every call moves closer to the base case.

11.2 Backtracking: Subsets, Permutations, N-Queens

INTUITION
In a maze, you walk until you hit a wall, then step back to the last junction and try another turn. Backtracking is that: make a choice, explore, undo the choice, make the next choice.

Pattern. Keep a current partial answer. At each step, loop over the choices: add one (choose), recurse (explore), remove it (un-choose). When the partial answer is complete, save a copy. For problems with rules, skip a choice that breaks a rule early (pruning). This is brute force, but smart brute force. Costs: subsets O(2ⁿ), permutations O(n!).

def subsets(a):
    res = []
    def go(i, cur):
        if i == len(a): res.append(cur[:]); return    # copy, not cur itself
        go(i + 1, cur)                 # skip a[i]
        cur.append(a[i]); go(i + 1, cur); cur.pop()   # take a[i], then undo
    go(0, []); return res

def perms(a):
    res = []
    def go(cur, used):
        if len(cur) == len(a): res.append(cur[:]); return
        for i in range(len(a)):
            if not used[i]:
                used[i] = True; cur.append(a[i])
                go(cur, used)
                cur.pop(); used[i] = False
    go([], [False] * len(a)); return res

def nq(n):
    sols = []; cols = []          # cols[r] = column of the queen in row r
    def ok(r, c):
        return all(c != cc and abs(c - cc) != r - rr for rr, cc in enumerate(cols))
    def go(r):
        if r == n: sols.append(cols[:]); return
        for c in range(n):
            if ok(r, c): cols.append(c); go(r + 1); cols.pop()
    go(0); return sols

Line by line. In subsets, go(i + 1, cur) is the branch where we skip item i; the next line takes it, recurses, then cur.pop() undoes the choice so the next branch starts clean. In nq, cols[r] is the column of the queen in row r, and ok rejects a square that shares a column or a diagonal with any earlier queen (same diagonal means column difference equals row difference).

The typical wrong version. Saving the working list itself, not a copy:

if i == len(a): res.append(cur); return     # no copy
[[], [], [], [], [], [], [], []]

All eight saved answers are the same list object, and by the end it has been popped back to empty. The fix is res.append(cur[:]).

Problem 11.2.2 Why is [1, 3, 0, 2] a valid 4-queens answer?

Step 1Queens are at (row, col): (0,1), (1,3), (2,0), (3,2). All columns differ: 1, 3, 0, 2.

11.3 Dynamic Programming: The Recipe and 1D Problems

INTUITION
You climb stairs, one or two steps at a time. The ways to reach stair 10 equal the ways to reach stair 9 plus the ways to reach stair 8. Solve small stairs first, write the answers in a table, and build up. That table is DP.

Definition. Dynamic programming solves a problem by (1) defining a state (a small set of numbers describing a sub-problem), (2) writing a recurrence (how a state depends on smaller states), (3) setting base cases, (4) filling the table in the right order (bottom-up) or using recursion with memoization (top-down). It applies when you have overlapping sub-problems and optimal substructure (the best answer is built from best answers of parts).

Recipe: state, recurrence, base case, order, answer cell. Always write these five lines before coding.

def climb(n):                       # ways to climb n stairs with steps of 1 or 2
    a, b = 1, 1
    for _ in range(n - 1): a, b = b, a + b
    return b

def coins(cs, t):                   # fewest coins to make each amount 0..t
    dp = [0] + [float('inf')] * t
    for x in range(1, t + 1):
        for c in cs:
            if c <= x: dp[x] = min(dp[x], dp[x - c] + 1)
    return dp

def rob(a):                         # max sum, no two neighbours
    p2 = p1 = 0
    for x in a: p2, p1 = p1, max(p1, p2 + x)
    return p1

Line by line. In coins, dp[x] starts as infinity ("not reachable yet") except dp[0] = 0. For each amount x we try each coin c; dp[x - c] + 1 means "best way for the smaller amount, plus this coin". In rob, p1 is the best sum so far and p2 is the best sum two houses ago; max(p1, p2 + x) chooses between skipping house x and taking it.

The typical wrong version. Forgetting the infinity start:

dp = [0] * (t + 1)      # wrong: every amount looks free

Then min(dp[x], ...) always returns 0, and the answer for 10 becomes 0 coins. The table must start as "impossible" (infinity) so that min can only improve it.

Problem 11.3.1 Fewest coins for 10 using coins 1, 5, 6.

Step 1State: dp[x] = fewest coins for amount x. Recurrence: dp[x] = 1 + min(dp[x − c]) over coins c ≤ x. Base: dp[0] = 0.
Step 2dp[5] = 1, dp[6] = 1. dp[10]: via coin 5 gives dp[5] + 1 = 2; via coin 6 gives dp[4] + 1 = 5; via coin 1 gives dp[9] + 1 = 5.
Answer2 coins (5 + 5). The array matches the program.
Check5 + 5 = 10 with 2 coins, and no single coin equals 10, so 1 coin is impossible.
Why it mattersIt says: the "greedy" idea (take the biggest coin 6 first) would need 5 coins, so DP beat it by 3 coins.

Problem 11.3.2 House robber on [2, 7, 9, 3, 1]: choose non-adjacent houses for the largest sum.

Step 1State: best(i) = best sum using the first i houses. Recurrence: best(i) = max(best(i−1), best(i−2) + a[i]) (skip house i, or take it and skip i−1).
Step 2Running values: after 2 → 2; after 7 → 7; after 9 → max(7, 2+9) = 11; after 3 → max(11, 7+3) = 11; after 1 → max(11, 11+1) = 12.
Answer12, from houses 2, 9 and 1.
CheckHouses 2, 9, 1 are not adjacent: 2 + 9 + 1 = 12. The alternative 7 + 3 = 10 is smaller, and 7 + 1 = 8 is smaller.
Why it matters"Take the best of two choices at every step, remembering only the last two answers" is the pattern behind many scheduling problems.
KEY INSIGHT
Notice that climb and rob only need the last two values, so we keep two variables instead of a whole table. This cuts memory from O(n) to O(1).

Connection to the real job. DP is behind the Viterbi algorithm (speech and sequence models), edit-distance spell correction, sequence alignment in bioinformatics, and the Bellman equations of reinforcement learning. Applications: resource allocation, text processing, pricing and inventory planning, finance.

11.4 Knapsack and Longest Increasing Subsequence

INTUITION
You have a bag that carries 7 kg. Each item has a weight and a value. You cannot take half an item. Which items give the most value? This 0/1 knapsack is the model for "choose items under a budget".

Knapsack. dp[c] = best value with capacity c. For each item (weight w, value v), update capacities from high to low: dp[c] = max(dp[c], dp[c − w] + v). Going downward makes sure each item is used at most once. Time O(items × W).

LIS (Longest Increasing Subsequence). dp[i] = length of the longest increasing subsequence ending at i. dp[i] = 1 + max(dp[j]) for j < i with a[j] < a[i]. Time O(n²). A faster O(n log n) version keeps a list of the smallest possible tails and uses binary search (bisect_left).

import bisect
def knap(items, W):
    dp = [0] * (W + 1)
    for w, v in items:
        for c in range(W, w - 1, -1):
            dp[c] = max(dp[c], dp[c - w] + v)
    return dp

def lis_dp(a):
    dp = [1] * len(a)
    for i in range(len(a)):
        for j in range(i):
            if a[j] < a[i]: dp[i] = max(dp[i], dp[j] + 1)
    return dp

def lis(a):
    t = []
    for x in a:
        i = bisect.bisect_left(t, x)
        if i == len(t): t.append(x)
        else: t[i] = x
    return len(t)

print(knap([(1,1),(3,4),(4,5),(5,7)], 7))
print(lis_dp([10,9,2,5,3,7,101,18]), lis([10,9,2,5,3,7,101,18]))

Line by line. dp[c] is the best value for capacity c. For each item we scan capacities from large to small, so dp[c - w] still holds the value before this item was added; that guarantees the item is used once. In lis, t[k] is the smallest possible last number of an increasing run of length k + 1; bisect_left finds where x fits, either extending the longest run or lowering a tail.

The typical wrong version. Looping capacity upward:

for c in range(w, W + 1):               # wrong direction for 0/1 knapsack
    dp[c] = max(dp[c], dp[c - w] + v)

For the same items the table becomes [0, 1, 2, 4, 5, 7, 8, 9]. Look at dp[2] = 2: the single 1-kg item (value 1) was used twice, which is not allowed. Correct is dp[2] = 1. Allowing an item many times is the unbounded knapsack, a different problem. The fix is the downward loop range(W, w - 1, -1).

11.5 Two-Dimensional DP: LCS, Edit Distance, Grids and Trees

INTUITION
To compare two strings, ask about prefixes: how similar are the first i letters of one and the first j letters of the other? A 2D table answers every pair of prefixes.

LCS (longest common subsequence). A subsequence keeps order but may skip letters. dp[i][j] = LCS length of a[:i] and b[:j]. If a[i−1] == b[j−1]: dp[i][j] = dp[i−1][j−1] + 1; else max(dp[i−1][j], dp[i][j−1]).

Edit distance (Levenshtein). Fewest insert, delete or replace operations to turn a into b. If letters match: dp[i][j] = dp[i−1][j−1]; else 1 + min(delete, insert, replace) = 1 + min(dp[i−1][j], dp[i][j−1], dp[i−1][j−1]). Base: dp[i][0] = i, dp[0][j] = j.

def lcs(a, b):
    dp = [[0]*(len(b)+1) for _ in range(len(a)+1)]
    for i in range(1, len(a)+1):
        for j in range(1, len(b)+1):
            dp[i][j] = dp[i-1][j-1] + 1 if a[i-1] == b[j-1] else max(dp[i-1][j], dp[i][j-1])
    return dp

def edit(a, b):
    dp = [[0]*(len(b)+1) for _ in range(len(a)+1)]
    for i in range(len(a)+1): dp[i][0] = i
    for j in range(len(b)+1): dp[0][j] = j
    for i in range(1, len(a)+1):
        for j in range(1, len(b)+1):
            dp[i][j] = dp[i-1][j-1] if a[i-1] == b[j-1] else \
                       1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
    return dp

Problem 11.5.2 Fewest-cost path in a grid, moving only right or down. Grid [[1,3,1],[1,5,1],[4,2,1]].

Step 1State: dp[i][j] = cheapest cost to reach cell (i, j). Recurrence: grid[i][j] + min(dp[i−1][j], dp[i][j−1]). Base: top-left equals its own value.
Step 2Program output: rows [1, 4, 5], [2, 7, 6], [6, 8, 7].
Answer7: the path 1, 3, 1, 1, 1 (right, right, down, down) costs 7.
CheckAdd along the path: 1 + 3 + 1 + 1 + 1 = 7. The other path, down first (1, 1, 4, 2, 1), costs 9.
Why it mattersCheapest-path tables like this are how you price routes or find the least costly seam through an image.
def grid(g):
    R, C = len(g), len(g[0]); dp = [[0]*C for _ in range(R)]
    for i in range(R):
        for j in range(C):
            best = 0 if i == j == 0 else min(dp[i-1][j] if i else 9e9, dp[i][j-1] if j else 9e9)
            dp[i][j] = g[i][j] + best
    return dp

DP on trees. For each node compute a pair of numbers from its children. Example "rob a tree of houses, no two directly connected": go(node) returns (take, skip): take = value + skip(left) + skip(right); skip = max(left) + max(right).

def rob3(t):                          # t = (value, left, right)
    def go(n):
        if not n: return 0, 0
        l, r = go(n[1]), go(n[2])
        return n[0] + l[1] + r[1], max(l) + max(r)
    return max(go(t))
print(rob3((3, (2, None, (3, None, None)), (3, None, (1, None, None)))))   # 7

Problem 11.5.3 Explain the answer 7 above.

11.6 Greedy Algorithms and Intervals

INTUITION
When you give change in rupees with notes of 500, 100, 50, 10, you hand out the biggest note that fits. You never regret it. Greedy means taking the best local choice and never reconsidering. It is simple and fast, but it is correct only for some problems.

When greedy works. You must be able to argue that the local best choice is part of some best overall answer (the greedy-choice property). Common provable cases: activity selection (sort by end time), merging intervals (sort by start), jump game (track the farthest reach), MST (Kruskal, Prim), Dijkstra.

When greedy fails. Coins [1, 5, 6], amount 10: greedy takes 6 first, then 1 + 1 + 1 + 1 = 5 coins. DP finds 5 + 5 = 2 coins (11.3). Always test a greedy idea on a tricky small case.

def intervals_merge(a):
    a = sorted(a); out = [a[0][:]]
    for s, e in a[1:]:
        if s <= out[-1][1]: out[-1][1] = max(out[-1][1], e)
        else: out.append([s, e])
    return out

def max_meet(a):                      # most non-overlapping meetings
    a = sorted(a, key=lambda x: x[1]); end = -1; ch = []
    for s, e in a:
        if s >= end: ch.append((s, e)); end = e
    return ch

def can_jump(a):
    far = 0
    for i, x in enumerate(a):
        if i > far: return False
        far = max(far, i + x)
    return True

Predict first: After merging the five intervals, how many remain? And is can_jump([3,2,1,0,4]) True or False?

merge [[1,3],[8,10],[2,6],[15,18],[17,20]] -> [[1, 6], [8, 10], [15, 20]]
max_meet(...) -> [(1, 4), (5, 7), (8, 11)]
can_jump([2,3,1,1,4]) True    can_jump([3,2,1,0,4]) False

Line by line. intervals_merge sorts by start, so any interval that overlaps the last output must start before that output ends; then only the end needs updating (max, since the new one may be shorter). max_meet sorts by end time and takes a meeting whenever it starts after the last chosen one ends. can_jump tracks far, the farthest index reachable so far; if we stand beyond far, we are stuck.

The typical wrong version. Forgetting max when merging:

out[-1][1] = e        # wrong: [1,10] then [2,3] would shrink the end to 3

With input [[1,10],[2,3]] the wrong code returns [[1, 3]] and loses part of the time range. The fix is max(out[-1][1], e).

Problem 11.6.1 Merge [1,3], [2,6], [8,10], [15,18], [17,20] by hand.

Problem 11.6.2 Meetings (1,4), (3,5), (0,6), (5,7), (3,9), (5,9), (6,10), (8,11): the most that fit in one room.

Step 1Sort by end time: (1,4), (3,5), (0,6), (5,7), (3,9), (5,9), (6,10), (8,11).
Step 2Take (1,4), end = 4. Skip (3,5) and (0,6) (start before 4). Take (5,7), end = 7. Skip (3,9), (5,9), (6,10). Take (8,11).
Answer3 meetings. Sorting by end time leaves the most room for the future.
CheckThe chosen meetings (1,4), (5,7), (8,11) do not overlap. Trying 4 meetings would need another meeting ending before 11 and starting after 7, and none exists.
Why it mattersIt says: three is the best you can do in one room; adding a fourth needs a second room.
COMMON MISTAKE
Choosing the wrong sort key. Sorting meetings by start time or by length gives wrong answers. Think about what choice leaves the most freedom for later.

Connection to the real job. Merging overlapping time ranges is common in log analysis (merge overlapping outage windows to compute total downtime), session windows and calendar tools. Greedy ideas also appear in decision tree training (best split at each node is a greedy choice) and beam search in text generation. Applications: scheduling, compression (Huffman coding), network routing, resource allocation.

11.7 Bit Manipulation and Number Theory Basics

INTUITION
Computers store numbers as bits (0 and 1). Working directly on bits is fast and gives neat tricks, like checking "is this a power of two?" in one line.

Bit operations. & (and), | (or), ^ (xor: 1 when bits differ), ~ (not), << (shift left = multiply by 2), >> (shift right = divide by 2). Useful facts: x & (x−1) removes the lowest set bit; x & −x isolates it; x ^ x = 0 and x ^ 0 = x.

n = 44
print(bin(n), n & 1, n >> 2, bin(n & (n-1)), bin(n & -n), n & (n-1) == 0, bin(1 << 5))
print(bin(44).count('1'), [x for x in range(1, 17) if x & (x-1) == 0])
def single(a):
    r = 0
    for x in a: r ^= x
    return r
print(single([4, 1, 2, 1, 2]))

Predict first: What is bin(44 & 43)? Write 44 and 43 in binary first.

0b101100 0 11 0b101000 0b100 False 0b100000
3 [1, 2, 4, 8, 16]
4

Line by line. bin(n) shows the bits with a 0b prefix. n & 1 looks at the last bit. n >> 2 shifts two places right. n & (n-1) turns off the lowest 1-bit, because subtracting 1 flips that bit and all bits after it. n & -n keeps only that lowest 1-bit.

The typical wrong version. Using + for XOR-style cancelling:

r = 0
for x in [4, 1, 2, 1, 2]: r += x      # gives 10, not 4

Addition does not cancel duplicates; only XOR does, since x ^ x = 0. The fix is r ^= x.

Problem 11.7.1 Read the first line of output for 44.

Problem 11.7.2 Why does single([4,1,2,1,2]) return 4?

Step 1XOR is order-free and x ^ x = 0. So 1 ^ 1 and 2 ^ 2 cancel.
Step 2What remains is 4 ^ 0 = 4.
Answer4, the element that appears once, found in O(n) time and O(1) memory.
CheckDo the XOR step by step: 4^1 = 5, 5^2 = 7, 7^1 = 6, 6^2 = 4. The result is 4.
Why it mattersNo dictionary and no sorting are needed, so memory stays constant.

Number theory basics. GCD (greatest common divisor) via Euclid; LCM = a·b / gcd. A prime has exactly two divisors. The Sieve of Eratosthenes finds all primes up to n in O(n log log n). Modular arithmetic: results are often asked "modulo 10⁹+7" to keep numbers small; Python's pow(a, b, m) does fast modular power.

from math import gcd, isqrt
print(gcd(48, 18), 48*18 // gcd(48, 18))
def sieve(n):
    p = [True]*(n+1); p[0:2] = [False, False]
    for i in range(2, isqrt(n)+1):
        if p[i]:
            for j in range(i*i, n+1, i): p[j] = False
    return [i for i, x in enumerate(p) if x]
print(sieve(50))

Problem 11.7.3 Compute gcd(48, 18) by Euclid and the LCM.

Step 148 mod 18 = 12; 18 mod 12 = 6; 12 mod 6 = 0. The last non-zero remainder is 6.
Step 2LCM = 48 × 18 / 6 = 864 / 6 = 144.
Answergcd 6, lcm 144.

Problem 11.7.4 Why does the sieve start crossing out at i*i?

Step 1A multiple i × k with k < i was already crossed out when we processed the smaller factor k.
AnswerThe first new composite for i is i², so starting there saves work.
CheckFor i = 5 the first crossed number is 25; 10, 15 and 20 were already crossed by 2 and 3.
Why it mattersIt makes the sieve fast enough for primes up to millions.

Connection to the real job. Hashing (Chapter 7), bloom filters and feature hashing use bit operations. Permission flags in Linux (rwx = 4+2+1) are bits. Applications: flags and permissions, compression, cryptography, fast set operations.

Chapter recap

  • Recursion = base case + a call on a smaller input; memoization removes repeated work and can turn exponential time into linear.
  • Backtracking is choose, explore, un-choose, with early pruning. Always copy the answer when you save it.
  • Subsets cost 2ⁿ, permutations n!, so use these only on small inputs.
  • DP recipe: state, recurrence, base case, fill order, answer cell. Define dp[i] in one sentence first.
  • 0/1 knapsack loops capacity downward; LIS is O(n²) or O(n log n) with binary search.
  • 2D DP on two strings (LCS, edit distance) uses a (m+1) × (n+1) table; grids and trees also fit the pattern.
  • Greedy is fast but only correct when the local best choice is provably safe; coin change with 1, 5, 6 is the classic failure.
  • For intervals: sort first (by start to merge, by end to select the most).
  • Bit tricks (x & (x−1), XOR cancelling) and number theory (gcd, sieve, pow(a, b, m)) are small tools with big payoff.

def subsets(a):
    res = []
    def go(i, cur):
        if i == len(a): res.append(cur); return
        go(i+1, cur); cur.append(a[i]); go(i+1, cur); cur.pop()
    go(0, []); return res

Answer: res.append(cur) stores the same list object each time; later pop() calls empty it. Use cur[:].
