A tree is data arranged like a family tree or a folder structure. A graph is a set of dots joined by lines, like cities and roads. Almost everything in data work is secretly one of these: a file system, a JSON document, a decision tree model, a pipeline of tasks, a road map, a social network, a train network. By the end of this chapter you will be able to store a tree or graph in Python, walk through it in the order you choose, find the shortest route, order tasks that depend on each other, and group things that are connected. You will use these skills to answer questions like "which dashboards break if I change this table?" in a real data job, and the same questions appear in coding interviews. Your running example is a small set of microservices and pipeline tasks, plus one 9-node tree. All code was run with Python 3 and the output is real. Every section builds only on the sections before it: trees first, then the general graph, then algorithms on graphs.

10.1 Binary Trees and the Four Traversals

INTUITION
Think of an org chart. The CEO is at the top, each manager has up to two reports. To list everybody, you must choose an order: boss first, boss in the middle, boss last, or floor by floor. Each order answers a different question.

Definitions. A tree has a root (top node). Each node has children. A node with no children is a leaf. A binary tree allows at most two children: left and right. The height is the number of levels from root to the deepest leaf. A traversal is a way to visit every node exactly once.

The three depth-first orders use recursion (or a stack). Level-order uses a queue (first in, first out) from Chapter 9.

from collections import deque

class Node:
    def __init__(s, v, l=None, r=None):
        s.val = v; s.left = l; s.right = r

def insert(root, v):
    if root is None: return Node(v)
    if v < root.val: root.left = insert(root.left, v)
    else:            root.right = insert(root.right, v)
    return root

root = None
for v in [8, 3, 10, 1, 6, 14, 4, 7, 13]:
    root = insert(root, v)

def inorder(n):   return inorder(n.left) + [n.val] + inorder(n.right) if n else []
def preorder(n):  return [n.val] + preorder(n.left) + preorder(n.right) if n else []
def postorder(n): return postorder(n.left) + postorder(n.right) + [n.val] if n else []

def level(n):
    out = []; q = deque([n])
    while q:
        row = []
        for _ in range(len(q)):          # exactly one level per pass
            x = q.popleft(); row.append(x.val)
            if x.left:  q.append(x.left)
            if x.right: q.append(x.right)
        out.append(row)
    return out

def height(n): return 0 if n is None else 1 + max(height(n.left), height(n.right))

Connection to the real job. A JSON file is a tree. A decision tree or random forest model is a tree (prediction walks root to leaf, O(h)). A SQL query plan is a tree. A folder walk (os.walk) is a traversal. Python's default recursion limit is about 1,000 frames, so a 1,000,000-node straight-line tree would crash a recursive traversal: use an explicit stack there.

Applications

  • File systems and the DOM of a web page.
  • Decision trees, random forests, gradient-boosted trees.
  • Expression parsing in compilers and SQL engines.
  • Org charts, category hierarchies in product catalogues.
COMMON MISTAKE
Forgetting the base case (if n is None). The recursion then calls .left on None and crashes with AttributeError. Write the base case first, always.

In plain words: a tree is just "lists inside lists". Learn to walk it with recursion and you can walk any nested data.

10.2 Binary Search Trees and Lowest Common Ancestor

INTUITION
Binary search on a sorted list throws away half the list each step. A binary search tree (BST) keeps that idea alive while you insert new items, which a sorted array cannot do cheaply.

Rule of a BST. For every node, all values in the left subtree are smaller, and all values in the right subtree are larger (or equal, depending on your duplicate rule). Search compares with the node and goes left or right: one branch per level, so O(h). In a balanced tree h ≈ log₂ n. In a badly ordered insertion (sorted input) the tree becomes a line and search becomes O(n). Real systems use self-balancing trees (AVL, red-black, B-trees in databases) to avoid this. You only need to know the idea for interviews.

Lowest Common Ancestor (LCA) of nodes a and b is the deepest node that has both as descendants (a node counts as its own descendant). In a BST, the LCA is the first node whose value lies between a and b: walk down from the root; if both are smaller go left, if both are larger go right, otherwise stop.

def search(n, t):
    steps = 0
    while n:
        steps += 1
        if t == n.val: return True, steps
        n = n.left if t < n.val else n.right
    return False, steps

def lca(n, a, b):
    while n:
        if a < n.val and b < n.val:   n = n.left
        elif a > n.val and b > n.val: n = n.right
        else: return n.val

def is_bst(n, lo=float('-inf'), hi=float('inf')):
    if not n: return True
    return lo < n.val < hi and is_bst(n.left, lo, n.val) and is_bst(n.right, n.val, hi)

10.3 Tries (Prefix Trees)

INTUITION
Your phone suggests "card", "care", "cart" as you type "car". It does not scan the whole dictionary. It follows the letters c, a, r down a tree and reads off everything below.

A trie stores words letter by letter. Each node has a dictionary of children (one per letter) and a flag end saying "a word finishes here". Words that share a prefix share a path. Insert and lookup cost O(L) where L is the word length, independent of how many words are stored.

class Trie:
    def __init__(s): s.kids = {}; s.end = False
    def add(s, w):
        n = s
        for c in w: n = n.kids.setdefault(c, Trie())
        n.end = True
    def starts(s, p):
        n = s
        for c in p:
            if c not in n.kids: return []
            n = n.kids[c]
        out = []
        def go(n, path):
            if n.end: out.append(p + path)
            for c in sorted(n.kids): go(n.kids[c], path + c)
        go(n, ""); return out

t = Trie()
for w in ["car", "card", "care", "cat", "dog", "do"]: t.add(w)
print(t.starts("car"), t.starts("do"), t.starts("x"))

10.4 Graphs: BFS, DFS and Connected Components

INTUITION
On a train map you have stations joined by tracks. Which stations can be reached from the central station? What is the fewest stops to the airport? These are graph questions.

Definitions. A graph is nodes (vertices) joined by edges. Edges can be directed (one way, like a hyperlink) or undirected (two way, like a friendship). They can carry a weight (distance, cost, latency). We store a graph as an adjacency list: a dictionary mapping each node to its neighbours. It uses O(V + E) memory, good for sparse graphs. An adjacency matrix uses O(V²).

BFS (breadth-first search) explores in rings: all nodes 1 hop away, then 2 hops. It uses a queue. In an unweighted graph it gives the shortest path in hops. DFS (depth-first search) goes as deep as possible, then backs up (recursion or a stack). Both cost O(V + E). A connected component is a group of nodes that can all reach each other.

 A ── B
 │    │
 C ── D
 │    │
 E ── F      (graph: A-B, A-C, B-D, C-D, C-E, D-F, E-F)

from collections import deque

g = {'A':['B','C'], 'B':['A','D'], 'C':['A','D','E'],
     'D':['B','C','F'], 'E':['C','F'], 'F':['D','E']}

def bfs(g, s):
    dist = {s: 0}; q = deque([s]); order = []
    while q:
        u = q.popleft(); order.append(u)
        for v in g[u]:
            if v not in dist:           # "seen" check prevents infinite loops
                dist[v] = dist[u] + 1; q.append(v)
    return order, dist

def dfs(g, u, seen=None, order=None):
    seen = seen if seen is not None else set()
    order = order if order is not None else []
    seen.add(u); order.append(u)
    for v in g[u]:
        if v not in seen: dfs(g, v, seen, order)
    return order

g2 = {1:[2], 2:[1,3], 3:[2], 4:[5], 5:[4], 6:[]}
def comps(g):
    seen = set(); res = []
    for s in g:
        if s not in seen:
            res.append(sorted(dfs(g, s, seen, [])))
    return res

10.5 Topological Sort

INTUITION
A data pipeline has steps: you cannot train before you build features, and you cannot build features before you clean. A topological sort puts tasks in an order that respects every "A must come before B" rule. Airflow and build tools do this.

It works on a DAG: a directed graph with no cycles. Kahn's algorithm: count each node's in-degree (number of arrows pointing in). Start with nodes of in-degree 0 (nothing to wait for). Remove one, output it, reduce the in-degree of its targets; when a target hits 0, add it to the queue. If you output fewer nodes than exist, there is a cycle, and no valid order exists. Cost O(V + E).

deps = {'extract':['clean'], 'clean':['features','report'],
        'features':['train'], 'train':['report'], 'report':[]}

def topo(g):
    indeg = {u: 0 for u in g}
    for u in g:
        for v in g[u]: indeg[v] += 1
    q = deque(sorted(u for u in g if indeg[u] == 0)); out = []
    while q:
        u = q.popleft(); out.append(u)
        for v in g[u]:
            indeg[v] -= 1
            if indeg[v] == 0: q.append(v)
    return out if len(out) == len(g) else None

print(topo(deps))
deps['report'].append('extract')      # report -> extract creates a cycle
print("cycle:", topo(deps))

10.6 Dijkstra's Shortest Path

INTUITION
A map app finds the fastest route, not the route with fewest turns. Edges have different costs, so BFS is not enough. Dijkstra always expands the closest unfinished node first, using a priority queue (heap, Chapter 9).

How it works. Keep dist[node] = best known cost from the start (infinity at first, 0 for the start). Push (0, start) into a min-heap. Pop the smallest; for each neighbour, if dist[u] + weight < dist[v], update and push. Skip stale heap entries. Time O((V + E) log V). It requires non-negative weights; with negative edges use Bellman-Ford.

import heapq
w = {'A':{'B':4,'C':1}, 'B':{'D':1}, 'C':{'B':2,'D':5}, 'D':{}}

def dijk(w, s):
    d = {u: float('inf') for u in w}; d[s] = 0
    pq = [(0, s)]; prev = {}

            if du + c < d[v]:
                d[v] = du + c; prev[v] = u
                heapq.heappush(pq, (d[v], v))
    return d, prev

10.7 Union-Find (Disjoint Set)

INTUITION
You are merging groups of friends as you learn "X knows Y". You need two fast operations: "are these two in the same group?" and "merge their groups". Union-find does both in almost constant time.

Each element points to a parent; the root of the chain names the group. find(x) walks to the root. union(a, b) links one root under the other. Two tricks make it fast: path compression (shorten the chain during find) and union by rank (attach the shorter tree under the taller). Together cost is nearly O(1) per operation (formally the inverse Ackermann function, which is below 5 for any realistic input).

class UF:
    def __init__(s, n): s.p = list(range(n)); s.r = [0]*n
    def find(s, x):
        while s.p[x] != x:
            s.p[x] = s.p[s.p[x]]      # path compression (halving)
            x = s.p[x]
        return x
    def union(s, a, b):
        a, b = s.find(a), s.find(b)
        if a == b: return False       # already same group
        if s.r[a] < s.r[b]: a, b = b, a
        s.p[b] = a
        if s.r[a] == s.r[b]: s.r[a] += 1
        return True

10.8 Minimum Spanning Tree (Kruskal and Prim)

INTUITION
You must connect 7 offices with cable at the lowest total length. You do not need every possible link, only enough that everyone is connected, with no wasteful loops.

A spanning tree connects all V vertices using exactly V − 1 edges and no cycle. The minimum spanning tree (MST) has the smallest total weight. Kruskal: sort edges by weight, take an edge if it does not create a cycle (check with union-find). Prim: grow one tree from a start node, always adding the cheapest edge leaving the tree (a heap). Both are greedy and give the same total weight.

10.9 Range Queries: Fenwick Tree, Segment Tree and Sparse Table

INTUITION
A prefix-sum array (Chapter 8) answers "what is the sum of positions 3 to 7?" in one step, but it is frozen: if one value changes, you must rebuild all the sums after it, which costs O(n). Many real systems need both: change one value and ask about a range, thousands of times. Think of a live leaderboard, or a metrics dashboard that sums the last 15 minutes of counters while new counters keep arriving. A Fenwick tree and a segment tree make both operations O(log n).

Definitions. A range query asks for a summary (sum, minimum, maximum) of a slice a[l..r]. A point update changes one value. A lowbit of a number i is its lowest set bit, i & -i (Chapter 11.7): lowbit(6) = 2, lowbit(8) = 8. All three structures below work on the same 8-number array, so you can compare them: [5, 3, 7, 9, 6, 4, 1, 2].

Fenwick tree (binary indexed tree)

A Fenwick tree is a plain array t (positions 1 to n). Entry t[i] stores the sum of the lowbit(i) values that end at position i. So t[4] covers 4 values (positions 1 to 4), t[6] covers 2 values (positions 5 and 6), and t[7] covers just position 7.

How to read it: each bar is one entry of t. The bar for t[6] sits above positions 5 and 6 only, so it holds 6 + 4 = 10. To get the prefix sum up to 7, hop left: take t[7], then remove the lowest bit of 7 to get 6, take t[6], remove the lowest bit of 6 to get 4, take t[4], then reach 0 and stop. The three bars you land on tile positions 1 to 7 exactly, with no overlap.

class Fenwick:
    def __init__(self, n):
        self.n = n
        self.t = [0] * (n + 1)          # 1-indexed; t[0] is unused

    def update(self, i, delta):         # add delta at position i (1-indexed)
        while i <= self.n:
            self.t[i] += delta
            i += i & -i                 # climb to the next entry that covers i

    def prefix(self, i):                # sum of positions 1..i
        s = 0
        while i > 0:
            s += self.t[i]
            i -= i & -i                 # drop the lowest set bit
        return s

    def range_sum(self, l, r):          # positions l..r inclusive
        return self.prefix(r) - self.prefix(l - 1)

Segment tree

A segment tree stores a summary for every aligned block: leaves hold single values, each parent holds the combined summary of its two children. It is more flexible than a Fenwick tree: it works for minimum and maximum, not only sums, and it supports lazy range updates. The bottom-up version keeps everything in one array of size 2n: leaves at positions n .. 2n-1, parent of node i is i // 2.

class SegTree:
    def __init__(self, a, op=lambda x, y: x + y, neutral=0):
        self.n = len(a); self.op = op; self.neutral = neutral
        self.t = [neutral] * self.n + list(a)          # leaves live at n..2n-1
        for i in range(self.n - 1, 0, -1):
            self.t[i] = op(self.t[2 * i], self.t[2 * i + 1])

    def update(self, i, v):                            # set a[i] = v
        i += self.n; self.t[i] = v
        while i > 1:
            i //= 2
            self.t[i] = self.op(self.t[2 * i], self.t[2 * i + 1])

    def query(self, l, r, show=False):                 # combine a[l:r], half-open
        res = self.neutral; l += self.n; r += self.n
        while l < r:
            if l & 1:
                if show: print("  take node", l, "=", self.t[l])
                res = self.op(res, self.t[l]); l += 1
            if r & 1:
                r -= 1
                if show: print("  take node", r, "=", self.t[r])
                res = self.op(res, self.t[r])
            l //= 2; r //= 2
        return res

Problem 10.9.4 Lazy propagation: add 5 to every value in a range, then ask a range sum, both in O(log n). The trick: when an update covers a whole block, do not touch its children. Store "pending add" on the block and push it down only when a later query needs to look inside.

import random

class LazySeg:
    def __init__(self, a):
        self.n = len(a); self.s = [0] * (4 * self.n); self.z = [0] * (4 * self.n)
        self._build(1, 0, self.n - 1, a)
    def _build(self, k, lo, hi, a):
        if lo == hi: self.s[k] = a[lo]; return
        mid = (lo + hi) // 2
        self._build(2 * k, lo, mid, a); self._build(2 * k + 1, mid + 1, hi, a)
        self.s[k] = self.s[2 * k] + self.s[2 * k + 1]
    def _push(self, k, lo, hi):
        if self.z[k]:
            mid = (lo + hi) // 2
            for c, clo, chi in ((2 * k, lo, mid), (2 * k + 1, mid + 1, hi)):
                self.s[c] += self.z[k] * (chi - clo + 1); self.z[c] += self.z[k]
            self.z[k] = 0
    def add(self, l, r, v, k=1, lo=0, hi=None):        # inclusive l..r
        hi = self.n - 1 if hi is None else hi
        if r < lo or hi < l: return
        if l <= lo and hi <= r:
            self.s[k] += v * (hi - lo + 1); self.z[k] += v; return
        self._push(k, lo, hi); mid = (lo + hi) // 2
        self.add(l, r, v, 2 * k, lo, mid); self.add(l, r, v, 2 * k + 1, mid + 1, hi)
        self.s[k] = self.s[2 * k] + self.s[2 * k + 1]
    def sum(self, l, r, k=1, lo=0, hi=None):
        hi = self.n - 1 if hi is None else hi
        if r < lo or hi < l: return 0
        if l <= lo and hi <= r: return self.s[k]
        self._push(k, lo, hi); mid = (lo + hi) // 2
        return self.sum(l, r, 2 * k, lo, mid) + self.sum(l, r, 2 * k + 1, mid + 1, hi)

A query of length L uses the largest k with 2k ≤ L and takes the minimum of two blocks that may overlap. Going deeper

Why does a Fenwick tree have the shape it has? Every positive integer is a sum of powers of two (its binary digits). A prefix of length 7 = 4 + 2 + 1 splits into three blocks of those sizes; a Fenwick tree stores exactly those blocks, aligned so that block boundaries come from clearing the lowest bit. That is why a query takes at most log2(n) + 1 hops: one per set bit. Segment trees generalise this: they let you choose any combining operation that is associative ((x op y) op z = x op (y op z)) and have a neutral element. Interviews use these for "range sum query, mutable", "count of smaller numbers after self" and "skyline" style problems. If an interviewer allows only the standard library, mention that you would reach for bisect and sorting first, and use a tree only when updates are mixed with queries.

10.10 Strongly Connected Components and Bipartite Graphs

INTUITION
In a one-way street map, two places are in the same strongly connected component (SCC) if you can drive from each to the other. A roundabout is one. A dead-end street leading away from it is not part of it. Collapse every SCC into a single dot and what remains is always a DAG (a graph with no cycles), so topological sort from 10.5 works again.

Definitions. In a directed graph, a strongly connected component is a maximal set of nodes where every node can reach every other. A graph is bipartite if you can colour nodes with two colours so every edge joins different colours. Real uses: finding circular dependencies between services (an SCC with more than one node is a cycle), and checking whether tasks can be split into two groups with no conflict inside a group.

Kosaraju's algorithm in three lines of idea

  1. Run DFS on the graph. Record nodes in the order they finish (post-order).
  2. Build the reverse graph (flip every edge).
  3. Take nodes in reverse finishing order. For each unvisited node, DFS on the reversed graph. Everything reached is one SCC.

Why it works in one sentence: the node that finishes last lies in a "source" component; in the reversed graph you can only leave that component into itself, so the DFS cannot escape into another component.

import sys
sys.setrecursionlimit(10000)

def scc(n, edges):
    g = [[] for _ in range(n)]; rg = [[] for _ in range(n)]
    for u, v in edges:
        g[u].append(v); rg[v].append(u)
    seen = [False] * n; order = []
    def dfs1(u):
        seen[u] = True
        for v in g[u]:
            if not seen[v]: dfs1(v)
        order.append(u)                          # finish time order
    for u in range(n):
        if not seen[u]: dfs1(u)
    comp = [-1] * n; groups = []
    def dfs2(u, c):
        comp[u] = c; groups[c].append(u)
        for v in rg[u]:
            if comp[v] == -1: dfs2(v, c)
    for u in reversed(order):
        if comp[u] == -1:
            groups.append([]); dfs2(u, len(groups) - 1)
    return [sorted(x) for x in groups]

Bipartite check by two-colouring

Colour the start node 0. Colour every neighbour 1, their neighbours 0, and so on (BFS). If an edge ever joins two nodes of the same colour, the graph is not bipartite. The exact rule: a graph is bipartite if and only if it has no cycle of odd length.

from collections import deque

def is_bipartite(n, edges):
    g = [[] for _ in range(n)]
    for u, v in edges:
        g[u].append(v); g[v].append(u)
    color = [-1] * n
    for s in range(n):                           # one BFS per component
        if color[s] != -1: continue
        color[s] = 0; q = deque([s])
        while q:
            u = q.popleft()
            for v in g[u]:
                if color[v] == -1:
                    color[v] = 1 - color[u]; q.append(v)
                elif color[v] == color[u]:
                    return False
    return True

Going deeper

Tarjan's algorithm finds all SCCs with one DFS instead of two, keeping for each node the earliest-discovered node it can reach (low) and a stack of nodes not yet assigned. A node whose low equals its own discovery time is the root of an SCC. It is the same O(V + E) time, and is what most libraries use. Practical uses: detecting import cycles in a codebase, finding groups of mutually dependent tables in a warehouse, and the 2-SAT problem (boolean constraints), which reduces to SCCs.

10.11 Shortest Paths Beyond Dijkstra: Bellman-Ford, Floyd-Warshall, A*

Dijkstra (10.6) is fast but has two limits: edge weights cannot be negative, and it solves one source at a time. Three tools remove those limits. Every one of them is built on a single move called relaxation: if going through u to v is shorter than the best known way to v, update dist[v] = dist[u] + w.

How to read it: the red number under each node is the best distance found so far, "inf" means no path found yet. In step 2, finalising B gives C a better distance (5 instead of 7) and gives D a first one (10). In step 3, C improves D from 10 to 6. In step 4, finalising D improves E from 10 to 8. Teal nodes never change again. A negative edge would break this: a finalised node could still be improved later.

Bellman-Ford

Idea. Relax every edge, and repeat that pass V - 1 times (V = number of nodes). A shortest path has at most V - 1 edges, and after pass k all shortest paths using at most k edges are correct. A V-th pass that still improves something proves a negative cycle (a loop whose total weight is below zero, so going round it forever keeps lowering the distance). Cost: O(V * E).

Problem 10.11.1 Edges A→B 4, A→C 5, B→C -3, C→D 3, B→D 6. Shortest distances from A, with a negative edge.

Pass 2Nothing improves, so we could stop early.
AnswerA 0, B 4, C 1, D 4. Here a lazy-heap Dijkstra happens to survive, because B (4) is popped before C (5). Change the edges to A→B 1, A→C 2, C→B -5 and a Dijkstra that finalises each node once marks B done at distance 1, while the true distance is 2 - 5 = -3. Heap versions that skip the finalised check may recover, but can take exponential time. Do not rely on either.
INF = float("inf")

def bellman_ford(n, edges, src):
    dist = [INF] * n; dist[src] = 0
    for rnd in range(1, n):                      # at most n-1 passes
        changed = False
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w; changed = True
        print(f"after pass {rnd}: {dist}")
        if not changed: break
    for u, v, w in edges:                         # one more look: still improving?
        if dist[u] + w < dist[v]:
            return None                           # negative cycle reachable
    return dist

Floyd-Warshall (all pairs)

Idea. Let d[i][j] be the best known distance from i to j. For each node k in turn, ask: "is going i → k → j shorter?" After processing k = 0, 1, ..., n-1, the matrix holds the shortest distances between every pair. Three nested loops, O(V3), memory O(V2). The loop on k must be the outermost. Put it inside and the answer is wrong, because the meaning "using only the first k nodes as stops" is lost.

Problem 10.11.2 Four cities 0..3 with one-way roads 0→1 (3), 0→3 (10), 1→2 (4), 2→3 (2), 3→0 (1). Find all shortest distances.

SetupThe matrix starts with 0 on the diagonal, the road weights where a road exists, and infinity elsewhere.
k = 1Via city 1: 0→1→2 = 3 + 4 = 7, better than infinity, so d[0][2] = 7.
k = 2Via city 2: 0→2→3 = 7 + 2 = 9, better than 10, so d[0][3] = 9. Also 1→2→3 = 6.
k = 3Via city 3 (which leads back to 0 in 1): 1→3→0 = 6 + 1 = 7, 2→3→0 = 3, and so on for the rest.
INF = float("inf")

def floyd(n, edges):
    d = [[0 if i == j else INF for j in range(n)] for i in range(n)]
    for u, v, w in edges: d[u][v] = min(d[u][v], w)
    for k in range(n):                            # k outermost
        for i in range(n):
            for j in range(n):
                if d[i][k] + d[k][j] < d[i][j]:
                    d[i][j] = d[i][k] + d[k][j]
    return d

A* search (guided shortest path)

Idea. Dijkstra explores in all directions by distance travelled so far, g. A* orders its priority queue by g + h, where h is a cheap estimate of the distance still to go. On a grid with 4-direction moves the Manhattan distance |dx| + |dy| is a good h. If h never over-estimates the true remaining distance (it is admissible), A* still returns a shortest path but usually expands far fewer nodes. With h = 0 A* is exactly Dijkstra.

Problem 10.11.3 On an open 30 by 30 grid with a wall, compare the number of cells expanded by Dijkstra and by A* from the top-left to the bottom-right corner.

SetupGrid with a vertical wall at column 15 from row 0 to row 25, leaving a gap at the bottom. Moves up, down, left, right, each cost 1.
ExpectBoth find the same path length. A* expands fewer cells. Exact counts come from the program, they depend on tie-breaking.
import heapq

N = 30
wall = {(r, 15) for r in range(0, 26)}
start, goal = (0, 0), (N - 1, N - 1)

def solve(use_h, walls, prefer_deep=False):
    h = (lambda p: abs(p[0] - goal[0]) + abs(p[1] - goal[1])) if use_h else (lambda p: 0)
    sign = -1 if prefer_deep else 1          # tie-break: prefer larger g when f is equal
    g = {start: 0}; pq = [(h(start), 0, start)]; expanded = 0; done = set()
    while pq:
        f, key, u = heapq.heappop(pq); d = g[u]
        if u in done: continue
        done.add(u); expanded += 1
        if u == goal: return d, expanded
        for dr, dc in ((1,0),(-1,0),(0,1),(0,-1)):
            v = (u[0] + dr, u[1] + dc)
            if 0 <= v[0] < N and 0 <= v[1] < N and v not in walls and d + 1 < g.get(v, 10**9):
                g[v] = d + 1; heapq.heappush(pq, (d + 1 + h(v), sign * (d + 1), v))

print("wall  Dijkstra (h = 0):", solve(False, wall))
print("wall  A* Manhattan    :", solve(True, wall))
print("open  Dijkstra (h = 0):", solve(False, set()))
print("open  A* Manhattan    :", solve(True, set()))
print("open  A*, deep tie-break:", solve(True, set(), prefer_deep=True))

On the open grid, every cell on the way to the goal has the same f = g + h (58), so the plain tie-break expands all 900 cells and A* is no better than Dijkstra. Preferring the larger g among equal f values makes the search dive toward the goal and expand only 59 cells, which is the 58 steps plus the start. KEY IDEA
Pick the algorithm by asking three questions: are the edges weighted? can a weight be negative? do I need one source or all pairs? Equal weights: BFS. Non-negative weights: Dijkstra (or A* with a safe heuristic). Negative weights: Bellman-Ford. All pairs on a small graph: Floyd-Warshall.

Chapter recap

  • A tree is a connected graph with no cycles; a binary tree has at most two children per node.
  • In-order of a BST gives sorted order; level-order uses a queue.
  • BST search costs O(h): fast if balanced, slow if it becomes a line. Databases use balanced B-trees.
  • LCA in a BST: walk down until the two values split.
  • A trie shares prefixes and answers "everything starting with..." in O(L).
  • BFS finds fewest hops in unweighted graphs; DFS explores deeply. Both cost O(V + E) and need a seen set.
  • Topological sort orders a DAG; leftover nodes mean a cycle.
  • Dijkstra handles non-negative weights with a heap; union-find tracks groups in near O(1); Kruskal and Prim build the MST.
