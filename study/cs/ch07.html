Imagine an online shop whose order system leaves five million rows in a file. You must find the slowest orders to pack, count the returns per product, and remove duplicate customers. Your first script runs all night, and your colleague's script finishes in seconds on the same data. The difference is not the computer. It is the shape of the work each script does. In this chapter you learn to measure that shape (Big-O), and then you learn the basic tools (lists, strings, hash maps, sorting) that make code fast. By the end you can look at a loop, say how its cost grows when the data grows, and pick the right tool.

Running example for this chapter. We use a tiny version of a restaurant kitchen log: eight tickets, each a dish name and the preparation time in seconds. You will meet it again in Chapters 8 and 9.

7.1 Complexity Analysis and Big-O

BASIC EXPLANATION
Complexity analysis measures how the time or memory of an algorithm grows with the input size n. Big-O notation gives an upper bound, such as O(n) or O(n log n), and ignores constants.
INTUITION
Imagine a restaurant kitchen. With 100 orders the cooks need 1 hour. With 200 orders do they need 2 hours (fine), 4 hours (worrying), or 100 hours (disaster)? You do not need a stopwatch to guess if you know how the work grows. Big-O describes that growth shape and ignores small details like machine speed.

Words you need first

WordPlain meaning
Input size nHow many items you give the code (rows in the file)
StepOne tiny action: compare two numbers, read one item, add one number
Worst caseThe input that makes your code do the most steps
SpaceExtra memory your code uses, not counting the input

Why we drop constants. A faster computer makes every step cheaper by the same factor, so 3n and n grow in the same shape. Big-O keeps the shape and ignores the speed of the machine. That is also why it is a fair way to compare two programs written by two people.

ClassExample valueWhere it appears in the job
O(1)Look up user id 42 in a dictA cache lookup in a web service
O(log n)Binary search in 1,000 sorted timestamps (about 10 steps)A database index lookup
O(n)Read 1,000,000 log lines oncegrep through a log file
O(n²)Compare every request with every other requestA slow df.apply that scans another table per row

Formal definition

We say an algorithm is O(f(n)) when, for a large input of size n, the number of basic steps grows no faster than a constant times f(n). We drop constants and smaller terms:

  • 3n + 10 becomes O(n).
  • n² + 5n + 2 becomes O(n²).
  • 5 steps always becomes O(1) (constant).

Time complexity counts steps. Space complexity counts extra memory used (not counting the input itself).

The common classes, from fastest to slowest:

ClassNameExamplen = 1,000
O(1)constantread a[5], dict lookup1
O(log n)logarithmicbinary searchabout 10
O(n)linearscan a list1,000

Worked examples (code and output)

Let us count steps for three loops, for n = 10, 100, 1000.

Predict first: for n = 1000, how many steps will the log loop, the linear loop and the quadratic loop run? Write three guesses, then run.

def count_linear(n):
    ops = 0
    for i in range(n): ops += 1
    return ops

def count_quadratic(n):
    ops = 0
    for i in range(n):
        for j in range(n): ops += 1
    return ops

def count_log(n):          # halve until 1
    ops = 0
    while n > 1:
        n //= 2; ops += 1
    return ops

for n in (10, 100, 1000):
    print(n, count_log(n), count_linear(n), count_quadratic(n))
10 3 10 100
100 6 100 10000
1000 9 1000 1000000

Read each row: n grows 100 times (10 to 1000). The log loop went from 3 to 9 steps. The linear loop grew 100 times. The quadratic loop grew 10,000 times. That is why O(n²) code "works on my laptop with 100 rows" and dies in production with a million rows.

Problem 7.1.1 Two functions detect a duplicate in a list. Which is better for 1,000,000 items?

Predict first: you will trust one of these functions with 1,000,000 items. Which one, and why?

def dup_slow(a):                 # compare every pair
    for i in range(len(a)):
        for j in range(i+1, len(a)):
            if a[i] == a[j]: return True
    return False

def dup_fast(a):                 # remember what we saw
    seen = set()
    for x in a:
        if x in seen: return True
        seen.add(x)
    return False
  • Step 1 dup_slow has two nested loops. In the worst case (no duplicate) it makes about n(n-1)/2 comparisons. For n = 1,000,000 that is about 5 × 10¹¹.
  • Step 2 dup_fast does one pass, and each set lookup is O(1) on average. So about 10⁶ steps. But it needs extra memory: O(n) space.
  • Step 3 I timed both on list(range(3000)) (no duplicates). The fast one was more than 100 times faster, and the gap widens as n grows.
  • Answer dup_fast is better: O(n) time and O(n) space, against O(n²) time and O(1) space for dup_slow. We traded memory for speed. This trade is the most common idea in algorithms.
  • Check Run both on [3, 1, 4, 1, 5]: both return True, so the answers agree and only the cost differs.
  • Meaning At an assumed 10 million simple steps per second, 5 × 10¹¹ steps take about 14 hours, while 10⁶ steps take a fraction of a second. Same answer, a completely different night.

Problem 7.1.2 Compute the complexity of this code.

Predict first: the code below has two loops. Is the answer O(n) or O(n²)?

for i in range(n):          # n times
    for j in range(5):      # 5 times
        total += i * j
for k in range(n):          # n times
    total += k
  • Step 1 First block: n × 5 = 5n steps.
  • Step 2 Second block: n steps.
  • Step 3 Total 6n. Drop the constant 6.
  • Answer O(n). The inner loop runs a fixed 5 times, so it is not a second power of n.
  • Check For n = 1000 the first block does 5 × 1000 = 5000 steps and the second does 1000, so 6000 in total, which is exactly 6n.
  • Meaning Double the data and the work only doubles. This code scales safely.

The picture

How to read it: each bar is the number of steps for n = 1,000. The bar lengths use a log scale, otherwise the O(n²) bar would be 100,000 times longer than the O(log n) bar and you could not see the small ones. Longer bar means more work.

steps

  |                          *

Best, worst and average case

The same code can be fast or slow depending on the input. In dup_fast, if the first two items are equal it stops at once (best case, O(1)). If no duplicates it scans everything (worst case, O(n)). Interviews mean worst case unless they say otherwise. A restaurant manager says the same: "look at the slowest 1% of orders, not the average wait." Same idea.

Connection to the real job

  • Pandas df.apply(row_function, axis=1) with an inner scan of another DataFrame is hidden O(n²). Rewriting it as a merge (hash join) is O(n).
  • SQL: a missing index turns a lookup from O(log n) into a full table scan O(n).
  • Everyday intuition: a checkout page that is O(n²) in the number of cart items works fine with 3 items and freezes with 300.

Applications

  • Choosing between data structures in any program.
  • Predicting whether a feature pipeline will finish overnight.
  • Explaining your solution in a coding interview (always state time and space).
COMMON MISTAKE
Forgetting hidden loops. x in my_list is a loop inside (O(n)). s = s + "a" copies the string. list.pop(0) shifts all items. Put any of these inside a for loop and you silently get O(n²).
INTERVIEW TIP
Always say both: "This is O(n log n) time and O(n) space." Then say what you could trade off.

Check yourself

  1. What is the complexity of a loop that halves n each step?

Answer: O(log n).

  1. What is O(3n² + 7n + 100) in simple form?

Answer: O(n²).

  1. Why is x in my_list inside a loop dangerous?

Answer: x in my_list is O(n), so the whole thing becomes O(n²).

7.2 Amortized Analysis

BASIC EXPLANATION
Amortized analysis gives the average cost per operation over a sequence of operations, even if single operations are sometimes costly. Appending to a dynamic array is amortized O(1).
INTUITION
A bus conductor sells tickets quickly all day, but once in a while stops to count all the money (slow). If you look at one single moment, the job can look slow. If you look at the whole day, the average cost per ticket is small. Amortized cost is "average cost per operation over a long sequence", with a guarantee, not a hope.

Words you need first

WordPlain meaning
Dynamic arrayAn array that can grow (Python list)
CapacityHow many slots are reserved, even if not all are used yet
ResizeGet a bigger block of memory and copy every item into it
AmortizedThe average cost per operation over a long sequence

Why not simply reserve a huge array at the start? Because you do not know the size, and a huge empty block wastes memory. Growing in big steps is the compromise.

ItemExample valueWhere it appears in the job
list.appendCollecting 1 row per requestBuilding a result list before making a DataFrame
Hash table resizeA dict that grew past its limitWhy one dict insert is sometimes slow
Write bufferFlush every 1,000 rowsBulk inserts into a database

How it works

A Python list is a dynamic array. It keeps spare room. append is normally one step. When the room is full, Python allocates a bigger block and copies every item (slow, O(n)). Because the new room grows by a proportion (roughly 1.125x in CPython for big lists; many languages use 2x), full copies get rarer and rarer. The total copy work over n appends is O(n), so each append is amortized O(1).

Worked examples

Problem 7.2.1 Watch a real list resize. We append 64 items and print the memory size each time it changes.

Predict first: out of 64 appends, how many trigger a resize: 64, 32 or 8?

import sys
lst = []; last = sys.getsizeof(lst); resizes = 0; sizes = [last]
for i in range(64):
    lst.append(i)
    z = sys.getsizeof(lst)
    if z != last:
        resizes += 1; last = z; sizes.append(z)
print("resizes in 64 appends:", resizes)
print(sizes)
resizes in 64 appends: 8
[56, 88, 120, 184, 248, 312, 376, 472, 568]
  • Step 1 An empty list is 56 bytes. Each pointer is 8 bytes.
  • Step 2 Memory jumps 56, 88, 120, 184... So the list reserved extra room several times, but only 8 times in 64 appends.
  • Answer 56 of the 64 appends were plain cheap steps. The exact byte numbers depend on the Python version, so do not memorize them; remember the idea.
  • Check 8 resizes in 64 appends means 56 of the 64 appends found free room and cost one step.
  • Meaning Resizing is rare, so building a list one append at a time is cheap on average.

Problem 7.2.2 Prove amortized O(1) with doubling. Start with capacity 1; double when full. Count total copies for 1,024 appends.

Predict first: guess the number of copies for 1,024 appends. About 10? About 1,000? About 500,000?

copies = 0; cap = 1; n = 0
for i in range(1, 1025):
    if n == cap:          # full: allocate double the room, copy n items
        copies += n; cap *= 2
    n += 1
print(copies, copies / 1024)
1023 0.9990234375
  • Step 1 Copies happen when size is 1, 2, 4, 8, ... 512. That is 1+2+4+...+512 = 1023 copies.
  • Step 2 I ran a simulation that gave 1023 total copies, and 1023/1024 = 0.999 copies per append.
  • Step 3 Add the 1 write per append: about 2 steps per append in total.
  • Answer Total work is about 2n, so the cost per append is a constant (about 2). That is amortized O(1).
  • Check 1023 copies plus 1024 writes is 2,047 steps for 1,024 appends, close to 2n.
  • Meaning Each append pays about 2 steps on average, however large the list becomes.

The picture

append #:   1  2  3  4  5  6  7  8  9 ...
cost:       1  2  1  3  1  1  1  5  1 ...   (spikes at 2, 4, 8, 16...)
average:    stays near 2-3, does NOT grow with n

Connection to the real job

  • Latency spikes: a service that is fast but occasionally pauses (garbage collection, resize, compaction) has good average latency and bad p99. Amortized thinking tells you the average is fine; a percentile chart (like the slowest 1% of deliveries) shows the spike.
  • Pandas append in a loop (copying a DataFrame each time) is not amortized, it is O(n) every time. Collect in a list, then build once.

Applications

  • Python list, Java ArrayList, C++ vector.
  • Hash tables (resize when too full).
  • Database write buffers, log batching.
COMMON MISTAKE
Saying "append is O(n) because resizing copies". That is the worst single case, not the amortized one. Also: insert(0, x) is truly O(n) every time.

Check yourself

  1. Is list.append O(1) worst case?

Answer: No, amortized O(1); a single resize is O(n).

  1. Why does growing by a proportion matter?

Answer: Copies become rarer as the list grows, so total work stays O(n).

  1. Which is slow in a loop: lst.append(x) or lst.insert(0, x)?

Answer: insert(0, x), it shifts every item.

7.3 Arrays and Strings

BASIC EXPLANATION
An array stores items in consecutive memory so any index is read in O(1) time. A string is a sequence of characters, and both are the base for many algorithms.
INTUITION
An array is a row of numbered lockers, all the same size, side by side in memory. Because they are side by side, jumping to locker 5000 is instant: address = start + 5000 × size. But squeezing a new locker in the middle means moving all later ones.

Words you need first

WordPlain meaning
IndexThe position number of an item. The first item is index 0
SliceA copy of a part of a list or string, written a[i:j]
ImmutableCannot be changed after it is made (Python strings)
In placeChanging the same list instead of building a new one
ItemExample valueWhere it appears in the job
List of numbers[120, 340, 95, ...] preparation times in secondsThe same data as a NumPy array or a DataFrame column
StringOne log lineParsing and cleaning text
Slicea[-100:], the last 100 ticketsLooking at the most recent events
Read and write indexClean a sorted list of ids in placeDedupe step in an ETL job

How it works

Python lists give array behaviour. Strings are arrays of characters but immutable: you cannot change one in place; every "change" builds a new string.

OperationListCost
a[i] read/writeO(1)
appendamortized O(1)
pop() (end)O(1)
pop(0), insert(0, x)O(n)
x in aO(n)
slice a[i:j]O(j - i) (makes a copy)

Worked examples

Problem 7.3.1 Rotate [1,2,3,4,5,6,7] right by 3.

Predict first: what does rotate([1,2,3,4,5,6,7], 3) return?

def rotate(a, k):
    k %= len(a)
    return a[-k:] + a[:-k]
print(rotate([1,2,3,4,5,6,7], 3))
[5, 6, 7, 1, 2, 3, 4]
  • Step 1 k %= len(a) handles k bigger than the length (rotating 10 times a list of 7 is the same as 3).
  • Step 2 The last 3 items [5,6,7] go in front; the first 4 follow.
  • Answer [5, 6, 7, 1, 2, 3, 4]. Time O(n), space O(n).
  • Check Rotating by the full length (k = 7) should change nothing. 7 % 7 = 0, and a[-0:] + a[:-0] is the whole list plus an empty list, so the list is unchanged.
  • Meaning The last three items moved to the front, like turning a ring of lockers three places.

Typical wrong version. You forget k %= len(a):

def rotate_wrong(a, k): return a[-k:] + a[:-k]
print(rotate_wrong([1,2,3,4,5,6,7], 10))
[1, 2, 3, 4, 5, 6, 7]

There is no error message. For k = 10 the slice a[-10:] is the whole list and a[:-10] is empty, so the list is silently unchanged. The right answer is the same as rotating by 10 % 7 = 3. The fix is the line k %= len(a). Silent wrong answers are the dangerous kind, so test with a k bigger than the length.

Problem 7.3.2 Is "A man, a plan, a canal: Panama" a palindrome, ignoring punctuation and case?

Predict first: is "hello" a palindrome? What about the empty string ""?

def is_pal(s):
    t = [c.lower() for c in s if c.isalnum()]
    return t == t[::-1]
print(is_pal("A man, a plan, a canal: Panama"), is_pal("hello"))
True False
  • Step 1 Keep only letters and digits, lower-cased.
  • Step 2 Compare with its reverse.
  • Answer The first is a palindrome, hello is not. O(n) time and space. (Chapter 8 does it in O(1) space with two pointers.)
  • Check is_pal("") returns True: nothing is left after filtering, and an empty list equals its own reverse.
  • Meaning Punctuation and case are ignored, so a sentence that reads the same both ways counts.

Problem 7.3.3 Remove duplicates from a sorted array in place using a read index and a write index. Then run-length compress a string.

Predict first: what are k and the first k items of x after the call, and what does compress print?

def remove_dups_sorted(a):
    if not a: return 0
    w = 1
    for r in range(1, len(a)):
        if a[r] != a[w-1]:
            a[w] = a[r]; w += 1
    return w

x = [1,1,2,2,2,3,4,4]
k = remove_dups_sorted(x); print(k, x[:k])

def compress(s):
    out = []; i = 0
    while i < len(s):
        j = i
        while j < len(s) and s[j] == s[i]: j += 1
        out.append(s[i] + str(j - i)); i = j
    return "".join(out)
print(compress("aaabccdddd"))
4 [1, 2, 3, 4]
a3b1c2d4
  • Step 1 r reads every item. w marks where the next new value goes.
  • Step 2 Only when a[r] differs from the last written value do we write it.
  • Step 3 For compress, i marks the start of a run and j finds its end.
  • Answer 4 unique values [1,2,3,4] in O(n) time and O(1) extra space; the string compresses to a3b1c2d4.
  • Check a3b1c2d4 expands back to aaabccdddd, and 3 + 1 + 2 + 4 = 10 letters, the original length.
  • Meaning You cleaned the list without making a second list, which matters when the data barely fits in memory.

Typical wrong version. Reading one past the end of a list:

x = [1, 2, 3]
print(x[len(x)])
IndexError: list index out of range

A list of length 3 has indexes 0, 1, 2, never 3. The last item is x[len(x) - 1], or simply x[-1].

Connection to the real job

  • Cleaning text (tokenizing, removing punctuation) is string work.
  • NumPy arrays are the same idea but typed and faster; vectorized code replaces Python loops.
  • Building a long string in a loop: collect pieces in a list, then "".join(pieces).

Applications

  • Log parsing, text preprocessing for NLP, time-series windows, image rows.
COMMON MISTAKE
Off-by-one errors with slices and indexes. a[i:j] includes i, excludes j. Test with the empty list and a one-item list before submitting.

Check yourself

  1. Why are strings called immutable?

Answer: You cannot change them in place; operations create new strings.

  1. What does a[-3:] give for [1,2,3,4,5]?

Answer: [3, 4, 5].

  1. Cost of a[2:7]?

Answer: O(5), a copy of 5 items.

7.4 Hashing: Maps, Sets, Counting, Grouping

BASIC EXPLANATION
A hash map stores key-value pairs and finds a key in average O(1) time using a hash function. A hash set stores unique keys. They are used for lookup, counting and grouping.
INTUITION
A library with no catalogue means you walk every shelf (O(n)). A hash map is a magic catalogue: you feed in the book title, a formula (the hash function) turns it into a shelf number, and you walk straight there. Lookup becomes about one step.

Words you need first

WordPlain meaning
Key and valueA key is what you look up (a user id). The value is what you get back (the profile)
Hash functionA formula that turns a key into a whole number
BucketA numbered slot in the table where an item is stored
CollisionTwo different keys that land in the same bucket
HashableA key that never changes, so its hash never changes (numbers, strings, tuples)
ItemExample valueWhere it appears in the job
dictuser_id -> profileA lookup table in an ETL job
setOrder ids already processedDeduplication
CounterCount of HTTP status codes: 200 and 500Error-rate reports
defaultdict(list)Group tickets by dish nameThe same job as SQL GROUP BY

How it works

A hash function turns a key into an integer. The table uses that integer to pick a bucket (a slot). Two different keys can land in the same bucket (a collision); the table handles it (Python uses open addressing). On average: insert, lookup and delete are O(1). Worst case (terrible collisions) O(n), but you rarely meet it.

Rules: keys must be hashable, which means immutable. Numbers, strings and tuples are fine. Lists and dicts are not.

print(hash("abc") == hash("abc"))
try:
    {[1]: 2}
except TypeError as e:
    print(e)
True
cannot use 'list' as a dict key (unhashable type: 'list')

(Note: Python randomizes string hashes between runs, so never print or store them. Within one run they are stable.)

Four patterns that solve hundreds of problems

  1. Seen-set: "have I met this before?" (duplicates).
  2. Counting: Counter to count frequency.
  3. Grouping: defaultdict(list) with a canonical key.
  4. Complement lookup: store what you have seen, look for what you need (Two Sum).

Worked examples

Problem 7.4.1 Two Sum: find indexes of two numbers adding to the target.

Predict first: what indexes does two_sum([3, 2, 4], 6) return? (3 + 3 = 6 is tempting, but you may not use the same item twice.)

def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen: return [seen[target - x], i]
        seen[x] = i
print(two_sum([2,7,11,15], 9), two_sum([3,2,4], 6))
[0, 1] [1, 2]
  • Step 1 For each x, the partner we need is target - x.
  • Step 2 If the partner is already in the dict, we are done. Otherwise store x with its index.
  • Answer [0, 1] for the first (2 + 7 = 9) and [1, 2] for the second (2 + 4 = 6). O(n) time, O(n) space. The naive double loop is O(n²).
  • Check 2 + 7 = 9 for the first call and 2 + 4 = 6 for the second, as required.
  • Meaning One pass with O(1) lookups replaces a double loop: about 10⁶ lookups instead of about 5 × 10¹¹ comparisons for a million numbers.

Typical wrong version. You store the number before you check for its partner:

def two_sum_wrong(nums, t):
    seen = {}
    for i, x in enumerate(nums):
        seen[x] = i                     # stored too early
        if t - x in seen: return [seen[t - x], i]
print(two_sum_wrong([3, 2, 4], 6))
[0, 0]

The first 3 finds itself as its own partner, so the answer uses one item twice. The fix: check first, then store, as in the correct version.

Problem 7.4.2 Group anagrams, check two words, and find the first unique character.

Predict first: how many groups will come out of the six words, and which words share a group?

from collections import Counter, defaultdict
def group_anagrams(words):
    g = defaultdict(list)
    for w in words: g["".join(sorted(w))].append(w)
    return list(g.values())
print(group_anagrams(["eat","tea","tan","ate","nat","bat"]))
print(Counter("listen") == Counter("silent"))

def first_unique(s):
    c = Counter(s)
    for i, ch in enumerate(s):
        if c[ch] == 1: return i
    return -1
print(first_unique("loveleetcode"), first_unique("aabb"))
[['eat', 'tea', 'ate'], ['tan', 'nat'], ['bat']]
True
2 -1
  • Step 1 Anagrams have the same letters, so sorting the letters gives the same key ("aet" for eat, tea, ate).
  • Step 2 Counter equality compares letter counts directly.
  • Step 3 First unique: count first, then scan for the first letter with count 1. In loveleetcode, l repeats, o repeats, v appears once at index 2.
  • Answer Three groups; listen and silent are anagrams; first unique index is 2 (and -1 when none).
  • Check The groups hold 3 + 2 + 1 = 6 words, so no word was lost.
  • Meaning This is GROUP BY where the grouping column is computed: the sorted letters.

Typical wrong version. You use a list inside the key:

d = {}
d[(1, [2])] = "x"
TypeError: cannot use 'tuple' as a dict key (unhashable type: 'list')

A tuple is hashable only if everything inside it is hashable. Convert the inner list to a tuple first: (1, (2,)).

Problem 7.4.3 Count subarrays whose sum equals k = 3 in [1,2,3,-2,2] (prefix sums with a hash map).

Predict first: how many subarrays of [1, 2, 3, -2, 2] add up to 3? Count by hand, then run.

def subarray_sum_k(a, k):
    cnt = Counter({0: 1}); s = 0; res = 0
    for x in a:
        s += x; res += cnt[s - k]; cnt[s] += 1
    return res
print(subarray_sum_k([1,2,3,-2,2], 3))
4
  • Step 1 Running sum s. A subarray ending here has sum k if some earlier prefix equals s - k.
  • Step 2 The map counts how often each prefix sum appeared. Start with {0: 1} for "empty prefix".
  • Answer 4. The subarrays are [1,2], [3], [2,3,-2] and [3,-2,2]. Time O(n).
  • Check By hand: 1+2 = 3, 3, 2+3-2 = 3, 3-2+2 = 3. That is four subarrays, matching the code.
  • Meaning You counted all matching subarrays without ever trying every start and end pair, so it stays fast on millions of numbers.

The picture

key "eat" --hash()--> 4172... --mod table size--> bucket 3
key "tea" --hash()--> 9981... --mod table size--> bucket 3   (collision, handled)
bucket 3 -> [eat][tea]    bucket 7 -> [bat]

Connection to the real job

  • A SQL GROUP BY and a hash join are exactly these maps inside the database.
  • Pandas value_counts(), groupby, merge use hashing.
  • Feature hashing in ML turns text tokens into column numbers.

Applications

7.5 Sorting and Custom Comparators

BASIC EXPLANATION
Sorting arranges items in order, and efficient algorithms take O(n log n) time. A custom comparator is a rule you supply that tells the sort how to order two items.
INTUITION
Sorting is arranging a deck of cards. The lazy way compares everything with everything (O(n²)). Clever ways split the deck, sort small piles, and combine: that gives O(n log n). A mathematical fact: any method that sorts by comparing pairs needs at least about n log n comparisons. Only methods that do not compare (like counting) can beat it.

Words you need first

The four algorithms

  • Merge sort: split in half, sort each half, merge the two sorted halves. Always O(n log n), needs O(n) extra space, and is stable (equal items keep their order).
  • Quick sort: pick a pivot, put smaller items left and larger right, repeat. Average O(n log n), worst O(n²) (bad pivots), in-place versions use little space.
  • Heap sort: build a heap, pop the smallest repeatedly. O(n log n) always (more on heaps in Chapter 9).
  • Counting sort: when values are small integers in 0..k, count each value. O(n + k), no comparisons.

Python's built-in sorted and list.sort use Timsort: O(n log n) worst case, stable, and very fast on partly sorted data.

Problem 7.5.1 Implement all four and sort [38, 27, 43, 3, 9, 82, 10, 3].

Predict first: all four functions get the same list. Will they print the same result?

import heapq
def merge_sort(a):
    if len(a) <= 1: return a
    m = len(a) // 2
    l, r = merge_sort(a[:m]), merge_sort(a[m:])
    out = []; i = j = 0
    while i < len(l) and j < len(r):
        if l[i] <= r[j]: out.append(l[i]); i += 1
        else: out.append(r[j]); j += 1
    return out + l[i:] + r[j:]

def quick_sort(a):
    if len(a) <= 1: return a
    p = a[len(a) // 2]
    return (quick_sort([x for x in a if x < p]) + [x for x in a if x == p]
            + quick_sort([x for x in a if x > p]))

def heap_sort(a):
    h = list(a); heapq.heapify(h)
    return [heapq.heappop(h) for _ in range(len(h))]

def counting_sort(a, mx):
    c = [0] * (mx + 1)
    for x in a: c[x] += 1
    out = []
    for v, k in enumerate(c): out += [v] * k
    return out

arr = [38, 27, 43, 3, 9, 82, 10, 3]

7.6 Recurrences, the Master Theorem, Quickselect and Open Addressing

BASIC EXPLANATION
A recurrence is an equation that gives the running time of a recursive algorithm in terms of smaller inputs. The Master Theorem solves common forms, quickselect finds the k-th smallest item, and open addressing is a way a hash table handles collisions.
INTUITION
Loops are easy to count. Recursive algorithms are counted with a recurrence: an equation that says "the cost for size n is the cost of the sub-problems plus the extra work to split and combine". Merge sort splits in two halves and merges in n steps, so T(n) = 2T(n/2) + n. Solving that equation gives O(n log n). The master theorem is a shortcut for the common shape T(n) = a T(n/b) + nd.

Solving a recurrence by hand: the tree method

Problem 7.6.1 Solve T(n) = 2T(n/2) + n with T(1) = 1, for n = 8, by listing the work at each level of the call tree.

Level 01 call of size 8: work 8.
Level 12 calls of size 4: work 2 x 4 = 8.
Level 24 calls of size 2: work 4 x 2 = 8.
Level 38 calls of size 1 (leaves): work 8 x 1 = 8.
TotalEvery level costs n = 8, and there are log2 8 + 1 = 4 levels, so T(8) = 32 = n (log2 n + 1). In big-O, n log n.
def T(n):
    return 1 if n == 1 else 2 * T(n // 2) + n

for n in (8, 16, 1024):
    print(n, T(n), n * (n.bit_length()))
8 32 32
16 80 80
1024 11264 11264

The third column is n x (log2 n + 1), because bit_length of a power of two n equals log2 n + 1. The match shows the formula is exact for powers of two.

The master theorem

For T(n) = a T(n/b) + O(nd) compare the number of sub-problems a with bd, which measures how fast the work per call shrinks:

CaseConditionResultWhere the work is
Leaves dominatea > bdO(nlogb a)Bottom of the tree
Balanceda = bdO(nd log n)Same at every level
Root dominatesa < bdO(nd)The top call

Problem 7.6.2 Classify binary search, merge sort, and a divide-and-conquer that makes 3 calls on halves and does linear work.

Binary searchT(n) = T(n/2) + 1: a = 1, b = 2, d = 0. bd = 1 = a, balanced: O(n0 log n) = O(log n).
Merge sortT(n) = 2T(n/2) + n: a = 2, b = 2, d = 1. bd = 2 = a, balanced: O(n log n).

COMMON MISTAKE
Using the master theorem when the sub-problems are not equal size, such as T(n) = T(n-1) + n (insertion-sort style), or T(n) = T(n/3) + T(2n/3) + n. Wrong: forcing a, b, d onto them. Right: T(n) = T(n-1) + n unrolls to n + (n-1) + ... + 1 = n(n+1)/2, so O(n2); for uneven splits draw the tree and add the levels.

Quickselect: the k-th smallest in expected O(n)

To find the k-th smallest you do not need to sort everything. Pick a pivot, partition into smaller, equal and larger, and recurse into only the one part that contains position k. The expected sizes shrink as n, n/2, n/4 ..., a geometric series with total about 2n, so O(n) on average. The worst case, with consistently bad pivots, is O(n2), which is why the pivot is picked randomly.

Problem 7.6.3 Find the 3rd smallest of [7, 2, 9, 4, 1, 8] (k = 3, counting from 1) with quickselect, pivot 4 first.

Partition by 4smaller [2, 1], equal [4], larger [7, 9, 8].
Locate2 elements are smaller, 1 equal: positions 1 to 2 belong to smaller, position 3 is the pivot.
Answerk = 3 falls on the equal group: the 3rd smallest is 4. Sorted check: [1, 2, 4, 7, 8, 9], third is 4.
import random

def quickselect(a, k):          # k counts from 1
    pivot = random.choice(a)
    small = [x for x in a if x < pivot]
    equal = [x for x in a if x == pivot]
    large = [x for x in a if x > pivot]
    if k <= len(small):
        return quickselect(small, k)
    if k <= len(small) + len(equal):
        return pivot
    return quickselect(large, k - len(small) - len(equal))

random.seed(1)
data = [7, 2, 9, 4, 1, 8]
print([quickselect(data, k) for k in range(1, 7)])
print(sorted(data))
[1, 2, 4, 7, 8, 9]
[1, 2, 4, 7, 8, 9]

The three-way split (smaller, equal, larger) handles duplicates correctly; a two-way split with many equal values can loop or degrade to quadratic time.

Hash tables: open addressing

Python dictionaries use open addressing: all entries live in one array, and when the slot you want is taken you probe the next slot in a fixed sequence. Chaining (a list per slot) is the alternative. Open addressing is friendlier to the CPU cache because probes touch neighbouring memory, but it needs the table kept below about two thirds full, and deletions must leave a marker (a tombstone) or later lookups stop too early.

Problem 7.6.4 A table of size 7 uses hash(k) = k mod 7 and linear probing (try the next slot). Insert 10, 17, 3, 24 and show the table. Then look up 24.

Insert 1010 mod 7 = 3: slot 3 is free. Slot 3 = 10.
Insert 1717 mod 7 = 3, taken, try 4: free. Slot 4 = 17.
Insert 33 mod 7 = 3, taken; 4 taken; 5 free. Slot 5 = 3.
Insert 2424 mod 7 = 3, taken; 4, 5 taken; 6 free. Slot 6 = 24.
Lookup 24Start at slot 3, probe 3, 4, 5, 6: 4 probes. The keys all landed in one cluster, which is the weakness of linear probing.
size = 7
table = [None] * size
def insert(k):
    i = k % size
    probes = 1
    while table[i] is not None:
        i = (i + 1) % size
        probes += 1
    table[i] = k
    return probes

print([insert(k) for k in (10, 17, 3, 24)], table)
[1, 2, 3, 4] [None, None, None, 10, 17, 3, 24]

Expected probes for an unsuccessful search at load factor α (fraction of slots used) are about 1 / (1 - α)2 / 2 + 1/2 for linear probing. At α = 0.5 that is 2.5 probes, at α = 0.9 it is 50.5. That sharp rise is why dictionaries resize (Python grows when about two thirds full).

for a in (0.5, 0.67, 0.9):
    print(a, round(0.5 * (1 + 1 / (1 - a) ** 2), 1))
0.5 2.5
0.67 5.1
0.9 50.5
COMMON MISTAKE
Deleting from an open-addressing table by just emptying the slot. In the table above, delete 17 by setting slot 4 to empty and then look up 3: the probe starts at slot 3, sees 10, goes to slot 4, sees "empty", and wrongly stops, reporting 3 as missing. Right: mark the slot as a tombstone (deleted, but keep probing), and rebuild the table when tombstones pile up.

Going deeper: space complexity and cache effects

  • Space counts recursion. A recursive function that goes n levels deep uses O(n) stack even if it allocates nothing, and Python stops at about 1000 frames. Merge sort uses O(n) extra memory for merging; quicksort on average O(log n) for its stack.
  • Memory access pattern matters as much as operation count. Both loops below do the same 25 million additions, but one walks memory in order and the other jumps across rows. Arrays in NumPy are stored row by row, so reading a row is a sequential scan that the CPU cache and prefetcher handle well.
import numpy as np, time
a = np.ones((5000, 5000))
t = time.perf_counter(); row_total = sum(a[i, :].sum() for i in range(5000)); t_row = time.perf_counter() - t
t = time.perf_counter(); col_total = sum(a[:, j].sum() for j in range(5000)); t_col = time.perf_counter() - t
print(row_total == col_total, "column walk slower than row walk:", t_col > t_row)
True column walk slower than row walk: True

The sums are equal, yet walking columns is usually several times slower, because each element read pulls in a 64-byte cache line of which only 8 bytes are used. Big-O hides this constant factor, so when two solutions have the same complexity, prefer the one that touches memory in order.

Chapter recap

  • Big-O describes how work grows with input size; drop constants and smaller terms.
  • Always give time and space, and think worst case.
  • Hidden loops (in list, pop(0), string +=) turn O(n) code into O(n²).
  • Amortized O(1) means cheap on average over many operations, even if one operation is occasionally expensive.
  • Arrays give instant index access; inserting at the front is slow.
  • Strings are immutable; build them with join.
  • Hash maps and sets give average O(1) lookup and power four patterns: seen-set, counting, grouping, complement lookup.
  • Comparison sorts cannot beat n log n; counting sort can, for small integer ranges.
  • Use key= for custom ordering and cmp_to_key when pairs must be compared.
  • Trading memory for time is the most common optimization.
