Imagine it is 2 AM and a data pipeline has failed on a cloud server. There is no mouse, no Excel, no screen with buttons. There is only a black window and a blinking cursor. Almost every data and ML job runs on Linux servers like this, so the people who can work calmly in that window are the people who fix problems fast, and get hired. In this chapter you build one small project folder in /tmp and use it as our running example all the way through. You will read it, search it, count it, protect it, pack it and watch it run. By the end you can find any file, answer questions about a big log with one line of commands, set safe permissions, manage running programs and test a network from the terminal.

Every command here was run for real on a Mac (macOS, with zsh and bash). macOS and Linux share most commands, but a few flags differ. When a command is Linux-only, the text says so. All examples live under /tmp, so nothing important can be damaged. You should type them yourself: reading is not enough.

1.1 What Is the Shell, and How Do I Move Around?

BASIC EXPLANATION
The shell is a program that reads typed commands and runs them on the operating system. Basic navigation uses commands such as pwd, ls and cd to see and change the current directory.
INTUITION
Many programs offer both a mouse-driven screen and a typed command. Think of ordering food through a touch-screen kiosk versus telling the kitchen the exact order in one line. The typed command is faster, repeatable (you can save it and run it again), and works over a remote connection. The shell is the program that reads what you type and runs it. It is like a waiter: you give the order (a command), it brings the result (text).

How it works

  • Terminal: the window where you type.
  • Shell: the program inside that reads your line. Common shells: bash, zsh. Both work for everything in this book.
  • Command: a program name, then options (flags), then arguments. Example: ls -l data. Here ls is the program, -l is an option, data is the argument.
  • Path: the address of a file. /tmp/cs_lab is absolute (starts at the root /). data/access.csv is relative (starts from where you are now). . means "here", .. means "one folder up", ~ means your home folder.

The basic navigation and file commands:

CommandMeaningExample

Worked example: build a project

We create a folder and a small web-server log with 6 requests.

mkdir -p /tmp/cs_lab/ch1/project/data /tmp/cs_lab/ch1/project/logs
cd /tmp/cs_lab/ch1/project
printf 'ts,endpoint,status,ms\n1,/login,200,120\n2,/search,200,340\n3,/login,500,900\n4,/cart,200,210\n5,/search,404,15\n6,/login,200,130\n' > data/access.csv
ls -l data

Output (long format; owner and date columns trimmed):

-rw-r--r--  1 user  group  124 ... access.csv

The file is 124 bytes. The first 10 characters -rw-r--r-- are the permissions; we study them in section 1.3.

Problem 1.1.1 You are in /tmp/cs_lab/ch1/project. What is the absolute path after cd data and then cd ../logs?

Step 1cd data moves to /tmp/cs_lab/ch1/project/data.
Step 2cd ../logs goes one folder up (to project), then down into logs.
AnswerThe path is /tmp/cs_lab/ch1/project/logs.
CheckRun pwd after the two cd commands. It prints the same path. In plain words: .. is how you walk "back out of a room" before entering another room.

Problem 1.1.2 A symbolic link is a pointer to another path. We ran ln -s data/access.csv link.csv and then ls -l link.csv.

Step 1The link file stores only the text of the target path, not a copy of the data.
Step 2ls -l shows the pointer.
AnswerThe output was link.csv -> data/access.csv, so reading link.csv reads the original file.
Checkcat link.csv | head -n 1 prints ts,endpoint,status,ms, the first line of the original. A link is a signpost, not a second copy, so it takes almost no disk space.

Data engineers move files between folders, check disk space (df -h) before a big load, and look at log files on remote servers. In Docker and Kubernetes you often get only a shell, no GUI.

COMMON MISTAKE

Check yourself

  1. What does .. mean in a path? Answer: the parent (one level up) folder.
  2. Which command shows free disk space in readable units? Answer: df -h.
  3. What is the difference between mv a b and cp a b? Answer: mv moves or renames (one copy remains); cp leaves the original and makes a second copy.

1.2 Reading and Transforming Text: Pipes and Redirection

BASIC EXPLANATION
A pipe (|) sends the output of one command into the input of the next. Redirection (>, >>, <) sends output to a file or reads input from one. Together they let small text tools be combined.
INTUITION
Unix has many tiny tools that each do one job: count, sort, cut, filter. A pipe | connects the output of one tool to the input of the next, like a conveyor belt in a factory. Together they answer questions about huge logs in one line.

How it works

Every program has three standard streams:

  • stdin (0): input
  • stdout (1): normal output
  • stderr (2): error messages

Redirection operators:

SymbolMeaning
>write stdout to a file (overwrite)
>>append stdout to a file
<read stdin from a file
2>write stderr to a file
2>&1send stderr to the same place as stdout
`\`

Core text tools:

ToolJob
catprint a file
lessscroll a file (q quits)
head -n N / tail -n Nfirst / last N lines (tail -f follows a growing log)
wc -lcount lines
cut -d, -f2take column 2 of comma-separated text
sort / sort -rnsort / sort numbers high to low
uniq -ccount repeated adjacent lines (so sort first)
trreplace or delete characters
grepkeep lines that match a pattern
xargsturn input lines into arguments of a command
teewrite to a file and also pass output on

Worked example: which endpoint is hit most?

cd /tmp/cs_lab/ch1/project
head -n 3 data/access.csv
tail -n 2 data/access.csv
wc -l data/access.csv
tail -n +2 data/access.csv | cut -d, -f2 | sort | uniq -c | sort -rn

Real output:

ts,endpoint,status,ms
1,/login,200,120
2,/search,200,340
5,/search,404,15
6,/login,200,130
       7 data/access.csv
   3 /login
   2 /search
   1 /cart

Reading the last pipeline from left to right:

  • Step 1 tail -n +2 prints from line 2 on, so the header line is skipped.
  • Step 2 cut -d, -f2 keeps only the endpoint column.
  • Step 3 sort puts equal endpoints next to each other (needed for uniq).
  • Step 4 uniq -c counts each group.
  • Step 5 sort -rn orders by the count, largest first.
  • Answer /login was hit 3 times, /search 2 times, /cart once.

Note: wc -l counts 7 lines: 1 header plus 6 requests. Some systems print the count with different padding.

grep, the search tool

grep -c ',200,' data/access.csv          # count matching lines
grep -n '500' data/access.csv            # show line numbers
grep -v '^ts' data/access.csv | grep -i -E 'login|cart' | wc -l
4
4:3,/login,500,900
4
  • -c counts matches (4 requests had status 200).
  • -n prints the line number (line 4 holds the 500 error).
  • -v inverts (drop the header). -i ignores case. -E allows a|b (either word). The last line counted 4 rows that mention login or cart (3 login plus 1 cart).

The error message of ls nothere went into logs/err.txt (its text on this Mac was ls: nothere: No such file or directory). tee saved hi to t.txt and also passed it on, so tr printed HI.

Problem 1.2.1 The log has 6 requests. How would you count the requests that are slower than 200 ms using only a pipe?

Step 1The 4th column is the time in ms. awk can compare numbers (we meet awk fully in Chapter 2). Skip the header with NR>1.
Step 2Command: awk -F, 'NR>1 && $4>200' data/access.csv | wc -l.
Step 3Rows with ms above 200: 340, 900, 210. That is 3 rows.
AnswerThe pipeline prints 3.
CheckCount by eye: 340, 900 and 210 are above 200. Yes, three rows. This means 3 of 6 requests (50%) were slow, which any shop owner would flag at once.

Problem 1.2.2 What is wrong with uniq -c used directly on unsorted data?

Step 1uniq only merges adjacent equal lines.
Step 2Data a b a is not adjacent, so a would count as two groups of 1.
AnswerAlways run sort before uniq -c.
CheckThe wrong-version output above shows /login three separate times, each with count 1.

Finding files

find . -name '*.csv'
find . -type f -size -1k

find PATH -name PATTERN walks folders. -type f means files only. -size -1k means smaller than one 1 KB block. locate is a faster index-based search on Linux, but it needs an updated database.

Packing files

cd /tmp/cs_lab/ch1
tar -czf p.tgz project      # c=create z=gzip f=file
tar -tzf p.tgz | sort | head -4   # t=list
project/
project/data/
project/data/access.csv
project/link.csv

tar -xzf p.tgz extracts. zip and unzip do the same with the .zip format.

Connection to the real job

When a production system fails at 2 AM, the fastest answer is often a pipe on the log file. Analysts do the same on web-shop logs: count error codes, find the slowest pages. Data engineers also peek at a 20 GB CSV with head instead of opening it in Excel.

Applications

  • Log analysis and incident response
  • Quick data checks before loading into a database
  • Data cleaning in pipelines (tr, cut, sed)
  • Archiving and moving datasets
COMMON MISTAKE
Using > when you meant >>. > empties the file first. Also: sort | uniq is fine, but uniq | sort is not.

Check yourself

  1. What does cmd 2> err.txt do? Answer: it writes only the error stream (stderr) of cmd into err.txt.
  2. Which flag makes grep print the line number? Answer: -n.
  3. Why sort before uniq -c? Answer: uniq counts only adjacent duplicates.

1.3 Permissions, Users and Environment

BASIC EXPLANATION
Permissions control which users may read, write or execute each file. Users and groups identify who is acting, and environment variables are named settings that programs inherit from the shell.
INTUITION
A shared server has many users. Permissions are the locks on every door: who can read, who can change, who can run. This is the first form of "least privilege", which Chapter 6 develops.

How it works

ls -l shows ten characters, for example -rwxr-x---:

- rwx r-x ---
│  │   │   └── others (everyone else)
│  │   └────── group
│  └────────── owner (user)
└───────────── file type (- file, d directory, l link)

Each triple is read (4), write (2), execute (1). Add the numbers to make an octal digit: rwx = 7, r-x = 5, r-- = 4, --- = 0.

  • chmod 750 f = owner rwx, group r-x, others nothing.
  • chmod u+x f = add execute for the owner.
  • chown user:group f = change owner (usually needs sudo).
  • sudo cmd = run cmd as the administrator (root). Use it rarely and carefully.
  • id shows your user and groups; whoami shows your name.

Worked example

touch s.sh
chmod 644 s.sh; ls -l s.sh | cut -c1-10
chmod u+x s.sh; ls -l s.sh | cut -c1-10
chmod 750 s.sh; ls -l s.sh | cut -c1-10
-rw-r--r--
-rwxr--r--
-rwxr-x---

Problem 1.3.1 Convert -rw-r----- to octal.

Step 1Owner rw- = 4 + 2 + 0 = 6.
Step 2Group r-- = 4.
Step 3Others --- = 0.
AnswerThe octal mode is 640.
CheckReverse it: 6 = 4+2 = rw-, 4 = r--, 0 = ---, so rw-r-----. The owner can edit, the group can only read, everyone else sees nothing.

Problem 1.3.2 You write backup.sh but get "Permission denied" when you run ./backup.sh. Why, and how do you fix it?

Step 1A new file has no execute bit (644 by default on most systems).
Step 2Add it: chmod u+x backup.sh.
AnswerRun chmod u+x backup.sh, then ./backup.sh works. (You could also run bash backup.sh without changing permissions.)
Checkls -l backup.sh now starts with -rwx. The same change happened in our real run above, where -rw-r--r-- became -rwxr--r--.

Environment variables and shell startup files

An environment variable is a named value that every program you start can read. We tested that a child process sees an exported variable:

export MYVAR=perf
bash -c 'echo child sees $MYVAR'
child sees perf

Without export, the child would see nothing. PATH is the most famous variable: a list of folders the shell searches for commands. echo $PATH shows it.

Startup files (~/.bashrc for bash, ~/.zshrc for zsh) run when a new shell starts. Put your aliases and exports there, for example alias ll='ls -lah'. After editing, run source ~/.zshrc.

Real-world mapping

ItemExample valueWhere it appears in the job
600rw-------SSH private keys, files with passwords
644rw-r--r--Normal data and text files
750rwxr-x---Team scripts: owner runs, group runs, others blocked
export DB_URL=...variable for child programsDocker, Airflow, CI settings

Connection to the real job

Pipelines read database passwords and API keys from environment variables, not from code. Containers get their settings the same way. Wrong file permissions on a private key make ssh refuse to use it (it demands 600).

Applications

  • Secure key files (chmod 600 key.pem)
  • Configuring apps in Docker, Airflow, CI systems
  • Shared team servers and data lakes with group access
COMMON MISTAKE
chmod 777 "to make it work". It gives everybody write access. Find the real cause (wrong owner or group) and give only the needed permission.

Check yourself

  1. What is 755 in letters? Answer: rwxr-xr-x.
  2. Why must you export a variable? Answer: so child processes inherit it.
  3. Where do you put a permanent alias? Answer: in ~/.bashrc or ~/.zshrc.

1.4 Processes, Jobs and Services

BASIC EXPLANATION
A process is a running instance of a program. Jobs and services are ways of managing processes: viewing them (ps, top), stopping them (kill), running them in the background, and keeping them running as services.
INTUITION
A running program is a process. A server runs hundreds. You need to see them, stop the broken ones and keep important ones alive after you close the terminal, just as a restaurant manager sees the cooks on shift, sends a stuck cook home, and keeps the night kitchen running after the front door closes.

How it works

CommandMeaning
ps aux (or ps -ef)list all processes
top / htoplive view of CPU and memory per process (q quits)
kill PIDpolitely ask a process to stop (signal TERM, 15)
kill -9 PIDforce kill (cannot be ignored; no clean-up)
cmd &run in the background
jobs, fg, bglist jobs, bring to front, resume in the background
Ctrl+C, Ctrl+Zstop the job / pause the job
nohup cmd &keep running after you log out

systemd is the service manager on most Linux servers. Basics (Linux only, not run here):

systemctl status nginx        # is the service running?
sudo systemctl restart nginx  # restart it
journalctl -u nginx -n 50     # last 50 log lines of that service

Worked example

sleep 1 &          # start a background job
echo "started pid $!"   # $! holds the PID of the last background job
wait               # wait for it
echo done

The real run printed done after about one second (the PID changes each run, so it is not shown). We also checked what shell we were in using ps -o pid,comm -p $$, which printed bash. $$ is the PID of the current shell.

Problem 1.4.1 A training script train.py must survive when you close SSH. Write the command.

Step 1Use nohup so the hang-up signal is ignored.
Step 2Redirect output to a log, and add & for background.
Answernohup python3 train.py > train.log 2>&1 &. Watch it with tail -f train.log. (Many teams prefer tmux or a job scheduler for this.)
CheckClose the terminal, open a new one, and run ps aux | grep train.py. The process is still there. It matters because a 10-hour training run should not die when your Wi-Fi drops.

Problem 1.4.2 kill 4321 did nothing. What next?

Step 1The process may ignore TERM or be stuck.
Step 2Try kill -9 4321 (signal KILL).
AnswerUse kill -9 as the last step, because the process gets no chance to save data or clean up.
Checkps -p 4321 should print nothing after the kill. If it still shows, the process is stuck in the kernel (waiting on disk or network) and you must fix the cause.

Real-world mapping

ItemExample valueWhere it appears in the job
PID4321Every tool (top, kill, logs) names a process by its PID
kill -9 PIDforce stopA frozen Spark driver or runaway test
nohup ... &job survives logoutOvernight training runs
systemctl statusactive (running)Is the database/web service up?

Predict, run, explain. Predict: in sleep 1 & echo started; wait; echo done, which word prints first, started or done? Answer: started, because & sends sleep to the background and the shell goes on immediately. wait then pauses until sleep finishes, and only then done prints.

The picture

 you ──► shell ──► fork ──► new process (PID 4321)
                              ├─ runs in foreground (shell waits)
                              └─ runs with &  (shell returns at once)

Connection to the real job

You will find the process that eats 100% CPU, kill a stuck Spark job, or check why a service restarted. Chapter 5 digs deeper into what the numbers in top mean.

Applications

  • Operating long ML training runs
  • Managing databases, web servers, Airflow, Kafka as services
  • Incident handling (find, stop, restart)
COMMON MISTAKE
Reaching for kill -9 first. It skips clean shutdown and can corrupt files or leave locks behind.

Check yourself

  1. What does & at the end of a command do? Answer: runs it in the background.
  2. Difference between kill and kill -9? Answer: normal stop request vs forced kill.
  3. What is $!? Answer: the PID of the last background job.

1.5 Networking Tools and Logs from the Shell

BASIC EXPLANATION
Shell networking tools such as ping, curl, dig and ss test connections, DNS and ports. Log commands such as tail and grep read system and application logs to find problems.
INTUITION
When "the app is slow", the first question is: is it the network or the server? A few commands answer that in seconds. They are like checking if the road is blocked before blaming the car.

How it works

CommandUse
ping hostis the host reachable; round-trip time
curl URLfetch a URL; -I headers only; -s quiet; -o file save
wget URLdownload a file
dig nameDNS lookup (Chapter 4)
ss -tulpn (Linux) / netstatwhich ports are listening
ssh user@hostlog in to a remote machine
scp file user@host:/pathcopy a file over ssh
rsync -av src/ dest/copy only what changed, resumable

Logs and monitoring on Linux (not run here, the Mac does not have them):

  • /var/log/ holds system logs. journalctl -xe shows recent systemd errors.
  • vmstat 1 and iostat -x 1 show CPU, memory and disk every second (Chapter 5).
  • strace -p PID prints the system calls a process makes. Treat it as an awareness tool: it slows the program a lot, so use it carefully on production.

Worked example: a local-only network test

To avoid touching the internet, we start a tiny web server on the local machine and call it.

mkdir -p /tmp/cs_lab/ch1/www && echo "hello from local server" > /tmp/cs_lab/ch1/www/index.html
python3 -m http.server 8765 --directory /tmp/cs_lab/ch1/www --bind 127.0.0.1 &
sleep 1
curl -s http://127.0.0.1:8765/index.html
curl -s -o /dev/null -w "status=%{http_code} bytes=%{size_download}\n" http://127.0.0.1:8765/index.html
kill %1
hello from local server
status=200 bytes=24

-w prints a custom report. The file has 23 characters plus a newline, which is 24 bytes. Replace the URL with a real service and the same -w trick can print timing fields such as time_total.

Problem 1.5.1 Which curl flag shows only the response headers?

Step 1HEAD requests return headers without a body.
Step 2curl -I URL sends HEAD.
Answercurl -I URL; look for the status line and headers such as Content-Type.
CheckOn our local server, curl -I http://127.0.0.1:8765/index.html prints a first line like HTTP/1.1 200 OK (the version number can differ). Seeing 200 means the server answered correctly.

Problem 1.5.2 Copy the folder reports/ to a server twice. Why is rsync better than scp -r on the second run?

Step 1rsync compares files and sends only differences.
Step 2If 1 GB of 100 GB changed, rsync sends about 1 GB.
Answerrsync -av reports/ user@host:/data/reports/ saves time and bandwidth, and can resume.
Check1 GB sent instead of 100 GB is a 99% saving of transfer. A scp of the full folder would repeat all 100 GB.

When a website seems down, you need exactly these checks: Is the port open? Does DNS resolve? How long does the server take to answer from here? You can ask all of these from a bare terminal.

1.6 Power Tools: find, xargs, Process Substitution, jq, ssh and tmux

BASIC EXPLANATION
These are advanced shell tools. find searches for files, xargs turns input lines into command arguments, jq processes JSON, ssh opens a remote shell and tmux keeps terminal sessions running.
INTUITION
The shell's real strength is composition: find produces a list of files, xargs turns that list into command arguments, and a pipeline filters the result. Learn three moves and you can handle ten thousand files as easily as one: select (find, grep), transform (sed, awk, jq) and apply (xargs, a loop).

Every example below was run on a Mac with the default tools in a scratch folder, so the output is real. Output order from find is not guaranteed, so most examples pipe it through sort.

find and xargs

Problem 1.6.1 Make a small tree of log and data files, list every .log file, then count lines per file.

Selectfind . -name '*.log' lists matching paths. Quote the pattern so the shell does not expand it first.

mkdir -p app/logs app/data
printf 'a\nb\nc\n' > app/logs/web.log
printf 'x\ny\n' > app/logs/db.log
printf '1,2\n' > app/data/t.csv

       2 app/logs/db.log
       3 app/logs/web.log
       5 total

Problem 1.6.2 File names with spaces break the simple pipe. Show the failure and the fix with null separators.

mkdir d && cd d
echo hi > 'my report.txt'
echo hey > 'plain.txt'
echo "--- naive:"
find . -name '*.txt' | xargs wc -c 2>&1 | sed 's/^ *//'
echo "--- safe:"
find . -name '*.txt' -print0 | xargs -0 wc -c | sed 's/^ *//'
--- naive:
wc: ./my: open: No such file or directory
wc: report.txt: open: No such file or directory
4 ./plain.txt
4 total
--- safe:
3 ./my report.txt
4 ./plain.txt
7 total

The naive version splits my report.txt into two arguments, my and report.txt, and complains that neither exists. -print0 ends each name with a NUL byte and -0 reads it back, and a NUL cannot appear in a file name, so this is always safe.

Problem 1.6.3 Run one command per file, in parallel with xargs -n 1 -P, and use find -exec as the alternative.

mkdir t && cd t
for i in 1 2 3 4; do echo "file $i" > f$i.txt; done
echo "--- xargs -n 1 (one file per command):"

find . -name 'f*.txt' -exec cat {} + | sort

COMMON MISTAKE
Running rm through xargs without looking first. Wrong: find . -name '*.tmp' | xargs rm on a folder with names containing spaces or a leading dash. Right: run the same find with -print first and read the list, then add -print0 | xargs -0 rm (or -delete).

Process substitution and comparing outputs

<(command) makes a command's output look like a file. It lets you compare two live results without temporary files.

Problem 1.6.4 Which users appear in this week's list but not in last week's, and the reverse?

printf 'ana\nbo\ncy\ndee\n' > last.txt
printf 'bo\ncy\neli\nfay\n' > this.txt
echo "new this week:"
comm -13 <(sort last.txt) <(sort this.txt)
echo "gone since last week:"
comm -23 <(sort last.txt) <(sort this.txt)
echo "diff view:"
diff <(sort last.txt) <(sort this.txt)
new this week:
eli
fay
gone since last week:
ana
dee
diff view:
1d0
< ana
4c3,4
< dee
---
> eli
> fay

comm needs sorted input. Its flags say which columns to hide: -13 hides the "only in file 1" and "in both" columns, leaving "only in file 2".

jq: grep for JSON

APIs return JSON, and grep and awk are the wrong tools for nested data. jq (install with a package manager) selects, filters and reshapes.

Problem 1.6.5 From an API response, list the names of orders over 50, total all amounts, and mark each order big or small.

cat > orders.json <<'JSON'
{"orders":[{"id":1,"name":"book","amount":12.5},{"id":2,"name":"lamp","amount":64},{"id":3,"name":"desk","amount":180}]}
JSON
jq -r '.orders[] | select(.amount > 50) | .name' orders.json
jq '[.orders[].amount] | add' orders.json
jq -c '.orders | map({id, big: (.amount > 50)})' orders.json

desk
256.5

ssh config, tunnels and tmux

These need a remote machine or a tool that is not installed here, so they are shown, not run. Put long options in ~/.ssh/config once:

# ~/.ssh/config
Host train
    HostName gpu-box.example.com
    User asha
    IdentityFile ~/.ssh/id_ed25519
    ForwardAgent no
    ServerAliveInterval 30

ssh train                              # connect with all of the above
ssh -L 8888:localhost:8888 train       # forward remote Jupyter to http://localhost:8888
scp train:results/metrics.json .       # copy a file back
tmux new -s job                        # start a session; run the long job; detach with Ctrl-b then d
tmux attach -t job                     # come back later, even after your laptop slept

A -L tunnel carries traffic from a local port to a port on the remote machine through the encrypted connection, so you never open that port to the internet. Use tmux (or nohup) for any job longer than your connection: when ssh drops, a plain shell sends hangup to its children and kills the job.

KEY IDEA
Safe order of work for any bulk operation: list, inspect, count, then act. find ... | head, then | wc -l, then add the destructive step. The five extra seconds are the cheapest insurance in computing.

Problem 1.6.6 Find all .csv files under a folder and print the total number of lines in them.

Answer: find data -name '*.csv' -print0 | xargs -0 cat | wc -l. Piping everything through cat into one wc gives one total. xargs wc -l would print per-file counts plus a total, and several partial totals if the list is long enough that xargs splits it into batches.

Chapter recap

  • The shell runs commands. A command is a program, options and arguments.
  • Absolute paths start with /; relative paths start from where you are.
  • rm has no undo. Print the path with ls before deleting.
  • Pipes | connect small tools: cut | sort | uniq -c | sort -rn is the classic frequency count.
  • > overwrites, >> appends, 2> redirects errors.
  • Permissions are read 4, write 2, execute 1 for owner, group and others. 750 means rwxr-x---.
  • Environment variables must be exported to reach child processes.
  • kill is polite, kill -9 is forced. Use nohup or tmux for long jobs.
  • curl, dig, ssh, rsync are the daily network tools.
  • Linux tools like journalctl, vmstat, iostat, strace are covered again in Chapter 5.

Practice set

  1. (Easy) What does ls -lah show beyond ls? Answer: long format with permissions, owner, size in readable units, and hidden files.
  2. (Easy) Write the command to make /tmp/x/y/z in one go. Answer: mkdir -p /tmp/x/y/z.
  3. (Easy) What is the octal for rwxr-xr-x? Answer: 755.
  4. (Medium) What is the output of printf 'b\na\nb\n' | sort | uniq -c? Answer: 1 a then 2 b (with spaces before the counts).
  5. (Medium) What is the output of echo "Hello" | tr 'a-z' 'A-Z'? Answer: HELLO.
  6. (Find the bug) cat access.csv | sort | uniq -c | cut -d, -f2 was meant to count endpoints. Why is the result wrong? Answer: uniq -c runs on whole lines, not on the endpoint column. Cut the column first: cut -d, -f2 access.csv | sort | uniq -c.
  7. (Find the bug) echo data > file.txt was run twice, but the file has one line. Why? Answer: > overwrites each time. Use >> to append.
  8. (Scenario) Your disk is 98% full. Which two commands find the cause? Answer: df -h finds which disk is full; du -sh * | sort -h (inside the suspect folder) finds the largest subfolders. Repeat one level deeper.
  9. (Scenario) A script on a server gives "Permission denied". List two possible causes. Answer: missing execute bit (chmod u+x), or the folder or file belongs to another user and you lack the rights; also a mounted disk with noexec.
  10. (Interview) Find the 5 most frequent IP addresses in a log where the IP is the first space-separated field. Answer: cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head -5 (or awk '{print $1}').
  11. (Interview) What is the difference between a process and a job? Answer: a process is any running program with a PID managed by the OS; a job is a process (or pipeline) started from your shell that the shell tracks with jobs, fg, bg.
