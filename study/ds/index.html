A Note From Your Professor

If you have ever planned a project, spotted what was going wrong and explained it to a manager, you already have more than half of what this document teaches, in a new setting. Data science is not "run an algorithm". It is turning a fuzzy question ("customers are leaving") into a decision someone can act on ("send this offer to these people, this week"), and proving with honest numbers that the decision worked.

Most books teach models. This document teaches the parts around the model, where careers are made and projects fail: choosing the right question, building a training table that matches real life, hunting leakage, knowing how data fools you, running experiments, reasoning about cause and effect, forecasting with intervals, and writing the memo that makes a stakeholder say yes. The models themselves, such as logistic regression, trees and neural networks, live in their own document (study/ml/). Here we call them tools and focus on how to use them well.

Every chapter uses real code on synthetic datasets with fixed seeds, so you can reproduce each number. When the result is disappointing (for example a simple rule that nearly beats a model), we show it, because that is what real work looks like.

One rule, please: never move on until the current topic feels obvious. If a worked problem feels shaky, redo it by hand with fresh numbers. One hour a day with understanding beats five hours of skimming.

What Every Topic Contains

  1. INTUITION callout: the problem this concept solves, in everyday language, often with an analogy from everyday life (shops, queues, schools, hospitals).
  2. Formal definition / how it works: precise but plain, with every new word defined at first use.
  3. Worked problems with real numbers: every step shown, with a Check and a plain-language meaning (or runnable code with the exact output).
  4. The picture: an ASCII diagram, table or figure, explained completely.
  5. Connection to the real job: where it shows up in analytics, data science and ML work.
  6. Applications: domains that use it.
  7. COMMON MISTAKE callouts: what beginners get wrong and how to catch it.
  8. Check yourself: 3 short questions with answers.

Each chapter ends with a recap (with a small formula and pattern table), a practice set of 8 to 12 graded problems with answers, and a prompt pack of 5 prompts you can paste into any AI assistant.

Contents

  1. What a Data Scientist Actually Does - the job and role types, the project lifecycle (CRISP-DM), turning a vague ask into a precise problem, baselines, and success metrics at three levels.
  2. Getting Trustworthy Data - data sources, point-in-time correct training sets in SQL, quality checks, labels and ground truth (delay, noise, selection bias), privacy, DPDP and GDPR ideas.
  3. Exploratory Data Analysis for Modelling - profiling, missingness, target analysis, segments, time and drift, and leakage hunting, with a full worked example.
  4. Statistical Thinking: Ways Data Fools You - confounding, Simpson's paradox, selection bias, regression to the mean, base rates, Goodhart's law, multiple testing, and honest uncertainty.
  5. Feature Engineering I - numeric transformations, encoding (target encoding done safely), dates and cycles, text and geo features.
  6. Feature Engineering II - behavioural and aggregate features (RFM, rolling windows, lags, trends), feature selection and stability (PSI), leakage-safe pipelines.
  7. Experimentation - A/B testing done properly: hypotheses, sample size and power, CUPED, sample ratio mismatch, peeking, sequential tests, bandits.
  8. Causal Inference - potential outcomes, DAGs, propensity scores, difference-in-differences, synthetic control, regression discontinuity, instrumental variables, uplift modelling.
  9. Forecasting and Time Series for Decisions - baselines, exponential smoothing, ARIMA ideas, ML with lags, rolling-origin backtests, prediction intervals, forecast to inventory decision.
  10. Recommendation, Ranking and Search - two-stage systems, matrix factorisation, ranking metrics, cold start, offline versus online evaluation.
  11. Applied Domains - churn and CLV, credit-risk scorecards (WoE, IV, KS, Gini, PSI), fraud, marketing mix and pricing, demand and supply chain, healthcare, performance-data analytics.
  12. From Prediction to Decision - cost matrices, thresholds, optimisation, simulation, feedback loops.
  13. Communication, Ethics, Reproducibility and Production - stakeholder management, writing, ethics checklist, reproducible work, prototype to production.
  14. Capstone Projects and the Interview Bank - eight project briefs with acceptance criteria, mastery tests, and a data science interview question bank.

How To Study This Document

Follow this loop for every chapter:

  1. Build first. Read the motivating paragraph, then type the code of the first section yourself (do not paste) and run it. Before each run, write down your prediction of the output.
  2. Ask. When something is unclear, use the chapter's Prompt pack. The prompts are self-contained: copy one, paste it into any AI assistant, and answer its questions.
  3. Just-in-time theory. Read the formal part only when the code raises a question. The worked problems show every step; redo them with new numbers.
  4. Rebuild. Close the document and rebuild the main example from a blank notebook, on your own data if you can (any spreadsheet or export you already work with is a good source).
  5. Teach. Explain the chapter's main idea aloud in 5 minutes, as if to a colleague. If you get stuck, that is the topic to revisit.

Pace. About one chapter per week at one hour a day: three days for reading and running code, two days for the practice set, one day for the prompt pack and re-explaining, one day of rest or catching up. Chapters 1 to 6 are the foundation; do them in order. Chapters 7 to 12 can follow the role you are aiming for: product roles go to 7 and 8 first, supply chain and finance to 9 and 11, e-commerce to 10. Chapters 13 and 14 are for the last weeks before applying.

Using the prompt packs. Use "teach me" prompts before a chapter, "quiz me" prompts after, "review my work" prompts on your own mini-projects, and the "mock interview" prompt in the week before interviews. Always attempt before you ask for the answer.

Reproducibility. All code runs on Python 3 with numpy, pandas, scikit-learn and scipy, with fixed random seeds. The shop dataset used in Chapters 1 to 6 comes from the ds_common.py listing in Chapter 1. Output may differ slightly across library versions; where exact digits matter we say so.

Prerequisites

  • Python basics and pandas (the learner's Python study document).
  • SQL basics: SELECT, JOIN, GROUP BY, CTEs (the learner's SQL study document).
  • School-level statistics: mean, variance, normal distribution, probability (see the learner's Math PDF, statistics and probability pillars).
  • No machine-learning background is needed to start; models appear as tools, and the algorithms are explained in study/ml/.

Tools you need

All free.

  • Python 3 with numpy, pandas, scipy, scikit-learn, matplotlib (the examples in this document were run with exactly these).
  • Jupyter Notebook or JupyterLab, or VS Code with the Jupyter extension.
  • SQLite (included with Python) for the SQL examples.
  • Optional, named in chapters but not required to follow along: statsmodels, lightgbm, lifelines, prophet, pulp or OR-Tools, PyMC, pandera, great_expectations, networkx.
  • Git for version control.
