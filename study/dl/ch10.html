Much real data comes in order: daily orders in a shop, temperature readings every hour, the words of a sentence, the sound of a voice. The meaning of one item depends on what came before it. A normal network (Chapter 1) sees a fixed-size input and has no memory. Recurrent neural networks (RNNs) add a memory that is updated one item at a time. This chapter builds an RNN cell by hand with real numbers, trains one in NumPy with a verified gradient (backpropagation through time), shows exactly why plain RNNs forget, and then opens up the LSTM and GRU gates that fix this. We then meet seq2seq (translate one sequence into another), teacher forcing, beam search and attention, and finish with the reasons transformers took over. You will be able to explain each model on a whiteboard and compute its steps. We build on Chapter 2 (backpropagation and gradient checking), Chapter 4 (vanishing and exploding gradients, clipping) and Chapter 6 (1D convolutions as an alternative for sequences). Transformers themselves are the next chapter, and language-model usage is in study/genai/.

10.1 Sequences and the Recurrent Neural Network

INTUITION
You read a sentence one word at a time and keep a running understanding in your head. After "The bank was closed because the river...", your running understanding changes how you read "bank". An RNN does exactly this: it reads one item, updates a small memory vector, reads the next item with the updated memory, and so on. The same rule (the same weights) is used at every step, like a shop clerk who handles every order with the same procedure but keeps a notepad of what has happened so far.

Words you need

WordPlain meaning
SequenceAn ordered list of items: x₁, x₂, ..., x_T
Time stepOne position in the sequence (it does not have to be time: it can be a word position)
Hidden state hₜThe memory vector after reading item t
CellThe small function that turns (xₜ, hₜ₋₁) into hₜ
UnrollingDrawing the loop as a chain of copies, one per step
BPTTBackpropagation through time: ordinary backpropagation on the unrolled chain

The recurrent update

hₜ = tanh(Wx · xₜ + Wh · hₜ₋₁ + b)       h₀ = 0

Wx turns the new input into the hidden space, Wh turns the old memory into the hidden space, b is a bias, and tanh squashes values into −1 to 1 (Chapter 1). The same Wx, Wh, b are used at every step: that is weight sharing over time, just as a CNN shares a kernel over space (Chapter 6). The number of parameters does not depend on the sequence length.

How to read it: each blue box is the same cell. Inputs x₁, x₂, x₃ enter from below. The arrows going right carry the hidden state to the next step. Each step also produces hₜ upwards, which can be used for an output. For a sentence-level answer (positive or negative review) you use only the last h. For a tagging task you use every hₜ.

Problem 10.1.1 An RNN has 1 input and 2 hidden units. Wx = [0.5, −0.3]ᵀ, Wh = [[0.1, 0.4], [0.2, −0.1]], b = [0, 0.1]. Read the sequence 1.0, 2.0, −1.0.

Formulahₜ = tanh(Wx·xₜ + Wh·hₜ₋₁ + b), h₀ = [0, 0].
Step 1 (t = 1, x = 1.0)Wh·h₀ = [0, 0]. First unit: 0.5 × 1.0 + 0 + 0 = 0.5. Second unit: −0.3 × 1.0 + 0 + 0.1 = −0.2. Apply tanh: h₁ = [tanh(0.5), tanh(−0.2)] = [0.4621, −0.1974].
Step 2 (t = 2, x = 2.0)Wh·h₁: first 0.1 × 0.4621 + 0.4 × (−0.1974) = 0.04621 − 0.07896 = −0.03275; second 0.2 × 0.4621 − 0.1 × (−0.1974) = 0.09242 + 0.01974 = 0.11216. Add Wx·x: first 0.5 × 2.0 = 1.0, so a₁ = 1.0 − 0.03275 = 0.96725; second −0.3 × 2.0 + 0.11216 + 0.1 = −0.38784. Then h₂ = [tanh(0.96725), tanh(−0.38784)] = [0.7475, −0.3695].
Step 3 (t = 3, x = −1.0)a = [−0.573, 0.5864], so h₃ = [−0.5176, 0.5273].
AnswerThe memory after the whole sequence is h₃ = [−0.5176, 0.5273].
CheckThe code below prints the same a and h at each step. Also, all values stay between −1 and 1 because of tanh.
InterpretationThe last memory depends on all three inputs. The third input (−1.0) pushed the first unit negative even though the first two inputs pushed it up: the cell mixes the new input with what it remembered. The order matters: reading −1.0, 1.0, 2.0 would give a different h₃.

Before you run it, predict: will the sign of h₃[0] match the sign of the last input?

import numpy as np
# A tiny RNN: 1 input number, 2 hidden numbers.  h_t = tanh(Wx*x_t + Wh@h_{t-1} + b)
Wx = np.array([[0.5], [-0.3]])             # shape (2,1)
Wh = np.array([[0.1, 0.4], [0.2, -0.1]])   # shape (2,2)
b  = np.array([0.0, 0.1])
xs = [1.0, 2.0, -1.0]                      # a sequence of 3 inputs
h = np.zeros(2)
for t, x in enumerate(xs, 1):
    a = Wx[:, 0] * x + Wh @ h + b          # pre-activation
    h = np.tanh(a)
    print(f"t={t} x={x:5.1f}  a={a.round(4)}  h={h.round(4)}")
t=1 x=  1.0  a=[ 0.5 -0.2]  h=[ 0.4621 -0.1974]
t=2 x=  2.0  a=[ 0.9673 -0.3878]  h=[ 0.7475 -0.3695]
t=3 x= -1.0  a=[-0.573   0.5864]  h=[-0.5176  0.5273]

Line by line. h = np.zeros(2) is the empty memory. Inside the loop, Wx[:, 0] * x is the input's contribution, Wh @ h is the old memory's contribution, and np.tanh squashes. The same variables Wx, Wh, b are reused each step. (Answer to the prediction: yes here, the sign is negative like the last input, but with a longer, stronger earlier history it might not be.)

Turning a series into training samples

For forecasting you slide a window over the series: the last T values are the input, the next value is the label. Shapes matter: sequence layers in PyTorch expect (batch, time, features) when batch_first=True.

series = np.array([10, 12, 13, 15, 14, 16, 18, 17, 19, 21.])   # e.g. daily orders in a small shop
T = 4                                                          # look at 4 days, predict day 5
X = np.array([series[i:i+T] for i in range(len(series) - T)])  # shape (N, T)
y = series[T:]
print("X shape", X.shape, "y shape", y.shape)
print(X[0], "->", y[0]); print(X[1], "->", y[1]); print(X[-1], "->", y[-1])
print("model input shape (batch, time, features):", X[:, :, None].shape)

Ten values and a window of 4 give 10 − 4 = 6 samples. Each input has shape (4,); adding a feature axis makes (6, 4, 1): 6 samples, 4 time steps, 1 feature (orders per day). With more measurements per step (orders and price) the last number would be 2. Important: split train and test by time (train on the past, test on the future), never randomly, or the model peeks at the future.

Backpropagation through time and why RNNs forget

BPTT applies the chain rule (see the learner's Math PDF, the backpropagation pillar) along the unrolled chain. The gradient reaching step t − 1 from step t is multiplied by the factor diag(1 − hₜ²) · Wh. The gradient from the last step back to the first is a product of T such factors. A product of many numbers below 1 goes to zero (vanishing gradient); a product of many numbers above 1 blows up (exploding gradient). This is the same disease you met in Chapter 4, but here the "depth" is the sequence length, so it hits RNNs hard.

Problem 10.1.2 Measure how strongly the first memory h₀ still influences h_T for a 16-unit RNN whose Wh has all singular values equal to scale (a rotation times scale).

Formula∂h_T/∂h₀ = Π diag(1 − hₜ²) · Wh; we report its largest singular value (the matrix 2-norm).
Step 1If the derivative of tanh were exactly 1, the norm after T steps would be scaleᵀ: for 0.9 and 50 steps 0.9⁵⁰ = 0.0052.
Step 2tanh' is at most 1 and usually smaller, so the real value is even smaller. The code multiplies the true Jacobians.
AnswerFor scale = 0.9 the influence shrinks to 4.3e-03 after 50 steps and 2.2e-05 after 100. For scale = 1.5 it grows to 162 and 2964. Even at scale = 1.0 it falls to 0.26, because tanh squashes.
CheckThe 0.9⁵⁰ = 0.0052 estimate is close to the measured 4.3e-03.
InterpretationA plain RNN cannot learn that "the word 50 steps ago decides the answer", because the learning signal from step 50 is about 0.004 of its original size (or enormous). Exploding gradients are repaired with gradient clipping (below). Vanishing gradients are not: this is why LSTM and GRU were invented (Section 10.2).
# How much does the first input still influence the last hidden state?  Measure |d h_T / d h_0|
rng = np.random.default_rng(0)
def grad_norm(scale, T, n=16):
    Q, _ = np.linalg.qr(rng.normal(size=(n, n)))
    Wh = Q * scale                          # every singular value equals `scale`
    h = rng.normal(size=n) * 0.5; J = np.eye(n)
    for t in range(T):
        a = Wh @ h; h = np.tanh(a)
        J = np.diag(1 - h**2) @ Wh @ J      # chain rule: dh_t/dh_0 = diag(1-h^2) Wh dh_{t-1}/dh_0
    return np.linalg.norm(J, 2)
print("steps   scale 0.9      scale 1.0      scale 1.5")
for T in (1, 5, 10, 20, 50, 100):
    print(f"{T:5d}   " + "   ".join(f"{grad_norm(s, T):12.3e}" for s in (0.9, 1.0, 1.5)))

Train an RNN in NumPy, with a gradient check

We train a 6-unit RNN to read 8 random numbers and say whether their sum is positive. Code highlights: the forward loop, a backward loop that walks from the last step to the first (dh = Wh.T @ da hands the gradient to the previous step), a numerical gradient check as in Chapter 2, and gradient clipping: if the gradient norm exceeds 1, scale it down to 1.

Before you run it, predict: will the gradient check pass (error below 1e-6)? And will the accuracy reach 100%?

# Train a small RNN (hidden 6) to say whether the sum of 8 numbers is positive.  Backprop through time + gradient check.
rng = np.random.default_rng(0)
H, T = 6, 8
P = {"Wx": rng.normal(0, 0.5, (H, 1)), "Wh": rng.normal(0, 0.5, (H, H)) / np.sqrt(H), "b": np.zeros(H),
     "Wo": rng.normal(0, 0.5, (1, H)), "bo": np.zeros(1)}
sig = lambda a: 1 / (1 + np.exp(-a))
def forward(P, x):                                   # x: (T,)
    hs = [np.zeros(H)]
    for t in range(T): hs.append(np.tanh(P["Wx"][:, 0] * x[t] + P["Wh"] @ hs[-1] + P["b"]))
    return hs, sig(P["Wo"] @ hs[-1] + P["bo"])[0]
def loss_grad(P, x, y):
    hs, p = forward(P, x)
    loss = -(y * np.log(p) + (1 - y) * np.log(1 - p))
    g = {k: np.zeros_like(v) for k, v in P.items()}
    d = p - y                                        # dL/d(output score) for sigmoid + cross-entropy
    g["Wo"] += d * hs[-1][None, :]; g["bo"] += d
    dh = d * P["Wo"][0]
    for t in range(T, 0, -1):                        # go backwards through time
        da = dh * (1 - hs[t] ** 2)
        g["Wx"][:, 0] += da * x[t - 1]; g["Wh"] += np.outer(da, hs[t - 1]); g["b"] += da
        dh = P["Wh"].T @ da                          # pass the gradient to the previous step
    return loss, g
# gradient check on one example
x0 = rng.normal(size=T); y0 = float(x0.sum() > 0)
_, g = loss_grad(P, x0, y0); worst = 0
for k in P:
    for idx in np.ndindex(*P[k].shape):
        old = P[k][idx]; P[k][idx] = old + 1e-6; lp = loss_grad(P, x0, y0)[0]
        P[k][idx] = old - 1e-6; lm = loss_grad(P, x0, y0)[0]; P[k][idx] = old
        num = (lp - lm) / 2e-6; worst = max(worst, abs(num - g[k][idx]) / (abs(num) + abs(g[k][idx]) + 1e-12))
print("gradient check, worst relative error:", f"{worst:.2e}")
X = rng.normal(size=(600, T)); Y = (X.sum(1) > 0).astype(float)
Xte = rng.normal(size=(300, T)); Yte = (Xte.sum(1) > 0).astype(float)
acc = lambda X, Y: np.mean([(forward(P, x)[1] > 0.5) == y for x, y in zip(X, Y)])
print("before training: test accuracy", round(float(acc(Xte, Yte)), 3))
lr = 0.02
def clip(g, m=1.0):                              # gradient clipping by global norm
    n = np.sqrt(sum((v ** 2).sum() for v in g.values()))
    return g if n <= m else {k: v * m / n for k, v in g.items()}
for epoch in range(1, 31):
    tot = 0
    for i in rng.permutation(len(X)):
        l, g = loss_grad(P, X[i], Y[i]); g = clip(g); tot += l
        for k in P: P[k] -= lr * g[k]
    if epoch in (1, 5, 10, 20, 30): print(f"epoch {epoch:2d}  mean loss {tot/len(X):.4f}  test accuracy {acc(Xte, Yte):.3f}")

Reading the result. The worst relative error of 2.86e-08 between our analytic BPTT gradient and the numerical gradient means the backward code is correct for all parameters. Test accuracy rises from 0.737 to about 0.94. It does not reach 100% because sums close to zero are genuinely hard to call (a sum of 0.05 versus −0.05 needs very precise arithmetic from a squashing network). Also note that the accuracy before training was already 0.737 because the random hidden units still respond to large positive and negative inputs; "before training" accuracy is not zero knowledge. Gradient clipping (clip) kept the updates stable. In my first attempt, with a larger learning rate (0.1) and no clipping, accuracy bounced between 0.5 and 0.77 and never settled. For long sequences, clipping is standard.

COMMON MISTAKE
Randomly shuffling time-series samples before splitting into train and test. Neighbouring windows overlap, so a test window is almost identical to a training window and the score is falsely high. Split by time. Another mistake: feeding (batch, features, time) to a layer that expects (batch, time, features); the code runs and gives nonsense.

10.2 LSTM, GRU, Bidirectional and Stacked RNNs

INTUITION
The plain RNN rewrites its whole notepad at every step, so old notes get smudged away. An LSTM (long short-term memory) keeps a separate conveyor belt (the cell state c) running through time. At each step it makes three decisions: how much of the belt's old content to keep (forget gate), how much of the new information to put on the belt (input gate), and how much of the belt to show to the outside (output gate). Because the belt is mostly copied forward, the gradient can travel back along it without shrinking. It is the same idea as the residual connection in Chapter 6, applied across time.

The LSTM cell

For input xₜ, previous hidden hₜ₋₁ and previous cell cₜ₋₁:

f = σ(Wf·[x, h] + bf)        forget gate   (0 = erase, 1 = keep)
i = σ(Wi·[x, h] + bi)        input gate    (0 = ignore new info, 1 = write it)
o = σ(Wo·[x, h] + bo)        output gate   (how much memory to reveal)
g = tanh(Wg·[x, h] + bg)     candidate     (the new content, between -1 and 1)
c = f ⊙ cₜ₋₁ + i ⊙ g          new cell state (⊙ means element-wise multiply)
h = o ⊙ tanh(c)              new hidden state

σ is the sigmoid (output between 0 and 1: it acts like a dimmer switch). [x, h] means the two vectors joined into one.

Problem 10.2.1 One LSTM unit with one input. Weights (on x, on h, bias): forget (0.6, 0.4, 0.5), input (0.3, 0.2, 0.0), output (0.5, 0.1, 0.0), candidate (0.7, 0.1, −0.2). Take x = 1.0, hₜ₋₁ = 0.5, cₜ₋₁ = 0.8. Compute c and h.

W = {"f": (0.6, 0.4, 0.5), "i": (0.3, 0.2, 0.0), "o": (0.5, 0.1, 0.0), "g": (0.7, 0.1, -0.2)}

Why this fixes the vanishing gradient. Look at the cell equation: c = f ⊙ cₜ₋₁ + i ⊙ g. The derivative of cₜ with respect to cₜ₋₁ along this path is just f (the forget gate), not a weight matrix times a squashing derivative. (The gates also depend on hₜ₋₁, which adds smaller side paths; the cell path is the dominant one.) So the gradient along the cell path over T steps is the product of the forget gates. If the network learns to set f close to 1 for information it wants to remember, that product stays large.

The GRU: a lighter alternative

The gated recurrent unit (GRU) merges the cell and hidden state into one and uses two gates:

z = σ(Wz·[x, h] + bz)          update gate: how much old memory to keep
r = σ(Wr·[x, h] + br)          reset gate: how much old memory to use when forming the candidate
n = tanh(Wn·[x, r ⊙ h] + bn)   candidate
h = (1 − z) ⊙ n + z ⊙ hₜ₋₁      blend

Problem 10.2.3 One GRU unit with weights (on x, on h, bias): update (0.4, 0.3, 0), reset (0.5, 0.2, 0.1), candidate (0.8, 0.6, 0). Take x = 1.0, hₜ₋₁ = 0.5.

Counting parameters, stacking and reading both ways

A recurrent layer with d inputs and h hidden units has gates × (h·(d + h) + h) parameters: 1 gate for the plain RNN, 3 for the GRU, 4 for the LSTM. (PyTorch stores two bias vectors per gate, so its counts are h larger per gate; check with sum(p.numel() for p in model.parameters()), not run here.) For d = 10, h = 20 the code printed 620 (RNN), 1,860 (GRU) and 2,480 (LSTM). So a GRU is 25% smaller than an LSTM and often performs about the same.

  • Stacked (multi-layer): the hidden states of layer 1 become the inputs of layer 2. Layer 2 then has d = h, so a 2-layer LSTM with d = 10, h = 20 has 2,480 + 4·(20·40 + 20) = 2,480 + 3,280 = 5,760 parameters (printed above). Depth lets the model build more abstract features, but training is slower and needs care (dropout between layers).
  • Bidirectional: run one RNN left to right and another right to left, and join their states at each position. Each position then knows both past and future context. The parameters double (4,960 for our LSTM). It suits tasks where the whole sequence is available (tagging, classification), but not forecasting or generation, where the future does not exist yet.

  3. When is a bidirectional RNN not allowed? Answer: when predicting the future or generating step by step.

10.3 Seq2Seq: Encoder-Decoder, Teacher Forcing and Beam Search

INTUITION
A human interpreter listens to a whole sentence first, forms an understanding, and then speaks the translation word by word, each word depending on what has already been said. A seq2seq model has the same two parts: the encoder reads the input sequence and compresses it into a summary vector; the decoder starts from that summary and writes the output sequence one item at a time. Input and output can have different lengths (a 7-word English sentence may become 6 words in Hindi).

How it works

Encoder:  x1 -> [RNN] -> h1 -> [RNN] -> h2 -> [RNN] -> h3 = summary vector s
Decoder:  s, <start> -> [RNN] -> y1 ; y1 -> [RNN] -> y2 ; y2 -> [RNN] -> y3 ; ... until <end>

At each decoder step a softmax over the vocabulary gives the probability of every possible next item, and the model picks one. Seq2seq was used for translation, summarisation, speech recognition and chatbots before transformers. Two practical questions arise: how to train it, and how to pick the output sequence.

Teacher forcing

During training the decoder input at step t could be (a) the model's own previous guess or (b) the true previous item. Option (a) means one early mistake derails the rest, so learning is slow and unstable. Teacher forcing uses (b): feed the true previous item. It is like a teacher correcting every word of a student's essay as the student writes, instead of letting errors pile up.

Target:                                      I      like   tea   <end>
Decoder input (training, teacher forcing):   <start> I      like  tea
Decoder input (inference):                   <start> + the model's own previous predictions

The cost is exposure bias: at test time the model sees its own, sometimes wrong, previous words, which it never saw in training. Remedies include scheduled sampling (sometimes feed the model's own guess during training).

Greedy decoding versus beam search

Greedy decoding picks the most probable item at each step. It is fast but short-sighted: a locally best first word can lead to a poor sentence. Beam search keeps the best k partial sequences (the beam width) at each step, extends each, and keeps the best k again. With k = 1 it is greedy.

Problem 10.3.1 A toy decoder gives P(A) = 0.6, P(B) = 0.4 for the first token. After A, the next token probabilities are C 0.34, D 0.33, E 0.33. After B: F 0.9, G 0.1. Find the best 2-token sequence with greedy and with beam width 2.

Step 3 (beam 2, step 2)Extend both: AC 0.204, AD 0.198, AE 0.198, BF 0.4 × 0.9 = 0.36, BG 0.04. Best two: BF (0.36) and AC (0.204).
AnswerGreedy returns AC with probability 0.204; beam search with width 2 finds BF with probability 0.36.
CheckThe code prints both results. The beam answer has the higher probability, so it is truly better under the model.
InterpretationGreedy committed to A because it looked best at step 1, but A led only to uncertain continuations. Beam search kept B alive long enough to discover its confident continuation. Larger beams give better sequences up to a point but cost more time; beams can also produce dull, repetitive text, which is why modern text generation often uses sampling (temperature, top-p) instead; see study/genai/. In practice probabilities are added as logs, and long sequences are length-normalised so that short ones are not unfairly favoured.
# Next-token probabilities P(next | previous) for a toy decoder. "<s>" starts, every path ends after 2 tokens.
P = {"<s>": {"A": 0.6, "B": 0.4},
     "A": {"C": 0.34, "D": 0.33, "E": 0.33},
     "B": {"F": 0.9, "G": 0.1}}
def greedy():
    seq, p, tok = [], 1.0, "<s>"
    for _ in range(2):
        tok, q = max(P[tok].items(), key=lambda kv: kv[1]); seq.append(tok); p *= q
    return seq, p
def beam(width):
    beams = [([], 1.0, "<s>")]
    for step in range(2):
        cand = [(s + [t], p * q, t) for s, p, last in beams for t, q in P[last].items()]
        beams = sorted(cand, key=lambda b: -b[1])[:width]
        print(f"  width {width}, step {step+1} keeps:", [("".join(s), round(p, 3)) for s, p, _ in beams])
    return beams[0][0], beams[0][1]
print("greedy:", greedy())
print("beam 1:", beam(1)); print("beam 2:", beam(2))

The bottleneck problem

The encoder squeezes the whole input into one summary vector s. For a short sentence this works; for a 60-word sentence a single vector of 256 numbers must hold everything, and early words fade (the vanishing-gradient and memory problem again). Translation quality of plain seq2seq fell as sentences grew longer. The fix is attention.

10.4 Attention, and Why Transformers Won

INTUITION
Instead of memorising a whole page before answering, you keep the page open and look back at the relevant lines when you need them. Attention lets the decoder do this: at each output step it scores every input position by how relevant it is, turns the scores into weights that sum to 1, and takes a weighted average of the input states. The summary is rebuilt freshly for each output word, so no single vector is a bottleneck.

How it works

Given encoder states h₁, ..., h_T (one per input item) and the decoder's current state q (the query):

  1. Score each position: scoreⱼ = q · hⱼ (a dot product: large when the two vectors point the same way). Bahdanau-style attention uses a small neural network for the score instead; the dot form is Luong-style.
  2. Normalise with softmax: weightⱼ = exp(scoreⱼ) / Σ exp(score). Weights are positive and add to 1.
  3. Context vector: context = Σ weightⱼ · hⱼ.
  4. The decoder uses context along with its own state to predict the next item.

The weights can be drawn as a grid (output word by input word), which also lets you see what the model looked at: a useful bit of interpretability.

Problem 10.4.1 Three source words have encoder states h₁ = [1, 0], h₂ = [0, 1], h₃ = [1, 1]. The decoder query is q = [2, 0]. Compute the attention weights and the context vector.

Step 1 (scores)q·h₁ = 2×1 + 0×0 = 2; q·h₂ = 0; q·h₃ = 2×1 + 0×1 = 2.
Step 2 (softmax)exp(2) = 7.389, exp(0) = 1, exp(2) = 7.389. Sum = 15.778. Weights = [0.4683, 0.0634, 0.4683].
Step 3 (context)0.4683 × [1,0] + 0.0634 × [0,1] + 0.4683 × [1,1] = [0.4683 + 0.4683, 0.0634 + 0.4683] = [0.9366, 0.5317].
AnswerWeights [0.468, 0.063, 0.468]; context [0.937, 0.532].
CheckThe weights add up to 0.4683 + 0.0634 + 0.4683 = 1.0. The context lies inside the region spanned by the three states, as any weighted average must.
InterpretationThe query points along the first axis, so the two states with a first component of 1 (words 1 and 3) get almost all of the attention, and word 2 gets 6%. The model has chosen which words to read.
Scaled versionDividing the scores by √d (here √2 = 1.414) before the softmax gives weights [0.446, 0.108, 0.446], flatter. Large vectors produce large dot products and a spiky softmax, so scaling keeps the weights reasonable. This scaled dot-product attention is exactly the form used in transformers.
enc = np.array([[1., 0.], [0., 1.], [1., 1.]])        # encoder states for 3 source words (2 numbers each)
q = np.array([2., 0.])                                # decoder state asking "what should I look at now?"
scores = enc @ q
def softmax(v): e = np.exp(v - v.max()); return e / e.sum()
w = softmax(scores); context = w @ enc
print("scores", scores, "-> weights", w.round(4), "sum", w.sum().round(4))
print("context vector", context.round(4))
ws = softmax(scores / np.sqrt(2))                     # scaled by sqrt(d), d = 2
print("scaled weights", ws.round(4), "context", (ws @ enc).round(4))

Attention first improved translation of long sentences a lot (2014 to 2015). Soon after, the paper "Attention Is All You Need" (2017) asked: if attention does the heavy work, why keep the recurrence at all? Chapter 11 builds that answer: self-attention, where every position attends to every other position in the same sequence.

Problem 10.4.2 For a sequence of T = 1,000 items, compare the number of unavoidable sequential steps and the size of the pairwise score table.

Step 1An RNN needs T = 1,000 sequential steps; each depends on the previous one, so even 1,000 GPUs could not shorten the chain.
Step 2Self-attention computes all pairs at once: T × T = 1,000,000 scores (one matrix multiply), a depth of 1 step.
Step 3For T = 10,000 the table is 10⁸ scores per head per layer: the quadratic cost, which is why long context needs tricks (efficient attention such as FlashAttention is covered in Chapter 11).
AnswerRNN: 1,000 sequential steps, tiny memory. Attention: 1 step of depth but 1,000,000 scores.
Check1,000² = 1,000,000, and 10,000² = 100,000,000.
InterpretationTransformers trade memory (quadratic) for speed of training (parallel) and for a direct path between any two positions. Parallel training meant that models could be trained on far more data in the same hardware time, and more data plus scale gave the leap in quality. That, not a single clever trick, is the reason transformers won. Recurrent ideas are not dead: state-space models such as Mamba (awareness only) bring back a fixed-size memory with cheap, long-range sequence processing.

Where recurrent models are still reasonable

  • Small devices with a tight memory budget (a small GRU for keyword spotting).
  • Streaming data that must be processed one item at a time with a constant memory footprint.
  • Small datasets of simple time series, where an LSTM or even a 1D CNN or gradient-boosted model on lag features is quick and good enough.
  • Understanding older code bases and papers (many production speech and forecasting systems still contain them).

Chapter recap

  • A sequence model reads items in order and keeps a hidden state h as memory; the same weights are used at every step, so the parameter count does not depend on length.
  • The RNN update is h = tanh(Wx·x + Wh·h + b); we computed three steps by hand and in NumPy, and trained an RNN with a gradient check error of 2.86e-08.
  • BPTT multiplies a factor per step, so gradients vanish (scale 0.9: 4.3e-03 after 50 steps) or explode (scale 1.5: 162). Clipping fixes explosion only.
  • The LSTM adds a cell state with forget, input and output gates; its memory path is multiplied only by forget gates, so it can remember for a long time if f stays near 1.
  • The GRU has two gates and fewer parameters (1,860 versus 2,480 in our example) and often performs similarly.
  • Stacked RNNs add depth; bidirectional RNNs read both ways and cannot be used where the future is unavailable.
  • Seq2seq uses an encoder and a decoder; train with teacher forcing; decode with beam search (width 2 found 0.36 where greedy found 0.204).
  • Attention rebuilds a context vector per output step as a weighted average of encoder states (weights from a softmax of scaled dot products), removing the single-vector bottleneck.
  • Transformers won because they train in parallel and connect any two positions in one step, at the cost of T² memory.

1. (easy) One RNN unit, Wx = 1, Wh = 0.5, b = 0, h₀ = 0, inputs 1, 1. Find h₂. Answer: h₁ = tanh(1) = 0.7616; h₂ = tanh(1 + 0.5 × 0.7616) = tanh(1.3808) = 0.8811.

3. (easy) Softmax of the scores [0, 0, 0]. Answer: each weight is 1/3: equal attention.

4. (medium) An LSTM forget gate stays at 0.9 for 20 steps. Fraction of the cell-path gradient that survives? Answer: 0.9²⁰ = 0.1216, about 12%.

5. (medium) LSTM unit with f = 0.5, i = 0.5, g = 1.0, c₀ = 2.0. New c? Answer: 0.5 × 2.0 + 0.5 × 1.0 = 1.5.

6. (medium) What is the output shape of X[:, :, None] when X has shape (100, 7)? Answer: (100, 7, 1): 100 samples, 7 time steps, 1 feature.

7. (medium) Find the bug: a bidirectional LSTM predicts tomorrow's sales and gets 98% R² on the test set but fails in production. Answer: the backward direction reads the future values inside the window (or the split is random and leaks neighbouring windows), so the model effectively sees the answer. Use a unidirectional model and a time-ordered split.

8. (medium) Attention: scores [1, 1], states [2, 0] and [0, 4]. Context vector? Answer: weights [0.5, 0.5]; context = 0.5 × [2,0] + 0.5 × [0,4] = [1, 2].

9. (hard) A 2-layer bidirectional LSTM with d = 10, h = 20 (formula in this chapter). Parameters? (Layer 2 input is 2h = 40 because it reads both directions.) Answer: layer 1: 2 × 2,480 = 4,960. Layer 2: each direction 4 × (20 × (40 + 20) + 20) = 4 × 1,220 = 4,880, two directions 9,760. Total 14,720.

10. (hard) Beam search with width 2: step 1 has A 0.5, B 0.3, C 0.2. After A: X 0.5, Y 0.5. After B: X 0.9, Y 0.1. Best two sequences after step 2? Answer: with width 2, C is cut at step 1. Candidates: AX 0.25, AY 0.25, BX 0.27, BY 0.03. Best two: BX (0.27) and AX or AY (tie at 0.25).

11. (interview) "Why do LSTMs handle long-range dependencies better than plain RNNs?" Answer: the cell state is updated additively, c = f·c₀ + i·g, so the gradient along that path is multiplied only by the forget gate, which can stay near 1, instead of by a weight matrix and a squashing derivative at every step. The gates also learn what to keep and what to drop.

12. (interview) "Why did transformers replace RNNs for language models?" Answer: self-attention processes all positions in parallel, which makes training on huge datasets fast on GPUs, and it connects any two positions in a single step so long-range dependencies are easier to learn. The cost is T² memory for attention scores, which is addressed by efficient attention implementations and long-context tricks. RNNs remain useful where memory and streaming constraints dominate.
