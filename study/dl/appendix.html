Chapters 1 and 2: Neurons, Forward and Backward Pass

IdeaFormula or pattern
Neuronz = w·x + b, h = f(z)
Dense layer parametersinputs × outputs + outputs
Stable softmaxe^(z−max) / Σ e^(z−max)
Sigmoid and its slopeσ(z) = 1/(1+e^(−z)), σ′ = σ(1−σ) (at most 0.25)
Binary cross-entropy−[y·ln p + (1−y)·ln(1−p)]
Output error (sigmoid or softmax with cross-entropy)p − y
Weight gradientdW = error ⊗ input (batches: inputᵀ @ error)
Error passed back(dz @ Wᵀ) × f′(z_prev)
Gradient stepw ← w − lr × grad
Gradient check(L(w+ε) − L(w−ε)) / 2ε, ε ≈ 1e-5
No-knowledge loss for K classesln K (2 classes: 0.6931)

Chapters 3 and 4: Training and Debugging

IdeaFormula or pattern
Focal loss(1−pₜ)^γ · CE
Adam stepm̂ = m/(1−β₁ᵗ), v̂ = v/(1−β₂ᵗ), w −= lr·m̂/(√v̂ + ε)
Cosine decaylr(t) = ½·peak·(1 + cos(π·progress)), after warmup
Weight decay (L2)w ← w − lr·(g + λw); use AdamW for transformers
InitialisationHe: std √(2/fan_in) for ReLU; Xavier: √(1/fan_in) for tanh
NormalisationBatchNorm over the batch; LayerNorm and RMSNorm over features; GroupNorm over channel groups

Debug orderfirst loss ≈ ln K; overfit 16 examples to loss ≈ 0; then scale up
Healthy logloss, grad_norm, lr each step; validation each epoch
Failure signsvanishing: tiny early-layer gradients; exploding: nan or jumps; dead ReLU: exactly zero gradient

Chapter 10: Sequence Models

IdeaFormula or pattern
RNN cellhₜ = tanh(Wx·xₜ + Wh·hₜ₋₁ + b); same weights at every step, so parameters do not depend on length
Backprop through timeone factor per step: vanishes (scale 0.9 gives 4.3e-03 after 50 steps) or explodes (scale 1.5 gives 162); clipping fixes explosion only
LSTMc = f⊙c₀ + i⊙g, h = o⊙tanh(c); memory path ∂c_T/∂c₀ = Π fₜ
GRUh = (1−z)⊙n + z⊙h₀; two gates, 1,860 versus 2,480 parameters in the chapter example
Parameter countgates × (h·(d+h) + h) with gates: RNN 1, GRU 3, LSTM 4
Stacked and bidirectionaldepth adds capacity; bidirectional cannot be used where the future is unavailable
Seq2seqencoder reads into a state, decoder writes step by step; train with teacher forcing
Decodingbeam search (width 2 found 0.36 where greedy found 0.204)
Attentionsoftmax(q·hⱼ/√d) then Σ wⱼ hⱼ: a fresh context vector per output step, removing the single-vector bottleneck
Why transformers wonparallel training and one-step links between any two positions, at T² memory
Tool (not run here)torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)

Chapter 11: Transformers

IdeaFormula or pattern
Attentionsoftmax(Q·Kᵀ/√d_k)·V; softmax over keys (rows sum to 1)
Causal maskscores[j > i] = −∞
Head size, attention parametersd_h = d/H; 4d² for Wq, Wk, Wv, Wo
Shapesinput (B,T,d); heads (B,H,T,d_h); scores (B,H,T,T); output (B,T,d)
Layer norm(x − μ)/√(σ² + ε)·γ + β
FFNd → 4d → d with GELU
Block (pre-norm)x = x + Attn(LN(x)), then x = x + FFN(LN(x))
Sinusoidal positionsin/cos(pos / 10000^(2i/d))

Starting loss of a language modelabout ln(vocab)

An Honest Closing Note

If you worked through this document with the code open, you can now do things that many people only talk about. You can push real numbers through a small network forward and backward and check the gradients. You can train a model, read its loss curve, and follow a checklist when it fails. You understand convolutions, residual blocks, transfer learning and the main vision tasks (classification, detection, segmentation, OCR). You can write self-attention from scratch, explain each tensor shape, and count the memory a transformer needs. You can explain how CLIP, diffusion models, VAEs and GANs work, with small numbers to back it up. And you can reason about quantization, pruning, distillation, batching and multi-GPU training with arithmetic, not guesses.

What this document does not cover, honestly:

  • Large-scale practice. Our NumPy models are tiny and our PyTorch code was not run here. You have not yet trained a real model on a GPU for hours, and that experience teaches a lot (data loading speed, crashes, cost). Do it with the free GPU notebooks.
  • Language models in depth. Prompting, retrieval, agents, evaluation and fine-tuning of language models are in the study/genai/ document.
  • Research-level topics. Graph neural networks, state space models, reinforcement learning, video and 3D vision, speech, and the newest model families are only named or skipped. A short list of useful extras (profiling, hyperparameter search tools, experiment tracking, calibration, explainability, adversarial robustness, data hygiene, legal rules for biometric data) is in _missing_topics.md.
  • Production engineering. Monitoring, data pipelines, model registries and security are mentioned, not taught.
  • Depth of proof. We checked ideas with numbers and code, not with full mathematical proofs; your Math PDF holds the theory.

What to practise next, in this order:

  1. Rebuild one chapter's key example from a blank file, without looking (the NumPy MLP, then the attention layer).
  2. Pick one capstone from Chapter 14.5 and finish it with numbers, a baseline and a "What failed and why" section.
  3. Reproduce a small result from a paper and write down where your number differs from theirs.
  4. Learn to profile a training run (data loader time, GPU use, memory) and write down what you find.
  5. Read the study/genai/ document and connect it to what you built here: you will notice the transformer is the same engine.

Be patient with yourself. A topic is learned when you can explain it simply and make it work, not when you have read it. One clear project, honestly measured, is worth more than ten half-finished ones.
