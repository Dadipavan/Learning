Before deep learning, computers "saw" with hand-made rules: blur the noise, find the edges, cut out the object with a threshold, clean the mask, count the blobs. These tools are still everywhere. They prepare images for neural networks, they run on cheap cameras where no GPU exists, and they often solve a factory or document problem in 20 lines with no training data at all. This chapter builds each tool from a tiny array you can compute by hand, then runs it in NumPy on small synthetic images and shows the real output. By the end you will be able to read an OpenCV pipeline, explain what each call does, and pick between a classical method and a CNN. Chapter 6 gave you convolution; here we use it as a toolbox. Chapter 7's augmentations (flip, crop, brightness) are the same pixel operations you will see below.

import numpy as np
def show(a, chars=" .:-=+*#%@"):
    """print a 2D array as ASCII art (each pixel is 2 characters wide)"""
    a = np.asarray(a, float); lo, hi = a.min(), a.max()
    q = ((a - lo) / (hi - lo + 1e-9) * (len(chars) - 1)).round().astype(int)
    print("\n".join("".join(chars[v] * 2 for v in row) for row in q))

def conv2d(x, k):
    """same-size 2D filtering (cross-correlation), edge pixels repeated"""
    kh, kw = k.shape; ph, pw = kh // 2, kw // 2
    xp = np.pad(x, ((ph, ph), (pw, pw)), mode='edge')
    out = np.zeros(x.shape, float)
    for i in range(x.shape[0]):
        for j in range(x.shape[1]):
            out[i, j] = (xp[i:i+kh, j:j+kw] * k).sum()
    return out

8.1 Pixels, Color Spaces, Resizing and Histogram Equalization

INTUITION
A digital photo is a spreadsheet of numbers. A grey image is one sheet (rows by columns) with values 0 (black) to 255 (white). A colour image is three sheets stacked: red, green, blue. Everything in this chapter is arithmetic on those sheets, like computing the average of a column of exam marks.

Words you need

WordPlain meaning
PixelOne number (grey) or three numbers (colour) at one position
ChannelOne sheet of the stack; RGB has 3 channels
Shape(height, width) for grey, (height, width, 3) for colour in NumPy and OpenCV (PyTorch uses (3, height, width))
Colour spaceA way to write a colour as numbers: RGB, HSV (hue, saturation, value), Lab (lightness plus two colour axes)
InterpolationHow to invent pixel values when resizing
HistogramCount of how many pixels have each grey level

Why several colour spaces? RGB mixes brightness and colour together, so "find the red apple under a shadow" is awkward. HSV separates them: Hue is the colour angle (0° red, 120° green, 240° blue), Saturation is how vivid (0 grey to 1 pure), Value is brightness. A colour rule on hue survives lighting changes better. Lab is designed so that distance between two Lab numbers matches how different the colours look to a human, so it is used for colour matching. OpenCV note: it loads images in BGR order, not RGB. Mixing the two up gives blue faces and is one of the most common bugs.

Problem 8.1.1 Convert the RGB pixel (200, 100, 50) to grey using the standard luma weights 0.299, 0.587, 0.114, and to HSV.

Formulagrey = 0.299·R + 0.587·G + 0.114·B. HSV: V = max, S = (max − min)/max, H = 60° × ((G − B)/(max − min)) when red is the max.
Compute grey0.299 × 200 = 59.8, 0.587 × 100 = 58.7, 0.114 × 50 = 5.7; sum 124.2.
Compute HSVmax = 200, min = 50, so V = 200/255 = 0.7843, S = 150/200 = 0.75, H = 60 × (50/150) = 20°.
AnswerGrey is 124.2. In HSV: hue 20° (orange), saturation 0.75, value 0.784.
CheckThe code below prints gray 124.2 and hsv [0.0556, 0.75, 0.7843] (0.0556 × 360 = 20°, Python's colorsys uses 0 to 1 for hue).
InterpretationGreen gets the biggest weight (0.587) because human eyes are most sensitive to green. A plain average (200+100+50)/3 = 116.7 would look slightly wrong.

Problem 8.1.2 Resize the 2×2 image [[10, 20], [30, 40]] to 3×3 by nearest neighbour and by bilinear interpolation.

Nearesteach new pixel copies the closest old pixel. Rows and columns map to old indices 0, 0, 1 (pixel positions 0, 0.5, 1 round to 0, 0, 1 with ties going down), giving [[10,10,20],[10,10,20],[30,30,40]].
Bilineara new pixel at fractional position is a weighted average of the 4 nearest old pixels. The centre (0.5, 0.5) has weights 0.25 each: 0.25 × (10 + 20 + 30 + 40) = 25. The top-middle (0, 0.5) is half of 10 and half of 20: 15.
AnswerBilinear gives [[10,15,20],[20,25,30],[30,35,40]]: a smooth ramp. Nearest gives blocks.
CheckThe output below matches. Also, rotating with np.rot90 and flipping with m[::-1] are one-line index changes.
InterpretationNearest is fastest and keeps hard edges (good for label masks, where you must not invent class 1.5). Bilinear or bicubic is smoother (good for photos). Shrinking a photo a lot needs area averaging (OpenCV INTER_AREA) or you get jagged aliasing.

a = np.array([[10., 20.], [30., 40.]])
def bilinear(a, H, W):
    h, w = a.shape; out = np.zeros((H, W))
    for i in range(H):
        for j in range(W):
            y = i * (h - 1) / (H - 1); x = j * (w - 1) / (W - 1)
            y0, x0 = int(np.floor(y)), int(np.floor(x))
            y1, x1 = min(y0 + 1, h - 1), min(x0 + 1, w - 1)
            fy, fx = y - y0, x - x0
            out[i, j] = (a[y0,x0]*(1-fy)*(1-fx) + a[y0,x1]*(1-fy)*fx
                         + a[y1,x0]*fy*(1-fx) + a[y1,x1]*fy*fx)
    return out
print(bilinear(a, 3, 3))

Line by line. colorsys.rgb_to_hsv takes values in 0 to 1, so we divide by 255. bilinear maps new index i of H to the old coordinate y = i·(h−1)/(H−1) (so the corners line up), takes the four neighbours (y0,x0), (y0,x1), (y1,x0), (y1,x1) and weights each by how close it is: (1−fy)(1−fx) and so on. np.rot90 of a (2,3) array gives shape (3,2), rotating counter-clockwise.

Histogram equalization: using the whole range

INTUITION
A foggy photo uses only grey levels 100 to 140. All the detail is squeezed into a narrow band. Equalization spreads the levels out so the busy band uses the whole 0 to 255 range, like re-scaling a chart axis that was too tight.

Rule: compute the histogram, then the cumulative histogram (the CDF: running total of counts). Map each level v to round((cdf(v) − cdf_min) / (N − cdf_min) × (L − 1)), where N is the number of pixels, cdf_min the smallest non-zero CDF value and L the number of levels.

Problem 8.1.3 A 4×4 image has only grey levels 1, 2, 3, 4 (on a scale of 8 levels, 0 to 7): rows [1,1,2,2], [1,2,2,3], [2,2,3,3], [2,3,3,4]. Equalize it.

Step 1Counts: level 1 appears 3 times, level 2 appears 7, level 3 appears 5, level 4 appears 1. Total 3+7+5+1 = 16.
Step 2CDF: level 1: 3, level 2: 10, level 3: 15, level 4: 16. cdf_min = 3, N = 16.
Step 3Map level 1: (3−3)/(16−3) × 7 = 0. Level 2: 7/13 × 7 = 3.77 → 4. Level 3: 12/13 × 7 = 6.46 → 6. Level 4: 13/13 × 7 = 7.
AnswerLevels 1,2,3,4 become 0,4,6,7: the image now spans the full 0 to 7 range.
CheckThe mapping is monotone (order of brightness preserved), and the code prints lut [0 0 4 6 7 7 7 7].
InterpretationContrast increased without losing the order of brightness. Use it for faint medical or surveillance images. Do not use it blindly before a CNN: it changes the statistics the network was trained on. For uneven contrast, CLAHE (cv2.createCLAHE, equalization on small tiles with a clip limit) is the usual choice.
im = np.array([[1,1,2,2],[1,2,2,3],[2,2,3,3],[2,3,3,4]])   # 4x4 image, gray levels 0..7

8.2 Filtering: Blur, Median and Sharpen

INTUITION
Noise is like a bad phone line: random crackle on top of the voice. Averaging a pixel with its neighbours cancels the crackle (blur). But averaging also smears real edges, and a single very loud pop (a dead pixel) ruins the average. Taking the middle value instead (median) ignores the pop. Sharpening is the opposite move: exaggerate what differs from the neighbours.

How it works

You already know convolution from Chapter 6: slide a kernel over the image and add up products. The kernel decides the effect:

FilterKernel (3×3)Effect
Mean (box) blurall 1/9equal average of neighbours
Gaussian blur[[1,2,1],[2,4,2],[1,2,1]] / 16centre pixel counts more; smoother, fewer artefacts
Sharpen[[0,−1,0],[−1,5,−1],[0,−1,0]]centre boosted, neighbours subtracted
Mediannot a convolutionsort the 9 values, take the 5th

The Gaussian kernel follows the bell curve exp(−d²/2σ²); a larger σ (sigma) blurs more. Its weights always add up to 1 so brightness is preserved. The median filter is non-linear (it cannot be written as a kernel) but is the best tool for salt-and-pepper noise (random pure white and black dots).

Problem 8.2.1 A 3×3 patch has a noise spike in the centre: [[10,20,30],[40,250,60],[70,80,90]]. Compute the centre output of the mean filter, the 3×3 Gaussian and the median.

Meansum = 10+20+30+40+250+60+70+80+90 = 650; 650/9 = 72.22.
Gaussianweighted sum: row 1 1·10 + 2·20 + 1·30 = 80; row 2 2·40 + 4·250 + 2·60 = 80 + 1000 + 120 = 1200; row 3 1·70 + 2·80 + 1·90 = 320. Total 1600, divided by 16 gives 100.
Mediansorted values 10, 20, 30, 40, 60, 70, 80, 90, 250; the 5th is 60.
AnswerMean 72.22, Gaussian 100, median 60.
CheckThe neighbours are between 10 and 90, so the "true" centre should be near 50. The median (60) is closest. The Gaussian is worst because it gives the spike weight 4/16.
InterpretationLinear filters spread an outlier into its neighbours; the median rejects it. This is the same reason a typical house price is reported as a median: a few extreme values distort the mean but not the middle value.

Problem 8.2.2 Sharpen: a flat patch of value 10 with one centre pixel of 50. Apply the sharpen kernel.

Formula5 × centre − (up + down + left + right).
Compute5 × 50 − (10 + 10 + 10 + 10) = 250 − 40 = 210.
AnswerThe centre becomes 210: a faint bump of 40 above its surroundings turns into a strong peak.
CheckOn a perfectly flat region of 10s: 5 × 10 − 40 = 10, unchanged. Sharpening only changes places where neighbours differ.
InterpretationSharpening amplifies noise as well as detail. Values above 255 must be clipped. Unsharp masking (original + amount × (original − blurred)) is the common practical form.

8.3 Edge Detection: Sobel, Canny and Hough

INTUITION
An edge is a place where brightness changes fast, like a cliff on a height map. The slope (gradient) tells you two things: how steep (magnitude) and which way (direction). A Sobel filter measures slope with two small kernels, one for left-to-right change and one for top-to-bottom change.

How it works

The two Sobel kernels:

Kx = [[-1, 0, 1],      Ky = [[-1, -2, -1],
      [-2, 0, 2],             [ 0,  0,  0],
      [-1, 0, 1]]             [ 1,  2,  1]]

Kx responds to vertical edges (brightness changing left to right), Ky to horizontal edges. The middle row/column has weight 2: it is a small smoothing built into the derivative. With gx and gy the two responses, magnitude = √(gx² + gy²) and direction = atan2(gy, gx).

Problem 8.3.1 Apply Sobel to a 5×5 patch whose every row is [10, 10, 50, 50, 50] (dark left, bright right). Find gx, gy, the magnitude and the direction at each of the three window positions across.

Step 1Window over columns 0 to 2: each row is (10, 10, 50). Kx row (−1, 0, 1) gives −10 + 0 + 50 = 40. The three rows carry weights 1, 2, 1, so gx = 40 × (1 + 2 + 1) = 160.
Step 2Window over columns 1 to 3: rows (10, 50, 50) give −10 + 50 = 40, so gx = 160.
Step 3Window over columns 2 to 4: rows (50, 50, 50) give −50 + 50 = 0, so gx = 0.
Step 4gy: every column is constant down the rows, so Ky gives 0 everywhere.
AnswerMagnitude 160, 160, 0 with direction 0° (the gradient points to the right, towards brighter pixels).
CheckThe code below prints the same numbers. A step of height 40 produced a response of 160 because the Sobel weights add to 4.
InterpretationThe response is large exactly at the cliff and zero on the flat area, as intended. The edge is two pixels wide because the 3×3 window straddles the cliff for two positions: this is why Canny adds a thinning step.
patch = np.array([[10,10,50,50,50]] * 5, float)               # dark left, bright right
Kx = np.array([[-1,0,1],[-2,0,2],[-1,0,1]], float); Ky = Kx.T

Noise breaks edge detectors: blur first

Derivatives amplify noise (a random jump looks like a cliff). So we blur first. On the 16×16 square image with strong noise (σ = 50 grey levels), we flag pixels with magnitude above 300 and compare with the true edge pixels (found on the clean image).

Canny and Hough in words

Canny (the standard edge detector, cv2.Canny(img, low, high), not run here) is Sobel plus four steps:

  1. Blur with a Gaussian to suppress noise.
  2. Gradient magnitude and direction with Sobel.
  3. Non-maximum suppression: at each pixel compare the magnitude with its two neighbours along the gradient direction; keep it only if it is the largest. This thins the thick edge to one pixel.
  4. Hysteresis thresholding: two thresholds, high and low. Pixels above high are certainly edges. Pixels between low and high are kept only if connected to a certain edge. This keeps long faint edges and drops isolated specks.

Typical settings: low about one half to one third of high.

Hough transform finds straight lines from edge points. A line can be written ρ = x·cos θ + y·sin θ (ρ is the distance from the origin, θ the angle of its normal). Each edge point votes for every (ρ, θ) pair it could lie on. A real line collects many votes at one (ρ, θ).

Problem 8.3.2 Ten edge points lie on the diagonal y = x at (0,0), (1,1), ..., (9,9). Show how Hough voting finds the line.

Formulaρ = x·cos θ + y·sin θ.
Step 1For θ = 135°: cos θ = −0.7071, sin θ = 0.7071. Point (k, k) gives ρ = −0.7071k + 0.7071k = 0 for every k.
Step 2So all 10 points vote for the same cell (ρ = 0, θ = 135°).
Step 3For θ = 0°: ρ = x, giving 10 different values, one vote each. Same idea for 45° and 90°.
AnswerThe cell (0, 135°) gets 10 votes, all others get 1, so the line y = x is detected.
CheckThe code prints angle 135 most votes for one rho: 10 (rho = 0.0) and 1 for the other angles.
InterpretationVoting makes the method robust: missing points or a few stray points do not matter. Real use: lane lines, document edges (cv2.HoughLinesP), circles (cv2.HoughCircles).
im = np.zeros((10, 10))
for i in range(10): im[i, i] = 1                              # one diagonal line y = x
ys, xs = np.where(im > 0)
for deg in (0, 45, 90, 135):

8.4 Thresholding, Morphology and Connected Components

INTUITION
You want a mask: white where the object is, black elsewhere. The simplest way is to pick a brightness cut-off. Then the mask is rough: it has holes and speckles. Morphology is "tidying with a small stamp": remove specks, fill holes. Finally you count and measure the white blobs, like counting coins on a table.

Thresholding

A threshold T turns grey into black and white: mask = pixel > T. The question is how to pick T automatically.

Otsu's method looks at the histogram and picks the T that best separates two groups. For each candidate T, split pixels into class 0 (≤ T) and class 1 (> T), and compute the between-class variance σb² = w0 · w1 · (mean0 − mean1)², where w0 and w1 are the fractions of pixels in each class. Pick the T that makes this biggest: the two groups are far apart and balanced.

Problem 8.4.1 A tiny image has 6 grey levels 0 to 5 with counts [8, 12, 5, 3, 10, 14] (total 52). Find Otsu's threshold.

Formulaσb² = w0 · w1 · (mean0 − mean1)².
Step 1T = 2 (class 0 is levels 0 to 2): pixels 8 + 12 + 5 = 25, w0 = 25/52 = 0.481, w1 = 0.519. mean0 = (0·8 + 1·12 + 2·5)/25 = 22/25 = 0.88. mean1 = (3·3 + 4·10 + 5·14)/27 = 119/27 = 4.407.
Step 2σb² = 0.481 × 0.519 × (0.88 − 4.407)² = 0.2497 × 12.44 = 3.106.
Step 3Repeat for the other T (the code does it): T = 0 gives 1.337, T = 1 2.787, T = 3 3.003, T = 4 1.929.
AnswerT = 2 has the largest value (3.106), so Otsu chooses it: levels 0 to 2 become black, 3 to 5 become white.
CheckThe histogram has two clumps (levels 0 to 2 and levels 4 to 5), and the cut falls in the valley between them. T = 3 is very close (3.003), as the valley is shallow.
InterpretationOtsu needs no manual tuning, but it assumes a two-clump histogram and even lighting.

Adaptive thresholding compares each pixel with the average of its own neighbourhood (pixel > local mean + c), so it survives lighting that changes across the image (a page photographed under a window). In the test below, a bright object on dark paper is photographed under even light and then with a brightness ramp added across the width.

Before you run it, predict: how much does a single global threshold suffer when the light is uneven?

def otsu(x):
    p = np.bincount(x.ravel().astype(int), minlength=256) / x.size
    best, bt = -1, 0
    for t in range(255):
        w0 = p[:t+1].sum(); w1 = 1 - w0
        if w0 == 0 or w1 == 0: continue
        m0 = (p[:t+1] * np.arange(t+1)).sum() / w0
        m1 = (p[t+1:] * np.arange(t+1, 256)).sum() / w1
        s = w0 * w1 * (m0 - m1) ** 2
        if s > best: best, bt = s, t
    return bt
def adaptive(x, k=9, c=5):                                    # pixel > local mean + c
    p = k // 2; xp = np.pad(x, p, mode='edge'); out = np.zeros(x.shape, bool)
    for i in range(x.shape[0]):
        for j in range(x.shape[1]): out[i, j] = x[i, j] > xp[i:i+k, j:j+k].mean() + c
    return out
rng = np.random.default_rng(2)
img = np.full((20, 20), 60.0); img[5:15, 5:15] = 180          # dark paper, bright object

Morphological operations

Morphology works on binary masks with a small structuring element (here a 3×3 square).

OperationRuleEffect
Erosionpixel stays white only if all its 3×3 neighbours are whiteshrinks objects, removes specks
Dilationpixel becomes white if any neighbour is whitegrows objects, fills small gaps
Openingerosion then dilationremoves small specks, keeps big shapes
Closingdilation then erosionfills small holes and gaps

Remember the order: open removes white noise, close fills black holes.

Problem 8.4.2 A 10×10 mask has a 6×6 square (rows and columns 2 to 7) with one hole at (5,5) and two speckles at (0,9) and (9,0). Which operation sequence cleans it?

Step 1Try opening first. Erosion removes both speckles (each has no white neighbours) but it also turns the 3×3 area around the hole black. Dilation then regrows the square, but the area next to the hole does not fully come back.
Step 2Try closing first. Dilation grows the square by one pixel, the hole (one pixel, all neighbours white) vanishes, and erosion shrinks the outline back. The speckles are dilated into 3×3 blobs and eroded back to single pixels, so they stay.
Step 3Then open: the single-pixel speckles do not survive an erosion, the solid square does.
AnswerClose, then open. The output below shows a clean 6×6 square.
CheckCompare with the "opening only" picture: it damaged the right side of the square near the hole.
InterpretationOrder matters. Match the order to the noise: holes inside objects need closing, specks outside need opening.
def erode(b, k=3):
    p = k // 2; bp = np.pad(b, p); out = np.zeros_like(b)
    for i in range(b.shape[0]):
        for j in range(b.shape[1]): out[i, j] = bp[i:i+k, j:j+k].all()
    return out
def dilate(b, k=3):
    p = k // 2; bp = np.pad(b, p); out = np.zeros_like(b)
    for i in range(b.shape[0]):
        for j in range(b.shape[1]): out[i, j] = bp[i:i+k, j:j+k].any()
    return out

Connected components and shape analysis

A connected component is a group of white pixels touching each other (here, up/down/left/right neighbours). Labelling them gives each blob an ID, so you can measure its area (pixel count) and bounding box. A contour is the outline of a blob (cv2.findContours, not run here); from contours you compute perimeter, area, and shape descriptors such as circularity 4π·area/perimeter² (1 for a perfect circle).

def label(b):
    lab = np.zeros(b.shape, int); n = 0
    for i in range(b.shape[0]):
        for j in range(b.shape[1]):
            if b[i, j] and lab[i, j] == 0:
                n += 1; stack = [(i, j)]; lab[i, j] = n
                while stack:
                    y, x = stack.pop()
                    for dy, dx in ((1,0), (-1,0), (0,1), (0,-1)):
                        yy, xx = y + dy, x + dx
                        if 0 <= yy < b.shape[0] and 0 <= xx < b.shape[1] and b[yy, xx] and lab[yy, xx] == 0:
                            lab[yy, xx] = n; stack.append((yy, xx))
    return lab, n

8.5 Features, Homography, Stitching and the Fourier View

INTUITION
To match two photos of the same building, the computer needs landmarks that are easy to find again. A flat wall is bad (all pixels look alike). A straight edge is better, but you could slide along it and not know where you are. A corner is best: move in any direction and the picture changes. Corner and blob detectors find such landmarks, descriptors write them down as numbers, and matching pairs landmarks between two photos.

Harris corners

Harris looks at a small window and asks "if I shift the window, how much does it change?". It builds a 2×2 matrix M from the image gradients Ix, Iy summed over the window:

M = [[Σ Ix·Ix, Σ Ix·Iy],
     [Σ Ix·Iy, Σ Iy·Iy]]
R = det(M) − k·(trace M)²     with k ≈ 0.04

The two eigenvalues of M (think: change strength along the two main directions) tell the story:

Both smallOne large, one smallBoth large
flat area, R ≈ 0edge, R < 0corner, R large positive

Problem 8.5.1 Run Harris on a white 6×6 square on black (rows and columns 4 to 9 of a 14×14 image). What do the eigenvalues say at a corner, on an edge and in a flat area?

Step 1At the corner (4, 4) the window sees gradients in both directions: eigenvalues 0.5625 and 1.0625, both large, so R = 0.492 is positive.
Step 2On the middle of the top edge (4, 7) the gradient points only up and down: eigenvalues 0 and 1.5, R = −0.09 is negative.
Step 3In the flat middle (7, 7) no gradients: eigenvalues 0, 0, R = 0.
AnswerLarge R appears in four clusters, one around each corner of the square (rows and columns 4 to 5 and 8 to 9).

SIFT, ORB, matching (concepts, not run here)

  • SIFT finds blobs at many scales and describes each by a 128-number histogram of gradient directions. It is robust to scale, rotation and some lighting change, but is slower. (Patent issues ended; it is available in current OpenCV.)
  • ORB is a fast, free alternative: FAST corners plus a 256-bit binary descriptor (BRIEF). Binary descriptors are compared with Hamming distance (count of different bits), which is extremely fast. Good for real-time and mobile use.
  • Matching: for each descriptor in image A, find the nearest descriptor in image B. Keep a match only if the best distance is clearly smaller than the second best (Lowe's ratio test, ratio about 0.75). Then RANSAC (random sample consensus) repeatedly fits a model to random small sets of matches and keeps the model that most matches agree with, which throws out wrong matches.
  • Today, learned detectors and matchers (SuperPoint, LightGlue, LoFTR) often beat these, but the classical pipeline is still a standard baseline and is used in robotics and AR.

Homography and image stitching

A homography is a 3×3 matrix H that maps points of one flat plane to another as seen by a camera (a tilted photograph of a document, or two photos of a distant scene from the same spot). A point (x, y) is written as (x, y, 1), multiplied by H, and the first two entries are divided by the third:

[u', v', w'] = H · [x, y, 1]        (u, v) = (u'/w', v'/w')

H has 8 free numbers (its overall scale does not matter, so we fix H[2,2] = 1). Each point pair gives 2 equations, so 4 point pairs are enough. We solve with SVD (the same decomposition you may know from the Math PDF).

Step 2The solution of A·h = 0 is the last right-singular vector from the SVD; reshape it to 3×3 and divide by its bottom-right entry.

The Fourier view

Any signal is a sum of waves. The Fourier transform (FFT, fast Fourier transform) writes a signal as how much of each frequency it contains. Slow waves are smooth, large-scale structure; fast waves are fine detail and noise. In an image, edges and noise live in high frequencies. Blur is simply removing high frequencies: a low-pass filter. Convolution in space equals multiplication in frequency, which is why large-kernel filtering can be done faster with the FFT.

Problem 8.5.3 Build x(t) = sin(2π·2t/32) + 0.5·sin(2π·10t/32) for t = 0..31. What magnitude does the FFT show at bins 2 and 10?

FormulaA sine of amplitude A at an exact frequency bin gives magnitude N·A/2 in an N-point FFT.
Computebin 2: 32 × 1 / 2 = 16. Bin 10: 32 × 0.5 / 2 = 8.
AnswerBin 2 shows 16, bin 10 shows 8, all other bins show 0.
CheckThe output below prints [0. 16. 8.] for bins 0, 2, 10 and zeros elsewhere.
InterpretationThe FFT separates the slow 2-cycle wave from the fast 10-cycle wave. Zeroing bin 10 would remove the fast component. For the 2D image test we keep only frequencies within radius 4 of the centre of the shifted spectrum: the error falls from 0.213 (noisy) to 0.145. Edges also lose sharpness, which is the price of low-pass filtering.

Chapter recap

  • An image is an array of numbers; pixel arithmetic needs care with uint8 wrap-around and with channel order (BGR in OpenCV).
  • HSV and Lab separate colour from brightness; grey uses weights 0.299, 0.587, 0.114.
  • Resizing needs interpolation: nearest for masks, bilinear or area averaging for photos.
  • Gaussian blur suits gentle noise, median suits salt-and-pepper noise (2.50 versus 21.92 error in our test), and sharpening amplifies differences.
  • Sobel measures gradient magnitude and direction; blur first or noise creates false edges (21 false alarms versus 0). Canny adds thinning and two-threshold hysteresis.
  • Hough voting finds lines (10 votes at one cell for ten collinear points).
  • Otsu picks the threshold that maximises between-class variance; adaptive thresholding handles uneven light (77.7% versus 90.2%).
  • Opening removes white specks, closing fills holes; connected components give area and bounding boxes for counting.
  • Harris finds corners (both eigenvalues large); ORB/SIFT describe them; a homography from 4 pairs maps one plane to another; the FFT shows frequency content.

Practice set

1. (easy) Grey value of (100, 150, 200) with luma weights. Answer: 29.9 + 88.05 + 22.8 = 140.75.

2. (easy) Median of the 3×3 patch values 5, 9, 1, 7, 200, 3, 8, 2, 6. Answer: sorted 1, 2, 3, 5, 6, 7, 8, 9, 200; the 5th value is 6.

3. (easy) What is np.uint8(250) + np.uint8(10)? Answer: 4 (wraps modulo 256; newer NumPy may also print a warning). Cast to float first.

4. (medium) Sobel gx for the window with rows (0, 0, 10) repeated three times. Answer: per row −0 + 10 = 10; times weights 1+2+1 = 4 gives 40.

5. (medium) Bilinear value at the centre of the 2×2 image [[0, 100], [100, 200]]. Answer: 0.25 × (0 + 100 + 100 + 200) = 100.

6. (medium) Find the bug: someone does img = cv2.imread('a.jpg') then passes it to a model expecting RGB. Answer: OpenCV loads BGR, so red and blue are swapped; convert with cv2.cvtColor(img, cv2.COLOR_BGR2RGB). Not run here.

7. (medium) Otsu on a histogram with counts [10, 10, 0, 0, 10, 10] (levels 0 to 5): compute σb² for T = 1. Answer: w0 = 20/40 = 0.5, w1 = 0.5, mean0 = 0.5, mean1 = 4.5; 0.25 × 16 = 4.0. (T = 2 and T = 3 give the same, since there are no pixels in the gap.)

8. (medium) A mask has one big blob (area 500) and 30 specks (area 1 to 3). What is the cleaning plan? Answer: opening with a 3×3 kernel, or connected components with a minimum area filter such as 5. Check that the big blob keeps its shape.

9. (hard) A grey ramp adds 100 grey levels from left to right to an image whose objects are 120 brighter than the background. Why does Otsu fail, and what do you do? Answer: the ramp is as large as the object contrast, so the two histogram clumps overlap and one threshold cannot separate them. Use adaptive thresholding, or estimate and subtract the background (large blur or flat-field correction), then Otsu.

10. (hard) Compute R for a Harris window with eigenvalues λ1 = 0.4, λ2 = 0.9, k = 0.04. Answer: det = 0.36, trace = 1.3, R = 0.36 − 0.04 × 1.69 = 0.36 − 0.0676 = 0.2924 (positive: corner).

11. (interview) "Compare Gaussian blur and median filter. When do you pick each?" Answer: Gaussian is linear and averages neighbours with bell-shaped weights, so it suits mild sensor noise but smears edges and spreads outliers. Median takes the middle value, so it removes impulse noise (dead pixels, salt and pepper) and keeps edges better, but is slower and not a kernel.

12. (interview/scenario) "Build a pipeline to count tablets in a photo on a plain tray." Answer: grey (or HSV) conversion; Gaussian blur; Otsu or adaptive threshold; closing to fill holes, opening to remove specks; connected components; discard blobs below a minimum area; if tablets touch, use a distance transform with watershed to split them; count the components. Validate on 20 labelled photos, and move to a detector (Chapter 9) if touching or varied tablets break the rules.
