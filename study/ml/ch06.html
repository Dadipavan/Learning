Your manager at an online grocery says: "Predict which deliveries will arrive late, and tell me the rules, because the operations team wants to read them." A straight line (Chapter 2) or a logistic model (Chapter 4) cannot give you rules like "if load is above 60 and queue is above 30, expect trouble". A decision tree can. 6.1 Impurity: How a Tree Decides What a Good Question Is

INTUITION
Play "20 questions". A good first question cuts the possibilities in half; a bad question ("is it a thing?") tells you almost nothing. A tree plays the same game with your data: each question splits the rows into two groups, and a good question makes each group more pure (mostly one class). The tree needs a number that says "how mixed is this group?". That number is called impurity.

Words you need

WordMeaningExample

Leafa node that stops splitting and makes the prediction"p(slow) = 0.97"
Depthnumber of questions from root to the deepest leaf
Impurityhow mixed the classes are in a node (0 = pure)

Entropy−Σ pₖ log₂ pₖ, measured in bitsfor p = 0.375: 0.954
Information gainparent impurity minus the weighted child impurity

Why "CART"? It means Classification And Regression Trees (1984). Trees are binary and chosen greedily: the best split for this node now, never looking ahead.

The formulas

For a node with a fraction p of positives (two classes):

Gini(p)    = 1 − p² − (1−p)²  = 2p(1−p)
Entropy(p) = −p·log₂(p) − (1−p)·log₂(1−p)

A split sends n_L rows left and n_R rows right (n = n_L + n_R). The impurity after the split is the weighted average:

Impurity_after = (n_L/n)·Impurity(left) + (n_R/n)·Impurity(right)
Gain           = Impurity(parent) − Impurity_after

For regression trees the target is a number, so "impurity" is the variance of the target in the node (or the sum of squared errors, SSE, around the node mean). The leaf predicts the mean of its rows. The gain is the variance reduction: SSE before minus SSE after.

COMMON MISTAKE
Thinking a tree compares every feature value in the data as a threshold. It tests only the midpoints between neighbouring sorted values (so at most n − 1 thresholds per feature). Equal values give no threshold between them.

Connection to the real job. The same gain rule runs inside XGBoost, LightGBM and every random forest (Chapter 7 uses a gradient-based version). Knowing it lets you read a tree dump and judge whether the splits make sense.

Applications. Credit scoring (readable rules for regulators), support-ticket routing, finding which order-volume and backlog mix makes deliveries late.

  3. For a regression tree, what does a leaf predict? Answer: the mean of the target values of its rows.

6.2 CART from Scratch (and Proof That It Matches scikit-learn)

INTUITION
Building a tree is one idea applied again and again. "Find the best question for these rows; split; repeat on each half; stop when a half is pure or too small." This is called recursion: a function that calls itself on smaller pieces of the problem.

The algorithm in plain steps

  1. Start with all training rows in the root.
  2. For each feature, sort the values and try each midpoint as a threshold. Score it by gain.
  3. Choose the feature and threshold with the largest gain.
  4. Send rows left or right and repeat from step 2 on each child.
  5. Stop a branch when: it is pure, or the depth limit is reached, or it has too few rows, or no split gives gain.
  6. The leaf's prediction is the class fraction (classification) or the mean (regression).

The code

This is the whole thing. Notice best_split loops over features and thresholds using a cumulative sum, so each feature costs one sort, not one pass per threshold.

import numpy as np
class Node:
    def __init__(s, **k): s.__dict__.update(k)

def best_split(X, y, min_leaf=1):
    n, p = X.shape; best = (None, None, 0.0)
    parent = 2*y.mean()*(1-y.mean())                 # Gini of the node
    for j in range(p):
        order = np.argsort(X[:, j], kind="stable")
        xs, ys = X[order, j], y[order]
        csum = np.cumsum(ys)                         # positives in the first i rows
        for i in range(1, n):
            if xs[i] == xs[i-1]: continue            # no threshold between equal values
            if i < min_leaf or n-i < min_leaf: continue
            pl = csum[i-1]/i; pr = (csum[-1]-csum[i-1])/(n-i)
            imp = (i*2*pl*(1-pl) + (n-i)*2*pr*(1-pr)) / n
            if parent - imp > best[2] + 1e-12:
                best = (j, (xs[i]+xs[i-1])/2, parent - imp)
    return best

def grow(X, y, depth, max_depth, min_leaf):
    if depth >= max_depth or y.min() == y.max() or len(y) < 2*min_leaf:
        return Node(leaf=True, p=y.mean(), n=len(y))
    j, t, g = best_split(X, y, min_leaf)
    if j is None: return Node(leaf=True, p=y.mean(), n=len(y))
    m = X[:, j] <= t
    return Node(leaf=False, j=j, t=t, n=len(y),
                left=grow(X[m], y[m], depth+1, max_depth, min_leaf),
                right=grow(X[~m], y[~m], depth+1, max_depth, min_leaf))

def predict_one(node, x):
    while not node.leaf: node = node.left if x[node.j] <= node.t else node.right
    return node.p

KEY INSIGHT
There is no magic in a decision tree. It is a nested list of if statements chosen by a greedy search. Everything else (forests, boosting) is built by combining many such lists.

Why greedy and not optimal? Finding the best tree overall is a very hard problem (exponentially many trees). Greedy is fast and usually good. Its weakness: a split that looks useless alone but is useful in combination (the XOR case from Chapter 4) can be missed at the root. In our data the interaction is visible because each single feature is also helpful alone.

Connection to the real job. Interviews often say "implement a decision tree split". The best_split function above is the answer. In the job you will use a library; the from-scratch version is how you know what min_samples_leaf actually does.

COMMON MISTAKE
Reading a leaf's p(slow) as a reliable probability regardless of its size. A leaf with 6 rows can show 0.667 and the true value could easily be 0.3 or 0.9. Use min_samples_leaf to force leaves to have enough rows.

Check yourself.

  2. Why sort each feature once? Answer: sorting lets a cumulative sum give the class counts on each side of every threshold in one pass.
  3. In our tree, which feature has no influence on the true label rule yet appears at depth 3? Answer: err has only a small effect (0.3 per unit in the log-odds); the tree used it because it is the best remaining question for the few rows left, not because it is strong.

6.3 Overfitting, Pruning, and What Trees Cannot Do

INTUITION
Let a tree grow until every leaf is pure and it behaves like a student who memorised last year's exam answers: perfect on the exam seen before, lost on new questions. A tree with no limit can always reach 100 percent training accuracy (one leaf per row at worst). We must tell it when to stop, or cut it back afterwards.

The best tree is a short one. (With 300 test rows, one accuracy point is 3 rows, so differences like 0.690 versus 0.700 are noise; the decline from 0.70 to 0.62 is not.)

Pruning: grow big, then cut back

Pre-pruning stops growth early (max_depth, min_samples_leaf). Post-pruning grows a big tree and then removes branches that do not earn their place. The standard version is cost-complexity pruning:

Cost(T) = Error(T) + α · (number of leaves of T)

α (alpha, "alpha") is the price per leaf. A big tree has low error but many leaves. A small tree is cheap but has higher error. A bigger α favours a smaller tree. The pruning order is by weakest link: remove first the branch that adds the least error reduction per extra leaf.

Problem 6.3.1 A node, if cut to a single leaf, would have error 0.10 (as a fraction of all training rows). The subtree below it has 3 leaves and error 0.06. At what α do we prefer to cut it?

Formulacost(leaf) = 0.10 + α·1; cost(subtree) = 0.06 + α·3.
Plug incut when 0.10 + α ≤ 0.06 + 3α.
Compute0.04 ≤ 2α, so α ≥ 0.02. This is also (0.10 − 0.06)/(3 − 1), the "error saved per extra leaf".
AnswerFor α ≥ 0.02 the three leaves are not worth their cost, so we prune to one leaf. For smaller α we keep them.
CheckAt α = 0.02 the costs are 0.12 and 0.12: a tie, as expected at the threshold.
Why it mattersEach branch has its own threshold α; raising α slowly removes branches in order of weakness. That gives a sequence of nested trees that you can score with cross-validation (Chapter 8).

Categoricals and missing values

Handling differs by library and version, so check your docs. scikit-learn trees accept NaN (since 1.3); HistGradientBoosting* has categorical_features; LightGBM and CatBoost handle categories natively. A category with 500 levels coded 0..499 gives the tree a fake order (id ≤ 247 means nothing), so use native handling or target encoding done inside cross-validation. Keep a "was missing" flag too, because missingness is often informative.

The step-like weakness: no extrapolation

A tree predicts the mean of the training rows in a leaf. It can never predict a value outside the range it saw. Train on the exact line y = 3x + 5 for x = 1..10 (so y from 8 to 35):

query x            5.5    10    15    30
tree prediction    20.0   35.0  35.0  35.0
linear prediction  21.5   35.0  50.0  95.0
true value         21.5   35    50    95

The tree is stuck at 35 forever after x = 10. A random forest does the same (the green curve in the picture). This is important for forecasting: if sales grow with time and you give a tree the raw time index, it will predict a flat line in the future. Fixes: predict the change or ratio rather than the level, detrend first, use a linear model for the trend and a tree for the residual, or add a linear-tree option (LightGBM has linear_tree).

COMMON MISTAKE
Using a forest or boosted trees on a target that trends upward (demand, traffic, price) and trusting the forecast beyond the training range. The model silently flatlines. Check by plotting predictions beyond the training range.

Strengths: no scaling, finds interactions, readable when shallow. Weaknesses: unstable (a small data change can change the root split), step-like, cannot extrapolate, overfits when deep.

Applications. Forecasting with detrended targets, shallow auditable risk scorecards, quick non-linear baselines.

6.4 Bagging and Random Forests: Averaging Away the Variance

INTUITION
Ask one person to guess the weight of an ox and they may be far off. Ask 500 independent people and average: the errors cancel and the crowd is usually close. One deep tree is a noisy guesser (high variance). A random forest asks hundreds of slightly different trees and averages them. The trick is making the trees different from each other, because averaging identical copies gives no improvement.

The two sources of randomness

  1. Bootstrap sample ("bagging" is short for bootstrap aggregating). For each tree, draw n rows from the n training rows with replacement. Some rows appear twice or more, some not at all. Each tree sees a different version of the data.
  2. Random feature subset at each split. Instead of testing all features, each split looks at only max_features randomly chosen ones. This stops every tree from using the same strong feature at the root.

Prediction: for classification average the trees' probabilities (or vote); for regression average the numbers.

Why averaging reduces variance: the formula

Suppose each tree's prediction at a point has variance σ², and any two trees have correlation ρ (rho). The variance of the average of B trees is:

Var(average) = ρ·σ² + (1 − ρ)·σ² / B

Problem 6.4.1 Each tree has σ² = 4. Compare B = 100 trees with correlation ρ = 0.5 and with ρ = 0.1.

FormulaVar = ρσ² + (1−ρ)σ²/B.
Plug in (ρ = 0.5)0.5 × 4 + 0.5 × 4 / 100 = 2 + 0.02.
Plug in (ρ = 0.1)0.1 × 4 + 0.9 × 4 / 100 = 0.4 + 0.036.
Compute2.02 and 0.436.
AnswerWith correlated trees (0.5) the average still has variance 2.02, about half of a single tree. With less correlated trees (0.1) it falls to 0.436, nearly a ninth.
CheckIf B → ∞ the second term vanishes and the floor is ρσ²: 2.0 and 0.4. Adding trees beyond a point cannot beat the correlation floor, which is why the random feature subset (which lowers ρ) matters more than the number of trees.
Why it mattersThis formula explains the two knobs: more trees shrink the second term; smaller max_features shrinks ρ (but raises each tree's bias a little).

Bias stays about the same as for one tree, so bagging works best with low-bias, high-variance trees: deep, unpruned trees. That is the opposite of boosting (Chapter 7), which uses shallow trees and attacks bias.

One tree versus a forest

Retrained 15 times on bootstrap resamples: a single tree scored 0.631 test accuracy (std 0.025); a 100-tree forest 0.680 (std 0.017). More accurate and more stable.

The main knobs

n_estimators (200 to 500; more never hurts accuracy), max_features (√p is the classification default; smaller means less correlated trees), min_samples_leaf (3 to 20 for noisy data), max_samples, class_weight. On our 3-feature data max_features=1, 2, 3 gave test accuracy 0.693, 0.693, 0.680; the effect is larger with many features.

Extra Trees (Extremely Randomized Trees) go one step further: instead of searching for the best threshold, each candidate feature gets a random threshold, and the best of those is used. It is faster and decorrelates trees more. On our data ExtraTreesClassifier scored 0.703 test. It often matches a random forest and sometimes beats it on noisy data.

Connection to the real job. A random forest is the best "first strong model" for tabular data: few hyperparameters, robust to scaling and outliers, OOB gives a quick score. Many teams ship it as the baseline before boosting.

Applications. Fraud and default baselines, churn with hundreds of features, small-data risk models, late-delivery prediction.

COMMON MISTAKE
Thinking "more trees overfit" and tuning n_estimators down to 10. The forest overfits by tree depth and leaf size, not by tree count. Use plenty of trees and regularize through min_samples_leaf and max_features.

Check yourself.

  1. With ρ = 1 (identical trees), what is the variance of the average? Answer: σ², no gain.
  2. How many of 1,000 rows are OOB for a typical tree? Answer: about 368.
  3. Why does max_features < p help? Answer: it lowers the correlation between trees, which lowers the variance floor ρσ².

6.5 Feature Importance: Which Number to Trust

INTUITION
After training, the boss asks "which features matter?". There are two ways to answer. One asks the trees how much each feature helped when building the model (impurity importance). The other breaks the feature and sees how much the score drops on held-out data (permutation importance). The first is quick but can be fooled; the second measures what you actually care about.

The two methods

  • Impurity importance (also "mean decrease in impurity", MDI; feature_importances_): for each feature, add up the gain of every split that used it, across all trees, and normalise to sum 1. It is computed from training data, so a feature that helps memorise gets credit.
  • Permutation importance: take held-out data, shuffle one feature's column (breaking its link to the target), and measure how much the score falls. A big drop means the model relied on it. Use sklearn.inspection.permutation_importance.

Impurity importance favours features with many distinct values (high cardinality): a column of random customer ids offers hundreds of thresholds, so by pure luck some split looks good in each node.

REAL JOB TIP
If an important feature in your model turns out to be an id, a timestamp or an index, assume leakage first (Chapter 8) and investigate before celebrating the score.

Chapter recap

  • A decision tree is a greedy nested list of if feature ≤ threshold questions. Each split is chosen to maximise gain = parent impurity minus weighted child impurity.
  • Gini 2p(1−p) and entropy −Σ p log₂ p rank splits almost identically. Regression uses variance (SSE) reduction and leaves predict the mean.
  • Candidate thresholds are midpoints between sorted values; sorting once and using cumulative sums keeps it fast.
  • Our 40-line NumPy tree matched scikit-learn exactly (max probability difference 0.0).
  • A tree with no limits memorises (train 1.00, test 0.62). Control it with max_depth, min_samples_leaf or cost-complexity pruning (ccp_alpha); choose by cross-validation.
  • Trees do not need scaling, find interactions, but are unstable, step-like and cannot extrapolate.
  • Bagging averages trees trained on bootstrap samples. Var = ρσ² + (1−ρ)σ²/B: random feature subsets lower ρ.
  • About 36.8 percent of rows are out-of-bag for each tree, giving a free validation score. More trees never hurt accuracy; depth and leaf size cause overfitting.
  • Impurity importance is biased toward high-cardinality features. Prefer permutation importance on held-out data.

Practice set

  1. (easy) A node has 20 rows, 5 positive. Gini? Answer: p = 0.25, 2 × 0.25 × 0.75 = 0.375.
  2. (easy) A split sends 6 rows left (all negative) and 4 rows right (all positive) from a 50/50 node of 10 rows. Gain in Gini? Answer: parent 0.5; children both 0; gain 0.5 (a perfect split).
  3. (medium) What is the output? DecisionTreeRegressor().fit([[1],[2],[3]], [10,20,30]).predict([[100]]). Answer: [30.], the right-most leaf; trees do not extrapolate.
  4. (medium) Find the bug: you one-hot encode customer_id with 20,000 levels and the forest's training score is 0.99 but test 0.70. Answer: the id lets trees memorise customers; drop the id (or use group-aware validation, Chapter 8). Check with permutation importance.
  5. (medium) A subtree has 4 leaves and error 0.05; as a single leaf its error would be 0.11. At what α is it pruned? Answer: (0.11 − 0.05)/(4 − 1) = 0.02.
  6. (hard, scenario) Your demand forecast uses a random forest on features [week_index, price, promo]. It is good in back-tests but flat when sales grow 30 percent next year. Why, and what do you do? Answer: trees cannot predict beyond the target range seen; week_index splits become constant. Model the trend separately (linear or growth rate), forecast the ratio to trend, or detrend; validate on a later time period (Chapter 8).
  7. (hard) Show that about 63.2 percent of rows are in a bootstrap sample. Answer: each row is missed with probability (1−1/n)ⁿ → e⁻¹ = 0.368, so it is included with 1 − 0.368 = 0.632.
  8. (interview) "Why does a random forest decorrelate its trees, and why does it matter?" Answer: Bootstrap rows and a random feature subset at each split make trees different. The variance of the average is ρσ² + (1−ρ)σ²/B; with identical trees (ρ = 1) averaging helps nothing, and lower ρ lowers the floor.
  9. (interview) "Gini vs entropy, and which feature-importance would you trust?" Answer: both are concave impurity measures that give almost the same trees; Gini is slightly cheaper. For importance, prefer permutation importance on held-out data, because impurity importance rewards high-cardinality features (an id looked 15 percent important in our test).
