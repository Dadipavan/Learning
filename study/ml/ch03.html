In Chapter 2 you met a model whose two cholesterol coefficients had standard errors so large that their signs meant nothing. Real tables have dozens or hundreds of columns, many of them near-copies of each other, and often fewer rows than columns. A plain least-squares fit on such data memorizes noise. Regularization is the cheap, powerful fix: add a small penalty on the size of the weights, and the model becomes calmer. You will derive ridge regression, solve lasso by the soft-threshold rule, watch coefficients shrink and vanish on real data, choose the penalty strength with cross-validation, and learn why feature scaling changes the answer. By the end you will know when to reach for ridge, lasso or elastic net, and what each one assumes.

Reminder: norms (‖w‖₂, ‖w‖₁) and the prior view of regularization are covered in the Math PDF (Pillar 5) and in Chapter 1 of this book (λ = σ²/τ²). Here we put them to work.

3.1 Ridge Regression (L2): Shrinking Everything a Little

BASIC EXPLANATION
Ridge regression adds an L2 penalty (the sum of squared weights) to the loss. It shrinks the weights toward zero, which lowers variance and makes the fit more stable when features are correlated.
INTUITION
A manager gives a team a budget of "points" to spread over the features. Giving a big weight to one feature is expensive. A model that can only afford small weights cannot make wild swings to chase noise. It is like driving with a speed limiter: you still get there, you just cannot swerve. Ridge puts the cost on the squared size of each weight, so it dislikes one huge weight more than several moderate ones, and it prefers to share credit among correlated features.

Words you need

WordPlain meaning
Penalty / regularizeran extra cost added to the loss that grows with the size of the weights
λ (lambda) or alphahow strong the penalty is. 0 means no penalty. Bigger means smaller weights
L2 norm squaredΣ wⱼ², the sum of squared weights
Shrinkagepulling coefficients toward zero
Interceptnever penalized (it only sets the average level)

Formal definition

ridge loss(w) = Σ (yᵢ − xᵢ·w)²  +  λ Σ wⱼ²

Derivation: the loss is (y − Xw)ᵀ(y − Xw) + λ wᵀw. The gradient is −2Xᵀ(y − Xw) + 2λw. Setting it to zero gives XᵀXw + λw = Xᵀy, so

w_ridge = (XᵀX + λ I)⁻¹ Xᵀ y

Compare with Chapter 2: the only change is adding λ to the diagonal of XᵀX. This has a lovely side effect. If XᵀX was singular (duplicate columns) or nearly singular, adding λ on the diagonal makes it invertible and well-behaved. This is the reason for the name "ridge": you add a ridge along the diagonal.

Why not just drop correlated columns? You can, but then you must decide which one to drop. Ridge keeps all of them and shares the credit.

Problem 3.1.1 Use the centred three-point data from Chapter 2: x = [−1, 0, 1] (the original 1,2,3 minus the mean 2) and y − ȳ = [−4/3, −1/3, 5/3]. Find the OLS slope and the ridge slope for λ = 1 and λ = 2. (With one feature and centred data, w = Sxy/(Sxx + λ).)

Formulaw = Σxy / (Σx² + λ)
Plug inΣxy = (−1)(−4/3) + 0 + (1)(5/3) = 4/3 + 5/3 = 3. Σx² = 1 + 0 + 1 = 2.
ComputeOLS (λ = 0): 3/2 = 1.5. Ridge λ = 1: 3/(2+1) = 1.0. Ridge λ = 2: 3/(2+2) = 0.75.
AnswerThe slope shrinks from 1.5 to 1.0 to 0.75 as λ rises. It never reaches exactly 0.
CheckRun Sxy/(Sxx+lam) in NumPy: it prints 1.5, 1.0, 0.75. As λ → ∞ the slope goes to 0, as expected.
Why it mattersRidge turns a "confident" slope into a "cautious" slope. When data is noisy, caution predicts better on new rows.

Ridge on real data

Diabetes data again (Chapter 2): 331 training rows, features standardized with training statistics. Our own ridge (np.linalg.solve(Z.T@Z + lam*np.eye(p), Z.T@(y - y.mean())), intercept ȳ) matches scikit-learn's Ridge(alpha=10) to 4×10⁻¹⁴.

import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler
d = load_diabetes()
Xtr, Xte, ytr, yte = train_test_split(d.data, d.target, test_size=.25, random_state=0)
sc = StandardScaler().fit(Xtr); Ztr, Zte = sc.transform(Xtr), sc.transform(Xte); ym = ytr.mean()
def ridge(Z, y, lam):
    p = Z.shape[1]; return np.linalg.solve(Z.T @ Z + lam * np.eye(p), Z.T @ (y - y.mean()))
rm = lambda a, p: np.sqrt(np.mean((a - p) ** 2))
print("lam | test RMSE | norm | s1 s2 coef")
for lam in [0, 1, 10, 100, 1000]:
    w = ridge(Ztr, ytr, lam); print(lam, round(rm(yte, Zte @ w + ym), 3), round(np.linalg.norm(w), 1), w[4:6].round(1))

Predict first: as λ grows from 0 to 1000, will the test error fall forever? Output:

lam | test RMSE | norm | s1 s2 coef

10 56.453 44.0 [-7.4 -2.5]
100 55.521 35.6 [-1.5 -4.6]
1000 59.129 15.9 [1.2 0.1]

Explain: the weight vector norm falls steadily (56.8 to 15.9). The collinear pair s1, s2 (coefficients −26.5 and +12.4 with opposite signs, a classic collinearity pattern) settles to small values as λ grows. Test error improves a little at λ = 100 (55.5), then rises (59.1 at 1000) because the model is now too stiff: bias has taken over. This is the bias-variance curve of Chapter 1, with λ as the complexity knob (large λ means a simple model). The gain on this dataset is small because the problem has only 10 columns and 331 rows; ridge pays off much more with more columns (3.4).

How to read it: each coloured line is one feature's coefficient. Move from left (no penalty) to right (strong penalty). On the left panel all lines glide to zero together and none touches zero until the very end. On the right panel lines snap to zero and stay there.

Connection to the real job

  • Ridge is a good default for linear models with many correlated features (marketing mix, sensor data, text TF-IDF).
  • It makes the linear model's predictions stable when features are noisy or nearly duplicated.
  • Many deep-learning libraries call the same idea weight decay.

Applications

  • Machine Learning: ridge baselines for high-dimensional tabular data; weight decay in neural nets.
  • Data Science: marketing-mix models where channels are correlated.
  • Finance: covariance and return models (the "shrinkage estimator" idea).
  • Genomics and text: many more columns than rows.
COMMON MISTAKE
Penalizing the intercept, or choosing λ on the training error. Training error always prefers λ = 0. Choose λ with validation or cross-validation (3.3).

Check yourself

  1. What does ridge add to XᵀX? Answer: λ times the identity matrix (λ on the diagonal).
  2. Does ridge ever set a coefficient to exactly zero? Answer: not in practice; it only shrinks.
  3. When λ → ∞, what do the non-intercept weights become and what does the model predict? Answer: all weights go to 0; it predicts the training mean.

3.2 Lasso (L1) and Elastic Net: Sparsity

BASIC EXPLANATION
Lasso adds an L1 penalty (the sum of absolute weights), which can set some weights exactly to zero and so selects features. Elastic Net combines the L1 and L2 penalties.
INTUITION
Ridge says "keep everybody on the team, but give them smaller roles". Lasso says "you have a limited number of seats; some of you are out". The L1 penalty charges a flat price per unit of weight (|w|), so a feature that does not earn at least that price is cut to exactly zero. That is automatic feature selection. The name stands for Least Absolute Shrinkage and Selection Operator. Elastic net is a blend of both penalties: it keeps the zeroing of lasso but shares credit among correlated features like ridge.

Formal definition

lasso loss(w) = (1/2n) Σ (yᵢ − xᵢ·w)²  +  α Σ |wⱼ|
elastic net  = (1/2n) Σ (...)² + α [ ρ Σ|wⱼ| + (1−ρ)/2 Σ wⱼ² ]

Here ρ is the l1_ratio in scikit-learn (1 means pure lasso, 0 means pure ridge). Scikit-learn divides the squared error by 2n; that is why its alpha has a different scale from the ridge alpha above.

There is no closed formula for many features, because |w| has a sharp corner at 0. Instead we use coordinate descent: update one weight at a time, holding the others fixed, and cycle through them. Each one-weight update has a neat closed form, the soft-threshold rule.

Deriving the soft threshold. For one feature, ignoring the others (standardized so that (1/n)Σx² = 1), let ρ = (1/n) Σ x r be the correlation-like number "how much the feature explains the current leftover r". The loss for the weight is ½(w − ρ)² + α|w| plus a constant. For w > 0 the slope is (w − ρ) + α; setting to zero gives w = ρ − α, which is valid only if ρ > α. For w < 0 we get w = ρ + α, valid if ρ < −α. If |ρ| ≤ α neither works, so the minimum sits at the corner w = 0. In one line:

w = sign(ρ) · max(|ρ| − α, 0)

In words: shrink toward zero by α; if you would cross zero, stop at zero.

Problem 3.2.1 Same three centred points (Sxy = 3, Sxx = 2). Use the form ½Σ(y − wx)² + λ|w| (no 1/n). Find the lasso slope for λ = 1 and λ = 3.

Formulaw = sign(Sxy) · max(|Sxy| − λ, 0) / Sxx
Plug inλ = 1: max(3 − 1, 0)/2 = 2/2. λ = 3: max(3 − 3, 0)/2 = 0/2.
Computeλ = 1 gives w = 1.0. λ = 3 gives w = 0.
AnswerAt λ = 1 the slope is 1.0 (the same as ridge λ = 1 by coincidence); at λ = 3 the feature is dropped completely.
CheckAt w = 1: loss = ½[(−4/3 + 1)² + (−1/3)² + (5/3 − 1)²] + 1·1 = ½[0.1111 + 0.1111 + 0.4444] + 1 = 1.3333. At w = 1.1: ½[(−1.3333+1.1)² + (−0.3333)² + (1.6667−1.1)²] + 1.1 = ½[0.0544+0.1111+0.3211] + 1.1 = 1.3433. At w = 0.9: the residuals are −0.4333, −0.3333, 0.7667, squares 0.1878, 0.1111, 0.5878, sum 0.8867, half is 0.4433, plus 0.9 gives 1.3433. So 1.0 beats both neighbours.
Why it mattersRidge slope shrinks smoothly; lasso slope sits at an exact zero once the evidence is weaker than the penalty. That is the mechanism of feature selection.

The geometry: why L1 gives zeros

Read it this way. Each axis is one weight. The black dot is the best weights without any penalty (smallest error). The blue ellipses are weight pairs with equal error, getting worse outward. The penalty says "stay inside the orange shape". You want the blue ellipse that just touches the orange shape. A circle has no corners, so the touching point is generic: both weights are non-zero. A diamond has sharp corners on the axes, and an ellipse coming from a distance usually reaches a corner first. At a corner one weight is zero.

Lasso on the diabetes data

We implemented coordinate descent with the soft threshold in NumPy and compared it with sklearn.linear_model.Lasso:

soft = lambda z, t: np.sign(z) * max(abs(z) - t, 0)
def lasso_cd(Z, y, a, it=500):
    n, p = Z.shape; w = np.zeros(p); yc = y - y.mean()
    for _ in range(it):
        for j in range(p):
            r = yc - Z @ w + Z[:, j] * w[j]          # leftover without feature j
            rho = Z[:, j] @ r / n
            w[j] = soft(rho, a) / (Z[:, j] @ Z[:, j] / n)
    return w

Collinear twins: ridge, lasso, elastic net behave differently

We make two nearly identical columns (x and x + tiny noise) with true effect 3 on x:

OLS         [1.371 1.629]    (unstable split, sum 3.0)
ridge       [1.494 1.499]    (shares evenly)
lasso       [2.909 0.001]    (picks one twin)
elastic net [1.443 1.444]    (shares, with a little shrinkage)

Interpretation: OLS splits the 3 in a random way. Ridge splits it evenly. Lasso picks one twin (and which twin it picks can change with a different sample, which is unstable). Elastic net, with l1_ratio = 0.5, shares. Elastic net is usually the safest sparse choice when you have groups of correlated features.

Connection to the real job

Lasso as a screening tool: "out of 300 candidate features, 12 survive" is a sentence in many reports. Remember the survivors are those the model used, not proven causes.

Applications

  • Data Science: automatic selection among hundreds of engineered features.
  • Genomics: thousands of genes, hundreds of patients.
  • Text classification: sparse L1 logistic regression keeps a short list of words.
  • MLOps: a sparse model is cheaper to serve and easier to monitor.
COMMON MISTAKE
Reading lasso's choice as "these are the only important features". Between two correlated features, lasso keeps one almost arbitrarily. Re-run on a bootstrap sample to see how stable the selection is.

  2. Which penalty gives exact zeros? Answer: L1 (lasso, and elastic net when l1_ratio > 0).

3.3 Choosing the Strength by Cross-Validation, and Why Scaling Matters

BASIC EXPLANATION
The penalty strength lambda (called alpha in scikit-learn) is a hyperparameter chosen by cross-validation. Because penalties depend on the size of the weights, features must be put on a common scale first.
INTUITION
The penalty strength λ is a hyperparameter: the training data cannot tell you its value (it always wants λ = 0). So you hide a piece of data, try many values of λ, and pick the one that predicts the hidden piece best. To make this fair and less noisy, you do it five or ten times with a different hidden piece each time. That is k-fold cross-validation. The second part: the penalty counts weight sizes, and the size of a weight depends on the units of its feature. So we must put all features on the same scale first.

How k-fold cross-validation works

  1. Shuffle rows and split into k equal folds (here k = 5).
  2. For each fold: train on the other 4, test on the held-out fold, record the error.
  3. Average the k errors. That is the CV score for this λ.
  4. Repeat for each candidate λ and choose the best (or the largest λ within one standard error of the best, the "one-standard-error rule", which prefers the simpler model).

Chapter 8 covers the design issues (groups, time) in depth.

from sklearn.linear_model import Ridge, RidgeCV
from sklearn.model_selection import KFold, cross_val_score
alphas = np.logspace(-2, 3, 11)
for a in alphas:
    s = -cross_val_score(Ridge(alpha=a), Ztr, ytr, cv=KFold(5, shuffle=True, random_state=0),
                         scoring="neg_root_mean_squared_error").mean()
    print(round(a, 3), round(s, 2))

Scaling changes the answer for regularized models

OLS gives the same predictions whatever the units. Ridge and lasso do not, because they charge for the numeric size of the weights. Experiment: y = 2·x₁ + 0.02·x₂ + noise, with x₁ of standard deviation 1 and x₂ of standard deviation 100 (so both features matter equally: 2 × 1 = 2, 0.02 × 100 = 2).

unscaled: ridge(alpha=10000) [0.061 0.021]   OLS [2.042 0.021]
scaled:   ridge(alpha=10000) [0.063 0.061]   OLS (scaled) [2.078 2.003]

Unscaled: the small-unit feature x₁ needs a large weight (2.04) so it is crushed by the penalty (to 0.061), while x₂ needs only a tiny weight (0.021) so the penalty barely touches it (0.021). The penalty was unfair, purely due to units. After standardizing, both features are treated alike (0.063 and 0.061). Rule: always standardize before ridge, lasso or elastic net, and fit the scaler inside the cross-validation (Chapter 8) so that scale statistics come from training folds only.

Problem 3.3.1 A 5-fold CV for λ = 1 gives fold errors (RMSE) 52, 55, 53, 58, 52. For λ = 100 the errors are 54, 55, 54, 57, 54. Which λ do you choose?

FormulaCV score = mean of fold errors; also look at the spread.
Plug inλ = 1: (52+55+53+58+52)/5. λ = 100: (54+55+54+57+54)/5.
Compute270/5 = 54.0 and 274/5 = 54.8.
Answerλ = 1 has the lower mean (54.0 vs 54.8). The sample standard deviation of the λ = 1 fold errors is about 2.55, so a "one standard error" band is about 2.55/√5 = 1.14. The difference (0.8) is smaller than that band, so the two are statistically tied and λ = 100 (the simpler model) is a defensible choice under the one-standard-error rule.

Why it mattersA tiny gap in the mean is not a reason to prefer a model. Fold-to-fold noise decides.

Connection to the real job

Pipelines (make_pipeline(StandardScaler(), RidgeCV())) are the standard way to keep scaling inside CV. In production the same fitted scaler must be saved and reused at serving time (Chapter 16).

Applications

  • ML: tuning alpha for linear models, C for SVMs and logistic regression.
  • Data Science: feature-selection screening with LassoCV.
  • MLOps: saving the whole pipeline object, not only the model.
COMMON MISTAKE
Standardizing on the full dataset before splitting. The scaler then "saw" the validation rows. It is mild here but it is the first step on the road to leakage (Chapter 8).

Check yourself

  1. Why can't we pick λ using training error? Answer: it always picks λ = 0 (the most flexible fit).
  2. Why standardize before ridge? Answer: the penalty depends on weight size, which depends on feature units.
  3. What does the one-standard-error rule choose? Answer: the simplest model whose CV error is within one standard error of the best.

3.4 When Regularization Really Pays: p > n, Collinearity, and the Toolkit

BASIC EXPLANATION
Regularization helps most when there are more features than rows (p > n), when features are strongly correlated, or when the data is noisy. In these cases ordinary least squares is unstable, and a penalty trades a little bias for much lower variance.
INTUITION
If you have 30 patients and 100 measurements, there are infinitely many weight vectors that fit the training data perfectly. The data cannot choose between them. Regularization is the tie-breaker: "among all the perfect fits, prefer the simplest (smallest or sparsest)". That is exactly the situation where it shines. It is also a way of saying "I have an opinion about what a reasonable solution looks like", which we called the prior in Chapter 1.

Experiment: 30 rows, 100 columns, 3 real signals

True weights are [3, −2, 1.5, 0, …, 0]. The other 97 columns are pure noise. Test on 1,000 fresh rows.

OLS (minimum-norm solution)  test RMSE 3.443
Ridge alpha=10               test RMSE 3.451
Lasso alpha=0.2              test RMSE 0.688   (10 non-zero coefficients; includes columns 0, 1, 2)

The noise standard deviation is 0.5, so 0.5 is the best achievable. Ridge does not help here: it shrinks all 100 weights, but 97 of them are noise and ridge keeps a little of each, so the model's error stays at 3.45. Lasso knows (by its assumption) that "few features matter", and that assumption is true here, so it wins by a large margin (0.69). This is inductive bias (Chapter 1) in action: pick the regularizer whose assumption matches the world. If instead the truth has many small effects, ridge wins.

Problem 3.4.1 A regression has 500 rows and 800 columns. You run OLS with np.linalg.lstsq. Training RMSE is 0.000. Explain, and name two fixes.

FormulaA linear model with p parameters can fit any n ≤ p points exactly (when columns are independent).

ComputeThere is more freedom than data, so the residuals can all be made zero.

CheckShuffle the target and refit: you will still get training RMSE 0 (this is a quick sanity test, Chapter 10). If a fit is "perfect" even on random labels, it says nothing.

Connection to the real job

When a recruiter-style question asks "what do you do when you have more features than rows?", the answer has three parts: regularize (L1 if you believe in sparsity, L2 otherwise), reduce dimension, and validate with repeated CV because variance is high.

Applications

  • Genomics / biostatistics: p ≫ n is the norm.
  • NLP bag-of-words: 100,000 columns, sparse L1/L2 logistic regression is a strong baseline.
  • Sensor data / telecom: thousands of correlated counters.
  • Quant finance: shrinkage for stable portfolio weights.
COMMON MISTAKE
Using ridge and expecting it to select features. It will not. If you need a short list, use lasso, elastic net, or a tree-based importance with caution (Chapter 6).

Check yourself

  1. When p > n, can OLS achieve zero training error? Answer: yes, usually, and that tells you nothing about test error.
  2. Which regularizer fits "I believe only a few features matter"? Answer: L1 (lasso).
  3. Which fits "many small effects"? Answer: L2 (ridge).

Chapter recap

  • Regularization adds a penalty on weight size to the loss. It lowers variance at the price of a little bias.
  • Ridge: w = (XᵀX + λI)⁻¹Xᵀy. It shrinks all weights smoothly, fixes singular or collinear problems, and shares credit among correlated features.
  • Lasso: L1 penalty. Each coordinate update is the soft threshold, so weak features go to exactly zero.
  • Elastic net blends both. It is the usual safe choice with groups of correlated features.
  • Geometry: L2's budget is a round ball (no corners, no zeros). L1's budget is a diamond with corners on the axes (zeros).
  • λ is a hyperparameter. Choose it by cross-validation, never by training error. If the CV curve is flat, prefer the simpler model.
  • Standardize features first (inside the CV pipeline). Penalties depend on units.
  • Match the regularizer to the world: few true signals favour lasso, many small effects favour ridge.
  • On the diabetes data all linear variants gave RMSE between 56.1 and 56.5, which is the same within noise.

  1. (easy) With Sxy = 6, Sxx = 4, find OLS and ridge (λ = 2) slopes. Answer: OLS 6/4 = 1.5; ridge 6/(4+2) = 1.0.
  2. (easy) What is the soft threshold of ρ = −0.8 with α = 0.3? Answer: sign(−0.8) · max(0.8 − 0.3, 0) = −0.5.
  3. (easy) What does alpha=0 mean in Ridge? Answer: no penalty, the same as OLS.
  4. (medium) With Sxy = 3, Sxx = 2, at what λ does the lasso slope become exactly 0? Answer: when λ ≥ |Sxy| = 3.
  5. (medium) What is the output? Ridge(alpha=1e9).fit(X, y).coef_ on standardized data. Answer: values extremely close to 0 (the model predicts almost the mean).
  6. (medium) Find the bug: scaler.fit(X_all) then train_test_split, then RidgeCV. Answer: the scaler saw the test rows. Split first, fit the scaler on train (or put it in a pipeline).
  7. (medium) You see a coefficient table where bmi has weight 28 and age 0.0 from LassoCV. A manager asks "does age matter?" Answer: not given the other features in this model; it may still correlate with them. Do not claim age has no effect on the outcome.
  8. (medium) λ = 4, σ = 2. What prior standard deviation τ? Answer: τ² = σ²/λ = 4/4 = 1, so τ = 1.
  9. (hard, scenario) Telecom: 5,000 counters, 800 labelled outages. You need a model the on-call team can read. Answer: standardize, use L1 or elastic-net logistic regression (Chapter 4), choose α by grouped CV (group by device), report the short list with its stability across bootstrap resamples.
  10. (hard) Show that adding λ to the diagonal of XᵀX always makes it invertible. Answer: XᵀX is positive semi-definite (eigenvalues ≥ 0). Adding λ > 0 makes every eigenvalue at least λ > 0, and a matrix with no zero eigenvalue is invertible.
  11. (interview) "L1 vs L2?" Answer: Both shrink weights. L2 shrinks smoothly, never to exactly zero, and shares credit between correlated features. L1 shrinks by a constant amount and sets weak features to zero, giving feature selection but unstable choices among correlated features. Probabilistically, L2 is a Gaussian prior and L1 a Laplace prior. Elastic net blends them.
  12. (interview) "Why must you standardize before lasso?" Answer: the penalty is on the size of the coefficient. A feature measured in small units needs a large coefficient and would be penalized more. Standardizing makes the penalty fair.
