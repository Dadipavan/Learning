1.1 The Four Kinds of Learning and Empirical Risk Minimization

BASIC EXPLANATION
Machine learning is the study of algorithms that learn a rule from example data instead of being given the rule. Learning can be supervised (labelled examples), unsupervised (no labels), semi-supervised, or reinforcement-based. Empirical risk minimization means choosing the model with the lowest average loss on the training data.
INTUITION
Think of baking bread. You choose the knobs (oven temperature, baking time, amount of yeast) and judge one number (how far the loaf is from the one you wanted). A model is the same: a function with knobs, and a number that tells you how bad it is. "Training" means turning the knobs until the bad number gets small. The big difference: in ML the number you really care about is measured on data you have not seen yet.

The four families

FamilyWhat the data looks likeWhat we learnExample
Supervisedinputs x with correct answers ya function x → ypredict loan default
Unsupervisedinputs x onlystructure in xgroup customers
Self-supervisedinputs only, but we invent labels from the data itselfuseful representationspredict the next word, hide a patch of an image
Reinforcementan agent acts and receives rewardsa policy (how to act)choose which ad to show

Supervised learning has two sub-types. Regression predicts a number (delivery time). Classification predicts a category (fraud or not fraud).

Empirical risk minimization (ERM)

Three choices define almost every supervised method:

  1. A model family (also called hypothesis class): the set of functions we allow. Example: all straight lines ŷ = w·x + b.
  2. A loss function ℓ(y, ŷ): a number that says how bad one prediction is.
  3. An optimizer: a procedure that searches the family for the best knobs.

The true risk is the average loss over all data the world could ever produce. We cannot compute it. The empirical risk is the average loss over the n examples we have:

R_emp(θ) = (1/n) · Σᵢ ℓ( yᵢ , f(xᵢ; θ) )

ERM says: pick θ that makes R_emp smallest. The hope is that a small empirical risk means a small true risk. That hope is not always true. That gap is the subject of the whole book.

Parameters are the knobs the optimizer learns (the slope and intercept). Hyperparameters are knobs you set before training (the degree of a polynomial, the tree depth, the learning rate). Capacity (or complexity) is how rich the model family is: degree-9 polynomials have more capacity than straight lines.

Connection to the real job

Every sklearn call model.fit(X, y) is ERM. When someone asks "what loss did you train with?" they are asking choice number 2. When a boosted-tree model says "learning rate = 0.05", that is a hyperparameter you tune (Chapter 11).

Applications

  • Credit scoring: model family is logistic regression, loss is log loss.
  • Demand forecasting: model family is boosted trees, loss is squared or Poisson error.
  • Spam filtering: model family is naive Bayes or a neural net.
  • Ad ranking: loss is log loss on click or no click.
COMMON MISTAKE
Calling the learned numbers "hyperparameters". If the optimizer finds it, it is a parameter. If you choose it (and must try several values), it is a hyperparameter.

Check yourself

  1. What are the three choices that define ERM? Answer: model family, loss function, optimizer.
  2. Why do we say "empirical" risk? Answer: because it is the average over the data we actually have, not over all possible data.
  3. Is the number of trees in a random forest a parameter or a hyperparameter? Answer: a hyperparameter.

1.2 Splits, the i.i.d. Assumption, and Generalization

BASIC EXPLANATION
Data is split into training, validation and test sets so a model is judged on examples it has not seen. The i.i.d. assumption says all examples are drawn independently from the same distribution. Generalization is how well a model performs on new data from that distribution.
INTUITION
A student who memorizes last year's exam gets 100 percent on last year's exam and fails this year's. Training error measures memory. We want to measure understanding, so we test on questions the model never saw.

Three roles for data

SetRoleRule
Trainingthe optimizer fits parameters herethe model may see it unlimited times
Validationchoose hyperparameters, compare modelsmany looks are allowed, but it slowly gets "used up"
Testone final honest scoretouch it once, at the very end

The i.i.d. assumption

i.i.d. means independent and identically distributed. Every example is drawn independently from the same distribution. Random splits only give honest scores if this is true. It breaks in three common ways:

  • Time: tomorrow's data differs from yesterday's (prices, trends). A random split lets the model "see the future".
  • Groups: many rows come from the same user, patient or device. Rows of one user are not independent. If user A is in both train and test, the model recognizes A, not the pattern.
  • Drift: the world changes after deployment (a new product, a new law, a pandemic).

Chapter 8 shows the fixes: group k-fold, time-series splits, adversarial validation.

Generalization gap, overfitting and underfitting

generalization gap = test error − training error
  • Underfitting: error is high on both sets. The model is too simple (a straight line through a sine wave).
  • Overfitting: training error is tiny, test error is much larger. The model learned the noise.

We make this visible. We draw 20 noisy points from y = sin(2πx) + noise (noise standard deviation 0.3, so the best possible mean squared error is 0.3² = 0.09). We fit polynomials of different degrees and test on 2,000 fresh points.

import numpy as np
rng = np.random.default_rng(0)
f = lambda x: np.sin(2*np.pi*x)
n = 20
x  = rng.uniform(0, 1, n);    y  = f(x)  + rng.normal(0, 0.3, n)
xt = rng.uniform(0, 1, 2000); yt = f(xt) + rng.normal(0, 0.3, 2000)
print("deg train_mse test_mse")
for d in [0, 1, 3, 5, 9, 12]:
    c = np.polyfit(x, y, d)
    print(d, round(np.mean((np.polyval(c, x) - y)**2), 3),
             round(np.mean((np.polyval(c, xt) - yt)**2), 3))

Think of a student preparing for an exam. With 10 practice questions she memorizes them (training error low) but fails the real exam (test error high). Problem 1.2.1 A model has training accuracy 99 percent and validation accuracy 71 percent. A teammate says "the model is great". Respond.

Step 1Gap = 99 − 71 = 28 points. That is large.
Step 2High training score only proves capacity to memorize.

AnswerThe model overfits. The honest score is 71 percent, not 99.
CheckIf you predicted the majority class for everyone, what would you score? If that baseline is 70 percent, your model barely beats a rule.

Problem 1.2.2 Learning curve: train error 0.30, validation error 0.32, and both stay flat when data goes from 1,000 to 100,000 rows. Is more data a good investment?

Step 1The gap is tiny (0.02), so variance is low.
Step 2Both errors are high and flat, so the model is too simple or the features lack signal (high bias).
AnswerNo. Improve features or use a richer model.
CheckCompare with the earlier table: at 200 and 1,000 rows the degree-3 curves had already met at the noise floor, which is the same situation.

Connection to the real job

The first question a senior reviewer asks on any model: "How did you split?" Most failures in production come from a split that did not mimic the real use.

Applications

  • Fraud: split by time, because fraud tactics change.
  • Medical: split by patient, because one patient has many scans.
  • Recommendation: split by user or by time, depending on the use.
COMMON MISTAKE
Tuning on the test set "just a little". Each look leaks information. After ten looks, the test set is just another validation set and its score is optimistic.

Check yourself

  1. Training MSE 0.02, test MSE 0.32. Over- or underfit? Answer: overfit.
  2. Why can a random split fail on user-level data? Answer: the same user appears in train and test, so the model can memorize users.
  3. Both curves are high and flat. More data? Answer: no, the model is too simple (high bias).

1.3 Bias-Variance Decomposition

BASIC EXPLANATION
The bias-variance decomposition splits a model's expected prediction error into bias squared, variance and irreducible noise. Bias is error from wrong or too simple assumptions. Variance is error from sensitivity to the particular training sample.
INTUITION
Imagine five students each get a different sample of delivery records from the same shop and each draws a trend line. If all five lines are in the same wrong place, that is bias (systematic error). If the five lines point in five different directions, that is variance (sensitivity to the sample). Simple models have high bias, low variance. Flexible models have low bias, high variance.

The decomposition for squared error

Let the truth be y = f(x) + ε, where noise ε has mean 0 and variance σ². Train the model on a random training set D. The prediction at a point x₀ is f̂(x₀), which is random because D is random. Then:

E[(y − f̂(x₀))²] = ( E[f̂(x₀)] − f(x₀) )²  +  Var( f̂(x₀) )  +  σ²
                         bias²                  variance        irreducible noise

Derivation in plain steps. Let m = E[f̂(x₀)] (the average prediction over many training sets). Write y − f̂ = (y − f) + (f − m) + (m − f̂). Square it and take the expectation. The cross terms vanish for two reasons: the noise ε = y − f is independent of f̂ and has mean zero, and E[m − f̂] = 0 by definition of m. What remains: E[ε²] = σ², (f − m)² = bias², and E[(m − f̂)²] = variance. Done.

We measure it. We repeat 500 times: draw a new 20-point training set, fit, predict at x₀ = 0.25 (true value sin(π/2) = 1).

The horizontal axis is model complexity. As it grows, the blue line (bias²) falls because the model can bend. The orange line (variance) rises because the model reacts to noise. The black line is their sum plus noise: the U-shape you are looking for.

Problem 1.3.1 At a point, true value 10. Five models trained on five samples predict 12, 12.5, 11.5, 12, 12. Compute bias² and variance (use population variance).

Step 1Mean prediction m = (12+12.5+11.5+12+12)/5 = 60/5 = 12.
Step 2Bias = 12 − 10 = 2, so bias² = 4.
Step 3Deviations from 12: 0, 0.5, −0.5, 0, 0. Squares: 0, 0.25, 0.25, 0, 0. Mean = 0.5/5 = 0.1.
Answerbias² = 4, variance = 0.1. The model is stable but systematically wrong: a high-bias model.
Checknp.mean([12,12.5,11.5,12,12]) - 10 is 2.0 and np.var([12,12.5,11.5,12,12]) is 0.1. Also, total error at the point is about 4 + 0.1 + σ².
Why it mattersThe five predictions agree with each other, so adding more data will not fix them. The model family itself is wrong (too simple).

Problem 1.3.2 Expected squared error is 9. Noise σ = 2. Variance = 3. What is bias²?

Step 19 = bias² + 3 + σ², with σ² = 4.
Step 2bias² = 9 − 3 − 4 = 2.
Answerbias² = 2, so bias = 1.41. No model can beat 4 (the noise floor) on this problem.
Check2 + 3 + 4 = 9, which is the stated total.
Why it mattersThe noise floor tells you when to stop tuning. If your error is 9 and the floor is 4, there is still room; at 4.1 you are done.

How the rest of the book connects

  • Regularization raises bias a little and cuts variance a lot (Chapter 3).
  • Bagging and random forests cut variance by averaging (Chapter 6).
  • Boosting cuts bias by adding corrections (Chapter 7).
  • Adding data cuts variance but not bias.
KEY INSIGHT
The decomposition is exact only for squared error, but the idea (error = systematic part + sample-sensitivity part + noise) holds for every loss and is the best mental model for choosing what to do next.

Applications

  • Choosing tree depth, polynomial degree, k in k-NN.
  • Deciding whether to buy more data or build more features.
  • Explaining ensembles to a manager.
COMMON MISTAKE
Believing a more complex model is always more accurate. Above the sweet spot, variance grows faster than bias shrinks.

Check yourself

  1. Which term does more data reduce? Answer: variance (bias stays, if the model family is too simple).
  2. The noise term σ² can be reduced by a better model? Answer: no, it is irreducible for these features (new features can reduce it).
  3. Predictions are scattered but centred on the truth. High bias or high variance? Answer: high variance.

1.4 The Probabilistic View: MLE, MAP, Generative and Discriminative

BASIC EXPLANATION
Maximum likelihood estimation (MLE) picks the parameters that make the observed data most probable. MAP estimation also uses a prior belief about the parameters. A generative model learns how the data is produced, p(x, y), while a discriminative model learns p(y | x) directly.
INTUITION
Many "different" methods are one idea wearing different clothes. Ask: "Which parameters make the data I saw most likely?" That is maximum likelihood. Add "and I believed small parameters were more likely before I saw anything" and you get regularization.

Definitions

  • Likelihood L(θ) = P(data | θ): how probable the data is, if the parameters were θ.
  • MLE (maximum likelihood estimation): choose θ that maximizes L(θ). In practice we maximize log L (sums are easier than products) or minimize −log L.
  • MAP (maximum a posteriori): choose θ that maximizes P(θ | data) ∝ P(data | θ) · P(θ). The extra factor P(θ) is the prior.
  • Bayesian posterior: keep the whole distribution P(θ | data), not just its peak. This gives uncertainty directly (Chapters 5 and 9).

The big dictionary

Loss you minimizeSame as MLE underPrior (extra penalty)
Squared errorGaussian noise y = f(x) + ε, ε ~ N(0,σ²)Gaussian prior on weights gives L2 (ridge)
Cross-entropy / log lossBernoulli (binary) or categorical (multi-class) labelsLaplace prior gives L1 (lasso)
Absolute errorLaplace noise
Poisson deviancePoisson counts

Why squared error is Gaussian MLE. For one point, the Gaussian density is P(y|x,θ) ∝ exp(−(y − f)² / 2σ²). Taking −log gives (y − f)² / 2σ² + constant. Summing over points gives the sum of squared errors up to a constant. So minimizing squared error equals maximizing Gaussian likelihood.

Why L2 is a Gaussian prior. With prior w ~ N(0, τ²), −log P(w) = w²/2τ² + const. The MAP objective becomes Σ squared errors/2σ² + w²/2τ². Multiply by 2σ²: Σ errors² + (σ²/τ²)·w². So λ = σ²/τ². A tight prior (small τ) means a large λ. For a Laplace prior P(w) ∝ exp(−|w|/b) the penalty is |w|/b, which is L1.

Worked problems

Problem 1.4.1 A coin shows 7 heads in 10 tosses. Find the MLE of p = P(heads), then the MAP with a Beta(2,2) prior and with a Beta(10,10) prior. (For a Beta(a,b) prior the MAP is (heads + a − 1)/(n + a + b − 2).)

Step 1Likelihood p⁷(1−p)³. Log: 7 ln p + 3 ln(1−p). Derivative 7/p − 3/(1−p) = 0 gives p = 7/10 = 0.7.
Step 2Beta(2,2): (7+1)/(10+2) = 8/12 = 0.667.
Step 3Beta(10,10): (7+9)/(10+18) = 16/28 = 0.571.
AnswerMLE 0.70; MAP 0.667 (weak prior) and 0.571 (strong prior). The stronger the belief in a fair coin, the more the estimate is pulled to 0.5. The code below prints the same numbers:
heads, n_ = 7, 10
print("MLE", heads/n_)
for a, b in [(2, 2), (10, 10)]:
    print("MAP", a, b, (heads + a - 1) / (n_ + a + b - 2))

Problem 1.4.2 Data 2, 3, 4 from N(μ, 1). Find the MLE of μ and the MAP with prior μ ~ N(0, 1).

Step 1MLE of a Gaussian mean is the sample mean: 3.0.
Step 2MAP: minimize Σ(xᵢ − μ)²/2 + μ²/2. Derivative: −Σ(xᵢ − μ) + μ = 0, so Σxᵢ = (n+1)μ, μ = 9/4 = 2.25.
AnswerMLE 3.0, MAP 2.25. The prior shrinks the estimate toward 0, exactly like ridge regression shrinks weights.
CheckPut μ = 2.25 into the objective: ((2−2.25)² + (3−2.25)² + (4−2.25)² + 2.25²)/2 = (0.0625+0.5625+3.0625+5.0625)/2 = 4.375. At μ = 3 it is (1+0+1+9)/2 = 5.5. So 2.25 is lower, as it should be.
Why it matters"Shrink toward zero" is the plain-language meaning of regularization: you trust the data a bit less and your prior belief a bit more.

Generative vs discriminative

  • Discriminative models learn P(y | x) directly (logistic regression, SVM, trees, neural nets). They draw the boundary.
  • Generative models learn P(x | y) and P(y), then use Bayes' rule to get P(y | x) (naive Bayes, Gaussian mixtures, LDA). They model how the data was produced, so they can also generate samples, handle missing inputs, and work with very little data. Discriminative models usually win with more data because they spend all capacity on the boundary.

The EM algorithm (intuition)

Some models have hidden variables (which cluster did each point come from?). If we knew the hidden labels, fitting is easy. If we knew the parameters, guessing the labels is easy. Expectation-Maximization alternates: E-step guess soft labels using current parameters; M-step refit parameters using those soft labels. Each loop never lowers the likelihood. Chapter 13 builds a Gaussian mixture with EM from scratch.

Information theory in four lines

For p = (0.5, 0.5) and q = (0.9, 0.1) (log base 2):

p = np.array([.5, .5]); q = np.array([.9, .1])
H = lambda p: -(p*np.log2(p)).sum()
print("H(p)", H(p), "CE", -(p*np.log2(q)).sum(), "KL", (p*np.log2(p/q)).sum())
H(p) 1.0 CE 1.736965594166206 KL 0.7369655941662061

Believing q costs 0.74 extra bits per event. Because H(p) is fixed by the data, minimizing cross-entropy equals minimizing KL equals maximum likelihood. That is why classifiers train on log loss.

Connection to the real job

When a colleague says "L2 is just a Gaussian prior", they are showing they understand why ridge works. In interviews this unification is a strong signal. Bayesian thinking also drives A/B testing, bandits and uncertainty (Chapters 9 and 15).

Applications

  • Ridge and lasso: priors on weights.
  • Naive Bayes spam filters and Gaussian mixture segmentation: generative.
  • Variational autoencoders and language models: cross-entropy and KL everywhere.
COMMON MISTAKE
Treating the prior as cheating. Every model has a prior, even when you do not write it. L2 regularization is a prior you chose. Writing it down only makes it visible.

Check yourself

  1. Which noise model gives squared error? Answer: Gaussian.
  2. Which prior gives L1? Answer: Laplace.
  3. In the coin example, what happens to MAP as n grows large? Answer: data dominates the prior and MAP approaches the MLE.

1.5 Loss Functions: What Each One Rewards

BASIC EXPLANATION
A loss function is a number that measures how wrong a prediction is, and training tries to make it small. Different losses (squared error, absolute error, log loss, hinge) penalize mistakes differently, so the choice changes what the model learns.
INTUITION
The loss is the grading rubric. A teacher who penalizes big mistakes heavily creates a student who plays safe; a teacher who counts every mistake equally creates a different student. Choose the rubric that matches the cost in your business.

See the Math PDF, Pillar 5, for the formulas and their derivatives. This section shows what each loss rewards, with numbers.

Problem 1.5.2 You forecast weekly demand for a shop's stock. Running out of stock (under-stocking) is 9 times worse than having too much (over-stocking). Which quantile loss, and what does it cost for y=100?

Step 1Cost ratio 9:1 means q = 9/(9+1) = 0.9 (under-prediction cost weight q, over-prediction weight 1−q).
Step 2Predict 80 (under by 20): 0.9 × 20 = 18. Predict 120 (over by 20): 0.1 × 20 = 2.
AnswerUse the 0.9 quantile (pinball) loss. Under-predicting by 20 costs 18; over-predicting by 20 costs 2. The model learns to predict high, as the business wants.
CheckRatio of costs 18 / 2 = 9, which equals the stated 9-to-1 business cost.
Why it mattersA forecast that is right on average is useless for stock planning. You want a forecast that is high enough 90 percent of the time.

Loss versus metric

You train on a smooth, differentiable loss because optimizers need gradients. You report a metric the business understands (accuracy, F1, AUC, MAPE). They can disagree. Example: log loss rewards honest probabilities, while accuracy only cares which side of 0.5. A model can improve log loss while accuracy stays the same, or the reverse. Always evaluate on the business metric, and choose the loss that is the best differentiable stand-in for it.

Connection to the real job

Choosing the loss is a business conversation: "Is a miss worse than a false alarm?" Quantile loss for stock planning and Tweedie loss for insurance claims are everyday examples.

Applications

  • Forecasting with Poisson loss for ticket counts.
  • Pinball loss for 90th-percentile delivery-time prediction.
  • Focal loss for rare-defect detection.
COMMON MISTAKE
Using MSE on heavy-tailed data (revenue, delivery times) and being surprised that a few outliers rule the model. Try MAE, Huber, or model log(y).

Check yourself

  1. MSE is minimized by which statistic? Answer: the mean.
  2. Which quantile for "missing is 4 times worse than over-estimating"? Answer: q = 4/5 = 0.8.
  3. Why differentiable losses for training but business metrics for reporting? Answer: optimizers need gradients; stakeholders need meaning.

1.6 No Free Lunch, Inductive Bias, and the Curse of Dimensionality

BASIC EXPLANATION
The No Free Lunch theorem says no learning algorithm is best on every problem. Inductive bias is the set of assumptions a model uses to generalize beyond its data. The curse of dimensionality is the problem that data becomes sparse and distances less useful as the number of features grows.
INTUITION
Every model is a set of assumptions in disguise. A linear model assumes "the effect is a straight line". A tree assumes "the world splits into boxes". A k-NN assumes "close points behave alike". If your world matches the assumption, learning is easy.

No free lunch

The No Free Lunch theorem says: averaged over all possible problems, no algorithm beats any other. So there is no "best algorithm". Real problems are not random; they have structure (smooth, sparse, tabular). The task is to match assumptions to the structure, and the way to find out is to run baselines and experiments.

Curse of dimensionality

As the number of features d grows, space gets huge and data gets sparse; distances lose meaning. Experiment: 500 random points in the unit cube, one random query point, ratio nearest distance / farthest distance.

for dim in [2, 10, 100, 1000]:
    X = rng.uniform(size=(500, dim)); q = rng.uniform(size=dim)
    ds = np.linalg.norm(X - q, axis=1); print(dim, round(ds.min()/ds.max(), 3))
2 0.011
10 0.25
100 0.703
1000 0.907

In 2 dimensions the nearest point is about 100 times closer than the farthest. In 1,000 dimensions it is only 10 percent closer: all points look equally far. "Nearest neighbour" then means little. The remedy: fewer, better features; regularization; dimensionality reduction (Chapter 13).

Problem 1.6.1 You need 10 samples per unit along each axis to cover space. How many points for 1, 2, 5 and 10 features?

Step 1Points needed = 10^d.
Step 2d=1: 10. d=2: 100. d=5: 100,000. d=10: 10,000,000,000.
AnswerData needs grow exponentially. Ten features at this density need ten billion rows, so real models rely on assumptions (inductive bias), not coverage.
Check10**10 = 10,000,000,000.
Why it mattersThis is why "just add more columns" quietly makes learning harder: the same number of rows now covers a vanishing fraction of the space.

Problem 1.6.2 A survey dataset has 200 rows (patients) and 400 columns (measurements per patient). Which kind of model is safer first, and why?

Step 1p = 400 > n = 200: a flexible model can memorize.
Step 2A regularized linear model has strong bias and low variance.
AnswerStart with ridge or lasso logistic/linear regression, and compare to a trivial baseline using repeated cross-validation.
CheckWith 400 columns and 200 rows, ordinary least squares has no unique solution at all (the matrix XᵀX is singular), which is another sign you need regularization.
Why it mattersWhen you have more columns than rows, the model needs a strong assumption to pick one answer out of infinitely many.

Connection to the real job

"Why did adding 50 features make my model worse?" is the curse of dimensionality plus variance. "Which model should I use?" is answered with inductive bias plus experiments, never with a favourite algorithm.

Applications

  • Choosing models for tabular, text, and image problems.
  • Feature selection in genomics (p ≫ n).
  • Nearest-neighbour search in embeddings (needs approximate search because of this effect).
COMMON MISTAKE
Adding every column "because more information cannot hurt". With limited data, noise columns hurt.

Check yourself

  1. What does No Free Lunch imply for practice? Answer: always run baselines; no algorithm wins everywhere.
  2. In very high dimensions, what happens to nearest vs farthest distances? Answer: they become almost equal.
  3. What is inductive bias? Answer: the assumptions a model makes that let it generalize.

Chapter recap

  • Learning means turning knobs to reduce a loss, but what matters is the loss on new data.
  • ERM = model family + loss + optimizer; empirical risk is the average loss on your sample.
  • Parameters are learned; hyperparameters are chosen by you; capacity is the richness of the family.
  • Train fits, validation chooses, test judges once. Random splits need i.i.d.; time, groups and drift break it.
  • Overfitting: tiny training error, large test error. Learning curves tell you whether to add data or change the model.
  • Error = bias² + variance + noise for squared error. Complex models trade bias for variance.
  • Squared error is Gaussian MLE; cross-entropy is Bernoulli MLE; L2 is a Gaussian prior; L1 is a Laplace prior.
  • Generative models learn how data is produced; discriminative models learn the boundary. EM alternates soft labels and refitting.
  • MSE rewards the mean, MAE the median, pinball loss a chosen percentile. Pick the loss to match business cost.
  • No model is best everywhere, and high dimensions make distances meaningless.

  10. (interview) Explain bias-variance to a manager in 30 seconds. Answer: "Bias is when the model is too simple and misses the pattern. Variance is when the model is so flexible it follows noise and changes with every new sample. We pick the complexity where the total error on new data is lowest, and validation data tells us where that is."
  11. (interview) Why is L2 regularization a Gaussian prior? Answer: MAP adds −log P(w). For a Gaussian prior this is w²/2τ², an L2 penalty with λ = σ²/τ². A tighter belief means a bigger λ.
