You trained a model and the score is disappointing. Or it looks great and you do not trust it. What do you do next? Most beginners start changing hyperparameters at random. A professional does something different: first checks that the pipeline is not lying, then reads the mistakes, then fixes the largest cause. A good doctor does not prescribe a new medicine before reading the test results; this is the same habit. By the end of this chapter you will be able to run four sanity tests that catch broken pipelines in minutes, read learning and validation curves to decide "more data or a different model?", slice the errors to find which customers the model fails, and compare two models with a paired test instead of staring at two numbers.

Running example. A telecom company wants to predict customer churn (the customer cancels the plan). We use a synthetic dataset of 4,000 customers (fixed seed 0) with columns tenure (months), spend (monthly bill), calls (support calls last month), plan (basic/plus/pro) and region. About 34% of customers churn. We planted one secret on purpose: customers with tenure under 12 months and 3 or more support calls churn very often. A simple linear model cannot see this "new and angry" group. Your task is to find it using only the tools in this chapter. All code uses numpy, pandas, scikit-learn 1.9.1 and scipy; every output below was really produced. Metrics (accuracy, ROC-AUC, log loss) and validation ideas come from Chapters 1 and 4; Math PDF Pillar 5 covers loss functions.

10.1 Sanity Tests: Is the Pipeline Even Honest?

INTUITION
Before you tune an engine, check the car has an engine. Before you debug a smart model, run tests so cheap that a failure means a bug in your pipeline, not a weakness of the model. A shop owner first checks that one sale rings up correctly at the till before opening the doors to 1,000 customers. Same idea.

Words you need

WordMeaning
BaselineA trivial model (for example "always predict the most common class") that any real model must beat.
Target leakageA feature that secretly contains the answer, or is only known after the outcome happens.
ROC-AUCA score from 0 to 1 for how well the model ranks positives above negatives. 0.5 is a coin flip.
Feature importanceA number saying how much the model used each feature.

The four tests

  1. Trivial baseline. Train a dummy model. Your real model must beat it, or there is no signal (or a bug).
  2. Shuffle the labels. Randomly permute y in the training set and retrain. There is now nothing to learn, so the test score must fall to chance (AUC near 0.5). If it stays high, the information is leaking from somewhere else.
  3. Overfit a tiny subset. Train on 40 rows. A flexible model should reach nearly 100% training accuracy. If it cannot, the model or the training loop is broken (wrong learning rate, wrong labels, frozen features).
  4. Read the top feature. If one feature has importance near 1.0, be suspicious. Real churn is never explained by one column.
import numpy as np, pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import GradientBoostingClassifier
from sklearn.dummy import DummyClassifier
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score, roc_auc_score, log_loss
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(0)
n = 4000
tenure = rng.integers(1, 60, n); spend = rng.normal(50, 15, n).round(1)
calls = rng.poisson(1.5, n)
plan = rng.choice(['basic','plus','pro'], n, p=[.5,.3,.2])
region = rng.choice(['N','S','E','W'], n)
z = -0.2 - 0.05*tenure + 0.03*(spend-50) + 0.3*calls + (plan=='basic')*0.6
z += ((tenure < 12) & (calls >= 3)) * 2.5          # the hidden segment
y = (rng.random(n) < 1/(1+np.exp(-z))).astype(int)
flip = rng.random(n) < 0.05                          # 5% label noise
y = np.where(flip, 1-y, y)
df = pd.DataFrame(dict(tenure=tenure, spend=spend, calls=calls,
                       plan=plan, region=region, churn=y))
X = pd.get_dummies(df.drop(columns='churn'), columns=['plan','region'], dtype=float)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.3, random_state=0, stratify=y)

Before you run the next block, predict: what accuracy will a model get that always says "no churn"? (Hint: 34% churn.)

d = DummyClassifier(strategy='prior').fit(Xtr, ytr)
print("dummy acc", round(accuracy_score(yte, d.predict(Xte)), 3))
lr = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)).fit(Xtr, ytr)
gb = GradientBoostingClassifier(random_state=0).fit(Xtr, ytr)
for nm, m in [('logreg', lr), ('gboost', gb)]:
    pr = m.predict_proba(Xte)[:, 1]
    print(nm, "acc", round(accuracy_score(yte, m.predict(Xte)), 3),
          "auc", round(roc_auc_score(yte, pr), 3), "logloss", round(log_loss(yte, pr), 3))

The dummy gets 65.8% accuracy by always saying "stays". So the real models at 73% are only 7 points better in accuracy. This is the honest size of the signal: it is a hard problem, and 5% of labels were flipped on purpose, which no model can recover. Notice also that the simple logistic regression beats gradient boosting on this data. We will come back to that.

A leaky feature, caught by test 4

Imagine a careless engineer adds days_since_cancel_request, taken from the billing system. It is small for churners (they asked to cancel) and large for others. This is information from the future, not available when we need to predict.

A test AUC of 1.000 on a churn problem is not a triumph, it is an alarm. One feature has importance 1.0. You would ask: "Is this value known at the moment of prediction?" The answer is no, so remove it.

Problem 10.1.1 A fraud model scores AUC 0.97 on validation. You shuffle the training labels and retrain; the validation AUC is 0.91. What do you conclude?

FormulaA model trained on shuffled labels has nothing to learn; expected AUC is about 0.5.
Plug inObserved 0.91 versus expected 0.5.
ComputeThe gap above chance is 0.91 − 0.50 = 0.41.
AnswerInformation reaches the model without passing through the training labels. Typical causes: the validation rows are duplicates of training rows, or a feature was computed using the labels (for example, target encoding fit on all data).
CheckA clean pipeline would return roughly 0.5 ± 0.03.
Why it mattersThis test finds leakage that no amount of staring at the model would reveal.

Problem 10.1.2 A churn model gets accuracy 90% on a dataset where 92% of customers stay. Is it good?

FormulaBaseline accuracy = share of the majority class.
Plug inAlways predicting "stays" gives 92%.
Compute90% − 92% = −2 points.
AnswerThe model is worse than a model that never thinks, so it is not good yet. We would look at recall and PR-AUC instead (Chapter 12 returns to this).
CheckIf 920 of 1,000 stay, "always stays" is right 920 times, which is 92%.

The picture

Sanity ladder (run top to bottom, stop at the first failure)
  [dummy baseline]   model must beat it            -> no? signal or bug
  [shuffle labels]   score must fall to chance     -> no? leakage
  [tiny overfit]     train score must hit ~100%    -> no? broken training
  [top features]     none should dominate at 1.0   -> yes? leakage
  then and only then: tune, engineer features, compare models

Connection to the real job

In a team this ladder is a small script that runs in the CI pipeline after every change. A junior who runs it before asking "why is my model bad?" saves a senior's afternoon.

Applications

  • Data Science: reject suspiciously perfect scores before they reach a slide deck.
  • MLOps: run the shuffle test as an automated check in the training pipeline.
  • Fraud and credit: leakage is the most common cause of a model that works offline and fails live.
  • Deep Learning: "overfit one batch" is the first debugging step for a neural network.
COMMON MISTAKE
Celebrating AUC above 0.95 on a business problem. Real-world noisy outcomes rarely allow it. Treat it as a bug until proven otherwise.
COMMON MISTAKE
Running the shuffle test on the test labels too. Shuffle only the training labels; keep the test labels real, because you are testing what the model learned.

Check yourself

  1. A model trained on 40 rows cannot reach high training accuracy. Is this overfitting? Answer: No. Something is broken (training loop, labels, learning rate) or the model is too weak; overfitting means the training score is high.
  2. What AUC should the shuffled-label test give? Answer: About 0.5.
  3. Why is a feature importance of 1.0 suspicious? Answer: Real outcomes depend on many causes; one feature explaining everything usually means it contains the answer (leakage).

10.2 Learning Curves and Validation Curves: Diagnosis by Picture

INTUITION
A doctor does not guess; she measures and reads a chart. A learning curve is the model's health chart: it answers "if I collect more data, will the model improve?" A validation curve answers "is my model too simple or too flexible?" It is like plotting a student's exam marks against hours studied to see where extra hours stop helping.

Chapter 1 introduced the generalization gap (training score minus validation score). Here we use it as a tool.

Definitions

  • Learning curve: train the model on 10%, 25%, 50%... of the data; at each size plot the training score and the cross-validation score. (Cross-validation, "CV": split into k parts, train on k−1, test on the rest, repeat.)
  • Validation curve: keep the data size fixed; change ONE hyperparameter (for example tree depth) and plot training and validation scores.

How to read them:

What you seeDiagnosisWhat to try
Both curves low and close togetherHigh bias (underfitting): model too simpleMore features, more flexible model
Training high, validation much lower, gap shrinking as data growsHigh variance (overfitting)More data, regularization, simpler model
Validation curve still rising at the right endMore data will helpCollect data
Validation curve flat at the right endMore data will not helpChange the model or features

The training score climbs from 0.748 to 0.999 as the trees get deeper, but the validation score falls from 0.733 to 0.676. The best depth is the shallowest one (1 or 2). On a noisy problem, flexibility only memorises noise. A depth-8 model "knows" the training set perfectly (0.999) and is the worst on new data.

Residual plots and calibration plots

For regression, plot the residual (actual minus predicted) against the prediction or against a feature. Random scatter around zero is healthy; a curve means missing non-linearity (Chapter 2); a funnel shape means the error grows with the size (heteroscedasticity). For classification, a calibration plot compares predicted probabilities with real frequencies (Chapter 4 touches on this; a later chapter goes deeper). All of them do the same job: show systematic error as a visible pattern.

Connection to the real job

Before any request for "more data" or "more compute", show the learning curve. It turns a budget argument into a picture.

Applications

  • Data Science: justify labeling budgets; stop collecting data when the curve is flat.
  • Machine Learning: choose regularization strength with the validation curve.
  • Deep Learning: the same plot with epochs on the x-axis shows when to stop training.
  • Forecasting: residual-versus-time plots reveal drift and seasonality that the model missed.
COMMON MISTAKE
Plotting only the training curve. It always goes up and tells you nothing. You need training and validation together.
COMMON MISTAKE
Reading tiny wiggles. Learning curves from 5-fold CV have noise (the boosting validation standard deviation across folds is about 0.015). Differences smaller than that are not real.

Check yourself

  1. Training 0.99, validation 0.70. Bias or variance? Answer: Variance (overfitting).
  2. Training 0.65, validation 0.64. Bias or variance? Answer: Bias (underfitting).
  3. Both curves flat at the right end. Will 10x more data help? Answer: No, change the model or the features.

10.3 Error Analysis: Read the Mistakes

INTUITION
A teacher marks an exam and then asks: "Which questions did the whole class miss?" Averages hide that. If 40 students all fail question 7, the lesson plan has a hole. Error analysis is the same: group the model's mistakes and find the pattern. Andrew Ng's rule is "look at the worst mistakes by hand, cluster them, fix the biggest cluster first". This beats blind tuning.

The method (four steps)

  1. Score every example by its individual loss (log loss per row for classifiers, absolute error for regression).
  2. Read the worst ones by hand: 30 to 50 rows. Write down a cause for each.
  3. Slice: compute the metric for each segment (tenure bucket, plan, region, new/old customers). A slice with a clearly worse score is a clue.
  4. Fix the biggest cluster and measure again with the same CV folds.

Per-row log loss for a true label y and predicted probability p is loss = −(y·ln(p) + (1−y)·ln(1−p)). If the customer churned (y = 1) and the model said p = 0.04, loss = −ln(0.04) = 3.22. A confident wrong answer costs a lot.

Confusion matrix and worst rows

Read the matrix: rows are the truth (0 = stayed, 1 = churned), columns are the prediction. There are 709 true "stays" predicted right, 81 false alarms, 240 churners we missed, and 170 churners we caught. Recall for churners is 170 / (170 + 240) = 0.41. We miss 59% of churners.

Read the worst rows: they are long-tenure, low-call customers who churned anyway. The model correctly thinks they are safe, and they left. Is this a bug? No. These are mostly the 5% of labels we randomly flipped, plus honest bad luck. Lesson: the worst-loss rows are often label noise, not model errors. If the worst 60 rows had a pattern (all from one region, say), we would investigate. Here the pattern is "very safe customers who left", which looks like noise, so we stop looking there. This is why you also slice.

Problem 10.3.2 Fix it and measure. We add one feature, new_calls = 1 if tenure < 12 and calls >= 3, a hand-made interaction (Chapter 2 introduced interaction terms).

from sklearn.model_selection import RepeatedStratifiedKFold, cross_val_score

Other things to look at

  • Label-noise inspection: rows where the model is very confident and the label disagrees. Here only 2 of 1,200 rows have p < 0.05 and y = 1. Open them and check whether the label is wrong. Tools such as cleanlab automate this (confident learning); not run here.
  • Confusion analysis for many classes: print the confusion matrix and find the biggest off-diagonal cell; those two classes need clearer features or labels.
  • Hardest examples versus ambiguous examples: if two human labelers disagree on a row, no model can be right.
  • Distribution shift: if errors cluster in the latest month, your data has drifted. The three types are covariate shift (inputs change), label shift (class balance changes), and concept drift (the rule x → y changes). Chapter 12 shows how to detect them.

Weekly "error review" meetings at strong ML teams are exactly this: 30 minutes, a table of worst rows, a decision about the next fix. It replaces guessing.

Applications

  • Machine Learning: discovering missing features and segments.
  • Data Analytics: finding which customers a dashboard metric hides.
  • Fairness work: slicing by group (region, age band) to catch worse performance on one group.
  • GenAI: reading the worst 50 chatbot answers and tagging causes is the same method.

Taking the highest-loss rows as the problem. In noisy data, they are often label noise. Check whether they have a pattern before you chase them.
COMMON MISTAKE

Check yourself

  1. Overall accuracy is 73%, but one slice has 40% accuracy and 3% of the data. Is the model fine? Answer: Not necessarily; the slice may matter more than its size suggests. Investigate its business value.
  2. Why can the highest-loss rows mislead? Answer: They are often label errors or irreducible noise.
  3. What is log loss for y = 1, p = 0.5? Answer: −ln(0.5) = 0.693.

10.4 Comparing Models Properly

INTUITION
Two runners finish a race in 12.1 s and 12.3 s on one day. Is the first faster? Not necessarily; on a different day the order may flip. To know, you must race many times under the same conditions and look at the typical difference. Comparing models is the same: one number each is a single race.

Rules

  1. Same folds for every model. Use the same split object (same seed), so each model sees the same train and test rows. Then the scores are paired: fold 1 of model A is compared to fold 1 of model B.
  2. Compare the differences, not the two averages. Compute d_i = score_A,i − score_B,i for each fold, then look at mean and spread of d.
  3. Use a test, but know its limits. The paired t-test on CV folds is the common choice. Its caveat: folds share training data, so the scores are not independent and the test is too optimistic (p-values too small). The Nadeau-Bengio correction inflates the variance: var_corrected = var(d) × (1/k + n_test/n_train), where k is the number of scores.
  4. McNemar's test compares two classifiers on the same test rows by looking only at the rows where exactly one is right.
  5. Bootstrap: resample the test set many times and compute the difference each time; the 2.5th and 97.5th percentiles give a 95% interval.
  6. Prefer the simpler model if the difference is within noise. It is cheaper, faster, easier to explain.
  7. Offline is not online. An offline win must be confirmed with an A/B test.

Real data: three models, 10 paired scores

Problem 10.4.2 Apply the Nadeau-Bengio correction.

Step 1k = 10, n_test = 800 (one fifth of 4,000), n_train = 3,200. So 1/k + n_test/n_train = 0.1 + 0.25 = 0.35.
Step 2Corrected variance = var(d) × 0.35, with var(d) = 0.0101² = 0.000102. So the variance is 0.0000357, and its square root is 0.00598.
Step 3Corrected t = −0.0134 / 0.00598 = −2.24 (code: −2.25; rounding).
AnswerCorrected p = 0.051. The naive test said "very significant" (p = 0.002); the honest test says "borderline". Always prefer the corrected version for CV scores.
CheckThe corrected standard error 0.00598 is bigger than the naive 0.00319 by a factor √(0.35 × 10) = 1.87. The t shrinks by the same factor: 4.21 / 1.87 = 2.25. Good.
Why it mattersNaive CV t-tests produce false "wins", which cost companies real money when a worse model ships.

McNemar's test and the bootstrap on the hold-out set

pa = gb.predict(Xte) == yte; pb = lr.predict(Xte) == yte
b = int((pa & ~pb).sum()); c = int((~pa & pb).sum())
stat = (abs(b - c) - 1)**2 / (b + c)
print("b", b, "c", c, "mcnemar", round(stat, 3), "p", round(stats.chi2.sf(stat, 1), 4))
rb = np.random.default_rng(0); ds = []
pg = gb.predict_proba(Xte)[:, 1]; pl = lr.predict_proba(Xte)[:, 1]
for _ in range(1000):
    i = rb.integers(0, len(yte), len(yte))
    ds.append(roc_auc_score(yte[i], pg[i]) - roc_auc_score(yte[i], pl[i]))
print("boot diff", np.mean(ds).round(4), np.percentile(ds, [2.5, 97.5]).round(4))
b 51 c 64
mcnemar 1.252 p 0.2631
boot diff -0.0216 [-0.034 -0.008]

Here b = 51 rows were right for boosting and wrong for logistic regression, and c = 64 rows the reverse. The test statistic is (|b − c| − 1)² / (b + c) = (13 − 1)² / 115 = 144 / 115 = 1.252, p = 0.26. On accuracy, the two models are not distinguishable on this test set: the models disagree on only 115 rows, and the split is 51 versus 64. Yet the bootstrap on AUC says boosting is lower by 0.022 with a 95% interval of [−0.034, −0.008], which excludes zero. Why do the two tests disagree? They measure different things: McNemar looks at accuracy at a 0.5 threshold, the bootstrap at ranking quality (AUC). Pick the metric that matches the business decision first, then test that metric.

The decision

  • Logistic regression has AUC 0.741, boosting 0.728. After the correction, the difference is borderline; the bootstrap says logistic regression is better.
  • Logistic regression is simpler, faster and explainable.
  • Decision: ship logistic regression (with the new_calls feature from 10.3), run an A/B test, and keep boosting as a challenger. A flexible model does not always win; on small noisy tabular data, it often does not.

Check yourself

  1. Why do we pair folds? Answer: Fold difficulty affects both models equally; pairing cancels it and makes the comparison more sensitive.
  2. Why correct the CV t-test? Answer: Folds share training data, so scores are correlated and the naive variance is too small.
  3. Two models are within noise. Which do you ship? Answer: The simpler, cheaper one.

Chapter recap

  • First check the pipeline: dummy baseline, shuffled labels (score must fall to chance), tiny-subset overfit, and suspicious top features.
  • AUC near 1.0 on a messy business problem is a leakage alarm, not a celebration.
  • Learning curves tell you if more data helps (rising validation curve, big gap) or not (flat, small gap means high bias).
  • Validation curves show where flexibility turns into memorising: training rose to 0.999 while validation fell to 0.676.
  • Error analysis: score each row, read the worst 30 to 50, slice by segment, fix the biggest systematic cluster first.
  • The worst-loss rows are often label noise; slices find fixable problems that averages hide (a 3.4% segment under-predicted by 22 points).
  • Compare models on identical folds, using paired differences; correct the CV t-test; use McNemar or bootstrap on a hold-out; choose the metric first.
  • If differences are within noise, ship the simpler model, then confirm with an online A/B test.

Practice set

Problem 10.P.1 (easy) 1,000 emails, 950 are not spam. What accuracy does "always not spam" get?

Answer: 950 / 1000 = 95%. Any real spam model must beat that (and we should look at recall).

Problem 10.P.2 (easy) Per-row log loss for y = 0 and p = 0.9?

Answer: −(0·ln 0.9 + 1·ln(0.1)) = −ln(0.1) = 2.303.

Problem 10.P.3 (easy) After shuffling training labels, your validation AUC is 0.52. Healthy or not?

Answer: Healthy; it is near the 0.5 chance level.

Problem 10.P.4 (what is the output?) Fold scores for A are [0.80, 0.82, 0.78, 0.84], for B [0.79, 0.80, 0.77, 0.82]. What is mean(d)?

Answer: d = [0.01, 0.02, 0.01, 0.02]; mean = 0.015.

Problem 10.P.5 (medium) For the d in 10.P.4, compute the paired t statistic.

Answer: mean = 0.015. Deviations: −0.005, 0.005, −0.005, 0.005; squares sum 0.0001; sample variance = 0.0001 / 3 = 0.0000333; sd = 0.005774. SE = 0.005774 / √4 = 0.002887. t = 0.015 / 0.002887 = 5.20 (3 degrees of freedom, p about 0.014). With only 4 folds and the correction factor, it would be much weaker; be careful.

Problem 10.P.6 (find the bug) train_test_split is called with a different random_state for each model, and the results are compared. What is wrong?

Answer: Each model sees a different test set, so differences may come from split luck. Use one split (or one CV object) for all models.

Problem 10.P.7 (medium) Training AUC 0.98, validation 0.76, and the gap barely changes from 50% to 100% of the data. What do you try?

Answer: High variance that more data does not fix at this scale. Try regularization, shallower trees, fewer features, or stronger early stopping; and look for leakage differences between train and validation.

Problem 10.P.8 (scenario) Overall accuracy is 91%. Slice by device: mobile 94% (80% of rows), desktop 70% (20% of rows). Check the overall number.

Answer: 0.8 × 94 + 0.2 × 70 = 75.2 + 14 = 89.2%, not 91%. So the stated numbers are inconsistent: someone made an arithmetic or slicing error, which is itself a finding. Weighted slice metrics must reproduce the overall number.

Problem 10.P.9 (interview) "How would you debug a model that works offline and fails in production?"

Answer: Check training-serving skew (different feature code paths), leakage (features not available at prediction time), distribution shift between training period and live data, and data pipeline bugs such as units or missing values. Compare feature distributions between training and logged serving data, and slice errors by time.

Problem 10.P.10 (interview) "Your new model has +0.4% AUC over the old one in CV. Do you deploy?"

Answer: Not on that alone. I would pair the folds, compute a corrected interval, check the gain on important slices, consider latency and maintenance, and run an A/B test. If the interval includes zero, I keep the simpler one.
