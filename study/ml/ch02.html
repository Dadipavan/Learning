Suppose you have delivery records and you want to say "each extra 10 km adds about 6 minutes to the delivery time". Or you have patient data and you want to predict disease progression. The oldest and most useful tool for both jobs is linear regression: draw the best flat surface through your data. Many production systems still use it, and every neural network is built from stacked pieces that look like it. In this chapter you will derive the formula that finds the best line, solve it by hand on three points, rebuild it in NumPy two different ways, check your code against scikit-learn, and learn the six ways a straight-line model can quietly lie to you. You will also learn when you are predicting and when you are explaining, because the same model is read very differently in each case.

You can skip the matrix-calculus details if they feel heavy. The worked problems show every step with small numbers. For the derivative rules, see the learner's Math PDF (Pillar 2, calculus; Pillar 1, matrices).

2.1 The Model and the Normal Equation

BASIC EXPLANATION
Linear regression predicts a number as a weighted sum of the input features plus an intercept. The normal equation is a closed-form formula that gives the weights that minimize the sum of squared errors.
INTUITION
You have a cloud of dots and a stiff ruler. You lay the ruler on the dots and slide and tilt it until the total squared distance from the dots to the ruler is as small as possible. "Squared" because a big miss should hurt much more than a small miss, and because squares are smooth, so calculus works. The normal equation is the formula that tells you exactly where the ruler ends up, with no sliding needed.

Words you need

WordPlain meaning
Featureone input column (for example, distance in km)
Targetthe number we want to predict (delivery time in minutes)
Weight (coefficient)how much the prediction changes when one feature goes up by 1, others fixed
Interceptthe prediction when every feature is 0
Residualactual value minus predicted value: rᵢ = yᵢ − ŷᵢ
Design matrix Xthe table of features, one row per example, with a column of 1s added for the intercept

Formal definition

The model: ŷ = w₀ + w₁x₁ + w₂x₂ + … + w_p x_p. In matrix form, with X of shape n × (p+1) (first column all ones) and w a vector of p+1 numbers:

ŷ = X w
loss(w) = Σ (yᵢ − ŷᵢ)²  =  (y − Xw)ᵀ (y − Xw)

Derivation of the normal equation. Expand the loss:

loss = yᵀy − 2 wᵀXᵀy + wᵀXᵀX w

Take the derivative with respect to w (using d(wᵀa)/dw = a and d(wᵀAw)/dw = 2Aw for symmetric A):

d loss / dw = −2 Xᵀy + 2 XᵀX w

Set it to zero: XᵀX w = Xᵀy. These are called the normal equations ("normal" means perpendicular, you will see why below). If XᵀX can be inverted:

w = (XᵀX)⁻¹ Xᵀ y

The loss is a bowl (it is convex), so the one point where the slope is zero is the unique bottom of the bowl.

Running example (tiny)

Three points: (x, y) = (1, 2), (2, 3), (3, 5). We will reuse this example throughout the chapter.

Problem 2.1.1 Find the best-fit line ŷ = w₀ + w₁x for these three points using the normal equation.

Formulaw = (XᵀX)⁻¹ Xᵀy, with X = [[1,1],[1,2],[1,3]] and y = [2,3,5].
Plug inXᵀX multiplies the 2×3 matrix [[1,1,1],[1,2,3]] by the 3×2 matrix X. Entry by entry: top-left 1+1+1 = 3; top-right 1·1+1·2+1·3 = 6; bottom-right 1+4+9 = 14. So XᵀX = [[3,6],[6,14]]. Next Xᵀy: top 2+3+5 = 10; bottom 1·2+2·3+3·5 = 23. So Xᵀy = [10, 23].
ComputeThe determinant of XᵀX is 3·14 − 6·6 = 42 − 36 = 6. The inverse of a 2×2 matrix [[a,b],[c,d]] is (1/det)[[d,−b],[−c,a]], so (XᵀX)⁻¹ = (1/6)[[14,−6],[−6,3]]. Then w = (1/6)[14·10 − 6·23, −6·10 + 3·23] = (1/6)[140 − 138, −60 + 69] = (1/6)[2, 9] = [0.3333, 1.5].
AnswerThe best line is ŷ = 0.333 + 1.5x. Each extra unit of x adds 1.5 to the prediction.
CheckRun in NumPy (below). Also by the shortcut for one feature, slope = Σ(x−x̄)(y−ȳ) / Σ(x−x̄)² = 3/2 = 1.5 and intercept ȳ − slope·x̄ = 3.333 − 1.5·2 = 0.333.
Why it mattersYou have solved a "machine learning problem" with plain arithmetic. For millions of rows, the library does exactly these steps.
import numpy as np
x = np.array([1, 2, 3.]); y = np.array([2, 3, 5.])
X = np.c_[np.ones(3), x]
print("XtX\n", X.T @ X, "\nXty", X.T @ y)
beta = np.linalg.solve(X.T @ X, X.T @ y); print("beta", beta)
res = y - X @ beta; print("resid", res, "X^T resid", X.T @ res)

Line by line: np.c_[np.ones(3), x] glues a column of ones next to x, which gives the intercept its own column. np.linalg.solve(A, b) solves A w = b; it is more accurate than computing the inverse yourself, so prefer it. The last line prints zeros: this is the key to the geometry.

The picture: projection

The grey dashed lines are the residuals: +0.167, −0.333, +0.167. The line cuts through the middle, with two points above and one below. The sum of the residuals is zero, and the residuals are also perpendicular to the x column (Σ rᵢxᵢ = 0.167 − 0.667 + 0.5 = 0).

Here is the deeper picture. Treat y = [2,3,5] as one arrow in 3-dimensional space (one axis per data point). The columns of X, namely [1,1,1] and [1,2,3], span a flat sheet (a plane) inside that space. Every possible set of predictions Xw lies on this sheet. Least squares finds the point on the sheet closest to y. The closest point is the projection of y onto the sheet, and the leftover arrow (the residual) is perpendicular to the sheet. That is why Xᵀ r = 0: "perpendicular to every column". The word "normal" in "normal equation" just means perpendicular.

        y  (the data arrow)
       /|
      / | residual r  (perpendicular to the sheet)
     /  |
 ---o---+----------- sheet = all predictions Xw
   ŷ = X w  (the projection)

The matrix H = X(XᵀX)⁻¹Xᵀ is called the hat matrix because ŷ = H y ("puts the hat on y"). Its diagonal entries are the leverage of each point: how strongly each point pulls the line toward itself. For our three points the leverages are [0.833, 0.333, 0.833]. The outer points have more pull, which is intuitive (they are the ends of a seesaw). Leverages always add up to the number of parameters, here 0.833 + 0.333 + 0.833 = 2.

A realistic dataset

Scikit-learn ships a small medical dataset (load_diabetes): 442 patients, 10 columns (age, sex, bmi, blood pressure, six blood-serum measurements s1 to s6), and a target that measures disease progression one year later. We split 75 percent train and 25 percent test with random_state=0. We will predict on the test part only for honesty (Chapter 1).

Connection to the real job

  • LinearRegression().fit(X, y) solves a version of the normal equations (internally with a numerically safer method called SVD or QR decomposition, which gives the same answer).
  • Cost estimation, demand forecasting, and A/B-test "regression adjustment" (CUPED) all use this.
  • Baselines: always fit a linear model first. If a complex model cannot beat it clearly, the complexity is not paying for itself.

Applications

  • Data Analytics: trend lines in dashboards, price elasticity.
  • Data Science: sales and demand baselines, feature effect estimates.
  • Machine Learning: the baseline every other regressor is compared with.
  • Operations and Logistics: parcels packed per hour vs staff on shift; delivery time vs distance.
COMMON MISTAKE
Forgetting the column of ones. Without it, the line is forced through the origin, which is almost never what you want. Scikit-learn adds the intercept for you; in NumPy you must do it yourself.

Check yourself

  1. What does Xᵀ r = 0 say in words? Answer: the residuals are perpendicular to every feature column; the fit has used up all the straight-line signal.
  2. For the three points, what is the sum of the residuals? Answer: 0.167 − 0.333 + 0.167 = 0.
  3. Why can the formula fail? Answer: when XᵀX has no inverse, for example when one column is a copy or a combination of other columns, or when there are more columns than rows.

2.2 Gradient Descent Version

BASIC EXPLANATION
Gradient descent is an iterative method that finds the weights by repeatedly stepping in the direction that lowers the loss. For linear regression it reaches the same answer as the normal equation and also works when the data is too large for a closed-form solution.
INTUITION
You are blindfolded on a hillside (a bowl-shaped valley) and want the bottom. You feel the slope under your feet and take a step downhill. Repeat. The step size is the learning rate. Too small: you take all day. Too big: you leap over the valley and end up higher on the other side. The normal equation is like having a map that says exactly where the bottom is. Gradient descent is walking there. Why walk if you have a map? The matrix XᵀX costs a lot to build and solve when you have millions of rows or hundreds of thousands of columns, and walking works for models (like logistic regression and neural nets) that have no map at all.

How it works

The gradient of the mean squared error L(w) = (1/n)(y − Xw)ᵀ(y − Xw) is ∇L = (2/n) Xᵀ(Xw − y). We repeat:

w ← w − lr · (2/n) · Xᵀ (X w − y)

For the one-point, one-weight case this is the rule you know from the Math PDF (Pillar 2): subtract the learning rate times the derivative.

Problem 2.2.1 Do two gradient-descent steps by hand on our three points, with weights starting at w = [0, 0] and lr = 0.1.

Formulaw ← w − lr · (2/n) · Xᵀ(Xw − y), with n = 3.
Plug in (step 1)Xw = [0,0,0], so Xw − y = [−2, −3, −5]. Then Xᵀ(Xw − y): first entry −2−3−5 = −10; second entry 1·(−2) + 2·(−3) + 3·(−5) = −2 −6 −15 = −23. So gradient = (2/3)·[−10, −23] = [−6.667, −15.333].
Computew = [0,0] − 0.1·[−6.667, −15.333] = [0.6667, 1.5333].
Plug in (step 2)Xw = [0.6667+1.5333, 0.6667+3.0667, 0.6667+4.6] = [2.2, 3.7333, 5.2667]. Xw − y = [0.2, 0.7333, 0.2667]. Xᵀ(...): first 0.2+0.7333+0.2667 = 1.2; second 0.2 + 1.4667 + 0.8 = 2.4667. Gradient = (2/3)·[1.2, 2.4667] = [0.8, 1.6444].
Computew = [0.6667, 1.5333] − 0.1·[0.8, 1.6444] = [0.5867, 1.3689].
AnswerAfter two steps w = [0.587, 1.369]. The target is [0.333, 1.5]: the intercept moved past 0.333 on step 1 and the slope is still catching up.
CheckThe loss falls. At w = [0,0] the MSE is (4+9+25)/3 = 12.67. After step 1, Xw − y = [0.2, 0.7333, 0.2667], squares 0.04, 0.5378, 0.0711, mean 0.2163. So the loss went from 12.67 to 0.2163 in one step (NumPy confirms this and gives w = [0.5867, 1.3689] after step 2).
Why it mattersEven from the worst start, the loss collapsed in one step. Later steps are much slower. Gradient descent is fast in the beginning and slow near the end.

A from-scratch class with both methods

import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.linear_model import LinearRegression
from sklearn.model_selection import train_test_split

class MyLinearRegression:
    """OLS two ways: normal equation or gradient descent."""
    def __init__(self, method="normal", lr=0.1, steps=20000):
        self.method, self.lr, self.steps = method, lr, steps
    def fit(self, X, y):
        A = np.c_[np.ones(len(X)), X]                      # add the intercept column of ones
        if self.method == "normal":
            self.w = np.linalg.solve(A.T @ A, A.T @ y)     # solve (XtX) w = Xty
        else:
            self.w = np.zeros(A.shape[1]); n = len(y)
            for _ in range(self.steps):
                grad = 2 / n * A.T @ (A @ self.w - y)      # gradient of the mean squared error
                self.w -= self.lr * grad
        return self
    def predict(self, X):
        return np.c_[np.ones(len(X)), X] @ self.w

d = load_diabetes()
Xtr, Xte, ytr, yte = train_test_split(d.data, d.target, test_size=0.25, random_state=0)
mu, sd = Xtr.mean(0), Xtr.std(0)
Ztr, Zte = (Xtr - mu) / sd, (Xte - mu) / sd               # scale with TRAIN statistics only
rmse = lambda a, p: np.sqrt(np.mean((a - p) ** 2))
ne = MyLinearRegression("normal").fit(Ztr, ytr)
gd = MyLinearRegression("gd").fit(Ztr, ytr)
sk = LinearRegression().fit(Ztr, ytr)
print("intercepts :", round(ne.w[0], 4), round(gd.w[0], 4), round(sk.intercept_, 4))
print("max |coef diff| NE vs sklearn:", np.abs(ne.w[1:] - sk.coef_).max())
print("max |coef diff| GD vs NE     :", np.abs(gd.w - ne.w).max())
print("test RMSE  NE/GD/sklearn:", [round(rmse(yte, m.predict(Zte)), 3) for m in (ne, gd, sk)])
print("baseline (predict train mean) RMSE:", round(rmse(yte, np.full(len(yte), ytr.mean())), 3))
print("test R2:", round(1 - np.sum((yte - ne.predict(Zte))**2) / np.sum((yte - yte.mean())**2), 4))

Explain: all three methods agree to 12 decimal places, because they solve the same convex problem. The intercept 151.92 is the mean of the training target (because we centred the features). The test RMSE of 56.4 beats the baseline (always guess the average) of 70.5, so the features carry real signal. R² (the "coefficient of determination") is 1 − (model's squared error) / (squared error of guessing the mean), so 0.359 means the model removes about 36 percent of the error compared with the guess-the-mean baseline. Disease progression is hard to predict from these ten columns, and that is honest information, not a bug.

Why scaling matters: the picture

The dashed line is the best possible training error (the normal equation). The lr=0.4 line shoots up out of the chart: that step was too big, so each step overshoots the valley by more than the last.

For a bowl-shaped loss there is a speed limit. Let λ_max be the largest eigenvalue of (2/n)XᵀX. Gradient descent converges only if lr < 2/λ_max. For the standardized diabetes data λ_max = 8.28, so the limit is 2/8.28 = 0.2415. This is why 0.1 works and 0.4 explodes (the loss reached 3.9×10¹⁰ by step 10). Real values from the run:

The speed limit is about 9.4×10⁻⁷. At lr = 1.5×10⁻⁶ we got nan (overflow), at 1×10⁻⁶ the weights reached 10⁹⁰, and at 1×10⁻⁷ it was safe but after 2000 steps the MSE was still 8.7 (true noise level is 0.25) with w = [0, 0.0011, 0.0018] while the right answer is [0.005, 3.03, 0.002]. The big column forces a tiny learning rate, and then the small column barely moves. The condition number (ratio of largest to smallest eigenvalue, roughly "how stretched the bowl is") tells you this: unscaled 1074, after standardizing 1.07. For the diabetes training data (with the intercept column): 217 on the raw columns, 21 after standardizing.

KEY INSIGHT
Scaling does not change the answer of OLS, but it changes how easy gradient descent finds it. For regularized models, scaling changes the answer too (Chapter 3).

Connection to the real job

Every deep-learning training loop is this loop with more weights. If a neural network's loss is nan, the first things to check are the learning rate and the input scale: the same story you just saw.

Applications

  • Machine Learning: linear/logistic regression on huge data via SGD.
  • Deep Learning: every network trained by (variants of) this loop.
  • Data Engineering: online/streaming regression where data never fits in memory.
  • MLOps: a loss that becomes nan is a standard training-job alert.
COMMON MISTAKE
Choosing a learning rate by guessing and concluding "gradient descent does not work". Standardize the features first, start with 0.1 or smaller, and plot the loss every few steps.

Check yourself

  1. Which is cheaper for 10 million rows and 50 columns, forming XᵀX or running mini-batch gradient descent? Answer: both are possible (XᵀX is 50×50), but for 500,000 columns only gradient descent is practical.
  2. What happens when lr is above 2/λ_max? Answer: the loss grows each step and the weights overflow to nan.
  3. Does scaling features change the OLS predictions? Answer: no, only the numeric size of the coefficients and the speed of gradient descent.

2.3 Assumptions and What Breaks Them

BASIC EXPLANATION
Linear regression relies on assumptions: a linear relationship, independent errors, constant error variance, roughly normal errors, and features that are not strongly correlated. When these are violated, the predictions or the coefficient estimates can become unreliable.
INTUITION
Linear regression is like a bridge calculator: it always produces a number, even if the bridge is in a swamp. The calculator assumes certain ground conditions. If the ground is different, the number is still printed but it means less than you think. You need to know the five conditions and how to see a failure.

The assumptions

AssumptionPlain meaningHow it failsHow to detect
Linearitythe effect is a straight linecurves, thresholds, interactionsresidual vs prediction plot shows a pattern
Constant variance (homoscedasticity)the scatter is the same everywherescatter grows with the levelresidual spread by range
Independent errorsmistakes do not follow each othertime series, grouped rowsDurbin-Watson, plots over time

For prediction you need these only loosely: a model with curved residuals still predicts, just badly. For explaining (confidence intervals, p-values) the assumptions matter more, as 2.4 shows.

Heteroscedasticity: the scatter changes

Think of delivery time against distance: short trips give steady times, long trips give wildly variable times. We simulate y = 2x + noise where the noise standard deviation is 0.3·x^1.5:

x = rng.uniform(1, 10, 300); y = 2*x + rng.normal(0, 0.3*x**1.5)
A = np.c_[np.ones(300), x]; b = np.linalg.lstsq(A, y, rcond=None)[0]; r = y - A@b
print("coef", b)
for lo, hi in [(1, 4), (4, 7), (7, 10)]:
    m = (x >= lo) & (x < hi); print("x in", lo, hi, "resid std", r[m].std().round(2))
coef [-0.7546  2.1163]
x in 1 4 resid std 1.26
x in 4 7 resid std 3.6
x in 7 10 resid std 8.2

The line (slope 2.12 vs true 2) is fine, but the residual spread grows 6.5 times from left to right. Predictions for large x are far less reliable, and the single "average error" hides it. The fixes: model log(y), use weighted least squares, or use quantile regression to give intervals that widen (Chapter 9).

Correlated errors: Durbin-Watson

When rows come in time order, the error today often resembles the error yesterday. The Durbin-Watson statistic is Σ(rₜ − rₜ₋₁)² / Σ rₜ². A value near 2 means no autocorrelation; near 0 means strongly positive autocorrelation. Simulated errors eₜ = 0.8 eₜ₋₁ + noise, trend 0.05t:

DW autocorr 0.5204886597338122 DW iid 2.131133120944078

0.52 is far below 2: the errors follow each other, so the effective sample size is smaller than the row count, and standard errors are too small. Fix: use time-series models or time-aware validation (Chapter 8).

Multicollinearity and VIF

If two features move together, the model cannot tell which one deserves the credit. It splits the credit unpredictably, so coefficients become unstable (but predictions can stay fine). The variance inflation factor for feature j is VIF_j = 1/(1 − R²_j), where R²_j is how well the other features predict feature j. A rule of thumb: above 5 to 10 is worrying.

Problem 2.3.1 Feature s1 (total serum cholesterol) is predicted from the other 9 diabetes columns with R² = 0.983. Find its VIF.

FormulaVIF = 1/(1 − R²)
Plug in1/(1 − 0.983)
Compute1/0.017 = 58.8
AnswerAbout 59, which matches the computed 59.2 (the exact R² is 0.98311).
Check1 − 1/59.2 = 0.9831.
Why it mattersIn plain words: 98 percent of s1 can be rebuilt from the other columns, so its coefficient is almost arbitrary. The standard error of its coefficient is about √59 = 7.7 times larger than if it were independent.

Outliers and leverage

Two different dangers. A high-leverage point has an unusual x (far from the other x values). An outlier has an unusual y given its x. A point with both can drag the line. Ten clean points follow y ≈ 2x + 1:

clean                              [intercept 0.8237, slope 1.9997]
add a point at x=30, y=10          [intercept 10.1261, slope 0.198]   leverage 0.88
add a point at x=5.5, y=40         [intercept 3.3854, slope 1.9997]   (y-outlier in the middle)

One point at x=30 (far right, true line would give 61) crushed the slope from 2.0 to 0.2. The leverage of that point is 0.88 where the average is 2/11 = 0.18. The big y-outlier in the middle (y=40 where about 12 was expected) only shifted the intercept and left the slope alone. High-leverage points are the dangerous ones, because the line must pass close to them.

Connection to the real job

When a delivery-time regression says "each extra kilometre adds 2 minutes" but the error bars are huge for long trips, you have heteroscedasticity. When a coefficient flips sign after you add one column, suspect collinearity. When a single bulk order ten times larger than usual distorts the fit, suspect leverage.

Applications

  • Data Science: checking a baseline before building something complex.
  • Analytics: explaining why a "driver analysis" gave odd signs.
  • MLOps: residual-by-segment monitoring.
  • Finance/Insurance: heteroscedastic claims models (use log or Gamma models, Chapter 4).
COMMON MISTAKE
Reading a coefficient as "the effect of this feature" when collinear columns are present. The model can swap credit between correlated features. Always check VIF before interpreting.

Check yourself

  1. A residual plot is a funnel (narrow on left, wide on right). Name the problem. Answer: heteroscedasticity.
  2. Which is more dangerous for the slope, an outlier in the middle of x or at the far end? Answer: the far end (high leverage).
  3. VIF of 40 for a feature. What does it mean? Answer: the other features explain 97.5 percent of it (1 − 1/40), so its coefficient is unstable.

2.4 Inference vs Prediction: Reading Coefficients Honestly

BASIC EXPLANATION
Prediction aims to guess outcomes accurately for new data. Inference aims to understand how each feature relates to the outcome, using coefficients, standard errors and confidence intervals. The two goals need different checks and different care.
INTUITION
There are two different jobs. Prediction: "what will this patient's number be next year?" You only care if the guess is close on new patients. Inference (explaining): "does BMI really drive progression, and by how much?" You care about each coefficient and how sure you are. A model that is perfect for the first job can be misleading for the second.

Formal definitions

If the assumptions hold and noise has variance σ², the estimated variance of the coefficients is σ̂² (XᵀX)⁻¹, where σ̂² = Σr²/(n − p − 1) (the denominator uses the degrees of freedom: rows minus parameters, because the fit used up p+1 pieces of information). The standard error (SE) of coefficient j is the square root of the j-th diagonal entry. The t-statistic is ŵⱼ/SEⱼ. The p-value answers: "if the true coefficient were 0, how often would a t-value this large appear by chance?" A 95% confidence interval is ŵⱼ ± t* · SEⱼ, where t* (about 1.97 for 330 degrees of freedom) is read from a t-table.

Standardized coefficients

To compare the importance of features measured in different units, rescale: standardized coefficient = ŵⱼ · std(xⱼ) / std(y). It reads "if feature j goes up by one standard deviation, the target moves by this many standard deviations". For diabetes the top ones are s5 0.436, bmi 0.365, s1 −0.335, bp 0.181. Prediction mode

For prediction, ignore p-values. Judge the model on test data. Collinearity is mostly harmless there, as long as test rows look like training rows. In 2.2 we found test RMSE 56.4 vs baseline 70.5.

Connection to the real job

Interview and stakeholder questions like "which factor matters most?" need inference care: CIs, collinearity checks, and the words "associated with" rather than "causes". Prediction questions like "how accurate is it on new data?" need a test set.

  • Data Analytics: driver analysis, pricing studies.

2.5 Curves, Interactions and Interpretable Non-Linearity

BASIC EXPLANATION
Linear regression can model curves by adding transformed features such as x^2 or interaction terms like x1*x2. The model stays linear in its weights, so it is still fitted the same way and remains interpretable.
INTUITION
"Linear" in linear regression means linear in the weights, not in the raw inputs. If you feed the model x and x² as two columns, it can draw a curve and it is still solved by the same normal equation. You change the ingredients, not the recipe.

Methods

  • Polynomial features: add x², x³, …. Easy but wild at high degree (Chapter 1: degree 12 overfit).
  • Interactions: add products such as x₁·x₂, for cases where the effect of one feature depends on another.
  • Splines: cut the x-axis at points called knots and fit a smooth low-degree curve in each piece, joined smoothly. They are more stable than high-degree polynomials.
  • GAMs (generalized additive models): ŷ = f₁(x₁) + f₂(x₂) + …, each fⱼ a smooth curve learned from the data. They keep the "add up effects" readability but allow curves. Libraries: pygam, and EBM (explainable boosting machine) in interpret. Not run here; see the skill map's library list.

Worked example: curve (60 noisy points from sin(2πx))

from sklearn.preprocessing import PolynomialFeatures, SplineTransformer
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import make_pipeline
xs = np.sort(rng.uniform(0, 1, 60)); ys = np.sin(2*np.pi*xs) + rng.normal(0, .3, 60)
xt = np.linspace(0, 1, 500)[:, None]; yt_ = np.sin(2*np.pi*xt[:, 0])
for name, m in [("linear", LinearRegression()),
                ("poly3", make_pipeline(PolynomialFeatures(3), LinearRegression())),
                ("poly15", make_pipeline(PolynomialFeatures(15), LinearRegression())),
                ("spline(6 knots,deg3)", make_pipeline(SplineTransformer(n_knots=6, degree=3), LinearRegression()))]:
    m.fit(xs[:, None], ys); print(name, "test MSE vs truth", np.mean((m.predict(xt) - yt_)**2).round(4))
linear test MSE vs truth 0.1998
poly3 test MSE vs truth 0.0111
poly15 test MSE vs truth 0.0487
spline(6 knots,deg3) test MSE vs truth 0.0097

Explain: the straight line is badly biased (0.20). Degree 3 fixes that (0.011). Degree 15 overshoots (0.049, more variance). The spline is the best (0.0097) because it bends where needed without wild swings. The error is measured against the noise-free truth, so 0 would be perfect.

Worked example: interaction

Let y = x_a · x_b + noise (the effect of x_a flips sign depending on x_b). A plain linear model sees nothing:

no interaction  R2 = 0.037
with x_a*x_b    R2 = 0.960   coefficients [-0.0123 -0.0054  0.009  0.9892]

Adding one product column lifts R² from 0.04 to 0.96, and the coefficient on the product is 0.989 (true value 1). A tree-based model would find this automatically, but a linear model needs you to hand it the interaction.

Problem 2.5.1 A model for delivery time has ŷ = 20 + 0.5·km + 8·is_rush + 0.3·(km × is_rush). Predict the delivery time (minutes) for a 100 km trip outside and during rush hour.

Connection to the real job

Feature engineering (Data Science skill map) is where linear models become powerful: logs, ratios, bins, interactions, and splines. A regularized linear model with good features often competes with boosted trees on small tabular data.

Applications

  • Insurance and credit: GAMs / EBMs for regulator-friendly non-linear scoring.
  • Marketing mix: log and saturation transforms.
  • Operations and Logistics: delivery time versus orders in the queue (a spline captures the "knee" where a queue starts to build up).
  • Forecasting: seasonal features inside a linear model.
COMMON MISTAKE
Making polynomial features of degree 10 on unscaled data. The columns explode in size, the matrix becomes nearly singular, and the fit swings. Scale first, use low degree, or use splines with regularization.

Check yourself

  1. Why is y = a + b·x + c·x² still "linear regression"? Answer: it is linear in the weights a, b, c.
  2. What does an interaction term let the model do? Answer: let the effect of one feature depend on another feature.
  3. Why splines over degree-15 polynomials? Answer: they are local and stable; polynomials swing wildly at the edges.

2.6 Bayesian Linear Regression and Gaussian Processes: Predictions With Honest Error Bars

Ordinary least squares gives one line. If you only have 8 points, you know the line is uncertain, and you know it is more uncertain far from the data. Bayesian linear regression keeps the whole family of plausible lines: put a prior on the weights (a bell curve centred at zero with precision α), assume Gaussian noise with variance σ², and the posterior is again a bell curve with

S = (αI + ΦᵀΦ/σ²)⁻¹ and m = S Φᵀ y / σ²

where Φ is the design matrix. The mean m is exactly ridge regression with λ = α σ² (Chapter 3 again: the penalty is a prior). The new part is S, which tells you how uncertain each weight is and gives a predictive standard deviation at any new x: sqrt(φᵀ S φ + σ²), noise plus weight uncertainty.

import numpy as np
rng = np.random.default_rng(0)
x = np.linspace(-3, 3, 8); y = 1.0 + 2.0 * x + rng.normal(0, 1.0, 8)
Phi = np.c_[np.ones_like(x), x]; sig2, alpha = 1.0, 1.0       # noise var, prior precision
S = np.linalg.inv(alpha * np.eye(2) + Phi.T @ Phi / sig2); m = S @ Phi.T @ y / sig2
ridge = np.linalg.solve(Phi.T @ Phi + alpha * sig2 * np.eye(2), Phi.T @ y)
print("posterior mean", m.round(3), "ridge (lambda=alpha*sigma2)", ridge.round(3))
print("posterior sd", np.sqrt(np.diag(S)).round(3))
for xs in (0.0, 2.0, 6.0):
    f = np.array([1, xs]); print(f"x={xs}: pred {f@m:.2f}  sd of mean {np.sqrt(f@S@f):.2f}  predictive sd {np.sqrt(f@S@f+sig2):.2f}")
from sklearn.gaussian_process import GaussianProcessRegressor as GPR
from sklearn.gaussian_process.kernels import RBF, WhiteKernel, ConstantKernel as C
xt = np.sort(rng.uniform(-4, 4, 12)); yt = np.sin(xt) + rng.normal(0, 0.15, 12)
gp = GPR(C(1.0) * RBF(1.0) + WhiteKernel(0.1), normalize_y=True, n_restarts_optimizer=5, random_state=0).fit(xt[:, None], yt)
print(gp.kernel_)
mu, sd = gp.predict(np.array([[0.0], [2.0], [8.0]]), return_std=True)
print("mean", mu.round(2), "sd", sd.round(2))

Problem 2.6.1 From the output, explain why the predictive standard deviation grows from 1.05 at x = 0 to 1.50 at x = 6, though the noise is fixed at σ = 1.

Step 1Split the predictive variance: σ² + φᵀSφ. At x = 0 the weight part is 0.33² = 0.11, so 1 + 0.11 = 1.11, sd 1.05.
Step 2At x = 6 the weight part is 1.11² = 1.23 (the slope uncertainty 0.177 is multiplied by 6 and added to the intercept uncertainty), so variance 2.23, sd 1.49 (printed 1.50 after rounding of S).
Step 3The training x values lie in [−3, 3]. Beyond them, a small change in slope moves the line a lot, and the weight term grows with x².
AnswerThe noise part never changes; the extrapolation part does. Honest error bars flare outward.
CheckThe posterior mean (1.202, 2.091) equals the ridge solution with λ = 1, as the theory says.

Gaussian processes: a prior over curves

A Gaussian process (GP) is Bayesian linear regression with infinitely many features, and you never write them down. You choose a kernel k(x, x′) that says how similar the outputs at two inputs should be; the RBF kernel says "nearby inputs have nearby outputs, and the length scale ℓ says how near is near". Given data, the prediction at a new point is a bell curve with a mean and a standard deviation, exactly like the line above but for a flexible curve. Fitting means choosing the kernel's hyper-parameters (length scale, signal variance, noise level) by maximising the marginal likelihood, which already penalises complexity, so you do not need a separate validation set for them.

In the run above, twelve noisy points from a sine wave led the optimiser to a signal variance of 1.41², a length scale of 1.4 and a noise level of 0.032 (on the standardised scale). The predicted mean at x = 2 is 0.78 with sd 0.13, close to sin 2 = 0.91, but at x = 8, far outside the data, the sd jumps to 0.80 and the mean reverts to about 0.11, near the prior mean.

How to read it: both bands are narrow where there are dots and wide where there are none. The line's band flares linearly forever because it still believes in a straight line far away. The GP band widens until it reaches the prior's width and the mean falls back to the prior mean (the dotted line is the true sine; outside [-4, 4] the GP says "I do not know" rather than guessing). Use GPs for small data (up to a few thousand rows, since the cost is cubic in rows), expensive experiments and Bayesian optimisation (Chapter 11), where the uncertainty decides where to try next.

COMMON MISTAKE
Treating the GP band as a guarantee. It is correct only if the kernel is right. An RBF GP is very smooth; if the real process has jumps or a period, the band will be too confident. Check coverage on held-out points (about 95% of them inside the two-sd band).
COMMON MISTAKE
Running a GP on 100,000 rows. Memory grows with n² and time with n³. Use sparse or inducing-point approximations, or switch to a different model.

Check yourself

  1. What does a large length scale mean? Answer: the function changes slowly, so far-apart points are still strongly related; the fit is smoother.
  2. How is the Bayesian posterior mean related to ridge? Answer: identical when λ = α σ²; the Bayesian version also returns the covariance of the weights.
  3. Why is the GP uncertainty large at x = 8? Answer: no training points are near, so the kernel ties the prediction weakly to the data and it falls back to the prior.

Chapter recap

  • Linear regression finds weights that minimize the sum of squared residuals. The solution is w = (XᵀX)⁻¹Xᵀy.
  • The picture: ŷ is the projection of y onto the space spanned by the feature columns; the residual is perpendicular to every column (Xᵀr = 0).
  • Leverage (the diagonal of the hat matrix) tells how much each row pulls on the fit.
  • Gradient descent reaches the same answer by walking downhill. It works for models with no closed form, but needs a sensible learning rate (below 2/λ_max) and scaled features.
  • The assumptions are linearity, constant variance, independent errors, no collinearity, and no wild leverage points. Each has a simple symptom you can look for.
  • VIF above about 10 means coefficients are unstable. Predictions can still be fine.
  • For inference, use SE, CI and the word "associated". For prediction, use a test set and a baseline.
  • Linear in the weights lets you add polynomial, spline and interaction columns and still use the same solver.
  • Always compare to a trivial baseline (predict the mean). Here the model's RMSE was 56.4 vs 70.5.

  2. (easy) With ŷ = 10 + 4x, what is the residual for x=3, y=25? Answer: ŷ = 22, residual 25 − 22 = +3.
  3. (easy) What is the output? np.c_[np.ones(2), [5, 7]]. Answer: [[1., 5.], [1., 7.]].

  5. (medium) Do one gradient-descent step on those four points from w = [0,0], lr = 0.05. Answer: Xw − y = [−2,−4,−5,−9]; Xᵀ(...): [−20, −(2 + 8 + 15 + 36)] = [−20, −61]; gradient (2/4)·[−20, −61] = [−10, −30.5]; w = [0.5, 1.525].
  6. (medium) Find the bug: w = np.linalg.inv(X.T @ X) @ X.T @ y returns huge unstable numbers when two columns are duplicates. Answer: XᵀX is singular. Drop the duplicate, use lstsq/ridge, and check VIF or the condition number.
  7. (medium) A model has train RMSE 12 and test RMSE 12.5; the baseline (mean) test RMSE is 13. Is it good? Answer: There is no overfit, but the gain over the baseline is tiny (4 percent). The features carry little signal.
  8. (medium) Gradient descent prints nan after 5 steps. List two causes. Answer: learning rate too large (above 2/λ_max); unscaled features with huge values. Fix with scaling and a smaller lr.
  9. (hard, scenario) Your team's regression says each extra courier on shift adds 3 minutes to the average delivery time, but the standard error is 4 minutes. Report it. Answer: The estimate is 3 minutes with 95% CI about 3 ± 7.8 = [−4.8, 10.8]. The data cannot tell whether more couriers slow things down, speed things up, or do nothing; collect more data.
  10. (hard) Compute the leverage sum for 3 points with 2 parameters. Answer: equals 2 (the number of parameters); our values were 0.833 + 0.333 + 0.833.
  11. (interview) "What is the difference between R² and RMSE, and when would you prefer each?" Answer: RMSE is in the units of the target (minutes, rupees), so it says how far off you are. R² is unit-free and says how much better you are than guessing the mean, so it compares models on the same data but not across different datasets. Report both plus a baseline.
  12. (interview) "A coefficient changed sign when you added a feature. Why?" Answer: the new feature is correlated with the old one (collinearity) or is an omitted confounder; the coefficient measures the effect holding the others fixed, so the meaning changes with the set of features.

(medium) A Bayesian linear model has posterior sd of the slope 0.177 and of the intercept 0.333. Why does the predictive sd at x = 6 exceed that at x = 0? Answer: the slope error is multiplied by x, so it contributes 6 × 0.177 = 1.06 at x = 6 and nothing at x = 0 (the exact value, 1.11, also includes the correlation between the two weights).
