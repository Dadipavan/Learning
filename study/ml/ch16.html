A model that scores well is not yet a model you can use. A bank manager asks "why was this loan refused?". A regulator asks "does the model treat both groups fairly?". A colleague asks "will it still work if the data is a bit noisy, and can you reproduce last month's result?". This chapter gives you the tools to answer: permutation importance, partial dependence, Shapley values, surrogate models and counterfactuals for explanations; group metrics for fairness; noise, adversarial and poisoning tests for robustness; and a short list of daily habits that separate careful practitioners from careless ones. It ends with the from-scratch implementations list (the "rebuild" list that proves you understand each algorithm) and an interview bank with short model answers.

All code uses NumPy and scikit-learn with fixed seeds, and every printed output is real, from /tmp/ml_scripts/c16a.py to c16f.py. The libraries shap, lime, fairlearn, aif360, interpret and mlflow are not installed here, so any use of them is marked "not run here". 16.1 Explainability: Global Methods

INTUITION
A model is like a clerk who stamps "approved" or "rejected" on forms. You want to ask the clerk two kinds of questions. Global: "In general, which parts of the form matter most?" Local: "For this one form, why did you reject it?" This section answers the global kind.

Words you need

WordPlain meaning
Interpretable modela model whose own structure explains it (a linear model, a short tree, a rule list)
Post-hoc explanationan explanation computed after training, for any black-box model
Global explanationdescribes the model's overall behaviour
Local explanationdescribes one prediction
Surrogatea simple model trained to imitate a complex one

Built-in interpretability first

Before you explain a black box, ask whether you need one. Logistic regression coefficients (Chapter 4) are an explanation. A depth-3 tree can be printed as rules. GAMs and the EBM (Explainable Boosting Machine, not run here) add one smooth curve per feature and are almost as accurate as boosting on many tabular problems. Monotonic constraints (supported in gradient boosting libraries) force the prediction to move only one way as a feature rises, which is often a legal or common-sense requirement ("more income can never raise default risk").

The running example: loan default

We simulate 3,000 loan applicants with five columns: income, debt, age, credit_len (years of credit history), and noise_id (a random number with no meaning, like a customer ID). Important design: credit_len = age − 18 + small noise, so age and credit length are correlated at 0.988. The true risk depends on income, debt and credit length, not on age directly. Default rate is 0.449. A random forest (300 trees, min_samples_leaf=5) is trained on 2,000 rows and tested on 1,000. Test AUC = 0.831.

Impurity importance versus permutation importance

Impurity importance (also "mean decrease in impurity", Chapter 6) is what rf.feature_importances_ returns: how much each feature reduced node impurity across all trees. It is computed on the training data, so it rewards features that help the model memorize.

Permutation importance answers a different, more honest question: "if I shuffle this column, destroying its link to the target, how much worse does the score on held-out data get?" The recipe:

  1. Score the model on the test set: base.
  2. For one feature, shuffle its values across the rows; score again.
  3. Importance = base score − shuffled score. Repeat several times, average.
  4. Repeat for every feature.

Problem 16.1.1 A tiny model f(x₁, x₂) = 2·x₁ is evaluated on four rows (x₁, x₂, y): (1, 5, 2), (2, 3, 4), (3, 9, 6), (4, 1, 8). Compute the permutation importance of each feature using mean squared error (MSE).

Formulaimportance = MSE(after shuffle) − MSE(before shuffle).
Plug in (baseline)Predictions 2, 4, 6, 8 equal y, so MSE = 0.
Compute (shuffle x₁)Use the shuffled order x₁ = (3, 4, 1, 2). Predictions 6, 8, 2, 4. Errors 6−2 = 4, 8−4 = 4, 2−6 = −4, 4−8 = −4. Squares all 16. MSE = 16. Importance of x₁ = 16 − 0 = 16.
Compute (shuffle x₂)The model never reads x₂, so any shuffle leaves predictions unchanged. MSE stays 0. Importance of x₂ = 0.
Answerx₁ has importance 16 and x₂ has importance 0.
CheckThe model is 2·x₁; a feature the formula does not use must score 0, and the feature it fully depends on must score high.
Why it mattersThe number has a meaning: "the error would grow by 16 squared units if this column were scrambled".

Now the real model. We compute it by hand (20 shuffles of AUC) and with sklearn.inspection.permutation_importance:

base = roc_auc_score(y[te], rf.predict_proba(X[te])[:, 1]); prng = np.random.default_rng(1)
for j, name in enumerate(names):
    drops = []
    for r in range(20):
        Xp = X[te].copy(); Xp[:, j] = prng.permutation(Xp[:, j])
        drops.append(base - roc_auc_score(y[te], rf.predict_proba(Xp)[:, 1]))
    print(name, round(np.mean(drops), 4), round(np.std(drops), 4))
pi = permutation_importance(rf, X[te], y[te], scoring="roc_auc", n_repeats=20, random_state=1)

Problem 16.1.2 Read the table. What do the two importance methods say about noise_id?

Step 1Impurity importance gives noise_id 0.090, about half of income's 0.207. By that measure the junk column looks useful.
Step 2Permutation importance gives 0.0009 (hand) and 0.0006 (sklearn). The hand value is smaller than its own spread (0.0018), so it is zero within noise.
Step 3Why the difference? A continuous random column offers the trees many possible split points. Trees use some of those splits to fit noise in the training rows, so impurity importance credits the column. On held-out data those splits do nothing.
AnswerImpurity importance wrongly rates the junk column at 0.090. Permutation importance correctly says about 0.
CheckThe two columns of the permutation results (hand and sklearn) agree to about 0.005, which is within the repeat-to-repeat spread (0.005 to 0.010) shown, so our hand implementation is correct. They are not identical because the random shuffles differ.
Why it mattersNever present feature_importances_ from a forest as "what drives the outcome" without checking with permutation importance on held-out data. This is the bias toward high-cardinality or continuous features listed in Chapter 6.

The correlated-feature trap

Age and credit length carry almost the same information (correlation 0.988). The true risk uses credit length only. Yet permutation importance gives age 0.029 and credit length 0.039: the credit effect is shared out between the two. When we drop age and retrain, credit_len jumps from 0.039 to 0.126, and the importances of income (0.063) and debt (0.156) barely change.

Problem 16.1.3 What is the total importance of the age-credit pair, before and after dropping age, and what is the lesson?

Step 1Before: 0.029 + 0.039 = 0.068.
Step 2After dropping age: 0.126 for credit length alone, nearly double.
Step 3When a feature is shuffled, the model can still read the same information from its correlated twin, so the score falls less. Each twin looks unimportant; together they matter.
AnswerThe pair's true importance is about 0.126, but each twin shows only about a quarter to a third of it. Shuffling one twin breaks the data pattern in an impossible way (a 22-year-old with 40 years of credit) and spreads the credit among the two.
CheckRun c16a.py to see: after dropping age: credit_len 0.1258.
Why it mattersImportance of a feature is conditional on what other features the model has. Group correlated features (shuffle them together) or drop one before ranking.

Partial dependence and ICE

Partial dependence (PDP) shows the average prediction as one feature moves over a grid, with all other columns left as they are. The recipe for feature j and grid value v: set column j to v in every row of the data, predict, average. ICE (individual conditional expectation) draws the same curve for each single row instead of averaging, so you can see whether people differ.

Problem 16.1.4 A model f(x₁, x₂) = x₁·x₂ is evaluated on three rows with x₂ = 1, 2, 3. Compute the PDP of x₁ at x₁ = 0 and x₁ = 2, and the three ICE slopes.

Step 1Set x₁ = 2 in all rows: predictions 2·1, 2·2, 2·3 = 2, 4, 6. Average 4.
Step 2Set x₁ = 0: predictions 0, 0, 0. Average 0.
Step 3PDP slope = (4 − 0)/2 = 2. ICE slopes (prediction change per unit of x₁) are 1, 2, 3, one per row, because ∂f/∂x₁ = x₂.
AnswerThe PDP says "each unit of x₁ adds 2 on average". The ICE lines say that the effect is 1 for one person, 2 for another and 3 for the third.
CheckThe PDP slope 2 equals the mean of the ICE slopes (1 + 2 + 3)/3.
Why it mattersA PDP can hide heterogeneity: an average of +2 might hide a group with +3 and a group with 0.

On the loan model, the hand PDP for debt and sklearn's partial_dependence agree exactly (maximum difference 0.0):

debt grid  [ 7.3,  11.1,  14.9,  18.7,  22.5,  26.3,  30.1,  33.9]
PDP        [0.1936, 0.2002, 0.2860, 0.4236, 0.5016, 0.5832, 0.7417, 0.7654]

The curve says: average default probability climbs from 19 percent at debt 7.3 to 77 percent at debt 33.9, then flattens (the forest sees few cases beyond 34). ICE for three applicants (debt grid 5 to 40) shows different shapes: for person 1 the curve stays near 0.12 until debt 15 and then jumps to 0.45 at debt 20; for person 0 the jump comes between debt 10 and 15 (0.31 to 0.66). Same direction, different thresholds. ALE (accumulated local effects) is a variant that is safer when features are correlated, because it never evaluates the model on impossible combinations (not run here).

Surrogate models

A global surrogate is a small, readable model trained to imitate the black box's predictions (not the true labels). We fit a depth-2 tree to the forest's predicted probabilities:

surrogate R² vs RF output on test: 0.511
|--- debt <= 21.58
|   |--- credit_len <= 24.75  -> 0.45
|   |--- credit_len >  24.75  -> 0.17
|--- debt >  21.58
|   |--- credit_len <= 28.73  -> 0.76
|   |--- credit_len >  28.73  -> 0.47

R² of 0.511 means the four-rule story reproduces only about half of the forest's variation, so it is a rough summary: high debt and short credit history mean high risk. Always report the surrogate's fidelity (R²) next to its rules. The logistic regression baseline gets test AUC 0.852 on this data (the true model is linear in logit), better than the forest's 0.831, so here the honest advice is "the simple interpretable model is also the more accurate one".

Connection to the real job

Permutation importance and PDP on held-out data are the first diagnostics after fitting any tabular model (also listed in Chapter 7 for boosting). Reviewers will ask for them.

Applications

  • Credit scoring: global drivers of risk and monotonic checks.
  • Healthcare: which measurements the model relies on.
  • Model debugging: a feature with large importance but no business sense often signals leakage (Chapter 8).
  • Feature selection: drop features with zero permutation importance.
COMMON MISTAKE
Reading importance as "effect of changing the feature". Importance says how much the model uses a feature, not what would happen to a person if you changed it. Models describe correlations, not causes.

Check yourself

  1. Which importance is computed on held-out data: impurity or permutation? Answer: permutation (when you pass the test set).
  2. Why do two correlated features each look weak? Answer: the model can use either twin, so shuffling one loses little.
  3. What does a PDP average hide? Answer: differences between individuals (use ICE).

16.2 Explainability: Local Methods (Shapley values, LIME, Counterfactuals)

INTUITION
A team of three friends wins a prize of 6,000 rupees. How do you split fairly when some contributed more? Shapley's answer: imagine adding friends one by one in every possible order, and give each friend the average of the extra value they brought when they joined. SHAP uses the same idea with features as the friends and the prediction as the prize.

Shapley values from first principles

A Shapley value φᵢ is feature i's fair share of the difference between this prediction and the average prediction. Define v(S) as the model's expected output when only the features in set S are known (others are filled in from background data). Then

φᵢ = Σ over S not containing i of  [ |S|! · (M − |S| − 1)! / M! ] · ( v(S ∪ {i}) − v(S) )

where M is the number of features. Think of it as the average marginal contribution over all orderings. Properties: the contributions add up exactly (Σφᵢ = f(x) − E[f], called efficiency); a feature that never matters gets 0; symmetric features get equal shares.

Problem 16.2.1 Compute the exact Shapley values for f(x) = 2·x₁ + 3·x₂ + x₁·x₂ (feature 3 is unused) at x = (1, 1, 1), with baseline (0, 0, 0) meaning "feature absent".

Step 1Needed values: v(∅) = f(0,0,0) = 0; v({1}) = 2; v({2}) = 3; v({1,2}) = 2 + 3 + 1 = 6. Feature 3 changes nothing.
Step 2For feature 1 with two other features (2 and 3 but 3 is inert), the orderings are equivalent to: feature 1 joins first (gain v({1}) − v(∅) = 2) or joins after feature 2 (gain v({1,2}) − v({2}) = 6 − 3 = 3), each with weight 1/2. φ₁ = ½·2 + ½·3 = 2.5.
Step 3For feature 2: first 3, after feature 1 6 − 2 = 4. φ₂ = ½·3 + ½·4 = 3.5.
Step 4φ₃ = 0.
Answerφ = (2.5, 3.5, 0).
CheckSum = 6 = f(1,1,1) − f(0,0,0). The interaction term x₁·x₂ = 1 was split equally (0.5 each), which is the Shapley rule for a shared term. The code (brute force over all orderings) printed [2.5, 3.5, 0.0], sum 6.0.
Why it mattersThis is exactly what SHAP computes. The exact sum has 2^M terms, so libraries use shortcuts.

Step 2Apply the formula for each of the five features (script c16c.py).
Step 3Output:

  • Check The five values sum to 0.320, exactly f(x) − E[f].
  • Why it matters This is the sentence you give a bank manager: "this applicant's risk is 32 points above average mainly because of a short credit history".

With 200 background rows and one model the estimates are also noisy.

TreeSHAP, KernelSHAP, interactions (not run here)

The shap library (not installed here) offers TreeSHAP, a fast exact algorithm for tree ensembles (seconds instead of 2^M), and KernelSHAP, a sampling method for any model (slower, approximate). It also gives interaction values (Shapley shares for pairs of features) and plots: a summary (beeswarm) plot for global patterns, and a waterfall plot for one prediction. Typical usage, not run here:

import shap
explainer = shap.TreeExplainer(model)
sv = explainer.shap_values(X_test)      # additive contributions, one per feature per row
shap.summary_plot(sv, X_test)

The assumptions to remember for interviews: SHAP needs a background distribution to represent "absent" features; with correlated features it may evaluate impossible combinations; the values are additive in the model's output space (log-odds for many classifiers, not probabilities).

LIME

LIME explains one prediction by sampling points around it, asking the black box for their predictions, and fitting a weighted linear model; the slopes are the local explanation. We did a quick hand version (500 samples with Gaussian jitter of 0.5 standard deviations, closer points weighted more) around applicant 0:

local slopes per 1 sd:  income -0.179, debt +0.233, age -0.105, credit_len -0.045, noise_id -0.033

Compare with the Shapley answer: here debt looks like the main driver (+0.233 per standard deviation), but Shapley says credit length and age. They answer different questions: LIME gives the local slope (what if the numbers wiggle a little), Shapley gives the share of the gap from the average. LIME also depends on its settings (jitter size, weights) and can change between runs. Treat both as hints, not truths.

Counterfactual explanations

A counterfactual answers "what is the smallest change that flips the decision?". It is the most useful message for a customer: not "your debt had importance 0.15" but "if your debt were 6 lower, you would be approved". We take the same applicant (probability 0.763, debt 18.6) and lower debt step by step:

high-risk person [66.3, 18.6, 25.9, 6.8, 0.3]  p 0.763
debt must drop by 6.0 to 12.6  p 0.315

Probability fell from 0.763 to 0.315 when debt went from 18.6 to 12.6. The forest is step-shaped, so the flip is abrupt (the PDP also showed a steep rise between 11 and 19). Good counterfactuals must use actionable features (debt, yes; age, no), small changes, and be realistic (do not suggest a 22-year-old with 40 years of credit). Libraries such as DiCE exist (not run here).

Model card. For every model you hand over, write a short document with: purpose and intended users; training data (source, dates, known gaps); metrics, overall and by slice; limits and known failure modes; fairness checks; monitoring plan; owner and date. A datasheet does the same for a dataset.

Connection to the real job

Interview stories often go: "The model had high AUC. Permutation importance showed one feature carried everything. It was a field filled in only after the outcome (leakage). We removed it." That is the whole value of explainability in one sentence.

Applications

  • Credit and insurance: adverse-action reasons ("why was I rejected?"), often required by regulation.
  • Healthcare: clinician trust and error checks.
  • Fraud: analysts see which factors flagged a transaction.
  • Debugging: spot leaks and spurious signals.
COMMON MISTAKE
Giving a Shapley or LIME explanation to a customer as "the cause". It says what the model did with the numbers, not what caused their situation.

Check yourself

  1. What do Shapley values add up to? Answer: the prediction minus the average prediction.
  2. Which question does a counterfactual answer? Answer: what smallest change would flip the decision.
  3. Why can SHAP mislead with correlated features? Answer: it may fill in "absent" features with unrealistic combinations, and credit gets shared between twins.

16.3 Fairness and Ethics

INTUITION
Two students with equal ability sit an entrance exam. One of them attended a school without a lab, so the same ability shows up as slightly lower marks. A model trained on marks learns "this school's students are weaker". Nothing in the code was "prejudiced", yet the outcome is unfair. Bias usually comes from the data and the world, not from a bad programmer.

Sources of bias

SourceExample
Historicalpast loan officers refused one group more often; the labels copy that
Samplingdata from one city only; other groups are rare
Measurementthe same ability yields lower marks for a disadvantaged group
Label"arrested" is used as the label for "committed a crime"
Aggregationone model for everyone, but groups behave differently
Proxypostcode or surname stands in for a protected attribute even when it is removed

A protected attribute is a characteristic such as gender, caste, religion or race that the law or your ethics say should not drive a decision. Removing the column does not remove the bias, because proxies leak it back.

The three most-used metrics

Let Ŷ be the model's decision (1 = approve) and Y the true outcome (1 = would repay), and A, B two groups.

Many practitioners also report the disparate impact ratio selection rate of B / selection rate of A; a common rule of thumb in US hiring law is that a ratio below 0.8 deserves attention (the "four-fifths rule"). Indian and EU law differ; get legal advice for the real case.

A simulated example

We simulate 20,000 applicants; group B is 30 percent. Skill is the same in both groups, and the true outcome follows skill by the same rule. But the observed score feature (like exam marks) is lowered by 0.5 for group B (measurement bias), and a proxy feature (like postcode) is correlated with group. The model never sees the group label. We train logistic regression on 14,000 rows and test on 6,000 (4,310 in A, 1,690 in B). Test AUC = 0.844.

single threshold 0.5          group A    group B
selection rate                 0.374      0.291
true-positive rate (TPR)       0.689      0.545
false-positive rate (FPR)      0.179      0.112
actual repay rate (base rate)  0.384      0.414

Problem 16.3.1 Compute the demographic parity gap, the disparate impact ratio and the equal opportunity gap.

Formulagap = rate A − rate B; ratio = rate B / rate A.
Plug inSelection: 0.374 − 0.291; TPR: 0.689 − 0.545.
ComputeParity gap = 0.083. Ratio = 0.291 / 0.374 = 0.777. Equal opportunity gap = 0.144. FPR gap = 0.179 − 0.112 = 0.067.
AnswerGroup B is approved 8.3 points less often, with a ratio of 0.777 (below the 0.8 rule of thumb). More importantly, among people who would have repaid, 68.9 percent of A but only 54.5 percent of B are approved: a 14.4-point gap.
CheckThe base repay rates are 0.384 for A and 0.414 for B, so B is not a riskier group. The gap does not come from different real risk; it comes from the measurement bias in score.
Why it mattersEqual opportunity shows the harm clearly: qualified people in B are turned away more often.

Mitigation

StageMethodIdea
Pre-processingreweighing, resamplingchange the training data so group and label are less tied

Problem 16.3.2 Apply group-specific thresholds. Find the cut-off for group B that gives B the same true-positive rate as A (0.689).

Step 1Scan thresholds from 0.05 to 0.95 for group B's actual positives (people with Y = 1); pick the one where the share above it is closest to 0.689.
Step 2The search gives threshold 0.385 for B, with 0.5 kept for A.
Step 3New results: B's TPR = 0.687, FPR = 0.192, selection rate 0.396; A unchanged (TPR 0.689, FPR 0.179, selection 0.374). Precision (share of approvals that repay): A 0.706, B 0.716.
AnswerThe equal opportunity gap fell from 0.144 to 0.002. The FPR gap is now −0.013 (B has slightly more false approvals), and B's selection rate is now above A's (0.396 versus 0.374). Precision is almost equal (0.706 versus 0.716), so approvals are about equally reliable in both groups.

Why it mattersFixing one metric moves the others; you must choose which one matters for the decision and document it. This is a trade-off, not a free lunch. Using group-specific thresholds may also be illegal in some settings; get legal review.

Problem 16.3.3 Reweighing: weights w = P(group)·P(label) / P(group, label) for each (group, label) cell. Did it fix the gap?

Step 1Compute weights and refit with sample_weight.
Step 2Output: selection A 0.375, B 0.289; TPR A 0.690, B 0.544. The gaps are 0.086 and 0.146, essentially unchanged.
Step 3Why? The repay rates by group are 0.386 and 0.398, nearly equal, so the weights are all close to 1. Reweighing fixes a label dependence on group. Our bias is in the feature (measurement), so there was nothing for it to fix.
AnswerReweighing did not help here, because it targets the wrong kind of bias.
CheckIf group and label are exactly independent, P(g,y) = P(g)P(y) and every weight equals 1, as the near-1 weights suggest.
Why it mattersPick the mitigation by diagnosing the source of the bias first. A common beginner error is to run a library tool and report "bias reduced" without checking where it came from.

Known trade-offs

When base rates differ between groups, a model cannot have equal false-positive rates, equal false-negative rates and calibrated scores at the same time (impossibility results, Kleinberg et al. and Chouldechova, 2016-2017). You must choose, and the choice is a business and ethical decision, not a purely mathematical one.

Tools: fairlearn and aif360 compute these metrics by group and offer mitigation (not run here). A responsible release includes a datasheet, a model card, and a short impact assessment: who could be harmed, how you would know, and who can override the model.

Connection to the real job

Hiring, lending, insurance and health use cases attract audits. Even in a non-regulated product, slicing metrics by group (Chapter 10) is routine.

Applications

  • Lending: approval-rate gaps by gender or region.
  • Hiring: screening models.
  • Healthcare: risk scores that under-treat a group.
  • Advertising: who sees job or housing ads.
COMMON MISTAKE
"We removed the gender column, so the model is fair." Proxies (postcode, name, school) bring it back. Measure outcomes by group, not just the inputs.

Check yourself

  1. What does equal opportunity compare? Answer: true-positive rates between groups.
  2. Why did reweighing not help in our example? Answer: the bias was in a feature, not in the link between group and label.
  3. Can all fairness metrics hold at once? Answer: not when base rates differ (impossibility results).

INTUITION
A bridge is not judged on a calm day. We load it beyond normal and see how it fails. A model deserves the same: add noise, add a nudge from an adversary, corrupt some training labels, and see how gracefully it degrades.

Problem 16.4.1 How much accuracy does each model lose when noise of standard deviation 0.5 is added to every test feature, and which degrades faster?

Step 1Logistic regression: 0.923 − 0.825 = 0.098. Forest: 0.885 − 0.803 = 0.082.
Step 2At noise 1.0 (as large as the features themselves): logreg 0.923 − 0.727 = 0.196; forest 0.885 − 0.719 = 0.166.
AnswerBoth degrade smoothly. The forest loses a little less, but it started lower and stays lower (0.803 versus 0.825 at noise 0.5). The linear model is better at every noise level, since the data follows a linear rule.
CheckAt very large noise both approach 0.5 (guessing); 0.72 is already about halfway between 0.92 and 0.5.
Why it mattersPlot a degradation curve before deployment, and compare it with the amount of noise your real inputs have.

Adversarial nudge. For a linear model an attacker knows that moving each feature against the sign of its weight lowers the score fastest. Our nudge: x' = x − ε·sign(w)·(2y − 1) (push each point toward the wrong side). A small change in every feature:

epsilon    0.0    0.1    0.3    0.5
accuracy   0.923  0.785  0.451  0.240

Problem 16.4.2 Read the table. How large must ε be to push the model below chance?

Step 1At ε = 0.1 (a tenth of a standard deviation) accuracy drops from 0.923 to 0.785, a loss of 13.8 points.
Step 2At ε = 0.3 it is 0.451, below the 0.5 of random guessing.
Step 3At ε = 0.5 it is 0.240: worse than a coin, meaning the attacker pushes most points to the wrong class.
AnswerA change of about 0.3 standard deviations in every feature is enough to push the accuracy under 50 percent.
CheckThis is a worst-case direction using full knowledge of the weights, so it is far more damaging than the random noise of the previous table (random noise of 0.5 cost only 10 points).
Why it mattersRandom noise tests accuracy; adversarial tests probe security. For deep image and text models, such attacks are the reason for adversarial training and input validation. Here, we only introduce the idea.

Poisoning by label flips. Flip a share of the training labels at random and measure test accuracy:

flipped    0%     10%    20%    30%
accuracy   0.923  0.920  0.915  0.900

Random label noise is tolerated well by a regularised linear model: 30 percent random flips cost only 2.3 points. This is not the worst case: a smart attacker would flip labels near the decision boundary or insert a few carefully chosen rows. Other attacks to know by name: model inversion (recover training data from a model's outputs), and membership inference (tell whether a person was in the training set). Defences: validate and rate-limit inputs, clean and version training data, limit what the API reveals, and use differential privacy where privacy matters. All awareness-level here.

Safe fallbacks. A good system has a plan for when the model should not decide: a rule-based default, a confidence threshold with human review (Chapter 9 conformal intervals help), and a kill switch.

Applications

  • Fraud: attackers adapt to your model, so it is adversarial by nature.
  • Vision: stickers on road signs.
  • Text: prompt injection on LLM apps.
  • Healthcare: robustness to scanner differences.
COMMON MISTAKE
Testing robustness only with random noise. Random noise is the easy case; also test targeted changes and shifts that match how your data can really change.

Check yourself

  1. What is an adversarial example? Answer: an input changed slightly on purpose so that the model errs.
  2. Why can random label flips be tolerable but targeted ones not? Answer: random flips average out; targeted ones push the boundary in one direction.
  3. What is a safe fallback? Answer: a default rule or human review when the model is unsure or inputs look wrong.

16.5 ML Engineering Hygiene

INTUITION
A kitchen can produce a great meal once. A restaurant produces it every day, for anyone, even when the head chef is on leave. That needs clean tools, written recipes, labelled shelves, and a habit of tasting before serving. Hygiene is how a model survives contact with other people and with time.

The rule of thumb (from Google's "Rules of Machine Learning"): start with a simple model and a solid pipeline; most gains come from better data and features; get the evaluation right before getting the model fancy.

Why pipelines matter: a demonstration

We create pure noise: 100 rows, 2,000 random columns, random 0/1 labels. No model can truly beat 50 percent. Two ways to evaluate:

from sklearn.feature_selection import SelectKBest, f_classif
from sklearn.pipeline import make_pipeline
# WRONG: pick the 20 "best" columns using ALL rows, then cross-validate
Xsel = SelectKBest(f_classif, k=20).fit_transform(Xn, yn)
wrong = cross_val_score(LogisticRegression(max_iter=1000), Xsel, yn, cv=KFold(5, shuffle=True, random_state=0)).mean()
# RIGHT: selection inside the pipeline, so it is re-done on each training fold
pipe = make_pipeline(SelectKBest(f_classif, k=20), LogisticRegression(max_iter=1000))
right = cross_val_score(pipe, Xn, yn, cv=KFold(5, shuffle=True, random_state=0)).mean()

Predict: what accuracy does each print? Real output:

pure noise, 100x2000: select-then-CV acc 0.81  | Pipeline acc 0.52

Problem 16.5.1 Explain the 0.81 and the 0.52.

Step 1With 2,000 random columns and only 100 rows, some columns correlate with the labels by pure luck. Selecting the 20 most correlated columns on all rows picks columns that already "know" the labels of the test folds.
Step 2Cross-validation then reports 0.81: leaked information, not skill.
Step 3In the pipeline, selection happens separately inside each training fold, using only that fold's labels. The test fold stays unseen, so accuracy is 0.52, the honest value for noise.
AnswerThe wrong method looks 31 points better than chance (0.81 versus 0.50) on data that contains no signal. The pipeline gives 0.52.
CheckOn random labels the correct answer is about 0.5, and the pipeline is the only one near it.
Why it mattersThis is train-test contamination (Chapter 8): any step that learns from data (scaling, imputing, selecting, encoding, even PCA) must be inside the pipeline.

When not to use ML

  • A simple rule works (if the order is over 5,000 rupees, ask for approval).
  • The data is too small or too noisy to learn anything reliable.
  • No action follows the prediction (nobody changes what they do).
  • Errors are too costly without human oversight.

Item 11: CV splitter and metrics from scratch

def kfold(n, k, seed=0):
    idx = np.random.default_rng(seed).permutation(n); folds = np.array_split(idx, k)
    for i in range(k):
        yield np.concatenate([folds[j] for j in range(k) if j != i]), folds[i]

16.7 The Interview Bank

Answer these aloud, in simple words, in under a minute each. The model answers below are short on purpose.

#QuestionModel answer
1Bias versus variance?Bias is error from a model too simple to capture the pattern; variance is error from a model so flexible that it changes a lot with the sample. Training error low and test error high means variance (Chapter 1).
2L1 versus L2?L2 (ridge) shrinks all weights smoothly; L1 (lasso) can set weights to exactly zero, so it selects features. L1 is a Laplace prior, L2 a Gaussian prior (Chapter 3).
3Random forest versus gradient boosting?A forest averages many deep trees built independently (reduces variance). Boosting builds shallow trees one after another, each fitting the remaining error (reduces bias). Boosting is more sensitive to tuning and noise.
4Why can boosting overfit, or not?Each tree is small and learning rate is low, so it improves slowly, but with enough trees it fits noise. Use early stopping and a validation set.
5How to handle imbalanced data?Use PR-AUC and recall at a threshold, class weights, threshold moving; resample only inside CV folds; consider an anomaly framing.
6Precision versus recall?Precision: of those I flagged, how many are real. Recall: of the real ones, how many I found. Raising the threshold raises precision and lowers recall; choose by the cost of each error.
7ROC-AUC versus PR-AUC?ROC-AUC is the chance a positive outranks a negative; it ignores class balance. PR-AUC reacts to the base rate, so it is more informative for rare positives.
8What is calibration?Predicted 0.7 should be right about 70 percent of the time. High AUC does not guarantee it. Check a reliability plot, fix with Platt or isotonic scaling.
9How to choose k in k-means?Elbow, silhouette, and stability across seeds; and above all, usefulness for the business.
10PCA assumptions?Linear structure, variance equals signal, features on comparable scales. It is sensitive to scaling and to outliers.
11How to detect and prevent leakage?Suspiciously good scores, one dominant feature; check permutation importance and feature timing; fit all preprocessing inside the pipeline; split by time or group.
12Cross-validation for time series?Never train on the future: expanding or rolling windows, with a gap if features look back.
13Explain SHAP.Each feature gets its fair (Shapley) share of the gap between this prediction and the average one, averaged over all orders in which features could be added. Shares add up exactly. TreeSHAP computes it fast for trees. Limits: needs a background set, correlated features, describes the model not the cause.
14Permutation versus impurity importance?Permutation shuffles a column on held-out data and measures the score drop; impurity counts split gains on training data and favours continuous or high-cardinality features.
15A model works offline but fails online: debug it.Check training-serving skew (feature code, units, missing values), leakage in offline data, distribution shift, label delay, a different population, and latency or timeouts that change inputs. Compare logged serving features with training features.
16How do you know a fairness problem exists?Slice metrics by group: selection rate, TPR, FPR, calibration. Compare base rates. Look for proxies. Decide which metric matters with the stakeholders.
17Bandit or A/B test?A/B test for a clean effect size; bandit when you must earn while learning and arms are many (Chapter 15).
18When would you not use ML?A rule works, data is tiny or noisy, no action follows, or errors are too costly without oversight.
19What is regularization, in one sentence?A penalty that discourages complex models so they generalise better.
20Walk me through your approach to a new tabular problem.Define the metric and the cost of errors; split correctly (time or group); baseline; simple model; pipeline; one improvement at a time; error analysis by slices; calibration and threshold; explain, check fairness and robustness; document and monitor.
21How do you detect anomalies without labels?Robust statistics or isolation forest to rank; inject synthetic anomalies to test; measure precision at the number of alerts a team can review (Chapter 14).
22What does Q-learning do?It learns a table of values for state-action pairs by moving each value toward reward plus discounted best next value; it is off-policy (Chapter 15).
23Self-training pitfalls?A weak first model gives wrong confident labels and then reinforces them. Compare with the supervised baseline and keep a clean validation set.
24How do you reproduce an experiment?Fixed seeds, pinned library versions, versioned data snapshot, config file, logged metrics and code commit.
25What do you do if the model's accuracy suddenly falls in production?Check data pipeline and schema first, then input drift (PSI, KS), then label shift, then retrain or roll back; add monitoring.

16.8 Three Specialist Problems: Survival, Uplift and Ranking

Three kinds of question look like classification or regression but break their rules. "How long until the customer leaves?" has people who have not left yet. "Who should get the coupon?" is about the change the coupon causes, not who buys. "Which ten results do we show?" cares about order, not about each score. Each needs its own metric and data design.

Survival analysis: when the outcome is not yet observed

Ten subscribers are followed for 12 months. Some cancel (event = 1); others are still subscribed when the study ends or they drop out of view (censored = 0). Dropping the censored rows throws away the information that those customers survived at least that long; treating them as cancellations is worse. The Kaplan-Meier estimator handles it: at each event time t, multiply the running survival by (1 − d/n), where d is the number of events at t and n the number still at risk (observed time at least t).

import numpy as np
# Kaplan-Meier by hand: times, event=1 observed, 0 censored
t = np.array([2, 3, 3, 5, 6, 8, 8, 9, 12, 12]); e = np.array([1, 1, 0, 1, 0, 1, 1, 0, 1, 0])
S = 1.0; print("time at_risk deaths  S(t)")
for u in np.unique(t[e == 1]):
    n = (t >= u).sum(); d = ((t == u) & (e == 1)).sum(); S *= 1 - d / n; print(f"{u:4d} {n:7d} {d:6d}  {S:.4f}")
# naive: drop censored vs treating censored as events
print("naive share of ALL 10 rows with an event by t=8:", ((t <= 8) & (e == 1)).sum() / len(t))
print("KM estimate of P(event by t=8):", round(1 - 0.4114, 4))

Problem 16.8.1 Reproduce the row for t = 8 and say what the estimate means.

Step 1Events happen at times 2, 3, 5, 8 (twice), 12. Censored subjects are at 3, 6, 9, 12.
Step 2At t = 5 the survival was 0.6857. At t = 8, how many are still at risk? Subjects with time of at least 8: times 8, 8, 9, 12, 12 = 5. Two events happen at 8.
Step 3S(8) = 0.6857 × (1 − 2/5) = 0.6857 × 0.6 = 0.4114.
AnswerEstimated chance of still being subscribed after 8 months is 41%, so the chance of cancelling by 8 is 59%.
CheckThe naive count "5 of 10 cancelled by t = 8" gives 50%. It is lower than the KM estimate because it treats the censored subjects (3 and 6) as if they had survived to 8, while KM only counts them while observed.

To explain why some customers leave sooner, the standard regression is the Cox proportional-hazards model: the hazard (instant risk) is a baseline hazard times exp(βᵀx), so exp(β) is a hazard ratio (1.5 means 50% higher risk per unit of the feature). The lifelines and scikit-survival packages are not installed here, so Cox fitting is not run here. Evaluate with the concordance index (does the customer who left first have the higher risk score?) rather than accuracy.

Uplift modelling: predicting who changes

A coupon campaign has four kinds of customer: persuadables (buy only if treated), sure things (buy anyway), lost causes (never buy), and sleeping dogs (the coupon annoys them and they leave). A normal response model ranks sure things first, so you waste coupons on them. Uplift models estimate τ(x) = P(y=1 | treated, x) − P(y=1 | control, x). The simplest recipe is the two-model (T-learner): fit one model on treated rows and one on controls and subtract. It needs data from a randomised test. Below, 40,000 simulated customers: for x > 0 the coupon adds 10 points of conversion, for x ≤ 0 it subtracts 4 (average effect +3).

import numpy as np
rng = np.random.default_rng(0); n = 40000
x = rng.normal(size=n); T = rng.integers(0, 2, n)
tau = np.where(x > 0, 0.10, -0.04)                      # persuadable if x>0, sleeping-dog otherwise
p = 0.10 + tau * T; y = rng.random(n) < p
from sklearn.ensemble import GradientBoostingClassifier as G
X = x[:, None]; m1 = G(max_depth=2, n_estimators=50, random_state=0).fit(X[T==1], y[T==1]); m0 = G(max_depth=2, n_estimators=50, random_state=0).fit(X[T==0], y[T==0])
up = m1.predict_proba(X)[:, 1] - m0.predict_proba(X)[:, 1]
print("true mean effect", round(tau.mean(), 3), " mean predicted uplift", up.mean().round(3))
order = np.argsort(-up)
for q in (0.25, 0.5, 1.0):
    k = order[: int(q * n)]; a = y[k][T[k]==1].mean() - y[k][T[k]==0].mean()
    print(f"top {int(q*100)}% by uplift: observed effect {a:.3f}")
r = np.argsort(-(m0.predict_proba(X)[:,1]))   # wrong: target by response propensity
k = r[: n // 4]; print("top 25% by baseline response: effect", round(y[k][T[k]==1].mean() - y[k][T[k]==0].mean(), 3))
true mean effect 0.03  mean predicted uplift 0.024
top 25% by uplift: observed effect 0.120
top 50% by uplift: observed effect 0.096
top 100% by uplift: observed effect 0.024

How to read it: in the left panel the curve steps down only at events, while the red ticks (censored subjects) shrink the at-risk group without a drop. On the right, the curve starts high (treating only the top few percent by predicted uplift gives a large measured effect) and falls to the average effect as you add everyone. The red dashed line is "treat everybody". Treating the top 25% gives an observed effect of 0.120, versus 0.024 when treating all (the true mean is 0.03), and targeting by baseline response instead yields 0.004, since the top responders are sure things.

COMMON MISTAKE
Evaluating an uplift model with AUC on the outcome. AUC rewards ranking buyers, not persuadable buyers. Use an uplift curve or Qini coefficient computed on a randomised hold-out.
COMMON MISTAKE
Fitting uplift on observational data where the treatment was targeted. If good customers were more likely to get the coupon, the T-learner learns the targeting rule, not the coupon's effect (Chapter 16 on causality).

Learning to rank: order is the product

For search and recommendations, a model scores each item for a query and the list is sorted by score. The metric is NDCG (normalised discounted cumulative gain): each result's gain 2^rel − 1 is divided by log₂(position + 1) so that top positions count more, then divided by the best possible ordering. Training methods are pointwise (regress the relevance), pairwise (RankNet, get pairs in the right order) and listwise (LambdaMART, directly weight swaps by their NDCG change); XGBoost and LightGBM offer the last (objective="rank:ndcg", not run here).

import numpy as np
def dcg(r): return sum((2**v - 1) / np.log2(i + 2) for i, v in enumerate(r))
rel = [3, 2, 3, 0, 1, 2]
print("DCG@6", round(dcg(rel), 4), "ideal", round(dcg(sorted(rel, reverse=True)), 4), "NDCG", round(dcg(rel) / dcg(sorted(rel, reverse=True)), 4))
from sklearn.metrics import ndcg_score
print("sklearn", round(ndcg_score([rel], [[6,5,4,3,2,1]]), 4))

sklearn 0.9608

Chapter recap

  • Prefer an interpretable model when it is accurate enough. If you need a black box, explain it with several tools and report their limits.
  • Permutation importance on held-out data beats impurity importance: it rated our junk column at about 0.0006 against 0.090 for impurity.
  • Correlated features split or hide importance (age and credit length: 0.068 together, but 0.126 once age was dropped).
  • Partial dependence shows an average effect; ICE shows individual curves; surrogates imitate a model, so report their R².
  • Shapley values give each feature a fair share of the gap between one prediction and the average; they add up exactly. LIME gives a local slope; counterfactuals give the smallest change that flips a decision.
  • Fairness needs group metrics (selection rate, TPR, FPR, calibration). Pick mitigation by diagnosing the source of bias; metrics conflict when base rates differ.
  • Test robustness with noise, targeted nudges and poisoned data. Random noise is the easy case.
  • Hygiene: baseline first, pipelines, seeds, logs, data tests, documentation, and knowing when not to use ML.
  • Rebuilding algorithms from scratch and checking against scikit-learn proves understanding. The interview bank gives short, plain answers to practise aloud.

Practice set

1. (easy) A model is f = 3·x₁ + 0·x₂. Which feature has zero permutation importance? Answer: x₂, because shuffling it does not change any prediction.

2. (easy) Group A has 400 applicants and 120 approvals. Group B has 200 applicants and 50 approvals. Compute the selection rates and the disparate impact ratio. Answer: A: 120/400 = 0.30. B: 50/200 = 0.25. Ratio 0.25/0.30 = 0.833, just above the 0.8 rule of thumb.

3. (easy) What do Shapley values add up to? Answer: Prediction minus the average prediction.

4. (medium) A PDP for x₁ with f = x₁·x₂ and rows with x₂ = 2, 4 is evaluated at x₁ = 3. What is the value? Answer: Predictions 6 and 12; average 9.

5. (medium) Exact Shapley for f = x₁ + 2·x₂ at x = (1,1) with baseline (0,0). Answer: No interaction, so each gets its own term: φ₁ = 1, φ₂ = 2; sum 3 = f(1,1) − f(0,0).

6. (medium) Find the bug: "I scaled all data with StandardScaler().fit_transform(X), then did 5-fold CV and got AUC 0.91." What is wrong and what is the fix? Answer: The scaler used the means and spreads of the test folds too (contamination). Put the scaler in a pipeline with the model so it is fit on training folds only. For scaling the effect is small, but the habit matters, and for target-aware steps like feature selection it is large (0.81 versus 0.52 in 16.5).

7. (medium) Group B has 1,690 applicants, of whom 700 would repay; the model approves 380 of those 700. Find the true-positive rate. Answer: 380/700 = 0.543.

8. (hard) A forest shows feature_importances_ of 0.4 for a customer ID column. What do you suspect and how do you check? Answer: The ID lets trees memorize rows (high cardinality bias) or leaks something like time order. Check permutation importance on held-out data (it should be about 0), and split by time or group to see if the score collapses.

9. (hard, interview) Explain SHAP to a bank manager in three sentences. Answer: "For one customer, SHAP starts from the average prediction and shows how much each factor pushed the risk up or down; the pushes add up to the customer's actual score. It is a fair-split rule from game theory. It tells us what the model used, not what caused the customer's situation."

10. (hard, interview) Your fairness audit shows equal approval rates but unequal true-positive rates. Is the model fair? Answer: It meets demographic parity but not equal opportunity: qualified people in one group are approved less often. Whether it is "fair" depends on which criterion matters for the decision. Discuss it with stakeholders, check base rates (different base rates make all criteria impossible together), document the choice.

11. (hard, interview) A model's offline AUC is 0.88 but online it is 0.71. Give four causes in order of what you check first. Answer: (1) Training-serving skew in features. (2) Leakage in the offline set (feature available only after the outcome). (3) Distribution shift between the offline period and now. (4) Label delay or different population or definition. Check by logging serving features and comparing distributions with training.

(easy) At time t, 8 subjects are at risk and 2 have the event. By what factor does S(t) multiply? Answer: 1 − 2/8 = 0.75.

(medium) A Cox model gives β = 0.4 for "support tickets in month 1". What is the hazard ratio per extra ticket and per 3 extra? Answer: e^0.4 = 1.49 per ticket (49% higher risk); e^1.2 = 3.32 for 3.

(medium) Treated conversion 12%, control 9% in the top uplift decile. Is the uplift 3 points or 1.33x? Answer: both, 0.12 − 0.09 = 3 points absolute (1.33 relative); budget with the absolute number.
