13.1 Convexity: Why Some Problems Are Easy

BASIC EXPLANATION
A function is convex if the line between any two points on its graph lies above the graph. For convex problems every local minimum is a global minimum, so they are easy to solve reliably.
INTUITION
A bowl has one lowest point. Put a ball anywhere, it rolls to the same bottom. A mountain range has many valleys; where the ball ends depends on where you drop it. A convex function is a bowl. Convex optimization means "there are no traps".

How it works

A function f is convex if the line segment between any two points on its graph lies on or above the graph. For a smooth function of one variable, this is the same as f''(x) ≥ 0 everywhere. For many variables, the Hessian (the matrix of second derivatives) must be positive semi-definite (all its eigenvalues are ≥ 0). For a convex function, every local minimum is a global minimum. A convex set is one where the line between any two of its points stays inside the set (a disc is convex, a doughnut is not).

Problem 13.1.1 Is f(x) = x² convex? Is f(x) = x⁴ − 3x² + x?

Step 1For x²: f'(x) = 2x, f''(x) = 2, which is positive everywhere. So it is convex, and its one minimum, x = 0, is global.
Step 2For the quartic: f'(x) = 4x³ − 6x + 1 and f''(x) = 12x² − 6. At x = 0, f'' = −6, which is negative. At x = 1, f'' = +6. The sign changes, so it is not convex.
Step 3Run a local minimizer from two starts:
from scipy.optimize import minimize
f=lambda x:x**4-3*x**2+x
for s in (-2,2):
    r=minimize(lambda z:f(z[0]),[s]);print("start",s,"->",r.x,r.fun)
start -2 -> [-1.30083949] -3.5139050389347464
start 2 -> [1.13090187] -1.0702301817735662
  • Answer The quartic has two valleys: a deep one at x ≈ −1.30 (f = −3.51) and a shallower one at x ≈ 1.13 (f = −1.07). Starting at 2 you land in the worse one.
  • Check f(1.13) = 1.63 − 3.83 + 1.13 = −1.07. Yes.
  • Why it matters Linear regression and logistic regression losses are convex, so training always reaches the best answer. Neural network losses are not convex; the starting point, learning rate and randomness matter.
KEY INSIGHT
In high dimensions, deep-learning losses have many saddle points (flat in one direction, curved in another, like a horse saddle). Where f' = 0, the Hessian has both positive and negative eigenvalues. Noise from stochastic gradient steps helps escape them.

Applications: SVM, logistic regression and Lasso are convex (Machine Learning); neural networks are not, so initialization matters (Deep Learning); portfolio optimization with cvxpy (Finance).

COMMON MISTAKE
Expecting a neural network to train to the same model twice. Non-convex problems have many solutions; fix seeds to compare experiments.

Check yourself

  1. Is f(x) = |x| convex? Answer: yes, though not differentiable at 0.
  2. In a convex problem, is a local minimum also global? Answer: yes.
  3. What does a negative Hessian eigenvalue tell you? Answer: the surface curves downward in that direction; it is not a minimum.

13.2 Gradient Descent: Batch, Stochastic and Mini-Batch

BASIC EXPLANATION
Gradient descent minimises a loss by repeatedly stepping against the gradient. Batch uses all data per step, stochastic uses one example, and mini-batch uses a small subset.
INTUITION
You stand on a foggy hillside and want the valley. You feel the slope under your feet and step downhill. The size of each step is the learning rate. Too small and you take all day; too big and you jump over the valley. The slope under your feet is the gradient.

Update rule

θ_new = θ − η × ∇L(θ), where η (eta) is the learning rate and ∇L the gradient of the loss. Convergence means the steps shrink toward zero near a minimum.

Problem 13.2.1 Minimise f(x) = x² from x = 5 with learning rate 0.1, then 0.5, 1.0 and 1.1.

Formulaf'(x) = 2x, so x_new = x − η·2x = x(1 − 2η).
Plug inFor η = 0.1 the factor is 1 − 0.2 = 0.8. For 0.5: 0. For 1.0: −1. For 1.1: −1.2.
Computeη = 0.1: 5 → 4 → 3.2 → 2.56 → 2.048 → 1.6384. η = 0.5: 5 → 0 (done in one step). η = 1.0: 5 → −5 → 5 → −5 (bounces forever). η = 1.1: 5 → −6 → 7.2 → −8.64 → 10.37 (grows).
AnswerThe step size must satisfy |1 − 2η| < 1, which means 0 < η < 1 here. Above 1 the method diverges.
CheckCode for η = 1.1 prints [5.0, -6.0, 7.2, -8.64, 10.368, -12.4416, 14.9299].
Why it matters"Loss going to NaN" in training is almost always this: a learning rate too high for the curvature.

Batch, stochastic and mini-batch

The loss is usually an average over n data rows. Three ways to compute the gradient:

Problem 13.2.2 Fit y = w₀ + w₁x to x = 1,2,3,4,5 and y = 2.1, 3.9, 6.2, 7.8, 10.1 by gradient descent on the mean squared error (MSE). Start at w = (0, 0), η = 0.02.

Formulagradient of MSE = (2/n) Xᵀ(Xw − y), where X has a column of ones and a column of x.
Step 1At w = 0: Xw − y = −y, so the gradient is −(2/5)(Σy, Σxy). Σy = 30.1 and Σxy = 2.1 + 7.8 + 18.6 + 31.2 + 50.5 = 110.2. Gradient = −(12.04, 44.08).
Step 2Update: w = 0 − 0.02 × (−12.04, −44.08) = (0.2408, 0.8816).
Step 3Repeat in code (x and y are the arrays above).
import numpy as np

COMMON MISTAKE
Features on very different scales (age 0 to 100, income 0 to 1,000,000). The loss surface becomes a long thin valley, and GD zig-zags. Standardize features first.

Check yourself

  1. Why does GD stay stable at η = 0.5 but not 1.1 for x²? Answer: the factor |1 − 2η| is 0 at 0.5 but 1.2 at 1.1.
  2. What is mini-batch's advantage over batch? Answer: faster steps on big data, while still averaging out some noise.
  3. What happens to the gradient near the minimum? Answer: it shrinks to zero.

13.3 Momentum, Adaptive Rates, Adam and Schedules

BASIC EXPLANATION
Momentum accumulates past gradients to smooth and speed up descent. Adaptive methods such as AdaGrad, RMSProp and Adam scale the step for each parameter, and learning-rate schedules change the step size over time.
INTUITION
A ball with weight (momentum) rolls through small bumps and keeps going down a long gentle slope. Adaptive methods give each parameter its own learning rate: big steps for weights that rarely get a gradient, small steps for ones that always do.

Words you need and the update rules

Let g be the gradient at the current point, η the learning rate.

MethodUpdateIdea
Momentumv = 0.9 v + g; θ = θ − η vKeep a running velocity
Nesterov (NAG)gradient at look-ahead point θ − η·0.9·vLook before you leap
AdaGrads += g²; θ −= η g / (√s + ε)Per-parameter rate that only decreases
RMSProps = 0.9 s + 0.1 g²; θ −= η g / (√s + ε)Forget old gradients
Adammomentum on g (m) and on g² (s), bias-correctedMost popular default
AdamWAdam with weight decay applied separately from the gradientBetter regularization; standard for transformers

ε is a tiny number (1e-8) that avoids division by zero. Learning-rate schedules change η over time: step decay (cut η by half every N epochs), cosine decay (smooth fall), warm-up (start tiny, rise, then decay: used for transformers).

A test: a long narrow valley

Use f(x, y) = 0.5(x² + 25y²): flat in x, steep in y (condition number 25). Start at (10, 1). Count steps until the distance to the minimum is below 10⁻⁶ (cap 2,000).

import numpy as np
A=np.array([1,25.])
def run(method,eta,cap=2000):
    p=np.array([10,1.]);v=np.zeros(2);s=np.zeros(2);m=np.zeros(2);eps=1e-8
    for k in range(1,cap+1):
        if method=="nag":
            g=A*(p-eta*0.9*v)
        else: g=A*p
        if method=="gd": p=p-eta*g
        elif method in("mom","nag"): v=0.9*v+g; p=p-eta*v
        elif method=="adagrad": s+=g*g; p=p-eta*g/(np.sqrt(s)+eps)
        elif method=="rms": s=0.9*s+0.1*g*g; p=p-eta*g/(np.sqrt(s)+eps)
        elif method=="adam":
            m=0.9*m+0.1*g; s=0.999*s+0.001*g*g
            p=p-eta*(m/(1-0.9**k))/(np.sqrt(s/(1-0.999**k))+eps)
        if np.linalg.norm(p)<1e-6: return k,p
    return None,p
for me,e in [("gd",.07),("gd",.04),("mom",.01),("nag",.01),("rms",.1),("adagrad",3.0),("adam",.3)]:
    k,p=run(me,e);print(me,e,k,p.round(2))

Problem 13.3.1 Explain these results and check the plain GD count by hand.

Step 1For plain GD on this function, the x coordinate shrinks by (1 − η) per step and y by |1 − 25η|. Stability needs η < 2/25 = 0.08. At η = 0.07: x factor 0.93, y factor |1 − 1.75| = 0.75. The slow coordinate is x.
Step 2Steps needed: 10 × 0.93ᵏ < 10⁻⁶ → k > ln(10⁷) / (−ln 0.93) = 16.118 / 0.0726 = 222.1, so 223. It matches the code.
Step 3The steepest direction caps η (0.08) while the flat direction crawls: ill-conditioning. Momentum and NAG converge in 272 and 209 steps with a much smaller η, because velocity builds up along the flat x direction.
AnswerAll but RMSProp converged. AdaGrad was fastest (71 steps, with a tuned η = 3.0). RMSProp with η = 0.1 never reached tolerance: its steps stay about η in size, so it bounces around the minimum at distance about 0.05.
Why it mattersOne toy function proves nothing general; the lesson is the mechanism. Adam is a good default but still needs a sensible η. A smaller or decaying η would let RMSProp settle.
REAL JOB TIP
In practice use Adam or AdamW with η around 1e-3 (small models) to 1e-5 (fine-tuning large models) plus warm-up and decay, and tune η first, before anything else.
COMMON MISTAKE
Adding an L2 penalty to the loss with Adam and calling it weight decay. With adaptive methods they differ; prefer AdamW.

Check yourself

  1. What limits plain GD's learning rate on an elongated valley? Answer: the steepest direction.
  2. What does RMSProp do that AdaGrad does not? Answer: it forgets old squared gradients, so the rate does not shrink to zero.
  3. Why use warm-up? Answer: early gradients are noisy and a large η can destabilize the start.

13.4 Second-Order Methods: Newton and L-BFGS

BASIC EXPLANATION
Second-order methods use curvature. Newton's method uses the Hessian matrix to take steps, and L-BFGS approximates the Hessian cheaply from recent gradients.
INTUITION
The gradient says which way is downhill. The Hessian says how curved the ground is. If you know the curvature, you can jump straight to the bottom of the bowl instead of inching.

Newton's method updates θ_new = θ − H⁻¹ g, where H is the Hessian. On a quadratic bowl it lands at the minimum in one step.

Problem 13.4.1 Apply Newton to f = 0.5(x² + 25y²) from (10, 1). Then use Newton's idea to find √2 as the root of x² − 2.

Step 1g = (x, 25y) = (10, 25). H = diag(1, 25), so H⁻¹g = (10, 1).
Step 2New point = (10, 1) − (10, 1) = (0, 0). One step, no matter the condition number.
Step 3For root finding, x_new = x − (x² − 2)/(2x). From x = 1: 1.5, 1.41667, 1.414216, 1.4142136, 1.41421356237. True √2 = 1.41421356237.
AnswerNewton needs just one step for the quadratic and about 4 steps to get 7 correct digits for √2. The number of correct digits roughly doubles per step.
CheckCode prints the same sequence: 1.5, 1.4166666666666667, 1.4142156862745099, 1.4142135623746899, 1.4142135623730951.
Why it mattersCost: for p parameters the Hessian has p² entries and inverting costs about p³ operations, impossible for a model with millions of weights.

Quasi-Newton methods (BFGS, and its memory-saving cousin L-BFGS) build an approximation to the curvature from recent gradients and never form H. L-BFGS is the default solver for logistic regression in scikit-learn and many classic models. Test on the Rosenbrock function, a curved narrow valley with its minimum at (1, 1), start (−1.2, 1):

from scipy.optimize import minimize
ros=lambda p:(1-p[0])**2+100*(p[1]-p[0]**2)**2
r=minimize(ros,[-1.2,1],method="L-BFGS-B")
print("lbfgs",r.x,r.nit,r.nfev)
r=minimize(ros,[-1.2,1],method="BFGS"); print("bfgs",r.x,r.nit)
lbfgs [0.9999969  0.99999379] 37 138
bfgs [0.99999547 0.99999094] 32
  • Answer Both methods reach (1, 1) to about 5 digits in 30 to 40 iterations. Plain GD with a fixed step needs thousands on this function.
COMMON MISTAKE
Calling minimize without a good starting point, tolerances or gradients on a non-convex function and trusting the output. Always check r.success, try several starts, and compare the final loss.

Check yourself

  1. How many Newton steps for a quadratic? Answer: one.
  2. Why not use Newton on a neural network? Answer: the Hessian is too big to compute and invert.
  3. What does L-BFGS store? Answer: a few recent gradient and step vectors, not the full Hessian.

13.5 Constrained Optimization: Lagrange Multipliers, KKT and Duality

BASIC EXPLANATION
Constrained optimisation minimises a function subject to constraints. Lagrange multipliers handle equality constraints, KKT conditions extend them to inequalities, and duality gives a related problem that bounds the solution.
INTUITION
"Find the lowest point of the hill, but you must stay on the road." At the best point on the road, the road runs exactly along a contour line of the hill; otherwise you could slide along the road to go lower. That means the hill's gradient points straight across the road, so it is a multiple of the road's gradient. That multiple is the Lagrange multiplier, usually called λ.

Equality constraints

To minimise f(x, y) subject to g(x, y) = 0, form L = f − λ g and set all partial derivatives (including with respect to λ) to zero.

Problem 13.5.1 Minimise x² + y² subject to x + y = 1.

FormulaL = x² + y² − λ(x + y − 1)
Step 1∂L/∂x = 2x − λ = 0 and ∂L/∂y = 2y − λ = 0, so x = y = λ/2.
Step 2The constraint x + y = 1 gives λ/2 + λ/2 = 1, so λ = 1 and x = y = 0.5.
AnswerThe closest point to the origin on the line is (0.5, 0.5), with value 0.25 + 0.25 = 0.5.
Checkscipy (SLSQP) gives [0.5 0.5] and 0.4999999999999998.
Why it mattersThe same idea derives PCA (maximise variance subject to unit length, Math PDF) and the Lagrangian form of Ridge regression (Chapter 7).

Inequality constraints and the KKT conditions

For g(x) ≤ 0, the Karush-Kuhn-Tucker (KKT) conditions say, at the optimum: (1) the gradient condition ∇f + μ ∇g = 0, (2) the constraint holds, (3) the multiplier μ ≥ 0, (4) complementary slackness: μ × g = 0, meaning either the constraint is active (g = 0) or its multiplier is zero (the constraint does not matter).

Problem 13.5.2 Minimise (x − 3)² + (y − 3)² subject to x + y ≤ 4.

Step 1Try ignoring the constraint: the minimum is (3, 3), but 3 + 3 = 6 > 4. It violates the constraint, so the constraint must be active: x + y = 4.
Step 2L = f + μ(x + y − 4). Then 2(x − 3) + μ = 0 and 2(y − 3) + μ = 0, so x = y = 3 − μ/2.
Step 3Active: x + y = 4 gives 6 − μ = 4, so μ = 2 ≥ 0 and x = y = 2.
AnswerThe best feasible point is (2, 2), with value 1 + 1 = 2, and μ = 2 ≥ 0 as KKT requires.
Checkscipy returns [2. 2.] and value 2.0000000000001954. The best value as a function of the limit L is 2(L/2 − 3)², whose slope at L = 4 is −2, which equals −μ: the multiplier is the price of the limit.
Why it mattersThe SVM is exactly this kind of problem; the training points with μ > 0 are the support vectors.

Duality in brief. Every constrained ("primal") problem has a "dual" built from the multipliers. For convex problems the best dual value equals the best primal value (strong duality). SVM solvers use it. Remember: multipliers are prices.

COMMON MISTAKE
Forgetting the sign condition μ ≥ 0 and the check that constraints are satisfied. A stationary point of the Lagrangian with a negative μ means the constraint should not be active.

Check yourself

  1. At the optimum, why is the objective's gradient a multiple of the constraint's? Answer: otherwise we could slide along the constraint and improve.
  2. What does complementary slackness say? Answer: μ × g = 0: an inactive constraint has zero multiplier.
  3. In 13.5.2, if the limit were x + y ≤ 8, what is the answer? Answer: (3, 3) with μ = 0; the constraint is inactive.

13.6 Linear Programming with scipy

BASIC EXPLANATION
Linear programming optimises a linear objective subject to linear constraints. In Python, scipy.optimize.linprog solves such problems.
INTUITION
A linear program (LP) is a planning problem where the goal and every limit are straight-line sums. You run a test lab: two kinds of nightly jobs compete for the same machines. How many of each should you run to get the most value?

Setting up

An LP: maximise (or minimise) cᵀx subject to A x ≤ b and x ≥ 0. Feasible region: all points obeying every limit. Its corners are called vertices. The key fact: an optimum, if it exists, is at a vertex. The simplex method walks from vertex to vertex; modern solvers (such as HiGHS inside scipy) also use interior-point methods. scipy.optimize.linprog always minimises, so to maximise, negate c.

Problem 13.6.1 Job A earns 40 value points, job B earns 30. Each A needs 2 CPU-hours, each B needs 1. You have 100 CPU-hours and 80 runner slots (each job takes one slot). At most 40 A jobs. Find the best plan.

Formulamaximise 40a + 30b subject to 2a + b ≤ 100, a + b ≤ 80, a ≤ 40, a, b ≥ 0.
Step 1List the vertices. (0,0): value 0. (40,0): 1600. (40,20): 2200 (meets a = 40 and 2a + b = 100). (20,60): 2600 (meets 2a + b = 100 and a + b = 80). (0,80): 2400.
Step 2The biggest is at (20, 60): 40×20 + 30×60 = 800 + 1800 = 2600.
Step 3Confirm with code.
from scipy.optimize import linprog
res=linprog(c=[-40,-30],A_ub=[[2,1],[1,1]],b_ub=[100,80],bounds=[(0,40),(0,None)],method="highs")
print(res.x,-res.fun,res.status);print(res.ineqlin.marginals)
[20. 60.] 2600.0 0
[-10. -20.]
  • Answer Run 20 A jobs and 60 B jobs for 2,600 points. status 0 means a solution was found.
  • Check CPU: 2×20 + 60 = 100 (full). Slots: 20 + 60 = 80 (full). Both limits are used up.
  • Why it matters The marginals are the shadow prices (negated because we minimised): one more CPU-hour is worth 10 points, one more slot is worth 20. Check: with 101 CPU-hours the optimum is 2610 at (21, 59); with 81 slots it is 2620 at (19, 62). This is the multiplier-as-price idea from 13.5.

Integer programming

Jobs come in whole numbers. With 99.5 CPU-hours the LP answer is fractional; an integer program forces whole numbers (harder, solved by branch-and-bound) with scipy.optimize.milp(c, constraints=LinearConstraint(A, ub=b), integrality=[1,1], bounds=Bounds(...)). Real result: the relaxed LP gives (19.5, 60.5) = 2595, impossible in practice; milp gives (19, 61) = 2590. Rounding the LP answer can be infeasible or suboptimal.

Network flow (shortest path, maximum flow, assignment) is an LP with special structure (networkx, OR-Tools, not run here). PuLP and cvxpy give friendlier modelling syntax for larger problems (not run here).

Applications: shift scheduling (Operations), assigning jobs to clusters (Data Engineering), choosing a product mix within a budget (Retail), budget allocation (Marketing).

COMMON MISTAKE
Forgetting that linprog minimises, so the printed fun is negative for a maximise problem. Also forgetting bounds: the default is x ≥ 0, which may or may not be what you want.

Check yourself

  1. Where is an LP optimum located? Answer: at a vertex of the feasible region.
  2. What does a shadow price of 20 mean? Answer: one more unit of that resource raises the best value by 20, as long as the plan structure stays the same.
  3. Why does linprog return a negative fun here? Answer: we negated the profit to maximise.

13.7 Hyperparameter Search and Heuristics

BASIC EXPLANATION
Hyperparameter search looks for the best settings of a model that are not learned from data, using methods such as grid search and random search. Heuristics are practical rules that find good solutions without a guarantee of the best.
INTUITION
Hyperparameters (learning rate, tree depth) are the dials you set before training; no gradient tells you how to turn them. You try settings and measure validation scores. Grid search tries every combination on a grid; random search samples settings at random; Bayesian optimization (for example Optuna) uses the results so far to pick the next promising setting.

Why random often beats grid: with 25 trials, a 5×5 grid tests only 5 distinct values of each hyperparameter, random search tests 25. Optuna (not run here) uses past trials to choose the next: study = optuna.create_study(direction="minimize"); study.optimize(objective, n_trials=50), where objective(trial) calls trial.suggest_float("lr", 1e-5, 1e-1, log=True) and returns the validation loss.

Heuristics such as genetic algorithms and simulated annealing need no gradients and can escape local minima, with no guarantee. The Rastrigin function 20 + Σ(xᵢ² − 10 cos(2π xᵢ)) has many valleys and best value 0 at (0, 0). We compared dual_annealing(rast, [(-5.12,5.12)]*2, seed=1) with the local minimize(rast, [3,3]):

anneal [-4.16829069e-09 -5.28841386e-09] 7.105427357601002e-15
local from 3,3 [2.98485572 2.98485572] 17.909202482974113

The annealing search found the global minimum (about 0); the local method got stuck in a valley at 17.9. A toy, and heuristics need many evaluations.

COMMON MISTAKE
Tuning hyperparameters on the test set. Use a validation set or cross-validation (Chapter 7), and keep the test set for one final check.

Check yourself

  1. Grid or random for 2 hyperparameters, one of which matters? Answer: random usually.
  2. What is "log=True" for? Answer: to sample learning rates across orders of magnitude evenly.
  3. Do heuristics guarantee the global optimum? Answer: no.

13.8 Information Theory Refresher

BASIC EXPLANATION
Entropy measures the average uncertainty of a distribution. Cross-entropy and KL divergence measure how different two distributions are, and they are used as loss functions and in model comparison.
INTUITION
How surprised are you when it rains in a desert? Very. In Mumbai in July? Not at all. Entropy is the average surprise of a source. A fair coin is maximum surprise; a coin that lands heads 90% of the time is more predictable. The Math PDF introduced these formulas; here we compute with them.

Formulas (log base 2 gives bits; natural log gives nats)

  • Entropy: H(p) = −Σ pᵢ log₂ pᵢ
  • Cross-entropy: H(p, q) = −Σ pᵢ log₂ qᵢ (the average cost if truth is p but you code using q)
  • KL divergence: KL(p ‖ q) = Σ pᵢ log₂(pᵢ / qᵢ) = H(p, q) − H(p), never negative, not symmetric
  • Mutual information: I(X; Y) = H(X) + H(Y) − H(X, Y): how much knowing Y reduces uncertainty about X

Problem 13.8.1 Entropy of a fair coin, a 90/10 coin and four equal outcomes?

ComputeFair: −2 × 0.5 log₂ 0.5 = 1 bit. 90/10: 0.1368 + 0.3322 = 0.469 bits. Four equal: 2 bits.
Answer1, 0.469 and 2 bits; predictable sources have lower entropy. entropy([.9,.1], base=2) gives 0.46899559358928117.

Problem 13.8.2 True distribution p = (0.7, 0.2, 0.1), model q = (0.5, 0.3, 0.2). Compute H(p), H(p, q) and KL(p ‖ q), KL(q ‖ p).

Step 1H(p) = −(0.7 log₂ 0.7 + 0.2 log₂ 0.2 + 0.1 log₂ 0.1) = 0.3602 + 0.4644 + 0.3322 = 1.1568 bits.
Step 2H(p, q) = −(0.7 log₂ 0.5 + 0.2 log₂ 0.3 + 0.1 log₂ 0.2) = 0.7 + 0.3474 + 0.2322 = 1.2796 bits.
Step 3KL(p ‖ q) = 1.2796 − 1.1568 = 0.1228 bits.
AnswerCoding with the wrong model costs 0.1228 extra bits per symbol. KL(q ‖ p) = 0.1328: different, so KL is not a distance.
Checkentropy(p, q, base=2) = 0.12280627887493814 and entropy(q, p, base=2) = 0.13277533663122576. Direct sum: 0.7·log₂(1.4) + 0.2·log₂(2/3) + 0.1·log₂(0.5) = 0.3398 − 0.1170 − 0.1 = 0.1228.
Why it mattersThe cross-entropy loss in classification equals H(p, q) with p the one-hot true label; minimising it is minimising KL since H(p) is fixed.

Problem 13.8.3 Joint table for X = "delivery is late" and Y = "the depot is overloaded": P(0,0) = 0.4, P(0,1) = 0.1, P(1,0) = 0.1, P(1,1) = 0.4. Find I(X; Y).

Step 1Marginals: P(X) = (0.5, 0.5), P(Y) = (0.5, 0.5), so H(X) = H(Y) = 1 bit.
Step 2H(X, Y) = −(2 × 0.4 log₂ 0.4 + 2 × 0.1 log₂ 0.1) = 1.0575 + 0.6644 = 1.7219 bits.
Step 3I = 1 + 1 − 1.7219 = 0.2781 bits.
AnswerKnowing the depot state removes 0.278 bits of the 1 bit of uncertainty about lateness.
CheckCode: MI 0.278071905.... If X and Y were independent, I would be exactly 0 (the code prints 0.0 for the product table).
Why it mattersMutual information scores feature relevance and catches non-linear links Pearson misses (sklearn.feature_selection.mutual_info_classif).

Applications: cross-entropy loss and tree splits by information gain (Machine Learning), KL in VAEs and distillation (Deep Learning), perplexity = 2^(cross-entropy) (GenAI), drift detection with KL/JS divergence (Data Engineering).

COMMON MISTAKE
Mixing bits and nats, or computing KL when q has a zero where p does not (KL becomes infinite). Smooth the probabilities or use Jensen-Shannon divergence, which is symmetric and bounded.

Check yourself

  1. Which has higher entropy: a 99/1 coin or a 50/50 coin? Answer: the fair coin.
  2. Is KL(p‖q) equal to KL(q‖p)? Answer: no.
  3. What is I(X; Y) if X and Y are independent? Answer: zero.

Chapter recap

  • Convex problems have no traps: local minimum = global minimum. Neural networks are non-convex.
  • Gradient descent steps θ − η∇L; η too large diverges (for x², η > 1).
  • Batch, SGD and mini-batch differ in how many rows give the gradient.
  • Momentum, RMSProp and Adam adapt steps; AdamW decouples weight decay; schedules change η over time.
  • Newton uses curvature (one step on a quadratic); L-BFGS approximates it cheaply.
  • Lagrange multipliers and KKT handle constraints; multipliers are prices of constraints.
  • LP optimum sits at a vertex; linprog minimises; integer problems need milp.
  • Entropy measures surprise; cross-entropy minus entropy is KL; mutual information is shared information.

Problem 13.9.1 For f(x) = x², starting at x = 4 with η = 0.25, what is x after two steps?

Answer: The factor is 1 − 2 × 0.25 = 0.5, so 4 → 2 → 1.

Problem 13.9.2 Is f(x) = x³ convex on all of ℝ? Minimise x² + y² subject to x + y = 4.

Answer: Not convex: f'' = 6x < 0 for x < 0. Second part: x = y = λ/2 and the constraint give x = y = 2, value 8.

Problem 13.9.3 What is the output? print(entropy([0.5,0.5], base=2)) (with from scipy.stats import entropy)

Answer: 1.0.

Problem 13.9.4 Gradient at the current point is 6, η = 0.1, momentum velocity before = 2 (β = 0.9). Find the new velocity and the parameter change.

Answer: v = 0.9 × 2 + 6 = 7.8. Change = −0.1 × 7.8 = −0.78.

Problem 13.9.6 Find the bug: linprog(c=[40,30], A_ub=[[2,1],[1,1]], b_ub=[100,80]) is used to maximise profit.

Answer: linprog minimises, so the call minimises 40a + 30b and returns (0, 0). Use c=[-40,-30] and negate fun.

Problem 13.9.7 p = (0.5, 0.5), q = (0.9, 0.1). Compute KL(p ‖ q) in bits.

Answer: 0.5 log₂(0.5/0.9) + 0.5 log₂(0.5/0.1) = 0.5(−0.848) + 0.5(2.3219) = −0.424 + 1.161 = 0.737 bits.

Problem 13.9.9 (Interview) Why is Adam popular, and when might plain SGD with momentum be better?

Answer: Adam adapts the step per parameter, so it works with little tuning on sparse or badly scaled problems. SGD with momentum often generalizes slightly better on some vision tasks when carefully tuned. Neither is universally best.

Problem 13.9.10 (Interview) Explain a Lagrange multiplier to a manager.

Answer: It is the price of a limit: how much better the best result becomes if you relax that limit by one unit. In our LP, a CPU-hour was worth 10 points.
